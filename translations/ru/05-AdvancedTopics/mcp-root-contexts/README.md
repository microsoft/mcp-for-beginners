# Корни MCP (Устаревшая функция)

> [!WARNING]
> Корни устарели с версии MCP `2026-07-28`. Они остаются в этой ревизии для
> совместимости и могут быть удалены в первом выпуске спецификации,
> выпущенном 28 июля 2027 года или позже. Новые реализации должны передавать
> директории или файлы через параметры инструментов, URI ресурсов или
> конфигурацию сервера.

## Обзор

Корни позволяют клиенту MCP сообщить серверу, какие местоположения в файловой системе актуальны
для текущего запроса. Корень содержит обязательный URI `file://` и необязательное
читаемое человеком имя.

Корни являются информационными подсказками. Они не являются контейнерами истории
общения, протокольными сессиями или механизмом контроля доступа. Протокол не
требует от сервера оставаться в пределах указанных корней.

## Цели обучения

К концу этого урока вы сможете:

- Объяснить, что представляют собой корни MCP и что они не представляют.
- Узнать текущий многоходовой поток `roots/list`.
- Применять меры безопасности независимо от корней.
- Перейти на поддерживаемые альтернативы в новых реализациях.

## Данные корня

Клиент возвращает каждый корень в виде URI `file://` с необязательным отображаемым именем:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

Клиенты должны показывать только локации, одобренные пользователем. Серверы должны
рассматривать результат как указание на релевантные файлы, а не как доказательство авторизации.

## Поток MCP 2026-07-28

Клиент, поддерживающий корни, объявляет эту возможность в каждом запросе:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

Во время обработки запроса клиента сервер может вернуть
`InputRequiredResult`, содержащий запрос ввода `roots/list`:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

Клиент собирает одобренные корни и повторно отправляет исходный запрос с
соответствующими `inputResponses` и неизменным `requestState`. Этот многоходовый
шаблон поддерживает безсессионность протокола; нет рукопожатия `initialize` или
сессии на уровне протокола.

## Устаревшее поведение 2025-11-25

В MCP `2025-11-25` клиенты объявляли корни во время инициализации. Сервер
мог инициировать прямой запрос `roots/list`, а клиент мог отправлять
уведомления `notifications/roots/list_changed` при изменении корней.

Этот жизненный цикл — устаревшее поведение. Не сочетайте его примеры инициализации или
уведомлений с реализацией `2026-07-28`.

## Рекомендуемые замены

### Параметры инструментов

Сделайте требуемую директорию или файл явными в схеме инструмента:

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### URI ресурсов

Используйте ресурсы MCP, когда сервер может предоставить доступ к релевантным файлам
через стабильные URI. Это делает обнаружение и получение данных явными.

### Конфигурация сервера

Для фиксированных развертываний настройте допустимые директории при запуске сервера.
Это часто понятнее, чем определять их в ходе вызова инструмента.

## Требования безопасности

Какую бы замену вы ни выбрали:

- Получайте согласие пользователя перед раскрытием местоположений в файловой системе.
- Канонизируйте и валидируйте пути, чтобы предотвратить traversal-атаки.
- Применяйте авторизацию и изоляцию независимо от значений корней.
- Проверяйте права доступа при каждом доступе к файлу, а не только при перечислении.
- Избегайте возврата чувствительных путей в логах или сообщениях об ошибках.

## Основные выводы

- Корни описывают релевантные местоположения в файловой системе; они не хранят состояние
  разговора.
- Корни служат подсказкой, а не границей контроля доступа.
- В MCP `2026-07-28` возможность указывается в каждом запросе и используется
  `InputRequiredResult` для `roots/list`.
- Новые реализации должны использовать параметры инструментов, URI ресурсов или
  конфигурацию сервера.
