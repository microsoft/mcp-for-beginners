Этот вводный лабораторный курс предоставляет комплексный обзор построения серверов Model Context Protocol (MCP) с интеграцией баз данных. Вы узнаете бизнес-обоснование, техническую архитектуру и реальные примеры применения через кейс Zava Retail аналитики на https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail.

## Обзор

**Model Context Protocol (MCP)** позволяет AI-ассистентам безопасно получать доступ и взаимодействовать с внешними источниками данных в режиме реального времени. В сочетании с интеграцией баз данных MCP раскрывает мощные возможности для AI-приложений, основанных на данных.

Этот учебный курс научит вас строить готовые к эксплуатации MCP-серверы, которые подключают AI-ассистентов к данным розничных продаж через PostgreSQL, реализуя корпоративные паттерны, такие как безопасность на уровне строк, семантический поиск и многопользовательский доступ к данным.

## 🧭 Задача: AI встречается с данными реального мира

### Ограничения традиционного AI

Современные AI-ассистенты невероятно мощные, но сталкиваются с существенными ограничениями при работе с реальными бизнес-данными:

| **Проблема** | **Описание** | **Бизнес-воздействие** |
|---------------|-----------------|-------------------|
| **Статичные знания** | AI модели обучены на фиксированных наборах данных и не имеют доступа к текущим бизнес-данным | Устаревшие выводы, упущенные возможности |
| **Изолированные данные** | Информация заперта в базах, API и системах, к которым AI не имеет доступа | Неполный анализ, фрагментированные процессы |
| **Ограничения безопасности** | Прямой доступ к базе данных создаёт проблемы безопасности и соответствия требованиям | Ограниченное развертывание, ручная подготовка данных |
| **Сложные запросы** | Бизнес-пользователям необходимы технические знания для извлечения данных | Снижение принятия, неэффективные процессы |

### Решение MCP

Model Context Protocol решает эти задачи, предоставляя:

- **Доступ к данным в реальном времени**: AI-ассистенты делают запросы к живым базам и API
- **Безопасная интеграция**: Контролируемый доступ с аутентификацией и правами
- **Интерфейс на естественном языке**: Бизнес-пользователи задают вопросы простым английским
- **Стандартизованный протокол**: Работает на разных AI-платформах и инструментах

## 🏪 Знакомьтесь с Zava Retail: Наш учебный кейс https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

В этом учебном курсе мы создадим MCP сервер для **Zava Retail**, вымышленной сети хозяйственных магазинов с несколькими локациями. Этот реалистичный сценарий демонстрирует реализацию корпоративного уровня MCP.

### Бизнес-контекст

**Zava Retail** управляет:
- **8 физическими магазинами** в штате Вашингтон (Сиэтл, Белвью, Такома, Спокан, Эверетт, Редмонд, Киркланд)
- **1 онлайн-магазином** для электронной коммерции
- **Разнообразным каталогом товаров** включающим инструменты, оборудование, садовую продукцию и строительные материалы
- **Многоуровневым управлением** с менеджерами магазинов, региональными менеджерами и руководителями

### Бизнес-требования

Менеджерам магазинов и руководителям нужен AI-аналитика для:

1. **Анализа продаж** по магазинам и периодам
2. **Отслеживания уровней запасов** и выявления потребности в пополнении
3. **Понимания поведения клиентов** и покупательских паттернов
4. **Обнаружения инсайтов по продуктам** с помощью семантического поиска
5. **Генерации отчетов** с запросами на естественном языке
6. **Обеспечения безопасности данных** с контролем доступа на основе ролей

### Технические требования

MCP сервер должен обеспечивать:

- **Многопользовательский доступ к данным**, где менеджеры видят данные только своего магазина
- **Гибкие запросы** с поддержкой сложных SQL операций
- **Семантический поиск** для обнаружения продуктов и рекомендаций
- **Данные в реальном времени**, отражающие актуальное состояние бизнеса
- **Безопасную аутентификацию** с безопасностью на уровне строк
- **Масштабируемую архитектуру**, поддерживающую множество одновременных пользователей

### Ключевые компоненты

#### **1. Слой MCP сервера**
- **Фреймворк FastMCP**: Современная реализация MCP сервера на Python
- **Регистрация инструментов**: Декларативные определения инструментов с типовой безопасностью
- **Контекст запроса**: Управление идентичностью пользователя и сессиями
- **Обработка ошибок**: Надёжное управление ошибками и логирование

#### **2. Слой интеграции с базой данных**
- **Пулы подключений**: Эффективное управление подключениями asyncpg
- **Поставщик схемы**: Динамическое обнаружение схем таблиц
- **Выполнение запросов**: Безопасное выполнение SQL с контекстом RLS
- **Управление транзакциями**: ACID соответствие и откат транзакций

#### **3. Слой безопасности**
- **Безопасность на уровне строк**: PostgreSQL RLS для изоляции данных по арендаторам
- **Идентификация пользователя**: Аутентификация и авторизация менеджеров магазинов
- **Контроль доступа**: Тонкая настройка прав и аудит доступа
- **Валидация ввода**: Предотвращение SQL-инъекций и проверка запросов

#### **4. Слой AI-улучшений**
- **Семантический поиск**: Векторные эмбеддинги для обнаружения продуктов
- **Интеграция с Azure OpenAI**: Генерация текстовых эмбеддингов
- **Алгоритмы похожести**: Поиск косинусного сходства с pgvector
- **Оптимизация поиска**: Индексация и настройка производительности

## 🎬 Сценарии использования в реальном мире

Рассмотрим, как разные пользователи взаимодействуют с нашим MCP сервером:

### Сценарий 1: Анализ эффективности менеджера магазина

**Пользователь**: Сара, менеджер магазина в Сиэтле  
**Цель**: Проанализировать результаты продаж за последний квартал

**Запрос на естественном языке**:
> "Покажи топ 10 товаров по выручке моего магазина за 4-й квартал 2024 года"

**Что происходит**:
1. AI чат в VS Code отправляет запрос к MCP серверу
2. MCP сервер определяет контекст магазина Сары (Сиэтл)
3. Политики RLS фильтруют данные только для магазина в Сиэтле
4. Генерируется и выполняется SQL-запрос
5. Результаты форматируются и отправляются в AI чат
6. AI предоставляет анализ и инсайты

### Сценарий 2: Обнаружение продуктов с помощью семантического поиска

**Пользователь**: Майк, менеджер по запасам  
**Цель**: Найти продукты, похожие на запрос клиента

**Запрос на естественном языке**:
> "Какие продукты мы продаём, похожие на «водонепроницаемые электрические разъёмы для использования на улице»?"

**Что происходит**:
1. Запрос обрабатывается инструментом семантического поиска
2. Azure OpenAI генерирует вектор эмбеддинга
3. pgvector выполняет поиск похожих товаров
4. Связанные продукты ранжируются по релевантности
5. Результаты включают детали продукта и наличие
6. AI предлагает альтернативы и возможности для комплектов

### Сценарий 3: Аналитика по всем магазинам

**Пользователь**: Дженнифер, региональный менеджер  
**Цель**: Сравнить показатели по всем магазинам

**Запрос на естественном языке**:
> "Сравни продажи по категориям для всех магазинов за последние 6 месяцев"

**Что происходит**:
1. Устанавливается контекст RLS для доступа регионального менеджера
2. Генерируется сложный запрос по нескольким магазинам
3. Данные агрегируются по локациям магазинов
4. Результаты включают тренды и сравнения
5. AI выявляет инсайты и рекомендации

## 🔒 Безопасность и глубокое погружение в многопользовательский режим

В нашей реализации приоритетом является корпоративный уровень безопасности:

### Безопасность на уровне строк (RLS)

PostgreSQL RLS обеспечивает изоляцию данных:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### Управление идентичностью пользователя

Каждое подключение MCP включает:
- **ID менеджера магазина**: Уникальный идентификатор для контекста RLS
- **Назначение ролей**: Права и уровни доступа
- **Управление сессиями**: Надёжные аутентификационные токены
- **Аудит доступа**: Полная история доступа

### Защита данных

Несколько уровней безопасности:
- **Шифрование соединения**: TLS для всех подключений к базе данных
- **Предотвращение SQL-инъекций**: Только параметризованные запросы
- **Валидация ввода**: Всесторонняя проверка запросов
- **Обработка ошибок**: Отсутствие чувствительной информации в сообщениях об ошибках
