# Исследование: Открытие REST API в API Management как сервер MCP

Azure API Management — это сервис, который предоставляет шлюз поверх ваших API-эндпоинтов. Его работа заключается в том, что Azure API Management действует как прокси перед вашими API и может решать, что делать с входящими запросами.

Используя его, вы добавляете множество функций, таких как:

- **Безопасность**, вы можете использовать всё — от ключей API, JWT до управляемой идентичности.
- **Ограничение скорости запросов**, отличная функция, позволяющая решать, сколько вызовов можно пропустить за определённый промежуток времени. Это помогает обеспечить отличный опыт для всех пользователей и не перегружать ваш сервис запросами.
- **Масштабирование и балансировка нагрузки**. Вы можете настроить несколько эндпоинтов для распределения нагрузки и решить, как именно выполнять балансировку.
- **Функции ИИ, такие как семантическое кэширование**, лимит токенов, мониторинг токенов и многое другое. Это отличные функции, которые улучшают отзывчивость и помогают контролировать расходы на токены. [Подробнее здесь](https://learn.microsoft.com/en-us/azure/api-management/genai-gateway-capabilities).

## Почему MCP + Azure API Management?

Протокол Model Context Protocol быстро становится стандартом для интеллектуальных приложений с агентами и способом последовательного открытия инструментов и данных. Azure API Management является естественным выбором, когда нужно "управлять" API. MCP серверы часто интегрируются с другими API для обработки запросов, например, к инструменту. Поэтому сочетание Azure API Management и MCP очень логично.

## Обзор

В этом конкретном примере мы научимся открывать API эндпоинты как MCP сервер. Таким образом, мы можем легко сделать эти эндпоинты частью агентного приложения и одновременно использовать возможности Azure API Management.

## Ключевые функции

- Вы выбираете методы эндпоинта, которые хотите открыть как инструменты.
- Дополнительные функции зависят от того, что вы настроите в разделе политик для вашего API. Здесь мы покажем, как добавить ограничение скорости запросов.

## Предварительный шаг: импорт API

Если у вас уже есть API в Azure API Management, отлично, этот шаг можно пропустить. Если нет, ознакомьтесь с этой ссылкой: [импорт API в Azure API Management](https://learn.microsoft.com/en-us/azure/api-management/import-and-publish#import-and-publish-a-backend-api).

## Открытие API как MCP сервера

Чтобы открыть API эндпоинты, выполните следующие шаги:

1. Перейдите в портал Azure по адресу <https://portal.azure.com/?Microsoft_Azure_ApiManagement=mcp> 
Перейдите к вашему экземпляру API Management.

1. В левом меню выберите APIs > MCP Servers > + Создать новый MCP Server.

1. В API выберите REST API для открытия в виде MCP сервера.

1. Выберите одну или несколько операций API для открытия как инструменты. Можно выбрать все операции или только конкретные.

    ![Выбор методов для открытия](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/create-mcp-server-small.png)


1. Выберите **Создать**.

1. Перейдите к меню **APIs** и **MCP Servers**, вы должны увидеть следующее:

    ![Просмотр MCP сервера в основной области](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-list.png)

    MCP сервер создан, и операции API открыты как инструменты. MCP сервер отображается в панели MCP Servers. Столбец URL показывает эндпоинт MCP сервера, который можно вызвать для теста или в клиентском приложении.

## Дополнительно: настройка политик

Azure API Management использует базовую концепцию политик, где вы устанавливаете разные правила для эндпоинтов, например, ограничение скорости запросов или семантическое кэширование. Эти политики создаются в формате XML.

Вот как можно настроить политику для ограничения скорости запросов на вашем MCP сервере:

1. В портале, в разделе APIs, выберите **MCP Servers**.

1. Выберите созданный MCP сервер.

1. В левом меню, в разделе MCP, выберите **Policies**.

1. В редакторе политик добавьте или измените политики, которые хотите применить к инструментам MCP сервера. Политики определяются в формате XML. Например, можно добавить политику для ограничения вызовов инструментов MCP сервера (в этом примере 5 вызовов за 30 секунд на IP клиента). Вот XML, который позволит установить ограничение скорости:

    ```xml
     <rate-limit-by-key calls="5" 
       renewal-period="30" 
       counter-key="@(context.Request.IpAddress)" 
       remaining-calls-variable-name="remainingCallsPerIP" 
    />
    ```

    Вот изображение редактора политик:

    ![Редактор политик](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-policies-small.png)
 
## Попробуйте

Давайте удостоверимся, что наш MCP сервер работает как задумано.

> [!NOTE]
> Azure API Management в настоящее время открывает этот сервер через потоковый
> HTTP эндпоинт `/mcp`. Старый транспорт HTTP+SSE `/sse` устарел и
> рекомендуется использовать только с устаревшими клиентами.

Для этого мы используем Visual Studio Code и GitHub Copilot с режимом агента. Мы добавим MCP сервер в файл *mcp.json*. Так Visual Studio Code выступит как клиент с агентными возможностями, и конечные пользователи смогут ввести запрос и взаимодействовать с сервером.

Посмотрим, как добавить MCP сервер в Visual Studio Code:

1. Используйте команду MCP: **Add Server из палитры команд**.

1. При запросе выберите тип сервера: **HTTP (HTTP или Server Sent Events)**.

1. Введите потоковый HTTP URL, указанный для MCP сервера в API Management.
    Например:
    `https://<apim-service-name>.azure-api.net/<api-name>-mcp/mcp`.

1. Введите идентификатор сервера по вашему выбору. Это не критичное значение, но поможет запомнить, что это за экземпляр сервера.

1. Выберите, сохранять конфигурацию в настройках рабочего пространства или пользовательских настройках.

  - **Настройки рабочего пространства** – конфигурация сервера сохраняется в файле .vscode/mcp.json, доступном только в текущем рабочем пространстве.

    *mcp.json*

    ```json
    "servers": {
        "APIM petstore" : {
            "type": "http",
            "url": "url-to-mcp-server/mcp"
        }
    }
    ```

  - **Пользовательские настройки** – конфигурация сервера добавляется в ваш глобальный файл *settings.json* и доступна во всех рабочих пространствах. Конфигурация выглядит примерно так:

    ![Пользовательская настройка](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-servers-visual-studio-code.png)

1. Также нужно добавить конфигурацию: заголовок для правильной аутентификации в Azure API Management. Используется заголовок **Ocp-Apim-Subscription-Key**.

    - Вот как его можно добавить в настройки:

    ![Добавление заголовка для аутентификации](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-with-header-visual-studio-code.png), это вызовет запрос на ввод ключа API, который можно найти в портале Azure для вашего экземпляра Azure API Management.

   - Чтобы добавить его в *mcp.json*, можно сделать так:

    ```json
    "inputs": [
      {
        "type": "promptString",
        "id": "apim_key",
        "description": "API Key for Azure API Management",
        "password": true
      }
    ]
    "servers": {
        "APIM petstore" : {
            "type": "http",
            "url": "url-to-mcp-server/mcp",
            "headers": {
                "Ocp-Apim-Subscription-Key": "Bearer ${input:apim_key}"
            }
        }
    }
    ```

### Использование режима агента

Теперь всё настроено либо в настройках, либо в *.vscode/mcp.json*. Давайте попробуем.

Должна появиться иконка Инструментов, где перечислены открытые инструменты с вашего сервера:

![Инструменты с сервера](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/tools-button-visual-studio-code.png)

1. Нажмите на иконку инструментов, и вы увидите список инструментов:

    ![Инструменты](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/select-tools-visual-studio-code.png)

1. Введите запрос в чат для вызова инструмента. Например, если вы выбрали инструмент для получения информации о заказе, можно спросить агента о заказе. Пример запроса:

    ```text
    get information from order 2
    ```

    Теперь появится иконка инструментов с просьбой продолжить вызов инструмента. Выберите продолжить, вы должны увидеть результат так:

    ![Результат запроса](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/chat-results-visual-studio-code.png)

    **то, что вы видите выше, зависит от настроенных вами инструментов, но суть в том, что вы получаете текстовый ответ, как показано выше**
