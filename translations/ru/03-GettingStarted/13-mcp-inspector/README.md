# Отладка с MCP Inspector

> [!NOTE]
> Команды с использованием `--sse` и URL, заканчивающиеся на `/sse`, тестируют устаревший транспорт HTTP+SSE.
> Для нового сервера MCP `2026-07-28` используйте версию Inspector, которая
> поддерживает Streamable HTTP, и выберите этот транспорт.

**MCP Inspector** — это важный инструмент для отладки, который позволяет интерактивно тестировать и устранять неполадки на ваших MCP серверах без необходимости запускать полное AI-хост-приложение. Можно считать его «Postman для MCP» — он предоставляет визуальный интерфейс для отправки запросов, просмотра ответов и понимания поведения вашего сервера.

## Почему стоит использовать MCP Inspector?

При создании MCP серверов вы часто столкнетесь со следующими задачами:

- **«Запущен ли вообще мой сервер?»** — Inspector показывает статус соединения
- **«Правильно ли зарегистрированы мои инструменты?»** — Inspector показывает список всех доступных инструментов
- **«Какой формат ответа?»** — Inspector отображает полные JSON-ответы
- **«Почему этот инструмент не работает?»** — Inspector показывает подробные сообщения об ошибках

## Требования

- Установленный Node.js 18+
- npm (идёт в комплекте с Node.js)
- MCP сервер для тестирования (см. [Модуль 3.1 - Первый сервер](../01-first-server/README.md))

## Установка

### Вариант 1: Запуск через npx (Рекомендуется для быстрого тестирования)

```bash
npx @modelcontextprotocol/inspector
```

### Вариант 2: Глобальная установка

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### Вариант 3: Добавить в проект

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

Добавьте в `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## Подключение к серверу

### stdio серверы (локальный процесс)

Для серверов, которые общаются через стандартный ввод/вывод:

```bash
# Сервер на Python
npx @modelcontextprotocol/inspector python -m your_server_module

# Сервер на Node.js
npx @modelcontextprotocol/inspector node ./build/index.js

# С переменными окружения
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP серверы (сеть)

Для серверов, работающих как HTTP-сервисы:

1. Сначала запустите ваш сервер:
   ```bash
   python server.py  # Сервер запущен на http://localhost:8080
   ```

2. Запустите Inspector и подключитесь:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## Тестирование инструментов

### Просмотр доступных инструментов

1. Нажмите вкладку **Tools**
2. Inspector автоматически вызовет `tools/list`
3. Вы увидите все зарегистрированные инструменты с:
   - Названием инструмента
   - Описанием
   - Схемой входных параметров

### Вызов инструмента

1. Выберите инструмент из списка
2. Заполните нужные параметры в форме
3. Нажмите **Run Tool**
4. Просмотрите ответ в панели результатов

**Пример: тестирование калькулятора**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### Отладка ошибок инструментов

Когда инструмент выдаёт ошибку, Inspector показывает:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

Распространённые коды ошибок:
| Код | Значение |
|------|---------|
| -32700 | Ошибка разбора (невалидный JSON) |
| -32600 | Неверный запрос |
| -32601 | Метод не найден |
| -32602 | Неверные параметры |
| -32603 | Внутренняя ошибка |

## Тестирование ресурсов

### Просмотр ресурсов

1. Нажмите вкладку **Resources**
2. Inspector вызовет `resources/list`
3. Вы увидите:
   - URI ресурсов
   - Названия и описания
   - MIME-типы

### Чтение ресурса

1. Выберите ресурс
2. Нажмите **Read Resource**
3. Посмотрите возвращённое содержимое

**Пример вывода:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## Тестирование подсказок

### Просмотр подсказок

1. Нажмите вкладку **Prompts**
2. Inspector вызовет `prompts/list`
3. Посмотрите доступные шаблоны подсказок

### Получение подсказки

1. Выберите подсказку
2. Заполните необходимые аргументы
3. Нажмите **Get Prompt**
4. Просмотрите отрендеренные сообщения подсказки

## Анализ журнала сообщений

Журнал сообщений показывает все сообщения протокола MCP. Ниже приведён протокол от
устаревшего сервера `2025-11-25` с удалённым рукопожатием `initialize`. Сервер
`2026-07-28` использует автономные метаданные запроса и `server/discover`
вместо этого.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### На что обратить внимание

- **Пары запрос/ответ**: для каждого `→` должен быть соответствующий `←`
- **Сообщения об ошибках**: ищите `"error"` в ответах
- **Тайминги**: большие промежутки могут указывать на проблемы с производительностью
- **Версия протокола**: убедитесь, что сервер и клиент согласованы по версии

## Интеграция с VS Code

Вы можете запускать Inspector напрямую из VS Code:

### Использование launch.json

Добавьте в `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

### Использование задач (Tasks)

Добавьте в `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Start MCP Inspector",
      "type": "shell",
      "command": "npx @modelcontextprotocol/inspector node ${workspaceFolder}/build/index.js",
      "isBackground": true,
      "problemMatcher": {
        "pattern": {
          "regexp": "^$"
        },
        "background": {
          "activeOnStart": true,
          "beginsPattern": "Inspector",
          "endsPattern": "listening"
        }
      }
    }
  ]
}
```

## Распространённые сценарии отладки

### Сценарий 1: Сервер не подключается

**Симптомы:** Inspector показывает «Disconnected» или зависает на «Connecting...»

**Контрольный список:**
1. ✅ Команда запуска сервера корректна?
2. ✅ Все зависимости установлены?
3. ✅ Путь к серверу абсолютный или относительный к текущей директории?
4. ✅ Установлены необходимые переменные окружения?

**Шаги для отладки:**
```bash
# Сначала вручную протестируйте сервер
python -c "import your_server_module; print('OK')"

# Проверьте наличие ошибок импорта
python -m your_server_module 2>&1 | head -20

# Убедитесь, что MCP SDK установлен
pip show mcp
```

### Сценарий 2: Инструменты не отображаются

**Симптомы:** Вкладка инструментов показывает пустой список

**Возможные причины:**
1. Инструменты не зарегистрированы во время инициализации сервера
2. Сервер упал после запуска
3. Обработчик `tools/list` возвращает пустой массив

**Шаги для отладки:**
1. Проверьте журнал сообщений на ответ `tools/list`
2. Добавьте логирование в код регистрации инструментов
3. Убедитесь, что декораторы `@mcp.tool()` присутствуют (Python)

### Сценарий 3: Инструмент возвращает ошибку

**Симптомы:** Вызов инструмента возвращает ошибку

**Подход к отладке:**
1. Внимательно прочитайте сообщение об ошибке
2. Проверьте, что типы параметров соответствуют схеме
3. Добавьте try/catch с подробными сообщениями об ошибках
4. Проверьте логи сервера на стек вызовов

**Пример улучшенной обработки ошибок:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # Логика инструмента здесь
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### Сценарий 4: Содержимое ресурса пустое

**Симптомы:** Ресурс возвращается, но содержимое пустое или null

**Контрольный список:**
1. ✅ Путь к файлу или URI правильны
2. ✅ Сервер имеет права на чтение ресурса
3. ✅ Содержимое ресурса корректно возвращается

## Расширенные возможности Inspector

### Пользовательские заголовки (SSE)

```bash
npx @modelcontextprotocol/inspector \
  --sse http://localhost:8080/sse \
  --header "Authorization: Bearer your-token"
```

### Подробное логирование

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### Запись сессий

Inspector может экспортировать журналы сообщений для последующего анализа:
1. Нажмите **Export Log** в панели сообщений
2. Сохраните JSON-файл
3. Поделитесь с членами команды для отладки

## Лучшие практики

1. **Тестируйте рано и часто** — Используйте Inspector в процессе разработки, а не только при сбоях
2. **Начинайте с простого** — Сначала проверяйте базовое подключение, затем сложные вызовы инструментов
3. **Проверяйте схему** — Многие ошибки связаны с несоответствием типов параметров
4. **Читайте сообщения об ошибках** — Ошибки MCP обычно информативны
5. **Держите Inspector открытым** — Это помогает быстро обнаруживать проблемы во время разработки
