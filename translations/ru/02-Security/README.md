# Безопасность MCP: комплексная защита для AI-систем

[![Лучшие практики безопасности MCP](../../../translated_images/ru/03.175aed6dedae133f.webp)](https://youtu.be/88No8pw706o)

_(Нажмите на изображение выше, чтобы посмотреть видео этого урока)_

Безопасность является фундаментом при проектировании AI-систем, поэтому мы уделяем ей приоритетное внимание во втором разделе. Это соответствует принципу Microsoft **Secure by Design** из [Инициативы Secure Future](https://www.microsoft.com/security/blog/2025/04/17/microsofts-secure-by-design-journey-one-year-of-success/).

Протокол контекста модели (MCP) предоставляет мощные новые возможности для приложений с AI, одновременно вводя уникальные задачи безопасности, выходящие за рамки традиционных рисков программного обеспечения. Системы MCP сталкиваются как с общепринятыми вопросами безопасности (безопасное кодирование, принцип наименьших привилегий, безопасность цепочки поставок), так и с новыми специфическими угрозами AI, включая внедрение команд (prompt injection), отравление инструментов, перехват сессий, атаки «confused deputy», уязвимости при передаче токенов и динамическое изменение возможностей.

В этом уроке рассматриваются наиболее критичные риски безопасности в реализации MCP — включая аутентификацию, авторизацию, чрезмерные полномочия, косвенное внедрение команд, безопасность сессий, проблемы confused deputy, управление токенами и уязвимости в цепочке поставок. Вы узнаете практические меры и лучшие методы для снижения этих рисков, используя решения Microsoft, такие как Prompt Shields, Azure Content Safety и GitHub Advanced Security, чтобы усилить защиту вашего MCP-развертывания.

## Цели обучения

К концу урока вы сможете:

- **Определять угрозы, специфичные для MCP**: Распознавать уникальные риски безопасности в системах MCP, включая внедрение команд, отравление инструментов, чрезмерные полномочия, перехват сессий, проблемы confused deputy, уязвимости при передаче токенов и риски цепочки поставок
- **Применять меры безопасности**: Внедрять эффективные меры защиты, включая надежную аутентификацию, доступ по принципу наименьших привилегий, безопасное управление токенами, контролировать безопасность сессий и верификацию цепочки поставок
- **Использовать решения безопасности Microsoft**: Понимать и применять Microsoft Prompt Shields, Azure Content Safety и GitHub Advanced Security для защиты MCP-нагрузок
- **Проверять безопасность инструментов**: Осознавать важность валидации метаданных инструментов, мониторинга динамических изменений и защиты от косвенных атак внедрения команд
- **Интегрировать лучшие практики**: Совмещать фундаментальные принципы безопасности (безопасное кодирование, усиление серверов, нулевое доверие) с MCP-специфическими мерами для комплексной защиты

# Архитектура и меры безопасности MCP

Современные реализации MCP требуют многослойных подходов к безопасности, которые охватывают как традиционную безопасность программного обеспечения, так и специфические угрозы AI. Быстро развивающаяся спецификация MCP продолжает совершенствовать меры безопасности, обеспечивая лучшую интеграцию с архитектурами корпоративной безопасности и проверенными лучшими практиками.

Исследование из [Microsoft Digital Defense Report](https://aka.ms/mddr) показывает, что **98% зарегистрированных нарушений предотвращаются за счет надежной безопасности**. Наиболее эффективная стратегия защиты сочетает фундаментальные меры безопасности с MCP-специфическими контролями — проверенные базовые меры остаются самым значимым способом снижения общего риска безопасности.

### Эволюция аутентификации MCP

Спецификация MCP значительно изменилась в подходах к аутентификации и авторизации:

- **Изначальный подход**: ранние спецификации требовали от разработчиков реализации собственных серверов аутентификации, при этом MCP-серверы выступали OAuth 2.0 серверами авторизации, непосредственно управляя аутентификацией пользователей
- **Текущий стандарт (`2026-07-28`)**: MCP-серверы могут делегировать аутентификацию
  внешним провайдерам идентичности, таким как Microsoft Entra ID. Клиенты также должны
  соблюдать текущие требования по валидации эмитента и связыванию учетных данных.
- **Безопасность уровня транспорта**: расширенная поддержка безопасных транспортных протоколов с правильными схемами аутентификации для локальных (STDIO) и удалённых (HTTP Streamable) подключений

## Безопасность аутентификации и авторизации

### Современные проблемы безопасности

Современные реализации MCP сталкиваются с несколькими вызовами в области аутентификации и авторизации:

### Риски и точки атаки

- **Некорректная логика авторизации**: ошибки в реализации авторизации MCP-серверов могут привести к раскрытию чувствительных данных и неправильному применению контроля доступа
- **Компрометация OAuth-токенов**: кража локальных токенов MCP-серверов позволяет злоумышленникам выдавать себя за серверы и получать доступ к сторонним сервисам
- **Уязвимости передачи токенов (Token Passthrough)**: неправильная обработка токенов создает обходы мер безопасности и разрывы в учете действий
- **Чрезмерные полномочия**: MCP-серверы с избыточными правами нарушают принцип наименьших привилегий и расширяют поверхность атаки

#### Token Passthrough: критический анти-паттерн

**Передача токена прямо запрещена** в текущей спецификации авторизации MCP из-за серьезных последствий для безопасности:

##### Обход мер безопасности
- MCP-серверы и подключенные API реализуют важные меры безопасности (ограничение частоты запросов, валидация запросов, мониторинг трафика), которые зависят от правильной проверки токенов
- Прямое использование клиентом токена для доступа к API обходит эти меры, подрывая архитектуру безопасности

##### Проблемы учета и аудита  
- MCP-серверы не могут отличить клиентов, использующих токены, выданные выше, что нарушает трассировку аудита
- Логи серверов ресурсов показывают неверное происхождение запросов, а не фактических посредников MCP-серверов
- Расследование инцидентов и аудит соответствия значительно усложняются

##### Риски утечки данных
- Неотвалидированные утверждения токена позволяют злоумышленникам с украденными токенами использовать MCP-серверы как прокси для вывода данных
- Нарушения границ доверия приводят к несанкционированным схемам доступа, обходящим намеченные меры безопасности

##### Векторы атак межсервисного взаимодействия
- Компрометированные токены принимаются множеством сервисов, что позволяет перемещаться по связанным системам
- Предположения о доверии между сервисами могут нарушаться, если происхождение токенов не может быть проверено

### Меры безопасности и способы смягчения

**Критические требования по безопасности:**

> **ОБЯЗАТЕЛЬНО:** MCP-серверы **НЕ ДОЛЖНЫ** принимать токены, которые явно не были выданы для данного MCP-сервера

#### Контроль аутентификации и авторизации

- **Тщательный аудит авторизации**: проводить комплексный аудит логики авторизации MCP-серверов, чтобы обеспечить доступ только для предназначенных пользователей и клиентов
  - **Руководство по реализации**: [Azure API Management как шлюз аутентификации для MCP-серверов](https://techcommunity.microsoft.com/blog/integrationsonazureblog/azure-api-management-your-auth-gateway-for-mcp-servers/4402690)
  - **Интеграция идентичности**: [Использование Microsoft Entra ID для аутентификации MCP-серверов](https://den.dev/blog/mcp-server-auth-entra-id-session/)

- **Безопасное управление токенами**: применение [лучших практик Microsoft по проверке и жизненному циклу токенов](https://learn.microsoft.com/en-us/entra/identity-platform/access-tokens)
  - Проверять соответствие аудитории токена идентичности MCP-сервера
  - Реализовывать корректные политики ротации и истечения токенов
  - Предотвращать повторное использование токенов и несанкционированное применение

- **Защищенное хранение токенов**: безопасное хранение токенов с шифрованием как в состоянии покоя, так и при передаче
  - **Лучшие практики**: [Руководство по безопасному хранению и шифрованию токенов](https://youtu.be/uRdX37EcCwg?si=6fSChs1G4glwXRy2)

#### Внедрение контроля доступа

- **Принцип наименьших привилегий**: предоставлять MCP-серверам только минимально необходимые права для выполнения функций
  - Регулярно пересматривать и обновлять права, чтобы предотвращать расширение полномочий
  - **Документация Microsoft**: [Безопасный доступ с наименьшими привилегиями](https://learn.microsoft.com/entra/identity-platform/secure-least-privileged-access)

- **Ролевой контроль доступа (RBAC)**: внедрять детальное назначение ролей
  - Ограничивать роли конкретными ресурсами и действиями
  - Избегать общих или лишних прав, расширяющих поверхность атаки

- **Постоянный мониторинг прав**: непрерывно проводить аудит и мониторинг доступа
  - Отслеживать аномалии в использовании прав
  - Быстро устранять избыточные или неиспользуемые привилегии

## Специфические угрозы безопасности AI

### Атаки внедрения команд и манипуляции инструментами

Современные реализации MCP сталкиваются со сложными специфическими векторами атак на AI, которые традиционные меры безопасности не могут полностью нейтрализовать:

#### **Косвенное внедрение команд (междоменное внедрение команд)**

**Косвенное внедрение команд** является одной из самых критичных уязвимостей в системах с поддержкой MCP. Злоумышленники внедряют вредоносные инструкции в внешний контент — документы, веб-страницы, электронные письма или источники данных, которые AI-системы затем обрабатывают как легитимные команды.

**Сценарии атак:**
- **Внедрение в документы**: вредоносные инструкции, скрытые в обрабатываемых документах, вызывают нежелательные действия AI
- **Эксплуатация веб-контента**: компрометированные веб-страницы с встроенными подсказками, которые манипулируют поведением AI при их обработке
- **Атаки по электронной почте**: вредоносные подсказки в письмах, вызывающие утечки информации или несанкционированные действия AI-ассистентов
- **Загрязнение источников данных**: скомпрометированные базы данных или API, предоставляющие зараженный контент AI-системам

**Реальное воздействие**: эти атаки могут привести к утечке данных, нарушениям конфиденциальности, созданию вредоносного контента и манипуляциям с взаимодействием пользователей. Для подробного анализа смотрите [Prompt Injection в MCP (Simon Willison)](https://simonwillison.net/2025/Apr/9/mcp-prompt-injection/).

![Диаграмма атаки внедрения команд](../../../translated_images/ru/prompt-injection.ed9fbfde297ca877.webp)

#### **Атаки отравления инструментов**

**Отравление инструментов** нацелено на метаданные, определяющие инструменты MCP, эксплуатируя способ, которым большие языковые модели (LLM) интерпретируют описания и параметры инструментов для принятия решений об их выполнении.

**Механизмы атаки:**
- **Манипуляция метаданными**: злоумышленники встраивают вредоносные инструкции в описания инструментов, определения параметров или примеры использования
- **Невидимые инструкции**: скрытые подсказки в метаданных инструментов, которые обрабатываются AI-моделями, но невидимы для людей
- **Динамическое изменение инструментов («Rug Pulls»)**: инструменты, одобренные пользователями, впоследствии модифицируются для вредоносных действий без ведома пользователя
- **Внедрение параметров**: вредоносный контент, вставленный в схемы параметров инструментов, влияющий на поведение модели


**Риски размещённых серверов**: Удалённые серверы MCP представляют повышенные риски, так как определения инструментов могут обновляться после первоначального утверждения пользователем, создавая сценарии, когда ранее безопасные инструменты становятся вредоносными. Для комплексного анализа см. [Атаки на отравление инструментов (Invariant Labs)](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks).

![Диаграмма атаки внедрения инструмента](../../../translated_images/ru/tool-injection.3b0b4a6b24de6bef.webp)

#### **Дополнительные векторы атак ИИ**

- **Внедрение подсказок через несколько доменов (XPIA)**: Сложные атаки, использующие контент из нескольких доменов для обхода средств безопасности
- **Динамическое изменение возможностей**: Изменения возможностей инструментов в реальном времени, которые ускользают от первоначальных оценок безопасности
- **Отравление окна контекста**: Атаки, манипулирующие большими окнами контекста для скрытия вредоносных инструкций
- **Атаки путаницы модели**: Использование ограничений модели для создания непредсказуемого или небезопасного поведения


### Влияние рисков безопасности ИИ

**Последствия с высоким уровнем воздействия:**
- **Экфильтрация данных**: Несанкционированный доступ и кража конфиденциальных данных предприятия или личных данных
- **Нарушение конфиденциальности**: Разглашение персональной информации (PII) и конфиденциальных деловых данных  
- **Манипуляция системами**: Непреднамеренные изменения критически важных систем и рабочих процессов
- **Кража учётных данных**: Компрометация токенов аутентификации и учётных данных сервисов
- **Латеральное перемещение**: Использование скомпрометированных систем ИИ в качестве точек опоры для более широких сетевых атак

## Продвинутые угрозы безопасности MCP

### Уязвимости захвата сессий

**Захват сессии** представляет собой критический вектор атаки в реализуемых с сохранением состояния MCP, когда злоумышленники получают и используют легитимные идентификаторы сессий для выдавания себя за клиентов и выполнения несанкционированных действий.

#### **Сценарии атак и риски**

- **Внедрение подсказки захвата сессии**: Злоумышленники с украденными ID сессий внедряют вредоносные события на серверах, совместно использующих состояние сессии, что может вызвать вредоносные действия или доступ к конфиденциальным данным
- **Прямое выдавание себя за пользователя**: Украденные ID сессий позволяют напрямую совершать вызовы MCP сервера, обходя аутентификацию, и действовать как легитимные пользователи
- **Скомпрометированные потоки с возможностью возобновления**: Злоумышленники могут преждевременно завершать запросы, заставляя легитимных клиентов возобновлять работу с потенциально вредоносным содержимым

#### **Контроли безопасности для управления сессиями**

**Критические требования:**
- **Проверка авторизации**: Серверы MCP, реализующие авторизацию, **ДОЛЖНЫ** проверять ВСЕ входящие запросы и **НЕ ДОЛЖНЫ** полагаться на сессии для аутентификации
- **Безопасное создание сессий**: Использовать криптографически безопасные, недетерминированные идентификаторы сессий, генерируемые с помощью защищённых генераторов случайных чисел
- **Привязка к пользователю**: Привязывать ID сессий к пользовательской информации с использованием форматов типа `<user_id>:<session_id>`, чтобы предотвратить злоупотребление сессиями между пользователями
- **Управление жизненным циклом сессии**: Внедрять адекватное истечение, ротацию и аннулирование сессий для ограничения времени уязвимости
- **Защита передачи данных**: Обязательное использование HTTPS для всей коммуникации во избежание перехвата идентификаторов сессий

### Проблема сбитого с толку посредника

Проблема **сбитого с толку посредника** возникает, когда серверы MCP работают как прокси-аутентификации между клиентами и сторонними сервисами, что создаёт возможности обхода авторизации путём эксплуатации статичных идентификаторов клиентов.

#### **Механика атаки и риски**

- **Обход согласия на основе cookie**: Предыдущая аутентификация пользователя создаёт cookie с согласием, которые злоумышленники используют через вредоносные запросы авторизации с подделанными URI перенаправления
- **Кража кода авторизации**: Существующие cookie могут заставлять серверы авторизации пропускать экраны согласия и перенаправлять коды на контролируемые злоумышленником конечные точки  
- **Несанкционированный доступ к API**: Украденные коды авторизации позволяют обмен токенов и выдачу себя за пользователя без явного одобрения

#### **Стратегии смягчения последствий**

**Обязательные меры:**
- **Требования явного согласия**: Прокси-серверы MCP с использованием статичных идентификаторов клиентов **ДОЛЖНЫ** получать согласие пользователя для каждого динамически зарегистрированного клиента
- **Реализация безопасности OAuth 2.1**: Следовать текущим рекомендациям по безопасности OAuth, включая PKCE (Proof Key for Code Exchange) для всех запросов авторизации
- **Строгая валидация клиентов**: Реализовать строгую проверку URI перенаправления и идентификаторов клиентов для предотвращения эксплуатации

### Уязвимости при прохождении токенов  

**Проход токенов** — это явный антипаттерн, при котором серверы MCP принимают клиентские токены без должной валидации и пересылают их нижестоящим API, нарушая спецификации авторизации MCP.

#### **Последствия для безопасности**

- **Обход контроля**: Прямое использование токенов клиентами для API обходит важные меры ограничения частоты, валидации и мониторинга
- **Повреждение аудита**: Токены, выданные выше, делают невозможным идентификацию клиента, нарушая возможности расследования инцидентов
- **Экфильтрация данных через прокси**: Невалидированные токены позволяют злоумышленникам использовать серверы как прокси для несанкционированного доступа к данным
- **Нарушение границ доверия**: Предположения о доверии нижестоящих сервисов могут быть нарушены, если происхождение токенов нельзя подтвердить
- **Расширение атак через мультисервисность**: Скомпрометированные токены, принятые в нескольких сервисах, позволяют латеральное перемещение

#### **Необходимые меры безопасности**

**Обязательные требования:**
- **Валидация токенов**: Серверы MCP **НЕ ДОЛЖНЫ** принимать токены, не выданные явно для сервера MCP
- **Проверка аудитории**: Всегда проверять совпадение утверждений аудитории токена с идентичностью сервера MCP
- **Правильный жизненный цикл токенов**: Реализовать короткоживущие токены доступа с надёжной ротацией


## Безопасность цепочки поставок для ИИ-систем

Безопасность цепочки поставок вышла за рамки традиционных программных зависимостей и охватывает всю экосистему ИИ. Современные реализации MCP должны строго проверять и контролировать все ИИ- компоненты, так как каждый из них вносит потенциальные уязвимости, которые могут компрометировать целостность системы.

### Расширенные компоненты цепочки поставок ИИ

**Традиционные программные зависимости:**
- Библиотеки и фреймворки с открытым исходным кодом
- Образы контейнеров и базовые системы  
- Инструменты разработки и сборочные пайплайны
- Инфраструктурные компоненты и сервисы

**Специфичные для ИИ элементы цепочки поставок:**
- **Фоновые модели**: Предобученные модели от различных поставщиков, требующие проверки происхождения
- **Сервисы векторизации**: Внешние сервисы векторизации и семантического поиска
- **Поставщики контекста**: Источники данных, базы знаний и репозитории документов  
- **Сторонние API**: Внешние AI-сервисы, ML-пайплайны и конечные точки обработки данных
- **Артефакты моделей**: Весы, конфигурации и варианты дообученных моделей
- **Источники обучающих данных**: Наборы данных для обучения и дообучения моделей

### Комплексная стратегия безопасности цепочки поставок

#### **Проверка компонентов и доверие**
- **Проверка происхождения**: Проверять источники, лицензии и целостность всех ИИ-компонентов перед интеграцией
- **Оценка безопасности**: Проводить сканирование уязвимостей и обзоры безопасности моделей, источников данных и AI-сервисов
- **Анализ репутации**: Оценивать историю безопасности и практики поставщиков AI-сервисов
- **Проверка соответствия**: Обеспечивать соответствие всех компонентов требованиям безопасности и регуляторным нормам организации

#### **Безопасные конвейеры развёртывания**  
- **Автоматизация CI/CD с безопасностью**: Интегрировать сканирование безопасности во все этапы автоматизированных конвейеров развёртывания
- **Целостность артефактов**: Использовать криптографическую проверку для всех развёртываемых артефактов (код, модели, конфигурации)
- **Пошаговое развёртывание**: Применять стратегии поэтапного развёртывания с проверкой безопасности на каждом этапе
- **Доверенные репозитории артефактов**: Развёртывать только из проверенных, безопасных реестров и репозиториев артефактов

#### **Непрерывный мониторинг и реагирование**
- **Сканирование зависимостей**: Постоянный мониторинг уязвимостей всех программных и AI-компонентных зависимостей
- **Мониторинг моделей**: Непрерывная оценка поведения модели, дрейфа производительности и аномалий безопасности
- **Отслеживание состояния сервисов**: Мониторинг внешних AI-сервисов на предмет доступности, инцидентов безопасности и изменений политик
- **Интеграция разведки угроз**: Включение информационных потоков об угрозах, специфичных для рисков безопасности ИИ и МО

#### **Контроль доступа и принцип минимальных привилегий**
- **Права на уровне компонентов**: Ограничивать доступ к моделям, данным и сервисам согласно потребностям бизнеса
- **Управление сервисными аккаунтами**: Внедрять выделенные сервисные аккаунты с минимально необходимыми правами
- **Сегментация сети**: Изолировать AI-компоненты и ограничивать сетевой доступ между сервисами
- **Контроль API-шлюзов**: Использовать централизованные API-шлюзы для контроля и мониторинга доступа к внешним AI-сервисам

#### **Реагирование на инциденты и восстановление**
- **Процедуры быстрого реагирования**: Установленные процессы по патчингу или замене скомпрометированных AI-компонентов
- **Ротация учётных данных**: Автоматизированные системы ротации секретов, ключей API и учётных данных сервисов
- **Возможности отката**: Способность быстро возвращаться к предыдущим стабильным версиям AI-компонентов

- **Многофакторная аутентификация**: Обязательное MFA для всех административных и сервисных аккаунтов

- **Интеграция поставщиков идентичности**: Централизованное управление идентификацией через корпоративные провайдеры (Microsoft Entra ID, Active Directory)

- **Всеобъемлющее логирование**: Детальный лог активности AI-приложений, включая взаимодействия клиентов и серверов MCP
- **Интеграция SIEM**: Централизованное управление информацией и событиями безопасности для обнаружения аномалий
- **Аналитика поведения**: AI-усиленный мониторинг для выявления необычных паттернов в поведении систем и пользователей
- **Разведка угроз**: Интеграция внешних потоков данных о угрозах и индикаторов компрометации (IOC)
- **Реагирование на инциденты**: Чётко определённые процедуры обнаружения, реагирования и восстановления после инцидентов безопасности

#### **Архитектура нулевого доверия**
- **Никогда не доверяй, всегда проверяй**: Непрерывная проверка пользователей, устройств и сетевых соединений
- **Микросегментация**: Тонкий сетевой контроль, изолирующий отдельные рабочие нагрузки и сервисы
- **Безопасность, ориентированная на идентичность**: Политики безопасности, основанные на подтверждённых личностях, а не на сетевом расположении
- **Непрерывная оценка рисков**: Динамическая оценка безопасности на основе текущего контекста и поведения
- **Условный доступ**: Контроли доступа, адаптирующиеся на основе факторов риска, местоположения и доверия устройству

## Основные выводы по безопасности  

- **Слоями безопасности**: объединение фундаментальных практик безопасности (безопасное программирование, принцип наименьших привилегий, проверка цепочки поставок, непрерывный мониторинг) с мерами, специфичными для ИИ, для комплексной защиты  

- **Специфические угрозы ИИ**: системы MCP сталкиваются с уникальными рисками, включая инъекции запросов (prompt injection), отравление инструментов, перехват сессий, проблемы confused deputy, уязвимости token passthrough и избыточные разрешения, требующие специализированных мер защиты  

- **Высокий уровень аутентификации и авторизации**: реализация надёжной аутентификации с использованием внешних провайдеров удостоверений (Microsoft Entra ID), обеспечение правильной проверки токенов и отказ от принятия токенов, явно не выданных для вашего MCP-сервера  

- **Предотвращение атак на ИИ**: внедрение Microsoft Prompt Shields и Azure Content Safety для защиты от косвенных инъекций запросов и отравления инструментов, а также проверка метаданных инструментов и мониторинг динамических изменений  

- **Безопасность сессий и транспортного уровня**: использование криптографически надёжных, недетерминированных идентификаторов сессий, привязанных к идентичностям пользователей, корректное управление жизненным циклом сессий и отказ от использования сессий для аутентификации  

- **Лучшие практики безопасности OAuth**: устранение атак confused deputy посредством явного согласия пользователей для динамически зарегистрированных клиентов, правильная реализация OAuth 2.1 с PKCE и строгая проверка redirect URI  

- **Принципы безопасности токенов**: избегание анти-паттернов token passthrough, проверка утверждений audience токена, использование токенов с коротким сроком жизни с безопасной ротацией и поддержание чётких границ доверия  

- **Всесторонняя безопасность цепочки поставок**: обращение со всеми компонентами экосистемы ИИ (модели, embedding, поставщики контекста, внешние API) с той же строгостью в области безопасности, что и с традиционными зависимостями программного обеспечения  

- **Непрерывное развитие**: быть в курсе быстро меняющихся спецификаций MCP, вносить вклад в стандарты сообщества по безопасности и поддерживать адаптивные позиции в области безопасности по мере развития протокола  

- **Интеграция с безопасностью Microsoft**: использовать комплексную экосистему безопасности Microsoft (Prompt Shields, Azure Content Safety, GitHub Advanced Security, Entra ID) для усиления защиты при развертывании MCP
