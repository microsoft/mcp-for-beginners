# Лучшие практики безопасности MCP — обновление за сентябрь 2026 года

Это всеобъемлющее руководство описывает основные лучшие практики безопасности для
внедрения систем Model Context Protocol (MCP) на основе
**Спецификации MCP 2026-07-28** и текущих отраслевых стандартов. Эти
практики охватывают как традиционные проблемы безопасности, так и специфические для ИИ угрозы,
уникальные для развертываний MCP.

## Критические требования безопасности

### Обязательные меры безопасности (требования MUST)

1. **Проверка токенов**: MCP-серверы **НЕ ДОЛЖНЫ** принимать токены, которые явно не были выданы для самого MCP-сервера
2. **Проверка авторизации**: MCP-серверы, реализующие авторизацию, **ДОЛЖНЫ** проверять ВСЕ входящие запросы и **НЕ ДОЛЖНЫ** использовать сессии для аутентификации  
3. **Согласие пользователя**: MCP-прокси-серверы с использованием статических сторонних идентификаторов клиентов **ДОЛЖНЫ** получать явное согласие для каждого MCP-клиента перед пересылкой потока авторизации
4. **Безопасность дескрипторов состояния**: MCP-серверы **НЕ ДОЛЖНЫ** считать владение дескриптором состояния приложения аутентификацией и **ДОЛЖНЫ** авторизовывать каждый
	запрос, который его использует


## Основные практики безопасности

### 1. Валидация и санитаризация входных данных
- **Комплексная валидация входных данных**: Валидируйте и обрабатывайте все входные данные для предотвращения атак инъекций, проблем с «запутавшимся посредником» и уязвимостей внедрения подсказок
- **Принудительное соблюдение схем параметров**: Реализуйте строгую валидацию JSON-схемы для всех параметров инструментов и входных данных API
- **Фильтрация содержимого**: Используйте Microsoft Prompt Shields и Azure Content Safety для фильтрации вредоносного контента в подсказках и ответах
- **Санитаризация вывода**: Валидируйте и очищайте все результаты моделей перед их представлением пользователям или системам

### 2. Исключительное управление аутентификацией и авторизацией  
- **Внешние поставщики идентификации**: Делегируйте аутентификацию проверенным поставщикам идентификации (Microsoft Entra ID, провайдеры OAuth 2.1), а не реализуйте собственную аутентификацию
- **Регистрация клиентов**: Предпочитайте документы метаданных клиентского идентификатора или предварительную регистрацию; используйте устаревшую динамическую регистрацию клиентов только для совместимости
- **Тонкая настройка разрешений**: Реализуйте гранулярные разрешения инструментов согласно принципу минимальных привилегий
- **Управление жизненным циклом токенов**: Используйте краткоживущие токены доступа с безопасной ротацией и корректной проверкой аудитории
- **Многофакторная аутентификация**: Требуйте МФА для всего административного доступа и операций с повышенной чувствительностью

### 3. Безопасные протоколы связи
- **Защита транспортного уровня**: Используйте HTTPS с корректной проверкой сертификатов
	для удаленной HTTP-связи MCP; используйте изоляцию процессов и
	учетные данные окружения для локальных stdio-серверов
- **Сквозное шифрование**: Реализуйте дополнительные слои шифрования для особо чувствительных данных при передаче и хранении
- **Управление сертификатами**: Поддерживайте жизненный цикл сертификатов с автоматизированными процессами обновления
- **Обязательное соблюдение версии протокола**: Используйте MCP версии `2026-07-28`, включайте требуемые
	метаданные версии в каждом запросе и отклоняйте неподдерживаемые версии

### 4. Продвинутое ограничение скорости и защита ресурсов
- **Многоуровневое ограничение скорости**: Реализуйте ограничение скорости по пользователю, учетным данным,
  операциям, инструментам и ресурсам для предотвращения злоупотреблений
- **Адаптивное ограничение скорости**: Используйте основанное на машинном обучении ограничение скорости, которое адаптируется к паттернам использования и индикаторам угроз
- **Управление квотами ресурсов**: Устанавливайте соответствующие лимиты для вычислительных ресурсов, использования памяти и времени выполнения
- **Защита от DDoS**: Развертывайте комплексную защиту от DDoS и системы анализа трафика

### 5. Всеобъемлющий аудит и мониторинг
- **Структурированное ведение журналов аудита**: Реализуйте подробные, поисковые логи для всех операций MCP, запусков инструментов и событий безопасности
- **Мониторинг безопасности в реальном времени**: Развертывайте SIEM-системы с ИИ-движком для обнаружения аномалий в нагрузках MCP
- **Журналирование с учетом конфиденциальности**: Ведите логи событий безопасности с соблюдением требований к конфиденциальности данных и нормативов
- **Интеграция с реагированием на инциденты**: Подключайте системы журналирования к автоматизированным процессам реагирования на инциденты

### 6. Продвинутые практики безопасного хранения
- **Аппаратные модули безопасности**: Используйте хранилища ключей на основе HSM (Azure Key Vault, AWS CloudHSM) для критических криптографических операций
- **Управление ключами шифрования**: Реализуйте корректную ротацию ключей, их сегрегацию и контроль доступа к ключам шифрования
- **Управление секретами**: Храните все API-ключи, токены и учетные данные в специализированных системах управления секретами
- **Классификация данных**: Классифицируйте данные по уровням чувствительности и применяйте соответствующие меры защиты

### 7. Продвинутое управление токенами
- **Запрет обхода с передачей токенов**: Явно запрещайте схемы передачи токенов, обходящие меры безопасности
- **Проверка аудитории**: Всегда проверяйте, что утверждения токена об аудитории соответствуют целевому MCP-серверу
- **Авторизация на базе утверждений**: Реализуйте тонкую авторизацию на основе утверждений токена и атрибутов пользователя
- **Привязка токенов**: Проверяйте, что токены предназначены для нужного ресурса MCP и
	привязывайте дескрипторы состояния приложения на стороне сервера к аутентифицированному субъекту

### 8. Безопасное состояние приложения

- **Криптографические дескрипторы состояния**: Генерируйте непрозрачные, недетерминированные дескрипторы
	для состояния, распространяющегося между запросами
- **Привязка к конкретному пользователю**: Привязывайте каждый дескриптор на стороне сервера к аутентифицированному
	субъекту; не доверяйте идентификатору пользователя, предоставленному клиентом
- **Контроль жизненного цикла**: Истекайте и отзывайте дескрипторы и определяйте, как вызывающие стороны
	восстанавливаются из устаревшего состояния
- **Авторизация по каждому запросу**: Перепроверяйте авторизацию при каждом предъявлении дескриптора;
	дескриптор — это имя, а не учетные данные

### 9. Специфические меры безопасности для ИИ
- **Защита от инъекций подсказок**: Разверните Microsoft Prompt Shields с подсветкой, разделителями и методами маркировки данных
- **Защита от отравления инструментов**: Проверяйте метаданные инструментов, контролируйте динамические изменения и проверяйте целостность инструментов
- **Валидация вывода модели**: Сканируйте вывод модели на наличие потенциальных утечек данных, вредоносного контента или нарушений политики безопасности
- **Защита контекстного окна**: Реализуйте меры для предотвращения отравления контекстного окна и атак манипулирования

### 10. Безопасность выполнения инструментов
- **Изоляция выполнения**: Запускайте выполнение инструментов в контейнеризированных, изолированных средах с ограничением ресурсов
- **Разделение привилегий**: Выполняйте инструменты с минимальными требуемыми привилегиями и отдельными учетными записями служб
- **Изоляция сети**: Реализуйте сегментацию сети для сред выполнения инструментов
- **Мониторинг выполнения**: Отслеживайте выполнение инструментов на предмет аномального поведения, использования ресурсов и нарушений безопасности

### 11. Непрерывная проверка безопасности
- **Автоматизированное тестирование безопасности**: Интегрируйте тестирование безопасности в CI/CD-пайплайны с использованием инструментов, таких как GitHub Advanced Security
- **Управление уязвимостями**: Регулярно сканируйте все зависимости, включая модели ИИ и внешние сервисы
- **Пентестинг**: Проводите регулярные оценки безопасности, специально направленные на реализации MCP
- **Код-ревью безопасности**: Обеспечивайте обязательное проведение проверок безопасности для всех изменений кода, связанных с MCP

### 12. Безопасность цепочки поставок ИИ
- **Проверка компонентов**: Проверяйте происхождение, целостность и безопасность всех компонентов ИИ (модели, эмбеддинги, API)
- **Управление зависимостями**: Поддерживайте актуальные инвентаризации всех программных и ИИ-зависимостей с отслеживанием уязвимостей
- **Доверенные хранилища**: Используйте проверенные, надежные источники для всех моделей, библиотек и инструментов ИИ
- **Мониторинг цепочки поставок**: Постоянно отслеживайте возможные компрометации поставщиков ИИ-сервисов и хранилищ моделей

## Расширенные шаблоны безопасности

### Архитектура с нулевым доверием для MCP
- **Никому не доверять, все проверять**: Реализуйте непрерывную проверку всех участников MCP
- **Микросегментация**: Изолируйте компоненты MCP с помощью детализированных сетевых и идентификационных контролей
- **Условный доступ**: Реализуйте управление доступом на основе оценки рисков, адаптирующееся к контексту и поведению
- **Непрерывная оценка рисков**: Динамически оценивайте уровень безопасности на основе текущих индикаторов угроз

### Реализация конфиденциального ИИ
- **Минимизация данных**: Предоставляйте только минимально необходимые данные для каждой операции MCP
- **Дифференциальная приватность**: Используйте методы защиты конфиденциальности при обработке чувствительных данных
- **Гомоморфное шифрование**: Применяйте современные методы шифрования для безопасных вычислений на зашифрованных данных
- **Федеративное обучение**: Реализуйте распределенное обучение, сохраняющее локальность данных и конфиденциальность

### Реагирование на инциденты для ИИ-систем
- **Процедуры реагирования, специфичные для ИИ**: Разработайте процедуры реагирования, ориентированные на угрозы ИИ и MCP
- **Автоматизированное реагирование**: Реализуйте автоматическое ограничение и устранение последствий распространенных инцидентов безопасности ИИ  
- **Возможности судебной экспертизы**: Поддерживайте готовность к проведению судебно-технических расследований при компрометации ИИ-систем и утечках данных
- **Процедуры восстановления**: Установите процессы восстановления после отравления моделей ИИ, атак внедрения подсказок и компрометаций сервисов
