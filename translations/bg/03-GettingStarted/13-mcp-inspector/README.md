# Отстраняване на грешки с MCP Inspector

> [!NOTE]
> Команди с `--sse` и URL адреси, завършващи на `/sse`, тестват наследения HTTP+SSE
> транспорт. За нов сървър MCP `2026-07-28` използвайте версия на Inspector, която
> поддържа Streamable HTTP и изберете този транспорт вместо това.

**MCP Inspector** е незаменим инструмент за отстраняване на грешки, който ви позволява интерактивно да тествате и отстранявате проблеми със сървърите MCP без да е необходим пълен домакин на AI приложение. Мислете за него като за "Postman за MCP" - предоставя визуален интерфейс за изпращане на заявки, преглед на отговори и разбиране на поведението на вашия сървър.

## Защо да използваме MCP Inspector?

При изграждане на MCP сървъри често се сблъсквате със следните предизвикателства:

- **"Изобщо работи ли сървърът ми?"** - Inspector показва статус на връзката
- **"Инструментите ми регистрирани ли са правилно?"** - Inspector показва всички налични инструменти
- **"Какъв е форматът на отговора?"** - Inspector показва пълните JSON отговори
- **"Защо този инструмент не работи?"** - Inspector показва подробни съобщения за грешки

## Предварителни условия

- Инсталиран Node.js 18+
- npm (идва с Node.js)
- Сървър MCP за тестване (вж. [Module 3.1 - First Server](../01-first-server/README.md))

## Инсталация

### Вариант 1: Стартиране с npx (Препоръчително за бързо тестване)

```bash
npx @modelcontextprotocol/inspector
```

### Вариант 2: Глобална инсталация

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### Вариант 3: Добавяне към вашия проект

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

Добавете в `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## Свързване към вашия сървър

### stdio сървъри (локален процес)

За сървъри, които комуникират чрез стандартен вход/изход:

```bash
# Python сървър
npx @modelcontextprotocol/inspector python -m your_server_module

# Node.js сървър
npx @modelcontextprotocol/inspector node ./build/index.js

# С променливи на средата
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP сървъри (мрежа)

За сървъри, работещи като HTTP услуги:

1. Стартирайте първо вашия сървър:
   ```bash
   python server.py  # Сървърът работи на http://localhost:8080
   ```

2. Стартирайте Inspector и се свържете:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## Тестване на инструменти

### Изброяване на наличните инструменти

1. Натиснете таба **Tools**
2. Inspector автоматично извиква `tools/list`
3. Ще видите всички регистрирани инструменти с:
   - Име на инструмента
   - Описание
   - Входна схема (параметри)

### Извикване на инструмент

1. Изберете инструмент от списъка
2. Попълнете необходимите параметри във формата
3. Натиснете **Run Tool**
4. Прегледайте отговора в панела с резултати

**Пример: Тестване на калкулатор**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### Отстраняване на грешки при инструментите

Когато инструментът се провали, Inspector показва:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

Чести кодове за грешка:
| Код | Значение |
|------|---------|
| -32700 | Грешка при анализ (невалиден JSON) |
| -32600 | Невалидна заявка |
| -32601 | Методът не е намерен |
| -32602 | Невалидни параметри |
| -32603 | Вътрешна грешка |

## Тестване на ресурси

### Изброяване на ресурсите

1. Натиснете таба **Resources**
2. Inspector извиква `resources/list`
3. Ще видите:
   - URI на ресурси
   - Имена и описания
   - MIME типове

### Четене на ресурс

1. Изберете ресурс
2. Натиснете **Read Resource**
3. Прегледайте върнатото съдържание

**Примерен изход:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## Тестване на подсказки

### Изброяване на подсказки

1. Натиснете таба **Prompts**
2. Inspector извиква `prompts/list`
3. Прегледайте наличните шаблони за подсказки

### Получаване на подсказка

1. Изберете подсказка
2. Попълнете всички необходими аргументи
3. Натиснете **Get Prompt**
4. Вижте изобразените съобщения с подсказки

## Анализ на лог на съобщенията

Логът на съобщенията показва всички съобщения от протокола MCP. Транскрипцията по-долу е от
наследен сървър `2025-11-25` и включва премахнатото ръкостискане `initialize`. Сървър от
`2026-07-28` използва самостоятелна мета информация за заявките и `server/discover`
вместо това.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### Какво да търсите

- **Двойки заявка/отговор**: Всяка `→` трябва да има съответстващо `←`
- **Съобщения за грешки**: Търсете `"error"` в отговорите
- **Времеви интервали**: Големи паузи могат да индикират проблеми с производителността
- **Версия на протокола**: Уверете се, че сървърът и клиента са съгласни относно версията

## Интеграция с VS Code

Можете да стартирате Inspector директно от VS Code:

### Използване на launch.json

Добавете в `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

### Използване на задачи (Tasks)

Добавете в `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Start MCP Inspector",
      "type": "shell",
      "command": "npx @modelcontextprotocol/inspector node ${workspaceFolder}/build/index.js",
      "isBackground": true,
      "problemMatcher": {
        "pattern": {
          "regexp": "^$"
        },
        "background": {
          "activeOnStart": true,
          "beginsPattern": "Inspector",
          "endsPattern": "listening"
        }
      }
    }
  ]
}
```

## Чести сценарии за отстраняване на грешки

### Сценарий 1: Сървърът не се свързва

**Симптоми:** Inspector показва "Disconnected" или зацикля на "Connecting..."

**Контролен списък:**
1. ✅ Правилна ли е командата за сървъра?
2. ✅ Всички зависимости инсталирани ли са?
3. ✅ Пътят към сървъра абсолютен ли е или относителен към текущата директория?
4. ✅ Зададени ли са необходимите променливи на средата?

**Стъпки за отстраняване на грешки:**
```bash
# Първо тествайте сървъра ръчно
python -c "import your_server_module; print('OK')"

# Проверете за грешки при импортиране
python -m your_server_module 2>&1 | head -20

# Потвърдете, че MCP SDK е инсталиран
pip show mcp
```

### Сценарий 2: Инструменти не се появяват

**Симптоми:** Табът Tools е с празен списък

**Възможни причини:**
1. Инструментите не са регистрирани при инициализацията на сървъра
2. Сървърът е спрял да работи след стартиране
3. Обработчикът `tools/list` връща празен масив

**Стъпки за отстраняване на грешки:**
1. Проверете логовете за отговора на `tools/list`
2. Добавете логване във вашия код за регистрация на инструменти
3. Уверете се, че декораторите `@mcp.tool()` са налице (Python)

### Сценарий 3: Инструмент връща грешка

**Симптоми:** Обаждането на инструмента връща грешка

**Подход за отстраняване:**
1. Прочетете внимателно съобщението за грешка
2. Проверете дали типовете параметри съвпадат със схемата
3. Добавете try/catch с подробни съобщения за грешка
4. Проверете логовете на сървъра за стек траси

**Пример за подобрено обработване на грешки:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # Логика на инструмента тук
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### Сценарий 4: Съдържанието на ресурс е празно

**Симптоми:** Ресурсът се връща, но съдържанието е празно или null

**Контролен списък:**
1. ✅ Пътят до файла или URI е правилен
2. ✅ Сървърът има разрешение да чете ресурса
3. ✅ Съдържанието на ресурса се връща правилно

## Разширени функции на Inspector

### Персонализирани заглавки (SSE)

```bash
npx @modelcontextprotocol/inspector \
  --sse http://localhost:8080/sse \
  --header "Authorization: Bearer your-token"
```

### Подробно логване

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### Запис на сесии

Inspector може да експортира логове на съобщения за по-късен анализ:
1. Натиснете **Export Log** в панела за съобщения
2. Запазете JSON файла
3. Споделете с членове на екипа за отстраняване на грешки

## Най-добри практики

1. **Тествайте рано и често** - Използвайте Inspector по време на разработка, не само при проблеми
2. **Започнете просто** - Тествайте основната свързаност преди сложни обаждания към инструменти
3. **Проверявайте схемата** - Много грешки идват от несъответствие на типовете параметри
4. **Четете съобщенията за грешки** - Грешките в MCP обикновено са описателни
5. **Дръжте Inspector отворен** - Помага да се хващат проблеми в процеса на разработка
