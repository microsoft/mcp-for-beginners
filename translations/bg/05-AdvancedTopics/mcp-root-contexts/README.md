# Корени на MCP (Старовременна Функция)

> [!WARNING]
> Корените са остарели от MCP `2026-07-28`. Те остават в тази ревизия за
> съвместимост и подлежат на премахване в първата спецификационна
> ревизия, издадена на или след 28 юли 2027. Новите имплементации трябва да предават
> директории или файлове чрез параметри на инструмента, ресурси URIs или сървърна
> конфигурация.

## Обзор

Корените позволяват на MCP клиент да каже на сървъра кои файлови системни местоположения са релевантни
за текущата заявка. Коренът съдържа задължителен `file://` URI и незадължително
човеко-четимо име.

Корените са информативни подсказки. Те не са контейнери за история на разговори,
протоколови сесии или механизъм за контрол на достъпа. Протоколът не
наложва сървърът да остане в рамките на изброените корени.

## Цели на обучението

Към края на този урок ще можете да:

- Обясните какво представляват корените на MCP и какво не представляват.
- Разпознавате текущия многоходов поток `roots/list`.
- Прилагате мерки за сигурност независимо от корените.
- Мигрирате нови имплементации към поддържани алтернативи.

## Данни за корен

Клиентът връща всеки корен като `file://` URI с незадължително име за показване:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

Клиентите трябва да показват само местоположения, одобрени от потребителя. Сървърите трябва да третират
резултата като насока за релевантни файлове, а не като доказателство за авторизация.

## Поток MCP 2026-07-28

Клиент, който поддържа корени, заявява тази възможност при всяка заявка:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

Докато обработва клиентска заявка, сървърът може да върне
`InputRequiredResult`, съдържащ заявка за вход `roots/list`:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

Клиентът събира одобрените корени и опитва отново първоначалната заявка с
съответните `inputResponses` и непроменено `requestState`. Този многоходов
модел запазва протокола безсъстоятелен; няма ръкостискане `initialize` или
протоколово ниво сесия.

## Старовременна Поведение от 2025-11-25

В MCP `2025-11-25` клиентите рекламираха корените по време на инициализация. Сървърът
можеше да издава директна заявка `roots/list`, а клиентът можеше да изпрати
`notifications/roots/list_changed`, когато корените му се променят.

Този жизнен цикъл е старовременна функционалност. Не комбинирайте примерите за инициализация или
известяване с имплементация от `2026-07-28`.

## Препоръчани заместители

### Параметри на инструмента

Направете необходимата директория или файл явен в схемата на инструмента:

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### Ресурсни URIs

Използвайте ресурси MCP, когато сървър може да предостави релевантните файлове чрез стабилни
URIs. Това прави откриването и извличането явни.

### Конфигурация на сървъра

За фиксирани разполагания конфигурирайте разрешените директории при стартиране на сървъра.
Това често е по-ясно отколкото да ги откривате по време на извикване на инструмента.

## Изисквания за сигурност

Какъвто и заместител да изберете:

- Получете съгласие от потребителя преди показване на файлови системни места.
- Канонизирайте и валидирайте пътищата, за да предотвратите обход.
- Налагайте авторизация и пясъчник независимо от стойностите на корените.
- Преоценявайте разрешенията при достъп до файла, не само при изброяване.
- Избягвайте връщането на чувствителни пътища в логове или съобщения за грешки.

## Основни изводи

- Корените описват релевантни файлови системни местоположения; не съхраняват състояние на разговори.

- Корените са насоки, а не граница за контрол на достъпа.
- MCP `2026-07-28` пренася възможността за всяка заявка и използва
  `InputRequiredResult` за `roots/list`.
- Новите имплементации трябва да използват параметри на инструмента, ресурсни URIs или сървърна
  конфигурация.
