# دیباگ با MCP Inspector

> [!NOTE]
> دستورات استفاده کننده از `--sse` و URLهایی که با `/sse` پایان می‌یابند، انتقال قدیمی HTTP+SSE را آزمایش می‌کنند.
> برای یک سرور جدید MCP `2026-07-28`، از نسخه Inspector استفاده کنید که
> از Streamable HTTP پشتیبانی می‌کند و به جای آن انتقال را انتخاب کنید.

ابزار **MCP Inspector** یک ابزار اساسی برای دیباگ است که به شما اجازه می‌دهد تا سرورهای MCP خود را به صورت تعاملی تست و عیب‌یابی کنید بدون نیاز به یک برنامه میزبان هوش مصنوعی کامل. می‌توانید آن را "Postman برای MCP" در نظر بگیرید - این ابزار واسط بصری برای ارسال درخواست‌ها، مشاهده پاسخ‌ها و درک رفتار سرور شما فراهم می‌کند.

## چرا از MCP Inspector استفاده کنیم؟

هنگام ساخت سرورهای MCP، اغلب با این چالش‌ها مواجه می‌شوید:

- **"آیا سرور من اصلاً در حال اجرا است؟"** - Inspector وضعیت اتصال را نمایش می‌دهد
- **"آیا ابزارهای من به درستی ثبت شده‌اند؟"** - Inspector تمام ابزارهای موجود را فهرست می‌کند
- **"فرمت پاسخ چیست؟"** - Inspector پاسخ‌های کامل JSON را نمایش می‌دهد
- **"چرا این ابزار کار نمی‌کند؟"** - Inspector پیام‌های خطای دقیق را نشان می‌دهد

## پیش‌نیازها

- نصب Node.js نسخه 18 به بالا
- npm (همراه Node.js می‌آید)
- یک سرور MCP برای تست (برای مشاهده به [بخش ۳.۱ - اولین سرور](../01-first-server/README.md) مراجعه کنید)

## نصب

### گزینه ۱: اجرا با npx (توصیه شده برای تست سریع)

```bash
npx @modelcontextprotocol/inspector
```

### گزینه ۲: نصب به صورت سراسری (Global)

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### گزینه ۳: افزودن به پروژه شما

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

افزودن به `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## اتصال به سرور شما

### سرورهای stdio (فرآیند محلی)

برای سرورهایی که از ورودی/خروجی استاندارد ارتباط برقرار می‌کنند:

```bash
# سرور پایتون
npx @modelcontextprotocol/inspector python -m your_server_module

# سرور Node.js
npx @modelcontextprotocol/inspector node ./build/index.js

# با متغیرهای محیطی
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### سرورهای SSE/HTTP (شبکه)

برای سرورهایی که به عنوان سرویس HTTP اجرا می‌شوند:

1. ابتدا سرور خود را راه‌اندازی کنید:
   ```bash
   python server.py  # سرور در حال اجرا در http://localhost:8080
   ```

2. Inspector را اجرا کنید و متصل شوید:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## تست ابزارها

### فهرست ابزارهای موجود

1. برگه **Tools** را کلیک کنید
2. Inspector به طور خودکار `tools/list` را فراخوانی می‌کند
3. همه ابزارهای ثبت شده را خواهید دید با:
   - نام ابزار
   - توضیحات
   - قالب ورودی (پارامترها)

### فراخوانی یک ابزار

1. یک ابزار را از لیست انتخاب کنید
2. پارامترهای لازم را در فرم پر کنید
3. بر روی **Run Tool** کلیک کنید
4. پاسخ را در پنل نتایج مشاهده کنید

**مثال: تست یک ابزار ماشین حساب**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### اشکال‌زدایی خطاهای ابزار

وقتی یک ابزار شکست می‌خورد، Inspector نمایش می‌دهد:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

کدهای متداول خطا:
| کد | معنی |
|------|---------|
| -32700 | خطای تجزیه (JSON نامعتبر) |
| -32600 | درخواست نامعتبر |
| -32601 | روش یافت نشد |
| -32602 | پارامترهای نامعتبر |
| -32603 | خطای داخلی |

## تست منابع

### فهرست منابع

1. برگه **Resources** را کلیک کنید
2. Inspector فراخوانی می‌کند `resources/list`
3. خواهید دید:
   - URIهای منابع
   - نام‌ها و توضیحات
   - نوع MIME

### خواندن یک منبع


1. یک منبع را انتخاب کنید
2. روی **خواندن منبع** کلیک کنید
3. محتوای بازگشتی را مشاهده کنید

**خروجی مثال:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## آزمایش درخواست‌ها

### فهرست‌کردن درخواست‌ها

1. روی زبانه **درخواست‌ها** کلیک کنید
2. بازرس `prompts/list` را فرا می‌خواند
3. قالب‌های درخواست در دسترس را مشاهده کنید

### دریافت یک درخواست

1. یک درخواست انتخاب کنید
2. هر آرگومان مورد نیاز را پر کنید
3. روی **دریافت درخواست** کلیک کنید
4. پیام‌های درخواست رندر شده را ببینید

---

## تحلیل ثبت پیام‌ها

ثبت پیام‌ها همه پیام‌های پروتکل MCP را نشان می‌دهد. نسخه زیر مکالمه‌ای است از 
سرور قدیمی `2025-11-25` که دست دادن `initialize` حذف شده را شامل می‌شود. 
سرور `2026-07-28` به جای آن از متادیتای درخواست مستقل و `server/discover` استفاده می‌کند.


```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### نکاتی برای بررسی

- **زوج درخواست/پاسخ**: هر `→` باید یک `←` معادل داشته باشد
- **پیغام‌های خطا**: به دنبال `"error"` در پاسخ‌ها باشید
- **زمان‌بندی**: فاصله‌های زیاد ممکن است مشکلات عملکردی را نشان دهد
- **نسخه پروتکل**: اطمینان حاصل کنید سرور و کلاینت بر سر نسخه توافق دارند

## یکپارچه‌سازی با VS Code

می‌توانید بازرس را مستقیماً از VS Code اجرا کنید:

### استفاده از launch.json

اضافه کنید به `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

### استفاده از تسک‌ها

اضافه کنید به `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Start MCP Inspector",
      "type": "shell",
      "command": "npx @modelcontextprotocol/inspector node ${workspaceFolder}/build/index.js",
      "isBackground": true,
      "problemMatcher": {
        "pattern": {
          "regexp": "^$"
        },
        "background": {
          "activeOnStart": true,
          "beginsPattern": "Inspector",
          "endsPattern": "listening"
        }
      }
    }
  ]
}
```

## سناریوهای رایج اشکال‌زدایی

### سناریو 1: سرور اتصال برقرار نمی‌کند

**نشانه‌ها:** بازرس "قطع شده" را نمایش می‌دهد یا در "اتصال..." گیر می‌کند

**فهرست بررسی:**
1. ✅ آیا فرمان سرور صحیح است؟
2. ✅ آیا همه وابستگی‌ها نصب شده‌اند؟
3. ✅ آیا مسیر سرور مطلق است یا نسبت به دایرکتوری جاری؟
4. ✅ آیا متغیرهای محیطی مورد نیاز تنظیم شده‌اند؟

**گام‌های اشکال‌زدایی:**
```bash
# ابتدا سرور را به صورت دستی آزمایش کنید
python -c "import your_server_module; print('OK')"

# بررسی خطاهای واردات
python -m your_server_module 2>&1 | head -20

# اطمینان حاصل کنید که MCP SDK نصب شده است
pip show mcp
```

### سناریو 2: ابزارها نمایش داده نمی‌شوند

**نشانه‌ها:** زبانه ابزارها فهرست خالی نشان می‌دهد

**دلایل ممکن:**
1. ابزارها در زمان راه‌اندازی سرور ثبت نشده‌اند
2. سرور بعد از شروع سقوط کرده است
3. هندلر `tools/list` آرایه خالی بازمی‌گرداند

**گام‌های اشکال‌زدایی:**
1. ثبت پیام‌ها را برای پاسخ `tools/list` بررسی کنید
2. به کد ثبت ابزار خود لاگ‌گذاری اضافه کنید
3. اطمینان حاصل کنید دکوراتورهای `@mcp.tool()` وجود دارند (پایتون)

### سناریو 3: ابزار خطا بازمی‌گرداند

**نشانه‌ها:** فراخوانی ابزار پاسخ خطا می‌دهد

**رویکرد اشکال‌زدایی:**
1. پیام خطا را با دقت بخوانید
2. بررسی کنید نوع پارامترها با طرح مطابقت دارند
3. try/catch با پیام‌های خطای تفصیلی اضافه کنید
4. لاگ‌های سرور برای دنبالۀ پشته را بررسی کنید

**نمونه بهبود یافته مدیریت خطا:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # منطق ابزار اینجا
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### سناریو 4: محتوای منبع خالی است

**نشانه‌ها:** منبع بازگشتی اما محتوا خالی یا نال است

**فهرست بررسی:**
1. ✅ مسیر فایل یا URI صحیح است
2. ✅ سرور اجازه خواندن منبع را دارد
3. ✅ محتوای منبع به درستی بازگردانده می‌شود

## بهترین شیوه‌ها

1. **زود و مکرراً آزمایش کنید** - از Inspector در طول توسعه استفاده کنید، نه فقط وقتی که مشکلات رخ می‌دهد
2. **با ساده شروع کنید** - قبل از فراخوانی‌های ابزار پیچیده، اتصال پایه را آزمایش کنید
3. **طرح‌واره را بررسی کنید** - بسیاری از خطاها ناشی از ناسازگاری نوع پارامترها است
4. **پیام‌های خطا را بخوانید** - خطاهای MCP معمولاً توصیفی هستند
5. **Inspector را باز نگه دارید** - این کمک می‌کند مشکلات را در حین توسعه شناسایی کنید
