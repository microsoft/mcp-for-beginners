# بهترین شیوه‌های امنیتی MCP - به‌روزرسانی سپتامبر ۲۰۲۶

این راهنمای جامع، بهترین شیوه‌های امنیتی ضروری برای اجرای سیستم‌های پروتکل زمینه مدل (MCP) را بر اساس
**مشخصات MCP ۲۰۲۶-۰۷-۲۸** و استانداردهای صنعت فعلی ترسیم می‌کند. این
شیوه‌ها هم نگرانی‌های امنیتی سنتی و هم تهدیدات خاص هوش مصنوعی
که در استقرارهای MCP منحصر به فرد است را پوشش می‌دهد.


## الزامات امنیتی حیاتی

### کنترل‌های امنیتی اجباری (الزامات باید)

1. **اعتبارسنجی توکن**: سرورهای MCP **نباید** هیچ توکنی را بپذیرند که صراحتاً برای خود سرور MCP صادر نشده باشد
2. **تأیید مجوز**: سرورهای MCP که مجوزدهی را پیاده‌سازی می‌کنند **باید** تمام درخواست‌های ورودی را تأیید کنند و **نباید** از جلسات برای احراز هویت استفاده کنند  
3. **رضایت کاربر**: سرورهای پروکسی MCP که از شناسه‌های کلاینت سوم‌شخص ثابت استفاده می‌کنند **باید** قبل از ارسال جریان مجوز برای هر کلاینت MCP رضایت صریح بگیرند
4. **امنیت هندل حالت**: سرورهای MCP **نباید** مالکیت هندل حالت برنامه را به عنوان احراز هویت تلقی کنند و **باید** هر
	درخواستی که از آن استفاده می‌کند را مجاز کنند


## شیوه‌های اصلی امنیتی

### ۱. اعتبارسنجی و پالایش ورودی
- **اعتبارسنجی جامع ورودی**: تمام ورودی‌ها را اعتبارسنجی و پالایش کنید تا از حملات تزریقی، مشکلات نماینده اشتباه و آسیب‌پذیری‌های تزریق پرامپت جلوگیری شود
- **اجرای طرح پارامترها**: اعتبارسنجی دقیق طرح JSON را برای همه پارامترهای ابزار و ورودی‌های API پیاده کنید
- **فیلتر کردن محتوا**: از Microsoft Prompt Shields و Azure Content Safety برای فیلتر کردن محتوای مخرب در پرامپت‌ها و پاسخ‌ها استفاده کنید
- **پالایش خروجی**: تمام خروجی‌های مدل را قبل از ارائه به کاربران یا سیستم‌های پایین‌دستی اعتبارسنجی و پالایش کنید

### ۲. برتری احراز هویت و مجوزدهی  
- **ارائه‌دهندگان هویت خارجی**: احراز هویت را به ارائه‌دهندگان هویت معتبر (Microsoft Entra ID، ارائه‌دهندگان OAuth 2.1) واگذار کنید به جای پیاده‌سازی احراز هویت سفارشی
- **ثبت نام کلاینت**: سندهای متادیتای شناسه کلاینت را ترجیح دهید یا پیش‌ثبت‌نام انجام دهید؛ استفاده از ثبت‌نام کلاینت داینامیک منسوخ را فقط برای سازگاری به کار ببرید
- **مجوزهای دقیق**: مجوزهای دقیق و مخصوص به هر ابزار را بر اساس اصل حداقل امتیاز اعمال کنید
- **مدیریت چرخه عمر توکن**: از توکن‌های دسترسی کوتاه‌مدت با چرخش امن و اعتبارسنجی مناسب مخاطب استفاده کنید
- **احراز هویت چند عاملی**: MFA برای دسترسی‌های مدیریتی و عملیات حساس لازم است

### ۳. پروتکل‌های ارتباطی امن
- **امنیت لایه انتقال**: برای ارتباطات HTTP راه دور MCP از HTTPS با اعتبارسنجی صحیح گواهی استفاده کنید
	؛ برای سرورهای stdio محلی از جداسازی فرآیند و گواهی‌نامه‌های محیطی بهره ببرید

- **رمزنگاری نقطۀ انتها به انتها**: لایه‌های رمزنگاری اضافی برای داده‌های بسیار حساس در حال انتقال و ذخیره‌سازی اعمال کنید
- **مدیریت گواهی‌نامه**: چرخه عمر گواهی‌نامه را با فرآیندهای تجدید خودکار مدیریت کنید
- **اجرای نسخه پروتکل**: از نسخه MCP `2026-07-28` استفاده کنید، متادیتای نسخه موردنیاز را روی هر درخواست قرار دهید و نسخه‌های پشتیبانی‌نشده را رد کنید


### ۴. محدودسازی پیشرفته نرخ و حفاظت منابع
- **محدودسازی نرخ چندلایه**: محدودسازی نرخ را بر اساس کاربر، گواهی‌نامه،
  عملیات، ابزار و منبع اجرا کنید تا از سوءاستفاده جلوگیری شود
- **محدودسازی نرخ انطباقی**: از محدودسازی نرخ مبتنی بر یادگیری ماشینی که با الگوهای استفاده و شاخص‌های تهدید سازگار است استفاده کنید
- **مدیریت سهمیه منابع**: محدودیت‌های مناسب برای منابع محاسباتی، مصرف حافظه و زمان اجرا تعیین کنید
- **حفاظت در برابر DDoS**: سیستم‌های جامع حفاظت در برابر DDoS و تحلیل ترافیک مستقر کنید

### ۵. لاگ‌گیری و مانیتورینگ جامع
- **لاگ‌گیری حسابرسی ساخت‌یافته**: گزارش‌های دقیق و قابل جستجو برای همه عملیات MCP، اجرای ابزار و رویدادهای امنیتی پیاده کنید
- **مانیتورینگ امنیتی در زمان واقعی**: سیستم‌های SIEM با تشخیص ناهنجاری مبتنی بر هوش مصنوعی برای بارگذاری‌های MCP مستقر کنید
- **لاگ‌گیری مطابق حریم خصوصی**: رویدادهای امنیتی را با رعایت الزامات و مقررات حفظ حریم خصوصی ثبت کنید
- **ادغام پاسخ به حادثه**: سیستم‌های لاگ‌گیری را به گردش‌کارهای پاسخ خودکار به حادثه متصل کنید

### ۶. شیوه‌های پیشرفته ذخیره‌سازی امن
- **ماژول‌های امنیت سخت‌افزاری**: برای عملیات رمزنگاری حساس از ذخیره‌سازی کلید مبتنی بر HSM (Azure Key Vault، AWS CloudHSM) استفاده کنید
- **مدیریت کلیدهای رمزنگاری**: چرخش مناسب کلید، تفکیک و کنترل دسترسی برای کلیدهای رمزنگاری پیاده کنید
- **مدیریت اسرار**: تمام کلیدهای API، توکن‌ها و گواهی‌نامه‌ها را در سیستم‌های مدیریت اسرار اختصاصی ذخیره کنید
- **طبقه‌بندی داده‌ها**: داده‌ها را بر اساس سطوح حساسیت طبقه‌بندی و تدابیر حفاظتی مناسب اعمال کنید

### ۷. مدیریت پیشرفته توکن
- **جلوگیری از عبور توکن**: الگوهای عبور توکن که کنترل‌های امنیتی را دور می‌زنند صراحتاً ممنوع است
- **اعتبارسنجی مخاطب**: همیشه ادعاهای مخاطب توکن را با شناسه سرور MCP موردنظر مطابقت دهید
- **مجوزدهی مبتنی بر ادعا‌ها**: مجوزدهی دقیق بر اساس ادعاهای توکن و ویژگی‌های کاربر پیاده کنید
- **بایندینگ توکن**: اعتبارسنجی کنید که توکن‌ها هدف منبع MCP موردنظر هستند و
	هندل‌های حالت برنامه را سمت سرور به هویت احراز هویت شده متصل کنید

### ۸. حالت امن برنامه

- **هندل‌های رمزنگاری حالت**: هندل‌های مبهم و غیرقابل پیش‌بینی برای حالت‌هایی که در درخواست‌ها گسترده می‌شوند تولید کنید

- **بایندینگ مخصوص کاربر**: هر هندل را سمت سرور به هویت احراز هویت شده متصل کنید؛ به شناسه کاربری که توسط کلاینت ارائه شده اطمینان نکنید

- **کنترل چرخه عمر**: هندل‌ها را منقضی و ابطال کنید و نحوه بازیابی از حالت قدیمی توسط فراخواننده‌ها را تعریف کنید

- **مجوزدهی به ازای هر درخواست**: هر بار که یک هندل ارائه می‌شود مجوز را دوباره بررسی کنید؛ هندل اسم است، نه مدرک احراز هویت


### ۹. کنترل‌های امنیتی خاص هوش مصنوعی
- **دفاع در برابر تزریق پرامپت**: از Microsoft Prompt Shields با تکنیک‌های برجسته‌سازی، جداکننده‌ها و علامت‌گذاری داده استفاده کنید
- **جلوگیری از مسمومیت ابزارها**: متادیتای ابزار را اعتبارسنجی کنید، به تغییرات داینامیک نظارت داشته و یکپارچگی ابزار را بررسی کنید
- **اعتبارسنجی خروجی مدل**: خروجی‌های مدل را از نظر نشت داده، محتوای مضر یا تخلفات سیاست‌های امنیتی اسکن کنید
- **حفاظت از پنجره زمینه**: کنترل‌هایی برای جلوگیری از مسمومیت پنجره زمینه و حملات دستکاری پیاده کنید

### ۱۰. امنیت اجرای ابزار
- **اجرای در محیط‌های جدا شده**: اجرای ابزارها را در محیط‌های کانتینریز شده و ایزوله با محدودیت منابع انجام دهید
- **تفکیک امتیازات**: ابزارها را با کمترین امتیازات لازم و حساب‌های سرویس جداگانه اجرا کنید
- **ایزوله شبکه**: قطعه‌بندی شبکه را برای محیط‌های اجرای ابزار پیاده کنید
- **مانیتورینگ اجرا**: اجرای ابزار را به منظور رفتارهای ناهنجار، مصرف منابع و نقض‌های امنیتی نظارت کنید

### ۱۱. اعتبارسنجی مداوم امنیتی
- **آزمایش امنیت خودکار**: آزمایش امنیت را در خط تولید CI/CD با ابزارهایی مانند GitHub Advanced Security ادغام کنید
- **مدیریت آسیب‌پذیری**: به طور منظم تمامی وابستگی‌ها از جمله مدل‌های هوش مصنوعی و سرویس‌های خارجی را اسکن کنید
- **آزمایش نفوذ**: ارزیابی‌های امنیتی منظم مخصوص پیاده‌سازی‌های MCP انجام دهید
- **بازبینی کد امنیتی**: بازبینی اجباری امنیتی برای تمام تغییرات کد مرتبط با MCP پیاده کنید

### ۱۲. امنیت زنجیره تأمین برای هوش مصنوعی
- **تأیید مؤلفه‌ها**: اصالت، تمامیت و امنیت همه اجزای هوش مصنوعی (مدل‌ها، جاسازی‌ها، APIها) را تأیید کنید
- **مدیریت وابستگی‌ها**: موجودی‌های فعلی تمام وابستگی‌های نرم‌افزاری و هوش مصنوعی را با ردیابی آسیب‌پذیری نگهداری کنید
- **مخازن مورد اعتماد**: از منابع تأیید شده و قابل اعتماد برای همه مدل‌ها، کتابخانه‌ها و ابزارهای هوش مصنوعی استفاده کنید
- **نظارت بر زنجیره تأمین**: به طور پیوسته برای شناسایی نفوذ در ارائه‌دهندگان خدمات هوش مصنوعی و مخازن مدل‌ها نظارت کنید

## الگوهای پیشرفته امنیتی

### معماری اعتماد صفر برای MCP
- **هرگز اعتماد نکن، همیشه تأیید کن**: تأیید مداوم برای همه شرکت‌کنندگان MCP اجرا کنید
- **ریزقطعه‌بندی**: اجزای MCP را با کنترل‌های شبکه و هویت دقیق ایزوله کنید
- **دسترسی شرطی**: کنترل‌های دسترسی مبتنی بر ریسک که متناسب با زمینه و رفتار تنظیم می‌شوند، پیاده کنید
- **ارزیابی مداوم ریسک**: وضعیت امنیتی را به طور پویا بر اساس شاخص‌های تهدید فعلی ارزیابی کنید

### پیاده‌سازی حفظ حریم خصوصی هوش مصنوعی
- **حداقل‌سازی داده**: تنها حداقل داده لازم برای هر عملیات MCP را افشا کنید
- **حریم خصوصی تفاضلی**: تکنیک‌های حفظ حریم خصوصی برای پردازش داده‌های حساس پیاده کنید
- **رمزنگاری همومورفیک**: از تکنیک‌های پیشرفته رمزنگاری برای محاسبات امن روی داده‌های رمزنگاری‌شده استفاده کنید
- **یادگیری فدراسیون‌شده**: رویکردهای یادگیری توزیع‌شده که محل داده و حریم خصوصی را حفظ می‌کنند پیاده کنید

### پاسخ به حادثه برای سیستم‌های هوش مصنوعی
- **رویه‌های حادثه خاص هوش مصنوعی**: رویه‌های پاسخ به حادثه منطبق با تهدیدهای خاص هوش مصنوعی و MCP توسعه دهید
- **پاسخ خودکار**: مهار و اصلاح خودکار برای حوادث رایج امنیتی هوش مصنوعی پیاده کنید  
- **توانمندی‌های دادگاه دیجیتال**: آمادگی جرم‌یابی برای نفوذها و نشت داده‌های سیستم‌های هوش مصنوعی حفظ کنید
- **رویه‌های بازیابی**: رویه‌هایی برای بازیابی از مسمومیت مدل هوش مصنوعی، حملات تزریق پرامپت و نفوذ به سرویس‌ها ایجاد کنید
