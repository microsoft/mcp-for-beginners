## 🔧 理解 MCP 服务器：初学者指南

### 什么是 MCP 服务器？

作为模型上下文协议（MCP）的新手，你可能会想：“MCP 服务器到底是什么，我为什么要关心？”让我们用一个简单的类比开始。

把 MCP 服务器想象成专门的助手，帮助你的 AI 编程伴侣（如 GitHub Copilot）连接到外部工具和服务。就像你用手机上的不同应用完成不同任务——一个查天气，一个导航，一个银行业务——MCP 服务器赋予了你的 AI 助手与各种开发工具和服务互动的能力。

### MCP 服务器解决了什么问题

之前，如果你想：
- 查看你的 Azure 资源
- 创建 GitHub 问题
- 查询数据库
- 搜索文档

你得停止编码，打开浏览器，导航到相应的网站，然后手动执行这些任务。这种频繁的上下文切换打断你的流程，降低效率。

### MCP 服务器如何改变你的开发体验

通过 MCP 服务器，你可以留在你的开发环境（VS Code、Visual Studio 等），只需让 AI 助手帮你处理这些任务。例如：

**传统工作流：**
1. 停止编码
2. 打开浏览器
3. 进入 Azure 门户
4. 查询存储账号信息
5. 返回 VS Code
6. 继续编码

**现在可以这样做：**
1. 问 AI：“我的 Azure 存储账号状态如何？”
2. 使用提供的信息继续编码

### 初学者的主要好处

#### 1. 🔄 <strong>保持专注状态</strong>
- 无需频繁切换多个应用
- 继续专注于你的代码
- 降低管理不同工具的心理负担

#### 2. 🤖 **使用自然语言，无需复杂命令**
- 不用记忆 SQL 语法，只需描述你需要的数据
- 不用记忆 Azure CLI 命令，只需说明你的目标
- 让 AI 处理技术细节，你专注逻辑

#### 3. 🔗 <strong>连接多个工具</strong>
- 通过组合不同服务创建强大工作流
- 例如：“获取所有最近的 GitHub 问题并创建相应的 Azure DevOps 工作项”
- 无需编写复杂脚本即可实现自动化

#### 4. 🌐 <strong>访问日益增长的生态系统</strong>
- 受益于微软、GitHub 和其他公司的服务器
- 无缝搭配不同供应商的工具
- 加入一个跨不同 AI 助手通用的标准化生态

#### 5. 🛠️ <strong>边做边学</strong>
- 先用预构建服务器理解概念
- 随着熟练度提升逐步构建自己的服务器
- 利用可用的 SDK 和文档指导学习


## 在 VS Code 和 Visual Studio 中开始使用 MCP 🚀

如果你使用 Visual Studio Code 或带有 GitHub Copilot 的 Visual Studio 2022，设置这些 MCP 服务器非常简单。

### VS Code 设置

VS Code 的基本流程如下：

1. <strong>启用代理模式</strong>：在 VS Code 的 Copilot 聊天窗口切换到代理模式
2. **配置 MCP 服务器**：将服务器配置添加到 VS Code 的 settings.json 文件中
3. <strong>启动服务器</strong>：点击你想使用的每个服务器的“启动”按钮
4. <strong>选择工具</strong>：选择本次会话要启用的 MCP 服务器

有关详细设置说明，请参见[VS Code MCP 文档](https://code.visualstudio.com/docs/copilot/copilot-mcp)。

> **💡 专业提示：像专家一样管理 MCP 服务器！**
> 
> VS Code 扩展视图现在包括一个[方便的新界面来管理已安装的 MCP 服务器](https://code.visualstudio.com/docs/copilot/chat/mcp-servers#_use-mcp-tools-in-agent-mode)！你可以通过清晰简洁的界面快速启动、停止、管理任何已安装的 MCP 服务器。快去试试吧！

### Visual Studio 2022 设置

对于 Visual Studio 2022（版本 17.14 或更高）：

1. <strong>启用代理模式</strong>：点击 GitHub Copilot 聊天窗口中的“询问”下拉菜单并选择“代理”
2. <strong>创建配置文件</strong>：在解决方案目录中创建 `.mcp.json` 文件（建议位置：`<SOLUTIONDIR>\.mcp.json`）
3. <strong>配置服务器</strong>：使用标准 MCP 格式添加 MCP 服务器配置
4. <strong>工具批准</strong>：系统提示时，批准你想使用的工具并授予相应权限范围

有关详细 Visual Studio 设置说明，请参见[Visual Studio MCP 文档](https://learn.microsoft.com/visualstudio/ide/mcp-servers)。

每个 MCP 服务器都有自身的配置需求（连接字符串、认证等），但两个 IDE 的设置方式是一致的。

### 1. 📚 Microsoft Learn 文档 MCP 服务器

[![Install in VS Code](https://img.shields.io/badge/VS_Code-Install_Microsoft_Docs_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D) [![Install in VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Microsoft_Docs_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/microsoft/mcp)

<strong>功能</strong>：Microsoft Learn 文档 MCP 服务器是一个云托管服务，通过模型上下文协议为 AI 助手提供对官方微软文档的实时访问。它连接到 `https://learn.microsoft.com/api/mcp`，支持对 Microsoft Learn、Azure 文档、Microsoft 365 文档及其他官方微软资源的语义搜索。

<strong>为何有用</strong>：虽然看起来“只是文档”，但该服务器对每个使用微软技术的开发者来说至关重要。许多 .NET 开发者对 AI 编码助手的最大抱怨之一是其未及时掌握最新的 .NET 和 C# 版本。Microsoft Learn 文档 MCP 服务器通过提供最新文档、API 参考及最佳实践的实时访问解决了这个问题。无论你是在使用最新 Azure SDK，探索新的 C# 13 特性，还是实现前沿的 Aspire 模式，该服务器可确保你的 AI 助手能访问权威且最新的信息，从而生成准确、现代的代码。

<strong>实际应用</strong>：“根据官方微软 Learn 文档，az cli 创建 Azure 容器应用的命令是什么？”或者“如何在 ASP.NET Core 中使用依赖注入配置 Entity Framework？”又比如“帮我审查这段代码，确保符合 Microsoft Learn 文档中的性能建议。”该服务器利用高级语义搜索对 Microsoft Learn、Azure 文档和 Microsoft 365 文档进行全面覆盖，返回最多 10 个高质量内容片段，附带文章标题和 URL，始终访问最新发布的微软文档。

<strong>特色示例</strong>：该服务器暴露了 `microsoft_docs_search` 工具，可针对微软官方技术文档进行语义搜索。配置后，你可以提问“如何在 ASP.NET Core中实现 JWT 认证？”并获得详细、官方的答案及来源链接。搜索质量优异，因其理解上下文——比如在 Azure 语境下询问“容器”将返回 Azure 容器实例文档，而在 .NET 语境下则返回相关的 C# 集合信息。

这对快速变化或最近更新的库及用例尤其有用。例如，最近的某些编码项目中，我想利用 Aspire 和 Microsoft.Extensions.AI 最新版本的特性。通过包含 Microsoft Learn Docs MCP 服务器，我不仅利用了 API 文档，还得到了刚发布的演练和指导。

> **💡 专业提示**

### 2. ☁️ Azure MCP 服务器


[![在 VS Code 中安装](https://img.shields.io/badge/VS_Code-Install_Azure_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D) [![在 VS Code Insiders 中安装](https://img.shields.io/badge/VS_Code_Insiders-Install_Azure_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Azure/azure-mcp)

<strong>功能介绍</strong>：Azure MCP 服务器是一套由 15+ 个专门的 Azure 服务连接器组成的综合套件，将整个 Azure 生态系统引入您的 AI 工作流程。这不仅仅是单一服务器——它是一个强大的集合，涵盖资源管理、数据库连接（PostgreSQL，SQL Server）、使用 KQL 的 Azure Monitor 日志分析、Cosmos DB 集成等多种功能。

<strong>它的用处</strong>：不仅仅是管理 Azure 资源，这个服务器在使用 Azure SDK 时显著提升代码质量。当您以 Agent 模式使用 Azure MCP 时，它不仅帮助您编写代码——还帮助您编写符合当前身份验证模式、错误处理最佳实践并利用最新 SDK 特性的更好 Azure 代码。您获得的不是可能可用的通用代码，而是符合 Azure 推荐生产工作负载模式的代码。

<strong>关键模块包括</strong>：
- **🗄️ 数据库连接器**：直接通过自然语言访问 Azure Database for PostgreSQL 和 SQL Server
- **📊 Azure Monitor**：基于 KQL 的日志分析和运营洞察
- **🌐 资源管理**：完整的 Azure 资源生命周期管理
- **🔐 身份验证**：DefaultAzureCredential 和托管身份模式
- **📦 存储服务**：Blob 存储、队列存储和表存储操作
- **🚀 容器服务**：Azure Container Apps、Container Instances 和 AKS 管理
- <strong>以及更多专门的连接器</strong>

<strong>实际应用</strong>：“列出我的 Azure 存储账户”、“查询我的 Log Analytics 工作区中过去一小时的错误”，或“帮助我使用带有正确身份验证的 Node.js 构建 Azure 应用程序”

<strong>完整演示场景</strong>：这是一个展示将 Azure MCP 与 VS Code 中的 GitHub Copilot for Azure 扩展结合使用威力的完整演练。当您同时安装并提示：

> “创建一个 Python 脚本，使用 DefaultAzureCredential 认证将文件上传到 Azure Blob Storage。脚本应连接到名为 ‘mycompanystorage’ 的 Azure 存储账户，上传到一个名为 ‘documents’ 的容器，创建一个带有当前时间戳的测试文件进行上传，优雅处理错误并提供信息性输出，遵循 Azure 身份验证和错误处理的最佳实践，包含解释 DefaultAzureCredential 认证工作原理的注释，并使脚本结构良好，包含适当的函数和文档。”

Azure MCP 服务器将生成一个完整的、可用于生产的 Python 脚本，该脚本：
- 使用最新的 Azure Blob Storage SDK 和适当的异步模式
- 实现带有全面回退链说明的 DefaultAzureCredential
- 包含针对特定 Azure 异常类型的健壮错误处理
- 遵循 Azure SDK 在资源管理和连接处理方面的最佳实践
- 提供详细日志记录和信息性的控制台输出
- 创建结构合理的脚本，包含函数、文档和类型提示

令人称奇的是，没有 Azure MCP，您可能会得到能用但不符合当前 Azure 模式的通用 Blob 存储代码。使用 Azure MCP，您获得的是利用最新身份验证方法、处理 Azure 特定错误场景并遵循微软生产应用推荐最佳实践的代码。

<strong>精选示例</strong>：我过去很难记住 `az` 和 `azd` CLI 的具体命令，这总是一个两步过程：先查语法，再运行命令。经常我会直接进入门户点击操作，因为不想承认自己记不住 CLI 语法。能够只用描述我想要的东西就行真是太棒了，更棒的是还能在 IDE 内完成！

[Azure MCP 仓库](https://github.com/Azure/azure-mcp?tab=readme-ov-file#-what-can-you-do-with-the-azure-mcp-server) 中有一个很棒的用例列表帮助您入门。有关全面的设置指南和高级配置选项，请查阅[官方 Azure MCP 文档](https://learn.microsoft.com/azure/developer/azure-mcp-server/)。

### 3. 🐙 GitHub MCP 服务器

[![在 VS Code 中安装](https://img.shields.io/badge/VS_Code-Install_Server-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D) [![在 VS Code Insiders 中安装](https://img.shields.io/badge/VS_Code_Insiders-Install_Server-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/github/github-mcp-server)

<strong>功能介绍</strong>：官方 GitHub MCP 服务器实现与 GitHub 整个生态系统的无缝集成，提供托管远程访问和本地 Docker 部署选项。这不仅是基础的仓库操作——它是一套包含 GitHub Actions 管理、拉取请求工作流、问题跟踪、安全扫描、通知和高级自动化功能的综合工具箱。

<strong>它的用处</strong>：此服务器改变了您与 GitHub 交互的方式，将完整平台体验直接带入您的开发环境。无需在 VS Code 和 GitHub.com 之间频繁切换进行项目管理、代码审查和 CI/CD 监控，您可以通过自然语言命令处理所有事务，同时专注于代码。

> **ℹ️ 注意：不同类型的“Agent”**
> 
> 请勿将此 GitHub MCP 服务器与 GitHub 的 Coding Agent（您可分配问题进行自动编码任务的 AI 代理）混淆。GitHub MCP 服务器在 VS Code 的 Agent 模式下工作，提供 GitHub API 集成，而 GitHub 的 Coding Agent 是单独的功能，会在分配 GitHub 问题时创建拉取请求。

<strong>关键功能包括</strong>：
- **⚙️ GitHub Actions**：完整的 CI/CD 管道管理、工作流监控与工件处理
- **🔀 拉取请求**：创建、审查、合并和管理 PR，全面追踪状态
- **🐛 问题**：完整的问题生命周期管理、评论、标记和分配
- **🔒 安全**：代码扫描警报、秘密检测及 Dependabot 集成
- **🔔 通知**：智能通知管理和仓库订阅控制
- **📁 仓库管理**：文件操作、分支管理和仓库管理
- **👥 协作**：用户和组织搜索、团队管理及访问控制

<strong>实际应用</strong>：“从我的特性分支创建拉取请求”、“显示本周所有失败的 CI 运行”、“列出我仓库中的未解决安全警报”或“查找分配给我的所有组织内问题”

<strong>完整演示场景</strong>：这是一个展示 GitHub MCP 服务器功能的强大工作流：

<strong>用途价值</strong>：现代文档工作流的必备工具！MarkItDown 支持广泛的文件格式，并能够保留关键的文档结构，如标题、列表、表格和链接。与简单的文本提取工具不同，它专注于保持对 AI 处理和人类可读性都有价值的语义含义和格式。

- <strong>办公文档</strong>：PDF、PowerPoint（PPTX）、Word（DOCX）、Excel（XLSX/XLS）
- <strong>媒体文件</strong>：图片（含 EXIF 元数据及 OCR）、音频（含 EXIF 元数据及语音转录）
- <strong>网页内容</strong>：HTML、RSS 源、YouTube URL、维基百科页面
- <strong>数据格式</strong>：CSV、JSON、XML、ZIP 文件（递归处理内容）
- <strong>出版格式</strong>：EPub、Jupyter 笔记本（.ipynb）
- <strong>邮件</strong>：Outlook 消息（.msg）
- <strong>高级功能</strong>：集成 Azure 文档智能以增强 PDF 处理能力

<strong>高级能力</strong>：MarkItDown 支持基于大语言模型的图像描述（需提供 OpenAI 客户端）、Azure 文档智能增强 PDF 处理、音频语音转录以及插件系统以扩展更多文件格式。

<strong>实际应用</strong>：“将这份 PowerPoint 演示文稿转换成 Markdown 用于我们的文档网站”，“从这份 PDF 中提取带有正确标题结构的文本”，或“把这份 Excel 表格转换成可读的表格格式”

<strong>特色示例</strong>：引用 [MarkItDown 文档](https://github.com/microsoft/markitdown#why-markdown)中的说明：

> Markdown 非常接近纯文本，只有最少的标记或格式，但仍能表达重要的文档结构。主流的大语言模型，比如 OpenAI 的 GPT-4o，本身就“理解”Markdown，并且常常无需提示就会在回复中使用 Markdown。这表明它们接受过大量 Markdown 格式文本的训练，并且理解它。此外，Markdown 规范还具有很高的 token 效率。

MarkItDown 非常擅长保持文档结构，这对 AI 工作流非常重要。例如，在转换 PowerPoint 演示文稿时，它保持了幻灯片的组织及正确的标题，提取表格为 Markdown 表格，包含图片的替代文本，甚至处理演讲者备注。图表被转换成可读的数据表，生成的 Markdown 保持了原始演示内容的逻辑流程。这使得它非常适合将演示内容输入到 AI 系统中或基于现有幻灯片制作文档。

## 📋 结论

模型上下文协议（MCP）正在改变开发者与 AI 助手及外部工具的交互方式。这 10 个 Microsoft MCP 服务器展示了标准化 AI 集成的强大功能，实现了无缝工作流，让开发者保持状态流畅同时访问强大的外部能力。

从全面的 Azure 生态系统集成，到专门的工具如用于浏览器自动化的 Playwright 和文档处理的 MarkItDown，这些服务器展示了 MCP 如何在多样开发场景中提升生产力。标准化协议确保这些工具无缝协作，打造统一的开发体验。

随着 MCP 生态系统不断发展，积极参与社区、探索新服务器及构建定制解决方案将是最大化开发效率的关键。MCP 的开放标准性质意味着你可以混合使用不同厂商的工具，打造适合自己需求的理想工作流。
