# AGENTS.md

## ទិដ្ឋភាពគំរូគម្រោង

**MCP សម្រាប់អ្នកថ្មី** ជាប្រព័ន្ធវគ្គសិក្សាពហុទំព័រដែលបើកចំហសម្រាប់ការសិក្សាស្តីពី Model Context Protocol (MCP) - ជាស៊ុមសំបុត្រតែមួយសម្រាប់ការបណ្ដើរផ្សារភាពរវាងម៉ូដែល AI និងកម្មវិធីអតិថិជន។ កន្លែងរក្សាទុកនេះផ្តល់ឯកសារសម្រាប់ការសិក្សាយ៉ាងពេញលេញជាមួយឧទាហរណ៍កូដអនុវត្តក្នុងភាសាកម្មវិធីជាច្រើន។

### បច្ចេកវិទ្យា​សំខាន់ៗ

- **ភាសាកម្មវិធី**: C#, Java, JavaScript, TypeScript, Python, Rust
- **ពហុក្រិត និង SDK**: 
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **មូលដ្ឋានទិន្នន័យ**: PostgreSQL ជាមួយបន្ថែម pgvector
- **វេទិកាបង្ហោះពពក**: Azure (Container Apps, OpenAI, Content Safety, Application Insights)
- **ឧបករណ៍សាងសង់**: npm, Maven, pip, Cargo
- **ឯកសារ**: ប្រើMarkdown ជាមួយការបកប្រែភាសាច្រើនដោយស្វ័យប្រវត្តិ (លើស ៤៨ ភាសា)

### ស្ថាបត្យកម្ម

- **១១ ម៉ូឌុលគន្លង (០០-១១)**: ផ្លូវរៀនតាមលំដាប់ពីមូលដ្ឋានទៅប្រធានបទជាក់លាក់ខ្ពស់
- **មន្ទីរពិសោធន៍អនុវត្ត**: សកម្មភាពដើម្បីអនុវត្តជាមួយកូដដំណោះស្រាយពេញលេញនៅក្នុងភាសាច្រើន
- **គំរូគម្រោង**: កម្មវិធីម៉ាស៊ីនមេ MCP និងអតិថិជនដែលដំណើរការបាន
- **ប្រព័ន្ធបកប្រែ**: ប្រើ GitHub Actions ដើម្បីគាំទ្រភាសាច្រើនដោយស្វ័យប្រវត្តិ
- **រូបភាព**: បណ្ណាល័យរូបភាពកណ្តាលដែលមានបំលែងភាសាច្រើន

## ពាក្យបញ្ជារតំឡើង

នេះជាកន្លែងរក្សាទុកផ្តោតលើឯកសារ។ ការតំឡើងភាគច្រើនធ្វើនៅក្នុងគំរូគម្រោងនិងមន្ទីរពិសោធន៍របស់ខ្លួន។

### ការតំឡើងក្នុង Repository

```bash
# ស្វែងយកកុងដែលរក្សាទុកសញ្ញា
git clone https://github.com/microsoft/mcp-for-beginners.git
cd mcp-for-beginners
```

### ដំណើរការជាមួយគំរូគម្រោង

គំរូគម្រោងត្រូវបានដាក់នៅ៖
- `03-GettingStarted/samples/` - ឧទាហរណ៍ជាភាសាផ្សេងៗ
- `03-GettingStarted/01-first-server/solution/` - ការអនុវត្តម៉ាស៊ីនមេដំបូង
- `03-GettingStarted/02-client/solution/` - ការអនុវត្តអតិថិជន
- `11-MCPServerHandsOnLabs/` - មន្ទីរពិសោធន៍បញ្ចូលទិន្នន័យពេញលេញ

គំរូគម្រោងនីមួយៗមានការណែនាំតំឡើងផ្ទាល់ខ្លួន៖

#### គំរូគម្រោង TypeScript/JavaScript
```bash
cd <project-directory>
npm install
npm start
```

#### គំរូគម្រោង Python
```bash
cd <project-directory>
pip install -r requirements.txt
# ឬ
pip install -e .
python main.py
```

#### គំរូគម្រោង Java
```bash
cd <project-directory>
mvn clean install
mvn spring-boot:run
```

#### ជំហរឧបករណ៍ MCP ពាក់ព័ន្ធ: `validate_curriculum_change`

##### គោលបំណង

ពិនិត្យការផ្លាស់ប្ដូរឯកសារបណ្ដុះបណ្ដាល និងកូដគំរូតំណាង
សុខភាពមុនការរួមបញ្ចូល។

##### បញ្ចូល

- `changed_paths: string[]` (ត្រូវការជាក់លាក់) - ផ្លូវសមាជិកដែលផ្លាស់ប្ដូរនៅក្នុង PR។
- `run_docs_lint: boolean` (លំនាំដើម `true`)
- `run_links_audit: boolean` (លំនាំដើម `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (លំនាំដើម ទាំងអស់ជា `false`)

##### លទ្ធផល

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,`
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### សិទ្ធិ

- អានឯកសារក្នុងកំណត់ត្រាការងារនិងសរសេរឯកសាររចនា ដែលផលិតដោយឧបករណ៍ (ឧ. របាយការណ៍ lint,
  របាយការណ៍តេស្ត) តែប៉ុណ្ណោះ; មិនបានផ្តល់សិទ្ធិដើម្បីសរសេរទៅកាន់ `translations/` ឬ
  `translated_images/` ទេ។
- ប្រតិបត្តិការបញ្ជារឿង shell ក្នុងម៉ាស៊ីន។
- ការចូលប្រើបណ្តាញជាជម្រើស សម្រាប់ស្តុកកញ្ចប់តែប៉ុណ្ណោះ (`npm ci`,
  `python -m pip install`, `mvn` សំរាប់ដោះស្រាយការពឹងផ្អែក)។
- គ្មានសិទ្ធិដើម្បីដាក់ជម្រះ, រួមបញ្ចូល, ឬផ្លាស់ប្ដូរ `translations/` ឬ
  `translated_images/` ទេ។

##### របៀបបរាជ័យ

- `E_NO_INPUT_PATHS`: `changed_paths` ខ្វះទំនិញ។
- `E_INVALID_PATH`: ផ្លូវបញ្ចូលចេញពីដើមហាង។
- `E_LINT_FAILED`: បញ្ចូល markdown lint ផុតកូដដោយមិនស្មើសូន្យ។
- `E_LINK_AUDIT_FAILED`: ឧបករណ៍ link audit ផុតកូដដោយមិនស្មើសូន្យ។
- `E_SAMPLE_TEST_FAILED`: តេស្ត/សាងសង់គំរូ ផុតកូដដោយមិនស្មើសូន្យ។
- `E_TIMEOUT`: បញ្ជារឿងលើសពេលកំណត់។

##### កិច្ចសន្យា CI ដែលបានណែនាំ

ដើម្បីធ្វើអូតូម៉ាទិកការផ្ទៀងផ្ទាត់ សូមកំណត់កិច្ចការជាមួយ CI ដូចខាងក្រោម:

- ចាប់ផ្តើមនៅពេលដែលមាន pull requests ប៉ះទង់ទៅ `*.md`, កូដគំរូ ឬឯកសារនេះ។
- ប្រតិបត្តិការបញ្ជា ដូចបានបញ្ជាក់ខាងលើ។
- រក្សាទុកកំណត់ហេតុជារូបសញ្ញា។
- បរាជ័យនៅក្នុងកិច្ចការនៅពេលមាន exit code ដែលមិនស្មើសូន្យ។

### ការផ្ទៀងផ្ទាត់ឯកសារ

ដោយសារតែវាគឺជាគណនីឯកសារ ជាប្រភេទធ្វើតេស្ដផ្តោតលើ:

1. **ពិនិត្យគំនូសតំណភ្ជាប់**: បញ្ជីតំណ Markdown សម្រាប់ការពិនិត្យឡើងវិញ

   ```bash
   # បញ្ជីតំណរភ្ជាប់ Markdown (ត្រួតពិនិត្យលំនាំ)
   find . -name "*.md" -not -path "*/node_modules/*" -not -path "./translations/*" -not -path "./translated_images/*" -print0 | xargs -0 grep -En "\[.*\]\(.*\)"
   ```

2. **ផ្ទៀងផ្ទាត់ឧទាហរណ៍កូដ**: សាកល្បងឲ្យឧទាហរណ៍កូដដំណើរការ/កូំពាយ

   ```bash
   # ធ្វើដំណើរទៅគំរូជាក់លាក់ ហើយបើករត់ការធ្វើតេស្តរបស់វា
   cd 03-GettingStarted/samples/typescript
   npm install && npm test
   ```

3. **ពិនិត្យ Markdown សម្រាប់ការត្រួតពិនិត្យរចនាសម្ព័ន្ធ** 

   ```bash
   # ប្រើ markdownlint ប្រសិនបើត្រូវការ
   npx --yes markdownlint-cli2 "**/*.md" "#node_modules" "#translations" "#translated_images"
   ```

### ដំណើរការដាក់សំណើ Pull Request

1. **Fork និង Clone**: Fork កញ្ចប់រូបមន្ត ហើយ clone fork របស់អ្នកទៅកន្លែង​របស់អ្នក
2. **បង្កើតសាខា**: ប្រើឈ្មោះសាខាជាក់លាក់ (ឧ. `fix/typo-module-3`, `add/python-example`)
3. **ធ្វើការផ្លាស់ប្តូរ**: កែសម្រួលឯកសារ markdown ភាសាអង់គ្លេសប៉ុណ្ណោះ (មិនមែនបកប្រែ)
4. **សាកល្បងក្នុងកន្លែងដំណើរការ**: ផ្ទៀងផ្ទាត់ markdown បង្ហាញត្រឹមត្រូវ
5. **ដាក់សំណើ PR**: ប្រើចំណងជើង និងការពិពណ៌នាខ្លីល្អ
6. **CLA**: ចុះហត្ថលេខាលើ Microsoft Contributor License Agreement នៅពេលត្រូវការ
