# មូលដ្ឋាន MCP (មុខងារចាស់)

> [!WARNING]
> មូលដ្ឋានត្រូវបានដកចេញចាប់ពី MCP `2026-07-28`។ ពួកវានៅតែមាននៅក្នុងការកែប្រែនេះសម្រាប់
> ការចម្រុះគ្នា ហើយអាចត្រូវបានដកចេញនៅក្នុងការកែប្រែការបញ្ជាក់ដំបូង
> ដែលបានផ្សាយនៅថ្ងៃ 28 ខែកក្កដា ឆ្នាំ 2027 ឬបន្ទាប់មក។ ការអនុវត្តថ្មីគួរបញ្ចូន
> ថតឯកសារឬឯកសារតាមរយៈប៉ារ៉ាម៉ែត្រឧបករណ៍ អាសយដ្ឋាន URI ឯកសារ ឬការកំណត់រចនាសម្ព័ន្ធម៉ាស៊ីនមេ។


## ទិដ្ឋភាពទូទៅ

មូលដ្ឋានអនុញ្ញាតឲ្យផ្នែកឆ្លើយតប MCP ពInform a server ថាតំបន់បណ្តាញនៃប្រព័ន្ធផ្ទុកទិន្នន័យប្រសើរជាមួយ
អំពីការស្នើសុំនាពេលបច្ចុប្បន្ន។ មូលដ្ឋានមាន URI `file://` ត្រូវការ និងឈ្មោះអាចអានបានដោយមនុស្ស (optional)។


មូលដ្ឋានគឺជាខ្លឹមសារជាម្រែសម្រួលព័ត៌មាន។ មិនមែនជាគ្រឿងឧបករណ៍រក្សាទុកប្រវត្តិកិច្ចការនិយាយ,
សម័យការសន្ទនា, ឬមេកានិចការត្រួតពិនិត្យការចូលប្រើ។ ពិធីសាស្ត្រមិនបង្ខំឲ្យម៉ាស៊ីនមេនៅក្នុងមូលដ្ឋានដែលបានរាយបញ្ចូលឡើយ។


## គោលបំណងរៀន

នៅចុងការរៀននេះ អ្នកនឹងអាច:

- ពន្យល់អំពីអ្វីដែលមូលដ្ឋាន MCP តំណាង និងអ្វីដែលវាមិនតំណាង។
- ស្គាល់ដំណើរការជាច្រើនជំនួប `roots/list` បច្ចុប្បន្ន។
- ដាក់ការត្រួតពិនិត្យសុវត្ថិភាពដោយឯករាជ្យពីមូលដ្ឋាន។
- ភ្ជាប់ការអនុវត្តថ្មីទៅជំនួបផ្សេងទៀតដែលគាំទ្រ។

## ទិន្នន័យមូលដ្ឋាន

អ្នកឆ្លើយតបមួយត្រឡប់មូលដ្ឋាននិមួយៗជាមួយ URI `file://` មានឈ្មោះបង្ហាញជាជម្រើស៖

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

អ្នកឆ្លើយតបគួរតែបង្ហាញតែទីតាំងដែលបានអនុញ្ញាតដោយអ្នកប្រើប្រាស់។ ម៉ាស៊ីនមេគួរតែ
ពិនិត្យលទ្ធផលជាការណែនាំអំពីឯកសារដែលពាក់ព័ន្ធ មិនមែនជា ពលកម្មគ្រប់គ្រងអាជ្ញាប័ណ្ណ។

## ដំណើរការ MCP 2026-07-28

អ្នកឆ្លើយតបដែលគាំទ្រមូលដ្ឋានប្រកាសសមត្ថភាពក្នុងសំណើរ គ្រប់ពេលៈ

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

ខណៈពេលដំណើរការសំណើរពីអ្នកឆ្លើយតប ម៉ាស៊ីនមេអាចត្រឡប់ចម្លើយ
`InputRequiredResult` ដែលមានសំណើបញ្ចូល `roots/list`៖

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

អ្នកឆ្លើយតបប្រមូលមូលដ្ឋានដែលអនុញ្ញាតហើយធ្វើសំណើរឡើងវិញជាមួយ `inputResponses` និង `requestState` ដែលមិនបានផ្លាស់ប្តូរ។ ដំណើរការជាច្រើនជំនួបនេះ
រក្សាប្រោយភាពស្ថិតស្ថេររបស់ពិធីសាស្ត្រ; គ្មានការចាប់ដៃគូ `initialize` ឬសម័យការសន្ទនា
កម្រិតពិធីសាស្ត្រឡើយ។


## អករៈពេល 2025-11-25 ចាស់

នៅក្នុង MCP `2025-11-25` អ្នកឆ្លើយតបបានផ្សព្វផ្សាយមូលដ្ឋាននៅពេលចាប់ផ្តើម។ ម៉ាស៊ីនមេអាច
ផ្ញើសំណើ `roots/list` ត្រឹមត្រូវ ហើយអ្នកឆ្លើយតបអាចផ្ញើ
`notifications/roots/list_changed` ពេលដែលមូលដ្ឋានរបស់វាបានផ្លាស់ប្តូរ។

អ្នកនិពន្ធសម័យនេះជាអនុក្រឹតកម្មចាស់។ កុំបញ្ចូលការចាប់ផ្តើម ឬ
ឧទាហរណ៍ជូនដំណឹងជាមួយការអនុវត្ត `2026-07-28`។

## ការជំនួសដែលបានផ្ដល់អនុសាសន៍

### ប៉ារ៉ាម៉ែត្រឧបករណ៍

បង្ហាញថតឯកសារឬឯកសារត្រូវបានទាមទារ ឲ្យច្បាស់ក្នុង schema ឧបករណ៍៖

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### អាសយដ្ឋាន URI ឯកសារ

ប្រើ MCP Resources នៅពេលម៉ាស៊ីនមេអាចបង្ហាញឯកសារពាក់ព័ន្ធតាមរយៈ URI ត្រឹមត្រូវ។ នេះរក្សាការរកឃើញ និងការទាញយកឲ្យច្បាស់លាស់។


### ការកំណត់រចនាសម្ព័ន្ធម៉ាស៊ីនមេ

សម្រាប់ការតំឡើងថេរ កំណត់ថតដែលអនុញ្ញាតនៅពេលម៉ាស៊ីនមេចាប់ផ្តើម។ នេះជាទូទៅច្បាស់ជាងការរកឃើញពេលហៅឧបករណ៍។


## តម្រូវការសុវត្ថិភាព

មិនថាអ្នកជ្រើសរើសជំនួសណាមួយ:

- ទទួលការយល់ព្រមពីអ្នកប្រើ មុនបង្ហាញទំរង់ទីតាំងប្រព័ន្ធផ្ទុកទិន្នន័យ។
- បញ្ចូលនិងផ្ទៀងផ្ទាត់ផ្លូវ ដើម្បីទប់ស្កាត់ការរំលោភទន្លេ។
- បង្ខំអាជ្ញាប័ណ្ណនិងសំបុកនៅឡើយដោយឯករាជ្យពីតម្លៃមូលដ្ឋាន។
- ពិនិត្យសិទ្ធិម្ដងទៀតពេលដែលចូលប្រើឯកសារ មិនមែនត្រឹមតែពេលដែលវាត្រូវបានរាយនាម។
- ជៀសវាងកំណត់ផ្លូវសំខាន់ក្នុងកំណត់ហេតុ ឬសារបញ្ហា។

## ចំណុចសង្ខេបសំខាន់ៗ

- មូលដ្ឋានពណ៌នាទីតាំងប្រព័ន្ធផ្ទុកទិន្នន័យពាក់ព័ន្ធ; វាមិនរក្សានូវស្ថានភាពកិច្ចការនិយាយឡើយ។

- មូលដ្ឋានជាខ្លឹមសារណែនាំ មិនមែនជាអធិបតេយ្យការចូលប្រើ។
- MCP `2026-07-28` បញ្ជាក់សមត្ថភាពបន្ដទៅក្នុងសំណើ និងប្រើ
  `InputRequiredResult` សម្រាប់ `roots/list`។
- ការអនុវត្តថ្មីគួរប្រើប៉ារ៉ាម៉ែត្រឧបករណ៍ អាសយដ្ឋាន URI ឯកសារ ឬរចនាសម្ព័ន្ធម៉ាស៊ីនមេជំនួស។
