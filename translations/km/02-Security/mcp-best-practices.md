# គន្លឹះការពារសន្តិសុខ MCP ល្អបំផុត - បច្ចុប្បន្នភាពខែកញ្ញា ២០២៦

សៀវភៅណែនាំទាំងមូលនេះបានរៀបរាប់ពីគន្លឹះការពារសន្តិសុខសំខាន់ៗសម្រាប់
ការអនុវត្តប្រព័ន្ធ Model Context Protocol (MCP) ដែលផ្អែកលើ
**MCP Specification 2026-07-28** និងស្តង់ដារឧស្សាហកម្មបច្ចុប្បន្ន។ គន្លឹះ
ទាំងនេះដោះស្រាយទាំងបញ្ហាសន្តិសុខប្រពៃណី និងឧបសគ្គជាក់លាក់
ស្ដីពី AI ដែលមានតែមុខងារពិសេសសម្រាប់ការដាក់ឲ្យដំណើរការនៅ MCP។

## តម្រូវការសន្តិសុខសំខាន់ៗ

### តម្រូវការគ្រប់គ្រងសន្តិសុខបង្រ្កាប់ (តម្រូវការត្រូវធ្វើ)

1. **ការបញ្ជាក់សញ្ញាសម្គាល់**: ម៉ាស៊ីនបម្រើ MCP **មិនត្រូវ** ទទួលយកសញ្ញាសម្គាល់ណាមួយដែលមិនត្រូវបានចេញផ្សាយយ៉ាងច្បាស់សម្រាប់ម៉ាស៊ីនបម្រើ MCP ដល់ខ្លួនវាឯង
2. **ការពិនិត្យអាជ្ញាបណ្ណ**: ម៉ាស៊ីនបម្រើ MCP ដែលអនុវត្តអាជ្ញាបណ្ណ **ត្រូវ** ពិនិត្យរាល់សំណើចូលមកទាំងអស់ និង **មិនត្រូវ** ប្រើវគ្គសម្គាល់សម្រាប់ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ
3. **ការយល់ព្រមពីអ្នកប្រើប្រាស់**: ម៉ាស៊ីនបម្រើ MCP proxy ដែលប្រើអត្តសញ្ញាណអ្នកប្រើប្រាស់ម៉ាស៊ីនភ្ញៀវភាគីទីបីថេរ **ត្រូវ** ទទួលយកការយល់ព្រមយ៉ាងច្បាស់សម្រាប់ម៉ាស៊ីនភ្ញៀវ MCP តែមួយមុនពេលផ្ដល់បន្តដំណើរការអាជ្ញាបណ្ណ
4. **សន្តិសុខ State Handle**: ម៉ាស៊ីនបម្រើ MCP **មិនត្រូវ** ប្រើបែបបទកាន់កាប់ state handle ជាការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ហើយ **ត្រូវ** អនុញ្ញាតគ្រប់សំណើដែលប្រើវា
	request that uses one


## គន្លឹះសន្តិសុខមូលដ្ឋាន

### 1. ការត្រួតពិនិត្យនិងសម្អាតបញ្ចូល
- **ការត្រួតពិនិត្យបញ្ចូលទូលំទូលាយ**: បញ្ចាក់ និងសម្អាតទិន្នន័យបញ្ចូលទាំងអស់ ដើម្បីការពារការវាយប្រហារចាក់ចូល, បញ្ហាអ្នកតំណាងច្របល់ និងចំណុចខ្សោយនៃការចាក់ចូលពាក្យបញ្ជា
- **ការអនុវត្តគំរូ Schema នៃប៉ារ៉ាទ័រ**: អនុវត្តការត្រួតពិនិត្យ schema JSON យ៉ាងតឹងរឹង សម្រាប់ប៉ារ៉ាទ័រសម្ភារៈ និងបញ្ចូល API ទាំងអស់
- **ការលៃតម្រូវមាតិកា**: ប្រើ Microsoft Prompt Shields និង Azure Content Safety ដើម្បីលៃតម្រូវមាតិកាដែលមានគ្រោះថ្នាក់នៅក្នុងពាក្យបញ្ជា និងចម្លើយ
- **ការសម្អាតចេញ**: ត្រួតពិនិត្យ និងសម្អាតចេញដែលមានគន្លងពីម៉ូដែលមុនពេលបង្ហាញអ្នកប្រើ បន្ទាត់ក្រោមឬប្រព័ន្ធក្រោម

### 2. ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ និងការអនុញ្ញាតល្អប្រសើរ  
- **អ្នកផ្តល់អត្តសញ្ញាណខាងក្រៅ**: ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណប្រែជារបស់អ្នកផ្តល់អត្តសញ្ញាណដែលបានបង្កើតឡើងជាមុន (Microsoft Entra ID, អ្នកផ្តល់ OAuth 2.1) ជំនួសការអនុវត្តផ្ទាល់ខ្លួន
- **ការចុះឈ្មោះអ្នកប្រើប្រាស់**: មានចំណាប់អារម្មណ៍ក្នុងអត្ថបទ Metadata អត្តសញ្ញាណឬការចុះឈ្មោះជាមុន; ប្រើ Dynamic Client Registration ដែលត្រូវបោះបង់ខ្លះសម្រាប់ភាពឆបគ្នា
- **សិទ្ធិវិញុស្សពីយ៉ាងតឹងរ៉ឹង**: អនុវត្តសិទ្ធិយ៉ាងមានប្រយោជន៍សម្រាប់ឧបករណ៍ជាក់លាក់ តាមលក្ខណៈការដាក់អនុសាសន៍អ្វីដែលតិចបំផុត
- **ការគ្រប់គ្រងរយៈពេលសញ្ញាសម្គាល់**: ប្រើសញ្ញាសម្គាល់ដែលមានរយៈពេលខ្លី មានការបម្លែងសុវត្ថិភាព និងការត្រួតពិនិត្យអ្នកទទួលបានត្រឹមត្រូវ
- **ការផ្ទៀងផ្ទាត់បន្តបន្តរ**: កំណត់អោយ MFA សម្រាប់ការចូលគ្រប់គ្រង និងប្រតិបត្ដិការរំខានខ្លាំងៗទាំងអស់

### 3. ប្រព័ន្ធសន្តិសុខការប្រាស្រ័យ
- **សន្តិសុខជាន់ដឹកជញ្ជូន**: ប្រើ HTTPS ជាមួយការត្រួតពិនិត្យវិញ្ញាបនបត្រយ៉ាងត្រឹមត្រូវសម្រាប់ការទំនាក់ទំនង HTTP MCP ពីចម្ងាយ; ប្រើការបែកបាញ់ដំណើរការនិងលិខិតឆ្លងកាត់បរិស្ថានសម្រាប់ម៉ាស៊ីនបម្រើ stdio ផ្ទាល់
	for remote HTTP MCP communications; use process isolation and environment
	credentials for local stdio servers
- **ការអ៊ិនគ្រីបចប់ពីចាប់ផ្តើមដល់ចប់**: អនុវត្តស្រទាប់អ៊ិនគ្រីបបន្ថែមសម្រាប់ទិន្នន័យមានសារសំខាន់ខ្ពស់ក្នុងដំណើរនិងកន្លែងផ្ទុក
- **ការគ្រប់គ្រងវិញ្ញាបនបត្រ**: រក្សាការគ្រប់គ្រងជីវចរនៃវិញ្ញាបនបត្រយ៉ាងត្រឹមត្រូវជាមួយដំណើរការបាត់បង់ឡើងវិញដោយស្វ័យប្រវត្តិ
- **ការអនុវត្តកំណែប្រព័ន្ធ**: ប្រើកំណែ MCP `2026-07-28`, រួមបញ្ចូលលំដាប់កំណែខ្លឹមសារនៅរាល់សំណើ, ហើយបដិសេធកំណែដែលមិនគាំទ្រ
	version metadata on every request, and reject unsupported versions

### 4. ការជម្ចុងពេល_RATE_LIMITING និងការពារព្រំប្រទល់ធនធាន
- **ការជម្ចុងពេល Multi-layer**: អនុវត្តការជម្ចុងពេលតាមអ្នកប្រើប្រាស់, លិខិតឆ្លងកាត់, ប្រតិបត្ដិការ, ឧបករណ៍ និងធនធាន ដើម្បីទប់ស្កាត់ការបោកបញ្ឆោត
  
- **ការជម្ចុងពេលរៀបរាប់មុខងារ**: ប្រើការជម្ចុងពេលដោយបច្ចេកវិទ្យាផ្អែកលើការរៀនម៉ាស៊ីនដែលប្ដូរតាមលំនាំប្រើប្រាស់ និងសញ្ញាដំណឹងគ្រោះថ្នាក់
- **ការគ្រប់គ្រងកំណត់កំណែនិងធនធាន**: កំណត់ដែនកំណត់សមរម្យសម្រាប់ធនធានគណនាផ្លូវគណនា ការប្រើប្រាស់ចងចាំ និងពេលវេលាដំណើរការ
- **ការពារវាយប្រហារប្រភេទ DDoS**: តំឡើងប្រព័ន្ធការពារវាយប្រហារប្រភេទ DDoS និងវិភាគចរាចរណ៍យ៉ាងទូលំទូលាយ

### 5. ការចុះកត់ត្រារួមនិងត្រួតពិនិត្យលម្អិត
- **ការចុះកត់ត្រាការត្រួតពិនិត្យតាមរចនាសម្ព័ន្ធ**: អនុវត្តកំណត់ហេតុចុះកត់ត្រាលម្អិតដែលអាចស្វែងរកបានសម្រាប់សកម្មភាព MCP ទាំងអស់ ការប្រតិបត្ដឧបករណ៍ និងព្រឹត្តិការណ៍សន្តិសុខ
- **ការត្រួតពិនិត្យសន្តិសុខស្របពេលវេលា**: ប្រើប្រព័ន្ធ SIEM ដែលបញ្ជូនដោយ AI ដើម្បីរកឃើញអក្សរប្រែប្រួលសម្រាប់បន្ទុកការងារ MCP
- **ការចុះកត់ត្រា​ស្របតាម​ទិន្នន័យ​ភាពឯកជន**: ចុះកត់ត្រាព្រឹត្តិការណ៍សន្តិសុខដោយគោរពតាមតម្រូវការការពារទិន្នន័យ
- **ការតភ្ជាប់ឆ្លើយតបហេតុការណ៍**: បញ្ចូលប្រព័ន្ធកត់ត្រានៅក្នុងសកម្មភាពឆ្លើយតបហេតុការណ៍ដោយស្វ័យប្រវត្តិ

### 6. គន្លឹះផ្ទុកសុវត្ថិភាពឧបករណ៍លើកទីពីរ
- **ម៉ូឌុលសន្តិសុខរឹង**: ប្រើការផ្ទុកគន្លឹះដែលគាំទ្រដោយ HSM (Azure Key Vault, AWS CloudHSM) សម្រាប់ប្រតិបត្តិការក្រអូបត្រូវបានអនុវត្ត
- **ការគ្រប់គ្រងគន្លឹះអ៊ិនគ្រីប**: អនុវត្តបម្លែងគន្លឹះ ធ្វើការបំបែក និងត្រួតពិនិត្យចូលដំណើរការសម្រាប់គន្លឹះអ៊ិនគ្រីប
- **ការគ្រប់គ្រងអាថ៌កំបាំង**: រក្សាជាមូលដ្ឋានកូនគន្លឹះ API, សញ្ញាសម្គាល់ និងលិខិតឆ្លងកាត់ទាំងអស់នៅក្នុងប្រព័ន្ធគ្រប់គ្រងអាថ៌កំបាំងឯកជន
- **ការបែងចែកទិន្នន័យ**: បែងចែកទិន្នន័យដោយផ្អែកលើកម្រិតភាពសំខាន់ ហើយអនុវត្តវិធានការពារសមរម្យ

### 7. គ្រប់គ្រងសញ្ញាសម្គាល់កម្រិតខ្ពស់
- **ការបញ្ឈប់ការបញ្ជូន Token ផ្ទាល់**: ធ្វើឲ្យជាក់លាក់ការហាមឃាត់លំនាំបញ្ជូន token ដែលល្មមលើការគ្រប់គ្រងសន្តិសុខ
- **ការពិនិត្យអ្នកទទួល**: តែងតែពិនិត្យអ្នកទទួលនៃ token អោយត្រូវគ្នាជាមួយអត្តសញ្ញាណម៉ាស៊ីនបម្រើ MCP គោល
- **អាជ្ញាបណ្ណផ្អែកលើការទាមទារ Claims**: អនុវត្តការអាជ្ញាបណ្ណលម្អិតដោយផ្អែកលើ claims របស់ token និងលក្ខណៈបុគ្គលរបស់អ្នកប្រើ
- **ការចងចម្រាស់ Token**: ពិនិត្យថា token មានគោលដៅទៅធនធាន MCP ត្រឹមត្រូវហើយ ចងបណ្ដាញ application state handles នៅខាងម៉ាស៊ីនបម្រើទៅនឹងអ្នកផ្ទៀងផ្ទាត់។
	bind application state handles server-side to the authenticated principal

### 8. រដ្ឋបាលកម្មវិធីសុវត្ថិភាព

- **Cryptographic State Handles**: បង្កើត handles អស្ចារ្យ ដែលមិនអាចប៉ាន់ស្មានសម្រាប់ស្ថានភាពបន្ថែមដែលលេចឡើងក្នុងសំណើផ្សេងៗ
	for state that spans requests
- **User-specific Binding**: ចងក្រង handle នីមួយៗនៅខាងម៉ាស៊ីនបម្រើជាមួយ principal ដែលបានផ្ទៀងផ្ទាត់; មិនគួរជឿលើ user ID ដែលបានផ្ដល់ដោយ client
	principal; do not trust a user ID supplied by the client
- **Lifecycle Controls**: ធ្វើឲ្យ handles ផុតកំណត់ និងលុបបំបាត់ ហើយកំណត់របៀបហៅត្រឡប់ពីស្ថានភាពដែលចាស់
	recover from stale state
- **Per-request Authorization**: ត្រួតពិនិត្យអាជ្ញាបណ្ណម្ដងទៀតរាល់ពេលមានការនាំ handle មក; handle គឺជាឈ្មោះ មិនមែនជាលិខិតឆ្លងកាត់
	presented; a handle is a name, not a credential

### 9. ការគ្រប់គ្រងសន្តិសុខជាក់លាក់ទាក់ទងAI
- **ការពារការចាក់បញ្ចូល Prompt Injection**: តំឡើង Microsoft Prompt Shields ជាមួយ spotlighting, delimiters, និងបច្ចេកទេស datamarking
- **ការការពារបារម្ភ Tool Poisoning**: ពិនិត្យមាតិកា metadata របស់ឧបករណ៍, ត្រួតពិនិត្យការផ្លាស់ប្តូរដោយរហ័ស, ហើយពិនិត្យភាពស្ងប់ស្ងាត់របស់ឧបករណ៍
- **ការត្រួតពិនិត្យលទ្ធផលម៉ូដែល**: ស្កេនលទ្ធផលម៉ូដែលសម្រាប់ការលេចធ្លាយទិន្នន័យគ្រោះថ្នាក់ មាតិកាអាក្រក់ ឬការព្រមព្រៀងគោលការណ៍សន្តិសុខ
- **ការពារបង្អួច Context Window**: អនុវត្តការគ្រប់គ្រង ដើម្បីទប់ស្កាត់ការបំផ្លាញ និងវាយប្រហាររស់នៅ context window

### 10. សន្តិសុខការប្រតិបត្ដិឧបករណ៍
- **ការរត់ក្នុងសេគ្រុត Sandbox**: បើកដំណើរការឧបករណ៍នៅបរិវិស sandbox ដែលមានការបិទបាំង និងកំណត់ធនធាន
- **ការបំបែកសិទ្ធិ**: ប្រតិបត្ដឧបករណ៍ជាមួយសិទ្ធិអប្បបរមា និងគណនីសេវាកម្មបំបែកដោយឡែក
- **ការបំបែកបណ្ដាញ**: អនុវត្តការបំបែកបណ្ដាញសម្រាប់បរិយាកាសប្រតិបត្ដិឧបករណ៍
- **ការត្រួតពិនិត្យការប្រតិបត្ដិ**: ត្រួតពិនិត្យការប្រតិបត្ដិឧបករណ៍សម្រាប់សកម្មភាពអសហាន្ត ដំណើរការថ្មី និងការលំបាកសន្តិសុខ

### 11. ការត្រួតពិនិត្យសន្តិសុខតន្ត្រី
- **ការប្រឡងសន្តិសុខដោយស្វ័យប្រវត្តិ**: បញ្ចូលការប្រឡងសន្តិសុខទៅក្នុង CI/CD pipelines ជាមួយឧបករណ៍ដូចជា GitHub Advanced Security
- **ការគ្រប់គ្រងរបួសខ្សោយ**: ប្រើប្រាស់ឧបករណ៍ស្កេនស regularly លើគ្រប់ dependency រួមទាំងម៉ូដែល AI និងសេវាកម្មក្រៅ
- **ការប្រឡងបាក់ទ្រាពហុ**: ប្រារព្ធការវាយតំលៃសន្តិសុខជាប្រចាំ សម្រាប់ករណីអនុវត្ត MCP មួយចំនួនជាក់លាក់
- **ការត្រួតពិនិត្យកូដសន្តិសុខ**: អនុវត្តការត្រួតពិនិត្យសន្តិសុខបង់បញ្ចាំសម្រាប់កូដដែលពាក់ព័ន្ធជាមួយ MCP ទាំងអស់

### 12. សន្តិសុខសង្វាក់ផ្គត់ផ្គង់សម្រាប់ AI
- **ការត្រួតពិនិត្យធាតុសាច់**: ត្រួតពិនិត្យប្រភព ដូចជាការសុវត្ថិភាព នៃធាតុ AI ទាំងអស់ (ម៉ូដែល, embeddings, API)
- **ការគ្រប់គ្រង dependency**: រក្សាបញ្ជីចុះបញ្ជីបច្ចុប្បន្ន នៃសូហ្វវែរនិង dependency AI ទាំងអស់ ជាមួយការតាមដានរបួសខ្សោយ
- **ឃ្លាំងទុកដែលគួរឱ្យទុកចិត្ត**: ប្រើប្រភពដែលត្រូវបានផ្ទៀងផ្ទាត់ និងទុកចិត្តសម្រាប់ម៉ូដែល AI, បណ្ណាល័យ និងឧបករណ៍ទាំងអស់
- **ការត្រួតពិនិត្យសង្វាក់ផ្គត់ផ្គង់**: ត្រួតពិនិត្យជាប់ជាប្រចាំសម្រាប់ការបំផ្លាញនៅក្នុងអ្នកផ្តល់សេវា AI និងឃ្លាំងម៉ូដែល


## គំរូសុវត្ថិភាពជំនាញខ្ពស់

### សំណង់ស្មារតី "Zero Trust" សម្រាប់ MCP
- **មិនទុកចិត្តទេ តែត្រូវផ្ទៀងផ្ទាត់ជាប្រចាំ**៖ អនុវត្តការផ្ទៀងផ្ទាត់បន្តសម្រាប់អ្នកចូលរួម MCP ទាំងអស់
- **ការចែកផ្នែកតូច (Micro-segmentation)**៖ បំបែកគ្រឿងផ្សំនៃ MCP ជាមួយការត្រួតពិនិត្យបណ្តាញនិងអត្តសញ្ញាណយ៉ាងម៉ត់ចត់
- **ការចូលប្រើដោយមូលដ្ឋានលើលក្ខខណ្ឌ (Conditional Access)**៖ អនុវត្តការត្រួតពិនិត្យចូលប្រើដោយផ្អែកលើហានិភ័យ ដែលប្តូរតាមបរិបទនិងបំណងប្រព្រឹត្ត
- **ការវាយតម្លៃហានិភ័យបន្ត**៖ ប៉ាន់ប្រមាណសភាពសុវត្ថិភាពយ៉ាងស្ទាត់ជាមួយសញ្ញាហានិភ័យបច្ចុប្បន្នក្នុងលំហមួយ

### ការអនុវត្ត AI ដើម្បីរក្សាសម្ងាត់
- **ការកាត់បន្ថយទិន្នន័យ**៖ បង្ហាញតែទិន្នន័យបន្ថែមតិចតួចបំផុតដែលចាំបាច់សម្រាប់ប្រតិបត្តិការ MCP នីមួយៗ
- **ភាពឯកជនខុសគ្នា (Differential Privacy)**៖ អនុវត្តបច្ចេកទេសរក្សាសម្ងាត់សម្រាប់ដំណើរការទិន្នន័យដែលមានភាពឯកជនខ្ពស់
- **ការអ៊ិនគ្រីបដោយ Homomorphic**៖ ប្រើបច្ចេកទេសអ៊ិនគ្រីបខ្ពស់សម្រាប់គណនា​យ៉ាង​សុវត្ថិភាពលើទិន្នន័យអ៊ិនគ្រីប
- **ការរៀនរៀបចំចែកចាយ (Federated Learning)**៖ អនុវត្តវិធីសាស្រ្តរៀនចែកចាយដែលរក្សាទុកទីតាំងទិន្នន័យនិងភាពឯកជន

### ការឆ្លើយតបទៅហេតុការណ៍សម្រាប់ប្រព័ន្ធ AI
- **នីតិវិធីឆ្លើយតបទៅហេតុការណ៍ជាក់លាក់សម្រាប់ AI**៖ អភិវឌ្ឍន៍នីតិវិធីឆ្លើយតបដែលផ្តល់ខ្លួនសម្រាប់ហានិភ័យជាក់លាក់ AI និង MCP
- **ការឆ្លើយតបដោយស្វ័យប្រវត្តិ**៖ អនុវត្តការការពារនិងជួសជុលដោយស្វ័យប្រវត្តិសម្រាប់ហេតុការណ៍សុវត្ថិភាព AI ទូទៅ  
- **សមត្ថភាពស្រាវជ្រាវ**៖ រក្សាការត្រៀមខ្លួនសម្រាប់ការស្រាវជ្រាវ​ហេតុការណ៍គម្រាមកំហែងប្រព័ន្ធ AI និងការបំពានទិន្នន័យ
- **នីតិវិធីស្តារឡើងវិញ**៖ បង្កើតនីតិវិធីសម្រាប់ស្តារឡើងវិញពីការបំពុលម៉ូឌែល AI, ការវាយប្រហារដោយដាក់សារបញ្ចូលព្រួញ, និងការបំពានសេវាកម្ម

## 🔄 ការកែលម្អជាប្រចាំ

### រក្សាបច្ចុប្បន្នភាពជាមួយស្ដង់ដារ​កំពុងអភិវឌ្ឍ
- **បច្ចុប្បន្នភាពបញ្ជាក់ MCP**: តាមដានការផ្លាស់ប្តូរបញ្ជាក់ MCP ផ្លូវការនិងការប្រុងប្រយ័ត្នសុវត្ថិភាព
- **ព័ត៌មានប្រឆាំងគំរាមកំហែង**: ចុះឈ្មោះទទួលព័ត៌មានអំពីគំរាមកំហែងសុវត្ថិភាព AI និងមូលដ្ឋានទិន្នន័យចំណុចងាយរងគ្រោះ  
- **ការចូលរួមសហគមន៍**: ចូលរួមក្នុងការពិភាក្សាសហគមន៍សុវត្ថិភាព MCP និងក្រុមការងារ
- **ការប៉ាន់ប្រមាណជាប្រចាំ**: ប្រតិបត្តិការវាយតម្លៃស្ថានភាពសុវត្ថិភាពរាជ្យ៤មុខនិងធ្វើបច្ចុប្បន្នភាពបទបញ្ញត្តិឲ្យសមរម្យ

### វារួមចំណែកដល់សុវត្ថិភាព MCP
- **ស្រាវជ្រាវសុវត្ថិភាព**: វារួមចំណែកក្នុងការស្រាវជ្រាវសុវត្ថិភាព MCP និងកម្មវិធីបង្ហាញចំណុចងាយរងគ្រោះ
- **ចែករំលែកអនុស្សរណៈល្អ**: ចែករំលែកការអនុវត្តសុវត្ថិភាពនិងបទពិសោធន៍ជាមួយសហគមន៍
- **អភិវឌ្ឍស្ដង់ដារ**: ចូលរួមអភិវឌ្ឍន៍បញ្ជាក់ MCP និងការបង្កើតស្ដង់ដាសុវត្ថិភាព
- **អភិវឌ្ឍឧបករណ៍**: អភិវឌ្ឍន៍និងចែករំលែកឧបករណ៍និងបណ្ណាល័យសុវត្ថិភាពសម្រាប់បរិស្ថាន MCP
