# แนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยของ MCP - การอัปเดตกันยายน 2026

คู่มือที่ครอบคลุมนี้สรุปแนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยที่จำเป็นสำหรับ
การใช้งานระบบโปรโตคอลบริบทแบบจำลอง (Model Context Protocol - MCP) โดยอิงตาม
**ข้อกำหนด MCP 2026-07-28** และมาตรฐานอุตสาหกรรมปัจจุบัน แนวทางปฏิบัติเหล่านี้
ครอบคลุมทั้งประเด็นด้านความปลอดภัยแบบดั้งเดิมและภัยคุกคามเฉพาะของ AI
ที่มีความเฉพาะตัวสำหรับการปรับใช้ MCP

## ข้อกำหนดด้านความปลอดภัยที่สำคัญ

### การควบคุมความปลอดภัยที่บังคับใช้ (ข้อกำหนดที่ต้องปฏิบัติ)

1. **การตรวจสอบโทเค็น**: เซิร์ฟเวอร์ MCP **ต้องไม่** ยอมรับโทเค็นใด ๆ ที่ไม่ได้ออกโดยชัดเจนสำหรับเซิร์ฟเวอร์ MCP นั้นเอง
2. **การตรวจสอบการอนุญาต**: เซิร์ฟเวอร์ MCP ที่ใช้งานการอนุญาต **ต้อง** ตรวจสอบคำขอเข้าทั้งหมดและ **ต้องไม่** ใช้เซสชันสำหรับการตรวจสอบสิทธิ์  
3. **ความยินยอมของผู้ใช้**: เซิร์ฟเวอร์พร็อกซี MCP ที่ใช้รหัสไคลเอนต์บุคคลที่สามแบบคงที่ **ต้อง** ได้รับความยินยอมอย่างชัดเจนสำหรับแต่ละไคลเอนต์ MCP ก่อนส่งต่อการไหลของการอนุญาต
4. **ความปลอดภัยของ handle สถานะ**: เซิร์ฟเวอร์ MCP **ต้องไม่** ถือครอง handle สถานะแอปพลิเคชันเป็นการตรวจสอบสิทธิ์ และ **ต้อง** อนุญาตคำขอทุกครั้งที่ใช้ handle นั้น



## แนวทางปฏิบัติความปลอดภัยหลัก

### 1. การตรวจสอบและทำความสะอาดข้อมูลเข้า
- **การตรวจสอบข้อมูลเข้าอย่างครบถ้วน:** ตรวจสอบและทำความสะอาดข้อมูลเข้าทั้งหมดเพื่อป้องกันการโจมตีแบบ Injection, ปัญหา confused deputy, และช่องโหว่ prompt injection
- **การบังคับใช้สคีมา parameter:** ใช้การตรวจสอบสคีมา JSON อย่างเข้มงวดสำหรับพารามิเตอร์เครื่องมือและข้อมูลเข้า API ทั้งหมด
- **การกรองเนื้อหา:** ใช้ Microsoft Prompt Shields และ Azure Content Safety ในการกรองเนื้อหาที่เป็นอันตรายใน prompt และคำตอบ
- **การทำความสะอาดผลลัพธ์:** ตรวจสอบและทำความสะอาดผลลัพธ์ของโมเดลทั้งหมดก่อนแสดงให้ผู้ใช้หรือระบบต่อไป

### 2. การตรวจสอบสิทธิ์และการอนุญาตที่ยอดเยี่ยม  
- **ผู้ให้บริการตัวตนภายนอก:** มอบหมายการตรวจสอบสิทธิ์ให้กับผู้ให้บริการตัวตนที่จัดตั้งแล้ว (Microsoft Entra ID, ผู้ให้บริการ OAuth 2.1) แทนการพัฒนาการตรวจสอบสิทธิ์แบบกำหนดเอง
- **การลงทะเบียนไคลเอนต์:** ใช้เอกสารข้อมูลเมตา Client ID หรือการลงทะเบียนล่วงหน้าเป็นหลัก; ใช้การลงทะเบียนไคลเอนต์แบบไดนามิกที่เลิกใช้แล้วเฉพาะเพื่อความเข้ากันได้เท่านั้น
- **สิทธิ์ละเอียด:** ใช้สิทธิ์เฉพาะสำหรับแต่ละเครื่องตามหลักการสิทธิน้อยที่สุด
- **การจัดการวงจรชีวิตโทเค็น:** ใช้โทเค็นเข้าถึงระยะสั้นพร้อมการหมุนเวียนที่ปลอดภัยและการตรวจสอบผู้รับที่ถูกต้อง
- **การยืนยันตัวตนแบบหลายปัจจัย:** ต้องมี MFA สำหรับการเข้าถึงผู้ดูแลระบบและการดำเนินการที่ละเอียดอ่อนทั้งหมด

### 3. โปรโตคอลการสื่อสารที่ปลอดภัย
- **ชั้นความปลอดภัยการส่งข้อมูล:** ใช้ HTTPS พร้อมการตรวจสอบใบรับรองที่ถูกต้อง
 สำหรับการสื่อสาร MCP HTTP ระยะไกล; ใช้การแยกกระบวนการและข้อมูลรับรอง
 สำหรับเซิร์ฟเวอร์ stdio ในเครื่อง
- **การเข้ารหัสแบบ end-to-end:** ใช้ชั้นการเข้ารหัสเพิ่มเติมสำหรับข้อมูลที่มีความละเอียดอ่อนสูงในระหว่างการส่งและเก็บรักษา
- **การจัดการใบรับรอง:** ดูแลวงจรชีวิตใบรับรองด้วยระบบการต่ออายุอัตโนมัติ
- **การบังคับใช้เวอร์ชันโปรโตคอล:** ใช้ MCP `2026-07-28` รวมข้อมูลเมตาเวอร์ชันที่จำเป็นในคำขอทุกครั้ง และปฏิเสธเวอร์ชันที่ไม่รองรับ


### 4. การจำกัดอัตราและการป้องกันทรัพยากรขั้นสูง
- **การจำกัดอัตราหลายชั้น:** ใช้การจำกัดอัตราตามผู้ใช้, ข้อมูลรับรอง,
  การดำเนินงาน, เครื่องมือ, และทรัพยากรเพื่อป้องกันการใช้งานเกินควร
- **การจำกัดอัตราปรับตัว:** ใช้การจำกัดอัตราที่ใช้แมชชีนเลิร์นนิงซึ่งปรับให้เข้ากับรูปแบบการใช้งานและตัวบ่งชี้ภัยคุกคาม
- **การจัดการโควต้าทรัพยากร:** ตั้งค่าขีดจำกัดที่เหมาะสมสำหรับทรัพยากรคำนวณ, การใช้หน่วยความจำ, และเวลาการประมวลผล
- **การป้องกัน DDoS:** ติดตั้งระบบป้องกัน DDoS ครอบคลุมและระบบวิเคราะห์ทราฟฟิก

### 5. การบันทึกและการตรวจสอบครบถ้วน
- **การบันทึกการตรวจสอบเชิงโครงสร้าง:** สร้างบันทึกรายละเอียดและค้นหาได้สำหรับการดำเนินงาน MCP ทั้งหมด, การเรียกใช้งานเครื่องมือ, และเหตุการณ์ความปลอดภัย
- **การตรวจสอบความปลอดภัยแบบเรียลไทม์:** ติดตั้งระบบ SIEM พร้อมการตรวจจับความผิดปกติด้วย AI สำหรับภาระงาน MCP
- **การบันทึกที่เป็นไปตามความเป็นส่วนตัว:** บันทึกเหตุการณ์ความปลอดภัยโดยเคารพข้อกำหนดและกฎหมายความเป็นส่วนตัวของข้อมูล
- **การผนวกรวมการตอบสนองเหตุการณ์:** เชื่อมต่อระบบบันทึกกับกระบวนการตอบสนองเหตุการณ์อัตโนมัติ

### 6. แนวทางการเก็บข้อมูลที่ปลอดภัยขั้นสูง
- **โมดูลความปลอดภัยฮาร์ดแวร์:** ใช้การจัดเก็บกุญแจที่รองรับ HSM (Azure Key Vault, AWS CloudHSM) สำหรับการดำเนินการเข้ารหัสที่สำคัญ
- **การจัดการกุญแจเข้ารหัส:** ดำเนินการหมุนเวียนกุญแจอย่างเหมาะสม, การแยกกุญแจ, และการควบคุมการเข้าถึงกุญแจเข้ารหัส
- **การจัดการความลับ:** จัดเก็บคีย์ API, โทเค็น, และข้อมูลรับรองทั้งหมดในระบบจัดการความลับโดยเฉพาะ
- **การจำแนกข้อมูล:** จำแนกข้อมูลตามระดับความละเอียดอ่อนและใช้มาตรการป้องกันที่เหมาะสม

### 7. การจัดการโทเค็นขั้นสูง
- **การป้องกันการผ่านโทเค็น:** ห้ามอย่างชัดเจนในรูปแบบการผ่านโทเค็นที่ข้ามการควบคุมความปลอดภัย
- **การตรวจสอบผู้รับการเข้าถึง:** ตรวจสอบเสมอว่า claims ผู้รับของโทเค็นตรงกับตัวตนเซิร์ฟเวอร์ MCP ที่ตั้งใจไว้
- **การอนุญาตตาม claims:** ใช้การอนุญาตละเอียดตาม claims ของโทเค็นและคุณสมบัติผู้ใช้
- **การผูกโทเค็น:** ตรวจสอบว่าโทเค็นมุ่งเป้าที่ทรัพยากร MCP ที่ตั้งใจไว้ และ
 ผูก handle สถานะแอปพลิเคชันฝั่งเซิร์ฟเวอร์กับตัวตนที่ผ่านการรับรองแล้ว

### 8. สถานะแอปพลิเคชันที่ปลอดภัย

- **การเข้ารหัส handle สถานะ:** สร้าง handle ที่ทึบและไม่สามารถทำนายได้
 สำหรับสถานะที่ขยายข้ามคำขอ
- **การผูกเฉพาะผู้ใช้:** ผูกแต่ละ handle ฝั่งเซิร์ฟเวอร์กับตัวตนที่ผ่านการรับรอง; ไม่ไว้วางใจ ID ผู้ใช้ที่ส่งมาจากไคลเอนต์
- **การควบคุมวงจรชีวิต:** หมดอายุและเพิกถอน handle รวมถึงกำหนดวิธีที่ผู้เรียกสามารถ
 กู้คืนจากสถานะที่ล้าสมัย
- **การอนุญาตต่อคำขอ:** ตรวจสอบการอนุญาตซ้ำทุกครั้งเมื่อมีการนำเสนอ handle; handle เป็นเพียงชื่อไม่ใช่ข้อมูลรับรอง



### 9. การควบคุมความปลอดภัยเฉพาะ AI
- **การป้องกัน prompt injection:** ใช้ Microsoft Prompt Shields พร้อมเทคนิค spotlighting, delimiters, และ datamarking
- **การป้องกันการปนเปื้อนเครื่องมือ:** ตรวจสอบข้อมูลเมตาเครื่องมือ, เฝ้าระวังการเปลี่ยนแปลงไดนามิก และยืนยันความสมบูรณ์ของเครื่องมือ
- **การตรวจสอบผลลัพธ์โมเดล:** สแกนผลลัพธ์โมเดลเพื่อหาการรั่วไหลของข้อมูลที่อาจเกิดขึ้น, เนื้อหาเป็นอันตราย หรือการละเมิดนโยบายความปลอดภัย
- **การป้องกันหน้าต่างบริบท:** ใช้มาตรการควบคุมเพื่อป้องกันการปนเปื้อนหน้าต่างบริบทและการโจมตีด้วยการบิดเบือน

### 10. ความปลอดภัยในการรันเครื่องมือ
- **การแยกสภาพแวดล้อมรัน:** รันการเรียกใช้เครื่องมือในสภาพแวดล้อมคอนเทนเนอร์แยกตัว พร้อมขีดจำกัดทรัพยากร
- **การแยกสิทธิ์:** รันเครื่องมือด้วยสิทธิ์ที่จำเป็นต่ำสุดและแยกบัญชีบริการ
- **การแยกเครือข่าย:** ใช้การแบ่งส่วนเครือข่ายสำหรับสภาพแวดล้อมการรันเครื่องมือ
- **การตรวจสอบการรัน:** เฝ้าระวังพฤติกรรมผิดปกติ, การใช้ทรัพยากร และการละเมิดความปลอดภัยระหว่างรันเครื่องมือ

### 11. การตรวจสอบความปลอดภัยอย่างต่อเนื่อง
- **การทดสอบความปลอดภัยอัตโนมัติ:** ผนวกการทดสอบความปลอดภัยในสายงาน CI/CD ด้วยเครื่องมือเช่น GitHub Advanced Security
- **การจัดการช่องโหว่:** สแกนอย่างสม่ำเสมอทุกส่วนประกอบ รวมถึงโมเดล AI และบริการภายนอก
- **การทดสอบเจาะระบบ:** ดำเนินการประเมินความปลอดภัยอย่างสม่ำเสมอโดยมุ่งเป้าที่การใช้งาน MCP โดยเฉพาะ
- **การตรวจสอบโค้ดความปลอดภัย:** ใช้นโยบายตรวจสอบความปลอดภัยสำหรับการเปลี่ยนแปลงโค้ดที่เกี่ยวกับ MCP ทุกครั้ง

### 12. ความปลอดภัยในห่วงโซ่อุปทานสำหรับ AI
- **การตรวจสอบส่วนประกอบ:** ตรวจสอบแหล่งกำเนิด, ความสมบูรณ์, และความปลอดภัยของส่วนประกอบ AI ทั้งหมด (โมเดล, embedding, API)
- **การจัดการการพึ่งพา:** รักษารายการปัจจุบันของซอฟต์แวร์และการพึ่งพา AI ทั้งหมด พร้อมตรวจสอบช่องโหว่
- **คลังเก็บที่เชื่อถือได้:** ใช้แหล่งที่มาได้รับการตรวจสอบและเชื่อถือได้สำหรับโมเดล AI, ไลบรารี และเครื่องมือทั้งหมด
- **การติดตามห่วงโซ่อุปทาน:** เฝ้าระวังอย่างต่อเนื่องสำหรับการถูกแทรกแซงในผู้ให้บริการ AI และคลังเก็บโมเดล

## รูปแบบความปลอดภัยขั้นสูง

### สถาปัตยกรรม Zero Trust สำหรับ MCP
- **ไม่เชื่อใจ ใด ๆ ตรวจสอบเสมอ:** ดำเนินการตรวจสอบอย่างต่อเนื่องสำหรับผู้เข้าร่วมทุกคนใน MCP
- **การแบ่งส่วนเครือข่ายย่อย:** แยกส่วนประกอบ MCP ด้วยการควบคุมเครือข่ายและตัวตนอย่างละเอียด
- **การเข้าถึงแบบมีเงื่อนไข:** ใช้การควบคุมการเข้าถึงตามความเสี่ยงที่ปรับตามบริบทและพฤติกรรม
- **การประเมินความเสี่ยงอย่างต่อเนื่อง:** ประเมินสถานะความปลอดภัยอย่างไดนามิกตามตัวบ่งชี้ภัยคุกคามปัจจุบัน

### การใช้งาน AI ที่คำนึงถึงความเป็นส่วนตัว
- **ลดข้อมูลที่จำเป็น:** เปิดเผยข้อมูลเท่าที่จำเป็นสำหรับแต่ละการดำเนินงาน MCP
- **ความเป็นส่วนตัวแบบต่าง:** ใช้วิธีการรักษาความเป็นส่วนตัวสำหรับการประมวลผลข้อมูลที่ละเอียดอ่อน
- **การเข้ารหัสแบบโฮโมมอร์ฟิก:** ใช้เทคนิคการเข้ารหัสขั้นสูงสำหรับการคำนวณที่ปลอดภัยบนข้อมูลเข้ารหัส
- **การเรียนรู้แบบกระจาย:** ใช้วิธีการเรียนรู้แบบกระจายที่คงไว้ซึ่งความเป็นส่วนตัวและท้องถิ่นของข้อมูล

### การตอบสนองเหตุการณ์สำหรับระบบ AI
- **ขั้นตอนเฉพาะ AI สำหรับเหตุการณ์:** พัฒนากระบวนการตอบสนองเหตุการณ์ที่ตอบโจทย์ภัยคุกคามเฉพาะของ AI และ MCP
- **การตอบสนองอัตโนมัติ:** ใช้งานระบบกักกันและแก้ไขอัตโนมัติสำหรับเหตุการณ์ความปลอดภัย AI ทั่วไป  
- **ความพร้อมด้านนิติวิทยาศาสตร์:** เตรียมความพร้อมด้านนิติวิทยาศาสตร์สำหรับการละเมิดระบบ AI และข้อมูลรั่วไหล
- **ขั้นตอนการกู้คืน:** สร้างขั้นตอนสำหรับการกู้คืนจากการปนเปื้อนโมเดล AI, การโจมตี prompt injection และการถูกเจาะระบบบริการ

## 🔄 การปรับปรุงอย่างต่อเนื่อง

### ติดตามมาตรฐานที่พัฒนาอย่างต่อเนื่อง
- **อัปเดตข้อกำหนด MCP**: ติดตามการเปลี่ยนแปลงข้อกำหนด MCP อย่างเป็นทางการและคำแนะนำความปลอดภัย
- **ข่าวกรองภัยคุกคาม**: สมัครรับข้อมูลข่าวสารภัยคุกคามด้านความปลอดภัย AI และฐานข้อมูลช่องโหว่  
- **การมีส่วนร่วมของชุมชน**: เข้าร่วมการสนทนาและกลุ่มทำงานความปลอดภัย MCP
- **การประเมินอย่างสม่ำเสมอ**: ดำเนินการประเมินสถานะความปลอดภัยไตรมาสต่อไตรมาสและปรับปรุงแนวทางตามนั้น

### การมีส่วนร่วมในความปลอดภัย MCP
- **งานวิจัยด้านความปลอดภัย**: มีส่วนร่วมในการวิจัยความปลอดภัย MCP และโปรแกรมเปิดเผยช่องโหว่
- **การแบ่งปันแนวปฏิบัติที่ดีที่สุด**: แบ่งปันการนำความปลอดภัยไปใช้และบทเรียนที่ได้รับกับชุมชน
- **การพัฒนามาตรฐาน**: มีส่วนร่วมในการพัฒนาข้อกำหนด MCP และการสร้างมาตรฐานความปลอดภัย
- **การพัฒนาเครื่องมือ**: พัฒนาและแบ่งปันเครื่องมือและไลบรารีความปลอดภัยสำหรับระบบนิเวศ MCP
