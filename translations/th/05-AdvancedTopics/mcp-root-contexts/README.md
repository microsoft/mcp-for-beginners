# ราก MCP (คุณสมบัติเดิม)

> [!WARNING]
> รากถูกยกเลิกใช้งานตั้งแต่ MCP `2026-07-28` เป็นต้นไป ยังคงอยู่ในการแก้ไขนี้เพื่อ
> ความเข้ากันได้ และมีสิทธิ์ถูกลบออกในการแก้ไขข้อกำหนดแรก
> ที่เผยแพร่ในหรือหลังวันที่ 28 กรกฎาคม 2027 การใช้งานใหม่ควรส่งผ่าน
> โฟลเดอร์หรือไฟล์ผ่านพารามิเตอร์เครื่องมือ, URI ของทรัพยากร, หรือการ
> กำหนดค่าเซิร์ฟเวอร์

## ภาพรวม

รากช่วยให้ลูกค้า MCP แจ้งเซิร์ฟเวอร์ว่าตำแหน่งระบบไฟล์ใดที่เกี่ยวข้อง
กับคำขอปัจจุบัน รากประกอบด้วย URI `file://` ที่จำเป็นและชื่อที่อ่านได้โดยมนุษย์ซึ่งเป็นค่าตัวเลือก


เซสชันโปรโตคอล หรือกลไกควบคุมการเข้าถึง โปรโตคอลไม่ได้
บังคับให้เซิร์ฟเวอร์อยู่ภายในรากที่ระบุไว้


## วัตถุประสงค์การเรียนรู้

เมื่อสิ้นสุดบทเรียนนี้ คุณจะสามารถ:

- อธิบายว่าราก MCP เป็นตัวแทนอะไรและไม่ใช่ตัวแทนอะไร
- ระบุรูปแบบการสื่อสารรอบหลายครั้งของ `roots/list` ปัจจุบัน
- ใช้มาตรการความปลอดภัยแยกต่างหากจากราก
- ย้ายการใช้งานใหม่ไปยังทางเลือกที่รองรับ

## ข้อมูลราก

ลูกค้าส่งคืนรากแต่ละอันเป็น URI `file://` พร้อมชื่อแสดงเป็นค่าตัวเลือก:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

ลูกค้าควรเปิดเผยเฉพาะตำแหน่งที่ได้รับอนุมัติจากผู้ใช้ เซิร์ฟเวอร์ควรมอง
ผลลัพธ์เป็นคำแนะนำเกี่ยวกับไฟล์ที่เกี่ยวข้อง ไม่ใช่หลักฐานการอนุญาต

## รูปแบบ MCP 2026-07-28

ลูกค้าที่รองรับราก ประกาศความสามารถนี้ในทุกคำขอ:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

ในขณะที่ดำเนินการคำขอของลูกค้า เซิร์ฟเวอร์สามารถส่งคืน
`InputRequiredResult` ที่มีคำขอข้อมูลเข้า `roots/list`:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

ลูกค้ารวบรวมรากที่ได้รับอนุมัติและลองคำขอเดิมใหม่โดยมี
`inputResponses` ที่ตรงกันและ `requestState` ที่ไม่เปลี่ยนแปลง รูปแบบรอบ
หลายครั้งนี้ช่วยให้โปรโตคอลไร้สถานะ ไม่มีการจับมือ `initialize` หรือ
เซสชันในระดับโปรโตคอล

## พฤติกรรมเดิม 2025-11-25

ใน MCP `2025-11-25` ลูกค้าโฆษณารากระหว่างการเริ่มต้น เซิร์ฟเวอร์
สามารถสั่งคำขอ `roots/list` โดยตรง และลูกค้าสามารถส่ง
`notifications/roots/list_changed` เมื่อรากเปลี่ยนแปลง

วงจรชีวิตนั้นเป็นพฤติกรรมเดิม หลีกเลี่ยงการรวมตัวอย่างการเริ่มต้นหรือ
การแจ้งเตือนกับการใช้งานแบบ `2026-07-28`

## ตัวเลือกแนะนำเพื่อแทนที่

### พารามิเตอร์เครื่องมือ

กำหนดไดเรกทอรีหรือไฟล์ที่จำเป็นอย่างชัดเจนในสคีมาเครื่องมือ:

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### URI ทรัพยากร

ใช้ MCP Resources เมื่อเซิร์ฟเวอร์สามารถเปิดเผยไฟล์ที่เกี่ยวข้องผ่าน
URI ที่เสถียร วิธีนี้ช่วยให้การค้นหาและการดึงข้อมูลชัดเจน

### การกำหนดค่าเซิร์ฟเวอร์

สำหรับการใช้งานแบบติดตั้งถาวร ให้กำหนดโฟลเดอร์ที่อนุญาตเมื่อเซิร์ฟเวอร์เริ่มต้น 
วิธีนี้มักชัดเจนกว่าการค้นหาพวกมันในขณะเรียกใช้เครื่องมือ

## ข้อกำหนดด้านความปลอดภัย

ไม่ว่าคุณจะเลือกตัวเลือกใด:

- ขอความยินยอมผู้ใช้ก่อนเปิดเผยตำแหน่งระบบไฟล์
- ปรับเส้นทางให้เป็นแบบมาตรฐานและตรวจสอบเพื่อป้องกันการเข้าถึงเกินจำเป็น
- บังคับใช้การอนุญาตและการแยกกล่องทรายแยกจากค่าราก
- ตรวจสอบสิทธิ์อีกครั้งเมื่อมีการเข้าถึงไฟล์ ไม่ใช่แค่ตอนแสดงรายการ
- หลีกเลี่ยงการแสดงเส้นทางที่ละเอียดอ่อนในบันทึกหรือข้อความแสดงข้อผิดพลาด

## สิ่งสำคัญที่ควรจดจำ

- รากอธิบายตำแหน่งระบบไฟล์ที่เกี่ยวข้อง; ไม่ใช่ตัวเก็บสถานะการสนทนา

- รากเป็นคำแนะนำ ไม่ใช่ขอบเขตควบคุมการเข้าถึง
- MCP `2026-07-28` ประกาศความสามารถต่อคำขอและใช้
  `InputRequiredResult` สำหรับ `roots/list`
- การใช้งานใหม่ควรใช้พารามิเตอร์เครื่องมือ, URI ทรัพยากร, หรือ
  การกำหนดค่าเซิร์ฟเวอร์แทน
