# AGENTS.md

## ภาพรวมโครงการ

**MCP สำหรับผู้เริ่มต้น** เป็นหลักสูตรการศึกษาที่เปิดเผยแหล่งที่มาเพื่อเรียนรู้ Model Context Protocol (MCP) - กรอบงานมาตรฐานสำหรับการโต้ตอบระหว่างโมเดล AI และแอปพลิเคชันของลูกค้า ที่เก็บนี้มีวัสดุการเรียนรู้ที่ครอบคลุมพร้อมตัวอย่างโค้ดใช้งานจริงในหลายภาษาโปรแกรม

### เทคโนโลยีสำคัญ

- **ภาษาโปรแกรม**: C#, Java, JavaScript, TypeScript, Python, Rust
- **เฟรมเวิร์ก & SDKs**: 
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **ฐานข้อมูล**: PostgreSQL พร้อมส่วนขยาย pgvector
- **แพลตฟอร์มคลาวด์**: Azure (Container Apps, OpenAI, Content Safety, Application Insights)
- **เครื่องมือสร้าง**: npm, Maven, pip, Cargo
- **เอกสารประกอบ**: Markdown พร้อมการแปลอัตโนมัติหลายภาษา (48+ ภาษา)

### สถาปัตยกรรม

- **11 โมดูลหลัก (00-11)**: เส้นทางการเรียนรู้ต่อเนื่องจากพื้นฐานถึงหัวข้อขั้นสูง
- **ห้องปฏิบัติการใช้งานจริง**: แบบฝึกหัดเชิงปฏิบัติพร้อมโค้ดโซลูชันครบถ้วนในหลายภาษา
- **โครงการตัวอย่าง**: การใช้งานเซิร์ฟเวอร์และไคลเอนต์ MCP ที่ทำงานได้จริง
- **ระบบแปลภาษา**: เวิร์กโฟลว์ GitHub Actions อัตโนมัติสำหรับรองรับหลายภาษา
- **แอสเซทภาพ**: โฟลเดอร์เก็บภาพรวมศูนย์พร้อมเวอร์ชันแปลภาษา

### การทำงานกับโครงการตัวอย่าง

โครงการตัวอย่างตั้งอยู่ที่:
- `03-GettingStarted/samples/` - ตัวอย่างเฉพาะภาษา

แต่ละโครงการตัวอย่างมีคำแนะนำการตั้งค่าเป็นของตัวเอง:

#### โครงการ TypeScript/JavaScript
```bash
cd <project-directory>
npm install
npm start
```

#### โครงการ Python
```bash
cd <project-directory>
pip install -r requirements.txt
# หรือ
pip install -e .
python main.py
```

#### โครงการ Java
```bash
cd <project-directory>
mvn clean install
mvn spring-boot:run
```

##### อินพุต

- `changed_paths: string[]` (จำเป็น) - เส้นทางสัมพัทธ์ที่เปลี่ยนใน PR
- `run_docs_lint: boolean` (ค่าเริ่มต้น `true`)
- `run_links_audit: boolean` (ค่าเริ่มต้น `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (ค่าเริ่มต้นทั้งหมด `false`)

##### เอาต์พุต

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### สิทธิ์

- อ่านไฟล์ในเวิร์กสเปซและเขียนผลลัพธ์ที่เครื่องมือสร้างเท่านั้น (เช่น รายงาน lint,
  บันทึกผลการทดสอบ); ห้ามเขียนลงในโฟลเดอร์ `translations/` หรือ
  `translated_images/`
- เรียกใช้คำสั่ง shell ในเครื่อง
- เข้าถึงเครือข่ายได้เฉพาะการกู้คืนแพ็กเกจ (`npm ci`,
  `python -m pip install`, การแก้ไข dependency ของ `mvn`)
- ไม่มีสิทธิ์ผลักดัน, ผสาน หรือแก้ไข `translations/` หรือ
  `translated_images/`

##### โหมดความล้มเหลว

- `E_NO_INPUT_PATHS`: ไม่มีค่าใน `changed_paths`
- `E_INVALID_PATH`: เส้นทางอินพุตหลุดออกจากราก repository
- `E_LINT_FAILED`: markdown lint จบการทำงานด้วยรหัสไม่เป็นศูนย์
- `E_LINK_AUDIT_FAILED`: คำสั่งสอบทานลิงก์จบการทำงานด้วยรหัสไม่เป็นศูนย์
- `E_SAMPLE_TEST_FAILED`: การทดสอบ/สร้างตัวอย่างจบการทำงานด้วยรหัสไม่เป็นศูนย์
- `E_TIMEOUT`: คำสั่งเกินเวลา timeout ที่ตั้งไว้

4. การแปลจะถูกสร้างใหม่เมื่อต้นทางหลักถูกผลักดัน

## แนวทางสไตล์โค้ด

### สไตล์เอกสาร

- ใช้ภาษาที่ชัดเจนและเข้าใจง่ายสำหรับผู้เริ่มต้น
- รวมตัวอย่างโค้ดในหลายภาษาเมื่อเหมาะสม
- ปฏิบัติตามแนวทางที่ดีที่สุดของ markdown:
  - ใช้หัวเรื่องสไตล์ ATX (`#` syntax)
  - ใช้โค้ดบล็อคที่มีรั้วและระบุภาษาชัดเจน
  - รวมข้อความคำอธิบาย alt สำหรับรูปภาพ
  - รักษาความยาวบรรทัดให้อยู่ในระดับสมเหตุสมผล (ไม่มีขีดจำกัดตายตัว แต่ต้องมีเหตุผล)

### สไตล์ตัวอย่างโค้ด

#### TypeScript/JavaScript
- ใช้โมดูล ES (`import`/`export`)
- ปฏิบัติตามข้อกำหนดโหมดเข้มงวดของ TypeScript
- รวมการระบุชนิดข้อมูล
- เป้าหมาย ES2022

#### Python
- ปฏิบัติตามแนวทางสไตล์ PEP 8
- ใช้คำใบ้ชนิดข้อมูลเมื่อเหมาะสม
- รวม docstrings สำหรับฟังก์ชันและคลาส
- ใช้ฟีเจอร์ Python สมัยใหม่ (3.8+)

#### Java
- ปฏิบัติตามแนวทาง Spring Boot
- ใช้ฟีเจอร์ Java 21
- ปฏิบัติตามโครงสร้างโปรเจกต์ Maven มาตรฐาน
- รวมคอมเมนต์ Javadoc

## แนวทางการมีส่วนร่วม

### กระบวนการ Pull Request

1. **Fork และ Clone**: Fork ที่เก็บและโคลน Fork ของคุณลงในเครื่อง
2. **สร้างสาขาใหม่**: ใช้ชื่อตามคำอธิบายที่ชัดเจน (เช่น `fix/typo-module-3`, `add/python-example`)
3. **แก้ไข**: แก้ไขไฟล์ markdown ภาษาอังกฤษเท่านั้น (ไม่แก้ไขการแปล)
4. **ทดสอบในเครื่อง**: ตรวจสอบว่า markdown แสดงผลถูกต้อง
5. **ส่ง PR**: ใช้หัวข้อและคำอธิบาย PR ที่ชัดเจน
6. **CLA**: ลงนามใน Microsoft Contributor License Agreement เมื่อได้รับแจ้ง

### รูปแบบชื่อ PR

ใช้ชื่อที่ชัดเจนและอธิบายได้ดี:
- `[Module XX] คำอธิบายสั้น` สำหรับการเปลี่ยนแปลงเฉพาะโมดูล
- `[Samples] คำอธิบาย` สำหรับการเปลี่ยนแปลงตัวอย่างโค้ด
- `[Docs] คำอธิบาย` สำหรับการอัปเดตเอกสารทั่วไป

### สิ่งที่ควรมีส่วนร่วม

- แก้ไขข้อผิดพลาดในเอกสารหรือโค้ดตัวอย่าง
- ตัวอย่างโค้ดใหม่ในภาษาเพิ่มเติม
- ชี้แจงและปรับปรุงเนื้อหาที่มีอยู่
- กรณีศึกษาใหม่หรือตัวอย่างเชิงปฏิบัติ
- รายงานปัญหาเนื้อหาที่ไม่ชัดเจนหรืไม่ถูกต้อง

### สิ่งที่ไม่ควรทำ

- ห้ามแก้ไขไฟล์โดยตรงในไดเรกทอรี `translations/`
- ห้ามแก้ไขไดเรกทอรี `translated_images/`
- ห้ามเพิ่มไฟล์ไบนารีขนาดใหญ่โดยไม่หารือก่อน
- ห้ามเปลี่ยนไฟล์กระบวนการแปลโดยไม่ประสานงาน

### เส้นทางการเรียนรู้

ปฏิบัติตามโมดูลตามลำดับ (00-11) เพื่อการเรียนรู้ที่ดีที่สุด:

2. **03**: เริ่มต้นใช้งานด้วยการปฏิบัติจริง
3. **04-05**: การปฏิบัติและหัวข้อขั้นสูง
4. **06-10**: ชุมชน, แนวทางปฏิบัติที่ดีที่สุด, และการประยุกต์ใช้ในโลกจริง
5. **11**: ห้องปฏิบัติการบูรณาการฐานข้อมูลเชิงลึก (13 ห้องปฏิบัติการเรียงตามลำดับ)

### การแก้ปัญหาที่พบบ่อย

**ถาม: PR ของฉันล้มเหลวในการตรวจสอบการแปล**
ตอบ: ตรวจสอบให้แน่ใจว่าแก้ไขไฟล์ markdown ภาษาอังกฤษในไดเรกทอรีโมดูลหลักเท่านั้น ไม่ใช่เวอร์ชันที่แปลแล้ว

**ถาม: ฉันจะเพิ่มภาษาใหม่ได้อย่างไร?**
ตอบ: การสนับสนุนภาษาได้รับการจัดการผ่านกระบวนการ co-op-translator เปิดปัญหาเพื่อหารือเกี่ยวกับการเพิ่มภาษาใหม่

**ถาม: ตัวอย่างโค้ดไม่ทำงาน**
ตอบ: ตรวจสอบว่าคุณได้ทำตามคำแนะนำการตั้งค่าใน README ของตัวอย่างนั้น ตรวจสอบว่าคุณมีเวอร์ชันของส่วนประกอบที่ถูกต้อง


**ถาม: รูปภาพไม่แสดงผล** 

A: ตรวจสอบให้แน่ใจว่าเส้นทางของรูปภาพเป็นแบบสัมพัทธ์และใช้สแลชไปข้างหน้า รูปภาพควรอยู่ในไดเรกทอรี `images/` หรือ `translated_images/` สำหรับเวอร์ชันที่แปล
