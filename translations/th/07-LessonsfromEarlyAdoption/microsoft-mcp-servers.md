# 🚀 10 เซิร์ฟเวอร์ Microsoft MCP ที่กำลังเปลี่ยนแปลงประสิทธิภาพการทำงานของนักพัฒนา

## 🎯 สิ่งที่คุณจะได้เรียนรู้ในคู่มือนี้

คู่มือเชิงปฏิบัตินี้นำเสนอเซิร์ฟเวอร์ Microsoft MCP สิบตัวที่กำลังเปลี่ยนแปลงวิธีการทำงานของนักพัฒนาด้วยผู้ช่วย AI แทนที่จะอธิบายแค่สิ่งที่เซิร์ฟเวอร์ MCP *สามารถ* ทำได้ เราจะแสดงเซิร์ฟเวอร์ที่กำลังสร้างความแตกต่างจริงในเวิร์กโฟลว์การพัฒนารายวันที่ Microsoft และที่อื่นๆ

เซิร์ฟเวอร์แต่ละตัวในคู่มือนี้ถูกคัดเลือกจากการใช้งานจริงและคำติชมของนักพัฒนา คุณจะได้เรียนรู้ไม่เพียงแค่ว่าแต่ละเซิร์ฟเวอร์ทำอะไร แต่ทำไมจึงสำคัญและวิธีใช้ประโยชน์สูงสุดในโปรเจกต์ของตัวเอง ไม่ว่าคุณจะเป็นมือใหม่กับ MCP หรือกำลังขยายระบบที่มีอยู่ เซิร์ฟเวอร์เหล่านี้เป็นเครื่องมือที่ใช้งานได้จริงและมีผลกระทบมากที่สุดในระบบนิเวศของ Microsoft

> **💡 เคล็ดลับเริ่มต้นอย่างรวดเร็ว**
> 
> มือใหม่กับ MCP ไม่ต้องกังวล! คู่มือนี้ออกแบบมาให้เหมาะกับผู้เริ่มต้น เราจะอธิบายแนวคิดไปพร้อมกัน และคุณสามารถอ้างอิงกลับไปยังโมดูล [บทนำสู่ MCP](../00-Introduction/README.md) และ [แนวคิดหลัก](../01-CoreConcepts/README.md) เพื่อความเข้าใจที่ลึกขึ้น

## ภาพรวม

คู่มือครบถ้วนนี้สำรวจเซิร์ฟเวอร์ Microsoft MCP สิบตัวที่ปฏิวัติวิธีที่นักพัฒนาสื่อสารกับผู้ช่วย AI และเครื่องมือภายนอก ตั้งแต่การจัดการทรัพยากร Azure ไปจนถึงการประมวลผลเอกสาร เซิร์ฟเวอร์เหล่านี้แสดงให้เห็นพลังของโปรโตคอล Model Context ในการสร้างเวิร์กโฟลว์การพัฒนาที่ราบรื่นและมีประสิทธิภาพ

## วัตถุประสงค์การเรียนรู้

เมื่อจบคู่มือนี้ คุณจะ:
- เข้าใจว่าเซิร์ฟเวอร์ MCP ช่วยเพิ่มประสิทธิภาพนักพัฒนาอย่างไร
- เรียนรู้เกี่ยวกับการใช้งานเซิร์ฟเวอร์ MCP ที่มีผลกระทบมากที่สุดของ Microsoft
- ค้นพบกรณีการใช้งานเชิงปฏิบัติสำหรับแต่ละเซิร์ฟเวอร์
- รู้วิธีตั้งค่าและกำหนดค่าเซิร์ฟเวอร์เหล่านี้ใน VS Code และ Visual Studio
- สำรวจระบบนิเวศ MCP ที่กว้างขึ้นและทิศทางในอนาคต

## 🔧 ทำความเข้าใจเซิร์ฟเวอร์ MCP: คู่มือสำหรับผู้เริ่มต้น

### เซิร์ฟเวอร์ MCP คืออะไร?

สำหรับผู้เริ่มต้นกับโปรโตคอล Model Context (MCP) คุณอาจสงสัยว่า: "เซิร์ฟเวอร์ MCP คืออะไร และทำไมฉันต้องสนใจ?" มาเริ่มด้วยการเปรียบเทียบง่ายๆ กัน

ลองคิดว่าเซิร์ฟเวอร์ MCP เป็นผู้ช่วยเฉพาะทางที่ช่วยให้ผู้ช่วยเขียนโค้ด AI ของคุณ (เช่น GitHub Copilot) เชื่อมต่อกับเครื่องมือและบริการภายนอก เช่นเดียวกับที่คุณอาจใช้แอปต่างๆ บนโทรศัพท์สำหรับงานต่างๆ หนึ่งแอปสำหรับดูสภาพอากาศ หนึ่งแอปสำหรับนำทาง หนึ่งแอปสำหรับธนาคาร เซิร์ฟเวอร์ MCP ช่วยให้ผู้ช่วย AI ของคุณโต้ตอบกับเครื่องมือและบริการพัฒนาได้หลายแบบ

### ปัญหาที่เซิร์ฟเวอร์ MCP แก้ไข

ก่อนจะมีเซิร์ฟเวอร์ MCP ถ้าคุณอยากจะ:
- ตรวจสอบทรัพยากร Azure ของคุณ
- สร้างปัญหาใน GitHub
- คิวรีฐานข้อมูลของคุณ
- ค้นหาในเอกสาร

คุณต้องหยุดเขียนโค้ด เปิดเว็บเบราว์เซอร์ ไปยังเว็บไซต์ที่เหมาะสม และทำงานเหล่านี้ด้วยตนเอง การสลับบริบทบ่อยๆ นี้ทำลายความต่อเนื่องและลดประสิทธิภาพ

### วิธีที่เซิร์ฟเวอร์ MCP เปลี่ยนประสบการณ์การพัฒนาของคุณ

ด้วยเซิร์ฟเวอร์ MCP คุณสามารถอยู่ในสภาพแวดล้อมการพัฒนา (VS Code, Visual Studio ฯลฯ) และขอให้ผู้ช่วย AI ของคุณจัดการงานเหล่านี้ได้ เช่น:

**แทนเวิร์กโฟลว์แบบดั้งเดิมนี้:**
1. หยุดเขียนโค้ด
2. เปิดเว็บเบราว์เซอร์
3. ไปที่พอร์ทัล Azure
4. ดูรายละเอียดบัญชีจัดเก็บข้อมูล
5. กลับไปยัง VS Code
6. เขียนโค้ดต่อ

**คุณสามารถทำแบบนี้ได้:**
1. ถาม AI: "สถานะของบัญชีจัดเก็บข้อมูล Azure ของฉันเป็นอย่างไรบ้าง?"
2. เขียนโค้ดต่อโดยใช้ข้อมูลที่ได้รับ

### ประโยชน์หลักสำหรับมือใหม่

#### 1. 🔄 **อยู่ในสภาพการไหลของคุณ**
- ไม่ต้องสลับไปมาระหว่างแอปต่างๆ หลายตัว
- รักษาความสนใจไว้ที่โค้ดที่คุณกำลังเขียน
- ลดภาระทางจิตใจจากการจัดการเครื่องมือต่างๆ

#### 2. 🤖 **ใช้ภาษาธรรมชาติแทนคำสั่งซับซ้อน**
- แทนที่จะจำ syntax SQL ให้บรรยายว่าข้อมูลที่คุณต้องการคืออะไร
- แทนที่จะจำคำสั่ง Azure CLI ให้บอกว่าคุณต้องการทำอะไร
- ให้ AI จัดการรายละเอียดทางเทคนิค ในขณะที่คุณมุ่งเน้นที่ตรรกะ

#### 3. 🔗 **เชื่อมต่อเครื่องมือหลายตัวเข้าด้วยกัน**
- สร้างเวิร์กโฟลว์ที่ทรงพลังโดยการผสมผสานบริการต่างๆ
- ตัวอย่าง: "ดึงปัญหา GitHub ล่าสุดทั้งหมดและสร้างงานที่เกี่ยวข้องใน Azure DevOps"
- สร้างระบบอัตโนมัติโดยไม่ต้องเขียนสคริปต์ซับซ้อน

#### 4. 🌐 **เข้าถึงระบบนิเวศที่เติบโตขึ้นเรื่อยๆ**
- ได้ประโยชน์จากเซิร์ฟเวอร์ที่สร้างโดย Microsoft, GitHub และบริษัทอื่นๆ
- ผสมผสานเครื่องมือจากผู้ขายต่างๆ ได้อย่างราบรื่น
- เข้าร่วมระบบมาตรฐานที่ใช้งานได้กับผู้ช่วย AI หลายตัว

#### 5. 🛠️ **เรียนรู้ผ่านการลงมือทำ**
- เริ่มต้นด้วยเซิร์ฟเวอร์ที่สร้างไว้แล้วเพื่อเข้าใจแนวคิด
- ค่อยๆ สร้างเซิร์ฟเวอร์ของตัวเองเมื่อรู้สึกมั่นใจขึ้น
- ใช้ SDK และเอกสารที่มีอยู่เป็นแนวทางเรียนรู้

### ตัวอย่างจากโลกจริงสำหรับผู้เริ่มต้น

สมมุติว่าคุณเป็นมือใหม่ด้านเว็บและกำลังทำโปรเจกต์แรก นี่คือวิธีที่เซิร์ฟเวอร์ MCP ช่วยได้:

**วิธีแบบดั้งเดิม:**
```
1. Code a feature
2. Open browser → Navigate to GitHub
3. Create an issue for testing
4. Open another tab → Check Azure docs for deployment
5. Open third tab → Look up database connection examples
6. Return to VS Code
7. Try to remember what you were doing
```

**ด้วยเซิร์ฟเวอร์ MCP:**
```
1. Code a feature
2. Ask AI: "Create a GitHub issue for testing this login feature"
3. Ask AI: "How do I deploy this to Azure according to the docs?"
4. Ask AI: "Show me the best way to connect to my database"
5. Continue coding with all the information you need
```

### ข้อได้เปรียบของมาตรฐานองค์กร

MCP กำลังกลายเป็นมาตรฐานอุตสาหกรรม ซึ่งหมายความว่า:
- **ความสม่ำเสมอ**: ประสบการณ์คล้ายกันผ่านเครื่องมือต่างๆ และบริษัทต่างๆ
- **ความสามารถในการทำงานร่วมกัน**: เซิร์ฟเวอร์จากผู้ขายต่างๆ สามารถทำงานร่วมกันได้
- **รองรับอนาคต**: ทักษะและการตั้งค่าสามารถย้ายไปยังผู้ช่วย AI ตัวอื่นได้
- **ชุมชน**: ระบบนิเวศขนาดใหญ่ของความรู้และทรัพยากรร่วมกัน

## การเริ่มต้นใช้งาน MCP ใน VS Code และ Visual Studio 🚀

การตั้งค่าเซิร์ฟเวอร์ MCP เหล่านี้ทำได้ง่ายถ้าคุณใช้ Visual Studio Code หรือ Visual Studio 2022 พร้อม GitHub Copilot

### การตั้งค่าใน VS Code

นี่คือกระบวนการพื้นฐานสำหรับ VS Code:

1. **เปิดโหมด Agent**: ใน VS Code สลับไปที่โหมด Agent ในหน้าต่างแชท Copilot
2. **กำหนดค่าเซิร์ฟเวอร์ MCP**: เพิ่มการกำหนดค่าเซิร์ฟเวอร์ในไฟล์ settings.json ของ VS Code
3. **เริ่มเซิร์ฟเวอร์**: คลิกปุ่ม "Start" สำหรับเซิร์ฟเวอร์ที่ต้องการใช้
4. **เลือกเครื่องมือ**: เลือกเซิร์ฟเวอร์ MCP ที่จะเปิดใช้งานสำหรับเซสชันปัจจุบัน

สำหรับคำแนะนำการตั้งค่าโดยละเอียด ให้ดูที่ [เอกสาร MCP ของ VS Code](https://code.visualstudio.com/docs/copilot/copilot-mcp)

> **💡 เคล็ดลับมือโปร: จัดการเซิร์ฟเวอร์ MCP เหมือนมืออาชีพ!**
> 
> ตอนนี้มุมมองส่วนขยายของ VS Code มี [UI ใหม่ที่ใช้งานง่ายสำหรับจัดการเซิร์ฟเวอร์ MCP ที่ติดตั้งไว้](https://code.visualstudio.com/docs/copilot/chat/mcp-servers#_use-mcp-tools-in-agent-mode)! คุณสามารถเข้าถึงได้อย่างรวดเร็วเพื่อเริ่ม หยุด และจัดการเซิร์ฟเวอร์ MCP ที่ติดตั้งด้วยอินเทอร์เฟซที่ชัดเจนและเรียบง่าย ลองใช้ดู!

### การตั้งค่า Visual Studio 2022

สำหรับ Visual Studio 2022 (เวอร์ชัน 17.14 ขึ้นไป):

1. **เปิดโหมด Agent**: คลิกเมนู "Ask" ในหน้าต่าง GitHub Copilot Chat แล้วเลือก "Agent"
2. **สร้างไฟล์กำหนดค่า**: สร้างไฟล์ `.mcp.json` ในไดเรกทอรีโซลูชันของคุณ (แนะนำที่ตั้ง: `<SOLUTIONDIR>\.mcp.json`)
3. **กำหนดค่าเซิร์ฟเวอร์**: เพิ่มการตั้งค่าเซิร์ฟเวอร์ MCP ด้วยรูปแบบมาตรฐาน MCP
4. **อนุมัติเครื่องมือ**: เมื่อได้รับแจ้ง ให้อนุมัติเครื่องมือที่จะใช้ด้วยสิทธิ์การเข้าถึงที่เหมาะสม

สำหรับคำแนะนำการตั้งค่า Visual Studio โดยละเอียด ให้ดูที่ [เอกสาร MCP ของ Visual Studio](https://learn.microsoft.com/visualstudio/ide/mcp-servers)

เซิร์ฟเวอร์ MCP แต่ละตัวมีความต้องการในการกำหนดค่าของตัวเอง (เช่น สตริงการเชื่อมต่อ การยืนยันตัวตน ฯลฯ) แต่รูปแบบการตั้งค่ามีความสอดคล้องกันทั้งสอง IDE

**ประโยชน์**: แม้มันอาจดูเหมือนแค่เอกสาร แต่เซิร์ฟเวอร์นี้มีความสำคัญสำหรับนักพัฒนาทุกคนที่ใช้เทคโนโลยีของ Microsoft หนึ่งในข้อร้องเรียนที่ใหญ่ที่สุดจากนักพัฒนา .NET เกี่ยวกับผู้ช่วยเขียนโค้ด AI คือพวกเขาไม่ได้อัปเดตล่าสุดในเรื่องของเวอร์ชัน .NET หรือ C# Microsoft Learn Docs MCP Server แก้ปัญหานี้ด้วยการให้การเข้าถึงเอกสาร API และแนวทางปฏิบัติที่เป็นปัจจุบันอย่างแท้จริง ไม่ว่าคุณจะทำงานกับ SDK Azure ล่าสุด สำรวจคุณลักษณะของ C# 13 หรือใช้รูปแบบ Aspire ที่ก้าวหน้า เซิร์ฟเวอร์นี้จะช่วยให้ผู้ช่วย AI ของคุณเข้าถึงข้อมูลที่เป็นทางการและทันสมัยเพื่อสร้างโค้ดที่ถูกต้องและทันสมัย

**การใช้งานจริง**: "คำสั่ง az cli ที่ใช้สร้างแอป Azure container ตามเอกสารอย่างเป็นทางการของ Microsoft Learn คืออะไร?" หรือ "ฉันจะกำหนดค่า Entity Framework ด้วยการฉีดพึ่งพาใน ASP.NET Core อย่างไร?" หรือ "ช่วยตรวจสอบโค้ดนี้ให้แน่ใจว่าเป็นไปตามคำแนะนำด้านประสิทธิภาพในเอกสาร Microsoft Learn" เซิร์ฟเวอร์ให้การค้นหาอย่างละเอียดทั่ว Microsoft Learn, เอกสาร Azure และ Microsoft 365 โดยใช้การค้นหาเชิงความหมายขั้นสูงเพื่อค้นหาข้อมูลที่เกี่ยวข้องที่สุด มันคืนผลลัพธ์เนื้อหาคุณภาพสูงสูงสุด 10 ชิ้นพร้อมชื่อบทความและ URL โดยเข้าถึงเอกสาร Microsoft ล่าสุดเสมอเมื่อมีการเผยแพร่

**ตัวอย่างเด่น**: เซิร์ฟเวอร์นี้เปิดเผยเครื่องมือ `microsoft_docs_search` ที่ทำการค้นหาเชิงความหมายกับเอกสารเทคนิคอย่างเป็นทางการของ Microsoft เมื่อกำหนดค่าแล้ว คุณสามารถถามคำถามเช่น "ฉันจะใช้งานระบบพิสูจน์ตัวตน JWT ใน ASP.NET Core ได้อย่างไร?" และได้รับคำตอบอย่างละเอียดและเป็นทางการพร้อมลิงก์แหล่งที่มา คุณภาพการค้นหายอดเยี่ยมเพราะมันเข้าใจบริบท – การถามเกี่ยวกับ "containers" ในบริบท Azure จะคืนเอกสาร Azure Container Instances ในขณะที่คำเดียวกันในบริบท .NET จะคืนข้อมูลที่เกี่ยวข้องกับการจัดเก็บข้อมูลของ C#

นี่มีประโยชน์อย่างยิ่งสำหรับไลบรารีและกรณีใช้งานที่เปลี่ยนแปลงเร็วหรือได้รับการอัปเดตใหม่ๆ เช่น ในโปรเจกต์โค้ดดิ้งล่าสุดของผมที่ต้องการใช้ฟีเจอร์ใน Aspire และ Microsoft.Extensions.AI รุ่นล่าสุด การเพิ่ม Microsoft Learn Docs MCP server ช่วยให้ผมใช้ได้ไม่เพียงแค่เอกสาร API แต่รวมถึงการสาธิตและคำแนะนำที่เพิ่งเผยแพร่ไม่นาน

### 2. ☁️ เซิร์ฟเวอร์ Azure MCP


[![ติดตั้งใน VS Code](https://img.shields.io/badge/VS_Code-Install_Azure_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D) [![ติดตั้งใน VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Azure_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Azure/azure-mcp)

**สิ่งที่มันทำ**: Azure MCP Server คือชุดเครื่องมือครบวงจรที่ประกอบด้วยตัวเชื่อมต่อบริการ Azure กว่า 15 ตัวที่เฉพาะเจาะจง ซึ่งนำระบบนิเวศ Azure ทั้งหมดมาสู่เวิร์กโฟลว์ AI ของคุณ นี่ไม่ใช่แค่เซิร์ฟเวอร์เดี่ยว — แต่มันคือชุดเครื่องมือทรงพลังที่รวมถึงการจัดการทรัพยากร การเชื่อมต่อฐานข้อมูล (PostgreSQL, SQL Server), การวิเคราะห์บันทึก Azure Monitor ด้วย KQL, การผสาน Cosmos DB และอื่น ๆ อีกมากมาย

**ทำไมมันถึงมีประโยชน์**: นอกจากแค่การจัดการทรัพยากร Azure แล้ว เซิร์ฟเวอร์นี้ยังช่วยปรับปรุงคุณภาพโค้ดอย่างมากเมื่อนำไปใช้กับ SDK ของ Azure เมื่อคุณใช้ Azure MCP ในโหมด Agent, มันไม่ได้แค่ช่วยคุณเขียนโค้ด — มันช่วยให้คุณเขียนโค้ด Azure ที่ *ดีกว่า* ซึ่งสอดคล้องกับรูปแบบการตรวจสอบสิทธิ์ปัจจุบัน, การจัดการข้อผิดพลาดตามแนวปฏิบัติที่ดีที่สุด และใช้ประโยชน์จากฟีเจอร์ SDK ล่าสุด แทนที่จะได้โค้ดทั่วไปที่อาจทำงานได้ คุณจะได้โค้ดที่สอดคล้องกับรูปแบบที่ Azure แนะนำสำหรับงานที่ใช้งานจริง

**โมดูลสำคัญประกอบด้วย**:
- **🗄️ ตัวเชื่อมต่อฐานข้อมูล**: เข้าถึงฐานข้อมูล Azure สำหรับ PostgreSQL และ SQL Server ด้วยภาษาธรรมชาติโดยตรง
- **📊 Azure Monitor**: วิเคราะห์บันทึกด้วย KQL และให้ข้อมูลเชิงลึกด้านการดำเนินงาน
- **🌐 การจัดการทรัพยากร**: การจัดการวงจรชีวิตทรัพยากร Azure แบบครบถ้วน
- **🔐 การตรวจสอบสิทธิ์**: รูปแบบ DefaultAzureCredential และ managed identity
- **📦 บริการเก็บข้อมูล**: การดำเนินการ Blob Storage, Queue Storage, และ Table Storage
- **🚀 บริการคอนเทนเนอร์**: การจัดการ Azure Container Apps, Container Instances, และ AKS
- **และตัวเชื่อมต่อเฉพาะทางอื่น ๆ อีกมากมาย**

**การใช้งานในโลกจริง**: "แสดงบัญชีเก็บข้อมูล Azure ของฉัน", "สอบถาม Log Analytics workspace ของฉันสำหรับข้อผิดพลาดในชั่วโมงที่ผ่านมา", หรือ "ช่วยฉันสร้างแอป Azure ด้วย Node.js โดยใช้การตรวจสอบสิทธิ์อย่างถูกต้อง"

**สถานการณ์เดโมเต็มรูปแบบ**: นี่คือการสาธิตที่สมบูรณ์ซึ่งแสดงให้เห็นพลังของการรวม Azure MCP กับส่วนขยาย GitHub Copilot for Azure ใน VS Code เมื่อคุณติดตั้งทั้งคู่และพิมพ์:

> "สร้างสคริปต์ Python ที่อัปโหลดไฟล์ไปยัง Azure Blob Storage โดยใช้การตรวจสอบสิทธิ์ DefaultAzureCredential สคริปต์นี้ต้องเชื่อมต่อกับบัญชีเก็บข้อมูล Azure ของฉันชื่อ 'mycompanystorage', อัปโหลดไปยังคอนเทนเนอร์ชื่อ 'documents', สร้างไฟล์ทดสอบพร้อมกับเวลาปัจจุบันเพื่อนำไปอัปโหลด, จัดการข้อผิดพลาดอย่างราบรื่นและให้ผลลัพธ์ที่ให้ข้อมูล, ปฏิบัติตามแนวทางปฏิบัติที่ดีที่สุดของ Azure สำหรับการตรวจสอบสิทธิ์และการจัดการข้อผิดพลาด, รวมคอมเมนต์อธิบายการทำงานของการตรวจสอบสิทธิ์ DefaultAzureCredential และจัดโครงสร้างสคริปต์ดีพร้อมฟังก์ชันและการจัดทำเอกสารอย่างเหมาะสม"

Azure MCP Server จะสร้างสคริปต์ Python ที่พร้อมใช้งานจริงและครบถ้วนที่:
- ใช้ SDK ล่าสุดของ Azure Blob Storage พร้อมรูปแบบ async ที่เหมาะสม
- ใช้ DefaultAzureCredential พร้อมคำอธิบายเชิงลึกของ fallback chain
- รวมการจัดการข้อผิดพลาดที่แข็งแกร่งพร้อมประเภทข้อยกเว้นเฉพาะของ Azure
- ปฏิบัติตามแนวทางที่ดีที่สุดของ SDK Azure สำหรับการจัดการทรัพยากรและการจัดการการเชื่อมต่อ
- ให้การบันทึกและผลลัพธ์บนคอนโซลที่ให้ข้อมูลอย่างละเอียด
- สร้างสคริปต์ที่มีโครงสร้างเรียบร้อยพร้อมฟังก์ชัน การจัดทำเอกสาร และคำบอกประเภท

สิ่งที่ทำให้สิ่งนี้โดดเด่นคือหากไม่มี Azure MCP คุณอาจได้โค้ด blob storage ทั่วไปที่ทำงานได้แต่ไม่สอดคล้องกับรูปแบบปัจจุบันของ Azure แต่กับ Azure MCP คุณจะได้โค้ดที่ใช้วิธีตรวจสอบสิทธิ์ล่าสุด จัดการสถานการณ์ข้อผิดพลาดเฉพาะของ Azure และปฏิบัติตามแนวทางที่ Microsoft แนะนำสำหรับแอปพลิเคชันที่ใช้งานจริง

**ตัวอย่างโดดเด่น**: ฉันมักจะลำบากกับการจำคำสั่ง `az` และ `azd` CLI สำหรับการใช้งานแบบทันที มันมักจะเป็นกระบวนการสองขั้นตอนสำหรับฉัน: ดูไวยากรณ์ก่อน แล้วจึงรันคำสั่ง ฉันมักจะเปิดพอร์ทัลและคลิกไปมาเพื่อทำงาน เพราะไม่อยากยอมรับว่าจำไวยากรณ์ CLI ไม่ได้ การที่สามารถอธิบายสิ่งที่ต้องการได้ตรง ๆ เป็นสิ่งที่ยอดเยี่ยม และที่ดีกว่านั้นคือทำได้โดยไม่ต้องออกจาก IDE ของฉัน!

มีรายการกรณีการใช้งานที่ยอดเยี่ยมใน [Azure MCP repository](https://github.com/Azure/azure-mcp?tab=readme-ov-file#-what-can-you-do-with-the-azure-mcp-server) เพื่อเริ่มต้น สำหรับคำแนะนำการตั้งค่าเต็มรูปแบบและตัวเลือกการกำหนดค่าขั้นสูง โปรดดูที่ [เอกสาร Azure MCP อย่างเป็นทางการ](https://learn.microsoft.com/azure/developer/azure-mcp-server/)

**ทำไมมันถึงมีประโยชน์**: เซิร์ฟเวอร์นี้เปลี่ยนแปลงวิธีที่คุณโต้ตอบกับ GitHub โดยนำประสบการณ์แพลตฟอร์มเต็มรูปแบบมาไว้ในสภาพแวดล้อมการพัฒนาของคุณ แทนที่จะต้องสลับไปมาระหว่าง VS Code กับ GitHub.com สำหรับการจัดการโปรเจกต์ การตรวจสอบโค้ด และการติดตาม CI/CD คุณสามารถจัดการทุกอย่างผ่านคำสั่งภาษาธรรมชาติขณะที่ยังโฟกัสกับโค้ดของคุณได้

> **ℹ️ หมายเหตุ: ประเภทต่าง ๆ ของ 'Agents'**
> 
> อย่าสับสนระหว่าง GitHub MCP Server นี้กับ GitHub's Coding Agent (เอเจนต์ AI ที่คุณสามารถมอบหมายงานโปรแกรมอัตโนมัติให้กับปัญหาได้) GitHub MCP Server ทำงานในโหมด Agent ของ VS Code เพื่อให้การผสานรวมกับ GitHub API ขณะที่ GitHub's Coding Agent เป็นฟีเจอร์แยกที่สร้าง pull request เมื่อได้รับมอบหมายให้กับปัญหาใน GitHub

**ความสามารถหลักประกอบด้วย**:
- **⚙️ GitHub Actions**: การจัดการ CI/CD pipeline แบบครบวงจร, การติดตามเวิร์กโฟลว์ และการจัดการ artifacts
- **🔀 Pull Requests**: สร้าง, ตรวจสอบ, รวม, และจัดการ PR พร้อมการติดตามสถานะอย่างครบถ้วน
- **🐛 Issues**: การจัดการวงจรชีวิตปัญหาอย่างเต็มรูปแบบ, การคอมเมนต์, การติดป้าย, และการมอบหมายงาน
- **🔒 ความปลอดภัย**: การแจ้งเตือนการสแกนโค้ด, การตรวจจับความลับ, และการผสาน Dependabot
- **🔔 การแจ้งเตือน**: การจัดการการแจ้งเตือนแบบชาญฉลาด และการควบคุมการสมัครสมาชิกรีโพซิทอรี
- **📁 การจัดการรีโพซิทอรี**: การดำเนินการไฟล์, การจัดการสาขา และการบริหารรีโพซิทอรี
- **👥 การทำงานร่วมกัน**: การค้นหาผู้ใช้และองค์กร, การจัดการทีม, และการควบคุมการเข้าถึง

**การใช้งานในโลกจริง**: "สร้าง pull request จากสาขาฟีเจอร์ของฉัน", "แสดงผลการรัน CI ที่ล้มเหลวทั้งหมดในสัปดาห์นี้", "แสดงแจ้งเตือนความปลอดภัยที่เปิดอยู่สำหรับรีโพซิทอรีของฉัน", หรือ "ค้นหาปัญหาทั้งหมดที่มอบหมายให้ฉันในองค์กรของฉัน"

**สถานการณ์เดโมเต็มรูปแบบ**: นี่คือเวิร์กโฟลว์ที่ทรงพลังซึ่งแสดงความสามารถของ GitHub MCP Server:

> "ฉันต้องเตรียมสำหรับการทบทวน sprint ของเรา แสดง pull request ทั้งหมดที่ฉันสร้างในสัปดาห์นี้, ตรวจสอบสถานะของ CI/CD pipeline ของเรา, สร้างสรุปของการแจ้งเตือนความปลอดภัยที่เราต้องจัดการ, และช่วยฉันร่างบันทึกการปล่อยเวอร์ชันโดยใช้ PR ที่ถูกรวมพร้อมป้าย 'feature'"

GitHub MCP Server จะ:
- สอบถาม pull request ล่าสุดของคุณพร้อมข้อมูลสถานะโดยละเอียด
- วิเคราะห์การรันเวิร์กโฟลว์และเน้นความล้มเหลวหรือปัญหาด้านประสิทธิภาพ
- รวบรวมผลการสแกนความปลอดภัยและจัดลำดับความสำคัญของการแจ้งเตือนที่สำคัญ
- สร้างบันทึกการปล่อยอย่างละเอียดโดยดึงข้อมูลจาก PR ที่ถูกรวม
- ให้ขั้นตอนถัดไปที่สามารถดำเนินการได้สำหรับการวางแผน sprint และการเตรียมปล่อยเวอร์ชัน

**ตัวอย่างโดดเด่น**: ฉันชอบใช้สิ่งนี้สำหรับเวิร์กโฟลว์ตรวจสอบโค้ด แทนที่จะต้องสลับไปมาระหว่าง VS Code, การแจ้งเตือน GitHub, และหน้าของ pull request ฉันสามารถพูดว่า "แสดง PR ทั้งหมดที่รอการตรวจสอบของฉัน" แล้วต่อด้วย "เพิ่มคอมเมนต์ใน PR #123 ถามเกี่ยวกับการจัดการข้อผิดพลาดในวิธีตรวจสอบสิทธิ์" เซิร์ฟเวอร์จะจัดการเรียก API ของ GitHub, คงบริบทเกี่ยวกับการสนทนา, และแม้แต่ช่วยฉันร่างคอมเมนต์ตรวจสอบที่สร้างสรรค์มากขึ้น

**ตัวเลือกการตรวจสอบสิทธิ์**: เซิร์ฟเวอร์รองรับทั้ง OAuth (แบบไร้รอยต่อใน VS Code) และ Personal Access Tokens พร้อมชุดเครื่องมือที่สามารถกำหนดค่าเพื่อเปิดใช้งานเฉพาะฟังก์ชัน GitHub ที่คุณต้องการ คุณสามารถใช้งานในฐานะบริการโฮสต์ระยะไกลสำหรับการตั้งค่าทันทีหรือในเครื่องผ่าน Docker เพื่อควบคุมทั้งหมด

> **💡 เคล็ดลับระดับโปร**
> 
> เปิดใช้งานเฉพาะชุดเครื่องมือที่คุณต้องการโดยการกำหนดค่าพารามิเตอร์ `--toolsets` ในการตั้งค่า MCP server เพื่อลดขนาดบริบทและปรับปรุงการเลือกเครื่องมือ AI ตัวอย่างเช่น เพิ่ม `"--toolsets", "repos,issues,pull_requests,actions"` ในอาร์กิวเมนต์การกำหนดค่า MCP สำหรับเวิร์กโฟลว์พัฒนาหลัก หรือใช้ `"--toolsets", "notifications, security"` หากคุณต้องการฟังก์ชันการตรวจสอบ GitHub เป็นหลัก

### 5. 📝 MarkItDown MCP Server


[![ติดตั้งใน VS Code](https://img.shields.io/badge/VS_Code-Install_MarkItDown_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=MarkItDown%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40microsoft%2Fmcp-markitdown%40latest%22%5D%7D) [![ติดตั้งใน VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_MarkItDown_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=MarkItDown%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40microsoft%2Fmcp-markitdown%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/microsoft/markitdown)

**สิ่งที่ทำได้**: MarkItDown เป็นเซิร์ฟเวอร์แปลงเอกสารแบบครบวงจรที่แปลงไฟล์หลากหลายรูปแบบเป็น Markdown คุณภาพสูง เหมาะสำหรับการใช้งานกับ LLM และกระบวนการวิเคราะห์ข้อความ

**เหตุใดจึงมีประโยชน์**: จำเป็นสำหรับกระบวนการจัดทำเอกสารสมัยใหม่! MarkItDown รองรับไฟล์หลากหลายรูปแบบอย่างน่าประทับใจพร้อมรักษาโครงสร้างของเอกสาร เช่น หัวข้อ รายการ ตาราง และลิงก์ ต่างจากเครื่องมือดึงข้อความธรรมดา MarkItDown ให้ความสำคัญกับการรักษาความหมายและรูปแบบที่สำคัญสำหรับทั้งการประมวลผล AI และการอ่านของมนุษย์

**รูปแบบไฟล์ที่รองรับ**:
- **เอกสารสำนักงาน**: PDF, PowerPoint (PPTX), Word (DOCX), Excel (XLSX/XLS)
- **ไฟล์สื่อ**: รูปภาพ (พร้อมข้อมูล EXIF และ OCR), เสียง (พร้อมข้อมูล EXIF และถอดเสียงพูด)
- **เนื้อหาเว็บ**: HTML, ฟีด RSS, URL YouTube, หน้า Wikipedia
- **รูปแบบข้อมูล**: CSV, JSON, XML, ไฟล์ ZIP (ประมวลผลเนื้อหาภายในแบบเรียกซ้ำ)
- **รูปแบบตีพิมพ์**: EPub, โน้ตบุ๊ก Jupyter (.ipynb)
- **อีเมล**: ข้อความ Outlook (.msg)
- **ขั้นสูง**: การรวม Azure Document Intelligence สำหรับการประมวลผล PDF ที่ดียิ่งขึ้น

**ความสามารถขั้นสูง**: MarkItDown รองรับการอธิบายภาพด้วย LLM (เมื่อใช้ลูกค้า OpenAI ร่วมด้วย), Azure Document Intelligence สำหรับการประมวลผล PDF อย่างครอบคลุม, การถอดเสียงจากเสียงพูด และระบบปลั๊กอินเพื่อขยายไปยังรูปแบบไฟล์เพิ่มเติม

**การใช้งานจริง**: "แปลงงานนำเสนอ PowerPoint นี้เป็น Markdown สำหรับไซต์เอกสารของเรา", "ดึงข้อความจาก PDF นี้พร้อมโครงสร้างหัวข้อที่ถูกต้อง" หรือ "แปลงสเปรดชีต Excel นี้เป็นรูปแบบตารางที่อ่านง่าย"

**ตัวอย่างเด่น**: อ้างอิงจาก [เอกสารของ MarkItDown](https://github.com/microsoft/markitdown#why-markdown):

> Markdown ใกล้เคียงกับข้อความธรรมดามากที่สุด โดยมีมาร์คอัปหรือรูปแบบน้อยที่สุด แต่ยังคงให้วิธีในการแสดงโครงสร้างเอกสารที่สำคัญ LLM ที่ได้รับความนิยมอย่าง OpenAI's GPT-4o พูด Markdown ได้โดยตรง และมักจะรวม Markdown เข้าไปในคำตอบของพวกเขาโดยไม่ได้รับการกระตุ้น นี่แสดงว่าพวกเขาผ่านการฝึกสอนด้วยข้อความ Markdown จำนวนมหาศาลและเข้าใจมันอย่างดี อีกทั้งหลักการของ Markdown ยังประหยัดโทเค็นอย่างมากด้วย

MarkItDown มีความสามารถยอดเยี่ยมในการเก็บรักษาโครงสร้างเอกสาร ซึ่งจำเป็นสำหรับเวิร์กโฟลว์ AI เช่น เมื่อต้องแปลงงานนำเสนอ PowerPoint จะรักษาการจัดระเบียบสไลด์ด้วยหัวข้อที่ถูกต้อง ดึงตารางออกมาเป็นตาราง Markdown แนบข้อความแทนภาพสำหรับรูปภาพ และแม้แต่ประมวลผลบันทึกผู้บรรยาย กราฟจะแปลงเป็นตารางข้อมูลที่อ่านง่าย และ Markdown ที่ได้จะยังรักษาการไหลอย่างมีเหตุผลของงานนำเสนอเดิม สิ่งนี้ทำให้เหมาะสมอย่างยิ่งสำหรับป้อนเนื้อหางานนำเสนอเข้าไปในระบบ AI หรือสร้างเอกสารจากสไลด์ที่มีอยู่แล้ว

**การใช้งานในโลกจริงสำหรับนักพัฒนา**: "ปรับใช้โมเดล Phi-4 ไปยัง Azure AI Services สำหรับแอปของฉัน", "สร้างดัชนีการค้นหาใหม่สำหรับระบบ RAG เอกสารของฉัน", "ประเมินคำตอบของเอเจนต์ของฉันเทียบกับเกณฑ์คุณภาพ" หรือ "ค้นหาโมเดลการวางเหตุผลที่ดีที่สุดสำหรับงานวิเคราะห์ที่ซับซ้อนของฉัน"

**สถานการณ์สาธิตเต็มรูปแบบ**: นี่คือเวิร์กโฟลว์การพัฒนา AI ที่ทรงพลัง:

> "ฉันกำลังสร้างเอเจนต์สนับสนุนลูกค้า ช่วยฉันหโมเดลการวางเหตุผลที่ดีจากแคตตาล็อก ปรับใช้โมเดลดังกล่าวสู่ Azure AI Services สร้างฐานความรู้จากเอกสารของเรา ตั้งค่ากรอบการประเมินผลเพื่อตรวจสอบคุณภาพการตอบกลับ แล้วช่วยฉันสร้างต้นแบบการรวมกับโทเค็น GitHub สำหรับการทดสอบ"

Microsoft Foundry MCP Server จะ:
- สืบค้นแคตตาล็อกโมเดลเพื่อแนะนำโมเดลวางเหตุผลที่เหมาะสมตามความต้องการของคุณ
- ให้คำสั่งปรับใช้และข้อมูลโควตาสำหรับภูมิภาค Azure ที่คุณเลือก
- ตั้งค่า Azure AI Search ดัชนีด้วยสคีมาที่เหมาะสมสำหรับเอกสารของคุณ
- กำหนดค่าท่อการประเมินด้วยเมตริกคุณภาพและการตรวจสอบความปลอดภัย
- สร้างโค้ดต้นแบบพร้อมการตรวจสอบสิทธิ์ GitHub สำหรับการทดสอบทันที
- มอบคำแนะนำการตั้งค่าอย่างครบถ้วนที่ปรับให้เหมาะสมกับสแต็กเทคโนโลยีเฉพาะของคุณ

**ตัวอย่างเด่น**: ในฐานะนักพัฒนาฉันเคยลำบากในการตามทันโมเดล LLM หลายชนิดที่มีอยู่ ฉันรู้จักแค่ไม่กี่ตัวหลัก แต่รู้สึกว่าพลาดโอกาสในการเพิ่มประสิทธิภาพและประสิทธิผล อีกทั้งการจัดการโทเค็นและโควตาก็เครียดและยากที่จะบริหาร – ฉันไม่แน่ใจว่าเลือกโมเดลถูกต้องสำหรับงานที่เหมาะสมหรือกำลังใช้จ่ายเกินงบประมาณหรือไม่ เพิ่งได้ยินเรื่อง MCP Server นี้จาก James Montemagno ตอนที่พูดคุยกับทีมเกี่ยวกับคำแนะนำสำหรับ MCP Server ในโพสต์นี้ และตื่นเต้นที่จะได้ใช้งาน! ความสามารถในการค้นหาโมเดลดูน่าประทับใจเป็นพิเศษสำหรับคนอย่างฉันที่ต้องการสำรวจนอกกรอบและค้นหาโมเดลที่เหมาะสมกับงานเฉพาะ กรอบการประเมินจะช่วยฉันตรวจสอบว่าได้ผลลัพธ์ที่ดีขึ้นจริง ไม่ใช่แค่ลองของใหม่ๆ แบบไม่มีเหตุผล

## 📋 สรุป

โปรโตคอล Model Context Protocol (MCP) กำลังเปลี่ยนวิธีที่นักพัฒนามีปฏิสัมพันธ์กับผู้ช่วย AI และเครื่องมือต่างประเทศ เซิร์ฟเวอร์ MCP ทั้ง 10 ของ Microsoft เหล่านี้แสดงให้เห็นถึงพลังของการบูรณาการ AI มาตรฐาน ช่วยให้เวิร์กโฟลว์ทำงานลื่นไหลและให้นักพัฒนายังคงรักษาสภาวะการทำงานที่มีประสิทธิผลพร้อมเข้าถึงความสามารถภายนอกที่ทรงพลัง

ตั้งแต่การรวมระบบนิเวศ Azure อย่างครบวงจรไปจนถึงเครื่องมือเฉพาะเช่น Playwright สำหรับอัตโนมัติบนเบราว์เซอร์และ MarkItDown สำหรับประมวลเอกสาร เซิร์ฟเวอร์เหล่านี้แสดงให้เห็นว่า MCP สามารถเพิ่มประสิทธิภาพในสถานการณ์การพัฒนาที่หลากหลายอย่างไร โปรโตคอลมาตรฐานทำให้เครื่องมือเหล่านี้ทำงานร่วมกันได้อย่างไร้รอยต่อ สร้างประสบการณ์การพัฒนาที่สอดคล้องกัน

เมื่อระบบนิเวศ MCP ยังคงพัฒนา การมีส่วนร่วมกับชุมชน การสำรวจเซิร์ฟเวอร์ใหม่ๆ และการสร้างโซลูชันที่ปรับแต่งเองจะเป็นกุญแจสำคัญในการเพิ่มประสิทธิภาพการพัฒนาของคุณ ธรรมชาติของมาตรฐานเปิดของ MCP หมายความว่าคุณสามารถผสมผสานเครื่องมือจากผู้ขายต่างๆ เพื่อสร้างเวิร์กโฟลว์ที่เหมาะสมที่สุดสำหรับความต้องการเฉพาะของคุณ

## 🎯 แบบฝึกหัด

1. **ติดตั้งและกำหนดค่า**: ตั้งค่าเซิร์ฟเวอร์ MCP หนึ่งตัวในสภาพแวดล้อม VS Code ของคุณและทดสอบฟีเจอร์พื้นฐาน
2. **การรวมเวิร์กโฟลว์**: ออกแบบเวิร์กโฟลว์การพัฒนาที่รวมเซิร์ฟเวอร์ MCP อย่างน้อยสามตัว
3. **การวางแผนเซิร์ฟเวอร์เฉพาะ**: ระบุงานในกิจวัตรการพัฒนาประจำวันที่สามารถได้รับประโยชน์จากเซิร์ฟเวอร์ MCP แบบกำหนดเองและสร้างข้อกำหนดสำหรับเซิร์ฟเวอร์นั้น
4. **การวิเคราะห์ประสิทธิภาพ**: เปรียบเทียบประสิทธิภาพการใช้เซิร์ฟเวอร์ MCP กับวิธีดั้งเดิมสำหรับงานพัฒนาทั่วไป
5. **การประเมินความปลอดภัย**: ประเมินผลกระทบด้านความปลอดภัยของการใช้เซิร์ฟเวอร์ MCP ในสภาพแวดล้อมพัฒนาของคุณและเสนอแนวปฏิบัติที่ดีที่สุด
