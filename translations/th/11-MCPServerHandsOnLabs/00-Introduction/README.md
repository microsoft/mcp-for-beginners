# แนะนำการรวมฐานข้อมูล MCP

> [!NOTE]
> แผนภาพหรือโค้ดในเส้นทางการเรียนรู้นี้ที่ใช้ HTTP/SSE หรือการกำหนดค่าเริ่มต้น
> สะท้อนถึง dependencies MCP `2025-11-25` ของตัวอย่าง สำหรับการใช้งานใหม่
> ให้ใช้คำขอ stateless `2026-07-28` และ Streamable HTTP

## 🎯 สิ่งที่ห้องปฏิบัติการนี้ครอบคลุม

ห้องปฏิบัติการแนะนำนี้ให้ภาพรวมอย่างครบถ้วนเกี่ยวกับการสร้างเซิร์ฟเวอร์ Model Context Protocol (MCP) ที่รวมฐานข้อมูล คุณจะเข้าใจกรณีธุรกิจ สถาปัตยกรรมเชิงเทคนิค และการใช้งานในโลกจริงผ่านกรณีวิเคราะห์ Zava Retail ที่ https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

## ภาพรวม

**Model Context Protocol (MCP)** ช่วยให้ผู้ช่วย AI สามารถเข้าถึงและโต้ตอบกับแหล่งข้อมูลภายนอกได้อย่างปลอดภัยและทันที เมื่อรวมกับการรวมฐานข้อมูล MCP จะเปิดใช้งานความสามารถที่ทรงพลังสำหรับแอปพลิเคชัน AI ที่ขับเคลื่อนด้วยข้อมูล

เส้นทางการเรียนรู้นี้สอนให้คุณสร้างเซิร์ฟเวอร์ MCP ที่พร้อมใช้งานจริง ซึ่งเชื่อมต่อผู้ช่วย AI กับข้อมูลการขายปลีกผ่าน PostgreSQL โดยใช้รูปแบบองค์กรเช่น Row Level Security, การค้นหาด้วยความหมาย และการเข้าถึงข้อมูลแบบหลายผู้เช่า

## วัตถุประสงค์การเรียนรู้

เมื่อสิ้นสุดห้องปฏิบัติการนี้ คุณจะสามารถ:

- **กำหนด** Model Context Protocol และประโยชน์หลักสำหรับการรวมฐานข้อมูล
- **ระบุ** ส่วนประกอบหลักของสถาปัตยกรรมเซิร์ฟเวอร์ MCP พร้อมฐานข้อมูล
- **เข้าใจ** กรณีใช้งาน Zava Retail และความต้องการทางธุรกิจ
- **จดจำ** รูปแบบองค์กรสำหรับการเข้าถึงฐานข้อมูลอย่างปลอดภัยและขยายได้
- **ระบุ** เครื่องมือและเทคโนโลยีที่ใช้ในเส้นทางการเรียนรู้นี้

## 🧭 ความท้าทาย: AI พบกับข้อมูลในโลกจริง

### ข้อจำกัด AI แบบดั้งเดิม

ผู้ช่วย AI สมัยใหม่มีความสามารถอย่างมากแต่เผชิญข้อจำกัดสำคัญในการทำงานกับข้อมูลธุรกิจในโลกจริง:

| **ความท้าทาย** | **คำอธิบาย** | **ผลกระทบทางธุรกิจ** |
|---------------|-----------------|-------------------|
| **ความรู้คงที่** | โมเดล AI ที่ฝึกด้วยชุดข้อมูลคงที่ไม่สามารถเข้าถึงข้อมูลธุรกิจปัจจุบันได้ | ข้อมูลล้าสมัย โอกาสสูญหาย |
| **ข้อมูลแยกส่วน** | ข้อมูลถูกล็อกไว้ในฐานข้อมูล, API, และระบบที่ AI ไม่สามารถเข้าถึง | การวิเคราะห์ไม่ครบถ้วน ขั้นตอนการทำงานแยกส่วน |
| **ข้อจำกัดด้านความปลอดภัย** | การเข้าถึงฐานข้อมูลโดยตรงสร้างความกังวลด้านความปลอดภัยและการปฏิบัติตามข้อกำหนด | การปรับใช้จำกัด การเตรียมข้อมูลด้วยตนเอง |
| **คำถามซับซ้อน** | ผู้ใช้ธุรกิจต้องมีความรู้ทางเทคนิคเพื่อดึงข้อมูลเชิงลึก | การยอมรับลดลง กระบวนการไม่มีประสิทธิภาพ |

### ทางแก้ MCP

Model Context Protocol แก้ปัญหาเหล่านี้โดยให้:

- **การเข้าถึงข้อมูลแบบเรียลไทม์**: ผู้ช่วย AI สอบถามฐานข้อมูลและ API สด
- **การรวมอย่างปลอดภัย**: การเข้าถึงควบคุมด้วยการยืนยันตัวตนและสิทธิ์
- **อินเทอร์เฟซภาษาธรรมชาติ**: ผู้ใช้ธุรกิจถามคำถามเป็นภาษาอังกฤษธรรมดา
- **โปรโตคอลมาตรฐาน**: ทำงานข้ามแพลตฟอร์ม AI และเครื่องมือต่าง ๆ

### บริบททางธุรกิจ

**Zava Retail** ดำเนินงาน:
- **8 ร้านค้าทางกายภาพ** ในรัฐวอชิงตัน (ซีแอตเทิล, เบลวิว, ทาโคมา, สโปแคน, เอฟเวอเร็ตต์, เรดมอนด์, เคิร์กลันด์)
- **1 ร้านค้าออนไลน์** สำหรับการขายอีคอมเมิร์ซ
- **แคตตาล็อกสินค้าที่หลากหลาย** รวมถึงเครื่องมือ, ฮาร์ดแวร์, อุปกรณ์สวน และวัสดุก่อสร้าง
- **การจัดการหลายระดับ** กับผู้จัดการร้าน, ผู้จัดการภูมิภาค และผู้บริหาร

### ความต้องการทางธุรกิจ

ผู้จัดการร้านและผู้บริหารต้องการการวิเคราะห์ด้วย AI เพื่อ:

1. **วิเคราะห์ผลการขาย** ในสาขาและช่วงเวลาต่าง ๆ
2. **ติดตามระดับสินค้าคงคลัง** และระบุความต้องการเติมสินค้า
3. **เข้าใจพฤติกรรมลูกค้า** และรูปแบบการซื้อ
4. **ค้นหาข้อมูลเชิงลึกเกี่ยวกับสินค้า** ผ่านการค้นหาด้วยความหมาย
5. **สร้างรายงาน** ด้วยคำถามภาษาธรรมชาติ
6. **รักษาความปลอดภัยข้อมูล** ด้วยการควบคุมการเข้าถึงตามบทบาท

### ความต้องการทางเทคนิค

เซิร์ฟเวอร์ MCP ต้องให้:

- **การเข้าถึงข้อมูลแบบหลายผู้เช่า** ที่ผู้จัดการร้านเห็นข้อมูลแค่ร้านของตน
- **การสอบถามที่ยืดหยุ่น** รองรับการดำเนินการ SQL ซับซ้อน
- **การค้นหาด้วยความหมาย** สำหรับการค้นพบสินค้าและคำแนะนำ
- **ข้อมูลแบบเรียลไทม์** แสดงสถานะธุรกิจปัจจุบัน
- **การยืนยันตัวตนอย่างปลอดภัย** ด้วย row-level security
- **สถาปัตยกรรมที่ขยายได้** รองรับผู้ใช้พร้อมกันหลายราย

### ส่วนประกอบสำคัญ

#### **1. เลเยอร์เซิร์ฟเวอร์ MCP**
- **FastMCP Framework**: การใช้งานเซิร์ฟเวอร์ MCP ด้วย Python รุ่นใหม่
- **การลงทะเบียนเครื่องมือ**: การกำหนดเครื่องมือแบบประกาศพร้อมความปลอดภัยชนิดข้อมูล
- **บริบทคำขอ**: การจัดการตัวตนผู้ใช้และเซสชัน
- **การจัดการข้อผิดพลาด**: การจัดการข้อผิดพลาดและบันทึกอย่างแข็งแกร่ง

#### **2. เลเยอร์รวมฐานข้อมูล**
- **การจัดกลุ่มการเชื่อมต่อ**: การจัดการเชื่อมต่อ asyncpg อย่างมีประสิทธิภาพ
- **ผู้ให้บริการสคีมา**: การค้นพบสคีมาของตารางแบบไดนามิก
- **ตัวดำเนินการคำถาม**: การดำเนินการ SQL อย่างปลอดภัยพร้อมบริบท RLS
- **การจัดการธุรกรรม**: การปฏิบัติตาม ACID และการจัดการ rollback

#### **3. เลเยอร์ความปลอดภัย**
- **Row Level Security**: PostgreSQL RLS สำหรับการแยกข้อมูลหลายผู้เช่า
- **ตัวตนผู้ใช้**: การยืนยันตัวตนและอนุญาตผู้จัดการร้าน
- **การควบคุมการเข้าถึง**: สิทธิ์ละเอียดและเส้นทางตรวจสอบ
- **การตรวจสอบอินพุต**: ป้องกัน SQL Injection และตรวจสอบคำถาม

#### **4. เลเยอร์เพิ่มประสิทธิภาพ AI**
- **การค้นหาด้วยความหมาย**: Vector embeddings สำหรับการค้นพบสินค้า
- **การรวม Azure OpenAI**: การสร้าง text embedding
- **อัลกอริทึมความคล้ายคลึง**: การค้นหาความคล้ายคลึงแบบ cosine similarity ด้วย pgvector
- **การเพิ่มประสิทธิภาพการค้นหา**: การจัดทำดัชนีและปรับแต่งประสิทธิภาพ

## 🔒 ลึกซึ้งเรื่องความปลอดภัยและการรองรับหลายผู้เช่า

การใช้งานของเรามุ่งเน้นความปลอดภัยระดับองค์กร:

### Row Level Security (RLS)

PostgreSQL RLS รับประกันการแยกข้อมูล:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### การจัดการตัวตนผู้ใช้

การเชื่อมต่อ MCP แต่ละอันรวมถึง:
- **รหัสผู้จัดการร้าน**: ตัวระบุเฉพาะสำหรับบริบท RLS
- **การกำหนดบทบาท**: สิทธิ์และระดับการเข้าถึง
- **การจัดการเซสชัน**: โทเค็นยืนยันตัวตนที่ปลอดภัย
- **บันทึกการตรวจสอบ**: ประวัติการเข้าถึงอย่างครบถ้วน

### การปกป้องข้อมูล

หลายชั้นของความปลอดภัย:
- **การเข้ารหัสการเชื่อมต่อ**: TLS สำหรับการเชื่อมต่อฐานข้อมูลทั้งหมด
- **ป้องกัน SQL Injection**: ใช้คำถามพารามิเตอร์เท่านั้น
- **การตรวจสอบอินพุต**: การตรวจสอบขอร้องอย่างครอบคลุม
- **การจัดการข้อผิดพลาด**: ไม่มีข้อมูลที่ละเอียดอ่อนในข้อความแสดงข้อผิดพลาด
