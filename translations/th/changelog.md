## 16 มิถุนายน 2026

### การปรับข้อกำหนด MCP & การตรวจสอบตัวอย่าง

ตรวจสอบหลักสูตรเทียบกับ **MCP Specification 2025-11-25** ปัจจุบันและ SDKs ทางการล่าสุด จากนั้นแก้ไขการอ้างอิงข้อกำหนดที่ล้าสมัยและยืนยันว่ายังสามารถสร้างและรันตัวอย่างหลักได้

#### การแก้ไขเวอร์ชันข้อกำหนด (2025-06-18 / 2025-03-26 → 2025-11-25)

ปรับปรุงเนื้อหาภาษาอังกฤษที่ยังระบุว่าฉบับแก้ไขข้อกำหนดรุ่นเก่าเป็น *มาตรฐานปัจจุบัน/ล่าสุด* และเปลี่ยนลิงก์ไปยังเส้นทางข้อกำหนด canonical บน `modelcontextprotocol.io`:
- **05-AdvancedTopics/mcp-security/README.md**: ปรับปรุงแบนเนอร์ "มาตรฐานปัจจุบัน", บทนำ, หัวข้อหลักการรักษาความปลอดภัย, หัวข้อข้อกำหนดบังคับ, ส่วน Microsoft Entra ID, ลิงก์อ้างอิงและทรัพยากร, และประกาศด้านความปลอดภัยตอนปิด (8 การอ้างอิง) เป็น 2025-11-25
- **05-AdvancedTopics/mcp-transport/README.md**: ปรับปรุงลิงก์ทรัพยากรเพิ่มเติมและแบนเนอร์ "มาตรฐานปัจจุบัน" เป็น 2025-11-25
- **05-AdvancedTopics/mcp-realtimesearch/README.md**: แทนที่ลิงก์ `2025-03-26` ด้านความปลอดภัยและความไว้วางใจด้วยหน้าแนวทางปฏิบัติด้านความปลอดภัยฉบับปัจจุบัน 2025-11-25
- **03-GettingStarted/14-sampling/README.md**: ปรับปรุงลิงก์เอกสาร Sampling ทางการเป็น 2025-11-25
- **03-GettingStarted/05-stdio-server/README.md**: ปรับปรุงการอ้างอิง "ข้อกำหนด MCP ปัจจุบัน" และลิงก์ทรัพยากรเพิ่มเติมเป็น 2025-11-25 (หมายเหตุการเลิกใช้ SSE ในอดีตยังคงไว้เพื่อความถูกต้อง)

#### การตรวจสอบตัวอย่างเทียบกับ SDK ปัจจุบัน

- **TypeScript (03-GettingStarted/01-first-server/solution/typescript)**: `npm install` ติดตั้ง `@modelcontextprotocol/sdk@1.29.0`; `tsc --noEmit` ผ่านไม่มีข้อผิดพลาดประเภท — API เดิมของ `McpServer`/`StdioServerTransport` ยังใช้ได้
- **Python (03-GettingStarted/01-first-server/solution/python)**: ตรวจสอบใน `.venv` แยกกับ `mcp[cli]` (1.27.2); ผ่าน `py_compile` และ `FastMCP.list_tools()` ส่งคืนเครื่องมือ `add` และ `subtract` อย่างถูกต้อง
- ยืนยันช่วงเวอร์ชัน `@modelcontextprotocol/sdk` ของตัวอย่างทุกตัว (`>=1.26.0` / `^1.26.0` / `^1.27.0`) ตรงกับ `1.29.0` ปัจจุบันโดยไม่มีการเปลี่ยนแปลง API ที่ทำลายล้าง

#### การปรับการตรึงพึ่งพา (ปิดช่องว่างเวอร์ชัน)

ปรับช่องเวอร์ชัน SDK ที่ล้าสมัยเพื่อให้ตัวอย่างทั้งหมดสอดคล้องกับการปล่อย MCP ปัจจุบัน โดยใช้มาตรฐานทั่วทั้งรีโป:

- **10-StreamliningAIWorkflows.../lab3/code/weather_mcp/pyproject.toml** และ **lab4/code/github_mcp_server/pyproject.toml**: ปรับช่องเวอร์ชันเฉพาะ `mcp==1.23.0` → `mcp>=1.26.0`; สร้างไฟล์ `uv.lock` ใหม่ทั้งสอง (`uv lock`) เพื่อให้ล็อคไฟล์สอดคล้องกับ `mcp 1.27.2` ปัจจุบันและสอดคล้องกับมานิเฟสต์

### การเสริมความปลอดภัย & การแก้ไขช่องโหว่การพึ่งพา

ดำเนินการตรวจสอบความปลอดภัยครบถ้วนในทุกมานิเฟสต์การพึ่งพาและรหัสตัวอย่าง จากนั้นแก้ไขคำเตือน npm ทั้งหมดและข้อผิดพลาดระดับโค้ดหนึ่งรายการ หลังแก้ไข `npm audit` รายงาน **0 ช่องโหว่** ในไดเรกทอรีที่ตรวจสอบทั้งหมด

#### ช่องโหว่การพึ่งพา npm (แบบอ้อม) — แก้ไขแล้ว

ตรวจสอบไฟล์ `package-lock.json` ที่คอมมิตทั้งหมด 15 ไฟล์ ช่องโหว่จำกัดเฉพาะการพึ่งพาแบบอ้อมที่ถูกดึงเข้ามาโดยเครื่องมือ MCP Inspector สำหรับนักพัฒนา, ลูกค้า OpenAI, และ MCP SDK; ทั้งหมดได้รับการแก้ไขโดยไม่ทำลายตัวอย่าง:
- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/inspector** และ **lab3/code/weather_mcp/inspector**: ปรับ `@modelcontextprotocol/inspector` (`0.16.6` / `0.14.1` → `0.22.0`) ซึ่งแก้ไขคำเตือน bundled `ajv`, `brace-expansion`, `diff`, `path-to-regexp` และ `ws` เพิ่มค่า npm `overrides` บังคับ `shell-quote@1.8.4` เวอร์ชันแก้ไขเพื่อลบคำเตือนวิกฤตที่เหลือจาก `concurrently`; สร้างไฟล์ล็อกใหม่ทั้งสอง (ตอนนี้ไม่มีช่องโหว่)
- **03-GettingStarted/samples/typescript**: ใช้ `npm audit fix` อัปเดต `qs` แบบอ้อม (ระดับกลาง) เป็นเวอร์ชันที่แก้ไข
- **03-GettingStarted/samples/javascript**: ใช้ `npm audit fix` อัปเดต `hono` แบบอ้อม (ระดับกลาง) เป็นเวอร์ชันที่แก้ไข
- **03-GettingStarted/03-llm-client/solution/typescript**: ใช้ `npm audit fix` อัปเดต `form-data` แบบอ้อม (ระดับสูง) เป็นเวอร์ชันที่แก้ไข
- **03-GettingStarted/11-simple-auth/solution/typescript**: สร้างไฟล์ `package-lock.json` ที่หายไปเพื่อให้โปรเจกต์สามารถทำซ้ำและตรวจสอบได้ (ไม่มีช่องโหว่)

#### การแก้ไขช่องโหว่ระดับโค้ด (OWASP A03: Injection)

- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/src/server.py**: ลบ `shell=True` จากเครื่องมือ `open_in_vscode` การเรียก `subprocess.run(["start", "", vscode_path, folder_path], shell=True)` ก่อนหน้าช่วยให้ตัวอักษรเมทาเชลล์ในเส้นทางโฟลเดอร์ถูกตีความโดย `cmd.exe` (เป็นช่องโหว่การฉีดคำสั่ง) ตอนนี้เรียกใช้งาน `Code.exe` ที่แก้ไขแล้วโดยตรงพร้อมโฟลเดอร์เป็นอาร์กิวเมนต์ — ไม่มีเชลล์ — ซึ่งมีฟังก์ชันเทียบเท่าและปลอดภัย

- ตรวจสอบทุกชุด requirements ของ Python ด้วย `pip-audit` พบว่า `05-AdvancedTopics` และ `03-GettingStarted/samples/python` รายงานว่า **ไม่มีช่องโหว่ที่รู้จัก** (ช่วง `mcp` / `httpx` / `pydantic` / `python-dotenv` ตรงกับเวอร์ชันที่แก้ไขแล้วปัจจุบัน)

  - แบบฝึกหัดโครงสร้างพร้อมสามสถานการณ์ใช้งานจริง (ทบทวนโค้ด, การตัดสินใจสถาปัตยกรรม, การควบคุมเนื้อหา)

- **คลายเริ่มต้นของไคลเอนต์ใหม่ - Roots**: เพิ่มเอกสารฉบับสมบูรณ์เกี่ยวกับคลายเริ่มต้น Roots ของไคลเอนต์ ช่วยให้เซิร์ฟเวอร์เข้าใจขอบเขตระบบไฟล์และสิทธิ์การเข้าถึง

- **กลไกการขนส่ง**: ตรวจสอบความถูกต้องเอกสารสำหรับการขนส่ง STDIO และ Streamable HTTP
- **แนวทางความปลอดภัย**: ยืนยันความสอดคล้องกับเอกสารแนวทางปฏิบัติด้านความปลอดภัย MCP ปัจจุบัน

#### ฟีเจอร์สำคัญ MCP 2025-11-25 ที่ได้รับการบันทึก

  - **ความปลอดภัย OAuth 2.1**: ยืนยันความสอดคล้องกับแนวทางปฏิบัติความปลอดภัย OAuth ล่าสุด
  - **มาตรฐาน OWASP**: ตรวจสอบ OWASP Top 10 สำหรับ LLMs ว่ายังคงเป็นปัจจุบัน
  - **บริการ Azure**: ตรวจสอบลิงก์เอกสาร Microsoft Azure และแนวทางปฏิบัติที่ดีที่สุดทั้งหมด

  - กรอบการบริหารความเสี่ยง AI ของ NIST
  - ISO 27001:2022
  - แนวทางปฏิบัติความปลอดภัย OAuth 2.1
  - กรอบการรักษาความปลอดภัยและการปฏิบัติตาม Azure
- **ทรัพยากรการใช้งาน**: ตรวจสอบลิงก์และทรัพยากรคู่มือการใช้งานทั้งหมด
  - รูปแบบการพิสูจน์ตัวตน Azure API Management
  - คู่มือการบูรณาการ Microsoft Entra ID
  - การจัดการความลับ Azure Key Vault
  - ท่อ DevSecOps และโซลูชันการตรวจสอบ

#### การใช้เซิร์ฟเวอร์ขั้นสูง (03-GettingStarted/10-advanced)
- **เพิ่มบทใหม่**: แนะนำคู่มือครอบคลุมสำหรับการใช้เซิร์ฟเวอร์ MCP ขั้นสูง ครอบคลุมทั้งสถาปัตยกรรมเซิร์ฟเวอร์ปกติและระดับต่ำ
  - **เซิร์ฟเวอร์ปกติกับระดับต่ำ**: การเปรียบเทียบโดยละเอียดและตัวอย่างโค้ดใน Python และ TypeScript สำหรับทั้งสองแนวทาง
  - **การออกแบบโดยใช้ผู้จัดการ**: อธิบายการจัดการเครื่องมือ/ทรัพยากร/พรอมต์แบบ handler-based สำหรับการนำไปใช้เซิร์ฟเวอร์ที่ขยายได้และยืดหยุ่น
  - **รูปแบบใช้งานจริง**: สถานการณ์จริงที่การใช้รูปแบบเซิร์ฟเวอร์ระดับต่ำมีประโยชน์สำหรับฟีเจอร์และสถาปัตยกรรมขั้นสูง

#### การพิสูจน์ตัวตนอย่างง่าย (03-GettingStarted/11-simple-auth)
- **เพิ่มบทใหม่**: คู่มือทีละขั้นตอนสำหรับการใช้งานการพิสูจน์ตัวตนอย่างง่ายในเซิร์ฟเวอร์ MCP
  - **แนวคิดการพิสูจน์ตัวตน**: อธิบายความแตกต่างระหว่างการพิสูจน์ตัวตนและการอนุญาต รวมถึงการจัดการข้อมูลรับรอง
  - **การใช้งานพิสูจน์ตัวตนพื้นฐาน**: รูปแบบการพิสูจน์ตัวตนแบบ middleware ใน Python (Starlette) และ TypeScript (Express) พร้อมตัวอย่างโค้ด
  - **การก้าวสู่ความปลอดภัยขั้นสูง**: แนวทางเริ่มต้นด้วยการพิสูจน์ตัวตนอย่างง่ายและการก้าวต่อไปยัง OAuth 2.1 และ RBAC พร้อมการอ้างอิงถึงโมดูลความปลอดภัยขั้นสูง

การเพิ่มเหล่านี้ให้คำแนะนำเชิงปฏิบัติที่เน้นการทำงานจริงเพื่อสร้างการใช้งานเซิร์ฟเวอร์ MCP ที่แข็งแรง ปลอดภัย และยืดหยุ่นมากขึ้น เชื่อมโยงแนวคิดพื้นฐานกับรูปแบบการผลิตขั้นสูง

- **MCP-SECURITY-BEST-PRACTICES-2025.md**: เขียนใหม่ทั้งหมดจัด Alignment กับสเปค MCP 2025-06-18
  - **ข้อกำหนดบังคับ**: เพิ่มข้อกำหนด MUST/MUST NOT อย่างชัดเจนจากสเปคทางการ พร้อมตัวบ่งชี้ภาพชัดเจน
  - **แนวปฏิบัติความปลอดภัย 12 ด้านหลัก**: ปรับโครงสร้างจากรายการ 15 รายการเป็นโดเมนความปลอดภัยที่ครอบคลุม
    - ความปลอดภัยโทเค็นและการยืนยันตัวตนพร้อมการผสานรวมผู้ให้บริการตัวตนภายนอก
    - การจัดการเซสชันและความปลอดภัยในการขนส่งพร้อมข้อกำหนดการเข้ารหัส

    - การควบคุมการเข้าถึงและสิทธิ์ด้วยหลักสิทธิ์ขั้นต่ำ
    - ความปลอดภัยและการตรวจสอบเนื้อหาพร้อมผสานรวม Azure Content Safety
    - ความปลอดภัยซัพพลายเชนพร้อมการตรวจสอบส่วนประกอบอย่างครอบคลุม

    - การปฏิบัติตามและการปกครองด้วยความสอดคล้องตามกฎระเบียบ
    - การควบคุมความปลอดภัยขั้นสูงด้วยสถาปัตยกรรม zero trust
    - การผสานรวมระบบนิเวศความปลอดภัยของ Microsoft ด้วยโซลูชันที่ครอบคลุม
    - การพัฒนาความปลอดภัยอย่างต่อเนื่องด้วยแนวปฏิบัติที่ปรับตัวได้
  - **โซลูชันความปลอดภัยของ Microsoft**: เพิ่มคำแนะนำการผสานรวมสำหรับ Prompt Shields, Azure Content Safety, Entra ID, และ GitHub Advanced Security
  - **ทรัพยากรการดำเนินงาน**: แบ่งหมวดลิงก์ทรัพยากรอย่างครอบคลุมเป็น เอกสาร MCP ทางการ, โซลูชัน Microsoft Security, มาตรฐานความปลอดภัย และคู่มือการดำเนินการ

    - การควบคุมความปลอดภัยเซสชันพร้อมการป้องกันการแอบใช้
    - การควบคุมความปลอดภัยเฉพาะ AI พร้อมป้องกัน prompt injection และการวางยาเครื่องมือ
    - การป้องกันการโจมตี Confused Deputy ด้วยความปลอดภัยพร็อกซี OAuth
    - ความปลอดภัยการดำเนินการเครื่องมือด้วยการแซนด์บ็อกซ์และการแยกส่วน

    - การตอบสนองเหตุการณ์และการกู้คืนด้วยความสามารถอัตโนมัติ
  - **ตัวอย่างการดำเนินการ**: เพิ่มบล็อกการตั้งค่า YAML และตัวอย่างโค้ดโดยละเอียด
  - **การผสานรวมโซลูชัน Microsoft**: ครอบคลุมบริการความปลอดภัย Azure, GitHub Advanced Security และการจัดการตัวตนองค์กร

#### แนวคิดหลัก (01-CoreConcepts/) - การปรับปรุงใหม่ทั้งหมด
- **อัปเดตเวอร์ชันโปรโตคอล**: อัปเดตให้เชื่อมโยงกับสเปค MCP ปัจจุบัน 2025-06-18 พร้อมการกำหนดเวอร์ชันแบบวันเดือนปี (รูปแบบ YYYY-MM-DD)
- **การปรับแต่งสถาปัตยกรรม**: คำอธิบายที่ปรับปรุงของ Hosts, Clients และ Servers เพื่อสะท้อนแบบแผนสถาปัตยกรรม MCP ปัจจุบัน
  - Hosts นิยามอย่างชัดเจนว่าเป็นแอป AI ที่ประสานงานการเชื่อมต่อ MCP Clients หลายรายการ
  - Clients อธิบายว่าเป็นตัวเชื่อมโปรโตคอลที่รักษาความสัมพันธ์หนึ่งต่อหนึ่งกับเซิร์ฟเวอร์
  - Servers ปรับปรุงด้วยสถานการณ์การปรับใช้งานแบบภายในเครื่องกับระยะไกล
- **การปรับโครงสร้าง Primitive**: ปรับปรุงใหม่ทั้งหมดของ primitive server และ client
  - Server Primitives: ทรัพยากร (แหล่งข้อมูล), Prompt (เทมเพลต), เครื่องมือ (ฟังก์ชันที่สามารถรันได้) พร้อมคำอธิบายและตัวอย่างโดยละเอียด
  - Client Primitives: การสุ่มตัวอย่าง (ผล LLM), การดึงข้อมูล (อินพุตผู้ใช้), การบันทึก (การดีบัก/ตรวจสอบ)
  - อัปเดตด้วยแบบแผนวิธีการค้นหา (`*/list`), ดึงข้อมูล (`*/get`), และการดำเนินการ (`*/call`) ปัจจุบัน
- **สถาปัตยกรรมโปรโตคอล**: นำเสนอโมเดลสถาปัตยกรรมสองชั้น
  - ชั้นข้อมูล: พื้นฐาน JSON-RPC 2.0 พร้อมการจัดการวงจรชีวิตและ primitives
  - ชั้นการขนส่ง: STDIO (ภายในเครื่อง) และ HTTP แบบสตรีมพร้อม SSE (ระยะไกล)
- **กรอบความปลอดภัย**: หลักการความปลอดภัยครอบคลุมรวมถึงความยินยอมผู้ใช้ที่ชัดเจน, การปกป้องข้อมูลส่วนบุคคล, ความปลอดภัยของเครื่องมือ, และความปลอดภัยชั้นการขนส่ง
- **รูปแบบการสื่อสาร**: อัปเดตข้อความโปรโตคอลแสดงโฟลว์การเริ่มต้น, ค้นพบ, ดำเนินการ และแจ้งเตือน
- **ตัวอย่างโค้ด**: รีเฟรชตัวอย่างหลายภาษา (.NET, Java, Python, JavaScript) ให้สะท้อนแบบแผน MCP SDK ปัจจุบัน

#### ความปลอดภัย (02-Security/) - การปรับปรุงความปลอดภัยอย่างครอบคลุม  
- **การจัด Alignment กับมาตรฐาน**: สอดคล้องเต็มที่กับข้อกำหนดความปลอดภัยสเปค MCP 2025-06-18
- **วิวัฒนาการการยืนยันตัวตน**: บันทึกวิวัฒนาการจากเซิร์ฟเวอร์ OAuth แบบกำหนดเองไปสู่การมอบอำนาจผู้ให้บริการตัวตนภายนอก (Microsoft Entra ID)
- **การวิเคราะห์ภัยคุกคามเฉพาะ AI**: ขยายเนื้อหาเกี่ยวกับเวกเตอร์การโจมตี AI สมัยใหม่
  - สถานการณ์โจมตี prompt injection โดยละเอียดพร้อมตัวอย่างในโลกจริง
  - กลไกการวางยาเครื่องมือและรูปแบบการโจมตี "rug pull"
  - การวางยาบริบทหน้าต่างและการโจมตีสับสนโมเดล
- **โซลูชันความปลอดภัย AI ของ Microsoft**: ครอบคลุมระบบนิเวศความปลอดภัยของ Microsoft
  - AI Prompt Shields พร้อมการตรวจจับขั้นสูง, การเน้น, และเทคนิคการแบ่งพรมแดน
  - รูปแบบการผสานรวม Azure Content Safety
  - GitHub Advanced Security สำหรับการป้องกันซัพพลายเชน
- **การบรรเทาภัยคุกคามขั้นสูง**: การควบคุมความปลอดภัยโดยละเอียดสำหรับ
  - การแอบใช้เซสชันพร้อมสถานการณ์โจมตีเฉพาะ MCP และข้อกำหนด session ID แบบเข้ารหัส
  - ปัญหา Confused Deputy ในสถานการณ์พร็อกซี MCP พร้อมข้อกำหนดความยินยอมชัดเจน
  - ช่องโหว่ token passthrough พร้อมการควบคุมการตรวจสอบบังคับ
- **ความปลอดภัยซัพพลายเชน**: ขยายความครอบคลุมซัพพลายเชน AI ที่รวมโมเดลพื้นฐาน, บริการ embeddings, ผู้ให้บริบท และ API จากบุคคลที่สาม
- **ความปลอดภัยขั้นพื้นฐาน**: เสริมการผสานรวมกับแบบแผนความปลอดภัยองค์กร รวมทั้งสถาปัตยกรรม zero trust และระบบนิเวศความปลอดภัย Microsoft
- **การจัดระเบียบทรัพยากร**: แบ่งหมวดลิงก์ทรัพยากรอย่างครอบคลุมตามประเภท (เอกสารทางการ, มาตรฐาน, งานวิจัย, โซลูชัน Microsoft, คู่มือการดำเนินการ)

### การปรับปรุงคุณภาพเอกสาร
- **วัตถุประสงค์การเรียนรู้ที่มีโครงสร้าง**: ปรับปรุงวัตถุประสงค์การเรียนรู้ด้วยผลลัพธ์ที่ชัดเจนและสามารถปฏิบัติได้
- **การอ้างอิงข้าม**: เพิ่มลิงก์ระหว่างหัวข้อความปลอดภัยและแนวคิดหลักที่เกี่ยวข้อง
- **ข้อมูลปัจจุบัน**: อัปเดตวันที่ทั้งหมดและลิงก์สเปคสู่มาตรฐานปัจจุบัน
- **คำแนะนำการดำเนินการ**: เพิ่มคำแนะนำการดำเนินการเฉพาะและสามารถปฏิบัติได้ทั่วทั้งสองส่วน

- ปรับปรุงคำอธิบายหัวข้อขั้นสูงให้ครอบคลุมพื้นที่เชิงเฉพาะทุกด้าน
- อัปเดตส่วนกรณีศึกษาให้สะท้อนตัวอย่างจริง
- เพิ่มบันทึกการเปลี่ยนแปลงที่ครอบคลุมนี้

### การสนับสนุนจากชุมชน (06-CommunityContributions/)
- เพิ่มข้อมูลโดยละเอียดเกี่ยวกับเซิร์ฟเวอร์ MCP สำหรับสร้างภาพ
- เพิ่มส่วนครอบคลุมการใช้งาน Claude ใน VSCode
- เพิ่มคำแนะนำการติดตั้งและใช้งานไคลเอนต์เทอร์มินัล Cline
- อัปเดตส่วน MCP client ให้รวมตัวเลือกไคลเอนต์ยอดนิยมทั้งหมด
- ปรับปรุงตัวอย่างการมีส่วนร่วมด้วยตัวอย่างโค้ดที่แม่นยำยิ่งขึ้น

### หัวข้อขั้นสูง (05-AdvancedTopics/)
- จัดระเบียบโฟลเดอร์หัวข้อเฉพาะทางทั้งหมดด้วยการตั้งชื่อที่สอดคล้อง
- เพิ่มเนื้อหาและตัวอย่างด้านวิศวกรรมบริบท
- เพิ่มเอกสารการผสานรวมเอเจนต์ Foundry
- ปรับปรุงเอกสารผสานความปลอดภัย Entra ID

## 11 มิถุนายน 2025

- เพิ่มตัวอย่างโครงการต้นแบบในหลายภาษาโปรแกรม

### เริ่มต้นใช้งาน (03-GettingStarted/)

- รวมคำแนะนำการผสานรวมไคลเอนต์ LLM
- เพิ่มเอกสารการผสาน VS Code
- นำเสนอตัวอย่าง Server-Sent Events (SSE)

### แนวคิดหลัก (01-CoreConcepts/)
- เพิ่มคำอธิบายโดยละเอียดของสถาปัตยกรรมไคลเอนต์-เซิร์ฟเวอร์
- สร้างเอกสารเกี่ยวกับส่วนประกอบโปรโตคอลหลัก
- บันทึกแบบแผนข้อความใน MCP
