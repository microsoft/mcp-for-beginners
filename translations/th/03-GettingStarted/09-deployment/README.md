# การปรับใช้เซิร์ฟเวอร์ MCP

> [!NOTE]
> ตัวอย่างการกำหนดค่าที่ใช้ปลายทาง `/sse` จะเป้าหมายไปยังการขนส่ง HTTP+SSE แบบเดิม เซิร์ฟเวอร์ระยะไกล MCP รุ่น `2026-07-28` ใช้ Streamable HTTP โดยปกติจะอยู่ที่ปลายทางที่กำหนดโดยเซิร์ฟเวอร์ เช่น `/mcp`
> 


การปรับใช้เซิร์ฟเวอร์ MCP ของคุณช่วยให้ผู้อื่นสามารถเข้าถึงเครื่องมือและทรัพยากรของเซิร์ฟเวอร์ได้เกินกว่าขอบเขตสิ่งแวดล้อมในเครื่องของคุณ มีวิธีการปรับใช้หลายแบบที่ควรพิจารณา ขึ้นอยู่กับความต้องการของคุณในเรื่องความสามารถในการขยายตัว ความน่าเชื่อถือ และความง่ายในการจัดการ ด้านล่างนี้คุณจะพบคำแนะนำสำหรับการปรับใช้เซิร์ฟเวอร์ MCP ในพื้นที่ (local), ในคอนเทนเนอร์ และบนคลาวด์

## ภาพรวม

บทเรียนนี้ครอบคลุมถึงวิธีการปรับใช้แอปเซิร์ฟเวอร์ MCP ของคุณ

## เป้าหมายการเรียนรู้

หลังจากเรียนบทนี้เสร็จ คุณจะสามารถ:

- ประเมินวิธีการปรับใช้ที่แตกต่างกัน
- ปรับใช้แอปของคุณ

## การพัฒนาและปรับใช้ในเครื่อง

หากเซิร์ฟเวอร์ของคุณตั้งใจให้ใช้งานโดยรันบนเครื่องของผู้ใช้ คุณสามารถทำตามขั้นตอนดังต่อไปนี้:

1. **ดาวน์โหลดเซิร์ฟเวอร์**. หากคุณไม่ได้เขียนเซิร์ฟเวอร์ ให้ดาวน์โหลดมาไว้บนเครื่องของคุณก่อน 
1. **เริ่มกระบวนการเซิร์ฟเวอร์**: รันแอปเซิร์ฟเวอร์ MCP ของคุณ

สำหรับ SSE (ไม่จำเป็นสำหรับเซิร์ฟเวอร์ประเภท stdio)

1. **กำหนดค่าเครือข่าย**: ตรวจสอบให้แน่ใจว่าเซิร์ฟเวอร์เข้าถึงได้ผ่านพอร์ตที่คาดหวัง
1. **เชื่อมต่อไคลเอนต์**: ใช้ URL การเชื่อมต่อในเครื่อง เช่น `http://localhost:3000`

## การปรับใช้บนคลาวด์

เซิร์ฟเวอร์ MCP สามารถปรับใช้บนแพลตฟอร์มคลาวด์ต่างๆ ได้:

- **ฟังก์ชันแบบไม่ใช้เซิร์ฟเวอร์ (Serverless Functions)**: ปรับใช้เซิร์ฟเวอร์ MCP แบบน้ำหนักเบาในรูปแบบฟังก์ชันแบบไม่ใช้เซิร์ฟเวอร์
- **บริการคอนเทนเนอร์**: ใช้บริการอย่าง Azure Container Apps, AWS ECS หรือ Google Cloud Run
- **Kubernetes**: ปรับใช้และจัดการเซิร์ฟเวอร์ MCP ในคลัสเตอร์ Kubernetes เพื่อความพร้อมใช้งานสูง

### ตัวอย่าง: Azure Container Apps

Azure Container Apps รองรับการปรับใช้ MCP Servers ขณะนี้ยังอยู่ในระหว่างการพัฒนาและรองรับเซิร์ฟเวอร์ SSE

นี่คือวิธีการที่คุณสามารถทำ:

1. โคลนรีโป:

  ```sh
  git clone https://github.com/anthonychu/azure-container-apps-mcp-sample.git
  ```

1. รันในเครื่องเพื่อตรวจสอบ:

  ```sh
  uv venv
  uv sync

  # ลินุกซ์/แมคโอเอส
  export API_KEYS=<AN_API_KEY>
  # วินโดวส์
  set API_KEYS=<AN_API_KEY>

  uv run fastapi dev main.py
  ```

1. เพื่อทดสอบในเครื่อง สร้างไฟล์ *mcp.json* ในไดเรกทอรี *.vscode* และเพิ่มเนื้อหาต่อไปนี้:

  ```json
  {
      "inputs": [
          {
              "type": "promptString",
              "id": "weather-api-key",
              "description": "Weather API Key",
              "password": true
          }
      ],
      "servers": {
          "weather-sse": {
              "type": "sse",
              "url": "http://localhost:8000/sse",
              "headers": {
                  "x-api-key": "${input:weather-api-key}"
              }
          }
      }
  }
  ```

เมื่อเซิร์ฟเวอร์ SSE เริ่มทำงานแล้ว คุณสามารถคลิกไอคอนเล่นในไฟล์ JSON คุณจะเห็นเครื่องมือบนเซิร์ฟเวอร์ถูก GitHub Copilot รับรู้ ให้ดูที่ไอคอนเครื่องมือ

1. ในการปรับใช้ ให้รันคำสั่งดังต่อไปนี้:

  ```sh
  az containerapp up -g <RESOURCE_GROUP_NAME> -n weather-mcp --environment mcp -l westus --env-vars API_KEYS=<AN_API_KEY> --source .
  ```

นั่นคือทั้งหมด ปรับใช้ในเครื่อง หรือติดตั้งบน Azure ผ่านขั้นตอนเหล่านี้
