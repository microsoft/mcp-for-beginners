# การแก้ไขข้อบกพร่องด้วย MCP Inspector

> [!NOTE]
> คำสั่งที่ใช้ `--sse` และ URL ที่ลงท้ายด้วย `/sse` ใช้ทดสอบการขนส่ง HTTP+SSE แบบเก่า สำหรับเซิร์ฟเวอร์ MCP รุ่นใหม่ `2026-07-28` ให้ใช้ Inspector เวอร์ชันที่รองรับ Streamable HTTP และเลือกการขนส่งนั้นแทน
> 
>  

**MCP Inspector** คือเครื่องมือแก้ไขข้อบกพร่องที่สำคัญที่ช่วยให้คุณทดสอบและแก้ไขปัญหาเซิร์ฟเวอร์ MCP ของคุณอย่างโต้ตอบได้โดยไม่จำเป็นต้องใช้แอปโฮสต์ AI เต็มรูปแบบ คิดว่ามันเหมือนกับ "Postman สำหรับ MCP" — มันให้ส่วนต่อประสานภาพเพื่อส่งคำขอ ดูการตอบสนอง และเข้าใจพฤติกรรมของเซิร์ฟเวอร์ของคุณ

## ทำไมต้องใช้ MCP Inspector?

เมื่อสร้างเซิร์ฟเวอร์ MCP คุณมักจะเผชิญกับความท้าทายเหล่านี้:

- **"เซิร์ฟเวอร์ของฉันกำลังทำงานหรือไม่?"** — Inspector แสดงสถานะการเชื่อมต่อ
- **"เครื่องมือของฉันลงทะเบียนถูกต้องหรือไม่?"** — Inspector แสดงรายการเครื่องมือทั้งหมดที่ใช้งานได้
- **"รูปแบบการตอบสนองเป็นอย่างไร?"** — Inspector แสดงผลตอบกลับ JSON เต็มรูปแบบ
- **"ทำไมเครื่องมือนี้ไม่ทำงาน?"** — Inspector แสดงข้อความแสดงข้อผิดพลาดโดยละเอียด

## ความต้องการเบื้องต้น

- ติดตั้ง Node.js 18 ขึ้นไป
- npm (มาพร้อมกับ Node.js)
- เซิร์ฟเวอร์ MCP สำหรับทดสอบ (ดู [Module 3.1 - First Server](../01-first-server/README.md))

## การติดตั้ง

### ตัวเลือกที่ 1: รันด้วย npx (แนะนำสำหรับการทดสอบอย่างรวดเร็ว)

```bash
npx @modelcontextprotocol/inspector
```

### ตัวเลือกที่ 2: ติดตั้งแบบทั่วระบบ

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### ตัวเลือกที่ 3: เพิ่มในโปรเจกต์ของคุณ

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

เพิ่มใน `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## การเชื่อมต่อกับเซิร์ฟเวอร์ของคุณ

### เซิร์ฟเวอร์ stdio (กระบวนการภายในเครื่อง)

สำหรับเซิร์ฟเวอร์ที่สื่อสารผ่านอินพุต/เอาต์พุตมาตรฐาน:

```bash
# เซิร์ฟเวอร์ Python
npx @modelcontextprotocol/inspector python -m your_server_module

# เซิร์ฟเวอร์ Node.js
npx @modelcontextprotocol/inspector node ./build/index.js

# พร้อมตัวแปรสภาพแวดล้อม
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### เซิร์ฟเวอร์ SSE/HTTP (ผ่านเครือข่าย)

สำหรับเซิร์ฟเวอร์ที่ทำงานเป็นบริการ HTTP:

1. เริ่มเซิร์ฟเวอร์ของคุณก่อน:
   ```bash
   python server.py  # เซิร์ฟเวอร์กำลังทำงานที่ http://localhost:8080
   ```

2. เปิด Inspector และเชื่อมต่อ:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## การทดสอบเครื่องมือ

### การแสดงรายการเครื่องมือที่ใช้งานได้

1. คลิกแท็บ **Tools**
2. Inspector จะเรียกใช้ `tools/list` โดยอัตโนมัติ
3. คุณจะเห็นเครื่องมือที่ลงทะเบียนทั้งหมดพร้อม:
   - ชื่อเครื่องมือ
   - คำอธิบาย
   - โครงสร้างอินพุต (พารามิเตอร์)

### การเรียกใช้เครื่องมือ

1. เลือกเครื่องมือจากรายการ
2. กรอกพารามิเตอร์ที่จำเป็นในฟอร์ม
3. คลิก **Run Tool**
4. ดูผลตอบกลับในแผงผลลัพธ์

**ตัวอย่าง: การทดสอบเครื่องคิดเลข**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### การแก้ไขข้อผิดพลาดของเครื่องมือ

เมื่อเครื่องมือผิดพลาด Inspector จะแสดง:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

รหัสข้อผิดพลาดทั่วไป:
| รหัส | ความหมาย |
|------|---------|
| -32700 | ข้อผิดพลาดการวิเคราะห์ (JSON ไม่ถูกต้อง) |
| -32600 | คำขอไม่ถูกต้อง |
| -32601 | ไม่พบเมทอด |
| -32602 | พารามิเตอร์ไม่ถูกต้อง |
| -32603 | ข้อผิดพลาดภายใน |

## การทดสอบทรัพยากร

### การแสดงรายการทรัพยากร

1. คลิกแท็บ **Resources**
2. Inspector เรียกใช้ `resources/list`
3. คุณจะเห็น:
   - URI ของทรัพยากร
   - ชื่อและคำอธิบาย
   - ประเภท MIME

### การอ่านทรัพยากร

1. เลือกทรัพยากร
2. คลิก **Read Resource**
3. ดูเนื้อหาที่ส่งกลับ

**ผลลัพธ์ตัวอย่าง:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## การทดสอบพรอมต์

### การแสดงรายการพรอมต์

1. คลิกแท็บ **Prompts**
2. Inspector เรียกใช้ `prompts/list`
3. ดูเทมเพลตพรอมต์ที่มีให้เลือก

### การรับพรอมต์

1. เลือกพรอมต์
2. กรอกอาร์กิวเมนต์ที่จำเป็น
3. คลิก **Get Prompt**
4. ดูข้อความพรอมต์ที่สร้างขึ้น

## การวิเคราะห์บันทึกข้อความ

บันทึกข้อความแสดงข้อความโปรโตคอล MCP ทั้งหมด ข้อความบันทึกด้านล่างมาจาก
เซิร์ฟเวอร์รุ่นเก่า `2025-11-25` และรวมการจับมือ `initialize` ที่ถูกลบออก เซิร์ฟเวอร์ `2026-07-28`
ใช้ข้อมูลคำขอที่บรรจุเองและใช้ `server/discover`
แทน

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### สิ่งที่ควรสังเกต

- **คู่คำขอ/ตอบกลับ**: แต่ละ `→` ควรมี `←` ที่ตรงกัน
- **ข้อความแสดงข้อผิดพลาด**: มองหา `"error"` ในการตอบสนอง
- **เวลา**: ช่องว่างที่ใหญ่แสดงถึงปัญหาด้านประสิทธิภาพ
- **เวอร์ชันโปรโตคอล**: ตรวจสอบให้แน่ใจว่าเซิร์ฟเวอร์และไคลเอนต์เห็นชอบในเวอร์ชันเดียวกัน

## สถานการณ์แก้ไขข้อบกพร่องทั่วไป

### สถานการณ์ที่ 1: เซิร์ฟเวอร์เชื่อมต่อไม่ได้

**อาการ:** Inspector แสดง "Disconnected" หรือค้างอยู่ที่ "Connecting..."

**รายการตรวจสอบ:**
1. ✅ คำสั่งเซิร์ฟเวอร์ถูกต้องหรือไม่?
2. ✅ ติดตั้งไลบรารีหรือ dependencies ครบหรือยัง?
3. ✅ เส้นทางเซิร์ฟเวอร์เป็นเส้นทางสัมบูรณ์หรือสัมพันธ์กับไดเรกทอรีปัจจุบันหรือไม่?
4. ✅ กำหนดตัวแปรสภาพแวดล้อมที่จำเป็นแล้วหรือยัง?

**ขั้นตอนแก้ไขข้อบกพร่อง:**
```bash
# ทดสอบเซิร์ฟเวอร์ด้วยตนเองก่อน
python -c "import your_server_module; print('OK')"

# ตรวจสอบข้อผิดพลาดในการนำเข้า
python -m your_server_module 2>&1 | head -20

# ยืนยันว่าได้ติดตั้ง MCP SDK แล้ว
pip show mcp
```

### สถานการณ์ที่ 2: เครื่องมือไม่แสดง

**อาการ:** แท็บเครื่องมือแสดงรายการว่างเปล่า

**สาเหตุที่เป็นไปได้:**
1. เครื่องมือไม่ได้ลงทะเบียนในช่วงเริ่มต้นเซิร์ฟเวอร์
2. เซิร์ฟเวอร์ล่มหลังจากเริ่มทำงาน
3. ตัวจัดการ `tools/list` คืนค่าเป็นอาร์เรย์ว่างเปล่า

**ขั้นตอนแก้ไขข้อบกพร่อง:**
1. ตรวจสอบบันทึกข้อความสำหรับการตอบสนอง `tools/list`
2. เพิ่มการบันทึก log ในโค้ดการลงทะเบียนเครื่องมือของคุณ
3. ตรวจสอบว่าใช้ตัวตกแต่ง `@mcp.tool()` อยู่ (สำหรับ Python)

### สถานการณ์ที่ 3: เครื่องมือคืนค่าข้อผิดพลาด

**อาการ:** การเรียกเครื่องมือคืนค่าข้อผิดพลาด

**แนวทางแก้ไข:**
1. อ่านข้อความแสดงข้อผิดพลาดอย่างรอบคอบ
2. ตรวจสอบว่าประเภทของพารามิเตอร์ตรงกับสคีมา
3. เพิ่ม try/catch พร้อมข้อความแสดงข้อผิดพลาดโดยละเอียด
4. ตรวจสอบบันทึกเซิร์ฟเวอร์สำหรับ stack trace

**ตัวอย่างการจัดการข้อผิดพลาดที่ดีขึ้น:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # ตรรกะของเครื่องมือนี้อยู่ที่นี่
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### สถานการณ์ที่ 4: เนื้อหาของทรัพยากรว่างเปล่า

**อาการ:** ทรัพยากรคืนค่ากลับมาแต่เนื้อหาเป็นค่าว่างหรือ null

**รายการตรวจสอบ:**
1. ✅ เส้นทางไฟล์หรือ URI ถูกต้อง
2. ✅ เซิร์ฟเวอร์มีสิทธิ์อ่านทรัพยากร
3. ✅ เนื้อหาของทรัพยากรถูกส่งกลับอย่างถูกต้อง

```bash
npx @modelcontextprotocol/inspector \

  --header "Authorization: Bearer your-token"
```

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### การบันทึกเซสชัน

Inspector สามารถส่งออกบันทึกข้อความเพื่อการวิเคราะห์ในภายหลัง:
1. คลิก **Export Log** ในแผงข้อความ
2. บันทึกไฟล์ JSON
3. แชร์กับสมาชิกทีมเพื่อแก้ไขข้อบกพร่อง

## แนวทางปฏิบัติที่ดีที่สุด

1. **ทดสอบตั้งแต่เนิ่นๆ และบ่อยครั้ง** - ใช้ Inspector ในระหว่างพัฒนา ไม่ใช่เฉพาะตอนที่เกิดปัญหา
2. **เริ่มจากเรื่องง่าย** - ทดสอบการเชื่อมต่อพื้นฐานก่อนเรียกใช้เครื่องมือที่ซับซ้อน
3. **ตรวจสอบสคีมา** - ข้อผิดพลาดจำนวนมากเกิดจากชนิดพารามิเตอร์ไม่ตรงกัน
4. **อ่านข้อความแสดงข้อผิดพลาด** - ข้อผิดพลาด MCP มักจะมีคำอธิบาย
5. **เปิด Inspector ไว้เสมอ** - ช่วยจับปัญหาในระหว่างการพัฒนา
