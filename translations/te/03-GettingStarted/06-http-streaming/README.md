# మోడల్ కాన్టెక్స్ట్ ప్రోటోకాల్ (MCP)తో HTTPS స్ట్రీమింగ్

ఈ అధ్యాయం HTTPS ఉపయోగించి మోడల్ కాన్టెక్స్ట్ ప్రోటోకాల్ (MCP)తో సురక్షితమైన, డిగ్రీబడైన, మరియు రియల్-టైమ్ స్ట్రీమింగ్‌ను అమలు చేయటానికి సమగ్ర మార్గదర్శకాన్ని అందిస్తుంది. ఇది స్ట్రీమింగ్‌కు ప్రేరణ, అందుబాటులో ఉన్న ట్రాన్స్గరం విధానాలు, MCPలో స్ట్రీమబుల్ HTTPని ఎలా అమలు చెయ్యాలి, సెక్యూరిటీ ఉత్తమ పద్ధతులు, SSE నుండి మైగ్రేషన్, మరియు మీ స్వంత స్ట్రీమింగ్ MCP అప్లికేషన్లు నిర్మించడానికి ప్రాక్టికల్ సూచనలు వీటిని కవర్ చేస్తుంది.

> **ముందుకు చూడండి:** ఈ పాఠం **MCP స్పెసిఫికేషన్ 2025-11-25** క్రింద స్ట్రీమబుల్ HTTPని వివరిస్తుంది, ఇక్కడ సెషన్ `initialize` సమయంలో స్థాపించబడుతుంది మరియు `Mcp-Session-Id` హెడ్డర్‌తో పిన్ చేయబడుతుంది. `2026-07-28` విడుదల అభ్యర్థి హ్యాండ్షేక్ మరియు సెషన్ IDని పూర్తిగా తొలగిస్తుంది, ప్రతి అభ్యర్థన స్వయంప్రతిపాదకంగా మరియు ఏ సర్వర్ ఇన్స్టాన్సుకీ రూటబుల్‌గా ఉంటుంది, స్టిక్కీ సెషన్లు అవసరం లేదు. వివరాలకు [MCPలో ఏమి మారుతోంది: 2026-07-28 విడుదల అభ్యర్థి](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) చూడండి.

## MCPలో ట్రాన్స్పోర్ట్ విధానాలు మరియు స్ట్రీమింగ్

ఈ విభాగం MCPలో అందుబాటులో ఉన్న విభిన్న ట్రాన్స్పోర్ట్ విధానాలు మరియు కస్టమర్లు మరియు సర్వర్స్ మధ్య రియల్-టైమ్ కమ్యూనికేషన్ కోసం స్ట్రీమింగ్ సామర్ధ్యాలను ఎలా సుసాధ్యం చేస్తాయో పరిశీలిస్తుంది.

### ట్రాన్స్పోర్ట్ విధానం అంటే ఏమిటి?

ట్రాన్స్పోర్ట్ విధానం కస్టమర్ మరియు సర్వర్ మధ్య డేటా ఎలా বিনిమయం అవుతుందో నిర్వచిస్తుంది. MCP విభిన్న పరిసరాలు మరియు అవసరాలకు అనుగుణంగా బహుభాగం ట్రాన్స్పోర్ట్ రకాల మద్దతు ఇస్తుంది:

- **stdio**: స్టాండర్డ్ ఇన్‌పుట్/అవుట్‌పుట్, స్థానిక మరియు CLI-ఆధారిత పనిమూలకాలకు అనుకూలం. సులభం కానీ వెబ్ లేదా క్లౌడ్‌కు అనుకూలం కాదు.
- **SSE (సర్వర్-సెంట్ ఈవెంట్స్)**: సర్వర్లు క్లయింటులను HTTP ద్వారా రియల్-టైమ్ నవీకరణలు పంపేందుకు అనుమతిస్తుంది. వెబ్ UIsకి మంచిది, కానీ డిగ్రీ మరియు లవచీత కారకాల పరిమితి ఉంది. MCP స్పెసిఫికేషన్ 2025-06-18 నుండి, స్టాండలోన్ SSE (సర్వర్-సెంట్ ఈవెంట్స్) ట్రాన్స్పోర్ట్ డిప్రికేటెడ్ చేయబడింది మరియు దాన్ని "Streamable HTTP" ట్రాన్స్పోర్ట్ మారుస్తుంది.
- **Streamable HTTP**: ఆధునిక HTTP-ఆధారిత స్ట్రీమింగ్ ట్రాన్స్పోర్ట్, నోటిఫికేషన్లు మరియు మెరుగైన డిగ్రీ మద్దతుతో. ఎక్కువగా ప్రొడక్షన్ మరియు క్లౌడ్ పరిసరాలకు సిఫార్సు చేయబడింది.

### పోలిక పట్టిక

ఈ క్రింద పోలిక పట్టికను చూడండి, ఈ ట్రాన్స్పోర్ట్ విధానాల మధ్య తేడాలు గుర్తించడానికి:

| ట్రాన్స్పోర్ట్         | రియల్-టైమ్ నవీకరణలు | స్ట్రీమింగ్ | డిగ్రీ | ఉపయోగ సందర్భం              |
|-------------------|------------------|-----------|-------------|-------------------------|
| stdio             | نہیں            | نہیں     | తక్కువ    | స్థానిక CLI పరికరాలు     |
| SSE               | అవును            | అవును     | మధ్యస్థ    | వెబ్, రియల్-టైమ్ నవీకరణలు  |
| Streamable HTTP   | అవును            | అవును     | అధిక        | క్లౌడ్, బహు-క్లయింట్     |

> **సూచన:** సరైన ట్రాన్స్పోర్ట్ ఎంచుకోవడం పనితనం, డిగ్రీ, మరియు వినియోగదారు అనుభవంపై ప్రభావం చూపుతుంది. **Streamable HTTP** ఆధునిక, డిగ్రీబుల్, మరియు క్లౌడ్-సన్నద్ధ అప్లికేషన్లకు సిఫార్సు చేయబడింది.

గమనించండి, మీరు ముందు అధ్యాయం లలో stdio మరియు SSE ట్రాన్స్పోర్టులు చూసారు మరియు ఈ అధ్యాయంలో స్ట్రీమబుల్ HTTP ట్రాన్స్పోర్ట్ గురించి చర్చించబడుతుంది.

## స్ట్రీమింగ్: ఆలోచనలు మరియు ప్రేరణ

స్ట్రీమింగ్ తెలుసుకోవడం అత్యంత ప్రాథమిక ఆలోచనలు మరియు ప్రేరణలు, సమర్ధవంతమైన రియల్-టైమ్ కమ్యూనికేషన్ వ్యవస్థలను అమలు చేయడానికి అవసరం.

**స్ట్రీమింగ్** నెట్‌వర్క్ ప్రోగ్రామింగ్‌లో ఒక సాంకేతిక విధానమై, ఇది మొత్తం స్పందన సిద్ధంగా ఉండే వరకు వేచిచూడకుండా, డేటాను చిన్న, నిర్వహించదగిన భాగాలు లేదా ఈవెంట్ల శ్రేణిగా పంపటం మరియు స్వీకరించటం అనుమతిస్తుంది. ఇది ప్రత్యేకంగా ఉపయోగకరం:

- పెద్ద ఫైళ్ళు లేదా డేటాసెట్‌లు.
- రియల్-టైమ్ నవీకరణలు (ఉదా: చాట్, ప్రోగ్రెస్ బార్లు).
- దీర్ఘకాలిక అనుకూలనలలో, వినియోగదారుని వినియోగంలో ఉంచడానికి.

స్ట్రీమింగ్ గురించి మీరు హై లెవెల్లో తెలుసుకోవలసినవి ఇవి:

- డేటా క్రమంగా పంపబడుతుంది, ఒకేసారి కాదు.
- క్లయింట్ వచ్చిన డేటాను ప్రాసెస్ చేయవచ్చు.
- అనుభావ సంకల్పకాలాన్ని తగ్గిస్తుంది మరియు వినియోగదారు అనుభవాన్ని మెరుగుపరుస్తుంది.

### స్ట్రీమింగ్ ఎందుకు ఉపయోగించాలి?

స్ట్రీమింగ్ ఉపయోగించే కారణాలు ఇవి:

- వినియోగదారులు తక్షణ ఫీడ్‌బ్యాక్ పొందుతారు, కేవలం ముగింపు వద్ద కాదు.
- రియల్-టైమ్ అప్లికేషన్లు మరియు స్పందనశీల UI లకు అనుమతిస్తుంది.
- నెట్‌వర్క్ మరియు కంప్యూటింగ్ వనరుల మరింత సమర్థవంతమైన వినియోగం.

### సాదా ఉదాహరణ: HTTP స్ట్రీమింగ్ సర్వర్ & క్లయింట్

స్ట్రీమింగ్ ఎలా అమలు చేయాలో ఒక సాదా ఉదాహరణ ఇవింది:

#### పైథాన్

**సర్వర్ (పైథాన్, FastAPI మరియు StreamingResponse ఉపయోగించి):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**క్లయింట్ (పైథాండ్, requests ఉపయోగించి):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

ఈ ఉదాహరణ ఒక సర్వర్ కస్టమర్‌కు సందేశాల వరుసను అందిస్తుంది, అన్ని సందేశాలు సిద్ధంగా ఉండే వరకు వేచిచూడకుండా.

**ఇది ఎలా పనిచేస్తుంది:**

- సర్వర్ ప్రతి సందేశం సిద్ధంగా ఉన్నప్పుడు విడుదల చేస్తుంది.
- క్లయింట్ వచ్చిన ప్రతి చంక్‌ని స్వీకరించి ప్రింట్ చేస్తుంది.

**అవసరాలు:**

- సర్వర్ స్ట్రీమింగ్ రెస్పాన్స్ ఉపయోగించాలి (ఉదా: FastAPIలో `StreamingResponse`).
- క్లయింట్ స్ట్రీమ్‌గా రెస్పాన్స్ ప్రాసెస్ చేయాలి (`requests`లో `stream=True`).
- కాంటెంట్-టైప్ సాధారణంగా `text/event-stream` లేదా `application/octet-stream`.

#### జావా

**సర్వర్ (జావా, Spring Boot మరియు Server-Sent Events ఉపయోగించి):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**క్లయింట్ (జావా, Spring WebFlux WebClient ఉపయోగించి):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**జావా అమలుపరచటం గమనికలు:**

- Spring Boot యొక్క రియాక్టివ్ స్తాక్ `Flux` తో స్ట్రీమింగ్ కు ఉపయోగపడుతుంది
- `ServerSentEvent` వివరణాత్మక ఈవెంట్ స్ట్రీమింగ్‌ను ఈవెంట్ రకాలతో అందిస్తుంది
- `WebClient` లో `bodyToFlux()` రియాక్టివ్ స్ట్రీమింగ్ వినియోగాన్నిఅనుమతిస్తుంది
- `delayElements()` ఈవెంట్ మధ్య ప్రాసెసింగ్ సమయాన్ని సిమ్యులేట్ చేస్తుంది
- ఈవెంట్లు రకాలవారేమైన (`info`, `result`) కావచ్చు కస్టమర్ సులభతారుగా నిర్వర్తించడానికి

### పోలిక: సాంప్రదాయక స్ట్రీమింగ్ మరియు MCP స్ట్రీమింగ్

సాంప్రదాయకంగా స్ట్రీమింగ్ ఎలా జరుగుతుందో మరియు MCPలో స్ట్రీమింగ్ ఎలా జరుగుతుందో మధ్య తేడాలను ఇలా చిత్రించవచ్చు:

| లక్షణం                | సాంప్రదాయక HTTP స్ట్రీమింగ్     | MCP స్ట్రీమింగ్ (నోటిఫికేషన్లు)  |
|------------------------|-------------------------------|-------------------------------------|
| ప్రధాన ప్రతిస్పందన       | చంక్‌లుగా                      | ఒకటే, చివరలో                      |
| ప్రోగ్రెస్ నవీకరణలు     | డేటా చంక్‌లుగా పంపబడతాయి     | నోటిఫికేషన్లుగా పంపబడతాయి          |
| కస్టమర్ అవసరాలు        | స్ట్రీమ్ ప్రాసెస్ చేయాలి          | మెసేజీ హ్యాండ్లర్ అమలు చేయాలి         |
| ఉపయోగ సందర్భం         | పెద్ద ఫైళ్ళు, AI టోకెన్ స్ట్రీమ్‌లు | ప్రోగ్రెస్, లాగ్లు, రియల్-టైమ్ ఫీడ్‌బ్యాక్  |

### ముఖ్యమైన తేడాలు

అదనంగా, కొన్ని ముఖ్య తేడాలు:

- **కమ్యూనికేషన్ ప్యాటర్న్:**
  - సాంప్రదాయక HTTP స్ట్రీమింగ్: సింపుల్ చంక్డ్ ట్రాన్స్ఫర్ కోడింగ్ ఉపయోగించి డేటా పంపటం
  - MCP స్ట్రీమింగ్: JSON-RPC ప్రోటోకాల్ తో నిర్మిత నోటిఫికేషన్ వ్యవస్థను ఉపయోగిస్తుంది

- **మెసేజీ ఫార్మాట్:**
  - సాంప్రదాయక HTTP: సాధారణ టెక్స్ట్ చంక్‌లు కొత్త లైన్లతో
  - MCP: నిర్మిత LoggingMessageNotification అబ్జెక్టులు మెటాడేటాతో

- **కస్టమర్ అమలు:**
  - సాంప్రదాయక HTTP: సింపుల్ క్లయింట్ స్ట్రీమింగ్ రెస్పాన్స్ ప్రాసెస్ చేస్తుంది
  - MCP: మెసేజీ హ్యాండ్లర్ తో అధిక సున్నితమైన క్లయింట్, వివిధ రకాల మెసేజీలను ప్రాసెస్ చేస్తుంది

- **ప్రోగ్రెస్ నవీకరణలు:**
  - సాంప్రదాయక HTTP: ప్రోగ్రెస్ ప్రధాన రెస్పాన్స్ స్ట్రీమ్ భాగం
  - MCP: ప్రోగ్రెస్ వేర్వేరు నోటిఫికేషన్ మెసేజీలుగా పంపబడుతుంది, ప్రధాన రెస్పాన్స్ చివర రాబోతుంది

### సిఫారసులు

క్లాసిక్ స్ట్రీమింగ్ (పై ఉదాహరణలో `/stream` ఉపయోగించి) మరియు MCP ద్వారా స్ట్రీమింగ్ ఎంచుకునేటప్పుడు కొన్ని సిఫార్సులు ఉన్నాయి.

- **సాధారణ స్ట్రీమింగ్ అవసరాల కోసం:** సాంప్రదాయక HTTP స్ట్రీమింగ్ సులభంగా అమలు చేసి ప్రాథమిక అవసరాలకు సరిపోతుంది.

- **సంధి, ఇంటరాక్టివ్ అప్లికేషన్ల కోసం:** MCP స్ట్రీమింగ్ మెరుగైన మెటాడేటాతో నిర్మిత విధానాన్ని అందిస్తుంది, నోటిఫికేషన్లు మరియు తుది ఫలితాలు విడదీసి ఉంటాయి.

- **AI అప్లికేషన్ల కోసం:** MCP యొక్క నోటిఫికేషన్ వ్యవస్థ దీర్ఘకాలిక AI టాస్కులకు ఉపయోగకరం, వినియోగదారులను ప్రగతి గురించి తెలియజేస్తుంది.

## MCPలో స్ట్రీమింగ్

మీరు ఇప్పటివరకు సిఫార్సులు మరియు పోలికలను చూశారు క్లాసిక్ స్ట్రీమింగ్ మరియు MCP స్ట్రీమింగ్ మధ్య తేడాలు. ఇప్పుడు MCPలో స్ట్రీమింగ్‌ను ఎలా ఉపయోగించుకోచ్చో వివరంగా చూద్దాం.

MCP ఫ్రేమ్‌వర్క్‌లో స్ట్రీమింగ్ ఎలా పనిచేస్తుందో అర్థం చేసుకోవడం అత్యవసరం, దీర్ఘకాల పరిశ్రమలు సమయంలో వినియోగదారులకు సకాలంలో ఫీడ్‌బ్యాక్ ఇస్తుంది.

MCPలో, స్ట్రీమింగ్ అనేది ప్రధాన ప్రతిస్పందనను చంక్లుగా పంపడమే కాదు, ఒక టూల్ అభ్యర్థనను ప్రాసెస్ చేస్తున్నప్పుడు క్లయింట్‌కు **నోటిఫికేషన్లు** పంపడమే. ఈ నోటిఫికేషన్లలో ప్రోగ్రెస్ నవీకరణలు, లాగ్‌లు లేదా ఇతర ఈవెంట్‌లు ఉండవచ్చు.

### ఇది ఎలా పని చేస్తుంది

ప్రధాన ఫలితం ఇంకా ఒకే రెస్పాన్స్‌గా పంపబడుతుంది. అయినప్పటికీ, ప్రాసెసింగ్ సమయంలో వేరే మెసేజీలా నోటిఫికేషన్లు పంపి క్లయింట్‌ను రియల్ టైమ్‌లో అప్డేట్ చేయవచ్చు. క్లయింట్ ఈ నోటిఫికేషన్లు తెచ్చుకుని ప్రదర్శించగలగాలి.

## నోటిఫికేషన్ అంటే ఏమిటి?

"నోటిఫికేషన్" అని చెప్పగా, MCP సందర్భంలో అర్థం ఏమిటి?

నోటిఫికేషన్ అనేది సర్వర్ నుండి క్లయింట్‌కు పంపబడే ఒక సందేశం, దీని ద్వారా ప్రగతి, స్థితి, లేదా ఇతర ఈవెంట్ల గురించి సమాచారం తెలియజేయబడుతుంది. నోటిఫికేషన్లు పారదర్శకత మరియు వినియోగదారు అనుభవాన్ని మెరుగుపరుస్తాయి.

ఉదాహరణకు, ఒక క్లయింట్ సర్వర్‌తో ప్రారంభ హ్యాండ్షేక్ పూర్తవగానే నోటిఫికేషన్ పంపాలి.

ఒక నోటిఫికేషన్ JSON సందేశంగా ఈ విధంగా ఉంటుంది:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

నోటిఫికేషన్లు MCPలో ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) అనే టాపిక్‌కు చెందుతాయి.

> **నిర్ఘాతం సూచన:** `2026-07-28` MCP స్పెసిఫికేషన్ విడుదల అభ్యర్థి Logging ప్రిమిటివ్‌ను stdio ట్రాన్స్పోర్ట్స్‌కి `stderr`గా మరియు నిర్మిత వ్యాఖ్యానం కోసం OpenTelemetryగా డిప్రికేటెడ్ ప్రకటిస్తుంది. Logging `2025-11-25`లో మరియు ఫార్మల్ డిప్రికేషన్ తరువాత కనీసం ఒక సంవత్సరం పాటు పనిచేస్తుంది. వివరానికి [MCPలో ఏమి మారుతోంది: 2026-07-28 విడుదల అభ్యర్థి](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) చూడండి.

లాగింగ్ పనిచేయడానికి సర్వర్ దాన్ని ఫీచర్/కెపబిలిటీగా ప్రారంభించాలి, ఇలా:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> ఉపయోగించే SDKపై ఆధారపడి, లాగింగ్ డిఫాల్ట్‌గా ప్రారంభించబడవచ్చు లేదా మీ సర్వర్ కాన్ఫిగరేషన్‌లో స్పష్టంగా ప్రారంభించడం అవసరం కావచ్చు.

వివిధ రకాల నోటిఫికేషన్లు ఉన్నాయి:

|-----------|-------------------------------|---------------------------------|

|	info       | సాధారణ సమాచారం సందేశాలు      | ప్రగతి నవీకరణలు                |
|	notice     | సాధారణ కానీ గమనికీయ ఈవెంట్లు  | కాన్ఫిగరేషన్ మార్పులు            |
|	warning    | హెచ్చరికలు                    | డిప్రికేటెడ్ ఫీచర్ వినియోగం    |

|	alert      | తక్షణ చర్య అవసరం            | డేటా కరుప్షన్ గుర్తింపు         |
|	emergency  | సిస్టమ్ ఉపయోగించలేనిది       | పూర్తి సిస్టమ్ విఫలము             |

## MCPలో నోటిఫికేషన్లు అమలు చేయడం

MCPలో నోటిఫికేషన్లను అమలు చేయటానికి, సర్వర్ మరియు క్లయింట్ రెండింటినీ రియల్-టైమ్ నవీకరణలు నిర్వహించేవిగా ఏర్పాటుచేయాలి. దీని ద్వారా దీర్ఘకాలిక ఆపరేషన్ల సమయంలో వినియోగదారులకు తక్షణ ఫీడ్‌బ్యాక్ అందించవచ్చు.

### సర్వర్-వైపు: నోటిఫికేషన్లు పంపడం

సర్వర్ వైపున నుండి ప్రారంభిద్దాం. MCP లో, మీరు అభ్యర్థనలను ప్రాసెస్ చేసే సమయంలో నోటిఫికేషన్లు పంపగలిగే టూల్స్ వ్యవస్థాపించాలి. సర్వర్ ప్రాసెస్ సమయంలో క్లయింట్ కు మెసేజీలు పంపటానికి కాంటెక్స్ట్ వస్తువు (సాధారణంగా `ctx`) ను ఉపయోగిస్తుంది.

#### పైటాన్

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

పైన ఉదాహరణలో, `process_files` టూల్ ప్రతి ఫైల్ ప్రాసెస్ చేస్తున్నప్పుడు క్లయింట్ కు మూడు నోటిఫికేషన్లు పంపుతుంది. `ctx.info()` పద్ధతి సమాచార సందేశాలు పంపటానికి ఉపయోగిస్తారు.

అదనంగా, నోటిఫికేషన్లు ప్రారంభించేందుకు, మీ సర్వర్ స్ట్రీమింగ్ ట్రాన్స్పోర్ట్ (ఉదా: `streamable-http`) ఉపయోగించాలి మరియు క్లయింట్ నోటిఫికేషన్లను ప్రాసెస్ చేయడానికి మెసేజీ హ్యాండ్లర్ ఏర్పాటు ఉండాలి. ఇలా సర్వర్‌ను `streamable-http` ట్రాన్స్పోర్ట్ ఉపయోగించడానికి సెట్ చేయవచ్చు:

```python
mcp.run(transport="streamable-http")
```

#### .నెట్

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

ఈ .నెట్ ఉదాహరణలో, `ProcessFiles` టూల్ `Tool` అట్రిబ్యూట్‌తో అలంకరించబడినది మరియు ప్రతి ఫైల్ ప్రాసెస్ చేస్తున్నప్పుడు క్లయింట్‌కు మూడు నోటిఫికేషన్లు పంపుతుంది. `ctx.Info()` పద్ధతిని సమాచార సందేశాలు పంపేందుకు ఉపయోగిస్తారు.

మీ .NET MCP సర్వర్‌లో నోటిఫికేషన్లను ప్రారంభించడానికి, మీరు స్ట్రీమింగ్ ట్రాన్స్పోర్ట్ ఉపయోగిస్తున్నారా అని నిర్ధారించుకోండి:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### క్లయింట్-వైపు: నోటిఫికేషన్లు పొందడం

క్లయింట్ చేరే నోటిఫికేషన్లను ప్రాసెస్ చేసి ప్రదర్శించేందుకు మెసేజీ హ్యాండ్లర్‌ను అమలు చేయాలి.

#### పైథాన్

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

పై కోడులో, `message_handler` ఫంక్షన్ వచ్చిన మెసేజీ నోటిఫికేషన్ అయితే దాన్ని ప్రింట్ చేస్తుంది; లేదంటే సాధారణ సర్వర్ సందేశంగా ప్రాసెస్ చేస్తుంది. అలాగే `ClientSession` ను `message_handler`తో ప్రారంభించి నోటిఫికేషన్లు స్వీకరించడానికి ఏర్పాటు చెయ్యబడింది.

#### .నెట్

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

ఈ .నెట్ ఉదాహరణలో, `MessageHandler` ఫంక్షన్ వచ్చిన మెసేజీ నోటిఫికేషన్ అయితే దాన్ని ప్రింట్ చేస్తుంది; లేదంటే సాధారణ సర్వర్ సందేశంగా ప్రాసెస్ చేస్తుంది. `ClientSession` ని `ClientSessionOptions` ద్వారా మెసేజీ హ్యాండ్లర్‌తో ప్రారంభించారు.

నోటిఫికేషన్లను ప్రారంభించడానికి, మీ సర్వర్ స్ట్రీమింగ్ ట్రాన్స్పోర్ట్ (ఉదా: `streamable-http`) ఉపయోగించాల్సిందే మరియు మీ క్లయింట్ నోటిఫికేషన్లను ప్రాసెస్ చేయటానికి మెసేజీ హ్యాండ్లర్‌ను అమలు చేయాలి.

## ప్రోగ్రెస్ నోటిఫికేషన్లు & సందర్భాలు

ఈ విభాగం MCPలో ప్రోగ్రెస్ నోటిఫికేషన్ల ఆలోచన, అవి ఎందుకు ముఖ్యమైనవి మరియు Streamable HTTP ఉపయోగించి వాటిని ఎలా అమలు చేయాలో వివరిస్తుంది. మీ అర్థాన్ని పెంచటానికి ఒక ప్రాక్టికల్ అసైన్మెంట్ కూడా ఇస్తుంది.

ప్రోగ్రెస్ నోటిఫికేషన్లు దీర్ఘకాలిక ఆపరేషన్ల సమయంలో సర్వర్ నుండి క్లయింట్‌కు పంపబడే రియల్-టైమ్ సందేశాలు. మొత్తం ప్రాసెస్ పూర్తవ్వడానికి వేచి ఉండటం కాకుండా, సర్వర్ క్లయింట్‌కి ప్రస్తుత స్థితి గురించి నవీకరించగలదు. ఇది పారదర్శకత, వినియోగదారు అనుభవం మెరుగుపరుస్తుంది మరియు డీబగ్గింగ్ సులభతరం చేస్తుంది.

**ఉదాహరణ:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### ప్రోగ్రెస్ నోటిఫికేషన్లు ఎందుకు ఉపయోగించాలి?

ప్రోగ్రెస్ నోటిఫికేషన్లు అనేక కారణాల వల్ల అవసరం:

- **మంచి వినియోగదారు అనుభవం:** పని కొనసాగుతున్నంత వరకు వినియోగదారులు నవీకరణలు చూస్తారు, కేవలం ముగింపుకే కాదు.
- **రియల్-టైమ్ ఫీడ్‌బ్యాక్:** క్లయింట్లు ప్రోగ్రెస్ బార్లు లేదా లాగ్లు ప్రదర్శించగలవు, అప్లికేషన్ స్పందనశీలంగా అనిపిస్తుంది.
- **డీబగ్గింగ్ మరియు మానిటరింగ్ సులభతరం:** డెవలపర్లు మరియు వినియోగదారులు ప్రాసెస్ ఎక్కడ నిద్రలేదో లేదా మందగానే ఉందో చూడగలరు.

### ప్రోగ్రెస్ నోటిఫికేషన్లు ఎలా అమలు చేయాలి

MCPలో ప్రోగ్రెస్ నోటిఫికేషన్లు ఇలా అమలు చేయవచ్చు:

- **సర్వర్ వైపు:** ప్రతి అంశం ప్రాసెస్ అవుతున్నప్పుడు `ctx.info()` లేదా `ctx.log()`తో నోటిఫికేషన్లు పంపండి. ఇది ప్రధాన ఫలితం సిద్ధంగా ఉండటానికి ముందు క్లయింట్ కి మెసేజ్ పంపుతుంది.
- **క్లయింట్ వైపు:** వచ్చిన నోటిఫికేషన్లను వింటూ ప్రదర్శించే మెసేజీ హ్యాండ్లర్ అమలు చేయండి. ఈ హ్యాండ్లర్ నోటిఫికేషన్లు మరియు తుది ఫలితాలను వేరుగా తెలుసుకుంటుంది.

**సర్వర్ ఉదాహరణ:**


#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

**క్లయింట్ ఉదాహరణ:**

#### Python

```python

        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)
```

## భద్రతా పరిశీలనలు

సర్వర్ అమలు చేయడం లో భద్రతా ముఖ్యమైన ప్రాధాన్యత కలిగి ఉండాలి, ముఖ్యంగా MCP లో Streamable HTTP వంటి HTTP-ఆధారిత పంపిణీలు ఉపయోగిస్తున్నప్పుడు.

HTTP-ఆధారిత పంపిణీలతో MCP సర్వర్లను అమలు చేస్తే, భద్రతా అంశం కీలకమైనది అవుతుంది, ఇది అనేక దాడి మార్గాలు మరియు రక్షణ పద్ధతులకు జాగ్రత్తగా గమనించాలని అవసరం.

### సమీక్ష

MCP సర్వర్లను HTTP మీద ప్రదర్శించేటప్పుడు భద్రత అత్యంత అవసరం. Streamable HTTP కొత్త దాడి ఉపరితలాలను పరిచయంచేస్తుంది మరియు జాగ్రత్తగా ఏర్పాట్లు అవసరం.

ఇక్కడ కొన్ని ప్రధాన భద్రతా పరిగణనలు ఉన్నాయి:

- **Origin హెడర్ ధృవీకరణ**: DNS రీబైండింగ్ దాడులను నివారించడానికి ఎప్పుడూ `Origin` హెడర్‌ను ధృవీకరించండి.
- **Localhost బైండింగ్**: లోకల్ అభివృద్ధి కోసం, సర్వర్లను `localhost` కి బాండింగ్ చేసి ప్రజా ఇంటర్నెట్ నుండి వాటిని దూరం ఉంచండి.
- **సర్టిఫికేషన్**: ఉత్పత్తి వెర్షన్ల కోసం సాక్ష్యపత్రాలు (API కీలు, OAuth) అమలు చేయండి.
- **CORS**: క్రాస్-ఓరిజిన్ రిసోర్స్ షేరింగ్(CORS) విధానాలను ఉపయోగించి యాక్సెస్ ని పరిమితం చేయండి.
- **HTTPS**: ట్రాఫిక్ ఎన్‌క్రిప్ట్ చేయడానికి ఉత్పత్తిలో HTTPS ఉపయోగించండి.

### ఉత్తమ పద్ధతులు

అదనంగా, మీ MCP స్ట్రీమింగ్ సర్వర్‌లో భద్రత అమలు చేసేటప్పుడు పాటించవలసిన కొన్ని ఉత్తమ పద్ధతులు:

- ధృవీకరణ లేకుండా వచ్చే అభ్యర్థనలను ఎప్పుడూ నమ్మకండి.
- అన్ని యాక్సెస్ మరియు లోపాలను లాగ్ చేసి, మానిటర్ చేయండి.
- భద్రతా లోపాలను ప్యాచ్ చేసేందుకు డిపెండెన్సీలను నియమితంగా అప్డేట్ చేయండి.

### సవాళ్లు

MCP స్ట్రీమింగ్ సర్వర్‌లలో భద్రత అమలు చేస్తున్నప్పుడు మీరు కొన్ని సవాళ్లను ఎదుర్కొంటారు:

- అభివృద్ధి సౌలభ్యం మరియు భద్రతా మధ్య సంతులనం
- వివిధ క్లయింట్ పరిసరాల సరఫరాను నిర్ధారించడం


## SSE నుండి Streamable HTTP కి అప్‌గ్రేడ్ చేయడం

ప్రస్తుతం Server-Sent Events (SSE) ఉపయోగిస్తున్న అప్లికేషన్లకు, Streamable HTTP కి మారడం MCP అమలు కోసం మెరుగైన సామర్థ్యాలు మరియు దీర్ఘకాలిక సుస్థిరత కల్పిస్తుంది.

### ఎందుకు అప్‌గ్రేడ్ చేయాలి?

SSE నుండి Streamable HTTP కి అప్‌గ్రేడ్ చేయడానికి రెండు బలమైన కారణాలు ఉన్నాయి:

- Streamable HTTP SSE కంటే మెరుగైన స్కేలబులిటీ, అనుకూలత, మరియు అధికమైన నోటిఫికేషన్ మద్దతు అందిస్తుంది.
- ఇది కొత్త MCP అప్లికేషన్ల కోసం సిఫార్సు చేయబడే పంపిణీ.

### మార్గదర్శక దశలు

మీ MCP అప్లికేషన్లలో SSE నుండి Streamable HTTP కి ఎలా మారాలో ఇదిగో:

- **సర్వర్ కోడ్ ను నవీకరించండి**: `mcp.run()` లో `transport="streamable-http"` ను ఉపయోగించండి.
- **క్లయింట్ కోడ్ నవీకరించండి**: SSE క్లయింట్ స్థానంలో `streamablehttp_client` ఉపయోగించండి.
- **మెసేజ్ హ్యాండ్లర్ అమలు చేయండి**: క్లయింట్‌లో నోటిఫికేషన్లను ప్రాసెస్ చేయడానికి.
- **ఉపకరణాలతో అనుకూలత కోసం పరీక్షించండి**.

### అనుకూలతను నిర్వహించడం

మార్పిడి ప్రక్రియలో ఉన్న SSE క్లయింట్లతో అనుకూలతను కార్యక్రమంగా నిర్వహించడం సిఫార్సు చేయబడుతుంది. కొన్ని వ్యూహాలు:

- వేరువేరు ఎండ్మొయింట్లపై SSE మరియు Streamable HTTP రెండింటినీ అమలు చేయవచ్చు.
- clients‌ను కొత్త పంపిణీకి ప్రశాంతంగా తరలించండి.

### సవాళ్లు

మార్పిడి సమయంలో క్రింది సవాళ్లను గుర్తించి పరిష్కరించండి:

- అన్ని క్లయింట్లు అప్డేట్ అయ్యాయనే నిర్ధారించుకోవడం
- నోటిఫికేషన్ డెలివరీలో వ్యత్యాసాలను నిర్వహించడం

### పని: మీ స్వంత స్ట్రీమింగ్ MCP ఆప్‌ను నిర్మించండి

**పరిస్థితి:**
ఒక MCP సర్వర్ మరియు క్లయింట్ నిర్మించండి, అందులో సర్వర్ అంశాల (ఉదా: ఫైళ్ళు లేదా డాక్) జాబితాను ప్రాసెస్ చేసి ప్రతి అంశం ప్రాసెస్ అయినప్పుడు ఒక నోటిఫికేషన్ పంపుతుంది. క్లయింట్ ఆ నోటిఫికేషన్లను వచ్చిన వెంటనే ప్రదర్శించాలి.

**దశలు:**

1. ఒక సర్వర్ సాధనాన్ని అమలు చేయండి, అది జాబితాను ప్రాసెస్ చేసి ప్రతి అంశంకోసం నోటిఫికేషన్లు పంపుతుంది.
2. నోటిఫికేషన్లను రియల్ టైమ్‌లో ప్రదర్శించడానికి మెసేజ్ హ్యాండ్లరుతో క్లయింట్ను అమలు చేయండి.
3. సర్వర్ మరియు క్లయింట్ రెండింటినీ నడిపించి, నోటిఫికేషన్లను గమనించి మీ అమలును పరీక్షించండి.

[సమాధానం](./solution/README.md)

## మ‌రింత చదవడం & తరువాత ఏమి చేయాలి?

MCP స్ట్రీమింగ్‌లో మీ ప్రయాణాన్ని కొనసాగించడానికి మరియు మీ సాంకేతిక పరిజ్ఞానాన్ని విస్తరించడానికి, ఈ విభాగం అదనపు వనరులు మరియు సూచించిన తదుపరి దశలను అందిస్తుంది.

- [Microsoft: Server-Sent Events (SSE)](https://learn.microsoft.com/azure/application-gateway/for-containers/server-sent-events?tabs=server-sent-events-gateway-api&WT.mc_id=%3Fwt.mc_id%3DMVP_452430)

### తరువాత ఏమి చేయాలి?

- స్ట్రీమింగ్‌ను ఉపయోగించి రియల్‌టైమ్ అనలిటిక్స్, సంభాషణ లేదా సహకార ఎడిటింగ్ కోసం మరింత అభివృద్ధి చెందిన MCP సాధనాలు రూపొందించడానికి ప్రయత్నించండి.
- MCP స్ట్రీమింగ్‌ను ఫ్రంట్ ఎండ్ ఫ్రేమ్‌వర్క్‌లతో (React, Vue, మొదలైనవి) కలిపి ప్రత్యక్ష UI నవీకరణల కోసం అన్వేషించండి.
- తదుపరి: [VSCode కోసం AI టూల్‌కిట్ ఉపయోగించడం](../07-aitk/README.md)
