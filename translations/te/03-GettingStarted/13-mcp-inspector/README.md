# MCP ఇంస్పెక్టర్‌తో డీబగ్గింగ్

> [!NOTE]
> `--sse` ఉపయోగించే కమాండ్లు మరియు `/sse`తో ముగిసే URLs పాత HTTP+SSE
> ట్రాన్స్పోర్ట్‌ను పరీక్షిస్తాయి. కొత్త MCP `2026-07-28` సర్వర్ కోసం,
> స్ట్రీమబుల్ HTTPని మద్దతు ఇచ్చే ఇంస్పెక్టర్ వెర్షన్‌ను ఉపయోగించి ఆ ట్రాన్స్పోర్ట్‌ను ఎంచుకోండి.

**MCP ఇంస్పెక్టర్** ఒక మౌలిక డీబగ్గింగ్ టూల్, ఇది మీరు పూర్తి AI హోస్ట్ అప్లికేషన్ అవసరం లేకుండా మీ MCP సర్వర్‌లను ఇంటరాక్టివ్‌గా పరీక్షించుకోవడానికి మరియు సమస్యలను పరిష్కరించుకునేందుకు అనుమతిస్తుంది. దీన్ని "MCP కోసం పోస్ట్‌మాన్"గా భావించండి - ఇది అభ్యర్ధనలు పంపేందుకు, ప్రతిస్పందనలను చూడటానికి, మరియు మీ సర్వర్ ఎలా నిర్వహిస్తోంది అనేదాన్ని అర్థం చేసుకోడానికి ఒక విజువల్ ఇంటర్‌ఫేస్‌ను అందిస్తుంది.

## MCP ఇంస్పెక్టర్ ఉపయోగించాల్సిన కారణాలు

MCP సర్వర్‌లు నిర్మిస్తున్నప్పుడు, మీరు తరచుగా ఈ సవాళ్ళను ఎదుర్కొంటారు:

- **"నా సర్వర్ పనిచేస్తుందా?"** - ఇంస్పెక్టర్ కనెక్షన్ స్థితిని చూపిస్తుంది
- **"నా టూల్‌లు సరైన రీతిలో నమోదయ్యాయా?"** - ఇంస్పెక్టర్ అందుబాటులో ఉన్న అన్ని టూల్‌లను జాబితా చేస్తుంది
- **"ప్రతిస్పందన ఫార్మాట్ ఏమిటి?"** - ఇంస్పెక్టర్ మొత్తం JSON ప్రతిస్పందనలను ప్రదర్శిస్తుంది
- **"ఈ టూల్ ఎందుకు పని చేయట్లేదు?"** - ఇంస్పెక్టర్ విస్తృతమైన పొరపాటు సందేశాలను చూపిస్తుంది

## ముందస్తు అవసరాలు

- Node.js 18+ ఇన్‌స్టాల్ చేయబడివుండాలి
- npm (Node.js‌తో వస్తుంది)
- పరీక్షించడానికి MCP సర్వర్ (చూడండి [Module 3.1 - First Server](../01-first-server/README.md))

## ఇన్‌స్టాలేషన్

### ఎంపిక 1: npx తో నడపడం (త్వరిత పరీక్షకు సిఫార్సు)

```bash
npx @modelcontextprotocol/inspector
```

### ఎంపిక 2: గ్లోబల్‌గా ఇన్‌స్టాల్ చేయండి

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### ఎంపిక 3: మీ ప్రాజెక్ట్‌లో జోడించండి

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json`లో జోడించండి:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## మీ సర్వర్‌తో కనెక్ట్ అవడం

### stdio సర్వర్‌లు (స్థానిక ప్రాసెస్)

స్టాండర్డ్ ఇన్పుట్/ఔట్‌పుట్ ద్వారా కమ్యూనికేట్ అయ్యే సర్వర్‌లకు:

```bash
# పైథన్ సర్వర్
npx @modelcontextprotocol/inspector python -m your_server_module

# నోడ్.జెఎస్ సర్వర్
npx @modelcontextprotocol/inspector node ./build/index.js

# పర్యావరణ వేరియబుల్స్‌తో
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP సర్వర్‌లు (నెట్‌వర్క్)

HTTP సర్వీస్‌లుగా నడిచే సర్వర్‌లకు:

1. ముందుగా మీ సర్వర్‌ను ప్రారంభించండి:
   ```bash
   python server.py  # సర్వర్ http://localhost:8080 పై నడుస్తోంది
   ```

2. ఇంస్పెక్టర్‌ను ప్రారంభించి కనెక్ట్ అవ్వండి:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## టూల్‌లను పరీక్షించడం

### అందుబాటులో ఉన్న టూల్‌లను జాబితా చేయడం

1. **Tools** టాబ్‌ను క్లిక్ చేయండి
2. ఇంస్పెక్టర్ ఆటోమేటిక్‌గా `tools/list` ను పిలుస్తుంది
3. మీరు నమోదు చేసిన అన్ని టూల్‌లను చూశావు:
   - టూల్ పేరు
   - వివరణ
   - ఇన్‌పుట్ స్కీమా (ప్యారామీటర్లు)

### టూల్ కాల్ చేయడం

1. జాబితా నుండి ఒక టూల్ ఎంపిక చేయండి
2. ఫారంలో అవసరమైన ప్యారామీటర్‌లను నింపండి
3. **Run Tool** క్లిక్ చేయండి
4. ఫలిత పానెల్లో ప్రతిస్పందనను చూడండి

**ఉదాహరణ: కల్యునేటర్ టూల్‌ని పరీక్షించడం**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### టూల్ పొరపాట్లను డీబగ్ చేయడం

ఒక టూల్ విఫలమైనప్పుడు, ఇంస్పెక్టర్ చూపిస్తుంది:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

సాధారణ పొరపాటు కోడ్‌లు:
| కోడ్ | అర్థం |
|------|---------|
| -32700 | పార్స్ పొరపాటు (చెల్లని JSON) |
| -32600 | చెల్లని అభ్యర్ధన |
| -32601 | పద్ధతి కనుగొనబడలేదు |
| -32602 | చెల్లని ప్యారామీటర్లు |
| -32603 | అంతర్గత పొరపాటు |

## వనరులను పరీక్షించడం

### వనరుల జాబితా

1. **Resources** టాబ్‌ను క్లిక్ చేయండి
2. ఇంస్పెక్టర్ `resources/list` ను పిలుస్తుంది
3. మీరు చూడాలి:
   - వనరు URIs
   - పేర్లను మరియు వివరాలను
   - MIME రకాలను

### వనరును చదవడం

1. ఒక వనరు ఎంపిక చేయండి
2. **Read Resource** క్లిక్ చేయండి
3. తిరిగి వచ్చిన కంటెంట్ను చూడండి

**ఉదాహరణ అవుట్‌పుట్:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## ప్రాంప్ట్‌లను పరీక్షించడం

### ప్రాంప్ట్‌ల జాబితా

1. **Prompts** టాబ్‌ను క్లిక్ చేయండి
2. ఇంస్పెక్టర్ `prompts/list` పిలుస్తుంది
3. అందుబాటులో ఉన్న ప్రాంప్ట్ టెంప్లేట్లు చూడండి

### ప్రాంప్ట్ పొందడం

1. ఒక ప్రాంప్ట్ ఎంచుకోండి
2. అవసరమైన ఏ ఆటర్గ్యూమెంట్లు ఉన్నా నింపండి
3. **Get Prompt** క్లిక్ చేయండి
4. రూపొందించిన ప్రాంప్ట్ సందేశాలను చూడండి

## సందేశ లాగ్ విశ్లేషణ

సందేశ లాగ్ మొత్తం MCP ప్రోటోకాల్ సందేశాలను చూపిస్తుంది. క్రింద ఉన్న ట్రాన్స్క్రిప్ట్ ఒక
పాత `2025-11-25` సర్వర్ నుండి మరియు తొలగించిన `initialize` హ్యాండ్షేక్‌ను కలిగి ఉంది. ఒక
`2026-07-28` సర్వర్ స్వీయ-సంకలన అభ్యర్థన మెటాడేటా మరియు `server/discover`
ను ఉపయోగిస్తుంది.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### ఏమి చూడాలి

- **అభ్యర్థన/ప్రతిస్పందన జతలు**: ప్రతి `→`కి సరిపోలే `←` ఉండాలి
- **దోష సంకేతాలు**: ప్రతిస్పందనల్లో `"error"` కోసం చూడండి
- **సమయం**: పెద్ద విరామాలు పనితీరు సమస్యలను సూచించవచ్చు
- **ప్రోటోకాల్ వెర్షన్**: సర్వర్ మరియు క్లయింట్ వెర్షన్‌పై ఏకీభవిస్తాయా చూసుకోండి

## సాధారణ డీబగ్గింగ్ సందర్భాలు

### సందర్భం 1: సర్వర్ కనెక్ట్ అవ్వడం లేదు

**చిహ్నాలు:** ఇంస్పెక్టర్ "Disconnected" చూపుతుంది లేదా "Connecting..." వద్ద నిలిపివేస్తుంది

**చెక్క్‌లిస్ట్:**
1. ✅ సర్వర్ కమాండ్ సరైనదా?
2. ✅ అన్ని డిపెండెన్సీలు ఇన్‌స్టాల్ అయ్యాయా?
3. ✅ సర్వర్ మార్గం సాపేక్షమా లేక సమగ్రమా?
4. ✅ అవసరమైన పర్యావరణ మార్పిడి విలువలు సెట్ అయినాయా?

**డీబగ్ దశలు:**
```bash
# సర్వర్‌ను మొదటగా మాన్యువల్‌గా పరీక్షించండి
python -c "import your_server_module; print('OK')"

# దిగుమతి లోపాలు ఉన్నాయో చూడండి
python -m your_server_module 2>&1 | head -20

# MCP SDK సంస్థాపితం అయ్యిందో నిర్థారించుకోండి
pip show mcp
```

### సందర్భం 2: టూల్స్ కనిపించడం లేదు

**చిహ్నాలు:** టూల్స్ టాబ్ ఖాళీగా కనిపిస్తుంది

**పట్టించుకోవాల్సిన కారణాలు:**
1. సర్వర్ ప్రారంభంలో టూల్‌లు నమోదు కాలేదు
2. సర్వర్ మొదలైన తర్వాత క్రాష్ అయ్యింది
3. `tools/list` హ్యాండ్లర్ ఖాళీ అర్రే తిరిగి ఇస్తోంది

**డీబగ్ దశలు:**
1. `tools/list` ప్రతిస్పందన కోసం సందేశ లాగ్‌ను చూడండి
2. మీ టూల్ నమోదు కోడ్‌కు లాగింగ్ జోడించండి
3. `@mcp.tool()` డెకరేటర్లు ఉన్నాయో లేదో నిర్ధారించుకోండి (పైథాన్)

### సందర్భం 3: టూల్ పొరపాటు తిరిగి ఇస్తుంది

**చిహ్నాలు:** టూల్ కాల్ పొరపాటు ప్రతిస్పందనను ఇస్తోంది

**డీబగ్ దృష్టి:**
1. పొరపాటు సందేశాన్ని సవిధిగా చదవండి
2. ప్యారామీటర్ రకాలలో స్కీమా సరిపోతుందా చూసుకోండి
3. విస్తృతమైన పొరపాటు సందేశాలతో try/catch జోడించండి
4. సర్వర్ లాగ్‌లలో స్టాక్ ట్రేస్‌లను పరిశీలించండి

**ఉదాహరణ మెరుగైన పొరపాటు హ్యాండిలింగ్:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # ఇక్కడ సాధనం తర్కం ఉంది
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### సందర్భం 4: వనరు కంటెంట్ ఖాళీగా ఉంది

**చిహ్నాలు:** వనరు తిరిగి వస్తోంది కానీ కంటెంట్ ఖాళీ లేదా నల్

**చెక్క్‌లిస్ట్:**
1. ✅ ఫైల్ మార్గం లేదా URI సరైనదా?
2. ✅ సర్వర్ వనరును చదవడానికి అనుమతిని కలిగి ఉందా?
3. ✅ వనరు కంటెంట్ సక్రమంగా తిరిగి వస్తోంది

## ఉత్తమ అభ్యాసాలు

1. **ముందుగా మరియు తరచుగా పరీక్షించండి** - డెవలప్‌మెంట్ సమయంలో ఇంస్పెక్టర్ ఉపయోగించండి, సమస్యలు వచ్చినప్పుడు మాత్రమే కాకుండా
2. **సాధారణంగా ప్రారంభించండి** - క్లిష్టమైన టూల్ కాల్‌లకు ముందు ప్రాథమిక కనెక్టివిటీని పరీక్షించండి
3. **స్కీమాను పరిశీలించండి** - పారామీటర్ రకాలు సరిపోలకపోవడం వల్ల చాలా పొరపాట్లు వస్తాయి
4. **పొరపాటు సందేశాలను చదవండి** - MCP పొరపాట్లు సాధారణంగా వివరణాత్మకంగా ఉంటాయి
5. **ఇంస్పెక్టర్ తెరిచి ఉంచండి** - డెవలప్‌మెంట్ సమయంలో సమస్యలను కనిపెట్టడంలో ఇది సహాయపడుతుంది
