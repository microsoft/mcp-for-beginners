# HTTPS ஸ்ட்ரீமிங் மாடல் Context ப்ரொட்டோக்கால் (MCP) உடன்

இந்த அத்தியாயம் HTTPS இல் மாடல் Context ப்ரொட்டோக்கால் (MCP) பயன்படுத்தி பாதுகாப்பான, பருமனான மற்றும் நேரடி ஸ்ட்ரீமிங்கை செயல்படுத்த ஒரு விரிவான வழிகாட்டியை வழங்குகிறது. இது ஸ்ட்ரீமிங்கிற்கான கோரிக்கையை, கிடைக்கும் டிரான்ஸ்போர்ட் முறைகள், MCP இல் ஸ்ட்ரீமபிள் HTTP ஐ எப்படி செயல்படுத்துவது, பாதுகாப்பு சிறந்த நடைமுறைகள், SSE இலிருந்து இடமாற்றம் மற்றும் உங்கள் சொந்த ஸ்ட்ரீமிங் MCP பயன்பாடுகளை கட்டும் நடைமுறைகளை உள்ளடக்கியது.

> **பார்க்க முன்னால்:** இந்த பாடம் **MCP குறிப்புரு 2025-11-25** க்குள் ஸ்ட்ரீமபிள் HTTP ஐ விவரிக்கின்றது, அதைauth்ற `initialize` நேரத்தில் ஒரு சேஷன் நிறுவப்படுகிறது மேலும் அது `Mcp-Session-Id` தலைப்பால் பின்தொடரப்படுகிறது. `2026-07-28` வெளியீட்டு வேட்பாளர் கைமோதல் மற்றும் சேஷன் ஐடியைப் முற்றிலும் நீக்கி, ஒவ்வொரு கோரிக்கையும் தானாகவே இருக்கும் மற்றும் எந்த சர்வர் இன்ஸ்டான்சுக்கும் நெறிப்படுத்தப்படும். விரிவுகளுக்கு [MCP இல் என்ன மாற்றப்படுகிறது: 2026-07-28 வெளியீடு வேட்பாளர்](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) பார்க்கவும்.

## MCP இல் டிரான்ஸ்போர்ட் முறைகள் மற்றும் ஸ்ட்ரீமிங்

இந்த பகுதியாக MCP இல் கிடைக்கும் வெவ்வேறு டிரான்ஸ்போர்ட் முறைகள் மற்றும் அவை கிளையண்ட்கள் மற்றும் சர்வர்களுக்கு இடையேயான நேரடி தொடர்பிற்கான ஸ்ட்ரீமிங் திறன்களை வழங்கும் பங்கு ஆராயப்படுகின்றது.

### டிரான்ஸ்போர்ட் மெக்கானிசம் என்றால் என்ன?

டிரான்ஸ்போர்ட் மெக்கானிசம் என்பது தரவு கிளையண்டுக்கும் சர்வருக்கும் எப்படி பரிமாறப்படுகிறது என்பதைக் குறிப்பிடுகின்றது. MCP பல்வேறு சூழல்களுக்கு மற்றும் தேவைகளுக்கு ஏற்ப பல டிரான்ஸ்போர்ட் வகைகள் ஆதரிக்கிறது:

- **stdio**: ஸ்டாண்டர்டு இன்புட்/அவுட், உள்ளூர் மற்றும் CLI அடிப்படையிலான கருவிகளுக்கு பொருத்தமானது. எளிமையானது ஆனால் வலை அல்லது கிளவுடுக்கு பொருத்தமல்ல.
- **SSE (சர்வர்-அனுப்பும் நிகழ்வுகள்)**: சர்வர்கள் HTTP வழியாக நேரடி புதுப்பிப்புகளை கிளையண்ட்களுக்கு தள்ள அனுமதிக்கிறது. வெப் UI க்கு நல்லது, ஆனால் பருமன் மற்றும் நெகிழ்வுத்தன்மையில் வரம்பு உள்ளது. MCP குறிப்புரு 2025-06-18 இல், தனித்த SSE (சர்வர்-அனுப்பும் நிகழ்வுகள்) டிரான்ஸ்போர்ட் நிலைநிறுத்தப்பட்டுள்ளது மற்றும் அதனை "ஸ்ட்ரீமபிள் HTTP" டிரான்ஸ்போர்ட் மாற்றியுள்ளது.
- **ஸ்ட்ரீமபிள் HTTP**: தமிழ்மையான HTTP அடிப்படையிலான ஸ்ட்ரீமிங், அறிவிப்புகளுக்கு ஆதரவும் மேம்பட்ட பருமனையும் கொண்டது. பெரும்பான்மை தயாரிப்பு மற்றும் கிளவுட் சூழலுக்கு பரிந்துரைக்கப்படுகிறது.

### ஒப்புமை அட்டவணை

கீழே உள்ள ஒப்புமை அட்டவணையைப் பாருங்கள், இவை இந்த டிரான்ஸ்போர்ட் முறைகளுக்கு இடையேயான வேறுபாடுகளைப் புரிந்துகொள்ள உதவும்:

| டிரான்ஸ்போர்ட்      | நேரடி புதுப்பிப்புகள் | ஸ்ட்ரீமிங் | பருமன்       | பயன்பாட்டு முறை         |
|--------------------|--------------------|-----------|--------------|-------------------------|
| stdio              | இல்லை             | இல்லை     | குறைந்தது    | உள்ளூர் CLI கருவிகள்     |
| SSE                | ஆம்                | ஆம்        | நடுத்தரம்    | வலை, நேரடி புதுப்பிப்புகள் |
| ஸ்ட்ரீமபிள் HTTP    | ஆம்                | ஆம்        | உயர்ந்தது    | கிளவுட், பன்முக கிளையண்ட் |

> **செய்தி:** சரியான டிரான்ஸ்போர்டை தேர்ச்சி செய்வது செயல்திறன், பருமன் மற்றும் பயனர் அனுபவத்தைக் கொண்டுவரும். **ஸ்ட்ரீமபிள் HTTP** இல் நவீன, பருமனான மற்றும் கிளவுட் தயார் பயன்பாடுகளுக்கு பரிந்துரைக்கப்படுகிறது.

முந்தைய அத்தியாயங்களில் நீங்கள் பார்த்த stdio மற்றும் SSE போன்ற டிரான்ஸ்போர்டுகளை மனதில் வைத்திருங்கள் மற்றும் இந்த அத்தியாயம் கையாளும் ஸ்ட்ரீமபிள் HTTP தான் டிரான்ஸ்போர்ட் என்பதை கவனியுங்கள்.

## ஸ்ட்ரீமிங்: கருத்துக்கள் மற்றும் உந்துதல்

ஸ்ட்ரீமிங்கின் அடிப்படை கருத்துக்கள் மற்றும் உந்துதல்களை புரிந்துகொள்வதில் வேலை செய்்படும் நேரடி தொடர்பு அமைப்புகளை உருவாக்க மிகவும் முக்கியம்.

**ஸ்ட்ரீமிங்** என்பது ஒரு நெட்வொர்க் நிரலாக்க யுக்தி, இதில் முழு பதிலை காத்திருக்கும்படியில்லை, அருகிலுள்ள சிறிய துண்டுகள் அல்லது நிகழ்வுகளின் தொடர் ஆக தரவு அனுப்பப்படுகிறது மற்றும் பெறப்படுகிறது. இது குறிப்பாக பயனுள்ளதாக இருக்கும்:

- பெரிய கோப்புகள் அல்லது தரவுத்தொகுதிகள்.
- நேரடி புதுப்பிப்புகள் (எ.கா., சாட், முன்னேற்ற பட்டைகள்).
- நீண்ட நேரம் இயங்கும் கணக்கீடுகள், இதில் பயனருக்கு நிலைகளை தெரிவிக்க வேண்டும்.

மேலோட்டமாக ஸ்ட்ரீமிங்கைப் பற்றி நீங்கள் அறியவேண்டியவை:

- தரவு கட்டத்திற்கு இயலும் முறையில் வழங்கப்படுகிறது, ஒரே நேரத்தில் அனைத்து தரவும் அல்ல.
- கிளையண்ட் தரவு வந்தவுடன் செயலாக்க முடியும்.
- அறிமுகம்கூறும் தாமதத்தைக் குறைக்கிறது மற்றும் பயனர் அனுபவத்தை மேம்படுத்துகிறது.

### ஏன் ஸ்ட்ரீமிங் பயன்படுத்த வேண்டும்?

ஸ்ட்ரீமிங் பயன்படுத்த காரணங்கள் இவை:

- பயனருக்கு உடனடி பின்னூட்டம் கிடைக்கிறது, முடிவில் மட்டும் அல்ல
- நேரடி பயன்பாடுகள் மற்றும் பதிலை உடனடி காட்டும் UI களை உருவாக்க உதவுகிறது
- நெட்‌வர்க்க் மற்றும் கணினி வளங்களை சிறப்பாக பயன்படுத்த முடியும்

### எளிய உதாரணம்: HTTP ஸ்ட்ரீமிங் சர்வர் மற்றும் கிளையண்ட்

ஸ்ட்ரீமிங் எப்படி செயல்படுகிறது என்பதற்கு எளிய உதாரணம் இதோ:

#### Python

**சர்வர் (Python, FastAPI மற்றும் StreamingResponse பயன்படுத்தி):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**கிளையண்ட் (Python, requests பயன்படுத்தி):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

இந்த உதாரணத்தில், சர்வர், அனைத்து செய்திகளும் தயார் ஆக காத்திருக்காமல், காணும் போதும் அணிவகுத்து கிளையண்ட்டுக்கு அனுப்புகிறது.

**எப்படி வேலை செய்கிறது:**

- சர்வர் ஒவ்வொரு செய்தியையும் அது தயார் ஆகும் போதே அளிக்கிறது.
- கிளையண்ட் அடையும் ஒவ்வொரு துண்டையும் பெற்றுக் கொண்டு அச்சடிக்கிறது.

**தேவைகள்:**

- சர்வர் ஸ்ட்ரீமிங் பதிலை பயன்படுத்த வேண்டியது (எ.கா., FastAPI இல் `StreamingResponse`).
- கிளையண்ட் பதிலை ஸ்ட்ரீமாக செயலாக்க வேண்டும் (`stream=True` requests இல்).
- உள்ளடக்க வகை `text/event-stream` அல்லது `application/octet-stream` ஆக இருக்கும்.

#### Java

**சர்வர் (Java, Spring Boot மற்றும் Server-Sent Events பாவித்து):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**கிளையண்ட் (Java, Spring WebFlux WebClient):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**Java நடைமுறை குறிப்புகள்:**

- Spring Boot இன் 반응 (reactive) ஸ்டாக் மற்றும் `Flux` மூலம் ஸ்ட்ரீமிங்
- `ServerSentEvent` நிகழ்வுகளுக்கு வகை வாய்ந்த ஸ்ட்ரீமிங் வழங்குகிறது
- `WebClient` உடன் `bodyToFlux()` மூலம் ஸ்ட்ரீமிங் பெறல் இயலும்
- `delayElements()` நிகழ்வுகளுக்கு இடையேயான செயலாக்க நேரத்தை அணிக்கிறது
- நிகழ்வுகள் (`info`, `result` போன்றவைகள்) கிளையண்ட் மேற்பார்வைக்கு சிறந்தவை

### ஒப்புமை: பழம்பொருள் ஸ்ட்ரீமிங் vs MCP ஸ்ட்ரீமிங்

`பழம்பொருள்` முறையில் ஸ்ட்ரீமிங் எப்படி நடக்கிறது என்பதையும் MCP இல் அது எப்படி நடைபெறுகிறது என்பதையும் கீழ்காணும் அட்டவணை மூலம் காட்டலாம்:

| அம்சம்                 | பழம்பொருள் HTTP ஸ்ட்ரீமிங்   | MCP ஸ்ட்ரீமிங் (அறிவிப்புகள்)           |
|------------------------|-----------------------------|----------------------------------------|
| முக்கிய பதில்          | துண்டாக்கப்பட்டது            | ஒரே பதில், முடிவில் மட்டுமே            |
| முன்னேற்ற புதுப்பிப்புகள் | தரவு துண்டுகளாக அனுப்பப்படுகிறது | அறிவிப்புகளாக அனுப்பப்படுகிறது           |
| கிளையண்ட் தேவைகள்      | ஸ்ட்ரீம் செயலாக்க வேண்டும்    | செய்தி கைையாளரை செயல்படுத்த வேண்டும்      |
| பயன்பாடு              | பெரிய கோப்புகள், AI டோக்கன் ஸ்ட்ரீம்கள் | முன்னேற்றம், பதிவுகள், நேரடி பின்னூட்டம்  |

### கவனிக்க வேண்டிய வேறுபாடுகள்

மேலும் சில முக்கிய வேறுபாடுகள் உள்ளன:

- **தொடர்புக் கூற்று (கம்யூனிகேசன் மாதிரி):**
  - பழம்பொருள் HTTP ஸ்ட்ரீமிங்: எளிய துண்டுதரவு மாற்றிக் கொடுப்பை பயன்படுத்துகிறது
  - MCP ஸ்ட்ரீமிங்: JSON-RPC ப்ரொட்டோக்கால் கொண்ட கட்டமைக்கப்பட்ட அறிவிப்பு முறை

- **செய்தி வடிவம்:**
  - பழம்பொருள் HTTP: வெறும் உரை துண்டுகள் வரிசையில்
  - MCP: கட்டமைக்கப்பட்ட LoggingMessageNotification பொருட்கள் இயற்பியலுடன்

- **கிளையண்ட் நடைமுறை:**
  - பழம்பொருள் HTTP: எளிய கிளையண்ட் ஸ்ட்ரீமிங் பதில்களை செயலாக்கும்
  - MCP: பலவகை செய்திகளை கையாளும் செய்தி கைையாளரை கொண்ட மேம்பட்ட கிளையண்ட்

- **முன்னேற்ற புதுப்பிப்புகள்:**
  - பழம்பொருள் HTTP: முன்னேற்றம் முக்கிய பதில் ஸ்ட்ரீம்க்குள் உள்ளடக்கம்
  - MCP: முன்னேற்றம் தனி அறிவிப்பு செய்திகளாக அனுப்பப்படும், முக்கிய பதில் முடிவில் வரும்

### பரிந்துரைகள்

பழமைவாய்ந்த ஸ்ட்ரீமிங்கை செயல்படுத்த (மேலே `/stream` பயன்படுத்தி காட்டிய மாதிரி) அல்லது MCP மூலம் ஸ்ட்ரீமிங்கை தேர்வு செய்வதில் சில பரிந்துரைகள் உள்ளன.

- **எளிய ஸ்ட்ரீமிங் தேவைகளுக்கு:** பழமைவாய்ந்த HTTP ஸ்ட்ரீமிங் செய்ய எளிது மற்றும் அடிப்படையாள தேவைகளுக்கு போதுமானது.

- **சிக்கலான, இடையிட்டு தொடர்பு பெறும் பயன்பாடுகளுக்கு:** MCP ஸ்ட்ரீமிங் கட்டமைப்பு சிறந்தது, அதிக தகவல்களுடன் அறிவிப்புகளையும் இறுதி முடிவுகளையும் பிரிக்கும்.

- **AI பயன்பாடுகளுக்கு:** MCP அறிவிப்பு முறை நீண்ட கால AI பணிகள் முன்னேற்றத்தை பயன்படுத்தி பயனர்களுக்கு தெரிவிக்க உதவும்.

## MCP இல் ஸ்ட்ரீமிங்

சரி, இதுவரை நீங்கள் பழமைவாய்ந்த ஸ்ட்ரீமிங் மற்றும் MCP ஸ்ட்ரீமிங்கில் உள்ள பரிந்துரைகள் மற்றும் ஒப்புமைகளை பார்த்துவிட்டீர்கள். இப்போது MCP இல் ஸ்ட்ரீமிங்கை முழுமையாக எவ்வாறு பயன்படுத்தலாம் என்பதை விரிவாக பார்க்கலாம்.

MCP கட்டமைப்பில் ஸ்ட்ரீமிங் எப்படி செயல்படுகிறது என்பதைப் புரிந்துகொள்வது முக்கியம், இது நீண்ட நேரம் தொழில்பணி செய்யும் போது பயனர்களுக்கு நேரடி பின்னூட்டத்தை வழங்க செய்கிறது.

MCP இல், முக்கிய பதிலை துண்டுகளாக அனுப்புவது அல்ல, பதிலுக்கு இடையில் ஒரு கருவி கோரிக்கையை செயலாக்கும்போது, கிளையண்டுக்கு **அறிவிப்புகளை** அனுப்புவதாகும். இந்த அறிவிப்புகள் முன்னேற்ற புதுப்பிப்புகள், பதிவுகள் அல்லது பிற நிகழ்வுகளை கொண்டிருக்க முடியும்.

### எப்படி வேலை செய்கிறது

முக்கிய முடிவு இன்னும் ஒரு ஒற்றைய பதிலாக அனுப்பப்படுகிறது. இருப்பினும், அறிவிப்புக்கள் செயலாக்கத்தின் போது தனித் தகுதீன செய்திகள் ஆக அனுப்பப்பட்டு, நேரடி புதுப்பிப்புகளை கிளையண்டுக்கு வழங்குகின்றன. கிளையண்ட் இந்த அறிவிப்புகளை கையாள்ந்து காட்ட இயல்வது அவசியம்.

## அறிவிப்புகள் என்றால் என்ன?

நாம் "அறிவிப்பு" என்று கூறினோம், MCP தொடர்பாக அதற்குப் பொருள் என்ன?

ஒரு அறிவிப்பு என்பது நீண்டநேரமாக இயங்கும் பணியிணைக்குப் போது முன்னேற்றம், நிலை, அல்லது பிற நிகழ்வுகள் குறித்து சர்வர் கிளையண்டிற்கு அனுப்பும் ஒரு செய்தி ஆகும். அறிவிப்புகள் தெளிவுத்தன்மை மற்றும் பயனர் அனுபவத்தை மேம்படுத்துகின்றன.

உதாரணமாக, பரிசீலனைக் கைமோதல் சர்வருடன் முடிந்தவுடன் ஒரு அறிவிப்பு கிளையண்ட் அனுப்பப்பட வேண்டும்.

அறிவிப்பு இவ்வாறு JSON செய்தியாக இருக்கும்:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

அறிவிப்புகள் MCP இல் ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) எனப்படும் தலைப்பிற்கு சொந்தமாகும்.

பதிவை செயல்படுத்த சர்வர் இதை பின்வரும் போல் ஒரு அம்சமாக இயங்கவைக்க வேண்டும்:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> SDK பயன்படுத்துவதற்கேற்ப பதிவுகள் இயல்புநிலைக்கு இயங்கக்கூடும் அல்லது உங்கள் சர்வர் ஒழுங்கமைப்பில் சிறப்பாக இயங்கச் செய்ய வேண்டும்.

பல வகையான அறிவிப்புகள் உள்ளன:

| நிலை       | விளக்கம்                      | உதாரண பயன்பாடு                |
|------------|-------------------------------|-------------------------------|
| debug      | விரிவான டிபக்கிங் தகவல்கள்   | செயல்பாட்டின் நுழைவு/வெளியேறு புள்ளிகள் |
| info       | பொது தகவல் செய்திகள்          | செயல்முறை முன்னேற்றம்          |
| notice     | சாதாரண ஆனால் முக்கிய நிகழ்வுகள் | கட்டமைப்பு மாற்றங்கள்          |
| warning    | எச்சரிக்கை நிலைகள்           | பழைய அம்ச பாவனை             |
| error      | பிழை நிலைகள்                | செயல்முறை தோல்விகள்           |
| critical   | முக்கிய நிலைகள்             | சிஸ்டம் கூறுகளின் தோல்விகள்   |
| alert      | உடனடி நடவடிக்கை எடுக்க வேண்டும் | தரவு ஊடறிவு கண்டுபிடிக்கப்பட்டது  |
| emergency  | சிஸ்டம் இயங்க முடியாத நிலை | முழுமையான சிஸ்டம் தோற்று     |

## MCP இல் அறிவிப்புகளை செயல்படுத்துதல்

MCP இல் அறிவிப்புகளை செயல்படுத்த, சர்வர் மற்றும் கிளையண்ட் இரு அணிகளையும் நேரடி புதுப்பிப்புகளை கையாளும் விதமாக அமைக்க வேண்டும். இது, நீண்டநேர செயல்களில் பயனருக்கு உடனடி பின்னூட்டம் கொடுக்க உதவும்.

### சர்வர் பக்கத்தில்: அறிவிப்பு அனுப்புதல்

சர்வர் பக்கத்தில் தொடங்குவோம். MCP இல், கோரிக்கைகள் செயலாக்கப்படுகையில் அறிவிப்புகளை அனுப்பக்கூடிய கருவிகளை நீங்கள் வரையறுக்கலாம். சர்வர் எனும் context பொருளை (பொதுவாக `ctx`) பயன்படுத்தி கிளையண்டுக்கு செய்திகளை அனுப்புகிறது.

#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

மேல் உள்ள உதாரணத்தில், `process_files` கருவி ஒவ்வொரு கோப்பையும் செயலாக்கும் போது மூன்று அறிவிப்புகளை கிளையண்டுக்கு அனுப்புகிறது. `ctx.info()` முறை தகவல் செய்திகள் அனுப்ப பயன்படுத்தப்படுகிறது.

மேலும், அறிவிப்புகளை இயங்க செய்ய, சர்வர் ஸ்ட்ரீமிங் டிரான்ஸ்போர்ட் (உதாரணமாக `streamable-http`) பயன்படுத்த வேண்டும் மற்றும் உங்கள் கிளையண்ட் அறிவிப்புகளை கையாள ஒரு செய்தி கைையாளரை செயல்படுத்த வேண்டும். சர்வரை `streamable-http` டிரான்ஸ்போர்ட் ஆக அமைக்கும் விதம் இதோ:

```python
mcp.run(transport="streamable-http")
```

#### .NET

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

இந்த .NET உதாரணத்தில், `ProcessFiles` கருவி `[Tool]` கதிகாரம் உடன் அலங்கரிக்கப்பட்டு, ஒவ்வொரு கோப்பையும் செயலாக்கும்போது கிளையண்டுக்கு மூன்று அறிவிப்புகளை அனுப்புகிறது. `ctx.Info()` முறை தகவல் செய்திகள் அனுப்ப பயன்படுத்தப்படுகிறது.

.NET MCP சர்வரில் அறிவிப்புகளை இயங்க செய்ய, ஸ்ட்ரீமிங் டிரான்ஸ்போர்ட் பயன்படுத்துகிறீர்கள் என்பதை உறுதி செய்யுங்கள்:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### கிளையண்ட் பக்கத்தில்: அறிவிப்புகள் பெறுதல்

கிளையண்ட் அறிவிப்புகளை பெறவும், காட்டவும் ஒரு செய்தி கைையாளரை செயல்படுத்த வேண்டும்.

#### Python

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

மேலே உள்ள குறியீட்டில், `message_handler` செய்பாடு வரும் செய்தி அறிவிப்பா என்பதை பரிசோதனை செய்கிறது. அறிவிப்பானால் அதை அச்சிடுகிறது; இல்லையேல் வழக்கமான சர்வர் செய்தியாக செயல்படுத்துகிறது. மேலும் `ClientSession` ஆரம்பிக்கும்போது `message_handler` அங்கீகரிக்கப்பட்டுள்ளது.

#### .NET

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

இந்த .NET உதாரணத்தில், `MessageHandler` செய்பாடு வரும் செய்தி அறிவிப்பா என்று சரிபார்க்கிறது. இருப்பின் அச்சிடுகிறது; இல்லையெனில் வழக்கமான சர்வர் செய்தியாக செயலாக்குகிறது. `ClientSession` `ClientSessionOptions` மூலமாக செய்தி கைையாளரை ஈட்டுகிறது.

அறிவிப்புகளை இயங்க செய்ய, சர்வர் ஸ்ட்ரீமிங் டிரான்ஸ்போர்ட் (உதாரணமாக `streamable-http`) பயன்படுத்து, கிளையண்ட் அறிவிப்புகளை கையாளும் செய்தி கைையாளரை செயல்படுத்து.

## முன்னேற்ற அறிவிப்புகள் மற்றும் சூழல்கள்

இந்த பகுதி MCP இல் முன்னேற்ற அறிவிப்புகளின் கருத்தை விளக்குகிறது, அவை ஏன் முக்கியம் என்பதும் ஸ்ட்ரீமபிள் HTTP பயன்படுத்தி அவற்றை எப்படி செயல்படுத்துவது என்பதையும் விவரிக்கிறது. மேலும் உங்கள் புரிதலை வலுப்படுத்த ஒரு பயிற்சி பணிக்கும் உள்ளது.

முன்னேற்ற அறிவிப்புகள் நீண்டநேர செயல்களில் சர்வரிலிருந்து கிளையண்டுக்கு நேரடி செய்திகளாக அனுப்பப்படும். முழு செயல்முறை முடியும் வரை காத்திருக்காமல், சர்வர் தற்போதைய நிலையை கிளையண்டுக்கு தெரிவிக்கிறது. இது தெளிவுத்தன்மை, பயனர் அனுபவம் மற்றும் பிழைத் திருத்தத்தை எளிதாக்குகிறது.

**உதாரணம்:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### ஏன் முன்னேற்ற அறிவிப்புகளை பயன்படுத்த வேண்டும்?

அவை என்றபோது சில காரணிகள் உள்ளன:

- **நன்றான பயனர் அனுபவம்:** வேலை முன்னெடுக்கப்படுகின்ற போது பயனர் புதுப்பிப்புகளை காண முடியும், முடிவில் மட்டும் அல்ல.
- **நேரடி பின்னூட்டம்:** கிளையண்ட் முன்னேற்ற பட்டைகள் அல்லது பதிவுகளை காட்ட முடியும், பயன்பாடு பதிலளிக்கும் போல உணரப்படுகின்றது.
- **எளிதான பிழைத் தீRésuméற்று மற்றும் கண்காணிப்பு:** உருவாக்குநர்கள் மற்றும் பயனர்கள் செயல்முறை எங்கு மந்தமாக உள்ளது அல்லது பிடித்துள்ளது என்று காண முடியும்.

### முன்னேற்ற அறிவிப்புகளை எப்படி செயல்படுத்துவது

MCP இல் முன்னேற்ற அறிவிப்புகளை இதுபோல் செயல்படுத்தலாம்:

- **சர்வர் பக்கம்:** ஒவ்வொரு பொருளும் செயலாக்கும்போது `ctx.info()` அல்லது `ctx.log()` பயன்படுத்தி அறிவிப்புகளை அனுப்பு. இது முக்கிய முடிவு தயார் ஆகுவதற்கு முன் கிளையண்டுக்கு செய்தி அனுப்பும்.
- **கிளையண்ட் பக்கம்:** வரும் அறிவிப்புகளை கேட்டுக் கொண்டு காட்டும் ஒரு செய்தி கைையாளரை செயல்படுத்து. இந்த கைையாளர் அறிவிப்புகளையும் இறுதி முடிவையும் வேறு வேறுபடுத்தும்.

**சர்வர் உதாரணம்:**

#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

**கிளையண்ட் உதாரணம்:**

#### Python

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)
```

## பாதுகாப்பு கருதுகோள்கள்

HTTP அடிப்படையிலான டிரான்ஸ்போர்ட்களுடன் MCP சர்வரை செயல்படுத்தும் போது, பல்வேறு தாக்குதல் நோக்குகள் மற்றும் பாதுகாப்புக் கருதுகோள்களை கவனிக்க வேண்டும் என்பதில் பாதுகாப்பு மிகவும் முக்கியமானது.

### மேலோட்ட பார்வை

MCP சர்வர்களை HTTP இல் வெளிப்படுத்தும் போது பாதுகாப்பு மிக முக்கியமானது. ஸ்ட்ரீமபிள் HTTP புதிய தாக்குதலுக்கு வாய்படுத்தும் பகுதியை கொண்டுவருகிறது மேலும் இவற்றை கவனமாக உள்ளமைவு செய்ய வேண்டும்.

### முக்கிய அம்சங்கள்
- **தயாரிப்பு தலைப்பு சரிபார்த்தல்**: DNS மறுவிணைப்பு தாக்குதல்களை தடுப்பதற்காக `Origin` தலைப்பை எப்போதும் சரிபார்க்கவும்.
- **உள்ளூர் இணைப்பை கட்டுப்படுத்தல்**: உள்ளூர் மேம்பாட்டிற்காக, சர்வர்களை பப்ளிக் இணையத்துடன் பகிராமல் `localhost` க்கு இணைக்கவும்.
- **ஆதரவு**: தயாரிப்பு வெளியீடுகளுக்காக ஆதரவு (உதாரணமாக, API விசைகள், OAuth) செயல்படுத்து.
- **CORS**: அணுகலை கட்டுப்படுத்த குறுக்கு-தயாரிப்பு பகிர்வு (CORS) கொள்கைகளை அமைக்கவும்.
- **HTTPS**: பயன்பாட்டில் ட்ராஃபிக் குறியாக்கத்திற்காக HTTPS பயன்படுத்தவும்.

### சிறந்த நடைமுறைகள்

- மாற்றுத்திறனின்றி வரும் கோரிக்கைகளை ஒருபோதும் நம்ப வேண்டாம்.
- அனைத்து அணுகலும் பிழைகளும் பதிவு செய்து கண்காணிக்கவும்.
- பாதுகாப்பு பாதிப்புகளை மூடும் வகையில் வினியோகக் கோப்புகளை (dependencies) முறையான கால இடைவெளிகளில் புதுப்பிக்கவும்.

### சவால்கள்

- பாதுகாப்பையும், மேம்பாட்டின் எளிமையையும் சமமாக கவனித்தல்
- பல்வேறு கிளையண்ட் சூழல்களில் இணக்கத்தன்மையை உறுதி செய்தல்

## SSE இருந்து Streamable HTTP க்கு மேம்படுத்தல்

தற்போது Server-Sent Events (SSE) பயன்படுத்தும் செயலிகள், Streamable HTTP க்கு மாறுவது மிக உயர்ந்த செயல்திறன் மற்றும் நீண்ட காலத்துக்கான MCP செயலாக்கத்திற்கான மேம்பாடுகளை வழங்குகிறது.

### ஏன் மேம்படுத்து?

SSE இருந்து Streamable HTTP க்கு மாற்றுவதற்கு இரண்டு முக்கிய காரணங்கள் உள்ளன:

- Streamable HTTP சிறந்த பரிமாணத்தன்மை, இணக்கத்தன்மை மற்றும் செம்மைப்படுத்தப்பட்ட அறிவிப்புகளுக்கான ஆதரவை SSE விட தருகிறது.
- இது புதிய MCP செயலிகளுக்கான பரிந்துரைக்கப்பட்ட பரிமாற்ற முறையாகும்.

### மாறுதல் படிகள்

உங்கள் MCP செயலிகளில் SSE இருந்து Streamable HTTP க்கு எப்படி மாறுவது:

- **சர்வர் குறியீட்டை** `mcp.run()` இல் `transport="streamable-http"` ஆகப் புதுப்பியுங்கள்.
- **கிளையண்ட் குறியீட்டை** SSE கிளையண்டின் பதிலாக `streamablehttp_client` பயன்படுத்துமாறு மாற்றுங்கள்.
- **அறிவிப்புகளை செயலாக்கும்** செய்தி நுண்ணறிவு நிரலானியை கிளையண்டில் உருவாக்குங்கள்.
- **இணக்கத்தன்மைக்காக** இருக்கக்கூடிய கருவிகள் மற்றும் பணியிட முயற்சிகள் மூலம் சோதனை நடுத்துங்கள்.

### இணக்கத்தன்மை பராமரிப்பு

மாறும்வழியில் நடப்பது போது உள்ள SSE கிளையண்டுகளுடன் இணக்கத்தன்மையை பராமரிப்பது பரிந்துரைக்கப்படுகிறது. சில செயல்முறைகள்:

- வெவ்வேறு முடிவுகளில் SSE மற்றும் Streamable HTTP இரண்டையும் ஓட்டி ஆதரிக்க முடியும்.
- கிளையண்டுகளை புதிய பரிமாற்றத்துக்குக் கட்டுத்தளமாக மாற்ற ஆரம்பியுங்கள்.

### சவால்கள்

மாறுதலில் பின்வரும் சவால்களை சமாளிக்க வேண்டும்:

- அனைத்து கிளையண்டுகளும் புதுப்பிக்கப்பட்டுள்ளன என்பதை உறுதி செய்தல்
- அறிவிப்பு விநியோக விதியில் வேறுபாடுகளை கையாளுதல்

## பாதுகாப்பு கருத்துக்கள்

எந்த சர்வர் சார்ந்த செயலிலும் பாதுகாப்பு மிக முக்கியமானது, குறிப்பாக MCP இல் Streamable HTTP போன்ற HTTP அடிப்படையிலான பரிமாற்றங்களை பயன்படுத்தும் போது. 

MCP சர்வர்களை HTTP மூலம் செயல்படுத்தும் போது பல்வேறு தாக்குதல்களும் பாதுகாப்பு நடைமுறைகளும் கவனிக்கப்பட வேண்டும்.

### மேற்கோள்

MCP சர்வர்களை HTTP மூலம் வெளிப்படுத்தும் போது பாதுகாப்பு பிரதான அம்சமாகிறது. Streamable HTTP புதிய தாக்குதல்தளங்களை அறிமுகப்படுத்துகிறது மற்றும் அதற்கான கவனமாக உள்ளமைவுகள் தேவைப்படும்.

பின்வரும் முக்கிய பாதுகாப்பு கருத்துக்களை நினைவில் வை:

- **தயாரிப்பு தலைப்பு சரிபார்த்தல்**: DNS மறுவிணைப்பு தாக்குதல்களை தடுப்பதற்காக `Origin` தலைப்பை படிப்படியாக சரிபார்க்கவும்.
- **உள்ளூர் இணைப்பை கட்டுப்படுத்தல்**: உள்ளூர் மேம்பாட்டிற்கு சர்வரை `localhost` இல் கட்டுப்படுத்து.
- **ஆதரவு**: தயாரிப்பில் API விசைகள், OAuth போன்ற ஆதரவை செயல்படுத்தவும்.
- **CORS**: குறுக்கு-தயாரிப்பு பகிர்வு கொள்கைகளை நிர்வகித்து அணுகலை கட்டுப்படுத்தவும்.
- **HTTPS**: டிராஃபிக் குறியாக்கத்திற்காக HTTPS பயன்படுத்தவும்.

### சிறந்த நடைமுறைகள்

நீங்கள் MCP ஸ்ட்ரீமிங் சர்வரை உருவாக்கும்போது பின்வரும் சிறந்த நடைமுறைகளைப் பின்பற்றவும்:

- வந்த கோரிக்கைகள் சரிபார்த்தல் இல்லாமல் ஒருபோதும் நம்பாதீர்கள்.
- அனைத்து அணுகல் மற்றும் பிழைகளை பதிவு செய்து கண்காணிக்கவும்.
- பாதுகாப்பு பாதிப்புகளைத் தடுக்கும் வகையில் வினியோகக்கோப்புகளை மாவட்டமாக புதுப்பிக்கவும்.

### சவால்கள்

MCP ஸ்ட்ரீமிங் சர்வர்களில் பாதுகாப்பை நடைமுறைப்படுத்தும் போது சந்திக்கும் சவால்கள்:

- பாதுகாப்பையும் மேம்பாட்டின் எளிமையையும் சமநிலை செய்தல்
- பலவிதமான கிளையண்ட் சூழல்களின் இணக்கத்தன்மையை உறுதி செய்தல்

### பணிபுரிதல்: உங்கள் சொந்த ஸ்ட்ரீமிங் MCP செயலியை உருவாக்கவும்

**நிலையைச் சொல்லுங்கள்:**
ஒரு MCP சர்வர் மற்றும் கிளையண்ட் உருவாக்கவும், இதில் சர்வர் ஒரு பொருட்களின் பட்டியலை (உதா. கோப்புகள் அல்லது ஆவணங்கள்) செயலாக்கி, ஒவ்வொரு செயலாக்கப்பட்ட பொருளுக்கும் அறிவிப்பை அனுப்பும். கிளையண்ட் அவ்வப்போது வரும் அறிவிப்புகளை காட்சிப்படுத்த வேண்டும்.

**படிகள்:**

1. ஒரு சர்வர் கருவியை உருவாக்கி, பட்டியலை செயலாக்கி, ஒவ்வொரு உருப்படியுக்கும் அறிவிப்புகளை அனுப்பவும்.
2. ஒரு கிளையண்டை உருவாக்கி, பிற செய்திகளைக் காட்சிப்படுத்தும் செய்தி செயலி உடன் இணைக்கவும்.
3. சர்வரும் கிளையண்டும் இயக்கி உங்கள் செயலியை சோதித்து, அறிவிப்புகளை கவனிக்கவும்.
