# மாடல் கருத்து தனிமுறை (MCP) உடன் HTTPS ஒருங்கோலறுத்தல்

இந்த அத்தியாயம் HTTPS பயன்படுத்தி மாடல் கருத்து தனிமுறை (MCP) மூலம் பாதுகாப்பான, பரிமாணக்கூடிய மற்றும் நேரடி ஒருங்கோலறுத்தலை நடாத்துவதற்கான விரிவான வழிகாட்டியை வழங்குகிறது. அது ஒருங்கோலறுத்தலுக்கான உற்சாகம், கிடைக்கும் பரிமாற்ற முறைகள், MCPத்தில் ஒருங்கோலறுத்தக்க HTTP இயல்பு, பாதுகாப்பு சிறந்த நடைமுறைகள், SSE இலிருந்து மாற்றம் மற்றும் உங்களது சொந்த ஒருங்கோலறுத்த MCP பயன்பாடுகளை உருவாக்குவதற்கான நடைமுறை வழிகாட்டலை நுட்பமாக உள்ளடக்கியுள்ளது.

> **எதிர்காலத்தை நோக்கி:** இந்த பாடம் **MCP விவரக்குறிப்பு 2025-11-25** இன் கீழ் ஒருங்கோலறுத்தக் கூடிய HTTP ஐ விவரிக்கிறது, இங்கு ஒரு அமர்வு `initialize` ஆல் ஏற்படுத்தப்பட்டு `Mcp-Session-Id` தலைப்புடன் பிணைக்கப்படுகிறது. `2026-07-28` வெளியீட்டு வேட்பாளர் கையொப்பம் மற்றும் அமர்வு ஐடியை முற்றிலும் நீக்கி, ஒவ்வொரு கோரிக்கையும் சுயமாகவும் எந்த சர்வர் உதாரணத்திற்கும் வழிமாறக்கூடியதாகவும் மாற்றுகிறது, ஒட்டும் அமர்வுகள் இல்லாமல். விவரங்களுக்கு [MCP இல் மாற்றங்கள்: 2026-07-28 வெளியீட்டு வேட்பாளர்](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ஐ காணவும்.

## MCP இல் பரிமாற்ற முறைகள் மற்றும் ஒருங்கோலறுத்தல்

இந்த பகுதியில் MCP இல் கிடைக்கும் வெவ்வேறு பரிமாற்ற முறைகள் மற்றும் வாங்கி-சர்வர் இடையிலான நேரடியான தொடர்புக்கான ஒருங்கோலறுத்தல் திறனை எவ்வாறு செயல்படுத்துகின்றன என்பதைக் காணலாம்.

### பரிமாற்ற முறை என்றால் என்ன?

ஒரு பரிமாற்ற முறை என்பது வாங்கியாளரும் சர்வரும் எப்படி தரவுகளை பரிமாறుకుంటார்கள் என்பதை வரையறுக்கிறது. MCP வெவ்வேறு சூழல்களில் மற்றும் தேவைகளுக்கு ஏற்ப பல பரிமாற்ற வகைகளை ஆதரிக்கிறது:

- **stdio**: நிலையான உள்ளீடு/வெளியீடு, உள்ளூர் மற்றும் கட்டளை வரி கருவிகளுக்குப் பொருத்தமானது. எளிமையாகவும், வலை அல்லது கிளவுட் பயன்பாடுகளுக்கு பொருத்தமற்றது.
- **SSE (சர்வர் அனுப்பும் நிகழ்வுகள்)**: சர்வர்கள் HTTP வழியாக நேரடியான புதுப்பிப்புகளை வாங்குநர்களுக்கு அனுப்ப அனுமதிக்கிறது. வலை UI களுக்கு நல்லது, ஆனால் பரிமாணம் மற்றும் திடத்தன்மையில் கட்டுப்பாடு உள்ளது. MCP விவரக்குறிப்பு 2025-06-18 முதல் தனித்த SSE (சர்வர் அனுப்பும் நிகழ்வுகள்) பரிமாற்றம் தவறுபடுத்தப்பட்டு "ஒருங்கோலறுத்த HTTP" பரிமாற்றத்தால் மாற்றப்பட்டுள்ளது.
- **ஒருங்கோலறுத்த HTTP**: நவீன HTTP அடிப்படையிலான ஒருங்கோலறுத்த பரிமாற்றம் ஆகும், அறிவிப்புகள் மற்றும் சிறந்த பரிமாணத்தைக் ஆதரிக்கிறது. பெரும்பாலான தயாரிப்பு மற்றும் கிளவுட் சூழலுக்கு பரிந்துரைக்கப்படுகிறது.

### ஒப்பீட்டு அட்டவணை

இந்த பரிமாற்ற முறைகளின் மாறுபாடுகளை புரிந்து கொள்வதற்காக கீழ்காணும் அட்டவணையை பாருங்கள்:

| பரிமாற்றம்          | நேரடி புதுப்பிப்புகள்  | ஒருங்கோலறுத்தல் | பரிமாணம்    | பயன்பாட்டு வழக்கு          |
|---------------------|---------------------|-----------------|-------------|----------------------------|
| stdio               | இல்லை               | இல்லை          | குறைந்தது  | உள்ளூர் CLI கருவிகள்      |
| SSE                 | ஆம்                 | ஆம்             | நடுத்தரம்  | வலை, நேரடி புதுப்பிப்புகள்  |
| ஒருங்கோலறுத்த HTTP | ஆம்                 | ஆம்             | அதிகம்     | கிளவுட், பல-வாங்குநர்      |

> **கருத்து:** சரியான பரிமாற்றம் தேர்வு செய்வது செயல்திறன், பரிமாணம் மற்றும் பயனர் அனுபவத்தை பாதிக்கும். **ஒருங்கோலறுத்த HTTP** நவீன, பரிமாணக்கூடிய மற்றும் கிளவுட்-தயாரான பயன்பாடுகளுக்கு பரிந்துரைக்கப்படுகிறது.

முந்தைய அத்தியாயங்களில் காட்டப்பட்ட stdio மற்றும் SSE பரிமாற்றங்களை கவனியுங்கள் மற்றும் இந்த அத்தியாயத்தில் கவனம் செலுத்தப்படும் ஒருங்கோலறுத்த HTTP பரிமாற்றத்தை அறியுங்கள்.

## ஒருங்கோலறுத்தல்: கருத்துகள் மற்றும் உற்சாகம்

ஒருங்கோலறுத்தலின் அடிப்படைக் கருத்துக்களையும் காரணிகளையும் புரிந்து கொள்வது நேரடி தொடர்பு அமைப்புகளை திறமையாக செயல்படுத்த முக்கியம்.

**ஒருங்கோலறுத்தல்** என்பது நெட்வொர்க் நிரலாக்கத்தில் மெனக்கெடாமல் தயவுசெய்து விரைவான தொடர்புக்கு ஒரு முறையாகும், இது முழு பதிலை காத்திருக்காமல் சிறிய துண்டுகளாக அல்லது நிகழ்வுகளின் தொடராய் தரவை அனுப்பவும் பெறவும் அனுமதிக்கிறது. இது குறிப்பாக பயன்படும்:

- பெரிய கோப்புகள் அல்லது தரவுத்தொகுதிகள்.
- நேரடி புதுப்பிப்புகள் (உதா., உரையாடல், முன்னேற்ற பட்டிகள்).
- நீண்டகால கணக்கீடுகள், பயனரை தகவல் வழங்க விரும்பும் போது.

இதோ ஒருங்கோலறுத்தல் குறித்து முக்கியமாக தெரிந்துகொள்ள வேண்டியவை:

- தரவு படிப்படியாக வழங்கப்படுகிறது, ஒரே நேரத்தில் அல்ல.
- வாங்கியாளர் வரும் தரவினை உடனடியாக செயலாக்க முடியும்.
- உணர்வுக்குரிய தாமதத்தை குறைக்கும் மற்றும் பயனர் அனுபவத்தை மேம்படுத்தும்.

### ஏன் ஒருங்கோலறுத்தல் பயன்படுத்த வேண்டும்?

ஒருங்கோலறுத்தலை பயன்படுத்த காரணங்கள் இவை:

- பயனர்கள் உடனடியாக பின்னூட்டத்தை பெறுவர், முடிவில் மட்டுமல்ல
- நேரடி செயலிகள் மற்றும் பதிலளிக்கும் UI களை இயற்கை ஆக்குகிறது
- நெட்வொர்க் மற்றும் கணக்கிடும் வளங்கள் சிறப்பாக பயன்படுகிறது

### எளிய எடுத்துக்காட்டு: HTTP ஒருங்கோலறுத்தல் சர்வர் மற்றும் வாங்கியாளர்

ஒருங்கோலறுத்தலை எவ்வாறு அமல்படுத்தலாம் என்பதற்கான எளிய எடுத்துக்காட்டு இதோ:

#### பைதான்

**சர்வர் (Python, FastAPI மற்றும் StreamingResponse பயன்படுத்தி):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**வாங்கியாளர் (Python, requests பயன்படுத்தி):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

இந்த எடுத்துக்காட்டு சர்வர் தயாராக இருக்கும் ஒவ்வொரு செய்திகள் தொடரை வாங்கியாளருக்கு அனுப்புகிறது, குழுமமான அனைத்து செய்திகள் தயாராக காத்திருக்கவில்லை.

**எப்படி இயங்குகிறது:**

- சர்வர் ஒவ்வொரு செய்தியையும் தயாராக விரும்பி தருகிறது.
- வாங்கியாளர் வரும் ஒவ்வொரு துண்டையும் பெற்றுக்கொண்டு அச்சிடுகிறது.

**தேவைகள்:**

- சர்வர் ஒருங்கோலறுத்த பதிலை பயன்படுத்த வேண்டும் (உதா., FastAPI இல் `StreamingResponse`).
- வாங்கியாளர் பதிலை ஒருங்கோலறுத்தலாக செயலாக்க வேண்டும் (`stream=True` requests இல்).
- உள்ளடக்க வகை பொதுவாக `text/event-stream` அல்லது `application/octet-stream` ஆகும்.

#### ஜாவா

**சர்வர் (Java, Spring Boot மற்றும் Server-Sent Events பயன்படுத்தி):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**வாங்கியாளர் (Java, Spring WebFlux WebClient பயன்படுத்தி):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**Java அமலாக்க குறிப்பு:**

- `Flux` உடன் Spring Boot இன் எதிரொலி தளம் ஒருங்கோலறுத்தலை நடத்துகிறது
- `ServerSentEvent` பண்பேற்றிய நிகழ்வு வகைகளுடன் கட்டமைக்கப்பட்ட நிகழ்வு ஒருங்கோலறுத்தலை வழங்குகிறது
- `WebClient` இன் `bodyToFlux()` எதிரொலி ஒருங்கோலறுத்த பயன்பாட்டை சாதிக்கிறது
- `delayElements()` நிகழவுகளுக்கு இடையில் செயலாக்க நேரத்தை பிம்மிதுகிறது
- `info`, `result` போன்ற வகைகள் வாடிக்கையாளர் சுட்டிக்காட்டல் மேம்பாட்டிற்கு இருக்கலாம்

### ஒப்பீடு: தொலைபேசி ஒருங்கோலறுத்தல் vs MCP ஒருங்கோலறுத்தல்

"பாரம்பரிய" முறையால் ஒருங்கோலறுத்தல் மற்றும் MCP இல் ஒருங்கோலறுத்தல் செயல்படுவது என்னவென்பதை கீழே காணலாம்:

| அம்சம்                   | பாரம்பரிய HTTP ஒருங்கோலறுத்தல்   | MCP ஒருங்கோலறுத்தல் (அறிவிப்புகள்)  |
|--------------------------|---------------------------------|---------------------------------------|
| பிரதான பதில்            | துண்டுகளாக                     | ஒரே நேரத்தில், முடிவில்                 |
| முன்னேற்ற புதுப்பிப்புகள் | தரவு துண்டுகளாக அனுப்பு          | அறிவிப்புகளாக அனுப்பு                  |
| வாங்கியாளர் தேவைகள்     | ஒருங்கோலத்தை செயலாக்க வேண்டியது | செய்திகள் ஹேண்ட்லர் அமுல்படுத்தும்        |
| பயன்பாடு               | பெரிய கோப்புகள், AI டோகன் ஸ்ட்ரீம்கள் | முன்னேற்றங்கள், பதிவுகள், நேரடி பின்னூட்டம்  |

### முக்கியமான வேறுபாடுகள்

கூடுதலாக, சில முக்கியமான வேறுபாடுகள்:

- **தொடர்பு முறை:**
  - பாரம்பரிய HTTP ஒருங்கோலறுத்தல்: எளிய துண்டுபிரிந்த பரிமாற்ற காவல் பயன்படுத்துகிறது
  - MCP ஒருங்கோலறுத்தல்: JSON-RPC நெறிமுறையுடன் கட்டமைக்கப்பட்ட அறிவிப்பு அமைப்பை பயன்படுத்துகிறது

- **செய்தி வடிவம்:**
  - பாரம்பரிய HTTP: புதிய வரிகளுடன் சாதாரண உரை துண்டுகள்
  - MCP: கட்டமைக்கப்பட்ட LoggingMessageNotification பொருட்கள் மற்றும் மெட்டாடேட்டா

- **வாங்கியாளர் அமலாக்கம்:**
  - பாரம்பரிய HTTP: ஒருங்கோல பதில்களை செயலாக்கக்கூடிய எளிய வாங்கியாளர்
  - MCP: பல்வேறு வகையான செய்திகள் செயலாக்க ஹேண்ட்லர் கொண்ட நுணுக்கமான வாங்கியாளர்

- **முன்னேற்ற புதுப்பிப்புகள்:**
  - பாரம்பரிய HTTP: முன்னேற்றம் பிரதான பதிலின் ஒரு பகுதியாகும்
  - MCP: முன்னேற்றம் தனித்தனியான அறிவிப்பு செய்திகளாக அனுப்பப்படும், பிரதான பதில் முடிவில் வரும்

### பரிந்துரைகள்

பாரம்பரிய ஒருங்கோலறுத்தலை (/stream என்கிற எண்ட்பாயிண்டை பயன்படுத்தி) செயல்படுத்துவது மற்றும் MCP மூலம் ஒருங்கோலறுத்தலை தேர்வு செய்வதற்கான சில பரிந்துரைகள் உள்ளன.


- **எளிய ஸ்ட்ரீமிங் தேவைகளுக்கு:** பாரம்பரிய HTTP ஸ்ட்ரீமிங் செயல்படுத்த எளிதானது மற்றும் அடிப்படை ஸ்ட்ரீமிங் தேவைகளுக்குத் தகுந்தது.

- **சிக்கலான, தொடர்பு கொண்ட செயலிகளுக்காக:** MCP ஸ்ட்ரீமிங் மேலும் அமைக்கப்பட்ட அணுகுமுறை வழங்குகிறது, அதில் முழுமையான மெட்டாடேட்டாவும் அறிவிப்புகளுக்கு மற்றும் இறுதி முடிவுகளுக்கும் பிரிப்பும் உள்ளன.

- **ஏ.ஐ செயலிகளுக்கு:** MCP இன் அறிக்கை அமைப்பு நீண்டநாள் ஏற்கனவே இயங்கும் AI பணிகளுக்கு மிகவும் பயனுள்ளதாக உள்ளது, இதில் நீங்கள் பயனர்களுக்கு முன்னேற்றத்தை தொடர்ந்து அறிய வைத்துக் கொள்ள விரும்புகிறீர்கள்.

## MCP இல் ஸ்ட்ரீமிங்

சரி, இப்போது நீங்கள் பாரம்பரிய ஸ்ட்ரீமிங் மற்றும் MCP இல் ஸ்ட்ரீமிங் இடையேயான வித்தியாசம் பற்றி சில பரிந்துரைகள் மற்றும் ஒப்பீடுகளை பார்ந்துள்ளீர்கள். இப்போது MCP இல் ஸ்ட்ரீமிங் எப்படி பயன்படுத்தலாம் என்பதைக் குறிப்பு முறையாகப் பார்ப்போம்.

MCP கட்டமைப்புக்குள்ளே ஸ்ட்ரீமிங் எப்படி செயல்படுகிறது என்பதை புரிந்துகொள்வது, நீண்டநாள் பணிகள் நடைபெறும் போது பயனர்களுக்கு நேரடி பிரதிபலிப்பு வழங்கும் பதிலளிக்கும் செயலிகளை உருவாக்குவதற்கு அவசியமாகும்.

MCP இல், ஸ்ட்ரீமிங் என்பது மிக முக்கிய முடிவை துண்டுகளாக அனுப்புவதல்ல, ஆனால் ஒரு கருவி கோரிக்கையை செயலாக்கும் போது **அறிவிப்புகளை** கிளையண்டுக்கு அனுப்புவது ஆகும். இந்த அறிவிப்புகள் முன்னேற்ற புதுப்பிப்புகள், பதிவுகள், அல்லது பிற நிகழ்வுகளை உள்ளடக்கியதாக இருக்கலாம்.

### இது எப்படி செயல்படுகிறது

முக்கிய முடிவு இன்னும் ஒரே பதிலாக அனுப்பப்படுகிறது. இருப்பினும், அறிவிப்புகள் செயலாக்கத்தின் போது தனித்தனியான செய்திகளாக அனுப்பப்படலாம், இதனால் கிளையண்டை நேரடி இப்போது புதுப்பிக்கும். கிளையண்டு இந்த அறிவிப்புகளை கையாள முடியும் மற்றும் காட்சியாக்க முடியும்.

## அறிவிப்பு என்றால் என்ன?

நாங்கள் "அறிவிப்பு" என்று கூறினோம், அது MCP மற்றும் அதன் சூழலில் என்ன பொருளுடையதாகும்?

அறிவிப்பு என்பது நீண்டநாள் இயங்கும் பணிகளின் போது முன்னேற்றம், நிலை, அல்லது பிற நிகழ்வுகள் குறித்து கிளையண்டுக்கு சேவையகத்திலிருந்து அனுப்பப்படும் செய்தி ஆகும். அறிவிப்புகள் வெளிப்படையான தன்மையையும் பயனர் அனுபவத்தையும் மேம்படுத்துகின்றன.

உதாரணமாக, கிளையண்ட் சேவையகத்துடன் ஆரம்ப ஒப்பந்தம் செய்யப்பட்டவுடன் ஒரு அறிவிப்பை அனுப்புவதாக இருக்க வேண்டும்.

ஒரு அறிவிப்பு JSON செய்தியாக கீழே காணப்படுகின்றது:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

MCP இல் அறிவிப்புகள் ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) என்ற தலைப்பிற்கு சொந்தமானவை.

> **முடிவுசெய்யும் அறிவிப்பு:** `2026-07-28` MCP குறிப்பீடு Candidate வெளிவரவு, stdio போக்குவரத்துக்கான `stderr` மற்றும் அமைவைத்தன்மை காண்பிக்க OpenTelemetry என்பதற்கான ஆதரவுடன் Logging மென்பொருள் பழையதாக அறிவிக்கப்பட்டுள்ளது. Logging `2025-11-25` வரை மற்றும் எந்தவொரு அதிகாரபூர்வ முடிவுடைய பின் குறைந்தது ஒரு வருடம் செயல்படும். [MCP இல் என்ன மாற்றப்படுகிறது: 2026-07-28 வெளியீடு Candidate](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ஐப் பாருங்கள்.

பதிவு செயல்பாட்டை இயக்க, சேவையகம் இது கீழ்காணும் போல ஒரு பண்பாக இயக்கு வேண்டும்:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> நீங்கள் பயன்படுத்தும் SDK அடிப்படையில், பதிவேற்றம் இயல்புநிலையாக இயங்கலாம் அல்லது நீங்கள் உங்கள் சேவையக विन्यासத்தில் அதை தெளிவாக இயக்கு வேண்டியிருக்கலாம்.

அறிவிப்புகளின் பல வகைகள் உள்ளன:

| நிலை       | விளக்கம்                       | எடுத்துக்காட்டு பயன்பாடு          |
|-----------|-------------------------------|---------------------------------|
| debug     | விரிவான பிழைத்திருத்தத் தகவல் | செயல்பாட்டு நுழைவு/வெளியேற்றப் புள்ளிகள்  |
| info      | பொதுவான தகவல் செய்திகள்        | செயல்முறை முன்னேற்ற சமீபிகள்    |
| notice    | சாதாரண ஆனால் முக்கிய நிகழ்வுகள் | கட்டமைப்பு மாற்றங்கள்           |
| warning   | எச்சரிக்கை நிலைகள்            | பழைய செயல்பாட்டு பயன்பாடு       |

| alert     | உடனடி நடவடிக்கை தேவை         | தரவுத் துறவி கண்டறிதல்         |
| emergency | அமைப்பு பயன்பாட்டுக்கேற்றதில்லை | முழுமையான அமைப்பு தோல்வி         |

## MCP இல் அறிவிப்புகளை செயல்படுத்துதல்

MCP இல் அறிவிப்புகளை செயல்படுத்த, நீங்கள் சேவையகம் மற்றும் கிளையண்ட் இரண்டையும் நேரடி புதுப்பிப்புகளை கையாள தயாராக அமைக்க வேண்டும். இது உங்கள் செயலியை நீண்டநாள் பணிகள் நடைபெறும் போது உடனடியான பிரதிபலிப்பை வழங்கும் வகையில் உதவும்.

### சேவையகப்பக்கம்: அறிவிப்புகளை அனுப்புதல்

சேவையகப்பக்கம் அறிவிப்புகளை அனுப்புவதோடு தொடங்குவோம். MCP இல், நீங்கள் கோரிக்கைகளை செயலாக்கும் போது அறிவிப்புகளை அனுப்பக்கூடிய கருவிகளை விவரிக்கின்றீர்கள். சேவையகம் பொருள் (முக்கியமாக `ctx`) பயன்படுத்தி கிளையண்டுக்கு செய்திகளை அனுப்புகிறது.

#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

முன் உள்ள எடுத்துக்காட்டில், `process_files` கருவி ஒவ்வொரு கோப்பும் செயலாக்கும் போது மூன்று அறிவிப்புகளை கிளையண்டுக்கு அனுப்புகிறது. `ctx.info()` முறை மூலம் தகவல் தகவல்களை அனுப்புகிறது.

மேலும, அறிவிப்புகளை இயக்க, உங்கள் சேவையகம் ஒரு ஸ்ட்ரீமிங் போக்குவரத்தை (எ.கா., `streamable-http`) பயன்படுத்த வேண்டும் மற்றும் உங்கள் கிளையண்ட் அறிவிப்புகளை செயலாக்க ஒரு செய்தி கையாளுதலை அம்சப்படுத்த வேண்டும். உங்கள் சேவையகத்தை `streamable-http` போக்குவரத்து பயன்படுத்தும் வகையில் அமைப்பது எப்படி என்பதைக் கீழே காணலாம்:

```python
mcp.run(transport="streamable-http")
```

#### .NET

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

இந்த .NET எடுத்துக்காட்டில், `ProcessFiles` கருவி `Tool` பண்புடன் அலங்கரிக்கப்பட்டது மற்றும் ஒவ்வொரு கோப்பும் செயலாக்கும் போது மூன்று அறிவிப்புகளை கிளையண்டுக்கு அனுப்புகிறது. `ctx.Info()` முறை தகவல் செய்திகள் அனுப்ப பயன்படுத்தப்படுகிறது.

உங்கள் .NET MCP சேவையில் அறிவிப்புகளை இயக்கு, ஸ்ட்ரீமிங் போக்குவரத்தைப் பயன்படுத்தி இருப்பதை உறுதி செய்யுங்கள்:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### கிளையண்ட்பக்கம்: அறிவிப்புகளை பெறுதல்

கிளையண்ட் இயமொரிக்கும் ஒரு செய்தி கையாளுதலை அம்சப்படுத்தி, வந்தவுடன் அறிவிப்புகளை செயலாக்கி காட்சியாக்க வேண்டும்.

#### Python

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

முன் காணப்பட்ட குறியீட்டில், `message_handler` செயலி வரும் செய்தி அறிவிப்பு என்றால் அதனை அச்சிடுகிறது; இல்லாவிட்டால் அதை சாதாரண சேவையக செய்தியாக செயலாக்குகிறது. மேலும் `ClientSession` அறிவிப்புகளை கையாளும் `message_handler` உடன் தொடக்கப்படுகிறது.

#### .NET

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

இந்த .NET எடுத்துக்காட்டில், `MessageHandler` செயலி வரும் செய்தி அறிவிப்பு என கூறின் அதை அச்சிடுகிறது; இல்லையெனில் சாதாரண சேவையக செய்தியாக செயலாக்குகிறது. `ClientSession` `ClientSessionOptions` மூலம் செய்தி கையாளுதலுடன் தொடக்கப்படுகிறது.

அறிவிப்புகளை இயக்க, உங்கள் சேவையகம் `streamable-http` போன்ற ஸ்ட்ரீமிங் போக்குவரத்தைப் பயன்படுத்த வேண்டும் மற்றும் உங்கள் கிளையண்ட் அறிவிப்புகளை செயலாக்க ஒரு செய்தி கையாளுதலை உருவாக்க வேண்டும்.

## முன்னேற்ற அறிவிப்புகள் மற்றும் சூழல்கள்

இந்த பகுதி MCP இல் முன்னேற்ற அறிவிப்புகளின் கருத்தை, அவை ஏன் முக்கியம் என்பதை மற்றும் அதை Streamable HTTP கொண்டு எப்படி செயல்படுத்துவது என்பதைக் குறிக்கும். உங்கள் புரிதலை வலுப்படுத்த ஒரு பயிற்சியையும் மறைமுகமாக வழங்குகிறது.

முன்னேற்ற அறிவிப்புகள் நீண்டநாள் பணிகளின் போது சேவையகம் கிளையண்டுக்கு நேரடியாக அனுப்பும் செய்திகள் ஆகும். முழு செயல்முறையும் முடிந்ததை காத்திருக்காமல், சேவையகம் தற்போதைய நிலையை பற்றி கிளையண்டை தொடர்ச்சியாக புதுப்பிக்கிறது. இது வெளிப்படையான தன்மை, பயனர் அனுபவம் மேம்பாடு மற்றும் பிழைத்திருத்தத்தை எளிமையாக்குகிறது.

**எடுத்துக்காட்டு:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### முன்னேற்ற அறிவிப்புகளை ஏன் பயன்படுத்த வேண்டும்?

முன்னேற்ற அறிவிப்புகள் பல காரணிகளுக்காக அவசியமாகின்றன:

- **மிகவும் சிறந்த பயனர் அனுபவம்:** பணிகள் முன்னேறுவதை பயனர்கள் பார்கிறார்கள், முடிவில் மட்டும் அல்ல.
- **நேரடி பிரதிபலிப்பு:** கிளையண்டுகள் முன்னேற்ற பட்டியல்கள் அல்லது பதிவுகளை காட்சியளிக்க முடியும், செயலி பதிலளிக்கும் தோற்றமாக இருக்கும்.
- **எளிதான பிழைத்திருத்தம் மற்றும் கண்காணிப்பு:** டெவலப்பர் மற்றும் பயனர்கள் எந்த பகுதி மெதுவாக உள்ளது அல்லது சிக்கலில் உள்ளது என்பதை காண முடியும்.

### முன்னேற்ற அறிவிப்புகளை செயல்படுத்துவது எப்படி

MCP இல் முன்னேற்ற அறிவிப்புகளை எப்படி செயல்படுத்துவது:

- **சேவையகத்தில்:** ஒவ்வொரு உருப்படியும் செயலாக்கப்படும் பொழுது `ctx.info()` அல்லது `ctx.log()` மூலம் அறிவிப்புகளை அனுப்புங்கள். இது முக்கிய முடிவு தயார் ஆகுவதற்கு முன்பே கிளையண்டுக்கு செய்தியை அனுப்பும்.

- **கிளையன்டில்:** அறிவுறுத்தல்கள் வந்தவுடன் அவற்றை கேட்டு மற்றும் காண்பிக்கும் செய்தி கைமாற்றியை அமல்படுத்தவும். இந்த கைமாறு அறிவுறுத்தல்கள் மற்றும் இறுதி முடிவை வேறுபடுத்துகிறது.

**சர்வர் உதாரணம்:**


#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

**வாடிக்கையாளர் எடுத்துக்காட்டு:**

## பாதுகாப்பு கவனிப்புகள்

எந்தவொரு சேவையகத்தையும் செயல்படுத்தும் போது பாதுகாப்பு மிக முக்கியமாக இருக்க வேண்டும், குறிப்பாக MCP இல் Streamable HTTP போன்ற HTTP-அடிப்படையிலான இடமாற்றங்கள் பயன்படுத்தும் போது.

HTTP-அடிப்படையிலான இடமாற்றங்களுடன் MCP சேவையகங்களை செயல்படுத்தும் போது, பல தாக்குதல் வழிகள் மற்றும் பாதுகாப்பு முறைகள் பற்றி கவனமாக இருக்க வேண்டிய அவசியமுள்ளது.

### கண்ணோட்டம்

MCP சேவையகங்களை HTTP மூலம் வெளிப்படுத்தும் போது பாதுகாப்பு மிகவும் அவசியம். Streamable HTTP புதிய தாக்குதல் மேடைகளை அறிமுகப்படுத்தி, கவனமாக கட்டமைக்க வேண்டும்.

இங்கு சில முக்கிய பாதுகாப்பு கவனிப்புகள் உள்ளன:

- **Origin Header Validation**: DNS மறுக்கலைத் தடுக்கும் வகையில் `Origin` தலைப்பை எப்போதும் செக்கிக்கொள்ளுங்கள்.
- **Localhost Binding**: உள்ளூர் மேம்பாட்டிற்கு சேவையகங்களை `localhost`-க்கு மட்டுப்படுத்தி பொதிய இணையத்துக்குக் காட்டு விடாதீர்கள்.
- **Authentication**: உற்பத்தி விண்ணப்பங்களுக்கு உள்நுழைவுக் கட்டுப்பாடு (உதா., API விசைகள், OAuth) அமல்படுத்து.
- **CORS**: பன்முக மூல வழங்கல் பகிர்வு கொள்கைகளை கட்டுப்படுத்து.
- **HTTPS**: உற்பத்தியில் HTTPS ஐ பயன்படுத்தி தகவல்பரிமாற்றத்தை குறியாக்கம் செய்.

### சிறந்த நடைமுறைகள்

கூடுதலாக, உங்கள் MCP ஸ்ட்ரீமிங் சேவையகத்தில் பாதுகாப்பு அமல்படுத்தும் போது பின்பற்ற வேண்டிய சில சிறந்த நடைமுறைகள் இங்கு உள்ளன:

- வரவிருக்கும் கோரிக்கைகளை நம்பாமல் உறுதிப்படுத்தல் செய்க.
- அனைத்து அணுகல்களையும் பிழைகளையும் பதிவு செய்து கண்காணிக்கவும்.
- பாதுகாப்பு சோற்றுகை திருத்தங்களுக்கு பின்பற்றும் சார்புகளை எப்போதும் புதுப்பிக்கவும்.

### சவால்கள்

MCP ஸ்ட்ரீமிங் சேவையகங்களில் பாதுகாப்பை அமல்படுத்தும் போது நீங்கள் சந்திக்கும் சில சவால்கள்:

- பாதுகாப்பையும் வளர்ச்சியையும் சமநிலையில் வைத்தல்
- பலவித வாடிக்கையாளர் சூழல்களுடன் பொருந்துதலை உறுதி செய்தல்


## SSE இலிருந்து Streamable HTTP க்கு மேம்படுத்தல்

தற்போது Server-Sent Events (SSE) பயன்படுத்தும் செயலிகளுக்காக, Streamable HTTP க்கு மாறுதல் உங்கள் MCP அமல்பாடுகளுக்கு மேம்பட்ட செயல்திறன் மற்றும் நீண்டகால நிலைத்தன்மையை வழங்குகிறது.

### ஏன் மேம்படுத்த வேண்டும்?

SSE இலிருந்து Streamable HTTP க்கு மேம்படுத்துவதற்கு இரண்டு முக்கிய காரணங்கள் உள்ளன:

- Streamable HTTP SSE-ஐவிட சிறந்த அளவு விரிவாக்கம், பொருந்துதலும், மேலும் செபலான அறிவிப்புச் சப்போர்ட்டையும் வழங்குகிறது.
- புதிய MCP செயலிகளுக்கு பரிந்துரைக்கப்பட்ட இடமாற்றமாகும்.

### மாற்றக் படிகள்

உங்கள் MCP செயலிகளில் SSE இலிருந்து Streamable HTTP க்கு எப்படி மாற்றுவது இங்கு உள்ளது:

- **சேவையக குறியீட்டை புதுப்பிக்கவும்** `mcp.run()` இல் `transport="streamable-http"` பயன்படுத்தவும்.
- **வாடிக்கையாளர் குறியீட்டை புதுப்பிக்கவும்** SSE வாடிக்கையாளர் பதிலாக `streamablehttp_client` பயன்படுத்தவும்.
- **அறிவிப்பு கையாள்பவரை** வாடிக்கையாளர் பக்கம் அமல்படுத்தவும்.
- **பொருந்துதலை சோதிக்கவும்** தற்போதைய கருவிகள் மற்றும் பணிய்நெறிகளுடன்.

### பொருந்துதலை பராமரித்தல்

மாற்று செயல்முறை காலத்தில் தற்போதைய SSE வாடிக்கையாளர்களுடன் பொருந்துதலை பராமரிப்பது பரிந்துரைக்கப்படுகிறது. கீழ்காணும் நெறிமுறைகள் உள்ளன:

- SSE மற்றும் Streamable HTTP இரண்டையும் வெவ்வேறு இடையீடுகளில் இயக்கி ஆதரிக்கலாம்.
- வாடிக்கையாளர்களை படிப்படியாக புதிய இடமாற்றத்திற்கு மாற்றவும்.

### சவால்கள்

மாற்று நேரத்தில் கீழ்கண்ட சவால்களை எதிர்கொள்ள வேண்டும்:

- அனைத்து வாடிக்கையாளர்களும் புதுப்பிக்கப்படுவதை உறுதி செய்தல்
- அறிவிப்பு விநியோகத்தில் வேறுபாடுகளை கையாளுதல்

### பணிகள்: உங்கள் சொந்த ஸ்ட்ரீமிங் MCP செயலியை உருவாக்குக

**அம்சம்:**
செர்வர் ஒரு உருப்படி வரிசையை (உதாரணமாக, கோப்புகள் அல்லது ஆவணங்கள்) செயலாக்கி ஒவ்வொரு செயலாக்கப்பட்ட உருப்படியும் அறிவிப்பு அனுப்பும் வகையில் MCP சேவையகத்தையும் வாடிக்கையாளரையும் உருவாக்குக. வாடிக்கையாளர் ஒவ்வொரு அறிவிப்பையும் வந்தவுடன் காட்சிப்படுத்த வேண்டும்.

**படிகள்:**

1. ஒரு சேவையக கருவியை உருவாக்கி, ஒரு பட்டியலை செயலாக்கி ஒவ்வொரு உருப்படியுக்கும் அறிவிப்புகளை அனுப்பவும்.
2. ஒரு வாடிக்கையாளர் உருவாக்கி, அறிவிப்புகளை நேரடியாக காட்சிப்படுத்த ஒரு செய்தி கையாள்பவரை அமல்படுத்தவும்.
3. உங்கள் செயல்பாட்டைப் பரிசோதிக்க, சேவையகத்தையும் வாடிக்கையாளரையும் இயக்கி அறிவிப்புகளை கவனியுங்கள்.
