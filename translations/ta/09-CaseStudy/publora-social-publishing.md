# வழக்கு ஆய்வு: அகழ்வாளர் மூலம் தொலைநிலை MCP சேவையகத்திலிருந்து சமூக வலைத்தளங்களில் வெளியீடு செய்வது

> **கூறுகோள்:** பல சேவைகள் மற்றும் திறந்த மூலத் திட்டங்கள் சமூக வலைத்தளங்களில் வெளியீடு செய்ய முடியும், மேலும் ஒரு குழு ஒவ்வொரு வலைத்தளங்களின் API ஐ நேரடியாக ஒருங்கிணைக்கலாம். கீழ்காணும் காட்சி, ஒரு **எழுதுவதற்கான திறன் உடைய தொலைநிலை MCP சேவையகம்** எவ்வாறு வடிவமைக்கப்பட்டு பயன்படுத்தப்படலாம் என்பதை ஒரு எடுத்துக்காட்டு வடிவில் கொடுக்கப்பட்டுள்ளது. பப்ளோரா என்பது இலவச நிலை கொண்ட வர்த்தக சேவை; இங்கேப் போடப்பட்ட மாதிரிகள் பயனாளியின் பெயரில் மாற்றமுடியாத நடவடிக்கைகளை செய்யும் எந்த MCP சேவையகத்திற்கு பொருந்தும்.

## முன்னோட்டம்

அகழ்வாளர்கள் உள்ளடக்கத்தை வடிவமைப்பதில் நல்லவர்களாக இருந்தாலும், அதை சமர்ப்பிப்பதில் வலுவற்றவர்கள். ஒரு மாதிரி секунடுகளில் ஒரு வெளியீட்டு அறிவிப்பை எழுதலாம், அதன்பிறகு வேலை நிற்கும்: வெளியிடுவதற்கு ஒவ்வொரு வலைத்தளத்துக்கும் API ஒன்று, OAuth பயன்பாடு ஒன்று மற்றும் ஒரு வேறு ஊடக விதிமுறைகள் அமைவதைக் கொண்டு வர வேண்டும். பெரும்பாலான குழுக்கள் இதனை கையால் உரையை உலாவியிலே நகலெடுத்து முடிக்கின்றனர்.

இந்த வழக்கு ஆய்வு அந்த கடைசி படியை ஒரு தனி தொலைநிலை MCP சேவையகம் மூலம் எப்படி முடிக்கப்படுகிறதெனும் மற்றும் — அதை கட்டமைக்கும் ஒருவருக்கு மிகவும் பயனுள்ள விதமாக — ஒரு **எழுதுவதற்கான திறன் உடைய** சேவையகத்திற்கு சரியான வடிவமைப்பு தீர்மானங்கள் என்ன என்பதை பார்்க்கிறது. தரவை வாசிப்பதில் மன்னிப்பு உண்டு. வெளியிடுவதில் இல்லை: தவறான கருவி அழைப்பு பார்வையாளர்களுக்கு தெளிவு, மற்றும் அதை திருத்த முடியாது.

## சூழல்

ஒரு சிறிய வியாபார முகவரிகள் குழு ஒரு அகழ்வாளரில் (கிளாட், VS கோட், குர்சர் — கிளையன்ட் முக்கியமல்ல) இடுகைகளை வடிவமைக்கிறது. அவர்கள் அகழ்வாளர் இதைப் பின்வருமாறு செய்க விரும்புகின்றனர்:

- குழுவிற்கான எந்த சமூக கணக்குகள் இணைக்கப்பட்டுள்ளன என்பது பார்க்க,
- ஒரு இடுகையை வடிவமைத்து, ஒரு மனிதர் அங்கீகரிக்க வேளையாக வரைபடமாக வைத்திருக்கும்,
- ஒரு படத்தை இணைக்க,
- தேர்ந்தெடுக்கப்பட்ட நேரத்தில் பல வலைத்தளங்களுக்கு அட்டவணை அமைக்க,
- பின்னர் அதன் செயல்திறன் எப்படி இருந்தது என அறிக்கை வழங்க,

முக்கியமாக, அவர்கள் முயற்சிக்கும்போது அகழ்வாளர் தவறுதலாக வெளியிட முடியாமல் இருக்க விரும்புகின்றனர்.

## பயன்படுத்திய கருவிகள்

- [Publora MCP சேவையகம்](https://github.com/publora/mcp-server) — வெளியீடு, அட்டவணை அமைப்பு, ஊடகங்கள் மற்றும் LinkedIn பகுப்பாய்வு கருவிகளைக் கொண்ட தொலைநிலை MCP சேவையகம் (`streamable-http`). அதிகாரபூர்வ MCP அட்டவணையில் `com.publora/mcp-server` என பதிவு செய்யப்பட்டுள்ளது.

## படி படியான வேலைநடத்தல்

1. **சேவையகத்தை இணைக்கவும்.** OAuth பேசும் கிளையன்ட்கள் சேவையகத்தின் சொந்த ஒப்புதலுக் திரையில் PKCE உடன் அங்கீகரித்தல் குறியீட்டின் வரிசைப்படியை நிறைவேற்றுவார்கள்; இல்லாத CLI போன்ற தலைமுடியாத கிளையன்ட்கள் `Publora API` விசையினை தலைப்பாக பயன்படுத்துவார்கள். இரண்டு பாதைகளும் ஆதரிக்கப்படுகின்றன, மற்றும் நீங்கள் எதுவை பெறுகிறீர்கள் என்பது கிளையன்ட் அவமானம், சேவையகம் அல்ல.
2. **இணைப்புகளை பட்டியலிடவும்.** அகழ்வாளர் `list_connections` ஐ அழைத்து, இணைக்கப்பட்ட கணக்குகள் மற்றும் அவற்றின் அடையாளங்களை பெற்று கொள்கிறது.
3. **வடிவமைக்கவும்.** அகழ்வாளர் ஒரு அட்டவணை நேரம் இல்லாமல் `create_post` ஐ அழைக்கிறது. அந்த இடுகை வரைபடமாக சேமிக்கப்படுகிறது — வெளியீடு எதுவும் இல்லை.
4. **ஊடகத்தை இணைக்கவும்.** பொதுமக்கள் பயன்பாட்டில் உள்ள ஆறு URLகள் அதே அழைப்பில் அனுப்பப்படுகின்றன; சேவையகம் அவற்றைக் பதிவிறக்கம் செய்து சரிபார்க்கிறது.
5. **அட்டவணை அமைக்கவும்.** மனிதர் அங்கீகரித்த பிறகு `update_post` மூலம் நிலையைக் "அட்டவணை அமைக்கப்பட்டது" ஆக மாற்றுகிறது ஒரு ISO 8601 நேரத்துடன்.
6. **அளவிடவும்.** LinkedInக்கானது, இடுகை நேரில் சென்ற பிறகு `linkedin_post_stats` ஈடுபாட்டைப் பெறுகிறது.

## தொழில்நுட்ப செயல்பாடு

கீழ்க்காணும் பாடங்கள் இந்த வழக்கு ஆய்வின் மாற்றம் செய்யக்கூடிய பாகமாகும்.

### திறந்த கண்டுபிடிப்பு, அங்கீகரிக்கப்பட்ட செயல்பாடு

`tools/list` அங்கீகரிப்பு இல்லாமல் வழங்கப்படுகிறது; ஒவ்வொரு `tools/call`க்கும் டோக்கன் தேவை
மற்றும் இல்லையேல் `401` ஐ `WWW-Authenticate` தலைப்புடன் தொகுத்து
பாதுகாக்கப்பட்ட வளங்களின் மெட்டாடேட்டாவைக் குறிக்கிறது. சேவையகத்தின் பழைய இடைமுகமும்
`2026-07-28` மீதான நிரல் பதிப்புகள் வளராத கிளையன்ட்களுக்கு அங்கீகரிக்காத `initialize` ஐ விடைக்கிறது;
தற்போதைய கிளையன்ட்கள் அந்த கையொப்பத்தைக் பயன்படுத்தாது.

இந்த சேவையகம்-சிறப்பு பிரிவு, பதிவேட்டுகள், பட்டியல்கள் மற்றும் கிளையன்ட்களுக்கு கருவி
பெயர்கள், திட்டங்கள் மற்றும் விளக்கங்களை இரகசியமில்லாமல் ஆய்வு செய்ய அனுமதிக்கும், அங்கீகரிக்கப்பட்ட
இல்லாத செயல்பாட்டை தடுக்கும் வகையில் உள்ளது. திறந்த கண்டுபிடிப்பு ஒரு கூறல் தேர்வு, MCP அவசியமல்ல; ஒரு
பாதுகாக்கப்பட்ட அமைப்புக்கு `tools/list`க்கு அங்கீகாரம் தேவையானதாக இருக்க முடியும்.

### பதிவு: தான்டிக்கும் கிளையன்ட் பதிவு, அதனை மாற்றியதென்ன

சேவையகம் `/.well-known/oauth-protected-resource` மற்றும் `/.well-known/oauth-authorization-server` ஐ விளம்பரம் செய்கிறது, மற்றும் PKCE உடன்  அங்கீகரித்தல் குறியீட்டின் பருவத்தை, புதுப்பிப்பு டோக்கன்களை, மற்றும் **தான்டிக்கும் கிளையन்ட் பதிவு** ஐ ஆதரிக்கிறது.

தான்டிக்கும் பதிவு பழைய கிளையன்ட்களுக்கு கைக்கூலி படியை நீக்கியது: அது இல்லாதால்,
ஒவ்வொரு கிளையன்டுக்கும் முன்னதாக வழங்கப்பட்ட ஒரு `client_id` வழங்குநரிடமிருந்து தேவைமானது.

இதனைப் பிரதிநிதித்துவ வினையாகவும், வடிவமைப்பாகவும் பார்க்க வேண்டாம். விவரக்குறிப்பு `2026-07-28` திருத்தம் கிளையன்ட் ID மெட்டாடேட்டா ஆவணங்களுக்கு மாறுதலாக தான்டிக்கும் கிளையன்ட் பதிவை தள்ளுபடி செய்கிறது, இதில் கிளையன்ட் ஒரு நிலையான HTTPS URLல் ஒரு மெட்டாடேட்டா ஆவணத்தை வைத்திருக்கும், அந்த URL தான் `client_id`. DCR இப்போது செயல்படுகிறது, ஆனால் இன்றைய சேவையகம் CIMDக்கு திட்டமிட வேண்டும் மற்றும் DCRஐ பழைய கிளையன்ட்களுக்கே மட்டுமே வைத்திருக்க வேண்டும்.

### கருவி விளக்கவுருக்கள் அலங்காரம் அல்ல

ஒவ்வொரு கருவிக்கும் `title` மற்றும் பொருத்தமான குறிப்பு அளவைகள் இருக்கின்றன: `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`.

அதில் முதலாவது, கிளையன்ட்கள் குறிகளை பயன்படுத்தி பயனாளரிடம் எந்த செயல்களை உறுதிப்படுத்த வேண்டும் என்பதை தீர்மானிக்கின்றனர் — ஒரு கிளையன்ட் படிக்க மட்டும் கூடிய தேடுதலை தானாக இயக்கி, அழிப்பதற்கு முன் அங்கீகாரம் பெற முடியும். விவரக்குறிப்பு விளக்கம் அளவைகள் நம்பத்தக்கவில்லையென தெளிவுபடுத்துகிறது; அதுவே அங்கீகரிப்பு முறையல்ல: அவை கிளையன்ட்கள் செய்ய விரும்பும் செயல்களை வடிவமைக்கின்றன, சேவையகத்தில் எந்ததையும் தடுக்கவோ இல்லை; சேவையகம் தனது விதிகளை பின்பற்றவேண்டும். இரண்டாவது, முக்கிய இணைப்பாளர் அடைவு பார்வையிடுவோர் இவற்றை *கட்டாயமாக* தருகின்றனர்; கருவிகளின் தலைப்புகள் மற்றும் குறிகள் இல்லாத சேவையகம் செயல்திறன் பெண்தவராக இருந்தாலும் மீள அனுப்பப்படும்.

### அடையாளங்களை கண்டுபிடிக்க முடியாமல் செய்யவும்

மேடையின் அடையாளங்கள் `list_connections` மூலம் தரப்படும் மறைக்கப்பட்ட சரங்களாகும்; திட்ட விவரணம் அவற்றை அசாதாரணமாக நகல் எடுக்கவேண்டும் என்றும் ஒருபோதும் கணிக்கக்கூடாது என்றும் கூறுகிறது. சேவையகம் வேறு எதையும் நிராகரிக்கிறது.

மாதிரிகள் உருத்தலும் நுட்பமான கணிப்பாளர்களாக இருக்கின்றன. எதுவும் எழுதக்கூடிய சேவையகம் ஒரு அடையாளம் கடைசியில் தூண்டப்பட வேண்டும் என்று கருதி அதனை அனுமதிக்காமல் அதற்கு முன்பு எழுதத்தக்க முறையில் தோல்வி அடைய வேண்டும்.

### வெளியீட்டிற்கு முன் தோல்வி அடைய வேண்டும், செயல்படுத்தக்கூடிய செய்தியுடன்

சில வலைத்தளங்கள் உரை மட்டும் இடுகைகளை நிராகரிக்கின்றன மற்றும் ஒரு படம் அல்லது வீடியோ தேவைப்படுகின்றது. இது அட்டவணைப்படுத்தும் போது சரிபார்க்கப்படும், பிழை அதற்கான மேடை மற்றும் தேவையற்ற பொருளைப் பெயரிடும்.

ஒரு அகழ்வாளர் "Instagram ஊடகம் தேவையாகும் — ஓர் படம் அல்லது வீடியோ இணைக்கவும்" என்பதை மீண்டும் சென்றுவராமல் குணமாக்க முடியும். பொதுவான `400` போன்ற பிழையிலிருந்து குணமாக்க முடியாது.

### மீண்டும் முயற்சிகள் பாதுகாப்பாக இருக்க வேண்டும்

உள்ளடக்கத்தை உருவாக்கும் இரண்டு கருவிகள் `create_post` மற்றும் `update_post`, ஒற்றுமை விசையை ஏற்றுக்கொள்கின்றன: அதே கோரிக்கையுடன் மீண்டும் பயன்படுத்தும் போது முதல் பதிலையே மீண்டும் வழங்கும்; புதிய இடுகை உருவாக்காது. அகழ்வாளர் நேரத்தடைகளை மீண்டும் முயற்சிக்கிறது; ஒற்றுமை இல்லாமல் மந்தமான பதில் மறு வெளியீட்டு சம்பவமாக மாறும். மற்ற எழுத்து கருவிகள் — அழிப்புகள், ஊடக படிகள், LinkedIn எதிர்ப்புகள் மற்றும் கருத்துக்கள் — ஒன்றும் எடுத்துக்கொள்ளாததால் மீண்டும் முயற்சி அங்கு தானாக பாதுகாப்பாகாது. உங்கள் சுய மாற்றங்கள் எவை பாதுகாக்கப்பட்டவை மற்றும் எவை இல்லாதவையாக இருக்கின்றன என்பதை தெரிந்து கொள்ள மதிப்புள்ளது.

### வெளியிடாதிருக்கும் சோதனை முறையை வழங்கவும்

சேவையகம் ஒதுக்கப்பட்ட இலக்கு `publora-playground` ஐ ஏற்றுக்கொள்கிறது; அது சரிபார்க்கப்படும் மற்றும் உண்மை இலக்காக அங்கீகரிக்கப்படும் பின் நிராகரிக்கப்படும் — எதுவும் நேரடி கணக்கிற்கு செல்லாது. இது கருவி திட்டத்தில் விளக்கப்பட்டுள்ளது, எந்த கிளையன்டும் அங்கீகரிப்பு இல்லாமல் வாசிக்க முடியும்: `create_post`இன் `platforms` புலம் இதனை "எல்லா இணைப்புகளும் இல்லாத இணைப்புச் சோதனை இலக்கு — இடுகை அங்கீகரிக்கப்படும் மற்றும் நிராகரிக்கப்படும், எதுவும் வெளியிடப்படாது" என விளக்குகிறது. இதை ஒற்றை பதிவாக வழங்கவும்: `platforms: ["publora-playground"]`.

இது முழு முகப்பில் மிகவும் பயனுள்ள விவரங்களில் ஒன்று என நிரூபிக்கப்பட்டது. இணைப்பாளர் அடைவு பார்வையாளர்கள், பங்களிப்பாளர்கள் மற்றும் CI முழு எழுதும் பாதையை ஓர் வாழ் பார்வையாளருக்கு எந்த அபாயமும் எழுதுாமல் பயிற்சி செய்யலாம். மாற்ற முடியாத செயல்களை செய்யும் எந்த MCP சேவையகமும் ஆவணபடுத்தப்பட்ட செயல் கொள்கை இலக்கை பெற்றிருப்பதால் பயன் பெரும்.

## முடிவுகள் மற்றும் தாக்கம்

- வெளியீட்டு படி உலாவியில் இருந்து உள்ளடக்கம் எழுதப்படும் தட்டச்சு உரையாடலுக்கு மாற்றப்பட்டது, மற்றும் வரைபடம் முதலில் வைத்திருப்பது மனிதரை சுழற்சியில் வைக்கிறது. அது என்ன என்பது தெளிவாக இருக்க வேண்டும்: ஒரு வரைபடம் ஒரு பழக்கம்; எல்லை அல்ல. அதே அங்கீகாரம் அட்டவணை அமைக்கவும் வெளியிடவும் பயன்படுத்தலாம், எனவே உண்மையான அங்கீகார வாயிலை தேவையடையும் ஒருவரும் கருவி மேற்சரிபார்ப்பை வெளியே கடைபிடிக்க வேண்டும் — பிரித்துவைத்த அங்கீகாரங்கள் அல்லது சேவையகத்திற்கு முன் கொள்கை அடுக்கு.
- வலைத்தள பல்வேறு வேறுபாடுகள் — ஊடக தேவைகள், நூல்முறை அமைப்புகள், பதில் கட்டுப்பாடுகள் — சேவையகத்தில் ஒருமுறை நிர்வகிக்கப்படுகின்றன, ஒவ்வொரு அகழ்வாளும் அல்ல.
- அதே சேவையகம் பல MCP கிளையன்ட்களை முன் வழங்கப்பட்ட அங்கீகாரங்கள் இல்லாமல் ஆதரிக்கிறது.
    தற்போதைய கிளையன்ட்கள் கிளையன்ட் ஐடி மெட்டாடேட்டா ஆவணங்களைப் பயன்படுத்தலாம்; பழைய கிளையன்ட்களுக்கு DCR மறுவிதி.

- மேலே கூறப்பட்ட வடிவமைப்பு கட்டுப்பாடுகள் இணைப்பாளர் அடைவு பார்வைகள் மற்றும் பயனர்களால் உருவானவை: விளக்கவுருக்கள், OAuth மற்றும் பாதுகாப்பான சோதனை இலக்கு ஒவ்வொன்றும் குறைந்தது ஒருவரால் தேவைப்பட்டது.

## அடுத்து என்ன

- நீங்கள் கட்டமைத்திருக்கும் MCP சேவையகத்தை எடுத்துக்கொண்டு இங்கு மூன்றாம் கூடிய வெற்றிகளை சரிபார்க்கவும்: ஒவ்வொரு கருவியிலும் விளக்கவுருக்கள், ஒவ்வொரு எழுத்திலும் ஒற்றுமை விசை, மற்றும் ஆவணம் செய்யப்பட்ட செயல் கொண்ட இலக்கு.
- திறந்த கண்டுபிடிப்பு பிரிவை முயற்சி செய்யவும்: பொதுமக்கள் தொலைநிலை சேவையகத்திற்கு எந்த அங்கீகாரமும் இல்லாமல் `tools/list` ஐ அழைக்கவும், பின்னர் ஒரு கருவியை அழைத்து `401` சவாலை ஆய்வு செய்யவும்.
- உங்கள் துறையில் "திரும்பப்பெறு" என்பது என்ன என்பதில் கவனம் செலுத்தவும். வெளியீடு வரைபடங்களும் அழிப்பும் உள்ளது; உங்கள் செயல்களுக்கு இணையானவை இல்லாவிட்டால், உறுதிப்படுத்தல் கருவி வடிவமைப்பில் இருக்க வேண்டும், கோரிக்கையில் அல்ல.
