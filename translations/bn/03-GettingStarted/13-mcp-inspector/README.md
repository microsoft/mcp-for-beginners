# MCP ইনস্পেক্টর দিয়ে ডিবাগিং

> [!NOTE]
> `--sse` ব্যবহার করে কমান্ড এবং `/sse` দিয়ে শেষ হওয়া URL গুলো পুরোনো HTTP+SSE
> পরিবহন পরীক্ষা করে। নতুন MCP `2026-07-28` সার্ভারের জন্য, এমন একটি ইনস্পেক্টর ভার্সন ব্যবহার করুন যা
> Streamable HTTP সাপোর্ট করে এবং সেটি পরিবহন হিসাবে নির্বাচন করুন।

**MCP ইনস্পেক্টর** একটি অপরিহার্য ডিবাগিং টুল যা আপনাকে সম্পূর্ণ AI হোস্ট অ্যাপ্লিকেশন ছাড়াই আপনার MCP সার্ভারগুলিকে ইন্টারঅ্যাকটিভভাবে পরীক্ষা এবং সমস্যার সমাধান করতে দেয়। এটিকে "MCP এর জন্য Postman" হিসাবে ভাবুন - এটি অনুরোধ পাঠানো, প্রতিক্রিয়া দেখা এবং সার্ভার কিভাবে আচরণ করে তা বুঝতে একটি ভিজ্যুয়াল ইন্টারফেস প্রদান করে।

## কেন MCP ইনস্পেক্টর ব্যবহার করবেন?

MCP সার্ভার তৈরি করার সময়, আপনি প্রায়শই এই চ্যালেঞ্জগুলির সম্মুখীন হবেন:

- **"আমার সার্ভার কি কাজ করছে?"** - ইনস্পেক্টর সংযোগের অবস্থা দেখায়
- **"আমার টুলগুলো সঠিকভাবে নিবন্ধিত কি?"** - ইনস্পেক্টর সমস্ত উপলব্ধ টুল তালিকাভুক্ত করে
- **"প্রতিক্রিয়ার ফরম্যাট কি?"** - ইনস্পেক্টর সম্পূর্ণ JSON প্রতিক্রিয়া প্রদর্শন করে
- **"এই টুলটি কেন কাজ করছে না?"** - ইনস্পেক্টর বিস্তারিত ত্রুটির বার্তা দেখায়

## পূর্বশর্ত

- Node.js 18+ ইনস্টল করা হয়েছে
- npm (Node.js এর সাথে আসে)
- একটি MCP সার্ভার পরীক্ষা করার জন্য (দেখুন [Module 3.1 - First Server](../01-first-server/README.md))

## ইনস্টলেশন

### অপশন 1: npx দিয়ে চালানো (দ্রুত পরীক্ষার জন্য সুপারিশকৃত)

```bash
npx @modelcontextprotocol/inspector
```

### অপশন 2: গ্লোবালি ইনস্টল করা

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### অপশন 3: আপনার প্রকল্পে যোগ করা

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` এ যোগ করুন:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## আপনার সার্ভারের সাথে সংযোগ করা

### stdio সার্ভার (স্থানীয় প্রক্রিয়া)

এমন সার্ভারগুলির জন্য যারা স্ট্যান্ডার্ড ইনপুট/আউটপুট এর মাধ্যমে যোগাযোগ করে:

```bash
# পাইথন সার্ভার
npx @modelcontextprotocol/inspector python -m your_server_module

# নোড.জেএস সার্ভার
npx @modelcontextprotocol/inspector node ./build/index.js

# পরিবেশ ভেরিয়েবল সহ
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP সার্ভার (নেটওয়ার্ক)

HTTP সার্ভিস হিসেবে চলমান সার্ভারগুলির জন্য:

1. প্রথমে আপনার সার্ভার চালু করুন:
   ```bash
   python server.py  # সার্ভার http://localhost:8080 এ চলছে
   ```

2. ইনস্পেক্টর চালু করুন এবং সংযোগ করুন:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## টুল পরীক্ষা করা

### উপলব্ধ টুল তালিকাভুক্ত করা

1. **Tools** ট্যাবে ক্লিক করুন
2. ইনস্পেক্টর স্বয়ংক্রিয়ভাবে `tools/list` কল করে
3. আপনি দেখতে পাবেন সমস্ত নিবন্ধিত টুল নিম্নরূপ:
   - টুলের নাম
   - বর্ণনা
   - ইনপুট স্কিমা (প্যারামিটার)

### একটি টুল আহ্বান করা

1. তালিকা থেকে একটি টুল নির্বাচন করুন
2. ফর্মে প্রয়োজনীয় প্যারামিটার পূরণ করুন
3. **Run Tool** ক্লিক করুন
4. ফলাফল প্যানেলে প্রতিক্রিয়া দেখুন

**উদাহরণ: একটি ক্যালকুলেটর টুল পরীক্ষা করা**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### টুল ত্রুটি ডিবাগিং

যখন একটি টুল ব্যর্থ হয়, ইনস্পেক্টর দেখায়:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

সাধারণ ত্রুটি কোড:
| কোড | অর্থ |
|------|---------|
| -32700 | পার্স ত্রুটি (অকার্যকর JSON) |
| -32600 | অকার্যকর অনুরোধ |
| -32601 | পদ্ধতি পাওয়া যায়নি |
| -32602 | অকার্যকর প্যারামিটার |
| -32603 | অভ্যন্তরীণ ত্রুটি |

## রিসোর্স পরীক্ষা করা

### রিসোর্স তালিকাভুক্ত করা

1. **Resources** ট্যাবে ক্লিক করুন
2. ইনস্পেক্টর `resources/list` কল করে
3. আপনি দেখতে পাবেন:
   - রিসোর্স URI
   - নাম এবং বর্ণনা
   - MIME ধরন

### একটি রিসোর্স পড়া

1. একটি রিসোর্স নির্বাচন করুন
2. **Read Resource** ক্লিক করুন
3. প্রতিক্রিয়া হিসেবে ফিরে আসা কনটেন্ট দেখুন

**উদাহরণ আউটপুট:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## প্রম্পট পরীক্ষা করা

### প্রম্পট তালিকাভুক্ত করা

1. **Prompts** ট্যাবে ক্লিক করুন

### একটি প্রম্পট পাওয়া

1. একটি প্রম্পট নির্বাচন করুন
2. প্রয়োজনীয় যে কোন যুক্তি পূরণ করুন
3. **Get Prompt** ক্লিক করুন
4. রেন্ডার্ড প্রম্পট মেসেজগুলি দেখুন

## মেসেজ লগ বিশ্লেষণ

মেসেজ লগে সমস্ত MCP প্রটোকল মেসেজ দেখায়। নীচের ট্রান্সক্রিপ্টটি একটি
পুরানো `2025-11-25` সার্ভার থেকে এবং এতে বাদ দেওয়া `initialize` হ্যান্ডশেক অন্তর্ভুক্ত। একটি
`2026-07-28` সার্ভার স্ব-সম্পূর্ণ অনুরোধ মেটাডেটা এবং পরিবর্তে `server/discover`
ব্যবহার করে।

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### কি খুঁজবেন

- **অনুরোধ/প্রতিক্রিয়া জোড়া**: প্রতিটি `→` এর জন্য একটি মিলানো `←` থাকা উচিত
- **ত্রুটির বার্তা**: প্রতিক্রিয়ায় `"error"` খুঁজুন
- **সময়**: দীর্ঘ বিরতি পারফরমেন্স সমস্যার ইঙ্গিত দিতে পারে
- **প্রটোকল ভার্সন**: সার্ভার এবং ক্লায়েন্ট একই ভার্সনে আছে কিনা নিশ্চিত করুন

## সাধারণ ডিবাগিং দৃশ্যপট

### দৃশ্যপট 1: সার্ভার সংযোগ করছে না

**লক্ষণ:** ইনস্পেক্টর "Disconnected" দেখায় অথবা "Connecting..." এ আটকে থাকে

**চেকলিস্ট:**
1. ✅ সার্ভার কমান্ড সঠিক কি?
2. ✅ সমস্ত নির্ভরতা ইনস্টল করা হয়েছে কি?
3. ✅ সার্ভার পাথ সম্পূর্ণ কি নাকি বর্তমান ডিরেক্টরির সম্পর্কিত?
4. ✅ প্রয়োজনীয় পরিবেশ ভেরিয়েবল সেট করা হয়েছে কি?

**ডিবাগ ধাপ:**
```bash
# প্রথমে ম্যানুয়ালি সার্ভারটি পরীক্ষা করুন
python -c "import your_server_module; print('OK')"

# ইমপোর্ট ত্রুটির জন্য পরীক্ষা করুন
python -m your_server_module 2>&1 | head -20

# নিশ্চিত করুন MCP SDK ইনস্টল করা হয়েছে
pip show mcp
```

### দৃশ্যপট 2: টুলগুলো দেখা যাচ্ছে না

**লক্ষণ:** Tools ট্যাবে খালি তালিকা দেখাচ্ছে

**সম্ভাব্য কারণ:**
1. সার্ভার ইনিশিয়ালাইজেশনের সময় টুল নিবন্ধিত হয়নি
2. শুরু করার পর সার্ভার ক্রাশ করেছে
3. `tools/list` হ্যান্ডলার খালি অ্যারে রিটার্ন করছে

**ডিবাগ ধাপ:**
1. `tools/list` প্রতিক্রিয়া জন্য মেসেজ লগ চেক করুন
2. আপনার টুল নিবন্ধন কোডে লগিং যুক্ত করুন
3. নিশ্চিত করুন `@mcp.tool()` ডেকোরেটর উপস্থিত আছে (Python)

### দৃশ্যপট 3: টুল ত্রুটি ফেরত দেয়

**লক্ষণ:** টুল কল ত্রুটি প্রতিক্রিয়া ফেরত দেয়

**ডিবাগ পদ্ধতি:**
1. ত্রুটির বার্তা সতর্কতার সাথে পড়ুন
2. প্যারামিটার টাইপ স্কিমার সাথে মিলান
3. বিস্তারিত ত্রুটির বার্তা সহ try/catch যুক্ত করুন
4. সার্ভার লগে স্ট্যাক ট্রেস চেক করুন

**উদাহরণ উন্নত ত্রুটি হ্যান্ডলিং:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # টুল লজিক এখানে
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### দৃশ্যপট 4: রিসোর্স কনটেন্ট খালি

**লক্ষণ:** রিসোর্স ফেরত দেয় কিন্তু কনটেন্ট খালি বা null

**চেকলিস্ট:**
1. ✅ ফাইল পাথ বা URI সঠিক
2. ✅ সার্ভারের রিসোর্স পড়ার অনুমতি আছে
3. ✅ রিসোর্স কনটেন্ট সঠিকভাবে ফেরত দিচ্ছে

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### সেশন রেকর্ডিং

ইনস্পেক্টর পড়ার জন্য পরবর্তী বিশ্লেষণের জন্য মেসেজ লগ রপ্তানি করতে পারে:
1. মেসেজ প্যানেলে **Export Log** ক্লিক করুন
2. JSON ফাইল সংরক্ষণ করুন
3. ডিবাগিং এর জন্য দলের সদস্যদের সাথে শেয়ার করুন

## সেরা অনুশীলনগুলি

1. **শুরুতেই এবং নিয়মিত পরীক্ষা করুন** - ইন্সপেক্টর ব্যবহার করুন উন্নয়নের সময়, শুধু সমস্যা দেখা দিলে নয়
2. **সরল থেকে শুরু করুন** - জটিল টুল কলের আগে মৌলিক সংযোগ পরীক্ষা করুন
3. **স্কিমা পরীক্ষা করুন** - অনেক ত্রুটি প্যারামিটার টাইপের অসঙ্গতির কারণে হয়
4. **এরর মেসেজ পড়ুন** - MCP এরর সাধারণত বর্ণনামূলক হয়
5. **ইন্সপেক্টর খোলা রাখুন** - এটি বিকাশের সময় সমস্যা ধরতে সাহায্য করে
