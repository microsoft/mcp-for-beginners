# MCP রুটস (পুরোনো বৈশিষ্ট্য)

> [!WARNING]
> MCP `2026-07-28` থেকে রুটস অব্যবহৃত হয়েছে। তারা সামঞ্জস্যতার জন্য এই সংস্করণে রয়েছে এবং
> ২৮ জুলাই, ২০২৭ বা এর পরে প্রকাশিত প্রথম স্পেসিফিকেশন পুনরাবৃত্তিতে অপসারণের জন্য যোগ্য।
> নতুন বাস্তবায়নগুলি সরঞ্জাম প্যারামিটার, রিসোর্স URI, অথবা সার্ভার কনফিগারেশনের মাধ্যমে
> ডিরেক্টরি বা ফাইল পাস করা উচিত।


## ওভারভিউ

রুটস একটি MCP ক্লায়েন্টকে একটি সার্ভারকে বলতে দেয় কোন ফাইল সিস্টেমের অবস্থানগুলি বর্তমান অনুরোধের জন্য প্রাসঙ্গিক।
একটি রুটে একটি প্রয়োজনীয় `file://` URI এবং ঐচ্ছিক মানব-পঠনযোগ্য নাম থাকে।


প্রোটোকল সেশন নয়, বা একটি অ্যাক্সেস-কন্ট্রোল মেকানিজম নয়। প্রোটোকল সার্ভারকে
তালিকাভুক্ত রুটসের মধ্যে থাকতে বাধ্য করে না।


## শেখার উদ্দেশ্য

এই পাঠের শেষে, আপনি সক্ষম হবেন:

- MCP রুটস কী প্রতিনিধিত্ব করে এবং কী প্রতিনিধিত্ব করে না তা ব্যাখ্যা করতে।
- বর্তমান `roots/list` মাল্টি-রাউন্ড-ট্রিপ ফ্লো চিনতে।
- রুটস থেকে স্বাধীনভাবে নিরাপত্তা নিয়ন্ত্রণ প্রয়োগ করতে।
- নতুন বাস্তবায়নসমূহকে সমর্থিত বিকল্পগুলিতে স্থানান্তর করতে।

## রুট ডেটা

একটি ক্লায়েন্ট প্রতিটি রুটকে একটি `file://` URI এবং একটি ঐচ্ছিক প্রদর্শন নাম হিসাবে ফেরত দেয়:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

ক্লায়েন্টদের শুধুমাত্র ব্যবহারকারী অনুমোদিত অবস্থানগুলি প্রকাশ করা উচিত। সার্ভারগুলো
ফলাফলকে প্রামাণিক অনুমতির প্রমাণের চেয়ে প্রাসঙ্গিক ফাইল সম্পর্কে নির্দেশনা হিসাবে গ্রহণ করা উচিত।

## MCP ২০২৬-০৭-২৮ ফ্লো

রুটস সমর্থনকারী একটি ক্লায়েন্ট প্রতিটি অনুরোধে সক্ষমতা ঘোষণা করে:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

ক্লায়েন্ট অনুরোধ প্রক্রিয়াকালে, একটি সার্ভার একটি
`InputRequiredResult` ফেরত দিতে পারে যা একটি `roots/list` ইনপুট অনুরোধ ধারণ করে:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

ক্লায়েন্ট অনুমোদিত রুটগুলি সংগ্রহ করে এবং মূল অনুরোধটি মিলিত `inputResponses` এবং অপরিবর্তিত `requestState` সহ পুনরায় চেষ্টা করে। এই মাল্টি-রাউন্ড-ট্রিপ
প্যাটার্ন প্রোটোকলকে স্থিতিশীল রাখে; কোনও `initialize` হ্যান্ডশেক বা
প্রোটোকল-স্তরের সেশন নেই।


## পুরানো ২০২৫-১১-২৫ আচরণ

MCP `2025-11-25` এ, ক্লায়েন্টরা রুটস প্রাথমিককালে বিজ্ঞাপন করত। একটি সার্ভার সরাসরি `roots/list` অনুরোধ করতে পারত, এবং একটি ক্লায়েন্ট `notifications/roots/list_changed` পাঠাতে পারত যখন তার রুট পরিবর্তিত হত।

সেই জীবনচক্রটি পুরোনো আচরণ। এর প্রাথমিককরণ বা বিজ্ঞপ্তির উদাহরণ গুলো `2026-07-28` বাস্তবায়নের সাথে মিলিয়ে ব্যবহার করবেন না।











### রিসোর্স URI

যখন সার্ভার প্রাসঙ্গিক ফাইলগুলি স্থিতিশীল URI এর মাধ্যমে প্রকাশ করতে পারে তখন MCP Resources ব্যবহার করুন। এটি আবিষ্কার এবং পুনরুদ্ধার স্পষ্ট রাখে।


### সার্ভার কনফিগারেশন

স্থির ডিপ্লয়মেন্টের ক্ষেত্রে, সার্ভার চালু হওয়ার সময় অনুমোদিত ডিরেক্টরি গুলো কনফিগার করুন।
এটি প্রায়ই টুল কল চলাকালীন সেগুলো আবিষ্কারের চেয়ে স্পষ্টতর।

## নিরাপত্তা প্রয়োজনীয়তা

যেকোনো বিকল্প আপনি বেছে নিন:

- ফাইল সিস্টেমের অবস্থান প্রকাশের আগে ব্যবহারকারীর সম্মতি নিন।
- পথসমূহ ক্যাননিক্যালাইজ এবং যাচাই করুন যেন ট্র্যাভার্সাল প্রতিরোধ করা যায়।
- রুট মান থেকে স্বাধীনভাবে অনুমোদন এবং স্যান্ডবক্সিং প্রয়োগ করুন।
- একটি ফাইল এক্সেস করার সময় অনুমতি আবার যাচাই করুন, শুধুমাত্র তালিকাভুক্ত হলে নয়।
- লগ বা ত্রুটি বার্তায় সংবেদনশীল পথ ফেরত দেওয়া এড়িয়ে চলুন।

## মূল বিষয়বস্তু

- রুটস প্রাসঙ্গিক ফাইল সিস্টেমের অবস্থান বর্ণনা করে; তারা কথোপকথন অবস্থা সংরক্ষণ করে না।

- রুটস নির্দেশনা, অ্যাক্সেস-কন্ট্রোল সীমান্ত নয়।
- MCP `২০২৬-০৭-২৮` প্রতি অনুরোধে সক্ষমতা বহন করে এবং `InputRequiredResult` ব্যবহার করে `roots/list` এর জন্য।

- নতুন বাস্তবায়নগুলি টুল প্যারামিটার, রিসোর্স ইউআরআই, বা সার্ভার কনফিগারেশন ব্যবহার করা উচিত।
