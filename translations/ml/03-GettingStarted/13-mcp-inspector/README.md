# MCP ഇൻസ്പക്റ്ററുമായി ഡീബഗിംഗ്

> [!NOTE]
> `--sse` ഉപയോഗിച്ച് ഉള്ള കമാൻഡുകളും `/sse` ആയി അവസാനിക്കുന്ന URLs ലെഗസി HTTP+SSE
> ട്രാൻസ്പോർട്ടിനെ ടെസ്റ്റ് ചെയ്യുന്നു. പുതിയ MCP `2026-07-28` സെർവറിനായി, സ്റ്റ്രീമബിൾ HTTP
> പിന്തുണക്കുന്ന ഇൻസ്പക്റ്റർ വേർഷൻ ഉപയോഗിച്ച് ആ ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുക്കുക.

**MCP ഇൻസ്പക്റ്റർ** ഒരു പ്രധാനപ്പെട്ട ഡീബഗിംഗ് ടൂൾ ആണ്, ഇത് ഒരു പൂർണ്ണ AI ഹോസ്റ്റ് അപ്ലിക്കേഷൻ ആവശ്യമില്ലാതെ MCP സെർവർകൾ ഇന്ററാക്ടീവ് ആയി ടെസ്റ്റ് ചെയ്യാനും പ്രശ്നങ്ങൾ പരിഹരിക്കുന്നതിനും സഹായിക്കുന്നു. ഇതിനെ "MCPക്കുള്ള പോസ്റ്റ്മാൻ" ആയി കരുതാം - ഇത് അഭ്യർത്ഥനകൾ അയയ്ക്കാനും, മറുപടികൾ കാണാനും, സെർവർ എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്നു മനസ്സിലാക്കാനായി ദൃശ്യ ഇന്റർഫേസ് നൽകുന്നു.

## എന്തുകൊണ്ട് MCP ഇൻസ്പക്റ്റർ ഉപയോഗിക്കണം?

MCP സെർവർ നിർമ്മിക്കുമ്പോൾ നിങ്ങൾക്ക് പലപ്പോഴും ഇത്തരത്തിലുള്ള പ്രശ്നങ്ങൾ നേരിടേണ്ടിവരും:

- **"എന്റെ സെർവർ പ്രവർത്തിക്കുമോ?"** - ഇൻസ്പക്റ്റർ കണക്ഷൻ നില അവലോകനം ചെയ്യുന്നു
- **"എന്റെ ടൂളുകൾ ശരിയായി രജിസ്റ്റർ ചെയ്തിട്ടുണ്ടോ?"** - ഇൻസ്പക്റ്റർ എല്ലാ ലഭ്യമായ ടൂളുകളും ലിസ്റ്റ് ചെയ്യുന്നു
- **"മറുപടി ഫോർമാറ്റ് എന്താണ്?"** - ഇൻസ്പക്റ്റർ പൂർണ്ണ JSON മറുപടികൾ പ്രദർശിപ്പിക്കുന്നു
- **"ഈ ടൂൾ പ്രവർത്തിക്കുന്നില്ലേ?"** - ഇൻസ്പക്റ്റർ വിശദമായ പിശക് സന്ദേശങ്ങൾ കാണിക്കുന്നു

## മുൻകൂട്ടി തയ്യാറെടുപ്പ്

- Node.js 18+ ഇൻസ്റ്റാൾ ചെയ്തു കഴിഞ്ഞത്
- npm (Node.js ഒപ്പം വരുന്ന പാക്കേജ് മാനേജർ)
- ഒരു MCP സെർവർ ടെസ്റ്റ് ചെയ്യാൻ (കാണുക [Module 3.1 - First Server](../01-first-server/README.md))

## ഇൻസ്റ്റലേഷൻ

### ഓപ്ഷൻ 1: npx ഉപയോഗിച്ച് ഓടിക്കുക (വേഗത്തിലുള്ള ടെസ്റ്റിംഗിന് ശുപാർശ)

```bash
npx @modelcontextprotocol/inspector
```

### ഓപ്ഷൻ 2: ഗ്ലോബലായി ഇൻസ്റ്റാൾ ചെയ്യുക

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### ഓപ്ഷൻ 3: നിങ്ങളുടെ പ്രോജക്റ്റിൽ ചേർക്കുക

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` ൽ ചേർക്കുക:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## നിങ്ങളുടെ സെർവറുമായി കണക്ട് ചെയ്യുന്നു

### stdio സെർവർসমূহ (ലോകൽ പ്രോസസ്)

സ്റ്റാൻഡേർഡ് ഇൻപുട്ട്/ഔട്ട്പുട്ട് വഴി സംസാരിക്കുന്ന സെർവർകൾക്ക്:

```bash
# പൈതൺ സെർവർ
npx @modelcontextprotocol/inspector python -m your_server_module

# നോഡ്.js സെർവർ
npx @modelcontextprotocol/inspector node ./build/index.js

# പരിസ്ഥിതി വ്യത്യാസങ്ങളോടെ
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP സെർവർകൾ (നെറ്റ്വർക്ക്)

HTTP സേവനമായിട്ടുള്ള സെർവർകൾക്ക്:

1. ആദ്യം നിങ്ങളുടെ സെർവർ ആരംഭിക്കുക:
   ```bash
   python server.py  # സെർവർ http://localhost:8080 എന്ന വിലാസത്തിൽ പ്രവർത്തിക്കുന്നു
   ```

2. ഇൻസ്പക്റ്റർ ആരംഭിച്ച് കണക്ട് ചെയ്യുക:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## ടൂൾസ് ടെസ്റ്റ് ചെയ്യൽ

### ലഭ്യമായ ടൂളുകൾ ലിസ്റ്റ് ചെയ്യൽ

1. **Tools** ടാബിൽ ക്ലിക്ക് ചെയ്യുക
2. ഇൻസ്പക്റ്റർ സ്വയം `tools/list` കാൾ ചെയ്യുന്നു
3. നിങ്ങൾക്ക് എല്ലാ രജിസ്റ്റർ ചെയ്ത ടൂളുകളും കാണാം:
   - ടൂൾ നാമം
   - وضנി്
   - ഇൻപുട്ട് സ്കീമ (പരാമീറ്ററുകൾ)

### ടൂൾ വിളിക്കൽ

1. ലിസ്റ്റിൽ നിന്ന് ഒരു ടൂൾ തിരഞ്ഞെടുക്കുക
2. ഫോം പൂരിപ്പിച്ച് ആവശ്യമായ പരാമീറ്ററുകൾ നൽകുക
3. **Run Tool** ക്ലിക്ക് ചെയ്യുക
4. ഫലങ്ങൾ പാനലിൽ മറുപടി കാണുക

**ഉദാഹരണം: കാൽക്കുലേറ്റർ ടൂൾ ടെസ്റ്റ് ചെയ്യുന്നു**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### ടൂൾ പിശക് ഡീബഗിംഗ്

ടൂൾ പരാജയപ്പെട്ടാൽ ഇൻസ്പക്റ്റർ കാണിക്കുന്നു:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

സാധാരണ പിശക് കോഡുകൾ:
| കോഡ് | അർത്ഥം |
|------|---------|
| -32700 | പാഴ്‌സ് പിശക് (ചെല്ലാത്ത JSON) |
| -32600 | തെറ്റായ അഭ്യർത്ഥന |
| -32601 | മെതഡ് കണ്ടെത്തിയില്ല |
| -32602 | തെറ്റായ പാരാമീറ്ററുകൾ |
| -32603 | അനുഭാവിക പിശക് |

## റിസോഴ്‌സസുകൾ ടെസ്റ്റുചെയ്യൽ

### റിസോഴ്‌സുകൾ ലിസ്റ്റുചെയ്യൽ

1. **Resources** ടാബിൽ ക്ലിക്ക് ചെയ്യുക
2. ഇൻസ്പക്റ്റർ `resources/list` കാൾ ചെയ്യുന്നു
3. നിങ്ങൾക്ക് കാണാം:
   - റിസോഴ്‌സ് URIകൾ
   - നാമങ്ങളും وضنിക്സുകളും
   - MIME ടൈപ്പുകൾ

### ഒരു റിസോഴ്‌സ് വായിക്കൽ

1. ഒരു റിസോഴ്‌സ് തിരഞ്ഞെടുക്കുക
2. **Read Resource** ക്ലിക്ക് ചെയ്യുക
3. മടക്കിയ ഉള്ളടക്കം കാണുക

**ഉദാഹരണ ഔട്ട്പുട്ട്:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## പ്രോംപ്റ്റുകൾ ടെസ്റ്റ് ചെയ്യൽ

### പ്രോംപ്റ്റുകൾ ലിസ്റ്റുചെയ്യൽ

1. **Prompts** ടാബിൽ ക്ലിക്ക് ചെയ്യുക
2. ഇൻസ്പക്റ്റർ `prompts/list` കാൾ ചെയ്യും
3. ലഭ്യമായ പ്രോംപ്റ്റ് ടെംപ്ലേറ്റുകൾ കാണുക

### ഒരു പ്രോംപ്റ്റ് ലഭിക്കൽ

1. പ്രോംപ്റ്റ് തിരഞ്ഞെടുക്കുക
2. ആവശ്യമായ ആർഗ്യുമെന്റുകൾ നൽകുക
3. **Get Prompt** ക്ലിക്ക് ചെയ്യുക
4. റെൻഡർ ചെയ്ത പ്രോംപ്റ്റ് സന്ദേശങ്ങൾ കാണുക

## സന്ദേശ ലോഗ് വിശകലനം

സമ്പൂർണ MCP പ്രോട്ടോക്കോൾ സന്ദേശങ്ങൾ സന്ദേശ ലോഗ് കാണിക്കുന്നു. താഴെയുള്ള ട്രാൻസ്ക്രിപ്റ്റ്
ഒരു ലെഗസി `2025-11-25` സെർവറിന്‍റെ ആണ്, ഇതിൽ നീക്കംചെയ്ത `initialize` ഹാൻഡ്‌ഷേക്ക് ഉൾക്കൊള്ളുന്നു. ഒരു
`2026-07-28` സെർവർ സ്വയം-കണ്ടെയ്ൻഡ് അഭ്യർത്ഥന മെടാഡാറ്റയും `server/discover`
സജ്ജീകരണവും ഉപയോഗിക്കുന്നു.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### എന്തെല്ലാം പരിശോധിക്കണമെന്ന്

- **അഭ്യർത്ഥന/മറുപടി ജോഡികൾ**: ഓരോ `→`ക്ക് ഒത്തുപോകുന്ന `←` അണുബന്ധിച്ചിരിക്കണം
- **പിശക് സന്ദേശങ്ങൾ**: മറുപടികളിൽ `"error"` നു ശ്രദ്ധിക്കുക
- **സമയം**: വലിയ ഇടവേളകൾ പ്രകടന പ്രശ്നങ്ങളാവാം
- **പ്രോട്ടോക്കോൾ വേർഷൻ**: സെർവർ, ക്ലയന്റ് തമ്മിൽ വേർഷൻ ഒത്തു പെരുക്കണം

## VS കോഡ് ഇന്റഗ്രേഷൻ

നിങ്ങൾക്ക് ഇൻസ്പക്റ്റർ നേരിട്ട് VS കോഡിൽ നിന്നു പ്രവർത്തിപ്പിക്കാം:

### launch.json ഉപയോഗിച്ച്

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

3. ✅ സെർവർ പാത്ത് മൊത്തം അല്ലെങ്കിൽ ഇപ്പോഴത്തെ ഡയറക്ടറിയെ സംബന്ധിച്ചുള്ളതാണോ?
4. ✅ ആവശ്യമായ എൻവയോൺമെന്റ് വേരിയബലുകൾ സജ്ജമാക്കിയിട്ടുണ്ടോ?

**ഡീബഗ് പടികൾ:**
```bash
# സേർവർ കൈയിൽ ടെസ്റ്റ് ചെയ്യുക
python -c "import your_server_module; print('OK')"

# ഇറക്കുമതി പിശകുകൾ പരിശോധിക്കുക
python -m your_server_module 2>&1 | head -20

# MCP SDK ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്ന് സ്ഥിരീകരിക്കുക
pip show mcp
```

### സന്നിവേശം 2: ടൂളുകൾ കാണപ്പെടുന്നില്ല

**ലക്ഷണങ്ങൾ:** ടൂളുകൾ ടാബിൽ പട്ടിക ശൂന്യമാണെന്ന് കാണിക്കുന്നു

**സാധ്യമായ കാരണങ്ങൾ:**
1. സെർവർ തുടങ്ങിയപ്പോൾ ടൂളുകൾ രജിസ്റ്റർ ചെയ്തിട്ടില്ല
2. സെർവർ ആരംഭിച്ചതിനു ശേഷം ക്രാഷ് ആയി
3. `tools/list` ഹാൻഡ്ലർ ശൂന്യമായ അറി നൽകുന്നു

**ഡീബഗ് പടികൾ:**
1. സന്ദേശ ലോഗിൽ `tools/list` മറുപടി പരിശോധിക്കുക
2. ടൂൾ രജിസ്‌ട്രേഷൻ കോഡിൽ ലോഗിംഗ് ചേർക്കുക
3. `@mcp.tool()` ഡെക്കറേറ്റർമാർ Python കോഡിൽ ലഭ്യമായിരിക്കണം എന്ന് പരിശോധിക്കുക

### സന്നിവേശം 3: ടൂൾ പിശക് മറുപടി നൽകി

**ലക്ഷണങ്ങൾ:** ടൂൾ വിളിക്കൽ പിശക് മറുപടി നൽകുന്നു

**ഡീബഗ് സമീപനം:**
1. പിശക് സന്ദേശം സന്ത്രസ്തമായി വായിക്കുക
2. പാരാമീറ്റർ തരം സ്കീമയ്ക്ക് പൊരുത്തമുണ്ടോ എന്ന് പരിശോധിക്കുക
3. വിശദമായ പിശക് സന്ദേശങ്ങളുമായി ട്രൈ/കാച്ച് ചേർക്കുക
4. സെർവർ ലോഗുകളിൽ സ്റ്റാക് ട്രെയ്‌സ് പരിശോധിക്കുക

**ഉദാഹരണമായ മെച്ചപ്പെട്ട പിശക് കൈകാര്യം:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # ടൂൾ ലാജിക് ഇവിടെ
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### സന്നിവേശം 4: റിസോഴ്‌സ് ഉള്ളടക്കം ശൂന്യമാണ്

**ലക്ഷണങ്ങൾ:** റിസോഴ്‌സ് തിരികെ നൽകുന്നു എങ്കിലും ഉള്ളടക്കം ശൂന്യമായിരിക്കുന്നു അല്ലെങ്കിൽ നുള്ള് ആണ്

**ചെക്ക്ലിസ്റ്റ്:**
1. ✅ ഫയൽ പാത്ത് അല്ലെങ്കിൽ URI ശരിയാണോ?
2. ✅ സെർവർക്കിന് റിസോഴ്‌സ് വായിക്കാൻ അനുമതി ഉണ്ടോ?
3. ✅ റിസോഴ്‌സ് ഉള്ളടക്കം ശരിയായി തിരികെ നൽകുന്നുണ്ടോ?

## മികച്ച പ്രയോഗങ്ങൾ

1. **ആദ്യമേയും പലപ്പോഴും പരിശോധന നടത്തുക** - വികസന സമയത്ത് മാത്രമല്ല, പ്രശ്നങ്ങൾ ഉണ്ടാകുമ്പോഴും ഇൻസ്പെക്ടർ ഉപയോഗിക്കുക
2. **സാരളമായി ആരംഭിക്കുക** - സങ്കീർണ്ണമായ ടൂൾ കോൾകൾക്കുമുമ്പ് അടിസ്ഥാന കണക്ടിവിറ്റി പരിശോധിക്കുക
3. **സ്കീമ പരിശോധിക്കുക** - പല പിശകുകളും പാരാമീറ്റർ തരം പൊരുത്തക്കേടുകളിൽ നിന്ന് ഉണ്ടാകും
4. **പിശക് സന്ദേശങ്ങൾ വായിക്കുക** - MCP പിശകുകൾ സാധാരണയായി വിശദീകരണപരമാണ്
5. **ഇൻസ്പെക്ടർ തുറന്നുകൊണ്ടിരിക്കൂ** - വികസനസമയം പ്രശ്നങ്ങൾ പിടിക്കാൻ സഹായിക്കുന്നു
