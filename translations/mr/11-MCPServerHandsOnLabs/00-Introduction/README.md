## 🎯 हा प्रयोग काय समाविष्ट करतो

हा परिचयात्मक प्रयोग Model Context Protocol (MCP) सर्व्हर तयार करण्याबाबत डेटाबेस एकत्रीकरणासह सविस्तर आढावा प्रदान करतो. तुम्हाला व्यवसाय केस, तांत्रिक आर्किटेक्चर, आणि https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail येथील Zava Retail विश्लेषण वापर प्रकरणाद्वारे वास्तविक जगातील अनुप्रयोग समजतील.

## आढावा

**Model Context Protocol (MCP)** AI सहाय्यकांना सुरक्षितपणे बाह्य डेटास्रोतांशी रिअल-टाइम मध्ये प्रवेश आणि संवाद साधण्यास सक्षम करते. डेटाबेस एकत्रीकरणासह MCP पॉवरफुल डेटा संचालित AI अनुप्रयोग सादर करते.

हा शिक्षण मार्ग तुम्हाला उत्पादनासाठी तयार MCP सर्व्हर तयार करण्याचे शिक्षण देतो जे AI सहाय्यकांना पोसgreSQL द्वारे किरकोळ विक्री डेटाशी कनेक्ट करतो, जिथे रो लेव्हल सिक्युरिटी, सेमांटिक शोध, आणि मल्टी-टेनेन्ट डेटा प्रवेश यांसारख्या एंटरप्राइझ पॅटर्नची अंमलबजावणी होते.

- डेटाबेससह MCP सर्व्हर आर्किटेक्चरच्या **मुख्य घटकांची ओळख करा**
- Zava Retail वापर प्रकरण आणि त्याच्या व्यवसाय आवश्यकता **समजून घ्या**

- या संपूर्ण शिक्षण मार्गात वापरलेले साधने आणि तंत्रज्ञान **यादी करा**

### MCP उपाय

Model Context Protocol या आव्हानांना पॅटर्न दिला आहे:

- **रिअल-टाइम डेटा प्रवेश**: AI सहाय्यक थेट डेटाबेस आणि API क्वेरी करतात
- **सुरक्षित एकत्रीकरण**: प्रमाणीकरण आणि परवानग्यांसह नियंत्रित प्रवेश
- **नैसर्गिक भाषा इंटरफेस**: व्यवसाय वापरकर्ते सोप्या इंग्रजीत प्रश्न विचारतात
- **मानकीकृत प्रोटोकॉल**: विविध AI मंच आणि साधनांवर कार्य करते

### मुख्य घटक

#### **1. MCP सर्व्हर लेयर**
- **FastMCP फ्रेमवर्क**: आधुनिक Python MCP सर्व्हर अंमलबजावणी
- **टूल नोंदणी**: प्रकार सुरक्षिततेसह घोषणाबद्ध टूल व्याख्या
- **विनंती संदर्भ**: वापरकर्ता ओळख आणि सत्र व्यवस्थापन
- **त्रुटी हाताळणी**: मजबूत त्रुटी व्यवस्थापन आणि लॉगिंग

#### **2. डेटाबेस एकत्रीकरण स्तर**
- **कनेक्शन पूलिंग**: कार्यक्षम asyncpg कनेक्शन व्यवस्थापन
- **स्कीमा पुरवठादार**: डायनॅमिक टेबल स्कीमा शोध
- **क्वेरी अंमलबजावणूकर्ता**: RLS संदर्भासह सुरक्षित SQL अंमलबजावणी
- **व्यवहार व्यवस्थापन**: ACID अनुरूपता आणि रोलबॅक हाताळणी

#### **3. सुरक्षा स्तर**
- **रो लेव्हल सिक्युरिटी**: मल्टी-टेनेन्ट डेटा वेगळेपणासाठी PostgreSQL RLS
- **वापरकर्ता ओळख**: स्टोअर मॅनेजर प्रमाणीकरण आणि प्राधिकार
- **प्रवेश नियंत्रण**: सूक्ष्म परवानग्या आणि लेखापरीक्षण ट्रेल्स
- **इनपुट वैधता**: SQL इंजेक्शन प्रतिबंध आणि क्वेरी सत्यापन

#### **4. AI सुधारणा स्तर**
- **सेमांटिक शोध**: उत्पादन शोधासाठी व्हेक्टर एम्बेडिंग्ज
- **Azure OpenAI एकत्रीकरण**: मजकूर एम्बेडिंग निर्माण
- **समानता अल्गोरिदम**: pgvector कोसाईन समानता शोध
- **शोध ऑप्टिमायझेशन**: निर्देशांकाकरण आणि कार्यक्षमता सुधारणा

### परिस्थिती 1: स्टोअर मॅनेजरचा कामगिरी पुनरावलोकन

**वापरकर्ता**: सारा, सिएटल स्टोअर मॅनेजर  
**ध्येय**: गेल्या तिमाहीतील विक्री कामगिरी विश्लेषण करा

**नैसर्गिक भाषा क्वेरी**:
> "माझ्या स्टोअरसाठी Q4 2024 मध्ये उत्पन्नानुसार टॉप 10 उत्पादने दाखवा"

**काय होते**:
1. VS Code AI चॅट MCP सर्व्हरकडे क्वेरी पाठवतो
2. MCP सर्व्हर सारा यांच्या स्टोअर संदर्भ (सिएटल) ओळखतो
3. RLS धोरणे सिएटल स्टोअरच्या डेटावर फिल्टर करतात
4. SQL क्वेरी तयार आणि अंमलात आणली जाते
5. निकाल स्वरूपित करून AI चॅटला परत दिले जातात
6. AI विश्लेषण आणि अंतर्दृष्टी प्रदान करतो

### परिस्थिती 2: सेमांटिक शोधाद्वारे उत्पादन शोध

**वापरकर्ता**: माइक, इन्व्हेंटरी मॅनेजर  
**ध्येय**: ग्राहकांच्या विनंतीशी समान असणारी उत्पादने शोधा

**नैसर्गिक भाषा क्वेरी**:
> "कोणती उत्पादने आपण विकतो जी 'आऊटडोअर वापरासाठी वॉटरप्रूफ इलेक्ट्रिकल कनेक्टर्स' सारखी असतील?"

**काय होते**:
1. क्वेरी सेमांटिक शोध टूलने प्रक्रिया केली जाते
2. Azure OpenAI एम्बेडिंग व्हेक्टर तयार करतो
3. pgvector समानता शोध करतो
4. संबंधित उत्पादने महत्त्वानुसार क्रमवारी लावली जातात
5. निकालांमध्ये उत्पादन तपशील आणि उपलब्धता असते

## 🔒 सुरक्षा आणि मल्टी-टेनेन्सी सखोल परिचय

आमच्या अंमलबजावणीत एंटरप्राइझ-ग्रेड सुरक्षा प्राधान्यामुळे:

### रो लेव्हल सिक्युरिटी (RLS)

PostgreSQL RLS डेटा वेगळेपण सुनिश्चित करते:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### वापरकर्ता ओळख व्यवस्थापन

प्रत्येक MCP कनेक्शन मध्ये समाविष्ट असते:
- **स्टोअर मॅनेजर आयडी**: RLS संदर्भासाठी अद्वितीय ओळख
- **भूमिका नेमणूक**: परवानग्या आणि प्रवेश स्तर
- **सत्र व्यवस्थापन**: सुरक्षित प्रमाणीकरण टोकन्स
- **लेखापरीक्षण लॉगिंग**: पूर्ण प्रवेश इतिहास

### डेटा संरक्षण

सुरक्षा चे अनेक स्तर:
- **कनेक्शन एन्क्रिप्शन**: सर्व डेटाबेस कनेक्शनसाठी TLS
- **SQL इंजेक्शन प्रतिबंध**: फक्त पॅरामीटरयुक्त क्वेर्या
- **इनपुट वैधता**: व्यापक विनंती सत्यापन
- **त्रुटी हाताळणी**: त्रुटी संदेशांमध्ये संवेदनशील डेटा नाही
