# MCP निरीक्षकासह डीबगिंग

> [!NOTE]
> `--sse` वापरून आणि `/sse` मध्ये संपणाऱ्या URL च्या कमांड्स परंपरागत HTTP+SSE
> ट्रान्सपोर्टची चाचणी करतात. नवीन MCP `2026-07-28` सर्व्हर साठी, असा निरीक्षक आवृत्ती वापरा जी
> Streamable HTTP ला समर्थन देते आणि त्याऐवजी तो ट्रान्सपोर्ट निवडा.

**MCP निरीक्षक** हा एक आवश्यक डीबगिंग साधन आहे जे तुम्हाला तुमचे MCP सर्व्हर संवादात्मकपणे तपासणे आणि त्रुटी शोधण्यास अनुमती देते, पूर्ण AI होस्ट अॅप्लिकेशनची गरज न पडता. याला "MCP साठी पोस्टमन" म्हणून विचार करा - ते विनंत्या पाठवण्यासाठी, प्रतिक्रिया पहाण्यासाठी आणि तुमचा सर्व्हर कसा वागत आहे हे समजून घेण्यासाठी एक दृश्य इंटरफेस प्रदान करते.

## MCP निरीक्षक का वापरायचा?

MCP सर्व्हर तयार करत असताना, तुम्हाला खालील अडचणी येऊ शकतात:

- **"माझा सर्व्हर चालू आहे का?"** - निरीक्षक कनेक्शन स्थिती दाखवतो
- **"माझी साधने योग्य प्रकारे नोंदणीकृत आहेत का?"** - निरीक्षक सर्व उपलब्ध साधने दाखवतो
- **"प्रतिक्रियेचा फॉरमॅट काय आहे?"** - निरीक्षक पूर्ण JSON प्रतिक्रिया दाखवतो
- **"हे साधन का काम करत नाही?"** - निरीक्षक तपशीलवार त्रुटी संदेश दाखवतो

## पूर्वतयारी

- Node.js 18+ संस्थापित केलेले
- npm (Node.js सोबत येते)
- तपासण्यासाठी एक MCP सर्व्हर (पहा [Module 3.1 - प्रथम सर्व्हर](../01-first-server/README.md))

## स्थापना

### पर्याय 1: npx सह चालवा (द्रुत तपासणीसाठी शिफारसीय)

```bash
npx @modelcontextprotocol/inspector
```

### पर्याय 2: जागतिक पातळीवर स्थापित करा

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### पर्याय 3: तुमच्या प्रकल्पात जोडा

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` मध्ये जोडा:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## तुमच्या सर्व्हरशी कनेक्ट होणे

### stdio सर्व्हर (स्थानिक प्रक्रिया)

जे सर्व्हर मानक इनपुट/आउटपुटद्वारे संवाद साधतात:

```bash
# Python सर्व्हर
npx @modelcontextprotocol/inspector python -m your_server_module

# Node.js सर्व्हर
npx @modelcontextprotocol/inspector node ./build/index.js

# पर्यावरण चलांसह
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP सर्व्हर (नेटवर्क)

HTTP सेवा म्हणून चालणारे सर्व्हरसाठी:

1. प्रथम तुमचा सर्व्हर सुरू करा:
   ```bash
   python server.py  # सर्व्हर http://localhost:8080 वर चालू आहे
   ```

2. निरीक्षक सुरू करा आणि कनेक्ट करा:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## साधने तपासणी

### उपलब्ध साधने यादीबद्ध करणे

1. **Tools** टॅबवर क्लिक करा
2. निरीक्षक आपोआप `tools/list` कॉल करतो
3. तुम्हाला सर्व नोंदणीकृत साधने दिसतील ज्यात:
   - साधनाचे नाव
   - वर्णन
   - इनपुट स्कीमा (पॅरामीटर्स)

### साधन चालवणे

1. यादीतून एक साधन निवडा
2. फॉर्ममध्ये आवश्यक पॅरामीटर्स भरा
3. **Run Tool** वर क्लिक करा
4. निकाल पॅनेलमध्ये प्रतिसाद पहा

**उदाहरण: कॅल्क्युलेटर साधन तपासणी**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### साधनाच्या त्रुटी डीबगिंग

जेव्हा साधन अयशस्वी होते, निरीक्षक दाखवतो:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

सामान्य त्रुटी संकेतकोड:
| कोड | अर्थ |
|------|---------|
| -32700 | पार्स त्रुटी (अवैध JSON) |
| -32600 | अवैध विनंती |
| -32601 | पद्धत सापडली नाही |
| -32602 | अवैध पॅरामीटर्स |
| -32603 | अंतर्गत त्रुटी |

## संसाधने तपासणी

### संसाधने यादीबद्ध करणे

1. **Resources** टॅबवर क्लिक करा
2. निरीक्षक `resources/list` कॉल करतो
3. तुम्हाला दिसेल:
   - संसाधनांचे URI
   - नावे आणि वर्णने
   - MIME प्रकार

### संसाधन वाचणे

1. संसाधन निवडा
2. **Read Resource** वर क्लिक करा
3. परत आलेले सामग्री पहा

**उदाहरण आउटपुट:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

---

## प्रॉम्प्ट तपासणी

### प्रॉम्प्ट्स यादीबद्ध करणे

1. **Prompts** टॅबवर क्लिक करा
2. निरीक्षक `prompts/list` कॉल करतो
3. उपलब्ध प्रॉम्प्ट टेम्पलेट्स पहा

### प्रॉम्प्ट मिळवणे

1. प्रॉम्प्ट निवडा
2. आवश्यक तर्क भरा
3. **Get Prompt** वर क्लिक करा
4. रेंडर केलेले प्रॉम्प्ट संदेश पहा

## संदेश लॉग विश्लेषण

संदेश लॉगमध्ये सर्व MCP प्रोटोकॉल संदेश दिसतात. खाली दिलेली ट्रान्सक्रिप्ट ही
परंपरागत `2025-11-25` सर्व्हरची असून त्यात काढलेला `initialize` हँडशेक समाविष्ट आहे. एका
`2026-07-28` सर्व्हरमध्ये स्व-समाविष्ट विनंती मेटाडेटा आणि `server/discover`
वापरला जातो.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### काय पहावे

- **विनंती/प्रतिक्रिया जोड्या**: प्रत्येक `→` साठी एक जुळणारा `←` पाहिजे
- **त्रुटी संदेश**: प्रतिक्रियांमध्ये `"error"` पाहा
- **वेळेचे अंतर**: मोठे अंतर कार्यक्षमता समस्या दर्शवू शकते
- **प्रोटोकॉल आवृत्ती**: सर्व्हर आणि क्लायंट आवृत्तीत सहमती आहे याची खात्री करा

## सामान्य डीबगिंग परिस्थिती

### परिस्थिती 1: सर्व्हर कनेक्ट होत नाही

**लक्षणे:** निरीक्षक "Disconnected" दाखवतो किंवा "Connecting..." वर अडकतो

**तपासणी यादी:**
1. ✅ सर्व्हर कमांड बरोबर आहे का?
2. ✅ सर्व अवलंबने स्थापित आहेत का?
3. ✅ सर्व्हरचा मार्ग पूर्ण का आहे की सध्याच्या डायरेक्टरीसंबंधी आहे का?
4. ✅ आवश्यक पर्यावरण बदल्यांच्या सेटिंग्ज आहेत का?

**डीबगिंग टप्पे:**
```bash
# प्रथम सर्व्हर मॅन्युअली तपासा
python -c "import your_server_module; print('OK')"

# आयात त्रुटींसाठी तपासा
python -m your_server_module 2>&1 | head -20

# MCP SDK स्थापित आहे का याची पुष्टी करा
pip show mcp
```

### परिस्थिती 2: साधने दिसत नाहीत

**लक्षणे:** Tools टॅब रिकामा आहे

**संभाव्य कारणे:**
1. सर्व्हर सुरू होताना साधने नोंदणीकृत झाली नाहीत
2. सर्व्हर सुरू झाल्यानंतर क्रॅश झाला
3. `tools/list` हँडलर रिकामा ऐरे परत करत आहे

**डीबगिंग टप्पे:**
1. `tools/list` प्रतिसादासाठी संदेश लॉग तपासा
2. तुमच्या साधन नोंदणी कोडमध्ये लॉगिंग जोडा
3. `@mcp.tool()` डेकोरेटर्स अस्तित्वात आहेत का तपासा (पायथन)

### परिस्थिती 3: साधन त्रुटी परत करते

**लक्षणे:** साधन कॉल त्रुटी प्रतिसाद परत करते

**डीबगिंग पध्दत:**
1. त्रुटी संदेश काळजीपूर्वक वाचा
2. पॅरामीटर प्रकार स्कीमाशी जुळतात का तपासा
3. तपशीलवार त्रुटी संदेशांसाठी try/catch जोडा
4. स्टॅक ट्रेससाठी सर्व्हर लॉग तपासा

**सुधारित त्रुटी हाताळणीचे उदाहरण:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # इथे टूल लॉजिक
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### परिस्थिती 4: संसाधन सामग्री रिकामी आहे

**लक्षणे:** संसाधन परत येते परंतु सामग्री रिकामी किंवा null आहे

**तपासणी यादी:**
1. ✅ फाईलचा मार्ग किंवा URI बरोबर आहे
2. ✅ सर्व्हरला संसाधन वाचण्याची परवानगी आहे
3. ✅ संसाधन सामग्री योग्यरित्या परत केली जात आहे

## सर्वोत्तम पद्धती

1. **लवकर आणि वारंवार तपासा** - विकासानुसार Inspector वापरा, फक्त काही गोष्टी तुटल्यावर नाही
2. **सोप्या गोष्टींपासून सुरू करा** - गुंतागुंतीच्या साधन कॉल्सपूर्वी मूलभूत कनेक्टिव्हिटी तपासा
3. **योजना तपासा** - अनेक चुका पॅरामीटर प्रकारांच्या विसंगतींपासून येतात
4. **त्रुटी संदेश वाचा** - MCP चुका सहसा वर्णनात्मक असतात
5. **Inspector उघडा ठेवा** - विकास करताना समस्या टिपण्यास मदत करते
