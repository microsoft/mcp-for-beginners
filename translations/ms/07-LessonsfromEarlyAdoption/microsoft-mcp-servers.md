## 🔧 Memahami Pelayan MCP: Panduan Untuk Pemula

### Apakah Pelayan MCP?

Sebagai pemula kepada Protokol Konteks Model (MCP), anda mungkin tertanya-tanya: "Apakah sebenarnya pelayan MCP, dan mengapa saya patut ambil peduli?" Mari kita mulakan dengan satu analogi mudah.

Fikirkan pelayan MCP sebagai pembantu khusus yang membantu rakan pembantu AI kod anda (seperti GitHub Copilot) berhubung dengan alat dan perkhidmatan luaran. Sama seperti bagaimana anda menggunakan pelbagai aplikasi pada telefon anda untuk tugasan berbeza—satu untuk cuaca, satu untuk navigasi, satu untuk perbankan—pelayan MCP memberikan pembantu AI anda keupayaan untuk berinteraksi dengan pelbagai alat dan perkhidmatan pembangunan.

### Masalah Yang Diselesaikan Oleh Pelayan MCP

Sebelum pelayan MCP, jika anda ingin:
- Periksa sumber Azure anda
- Cipta isu GitHub
- Pertanyaan pangkalan data anda
- Mencari maklumat dalam dokumentasi

Anda perlu berhenti menulis kod, buka penyemak imbas, pergi ke laman web yang sesuai, dan lakukan tugasan ini secara manual. Pertukaran konteks yang berterusan ini memecah aliran kerja anda dan mengurangkan produktiviti.

### Bagaimana Pelayan MCP Mengubah Pengalaman Pembangunan Anda

Dengan pelayan MCP, anda boleh kekal dalam persekitaran pembangunan anda (VS Code, Visual Studio, dan lain-lain) dan hanya minta pembantu AI anda mengendalikan tugasan ini. Contohnya:

**Ganti aliran kerja tradisional ini:**
1. Berhenti menulis kod
2. Buka penyemak imbas
3. Pergi ke portal Azure
4. Semak butiran akaun penyimpanan
5. Kembali ke VS Code
6. Sambung menulis kod

**Anda kini boleh lakukan ini:**
1. Tanya AI: "Apakah status akaun simpanan Azure saya?"
2. Teruskan menulis kod dengan maklumat yang diberikan

### Manfaat Utama Untuk Pemula

#### 1. 🔄 **Kekal Dalam Keadaan Aliran Anda**
- Tidak perlu tukar antara pelbagai aplikasi
- Kekalkan fokus pada kod yang anda tulis
- Kurangkan beban mental mengurus pelbagai alat

#### 2. 🤖 **Gunakan Bahasa Semula Jadi Daripada Perintah Kompleks**
- Daripada menghafal sintaks SQL, terangkan data yang anda perlukan
- Daripada ingat perintah Azure CLI, jelaskan apa yang anda ingin capai
- Biarkan AI mengendalikan butiran teknikal sementara anda fokus pada logik

#### 3. 🔗 **Sambungkan Pelbagai Alat Bersama**
- Cipta aliran kerja yang kuat dengan menggabungkan perkhidmatan berbeza
- Contoh: "Dapatkan semua isu GitHub terkini dan cipta item kerja Azure DevOps yang sepadan"
- Bina automasi tanpa menulis skrip kompleks

#### 4. 🌐 **Akses Ekosistem Yang Berkembang**
- Manfaatkan pelayan yang dibina oleh Microsoft, GitHub, dan syarikat lain
- Campur dan padankan alat dari vendor berbeza secara lancar

#### 5. 🛠️ **Belajar Dengan Melakukan**
- Mula dengan pelayan siap guna untuk fahami konsep
- Secara beransur bina pelayan anda sendiri semasa lebih selesa
- Gunakan SDK dan dokumentasi yang ada untuk membimbing pembelajaran

## Memulakan MCP di VS Code dan Visual Studio 🚀

Pemasangan pelayan MCP ini mudah jika anda menggunakan Visual Studio Code atau Visual Studio 2022 dengan GitHub Copilot.

### Pemasangan VS Code

Berikut adalah proses asas untuk VS Code:

1. **Aktifkan Mod Ejen**: Dalam VS Code, tukar ke mod Ejen di tetingkap Copilot Chat
2. **Konfigurasi Pelayan MCP**: Tambah konfigurasi pelayan ke fail settings.json VS Code anda
3. **Mula Pelayan**: Klik butang "Start" untuk setiap pelayan yang anda ingin gunakan
4. **Pilih Alat**: Pilih pelayan MCP yang ingin diaktifkan untuk sesi semasa

Untuk arahan pemasangan terperinci, lihat [dokumentasi MCP VS Code](https://code.visualstudio.com/docs/copilot/copilot-mcp).

> **💡 Petua Pro: Urus Pelayan MCP seperti Pro!**
> 
> Pandangan Ekstensi VS Code kini termasuk [UI baru yang berguna untuk mengurus Pelayan MCP yang dipasang](https://code.visualstudio.com/docs/copilot/chat/mcp-servers#_use-mcp-tools-in-agent-mode)! Anda mendapat akses cepat untuk memulakan, menghentikan, dan mengurus mana-mana Pelayan MCP yang dipasang menggunakan antaramuka yang jelas dan mudah. Cuba ia!

### Pemasangan Visual Studio 2022

Untuk Visual Studio 2022 (versi 17.14 atau lebih baru):

1. **Aktifkan Mod Ejen**: Klik dropdown "Ask" dalam tetingkap GitHub Copilot Chat dan pilih "Agent"
2. **Cipta Fail Konfigurasi**: Cipta fail `.mcp.json` dalam direktori solusi anda (lokasi disyorkan: `<SOLUTIONDIR>\.mcp.json`)
3. **Konfigurasi Pelayan**: Tambah konfigurasi pelayan MCP menggunakan format standard MCP
4. **Kelulusan Alat**: Apabila diminta, luluskan alat yang anda ingin gunakan dengan kebenaran skop yang sesuai

Untuk arahan pemasangan Visual Studio terperinci, lihat [dokumentasi MCP Visual Studio](https://learn.microsoft.com/visualstudio/ide/mcp-servers).

Setiap pelayan MCP mempunyai keperluan konfigurasi tersendiri (rentetan sambungan, pengesahan, dan lain-lain), tetapi corak pemasangannya konsisten merentas kedua-dua IDE.

**Apa yang ia lakukan**: Pelayan Microsoft Learn Docs MCP ialah perkhidmatan yang dihoskan di awan yang menyediakan pembantu AI dengan akses masa nyata kepada dokumentasi rasmi Microsoft melalui Protokol Konteks Model. Ia berhubung dengan `https://learn.microsoft.com/api/mcp` dan membolehkan carian semantik merentasi Microsoft Learn, dokumentasi Azure, dokumentasi Microsoft 365, dan sumber rasmi Microsoft lain.

**Mengapa ia berguna**: Walaupun nampak seperti "hanya dokumentasi," pelayan ini sebenarnya penting untuk setiap pembangun yang menggunakan teknologi Microsoft. Salah satu rungutan terbesar dari pembangun .NET tentang pembantu kod AI ialah mereka tidak terkini dengan keluaran .NET dan C# terbaru. Pelayan Microsoft Learn Docs MCP menyelesaikan ini dengan menyediakan akses masa nyata kepada dokumentasi terkini, rujukan API, dan amalan terbaik. Sama ada anda bekerja dengan SDK Azure terbaru, meneroka ciri baru C# 13, atau melaksanakan corak Aspire terkini, pelayan ini memastikan pembantu AI anda mempunyai akses kepada maklumat berwibawa dan terkini yang diperlukan untuk menjana kod yang tepat dan moden.

**Penggunaan dunia sebenar**: "Apakah arahan az cli untuk mencipta aplikasi kontena Azure mengikut dokumentasi rasmi Microsoft Learn?" atau "Bagaimana saya mengkonfigurasi Entity Framework dengan suntikan pergantungan dalam ASP.NET Core?" Atau bagaimana pula dengan "Semak kod ini supaya sepadan dengan cadangan prestasi dalam Dokumentasi Microsoft Learn." Pelayan menyediakan liputan komprehensif merentasi Microsoft Learn, dokumen Azure, dan dokumentasi Microsoft 365 menggunakan carian semantik maju untuk mencari maklumat paling relevan berdasarkan konteks. Ia mengembalikan sehingga 10 bahagian kandungan berkualiti tinggi dengan tajuk artikel dan URL, sentiasa mengakses dokumentasi Microsoft terkini sebaik sahaja ia diterbitkan.

**Contoh ditonjolkan**: Pelayan ini mendedahkan alat `microsoft_docs_search` yang melakukan carian semantik terhadap dokumentasi teknikal rasmi Microsoft. Setelah dikonfigurasi, anda boleh tanya soalan seperti "Bagaimana saya melaksanakan pengesahan JWT dalam ASP.NET Core?" dan dapatkan jawapan terperinci dan rasmi dengan pautan sumber. Kualiti carian sangat baik kerana ia memahami konteks – bertanya tentang "kontena" dalam konteks Azure akan mengembalikan dokumentasi Azure Container Instances, manakala istilah sama dalam konteks .NET mengembalikan maklumat koleksi C# yang relevan.

Ini sangat berguna untuk perpustakaan dan kes penggunaan yang berubah dengan pantas atau baru dikemas kini. Sebagai contoh, dalam beberapa projek pengekodan baru-baru ini saya ingin memanfaatkan ciri dalam keluaran Aspire dan Microsoft.Extensions.AI terkini. Dengan memasukkan pelayan Microsoft Learn Docs MCP, saya dapat memanfaatkan bukan sahaja dokumentasi API tetapi juga panduan dan tutorial yang baru diterbitkan.

### 2. ☁️ Pelayan Azure MCP

[![Pasang dalam VS Code](https://img.shields.io/badge/VS_Code-Install_Azure_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D) [![Pasang dalam VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Azure_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Azure/azure-mcp)

**Apa yang ia lakukan**: Pelayan Azure MCP ialah suite komprehensif yang terdiri lebih daripada 15 penyambung perkhidmatan Azure khusus yang membawa seluruh ekosistem Azure ke dalam aliran kerja AI anda. Ini bukan hanya pelayan tunggal – ia adalah koleksi berkuasa termasuk pengurusan sumber, sambungan pangkalan data (PostgreSQL, SQL Server), analisis log Azure Monitor dengan KQL, integrasi Cosmos DB, dan banyak lagi.

**Mengapa ia berguna**: Selain hanya mengurus sumber Azure, pelayan ini secara dramatik meningkatkan kualiti kod apabila bekerja dengan SDK Azure. Apabila anda menggunakan Azure MCP dalam mod Ejen, ia bukan saja membantu anda menulis kod – ia membantu anda menulis kod Azure yang *lebih baik* yang mengikut corak pengesahan semasa, amalan terbaik pengendalian ralat, dan memanfaatkan ciri SDK terkini. Daripada mendapat kod generik yang mungkin berfungsi, anda mendapat kod yang mengikuti corak yang disyorkan Azure untuk beban kerja pengeluaran.

**Modul utama termasuk**:
- **🗄️ Penyambung Pangkalan Data**: Akses bahasa semula jadi terus ke Azure Database for PostgreSQL dan SQL Server
- **📊 Azure Monitor**: Analisis log dipacu KQL dan pandangan operasi
- **🌐 Pengurusan Sumber**: Pengurusan kitaran hayat sumber Azure penuh
- **🔐 Pengesahan**: Pola DefaultAzureCredential dan identiti terurus
- **📦 Perkhidmatan Penyimpanan**: Operasi Blob Storage, Queue Storage, dan Table Storage
- **🚀 Perkhidmatan Kontena**: Pengurusan Azure Container Apps, Container Instances, dan AKS
- **Dan banyak penyambung khusus lain**

**Penggunaan dunia sebenar**: "Senarai akaun simpanan Azure saya", "Pertanyaan ruang kerja Log Analytics untuk ralat dalam sejam terakhir", atau "Tolong bantu bina aplikasi Azure menggunakan Node.js dengan pengesahan yang betul"

**Senario demo penuh**: Berikut ialah penjelajahan lengkap yang menunjukkan kuasa menggabungkan Azure MCP dengan sambungan GitHub Copilot untuk Azure dalam VS Code. Apabila anda memasang kedua-duanya dan berikan arahan:

> "Buat skrip Python yang memuat naik fail ke Azure Blob Storage menggunakan pengesahan DefaultAzureCredential. Skrip tersebut harus menyambung ke akaun storan Azure saya yang bernama 'mycompanystorage', memuat naik ke kontena bernama 'documents', mencipta fail ujian dengan cap waktu semasa untuk dimuat naik, menangani ralat dengan cermat dan menyediakan output yang informatif, mengikuti amalan terbaik Azure untuk pengesahan dan pengendalian ralat, termasuk komen yang menerangkan bagaimana pengesahan DefaultAzureCredential berfungsi, serta menjadikan skrip itu tersusun rapi dengan fungsi dan dokumentasi yang betul."

Pelayan Azure MCP akan menghasilkan skrip Python lengkap dan sedia untuk produksi yang:
- Menggunakan SDK Azure Blob Storage terkini dengan corak async yang betul
- Melaksanakan DefaultAzureCredential dengan penjelasan rantai fallback yang komprehensif
- Menyertakan pengendalian ralat yang kukuh dengan jenis pengecualian Azure yang khusus
- Mengikuti amalan terbaik SDK Azure untuk pengurusan sumber dan pengendalian sambungan
- Menyediakan pelaporan terperinci dan output konsol yang informatif
- Mencipta skrip yang terstruktur dengan fungsi, dokumentasi, dan penunjuk jenis

Apa yang membuat ini luar biasa ialah tanpa Azure MCP, anda mungkin mendapat kod storan blob generik yang berfungsi tetapi tidak mengikuti corak Azure terkini. Dengan Azure MCP, anda mendapat kod yang memanfaatkan kaedah pengesahan terkini, menangani senario ralat khusus Azure, dan mengikuti amalan yang disyorkan Microsoft untuk aplikasi produksi.

**Contoh utama**: Saya menghadapi kesukaran mengingat arahan khusus untuk CLI `az` dan `azd` untuk penggunaan ad-hoc. Sentiasa ada proses dua langkah bagi saya: pertama cari sintaks, kemudian jalankan arahan. Saya sering hanya masuk ke portal dan klik sana sini untuk menyelesaikan kerja kerana saya tidak mahu mengaku saya tidak dapat mengingat sintaks CLI. Boleh sahaja terangkan apa yang saya mahu adalah luar biasa, dan lebih baik boleh lakukan itu tanpa meninggalkan IDE saya!

Ada senarai kegunaan yang hebat di [repositori Azure MCP](https://github.com/Azure/azure-mcp?tab=readme-ov-file#-what-can-you-do-with-the-azure-mcp-server) untuk memulakan anda. Untuk panduan persediaan komprehensif dan pilihan konfigurasi lanjutan, lihat [dokumentasi rasmi Azure MCP](https://learn.microsoft.com/azure/developer/azure-mcp-server/).

### 3. 🐙 Pelayan GitHub MCP

[![Pasang di VS Code](https://img.shields.io/badge/VS_Code-Install_Server-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D) [![Pasang di VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Server-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/github/github-mcp-server)

**Apa yang ia lakukan**: Pelayan GitHub MCP rasmi menyediakan integrasi lancar dengan keseluruhan ekosistem GitHub, menawarkan kedua-dua akses jauh dihoskan dan pilihan penerapan Docker tempatan. Ini bukan sahaja tentang operasi repositori asas – ia adalah kit alat komprehensif yang merangkumi pengurusan GitHub Actions, aliran kerja pull request, penjejakan isu, pengimbasan keselamatan, notifikasi, dan kebolehan automasi lanjutan.

**Mengapa ia berguna**: Pelayan ini mengubah cara anda berinteraksi dengan GitHub dengan membawa pengalaman platform sepenuhnya terus ke persekitaran pembangunan anda. Daripada sentiasa bertukar antara VS Code dan GitHub.com untuk pengurusan projek, semakan kod, dan pemantauan CI/CD, anda boleh mengendalikan semuanya melalui arahan bahasa semula jadi sambil kekal fokus pada kod anda.

> **ℹ️ Nota: Jenis 'Ejen' Berbeza**
> 
> Jangan kelirukan Pelayan GitHub MCP ini dengan Coding Agent GitHub (ejen AI yang boleh anda tugaskan isu untuk tugas pengekodan automatik). Pelayan GitHub MCP berfungsi dalam mod Ejen VS Code untuk menyediakan integrasi API GitHub, sementara Coding Agent GitHub adalah ciri berasingan yang mencipta pull request apabila ditugaskan kepada isu GitHub.

**Keupayaan utama termasuk**:
- **⚙️ GitHub Actions**: Pengurusan lengkap pipeline CI/CD, pemantauan aliran kerja, dan pengendalian artifak
- **🔀 Pull Requests**: Cipta, semak, gabung, dan urus PR dengan penjejakan status komprehensif
- **🐛 Isu**: Pengurusan kitaran hayat isu penuh, komen, pelabelan, dan penugasan
- **🔒 Keselamatan**: Amaran imbasan kod, pengesanan rahsia, dan integrasi Dependabot
- **🔔 Notifikasi**: Pengurusan notifikasi pintar dan kawalan langganan repositori
- **📁 Pengurusan Repositori**: Operasi fail, pengurusan cawangan, dan pentadbiran repositori
- **👥 Kolaborasi**: Carian pengguna dan organisasi, pengurusan pasukan, dan kawalan akses

**Penggunaan dunia sebenar**: "Cipta pull request dari cawangan ciri saya", "Tunjukkan semua larian CI gagal minggu ini", "Senaraikan amaran keselamatan terbuka untuk repositori saya", atau "Cari semua isu yang ditugaskan kepada saya di seluruh organisasi saya"

**Mengapa ia berguna**: Penting untuk aliran kerja dokumentasi moden! MarkItDown mengendalikan pelbagai format fail yang mengagumkan sambil mengekalkan struktur dokumen penting seperti tajuk, senarai, jadual, dan pautan. - **Dokumen Pejabat**: PDF, PowerPoint (PPTX), Word (DOCX), Excel (XLSX/XLS)

- **Kandungan Web**: HTML, suapan RSS, URL YouTube, halaman Wikipedia
- **Format Data**: CSV, JSON, XML, fail ZIP (memproses kandungan secara rekursif)
- **Format Penerbitan**: EPub, buku nota Jupyter (.ipynb)
- **E-mel**: Mesej Outlook (.msg)
- **Lanjutan**: Integrasi Azure Document Intelligence untuk pemprosesan PDF yang dipertingkatkan

**Keupayaan lanjutan**: MarkItDown menyokong penerangan imej yang dikuasakan LLM (apabila disediakan dengan klien OpenAI), Azure Document Intelligence untuk pemprosesan PDF yang dipertingkatkan, transkripsi audio untuk kandungan ucapan, dan sistem plugin untuk mengembangkan kepada format fail tambahan.

**Penggunaan dunia sebenar**: "Tukar pembentangan PowerPoint ini ke Markdown untuk laman dokumentasi kami", "Ekstrak teks dari PDF ini dengan struktur tajuk yang betul", atau "Transformasikan hamparan Excel ini menjadi format jadual yang boleh dibaca"

**Contoh utama (diparafrasekan)**:

bahawa Markdown mengekalkan struktur dokumen dengan sedikit beban format.
Model bahasa biasanya menghasilkan Markdown, menjadikannya format yang berguna dan cekap token
untuk aliran kerja pemprosesan dokumen.

MarkItDown memang cekap dalam mengekalkan struktur dokumen, yang penting untuk aliran kerja AI. Sebagai contoh, ketika menukar pembentangan PowerPoint, ia mengekalkan organisasi slaid dengan tajuk yang betul, mengekstrak jadual sebagai jadual Markdown, memasukkan teks alternatif untuk imej, dan malah memproses nota pembentang. Carta ditukar menjadi jadual data yang boleh dibaca, dan Markdown hasil mengekalkan aliran logik pembentangan asal. Ini menjadikannya sempurna untuk memberi makan kandungan pembentangan ke dalam sistem AI atau mencipta dokumentasi daripada slaid sedia ada.

## 📋 Kesimpulan

Protokol Konteks Model (MCP) sedang mengubah cara pemaju berinteraksi dengan pembantu AI dan alat luaran. 10 pelayan MCP Microsoft ini menunjukkan kuasa integrasi AI yang standard, membolehkan aliran kerja lancar yang mengekalkan pemaju dalam keadaan fokus sambil mengakses keupayaan luaran yang berkuasa.

Dari integrasi ekosistem Azure yang komprehensif hingga alat khusus seperti Playwright untuk automasi pelayar dan MarkItDown untuk pemprosesan dokumen, pelayan ini mempamerkan bagaimana MCP boleh meningkatkan produktiviti di pelbagai senario pembangunan. Protokol standard memastikan bahawa alat-alat ini bekerjasama dengan lancar, mewujudkan pengalaman pembangunan yang padu.

Apabila ekosistem MCP terus berkembang, kekal terlibat dengan komuniti, meneroka pelayan baru, dan membina penyelesaian tersuai akan menjadi kunci untuk memaksimumkan produktiviti pembangunan anda. Sifat piawaian terbuka MCP bermakna anda boleh mencampur dan padankan alat dari vendor yang berbeza untuk mencipta aliran kerja yang sempurna mengikut keperluan khusus anda.
