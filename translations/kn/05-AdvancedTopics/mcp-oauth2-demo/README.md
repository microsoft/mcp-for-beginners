# ಎಂಸಿಪಿ OAuth2 ಡೆಮೊ

> [!WARNING]
> ಇದು ಸ್ಥಳೀಯ ಅಧ್ಯಯನ ಮಾದರಿ, ಉತ್ಪಾದನಾ ಅನುಮೋದನಾ ಸೇವೆ ಅಲ್ಲ. ಇದು
> ಸ್ಮರಣಶಕ್ತಿ ಗ್ರಾಹಕವನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು ಪ್ರಾರಂಭಿಕ ಸಮಯದಲ್ಲಿ ಹೊಸ ಸಹಿ ಕೀ ಅನ್ನು ರಚಿಸುತ್ತದೆ. ಎಂದಿಗೂ
> ಇದನ್ನು ಹಂಚಿಕೊಂಡ, ಡೀಫಾಲ್ಟ್ ಅಥವಾ ಮೂಲ-ನಿಯಂತ್ರಿತ ಗ್ರಾಹಕ ರಹಸ್ಯದೊಂದಿಗೆ ನಿಯೋಜಿಸಬೇಡಿ.

## ಪರಿಚಯ

OAuth2 ಬಳಕೆದಾರರ ಪ್ರಮಾಣೀಕರಣವನ್ನು ಹಂಚಿಕೊಳ್ಳದೆ ಸಂಪನ್ಮೂಲಗಳಿಗೆ ಸುರಕ್ಷಿತ ಪ್ರವೇಶವನ್ನು ಸಾಧಿಸುವುದಾದಾಗಿ ಕೈಗಾರಿಕಾ-ಮಾನಕ ಪ್ರೋಟೋಕಾಲ್ ಆಗಿದೆ. ಎಂಸಿಪಿ (ಮಾದರಿ ಪ್ರಾಸಂಗಿಕ ಪ್ರೋಟೋಕಾಲ್) ಅನುಷ್ಠಾನಗಳಲ್ಲಿ, OAuth2 ಎಂಸಿಪಿ ಸರ್ವರ್‌ಗಳು ಮತ್ತು ಅವುಗಳ ಉಪಕರಣಗಳಿಗೆ ಪ್ರವೇಶ ಮಾಡಲು ಗ್ರಾಹಕರು (ಉದಾಹರಣೆಗೆ AI ಏಜೆಂಟ್ಸ್) ಅನ್ನು ದೃಢೀಕರಿಸಲು ಮತ್ತು ಅನುಮೋದಿಸಲು ಬಲಶಾಲಿಯಾದ ಮಾರ್ಗವನ್ನು ಒದಗಿಸುತ್ತದೆ.

ಈ ಪಾಠವು ಸ್ಪ್ರಿಂಗ್ ಬೂಟ್ ಅನ್ನು ಬಳಸಿ ಎಂಸಿಪಿ ಸರ್ವರ್‌ಗಳಿಗೆ OAuth2 ಪ್ರಮಾಣೀಕರಣವನ್ನು ಹೇಗೆ ಅನುಷ್ಠಾನಗೊಳಿಸಬಹುದು ಎಂದು ತೋರಿಸುತ್ತದೆ, ಇದು ಉದ್ಯಮ ಮತ್ತು ಉತ್ಪಾದನಾ ನಿಯೋಜನೆಗಳ ಸಾಮಾನ್ಯ ಮಾದರಿಯಾಗಿದೆ.

## ಅಧ್ಯಯನ ಗುರಿಗಳು

ಈ ಪಾಠದ ಅಂತ್ಯಕ್ಕೆ ನೀವು:
- ಎಂಸಿಪಿ ಸರ್ವರ್‌ಗಳೊಂದಿಗೆ OAuth2 ಹೇಗೆ ಸಂಯೋಜಿತವಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಹೊರತುಪಡಿಸಿ ತಿಳಿದುಕೊಳ್ಳಿ
- ಟೋಕನ್ ನೀಡಿಕೆಗೆ ಸ್ಪ್ರಿಂಗ್ ಅನುಮೋದನಾ ಸರ್ವರ್ ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸಿ
- JWT ಆಧಾರಿತ ಪ್ರಮಾಣೀಕರಣದೊಂದಿಗೆ ಎಂಸಿಪಿ ಅಂತಿಮಬಿಂದುಗಳನ್ನು ರಕ್ಷಿಸಿ
- ಮೆಷಿನ್-ಟು-ಮೆಷಿನ್ ಸಂವಹನಕ್ಕಾಗಿ ಗ್ರಾಹಕ ಪ್ರಮಾಣಪತ್ರ ಪ್ರವರ್ತನೆಯನ್ನು ಸಂರಚಿಸಿ

## ಪೂರ್ವಾಪೇಕ್ಷೆಗಳು

- ಜಾವಾ ಮತ್ತು ಸ್ಪ್ರಿಂಗ್ ಬೂಟ್‌ನ ಮೂಲಭೂತ ತಿಳಿವು
- ಹಿಂದಿನ ಘಟಕಗಳಿಂದ ಎಂಸಿಪಿ ತತ್ತ್ವಜ್ಞಾನದ ಪರಿಚಯ
- ಮೆವೆನ ಅಥವಾ ಗ್ರೇಡ್ಲ್ ಅನುಸ್ಥಾಪಿತವಿದೆ

---

## ಯೋಜನೆ ಅವಲೋಕನ

ಈ ಯೋಜನೆ ಒಂದು **ಅತಿ ಸಣ್ಣ ಸ್ಪ್ರಿಂಗ್ ಬೂಟ್ ಅಪ್ಲಿಕೇಶನ್** ಆಗಿದ್ದು,

* ಒಂದು **ಸ್ಪ್ರಿಂಗ್ ಅನುಮೋದನಾ ಸರ್ವರ್** ಆಗಿದ್ದು (`client_credentials` ಪ್ರವರ್ತನೆಯ ಮೂಲಕ JWT ಪ್ರವೇಶ ಟೋಕನ್ಗಳನ್ನು ನೀಡುತ್ತದೆ), ಮತ್ತು  
* ಒಂದು **ಸಂಪನ್ಮೂಲ ಸರ್ವರ್** ಆಗಿದ್ದು ಅದರ ಸ್ವಂತ `/hello` ಅಂತಿಮಬಿಂದುವನ್ನು ರಕ್ಷಿಸುತ್ತದೆ.

ಇದು [ಸ್ಪ್ರಿಂಗ್ ಬ್ಲಾಗ್ ಪೋಸ್ಟ್ (2 ಏಪ್ರಿಲ್ 2025)](https://spring.io/blog/2025/04/02/mcp-server-oauth2) ನಲ್ಲಿ ತೋರಿಸಲಾದ ವ್ಯವಸ್ಥೆಯ ಹೋಲಿಕೆಯನ್ನು ಮಾಡುತ್ತದೆ.

---

## ತ್ವರಿತ ಪ್ರಾರಂಭ (ಸ್ಥಳೀಯ)

```bash
# ವಿಶಿಷ್ಟ ಸ್ಥಳೀಯ ಮೌಲ್ಯದ ಬಳಕೆ ಮಾಡಿ ಮತ್ತು ಸಾಧ್ಯವಾದಲ್ಲಿ ಅದನ್ನು ಶೆಲ್ ಇತಿಹಾಸದಿಂದ ಹೊರಗಿಟ್ಟು ಇಡಿ.
export OAUTH_CLIENT_SECRET="replace-with-a-random-local-secret"
mvn spring-boot:run

# ಟೋಕನ್ ಪಡೆಯಿರಿ
curl -u "mcp-client:${OAUTH_CLIENT_SECRET}" -d grant_type=client_credentials \
     http://localhost:8081/oauth2/token | jq -r .access_token > token.txt

# ರಕ್ಷಿತ ಅಂತಿಮ ಪಾಯಿಂಟ್ ಅನ್ನು ಕರೆ ಮಾಡಿ
curl -H "Authorization: Bearer $(cat token.txt)" http://localhost:8081/hello
```

---

## OAuth2 ಸಂರಚನೆಯನ್ನು ಪರೀಕ್ಷಿಸುವುದು

ಕೆಳಗಿನ ಹಂತಗಳನ್ನು ಅನುಸರಿಸಿ ನೀವು OAuth2 ಭದ್ರತಾ ಸಂರಚನೆಯನ್ನು ಪರೀಕ್ಷಿಸಬಹುದು:

### 1. ಸರ್ವರ್ ಚಲಿಸುತ್ತಿದ್ದು ಮತ್ತು ಭದ್ರಿತವಾಗಿರುವುದನ್ನು ದೃಢೀಕರಿಸಿ

```bash
# ಇದು 401 ಅನಧಿಕೃತವೆಂದು ತಿರುಗಿಸಬೇಕು, OAuth2 ಭದ್ರತೆ ಸಕ್ರಿಯವಿದ್ದುದನ್ನು ದೃಢಪಡಿಸುವಂತೆ
curl -v http://localhost:8081/
```

### 2. ಗ್ರಾಹಕ ಪ್ರಮಾಣಪತ್ರಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಪ್ರವೇಶ ಟೋಕನ್ಸನ್ನು ಪಡೆಯಿರಿ

```bash
# ಪೂರ್ಣ ಟೋಕೆನ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಪಡೆಯಿರಿ ಮತ್ತು ಹೊರತೆಗೆಯಿರಿ
curl -v -X POST http://localhost:8081/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -u "mcp-client:${OAUTH_CLIENT_SECRET}" \
  -d "grant_type=client_credentials&scope=mcp.access"

# ಅಥವಾ ಕೇವಲ ಟೋಕೆನ್ ಅನ್ನು ಹೊರತೆಗೆಯಲು (jq ಬೇಕು)
curl -s -X POST http://localhost:8081/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -u "mcp-client:${OAUTH_CLIENT_SECRET}" \
  -d "grant_type=client_credentials&scope=mcp.access" | jq -r .access_token > token.txt
```

ಪವರ್‌ಶೆಲ್‌ನಲ್ಲಿ, ಮೆವೆನ್ ಓಡಿಸುವ ಮುನ್ನ ಸ್ಥಳೀಯ ರಹಸ್ಯವನ್ನು ಹೊಂದಿಸಿ:

```powershell
$env:OAUTH_CLIENT_SECRET = "replace-with-a-random-local-secret"
mvn spring-boot:run
```

### 3. ಟೋಕನ್ನನ್ನು ಬಳಸಿ ರಕ್ಷಿತ ಅಂತಿಮಬಿಂದುಗೆ ಪ್ರವೇಶಿಸಿ

```bash
# ಸಂರಕ್ಷಿಸಲಾದ ಟೋಕನ್ ಬಳಕೆಮಾಡುವುದು
curl -H "Authorization: Bearer $(cat token.txt)" http://localhost:8081/hello

# ಅಥವಾ ನೇರವಾಗಿ ಟೋಕನ್ ಮೌಲ್ಯದಿಂದ
curl -H "Authorization: Bearer eyJra...token_value...xyz" http://localhost:8081/hello
```

"Hello from MCP OAuth2 Demo!" ಎಂಬ ಯಶಸ್ವಿ ಪ್ರತಿಕ್ರಿಯೆ OAuth2 ಸಂರಚನೆ ಸರಿಯಾಗಿರುವುದನ್ನು ದೃಢೀಕರಿಸುತ್ತದೆ.

## ಕಂಟೈನರ್ ನಿರ್ಮಾಣ

```bash
docker build -t mcp-oauth2-demo .
docker run --rm -p 8081:8081 \
  -e OAUTH_CLIENT_SECRET="$OAUTH_CLIENT_SECRET" \
  mcp-oauth2-demo
```

## ಉತ್ಪಾದನಾ ಭದ್ರತೆ

ಉತ್ಪಾದನಾ ನಿಯೋಜನೆಗಾಗಿ, ಈ ಪ್ರಕ್ರಿಯೆಯೊಳಗಿನ ಡೆಮೊ ಅನುಮೋದನಾ ಸರ್ವರ್ ಬದಲು ಸಮರ್ಪಿತ ಗುರುತಿನ ಒದಗಿಸಿದವರನ್ನು ಬಳಸಿ. ಗುರುತಪತ್ರಗಳನ್ನು ನಿರ್ವಹಿತ ರಹಸ್ಯ ಅಂಗಡಿಯಲ್ಲಿ ಸಂಗ್ರಹಿಸಿ, ಅವುಗಳನ್ನು ಚಲಾಯಿಸಿ, ಸತತ ಸಹಿ ಕೀಲಿಗಳನ್ನು ಬಳಸಿ, ವ್ಯಾಪ್ತಿಗಳನ್ನು ಸೀಮಿತಗೊಳಿಸಿ, ಮತ್ತು ಸ್ಪಷ್ಟ ಪ್ರಕಟಕರನ್ನು ಹೊಂದಿಸಿ. ದಯವಿಟ್ಟು ಗ್ರಾಹಕ ರಹಸ್ಯವನ್ನು ಮೂಲ ಕೌಡ್, ಕಂಟೈನರ್ ಇಮೇಜುಗಳು, ನಿಯೋಜನಾ ಕಡತಗಳು ಅಥವಾ கட்டளை ಉತ್ಪನ್ನದಲ್ಲಿ ಇಡಬೇಡಿ.

ಅಜೂರ್ ಕಂಟೈನರ್ ಅಪ್ಲಿಕೇಶನ್ಗಳಿಗಾಗಿ, ಮೌಲ್ಯವನ್ನು ಸಾಧ್ಯವಾದರೆ ಕೀ ವಾಲ್ಟ್ ಮೂಲಕ ಬೆಂಬಲಿತ ಕಂಟೈನರ್ ಅಪ್ಲಿಕೇಶನ್ಗಳು ರಹಸ್ಯವಾಗಿ ಸಂಗ್ರಹಿಸಿ, ನಂತರ ಕೇವಲ `OAUTH_CLIENT_SECRET` ಪರಿಸರ ಚರವನ್ನು ಮೂಲಕ ರಹಸ್ಯ ಉಲ್ಲೇಖವನ್ನು ತೆರೆದಿಡಿ.

## **ಅಜೂರ್ ಕಂಟೈನರ್ ಅಪ್ಲಿಕೇಶನ್ಗಳಿಗೆ** ನಿಯೋಜಿಸಿ

```bash
az containerapp up -n mcp-oauth2 \
  -g demo-rg -l westeurope \
  --image <your-registry>/mcp-oauth2-demo:latest \
  --ingress external --target-port 8081
```

ಇಂಗ್ರೆಸ್ FQDN ನಿಮ್ಮ **ಪ್ರಕಾಶಕರಾಗುತ್ತದೆ** (`https://<fqdn>`).  
ಅಜೂರ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ `*.azurecontainerapps.io` ಗಾಗಿ ಭರವಸೆಗಾರ TLS ಪ್ರಮಾಣಪತ್ರವನ್ನು ಒದಗಿಸುತ್ತದೆ.

## **ಅಜೂರ್ API ನಿರ್ವಹಣೆಯಲ್ಲಿ** ಸಂಪರ್ಕಿಸಿರಿ

ನಿಮ್ಮ APIಗೆ ಇದೊಂದು ಒಳಹರಿವು ನಿಯಮವನ್ನು ಸೇರಿಸಿ:

```xml
<inbound>
  <validate-jwt header-name="Authorization">
    <openid-config url="https://<fqdn>/.well-known/openid-configuration"/>
    <audiences>
      <audience>mcp-client</audience>
    </audiences>
  </validate-jwt>
  <base/>
</inbound>
```

APIM JWKS ಅನ್ನು ಪಡೆಯುತ್ತದೆ ಮತ್ತು ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯನ್ನೂ ಪರಿಶೀಲಿಸುತ್ತದೆ.
