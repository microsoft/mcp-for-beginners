# ಮಾದರಿ ಪರಿಪ्रेಕ್ಷ್ಯ ಪ್ರೋಟೋಕಾಲ್ (MCP) ಮೂಲಕ HTTPS ಸ್ಟ್ರೀಮಿಂಗ್

ಈ ಅಧ್ಯಾಯವು ಮಾದರಿ ಪರಿಪ್ರೆಕ್ಷ್ಯ ಪ್ರೋಟೋಕಾಲ್ (MCP) ನೊಂದಿಗೆ HTTPS ಉಪಯೋಗಿಸಿ ಸುರಕ್ಷಿತ, ಏರಿಕೆ ಪಡಬಹುದಾದ ಮತ್ತು ನೈಜ ಕಾಲದ ಸ್ಟ್ರೀಮಿಂಗ್ ಅನ್ನು ಅಳವಡಿಸುವ ಬಗ್ಗೆ ಸಮಗ್ರ ಮಾರ್ಗದರ್ಶಕ ಒದಗಿಸುತ್ತದೆ. ಇದಕ್ಕೆ ಸ್ಟ್ರೀಮಿಂಗ್ ಉಳಿರುವ ಉద్దೇಶ್ಯ, ಲಭ್ಯವಿರುವ ಸಾರಿಗೆ ಯಂತ್ರಗಳು, MCP ನಲ್ಲಿ ಸ್ಟ್ರೀಮಬಲ್ HTTP ಅನ್ನು ಹೇಗೆ ಅಳವಡಿಸಬೇಕು, ಸುರಕ್ಷತೆ ಅತ್ಯುತ್ತಮ ಅಭ್ಯಾಸಗಳು, SSE ನಿಂದ ವಲಸಣೆ ಮತ್ತು ನಿಮ್ಮ ಸ್ವಂತ ಸ್ಟ್ರೀಮಿಂಗ್ MCP ಆಪ್ಲಿಕೆಶನ್‌ಗಳನ್ನು ನಿರ್ಮಿಸಲು ವೈಯಕ್ತಿಕ ಮಾರ್ಗದರ್ಶನ ಸೇರಿವೆ.

> **ಭವಿಷ್ಯ ನೋಟ:** ಈ ಪಾಠವು **MCP ವಿವರಣೆ 2025-11-25** ರ ಅಡಿಯಲ್ಲಿ ಸ್ಟ್ರೀಮಬಲ್ HTTP ಅನ್ನು ವಿವರಿಸುತ್ತದೆ, ಇಲ್ಲಿ ಒಂದು ಸೆಷನ್ `initialize` ಸಮಯದಲ್ಲಿ ಸ್ಥಾಪಿಸಲ್ಪಡುತ್ತದೆ ಮತ್ತು `Mcp-Session-Id` ಹೆಡರ್ ಬಳಸಿ ಪಿನ್ ಮಾಡಲಾಗುತ್ತದೆ. `2026-07-28` ಬಿಡುಗಡೆ ಅಭ್ಯರ್ಥಿ ಹಸ್ತಮೇಳ ಮತ್ತು ಸೆಷನ್ ಐಡಿ ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ತೆಗೆದುಹಾಕುತ್ತದೆ, ಪ್ರತಿ ವಿನಂತಿ ಸ್ವ-ನಿರ್ವಹಿತವಾಗಿ ಮತ್ತು ಯಾವುದೇ ಸರ್ವರ್ ಉದಾಹರಣೆಗೆ ಮಾರ್ಗ ನೀಡಬಹುದಾಗಿಸುತ್ತದೆ, ಅಂಟಿಕೊಂಡ ಸೆಷನ್‌ಗಳಿಲ್ಲದೆ. ವಿವರಗಳಿಗೆ [MCP ನಲ್ಲಿ ಏನಾದರೂ ಬದಲಾಗುತ್ತದೆ: 2026-07-28 ಬಿಡುಗಡೆ ಅಭ್ಯರ್ಥಿ](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ನೋಡಿ.

## MCP ನಲ್ಲಿ ಸಾರಿಗೆ ಯಂತ್ರಗಳು ಮತ್ತು ಸ್ಟ್ರೀಮಿಂಗ್

ಈ ವಿಭಾಗವು MCP ನಲ್ಲಿ ಲಭ್ಯವಿರುವ ವಿವಿಧ ಸಾರಿಗೆ ಯಂತ್ರಗಳನ್ನು ಮತ್ತು ಕ್ಲೈಂಟ್ ಮತ್ತು ಸರ್ವರ್ ನಡುವೆ ನೈಜ ಕಾಲದ ಸಂವಹನಕ್ಕಾಗಿ ಸ್ಟ್ರೀಮಿಂಗ್ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವ ಅವರ ಪಾತ್ರವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ.

### ಸಾರಿಗೆ ಯಂತ್ರವೆಂದರೆ ಏನು?

ಸಾರಿಗೆ ಯಂತ್ರವು ಕ್ಲೈಂಟ್ ಮತ್ತು ಸರ್ವರ್ ನಡುವೆ ಡೇಟಾ ಹೇಗೆ ವಿನಿಮಯ ಮಾಡಿಕೊಳ್ಳಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು นิಧಿಸುತ್ತದೆ. MCP ವಿವಿಧ ಪರಿಸರಗಳು ಮತ್ತು ಅವಶ್ಯಕತೆಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ಅನೇಕ ಸಾರಿಗೆ ಪ್ರಕಾರಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

- **stdio**: ಸ್ಟ್ಯಾಂಡರ್ಡ್ ಇನ್‌ಪುಟ್/ಔಟ್‌ಪುಟ್, ಸ್ಥಳೀಯ ಮತ್ತು CLI ಆಧಾರಿತ ಸಾಧನಗಳಿಗೆ ಸೂಕ್ತ. ಸರಳ ಆದರೆ ವೆಬ್ ಅಥವಾ ಕ್ಲೌಡ್‌ಗಾಗಿ ಸೂಕ್ತವಲ್ಲ.
- **SSE (ಸರ್ವರ್-ಸೇಂಟ್ ಇವೆಂಟ್ಸ್)**: ಸರ್ವರ್‌ಗಳು HTTP ಮೂಲಕ ನೈಜ ಕಾಲದ ನವೀಕರಣಗಳನ್ನು ಕ್ಲೈಂಟ್‌ಗಳಿಗೆ ತಲುಪಿಸಲು ಅನುಮತಿಸುತ್ತದೆ. ವೆಬ್ UI ಗಾಗಿ ಒಳ್ಳೆಯದು, ಆದರೆ ಏರಿಕೆ ಮತ್ತು ಅಳವಡಿಕೆ ಚಲನೆಯಲ್ಲಿದೆ. MCP ವಿವರಣೆ 2025-06-18 ರ ನಂತರ, ಸ್ಥಿರೀಕೃತ SSE (ಸರ್ವರ್-ಸೇಂಟ್ ಇವೆಂಟ್ಸ್) ಸಾರಿಗೆ ತೆರವು ಮಾಡಲಾಗಿದೆ ಮತ್ತು "ಸ್ಟ್ರೀಮಬಲ್ HTTP" ಸಾರಿಗೆ ಮೂಲಕ ಬದಲಾಯಿಸಲಾಗಿದೆ.
- **ಸ್ಟ್ರೀಮಬಲ್ HTTP**: ಆಧುನಿಕ HTTP ಆಧಾರಿತ ಸ್ಟ್ರೀಮಿಂಗ್ ಸಾರಿಗೆ, ಸೂಚನೆಗಳು ಮತ್ತು ಉತ್ತಮ ಏರಿಕೆ ಸಾಮರ್ಥ್ಯ ಸಹಾಯ. ಬಹುತೇಕ ಉತ್ಪಾದನಾ ಮತ್ತು ಕ್ಲೌಡ್ ಸಂದರ್ಭಗಳಿಗೆ ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ.

### ಹೋಲಿಕೆಯ ಟೇಬಲ್

ಈ ಕೆಳಗಿನ ಹೋಲಿಕೆಯ ಟೇಬಲ್ ನೋಡಿ ಈ ಸಾರಿಗೆ ಯಂತ್ರಗಳ ನಡುವಿನ ವ್ಯತ್ಯಾಸಗಳನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಿ:

| ಸಾರಿಗೆ          | ನೈಜ ಕಾಲದ ನವೀಕರಣಗಳು | ಸ್ಟ್ರೀಮಿಂಗ್ | ಏರಿಕೆ ಸಾಮರ್ಥ್ಯ | ಬಳಕೆ ಪ್ರಕರಣ                   |
|-----------------|---------------------|------------|---------------|-------------------------------|
| stdio           | ಇಲ್ಲ                 | ಇಲ್ಲ        | ಕಡಿಮೆ          | ಸ್ಥಳೀಯ CLI ಸಾಧನಗಳು           |
| SSE             | ಹೌದು                 | ಹೌದು       | ಮಧ್ಯಮ          | ವೆಬ್, ನೈಜ ಕಾಲದ ನವೀಕರಣಗಳು  |
| ಸ್ಟ್ರೀಮಬಲ್ HTTP | ಹೌದು                 | ಹೌದು       | ಹೈ             | ಕ್ಲೌಡ್, ಬಹು-ಕ್ಲೈಂಟ್          |

> **ಸೂಚನೆ:** ಸರಿಯಾದ ಸಾರಿಗೆಯನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದು ಕಾರ್ಯಕ್ಷಮತೆ, ಏರಿಕೆ ಸಾಮರ್ಥ್ಯ ಮತ್ತು ಬಳಕೆದಾರ ಅನುಭವದ ಮೇಲೆ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ. **ಸ್ಟ್ರೀಮಬಲ್ HTTP** ಇಂದಿನ ಆಧುನಿಕ, ಏರಿಕೆ ಮತ್ತು ಕ್ಲೌಡ್-ತಯಾರ ಆಪ್ಲಿಕೆಶನ್‌ಗಳಿಗೆ ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ.

ನೀವು ಹಿಂದಿನ ಅಧ್ಯಾಯಗಳಲ್ಲಿ ನೋಡಿದ stdio ಮತ್ತು SSE ಸಾರಿಗಳನ್ನೂ ಗಮನಿಸಿ ಮತ್ತು ಈ ಅಧ್ಯಾಯದಲ್ಲಿ ಸ್ಟ್ರೀಮಬಲ್ HTTP ಹೇಗೆ ಸಾರಿಗೆಯಾಗುತ್ತದೆ ಎಂದು ತಿಳಿದುಕೊಳ್ಳಿ.

## ಸ್ಟ್ರೀಮಿಂಗ್: ಗುರಿಗಳು ಮತ್ತು ಉದ್ದೇಶಗಳು

ಸ್ಟ್ರೀಮಿಂಗ್‌ನ ಮೂಲಭೂತ ಪರಿಕಲ್ಪನೆಗಳು ಮತ್ತು ಉದ್ದೇಶಗಳನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು ಪರಿಣಾಮಕಾರಿ ನೈಜ ಕಾಲದ ಸಂವಹನ ವ್ಯವಸ್ಥೆಗಳನ್ನು ಅಳವಡಿಸಲು ಅತ್ಯಾವಶ್ಯಕ.

**ಸ್ಟ್ರೀಮಿಂಗ್** ಎಂದರೆ ನೆಟ್‌ವರ್ಕ್ ಪ್ರೋಗ್ರಾಮಿಂಗ್‌ನಲ್ಲಿ ಒಂದು ತಂತ್ರ, ಇದರಿಂದ ಡೇಟಾವನ್ನು ಚಿಕ್ಕ, ನಿರ್ವಹಣೀಯ ತುಂಡುಗಳಲ್ಲಿ ಅಥವಾ ಘಟನೆಗಳ ಸರಣಿಯಾಗಿ ಕಳುಹಿಸಿ ಸ್ವೀಕರಿಸಬಹುದು, ಸಂಪೂರ್ಣ ಪ್ರತಿಕ್ರಿಯೆ ಸಿದ್ಧವಾಗುವವರೆಗಿನ ನಿರೀಕ್ಷೆಯ ಹೊರತಾಗಿಯೇ. ಇದು ವಿಶೇಷವಾಗಿ ಉಪಯುಕ್ತ:

- ದೊಡ್ಡ ಫೈಲ್‌ಗಳು ಅಥವಾ ಡೇಟಾಸೆಟ್‌ಗಳು.
- ನೈಜ ಕಾಲದ ನವೀಕರಣಗಳು (ಉದಾ., ಚಾಟ್, ಪ್ರಗತಿ ಬಾರ್‌ಗಳು).
- ದೀರ್ಘ-ಕಾಲದ ಗಣನೆಗಳು, ಬಳಕೆದಾರರಿಗೆ ಸುದ್ದಿಯನ್ನು ನೀಡಲು.

ಸ್ಟ್ರೀಮಿಂಗ್ ಬಗ್ಗೆ ನೀವು ತಿಳಿದಿರಿ ಬೇಕಾದ ಮುಖ್ಯ ವಿಷಯಗಳು:

- ಡೇಟಾ ಕ್ರಮೇಣ ನೀಡಲ್ಪಡುವುದು, ಎಲ್ಲವನ್ನೂ ಒಂದೇ ಸಲವಲ್ಲ.
- ಕ್ಲೈಂಟ್ ಡೇಟಾವನ್ನು ಬರುವಂತೆ ಪ್ರಕ್ರಿಯೆ ಮಾಡಬಹುದು.
- ಅನುಭವದ ಆಗುಹೋಗುವಿಕೆಯನ್ನು ಕಡಿಮೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಬಳಕೆದಾರ ಅನುಭವವನ್ನು ಸುಧಾರಿಸುತ್ತದೆ.

### ಸ್ಟ್ರೀಮಿಂಗ್ ಅನ್ನು ಏಕೆ ಬಳಸಬೇಕು?

ಸ್ಟ್ರೀಮಿಂಗ್ ಬಳಸಬೇಕಾದ ಕಾರಣಗಳು ಈ ಕೆಳಕಂಡವು:

- ಬಳಕೆದಾರರು ತಕ್ಷಣ ಪ್ರತಿಕ್ರಿಯೆ ಪಡೆಯುತ್ತಾರೆ, ಕೇವಲ ಕೊನೆಗೆ ಅಲ್ಲ.
- ನೈಜ ಕಾಲದ ಆಪ್ಲಿಕೆಶನ್‌ಗಳು ಮತ್ತು ಪ್ರತಿಕ್ರಿಯಾಶೀಲ UI ಗಳನ್ನು ಸಾಧ್ಯಮಾಡುತ್ತದೆ.
- ನೆಟ್‌ವರ್ಕ್ ಮತ್ತು ಗಣನೆ ಸಂಪನ್ಮೂಲಗಳ ಸುಗಮ ಉಪಯೋಗ.

### ಸರಳ ಉದಾಹರಣೆ: HTTP ಸ್ಟ್ರೀಮಿಂಗ್ ಸರ್ವರ್ & ಕ್ಲೈಂಟ್

ಸ್ಟ್ರೀಮಿಂಗ್ ಹೇಗಾಗುತ್ತದೆ ಎಂಬುದು ತಿಳಿದುಕೊಳ್ಳಲು ಸರಳ ಉದಾಹರಣೆ ಇಲ್ಲಿದೆ:

#### ಪೈಥಾನ್

**ಸರ್ವರ್ (ಪೈಥಾನ್, FastAPI ಮತ್ತು StreamingResponse ಬಳಸಿ):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**ಕ್ಲೈಂಟ್ (ಪೈಥಾನ್, requests ಬಳಸಿ):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

ಈ ಉದಾಹರಣೆ ಒಂದೇ ಸಮಯದಲ್ಲಿ ಸರ್ವರ್ ಉತ್ತಮ ಸಂದೇಶಗಳನ್ನು ಕ್ಲೈಂಟ್‌ಗೆ ಕಳುಹಿಸುವುದನ್ನು ತೋರಿಸುತ್ತದೆ, ಎಲ್ಲ ಸಂದೇಶಗಳು ಸಿದ್ಧವಾಗುವವರೆಗೆ ಕಾಯುವುದು ಬೇಡ.

**ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ:**

- ಸರ್ವರ್ ಪ್ರತಿ ಸಂದೇಶವನ್ನು ಸಿದ್ದವಾಗಿದ್ದಂತೆ ಉತ್ಪಾದಿಸುತ್ತದೆ.
- ಕ್ಲೈಂಟ್ ಬಂದಂತೆ ಪ್ರತಿ ತುಂಡನ್ನು ಸ್ವೀಕರಿಸಲು ಮತ್ತು ಮುದ್ರಿಸಲು.

**ಅವಶ್ಯಕತೆಗಳು:**

- ಸರ್ವರ್ ಸ್ಟ್ರೀಮಿಂಗ್ ಪ್ರತಿಕ್ರಿಯೆ ಬಳಸದಿರಬೇಕು (ಉದಾ., FastAPI ಅನ್ನು `StreamingResponse`).
- ಕ್ಲೈಂಟ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಸ್ಟ್ರೀಮ್ ಆಗಿ ಪ್ರಕ್ರಿಯೆ ಮಾಡಬೇಕು (`stream=True` requests ನಲ್ಲಿ).
- ವಿಷಯ ಪ್ರಕಾರ ಸಾಮಾನ್ಯವಾಗಿ `text/event-stream` ಅಥವಾ `application/octet-stream` ಆಗಿರುತ್ತದೆ.

#### ಜಾವಾ

**ಸರ್ವರ್ (ಜಾವಾ, Spring Boot ಮತ್ತು Server-Sent Events ಬಳಸಿ):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**ಕ್ಲೈಂಟ್ (ಜಾವಾ, Spring WebFlux WebClient ಬಳಸಿ):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**ಜಾವಾ ಅಳವಡಿಸುವಿಕೆ ಟಿಪ್ಪಣಿಗಳು:**

- ಸ್ಟ್ರೀಮಿಂಗ್‌ಗಾಗಿ Spring Boot ನ ಪ್ರತಿಕ್ರಿಯಾತ್ಮಕ ಸ್ಟ್ಯಾಕ್ ಅನ್ನು `Flux` ಬಯಸುತ್ತದೆ
- `ServerSentEvent` ಘಟನೆ ಪ್ರಕಾರಗಳೊಂದಿಗೆ ವಿನ್ಯಾಸಗೊಳ್ಳದ ತಯಾರಿತ ಸಂದೇಶ ಸ್ಟ್ರೀಮ್ ಒದಗಿಸುತ್ತದೆ
- `WebClient` ನ `bodyToFlux()` ಪ್ರತಿಕ್ರಿಯಾತ್ಮಕ ಸ್ಟ್ರೀಮಿಂಗ್ ಉಪಯೋಗಿಸುವುವಂತೆ ಮಾಡುತ್ತದೆ
- `delayElements()` ಘಟನೆಗಳ ಮಧ್ಯೆ ಪ್ರಕ್ರಿಯೆ ಸಮಯವನ್ನು ನಕಲಿ ಮಾಡುತ್ತದೆ
- ಘಟನೆಗಳಿಗೆ ಉಪಯುಕ್ತತೆಗಾಗಿ ಪ್ರಕಾರಗಳು (ಉದಾ., `info`, `result`) ಇರಬಹುದು

### ಹೋಲಿಕೆ: ಪಾರಂಪರಿಕ ಸ್ಟ್ರೀಮಿಂಗ್ ವಿರುದ್ದ MCP ಸ್ಟ್ರೀಮಿಂಗ್

"ಪಾರಂಪರಿಕ" ರೀತಿಯಲ್ಲಿ ಸ್ಟ್ರೀಮಿಂಗ್ ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಮತ್ತು MCP ನಲ್ಲಿ ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಎಂಬ ವ್ಯತ್ಯಾಸಗಳನ್ನು ಹೀಗಾಗಿ ಚಿತ್ರಿಸಬಹುದು:

| ವೈಶಿಷ್ಟ್ಯ                 | ಪಾರಂಪರಿಕ HTTP ಸ್ಟ್ರೀಮಿಂಗ್   | MCP ಸ್ಟ್ರೀಮಿಂಗ್ (ಸೂಚನೆಗಳು)    |
|--------------------------|-----------------------------|-------------------------------|
| ಮುಖ್ಯ ಪ್ರತಿಕ್ರಿಯೆ          | ತುಂಡುಗಟ್ಟಿದ                | ಒ Programsಿಕೊಂಡ, ಕೊನೆಯಲ್ಲಿ          |
| ಪ್ರಗತಿ ನವೀಕರಣಗಳು        | ಡೇಟಾ ತುಂಡುಗಳಾಗಿ ಕಳುಹಿಸಲಾಗುತ್ತದೆ | ಸೂಚನೆಗಳಾಗಿ ಕಳುಹಿಸಲಾಗುತ್ತದೆ |
| ಕ್ಲೈಂಟ್ ಅವಶ್ಯಕತೆಗಳು     | ಸ್ಟ್ರೀಮ್ ಪ್ರಕ್ರಿಯೆ ಮಾಡಬೇಕಾಗುತ್ತದೆ | ಸಂದೇಶ ಹ್ಯಾಂಡಲ್ ಅಳವಡಿಸಬೇಕು     |
| ಬಳಕೆ ಪ್ರಕರಣ             | ದೊಡ್ಡ ಫೈಲ್‌ಗಳು, AI ಟೋಕನ್ ಸ್ಟ್ರೀಮ್‌ಗಳು | ಪ್ರಗತಿ, ಲಾಗ್‌ಗಳು, ನೈಜ ಕಾಲ ಪ್ರತಿಕ್ರಿಯೆ       |

### ಪ್ರಮುಖ ವೈಶಿಷ್ಟ್ಯಗಳ ವೀಕ್ಷಣೆ

ಈ ಕೆಳಗಿನವು ಕೆಲವು ಪ್ರಮುಖ ವ್ಯತ್ಯಾಸಗಳಾಗಿವೆ:

- **ಸಂವಹನ ಮಾದರಿ:**
  - ಪಾರಂಪರಿಕ HTTP ಸ್ಟ್ರೀಮಿಂಗ್: ಸರಳ ತುಂಡುಗಟ್ಟಿದ ಟ್ರಾನ್ಸ್‌ಫರ್ ಎಂಕೋಡಿಂಗ್ ಬಳಸಿ ಡೇಟಾ ಕಳುಹಿಸಿದೆ
  - MCP ಸ್ಟ್ರೀಮಿಂಗ್: JSON-RPC ಪ್ರೋಟೋಕಾಲ್ ಬಳಸಿ ವಿನ್ಯಾಸಗೊಳ್ಳದ ಸೂಚನಾ ವ್ಯವಸ್ಥೆ ಉಪಯೋಗಿಸುತ್ತದೆ

- **ಸಂದೇಶ ಫಾರ್ಮ್ಯಾಟ್:**
  - ಪಾರಂಪರಿಕ HTTP: ಸರಳ ಪಠ್ಯ ತುಂಡುಗಳು ಹೊಸ ಸಾಲುಗಳೊಂದಿಗೆ
  - MCP: ವಿನ್ಯಾಸಗೊಳ್ಳದ LoggingMessageNotification ವಸ್ತುಗಳು ಮೆಟಾ‌ಡೇಟಾ ಸಹಿತ

- **ಕ್ಲೈಂಟ್ ಅಳವಡಿಕೆ:**
  - ಪಾರಂಪರಿಕ HTTP: ಸ್ಟ್ರೀಮಿಂಗ್ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಪ್ರಕ್ರಿಯೆ ಮಾಡುವ ಸರಳ ಕ್ಲೈಂಟ್
  - MCP: ವಿವಿಧ ಸಂದೇಶ ಪ್ರಕಾರಗಳನ್ನು ಪ್ರಕ್ರಿಯೆ ಮಾಡುವ ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರ್ ಒಳಗೊಂಡ ಸುಧಾರಿತ ಕ್ಲೈಂಟ್

- **ಪ್ರಗತಿ ನವೀಕರಣಗಳು:**
  - ಪಾರಂಪರಿಕ HTTP: ಪ್ರಗತಿ ಮುಖ್ಯ ಪ್ರತಿಕ್ರಿಯೆ ಸ್ಟ್ರೀಮ್ ಭಾಗವಾಗಿದೆ
  - MCP: ಪ್ರಗತಿ ಪ್ರತ್ಯೇಕ ಸೂಚನೆ ಸಂದೇಶಗಳ ಮೂಲಕ ಕಳುಹಿಸಲಾಗುತ್ತದೆ, ಮುಖ್ಯ ಪ್ರತಿಕ್ರಿಯೆ ಕೊನೆಯಲ್ಲಿ ಬರುತ್ತದೆ

### ಶಿಫಾರಸುಗಳು

ಪಾರಂಪರಿಕ ಸ್ಟ್ರೀಮಿಂಗ್ (ಮೇಲಿನ `/stream` ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ನಾವು ತೋರಿಸಿದ್ದಂತೆ) ಮತ್ತು MCP ಮೂಲಕ ಸ್ಟ್ರೀಮಿಂಗ್ ಆಯ್ಕೆ ಮಾಡುವ ಬಗ್ಗೆ ಕೆಲ ಶಿಫಾರಸುಗಳು ಇಲ್ಲಿವೆ.

- **ಸರಳ ಸ್ಟ್ರೀಮಿಂಗ್ ಅಗತ್ಯಗಳು ಇರುವವರಿಗೆ:** ಪಾರಂಪರಿಕ HTTP ಸ್ಟ್ರೀಮಿಂಗ್ ಸರಳವಾಗಿದ್ದು ಮೂಲಭೂತ ಅಗತ್ಯಗಳಿಗೆ ಸಾಕಾಗುತ್ತದೆ.

- **ಸಂಕೀರ್ಣ, ಪರಸ್ಪರ ಕ್ರಿಯಾತ್ಮಕ ಆಪ್ಲಿಕೆಶನ್‌ಗಳಿಗೆ:** MCP ಸ್ಟ್ರೀಮಿಂಗ್ ಹೆಚ್ಚು ವಿನ್ಯಾಸಗೊಳ್ಳದ ವಿಧಾನವನ್ನು ಒದಗಿಸುತ್ತದೆ, ಹೆಚ್ಚಿನ ಮೆಟಾ‌ಡೇಟಾ ಮತ್ತು ಸೂಚನೆ ಮತ್ತು ಅಂತಿಮ ಫಲಿತಾಂಶಗಳ ವಿಭಜನೆ ಸಹಿತ.

- **ಕೃತಕ ಬುದ್ಧಿಮತ್ತೆ ಆಪ್ಲಿಕೆಶನ್‌ಗಳಿಗೆ:** MCP ಸೂಚನಾ ವ್ಯವಸ್ಥೆ ದೀರ್ಘಕಾಲದ AI ಕಾರ್ಯಗಳಲ್ಲಿ ಬಳಕೆದಾರರಿಗೆ ಪ್ರಗತಿ ತಿಳಿಸುವಲ್ಲಿ ಬಹುಪಯೋಗಿಯಾಗುತ್ತದೆ.

## MCP ನಲ್ಲಿ ಸ್ಟ್ರೀಮಿಂಗ್

ಸರಿಹೊಂದಿಸುವ ಸಲುವಾಗಿ ನೀವು ಈಗಾಗಲೇ ಪಾರಂಪರಿಕ ಸ್ಟ್ರೀಮಿಂಗ್ ಮತ್ತು MCP ಸ್ಟ್ರೀಮಿಂಗ್ ನಡುವಿನ ವ್ಯತ್ಯಾಸ ಮತ್ತು ಶಿಫಾರಸುಗಳನ್ನು ಕಂಡಿದ್ದೀರಿ. ಹೀಗಾಗಿ, MCP ನಲ್ಲಿ ಸ್ಟ್ರೀಮಿಂಗ್ ಹೇಗೆ ಬಳಸಬಹುದು ಎಂಬುದನ್ನು ವಿವರವಾಗಿ ನೋಡೋಣ.

MCP ರಚನೆಯಲ್ಲಿ ಸ್ಟ್ರೀಮಿಂಗ್ ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು, ದೀರ್ಘಿರುವ ಕಾರ್ಯಗಳ ವೇಳೆ ನೈಜ ಕಾಲ ಪ್ರತಿಕ್ರಿಯೆ ನೀಡುವ ಪ್ರತಿಕ್ರಿಯಾಶೀಲ ಆಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನು ನಿರ್ಮಿಸಲು ಅಗತ್ಯ.

MCP ನಲ್ಲಿ, ಸ್ಟ್ರೀಮಿಂಗ್ ಅಂತರೆಡಿಕೆ ಕೊನೆಯಲ್ಲಿ ಮುಖ್ಯ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ತುಂಡುಗಳಲ್ಲಿ ಕಳುಹಿಸುವುದಲ್ಲ, ಬದಲಿಗೆ ಆಪ್ಲಿಕೇಶನ್ ಪ್ರಕ್ರಿಯೆಯ ಸಮಯದಲ್ಲಿ ಕ್ಲೈಂಟ್ ಗೆ **ಸೂಚನೆಗಳು** ಕಳುಹಿಸುವುದಾಗಿದೆ. ಈ ಸೂಚನೆಗಳಲ್ಲಿ ಪ್ರಗತಿ ನವೀಕರಣಗಳು, ಲಾಗ್ ಗಳು ಅಥವಾ ಇತರೆ ಘಟನೆಗಳು ಇರಬಹುದು.

### ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

ಮುಖ್ಯ ಫಲಿತಾಂಶವನ್ನು ಇನ್ನೂ ಒಟ್ಟುಗೂಡಿದ ಪ್ರತಿಕ್ರಿಯೆಯಾಗಿ ಕಳುಹಿಸಲಾಗುತ್ತದೆ. ಆದಾಗ್ಯೂ, ಪ್ರಕ್ರಿಯೆಯ ನಡುವೆ ಪ್ರತ್ಯೇಕ ಸಂದೇಶಗಳಾಗಿ ಸೂಚನೆಗಳನ್ನು ಕಳುಹಿಸಿ ನೈಜ ಕಾಲದಲ್ಲಿ ಕ್ಲೈಂಟ್ ನವೀಕರಿಸಲಾಗುತ್ತದೆ. ಕ್ಲೈಂಟ್ ಈ ಸೂಚನೆಗಳನ್ನು ನಿರ್ವಹಿಸಿ ಪ್ರದರ್ಶಿಸುವ ಸಾಮರ್ಥ್ಯ ಹೊಂದಿರಬೇಕು.

## ಸೂಚನೆ ಎಂದರೆ ಏನು?

ನಾವು "ಸೂಚನೆ" ಎಂದು ಹೇಳಿದಾಗ, MCP ಸಂದರ್ಭದಲ್ಲಿ ಅದು ಏನು ಅರ್ಥ?

ಸೂಚನೆ ಎಂದರೆ ಸರ್ವರ್‌ನಿಂದ ಕ್ಲೈಂಟ್‌ಗೆ ಕಳುಹಿಸಲ್ಪಡುವ ಸಂದೇಶ, ಇದು ದೀರ್ಘಕಾಲದ ಕಾರ್ಯದ ಪ್ರಗತಿ, ಸ್ಥಿತಿ ಅಥವಾ ಇತರೆ ಘಟನೆಗಳ ಬಗ್ಗೆ ತಿಳಿಸುತ್ತದೆ. ಸೂಚನೆಗಳು ಪಾರದರ್ಶಕತೆ ಮತ್ತು ಬಳಕೆದಾರ ಅನುಭವವನ್ನು ಸುಧಾರಿಸುತ್ತವೆ.

ಉದಾಹರಣೆಗೆ, ಸರ್ವರ್ ಯೊಂದಂದಿನ ಮೌಲ್ಯಮಾಪನ ಮಾಡಿಕೊಂಡ ನಂತರ ಕ್ಲೈಂಟ್ ಗೆ ಸೂಚನೆಗಳನ್ನು ಕಳುಹಿಸುವ ನಿರೀಕ್ಷೆಯಿದೆ.

ಸೂಚನೆ ಹೀಗಾಗಿ JSON ಸಂದೇಶವಾಗಿ ಕಾಣುತ್ತದೆ:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

ಸೂಚನೆಗಳು MCP ಯಲ್ಲಿ ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) ಎಂಬ ವಿಷಯಕ್ಕೆ ಸೇರಿವೆ.

> **ತೊಲಗಿಸುವ ಸೂಚನೆ:** `2026-07-28` MCP ವಿವರಣೆ ಬಿಡುಗಡೆ ಅಭ್ಯರ್ಥಿ Logging ಪ್ರಕ್ಕೂತವನ್ನು `stderr` ಗೆ ಯಾವುದಾಗಲೀ ಸಾರಿಗೆಗಳು ಮತ್ತು OpenTelemetry ಗೆ ಸಂರಚಿತ ವೀಕ್ಷಣೆಯ ಪರವಾಗಿ ತೊಲಗಿಸುವುದಾಗಿ ಸೂಚಿಸುತ್ತದೆ. Logging  `2025-11-25` ನಲ್ಲಿ ಮತ್ತು ಅಧಿಕೃತ ತೊಲگزಿದ ಬಳಿಕ ಕನಿಷ್ಠ ಒಂದು ವರ್ಷ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ. ವಿವರಗಳಿಗೆ [MCP ನಲ್ಲಿ ಏನಾದರೂ ಬದಲಾಗುತ್ತದೆ: 2026-07-28 ಬಿಡುಗಡೆ ಅಭ್ಯರ್ಥಿ](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ನೋಡಿ.

ಲಾಗಿಂಗ್ ಕಾರ್ಯನಿರ್ವಹಿಸಲು, ಸರ್ವರ್ ಇದನ್ನು ವೈಶಿಷ್ಟ್ಯ/ಸಾಮರ್ಥ್ಯವಾಗಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕು ಹೀಗಾಗಿ:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> ಉಪಯೋಗಿಸಿದ SDK ಅನುಸಾರ, ಲಾಗಿಂಗ್ ಡೀಫಾಲ್ಟ್ ಆಗಿ ಸಕ್ರಿಯಗೊಂಡಿರಬಹುದು ಅಥವಾ ಸರ್ವರ್ ಸಂರಚನೆಯಲ್ಲಿ ಸ್ಪಷ್ಟವಾಗಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾಗಬಹುದು.

ವಿವಿಧ ರೀತಿಯ ಸೂಚನೆಗಳು ಇವೆ:

| ಮಟ್ಟ      | ವಿವರಣೆ                          | ಉದಾಹರಣೆ ಬಳಕೆ ಪ್ರಕರಣ          |
|-----------|--------------------------------|-------------------------------|
| debug     | ವಿಶದ ಡಿಬಗ್ ಮಾಹಿತಿ             | ಕಾರ್ಯ ಪ್ರವೇಶ/ಹೊರಡುವ ಬಿಂದುಗಳು  |
| info      | ಸಾಮಾನ್ಯ ಮಾಹಿತಿ ಸಂದೇಶಗಳು      | ಕಾರ್ಯ ಪ್ರಗತಿ ನವೀಕರಣಗಳು         |
| notice    | ಸಾಮಾನ್ಯ ಆದರೆ ಪ್ರಮುಖ ಘಟನೆಗಳು | ಸಂರಚನಾ ಬದಲಾವಣೆಗಳು          |
| warning   | ಎಚ್ಚರಿಕೆ ಪರಿಸ್ಥಿತಿಗಳು         | ತೊಲಗಿಸಿದ ವೈಶಿಷ್ಟ್ಯ ಬಳಕೆ        |
| error     | ದೋಷ ಪರಿಸ್ಥಿತಿಗಳು             | ಕಾರ್ಯ ವೈಫಲ್ಯಗಳು               |
| critical  | ಗಂಭೀರ ಪರಿಸ್ಥಿತಿಗಳು           | ಸಿಸ್ಟಮ್ ಘಟಕ ವೈಫಲ್ಯಗಳು       |
| alert     | ತಕ್ಷಣ ಕ್ರಮ ವಹಿಸುವುದು ಅಗತ್ಯ      | ಡೇಟಾ ಹಾನಿ ಪತ್ತೆಯಾಗಿದೆ          |
| emergency | ಸಿಸ್ಟಮ್ ಬಳಕೆಗೆ ಅಸಾಧ್ಯ          | ಸಂಪೂರ್ಣ ಸಿಸ್ಟಮ್ ವೈಫಲ್ಯ      |

## MCP ನಲ್ಲಿ ಸೂಚನೆಗಳನ್ನು ಅಳವಡಿಸುವುದು

MCP ನಲ್ಲಿ ಸೂಚನೆಗಳನ್ನು ಅಳವಡಿಸಲು, ಸರ್ವರ್ ಮತ್ತು ಕ್ಲೈಂಟ್ ಎರಡೂ ಪಾತ್ರಗಳು ನೈಜ ಕಾಲದ ನವೀಕರಣಗಳನ್ನು ನಿರ್ವಹಿಸಲು ಹೊಂದಿಸಬೇಕು. ಇದು ದೀರ್ಘಕಾಲದ ಕಾರ್ಯಗಳ ವೇಳೆ ಬಳಕೆದಾರರಿಗೆ ತಕ್ಷಣ ಪ್ರತಿಕ್ರಿಯೆ ನೀಡಲು ನಿಮ್ಮ ಆಪ್ಲಿಕೇಶನ್‌ನಲ್ಲಿ ಸಹಾಯ ಮಾಡುತ್ತದೆ.

### ಸರ್ವರ್-ಪಾರ್ಶ್ವ: ಸೂಚನೆಗಳನ್ನು ಕಳುಹಿಸುವುದು

ಸರ್ವರ್ ಪಾರ್ಶ್ವದಿಂದ ಪ್ರಾರಂಭಿಸುವುದು. MCP ಯಲ್ಲಿ, ನೀವು ವಿನಂತಿ ಪ್ರಕ್ರಿಯಿಸುವಾಗ ಸೂಚನೆಗಳನ್ನು ಕಳುಹಿಸಬಹುದಾದ ಟೂಲ್ಗಳನ್ನು ಪರिभಾಷಿಸುತ್ತೀರಿ. ಸರ್ವರ್ ಸಾಮಾನ್ಯವಾಗಿ `ctx` ಎಂಬ ಪರಿಪ್ರೆಕ್ಷ್ಯ ವಸ್ತುವನ್ನು ಬಳಸಿಕೊಂಡು ಕ್ಲೈಂಟ್ ಗೆ ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ.

#### ಪೈಥಾನ್

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

ಮೇಲಿನ ಉದಾಹರಣೆಯಲ್ಲಿ, `process_files` ಉಪಕರಣವು ಪ್ರತಿ ಫೈಲ್ ಪ್ರಕ್ರಿಯೆ ಮಾಡುತ್ತಿರುವಾಗ ಮೂರು ಸೂಚನೆಗಳನ್ನು ಕ್ಲೈಂಟ್ ಗೆ ಕಳುಹಿಸುತ್ತದೆ. `ctx.info()` ವಿಧಾನ ಬಳಸಿ ಮಾಹಿತಿ ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸಲಾಗಿದೆ.

ಹೆಚ್ಚಾಗಿ, ಸೂಚನೆಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲು, ನಿಮ್ಮ ಸರ್ವರ್ ಸ್ಟ್ರೀಮಿಂಗ್ ಸಾರಿಗೆ (ಹಾಗಾಗಿ `streamable-http`) ಬಳಸಬೇಕು ಮತ್ತು ಕ್ಲೈಂಟ್ ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ಅಳವಡಿಸಬೇಕು. ಇದರಿಂದ ಹಿಡಿದಿಟ್ಟ ಕಾರ್ಯವಿಧಾನ ಹೀಗಿದೆ:

```python
mcp.run(transport="streamable-http")
```

#### .ನೆಟ್

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

ಈ .ನೆಟ್ ಉದಾಹರಣೆಯಲ್ಲಿ, `ProcessFiles` ಉಪಕರಣವು `Tool` ಗುರುತಿಸಿರುವುದು ಮತ್ತು ಪ್ರತಿ ಫೈಲ್ ಪ್ರಕ್ರಿಯೆ ಮಾಡುವಾಗ ಮೂರು ಸೂಚನೆಗಳನ್ನು ಕ್ಲೈಂಟ್ ಗೆ ಕಳುಹಿಸುತ್ತದೆ. `ctx.Info()` ವಿಧಾನ ಬಳಸಿ ಮಾಹಿತಿ ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸಲಾಗಿದೆ.

ನಿಮ್ಮ .ನೆಟ್ MCP ಸರ್ವರ್ ನಲ್ಲಿ ಸೂಚನೆಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲು, ಸ್ಟ್ರೀಮಿಂಗ್ ಸಾರಿಗೆ ಬಳಕೆ ಮಾಡುತ್ತಿರುವಿರಾ ಎಂಬುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### ಕ್ಲೈಂಟ್-ಫಲಕ: ಸೂಚನೆಗಳನ್ನು ಸ್ವೀಕರಿಸುವುದು

ಕ್ಲೈಂಟ್ ನುಡಿಯನ್ನು ಅಳವಡಿಸಬೇಕು ಮತ್ತು ಬರುವ ಸೂಚನೆಗಳನ್ನು ಪ್ರಕ್ರಿಯೆ ಮಾಡಬೇಕು ಮತ್ತು ಪ್ರದರ್ಶಿಸಬೇಕು.

#### ಪೈಥಾನ್

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

ಮೇಲಿನ ಕೋಡ್ ನಲ್ಲಿ, `message_handler` ಅಭಿರುಚಿಯ ಸಂದೇಶ ಸೂಚನೆ ಆಗಿದೆಯೇ ಅಥವಾ ಇಲ್ಲವೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಅದು ಇದ್ದರೆ ಸೂಚನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ, ಸಾಮಾನ್ಯ ಸರ್ವರ್ ಸಂದೇಶವಾಗಿ ಪ್ರಕ್ರಿಯೆ ಮಾಡುತ್ತದೆ. ಜೊತೆಗೆ `ClientSession` ಅನ್ನು `message_handler` ನೊಂದಿಗೆ ಪ್ರಾರಂಭಿಸಲಾಗುತ್ತದೆ ಸೂಚನೆಗಳನ್ನು ನಿರ್ವಹಿಸಲು.

#### .ನೆಟ್

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

ಈ .ನೆಟ್ ಉದಾಹರಣೆಯಲ್ಲಿ, `MessageHandler` ಕಾರ್ಯ incoming ಸಂದೇಶ ಸೂಚನೆಗಳಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದ್ದರೆ ಸೂಚನೆಯನ್ನು ಮುದ್ರಿಸುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ, ಸಾಮಾನ್ಯ ಸರ್ವರ್ ಸಂದೇಶವಾಗಿ ಪ್ರಕ್ರಿಯೆ ಮಾಡುತ್ತದೆ. `ClientSession` ಅನ್ನು `ClientSessionOptions` ಮೂಲಕ ಸಂದೇಶ ಹ್ಯಾಂಡಲ್ ಅಥೋರೊಂದಿಗೆ ಪ್ರಾರಂಭಿಸಲಾಗುತ್ತದೆ.

ಸೂಚನೆಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲು, ನಿಮ್ಮ ಸರ್ವರ್ ಸ್ಟ್ರೀಮಿಂಗ್ ಸಾರಿಗೆ ಸೇವಿಸುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ (ಹಾಗಾಗಿ `streamable-http`) ಮತ್ತು ನಿಮ್ಮ ಕ್ಲೈಂಟ್ ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರ್ ಅಳವಡಿಸಿಕೊಳ್ಳಿ.

## ಪ್ರಗತಿ ಸೂಚನೆಗಳು ಮತ್ತು ಸಂದರ್ಭಗಳು

ಈ ವಿಭಾಗದಲ್ಲಿ MCP ಯಲ್ಲಿ ಪ್ರಗತಿ ಸೂಚನೆಗಳ ಪರಿಕಲ್ಪನೆ, ಅವುಗಳ ಮಹತ್ವ ಮತ್ತು Streamable HTTP ಬಳಸಿ ಹೇಗೆ ಅಳವಡಿಸುವುದು ಎಂಬುದನ್ನು ವಿವರಿಸಲಾಗುತ್ತದೆ. ನಿಮ್ಮ ಅರ್ಥವನ್ನು ಬಲಪಡಿಸಲು ವ್ಯವಹಾರಿಕ ಕಾರ್ಯವನ್ನು ಸಹ ಇಲ್ಲಿ ಕಾಣಬಹುದು.

ಪ್ರಗತಿ ಸೂಚನೆಗಳು ಸರ್ವರ್‌ನಿಂದ ಕ್ಲೈಂಟ್‌ಗೆ ದೀರ್ಘಕಾಲದ ಕಾರ್ಯಗಳ ಸಂದರ್ಭದಲ್ಲಿ ನೈಜ ಕಾಲದ ಸಂದೇಶಗಳಾಗಿವೆ. ಸಂಪೂರ್ಣ ಪ್ರಕ್ರಿಯೆ ಮುಗಿಯುವವರೆಗೆ ಕಾಯದೆ, ಸರ್ವರ್ ಪ್ರಸ್ತುತ ಸ್ಥಿತಿಯ ಬಗ್ಗೆ ಕ್ಲೈಂಟ್ ಅನ್ನು ನವೀಕರಿಸುತ್ತದೆ. ಇದು ಪಾರದರ್ಶಕತೆ, ಬಳಕೆದಾರ ಅನುಭವವನ್ನು ಸುಧಾರಿಸುತ್ತದೆ ಮತ್ತು ದೋಷ ಪರಿಹಾರವನ್ನು ಸುಲಭಗೊಳಿಸುತ್ತದೆ.

**ಉದಾಹರಣೆ:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### ಪ್ರಗತಿ ಸೂಚನೆಗಳನ್ನು ಏಕೆ ಬಳಸಬೇಕು?

ಪ್ರಗತಿ ಸೂಚನೆಗಳು ಹಲವಾರು ಕಾರಣಗಳಿಂದ ಅವಶ್ಯಕ:

- **ಬೆಚ್ಚಗಿನ ಬಳಕೆದಾರ ಅನುಭವ:** ಕೆಲಸ ಪ್ರಗತಿ ಹೊಂದಿರುವಂತೆ ಬಳಕೆದಾರರಿಗೆ ನವೀಕರಣಗಳು ತೋರಿಸಲಾಗುತ್ತವೆ, ಕೇವಲ ಕೊನೆಯಲ್ಲಿ ಮಾತ್ರವಲ್ಲ.
- **ನೈಜ ಕಾಲ ಪ್ರತಿಕ್ರಿಯೆ:** ಕ್ಲೈಂಟ್‌ಗಳು ಪ್ರಗತಿ ಬಾರ್‌ಗಳು ಅಥವಾ ಲಾಗ್‌ಗಳನ್ನು ತೋರಿಸಬಹುದು, ಒ ಅಪ್ಲಿಕೆಶನ್ ನೈಜ ಪ್ರತಿಕ್ರಿಯಾಶೀಲವಾಗುತ್ತದೆ.
- **ತಪ್ಪೊಪರಿಷ್ಕರಣೆಯ ಸುಲಭತೆ ಮತ್ತು ವೀಕ್ಷಣೆ:** ಅಭಿವೃದ್ಧಿಪರರು ಮತ್ತು ಬಳಕೆದಾರರು ಪ್ರಕ್ರಿಯೆ ಎಲ್ಲಿ ನಿಧಾನವಾಗುತ್ತಿದೆ ಅಥವಾ ಸ್ಥಗಿತವಾಗಿದೆ ಎಂದು ನೋಡಬಹುದು.

### ಪ್ರಗತಿ ಸೂಚನೆಗಳನ್ನು ಹೇಗೆ ಅಳವಡಿಸಬೇಕು

MCP ಯಲ್ಲಿ ಪ್ರಗತಿ ಸೂಚನೆಗಳನ್ನು ಅಳವಡಿಸುವ ವಿಧಾನ ಇಲ್ಲಿದೆ:

- **ಸರ್ವರ್ ನಲ್ಲಿ:** ಪ್ರತಿ ಐಟಂ ಪ್ರಕ್ರಿಯೆ ಆಗುತ್ತಿರುವಾಗ ಸೂಚನೆಗಳನ್ನು ಕಳುಹಿಸಲು `ctx.info()` ಅಥವಾ `ctx.log()` ಬಳಸಿರಿ. ಇದು ಮುಖ್ಯ ಫಲಿತಾಂಶ ಸಿದ್ಧವಾಗುವ ಮುಂಚೆ ಕ್ಲೈಂಟ್ ಗೆ ಸಂದೇಶ ಕಳುಹಿಸುತ್ತದೆ.
- **ಕ್ಲೈಂಟ್ ನಲ್ಲಿ:** ಬರುವ ಸೂಚನೆಗಳನ್ನು ಕೇಳಿ ಪ್ರದರ್ಶಿಸಲು ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರ್ ಅಳವಡಿಸಿ. ಇದು ಸೂಚನೆಗಳು ಮತ್ತು ಅಂತಿಮ ಫಲಿತಾಂಶವನ್ನು ವಿಭಜಿಸುತ್ತವೆ.

**ಸರ್ವರ್ ಉದಾಹರಣೆ:**


#### Python

```python
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

## ಭದ್ರತೆ ಪರಿಗಣನೆಗಳು

ಯಾವುದೇ ಸರ್ವರ್ ಅನ್ನು ನಿರ್ವಹಿಸುವಾಗ ಭದ್ರತೆ ಅತ್ಯಂತ ಮಹತ್ವದ್ದು, ವಿಶೇಷವಾಗಿ MCP ನಲ್ಲಿ Streamable HTTP ಸಾಬೀತುಗಳಲ್ಲಿ HTTP ಆಧಾರಿತ ಸಾರಿಗೆಗಳನ್ನು ಬಳಸದಾಗ.

HTTP ಆಧಾರಿತ ಸಾರಿಗೆಗಳೊಂದಿಗೆ MCP ಸರ್ವರ್‌ಗಳನ್ನು ಅನುಷ್ಠಾನ ಮಾಡುತ್ತಿದ್ದಾಗ, ಭದ್ರತೆ ಮುಖ್ಯವಾದ ವಿಚಾರವಾಗಿದ್ದು, ಹಲವಾರು ದಾಳಿಯ ಮಾರ್ಗಗಳ ಮತ್ತು ರಕ್ಷಣೆ ವಿಧಾನಗಳ ಮೇಲೆ ನೋಟವಿರಬೇಕು.

### ಅವಲೋಕನ

MCP ಸರ್ವರ್‌ಗಳನ್ನು HTTP ಮೂಲಕ ಪ್ರೊಕಾಶಿಸುವಾಗ ಭದ್ರತೆ ಅತ್ಯಂತ ಪ್ರಮುಖವಾಗಿದೆ. Streamable HTTP ಹೊಸ ದಾಳಿ ಮೇಲ್ಮೈಗಳನ್ನು ಪರಿಚಯಿಸುತ್ತದೆ ಮತ್ತು ಅದನ್ನು ಸೂಕ್ತವಾಗಿ ಸಂಯೋಜಿಸಬೇಕು.

ಇಲ್ಲಿವೆ ಕೆಲವು ಪ್ರಮುಖ ಭದ್ರತೆ ಪರಿಗಣನೆಗಳು:

- **Origin ಶೀರ್ಷಿಕೆ ಪರಿಶೀಲನೆ**: DNS ಮರುಬಾಂಧನ ದಾಳಿಗಳನ್ನು ತಡೆಯಲು ಸದಾ `Origin` ಶೀರ್ಷಿಕೆಯನ್ನು ಪರಿಶೀಲಿಸಿ.
- **Localhost ಬಾಂಧನ**: ಸ್ಥಳೀಯ ಅಭಿವೃದ್ಧಿಗಾಗಿ, ಸರ್ವರ್‌ಗಳನ್ನು `localhost` ಗೆ ಬಾಂಧಿಸಿ ಸಾರ್ವಜನಿಕ ಇಂಟರ್ನೆಟ್‌ಗೆ ಮುಕ್ತಾಯಿಸಲು ನಿರಾಕರಿಸಿ.
- **ಪರಿಚಯೀಕರಣ**: ಉತ್ಪಾದನಾ ನಿಯೋಜನೆಗಳಿಗೆ ಪರಿಚಯೀಕರಣ (ಉದಾ: API ಕೀಗಳು, OAuth) ಅನುಷ್ಠಾನ ಮಾಡಿ.
- **CORS**: ಪ್ರವೇಶವನ್ನು ನಿರ್ಬಂಧಿಸಲು Cross-Origin Resource Sharing (CORS) ನೀತಿಗಳನ್ನು ಸಂರಚಿಸಿ.
- **HTTPS**: ಟ್ರಾಫಿಕ್ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲು ಉತ್ಪಾದನೆಯಲ್ಲಿ HTTPS ಬಳಸಿ.

### ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು

ಹೆಚ್ಚುವರಿಯಾಗಿ, ನಿಮ್ಮ MCP ಸ್ಟ್ರೀಮಿಂಗ್ ಸರ್ವರ್‌ನಲ್ಲಿ ಭದ್ರತೆಯನ್ನು ಅನುಷ್ಠಾನ ಮಾಡುತ್ತಿರುವಾಗ ಕೆಳಗಿನ ಉತ್ತಮ ಅಭ್ಯಾಸಗಳನ್ನು ಅನುಸರಿಸಿ:

- ಪರಿಶೀಲನೆಯಿಲ್ಲದೆ ಬರುವ ವಿನಂತಿಗಳನ್ನು ಎಂದಿಗೂ ನಂಬಬೇಡಿ.
- ಎಲ್ಲಾ ಪ್ರವೇಶ ಮತ್ತು ದೋಷಗಳನ್ನು ಲಾಗ್ ಮಾಡಿ ಮತ್ತು ನಿಗಾ ವಹಿಸಿ.
- ಭದ್ರತೆ ದುರ್ಬಲತೆಗಳನ್ನು ತುಂಬಲು ನಿಯಮಿತವಾಗಿ ಅವಲಂಬನೆಗಳನ್ನು ನವೀಕರಿಸಿ.

### ಸವಾಲುಗಳು

MCP ಸ್ಟ್ರೀಮಿಂಗ್ ಸರ್ವರ್‌ನಲ್ಲಿ ಭದ್ರತೆಯನ್ನು ಅನುಷ್ಠಾನ ಮಾಡುವಾಗ ನೀವು ಕೆಲವು ಸವಾಲುಗಳನ್ನು ಎದುರಿಸುತ್ತೀರಿ:

- ಅಭಿವೃದ್ಧಿಯ ಸುಲಭತೆಯೊಂದಿಗೆ ಭದ್ರತೆಯನ್ನು ಸಮತೂಲ್ಯಗೊಳಿಸುವುದು
- ವಿವಿಧ ಗ್ರಾಹಕ ಪರಿಸರಗಳಿಗೆ ಹೊಂದಾಣಿಕೆಯ ಭರವಸೆ ನೀಡುವುದು


## SSE ರಿಂದ Streamable HTTP ಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡುವುದು

ಈ ಪರಿಸರದಲ್ಲಿ Server-Sent Events (SSE) ಬಳಸುತ್ತಿರುವ ಅಪ್ಲಿಕೇಶನ್‌ಗಳಿಗೆ, Streamable HTTP ಗೆ ವಲಯಿಸುವುದು ನಿಮ್ಮ MCP ಅನುಷ್ಠಾನಗಳಿಗೆ ಉತ್ತಮ ಸಾಮರ್ಥ್ಯಗಳು ಮತ್ತು ಶಾಶ್ವತತೆಯ ವಹಿಸುತ್ತದೆ.

### ಏಕೆ ಅಪ್‌ಗ್ರೇಡ್ ಮಾಡಬೇಕು?

SSE ರಿಂದ Streamable HTTP ಗೆ ಅಪ್‌ಗ್ರೇಡ್ ಮಾಡಲು ಎರಡು ಪ್ರಮುಖ ಕಾರಣಗಳಿವೆ:

- Streamable HTTP ನಲ್ಲಿ SSE ಗಿಂತ ಉತ್ತಮ ವ್ಯಾಪ್ತಿಗೊಳಿಸುವುದು, ಹೊಂದಾಣಿಕೆ ಮತ್ತು ಶ್ರೀಮಂತ ನೋಟಿಫಿಕೇಶನ್ ಬೆಂಬಲವಿದೆ.
- ಇದು ಹೊಸ MCP ಅಪ್ಲಿಕೇಶನ್‌ಗಳಿಗೆ ಶಿಫಾರಸು ಮಾಡಲಾದ ಸಾರಿಗೆ.

### ವರ್ಗಾಯಿಸುವ ಹಂತಗಳು

ನಿಮ್ಮ MCP ಅಪ್ಲಿಕೇಶನ್‌ಗಳಲ್ಲಿ SSE ರಿಂದ Streamable HTTP ಗೆ ಹೀಗೆ ವರ್ಗಾಯಿಸಬಹುದು:

- **ಸರ್ವರ್ ಕೋಡ್ ಅಪ್‌ಡೇಟ್ ಮಾಡಿ** `mcp.run()` ನಲ್ಲಿ `transport="streamable-http"` ಬಳಸಿ.
- **ಗ್ರಾಹಕ ಕೋಡ್ ಅಪ್‌ಡೇಟ್ ಮಾಡಿ** SSE ಗ್ರಾಹಕ ಬದಲು `streamablehttp_client` ಬಳಸಿ.
- **ಗ್ರಾಹಕದಲ್ಲಿ ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರನ್ನು ಅನುಷ್ಠಾನ ಮಾಡಿ** ನೋಟಿಫಿಕೇಶನ್ ಪ್ರಕ್ರಿಯೆಗಾಗಿ.
- **ಹೊಂದಾಣಿಕೆಯ ಪರೀಕ್ಷೆ ಮಾಡಿ** ಅದೇ ಉಪಕರಣಗಳು ಮತ್ತು ಕಾರ್ಯಪ್ರವಾಹಗಳೊಂದಿಗೆ.

### ಹೊಂದಾಣಿಕೆ ಕಾಪಾಡಿಕೊಳ್ಳುವುದು

ವರ್ಗಾಯಿಸುವ ಸಮಯದಲ್ಲಿ ಇತ್ತೀಚಿನ SSE clients ಗಳೊಂದಿಗೆ ಹೊಂದಾಣಿಕೆ ಕಾಪಾಡಿಕೊಳ್ಳುವುದು ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ. ಕೆಲವು ತಂತ್ರಗಳು ಇಲ್ಲಿವೆ:

- ನೀವು SSE ಮತ್ತು Streamable HTTP ಎರಡನ್ನೂ ವಿಭಿನ್ನ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗಳಲ್ಲಿ ರನ್ ಮಾಡಿಸಿ ಬೆಂಬಲಿಸಬಹುದು.
- ಗ್ರಾಹಕರನ್ನು ಹಂತ ಹಂತವಾಗಿ ಹೊಸ ಸಾರಿಗೆಗೆ ವರ್ಗಾಯಿಸಿ.

### ಸವಾಲುಗಳು

ವರ್ಗಾಯಿಸುವಾಗ ನೀವು ಈ ಕೆಳಗಿನ ಸವಾಲುಗಳನ್ನು ಎದುರಿಸಬೇಕು:

- ಎಲ್ಲಾ ಗ್ರಾಹಕರು ನವೀಕರಿಸಲಾಗಿರುವುದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ
- ನೋಟಿಫಿಕೇಶನ್ ವಿತರಣೆಯಲ್ಲಿ ವ್ಯತ್ಯಾಸಗಳನ್ನು ನಿರ್ವಹಿಸುವುದು

### ವ್ಯಾಯಾಮ: ನಿಮ್ಮ ಸ್ವಂತ ಸ್ಟ್ರೀಮಿಂಗ್ MCP ಅಪ್ಲಿಕೇಶನ್ ನಿರ್ಮಿಸಿ

**ದೃಶ್ಯ:**
ಒಂದು ಸರ್ವರ್ ಮತ್ತು ಗ್ರಾಹಕವನ್ನು ನಿರ್ಮಿಸಿ, ಸರ್ವರ್ ಐಟಂಗಳ (ಉದಾ: ಫೈಲುಗಳು ಅಥವಾ ಡಾಕ್ಯುಮೆಂಟ್ಸ್) ಪಟ್ಟಿಯನ್ನು ಪ್ರಕ್ರಿಯೆ ಮಾಡಿ ಪ್ರತಿ ಐಟಂ ಪ್ರಕ್ರಿಯೆಗೆ ನೋಟಿಫಿಕೇಶನ್ ಕಳುಹಿಸುತ್ತದೆ. ಗ್ರಾಹಕ ತಲುಪುವ ಪ್ರತಿಯೊಬ್ಬ ನೋಟಿಫಿಕೇಶನ್ ಅನ್ನು ತೋರಿಸಬೇಕು.

**ಹಂತಗಳು:**

1. ಐಟಂಗಳ ಪಟ್ಟಿಯನ್ನು ಪ್ರಕ್ರಿಯೆಮಾಡುವ ಮತ್ತು ಪ್ರತಿ ಐಟಂಗೆ ನೋಟಿಫಿಕೇಶನ್ ಕಳುಹಿಸುವ ಸರ್ವರ್ ಸಾಧನವನ್ನು ಅನುಷ್ಠಾನ ಮಾಡಿ.
2. ನೋಟಿಫಿಕೇಶನ್‌ಗಳನ್ನು ನೇರವಾಗಿ ತೋರಿಸುವ ಸಂದೇಶ ಹ್ಯಾಂಡ್ಲರ್ ಹೊಂದಿರುವ ಗ್ರಾಹಕವನ್ನು ಅನುಷ್ಠಾನ ಮಾಡಿ.
3. ನಿಮ್ಮ ಅನುಷ್ಠಾನವನ್ನು ಪರೀಕ್ಷಿಸಲು ಸರ್ವರ್ ಮತ್ತು ಗ್ರಾಹಕ ಎರಡನ್ನೂ ರನ್ ಮಾಡಿ ಮತ್ತು ನೋಟಿಫಿಕೇಶನ್‌ಗಳನ್ನು ಗಮನಿಸಿ.
