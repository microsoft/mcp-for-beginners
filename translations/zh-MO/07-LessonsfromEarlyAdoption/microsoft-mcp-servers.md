## 🔧 了解MCP伺服器：初學者指南

### MCP伺服器是什麼？

作為Model Context Protocol (MCP)的新手，你可能會想：「MCP伺服器到底是什麼，為什麼我需要關心？」我們從一個簡單的類比開始說明。

把MCP伺服器想像成專門的助手，幫助你的AI程式碼夥伴（像是GitHub Copilot）連接外部工具和服務。就像你會在手機上用不同應用程式處理不同任務—一個查天氣，一個導航，一個理財工具—MCP伺服器賦予你的AI助手與不同開發工具及服務互動的能力。

### MCP伺服器解決了什麼問題

以前沒有MCP伺服器時，如果你想：
- 查看你的Azure資源
- 創建GitHub議題
- 查詢資料庫
- 搜尋文件

你得停止編碼，打開瀏覽器，導航到相應網站並手動執行這些任務。這種不斷的上下文切換打斷你的流暢度，降低生產力。

### MCP伺服器如何改變你的開發體驗

有了MCP伺服器，你可以留在開發環境中（VS Code、Visual Studio等等），只需請你的AI助手處理這些任務。例如：

**傳統工作流程是這樣的：**
1. 停止編碼
2. 打開瀏覽器
3. 前往Azure管理平台
4. 查找儲存帳戶細節
5. 返回VS Code
6. 繼續編碼

**現在你可以這樣做：**
1. 問AI：「我的Azure儲存帳戶狀態如何？」
2. 搭配收到的資訊繼續編碼

### 初學者的主要好處

#### 1. 🔄 <strong>保持你的心流狀態</strong>
- 不必再在多個應用間切換
- 保持專注在你寫的程式碼上
- 降低管理不同工具時的心理負擔

#### 2. 🤖 <strong>用自然語言替代複雜指令</strong>
- 不需記憶SQL語法，只要描述你需要的資料
- 不需記Azure CLI指令，只說明你想做的事
- 讓AI處理技術細節，你專注在邏輯

#### 3. 🔗 <strong>串連多個工具</strong>
- 透過組合不同服務建立強大工作流程
- 例：「取回所有近期GitHub議題並建立相對應Azure DevOps工作項目」
- 無需編寫複雜腳本即可打造自動化

#### 4. 🌐 <strong>享用日益成長的生態系</strong>
- 享受由Microsoft、GitHub等公司打造的伺服器服務
- 無縫組合不同廠商的工具
- 參與跨多種AI助手都能用的標準化生態系

#### 5. 🛠️ <strong>透過實作學習</strong>
- 從預建伺服器開始理解概念
- 慢慢建立自己的伺服器以增強熟練度
- 利用現有SDK和文件輔助學習

### 初學者的實際案例

假設你是網頁開發新手，正在做你的第一個專案。MCP伺服器如何協助你：

**傳統做法：**
```
1. Code a feature
2. Open browser → Navigate to GitHub
3. Create an issue for testing
4. Open another tab → Check Azure docs for deployment
5. Open third tab → Look up database connection examples
6. Return to VS Code

```

**使用MCP伺服器：**
```
1. Code a feature
2. Ask AI: "Create a GitHub issue for testing this login feature"
3. Ask AI: "How do I deploy this to Azure according to the docs?"
4. Ask AI: "Show me the best way to connect to my database"
5. Continue coding with all the information you need
```

## 在VS Code和Visual Studio中開始使用MCP 🚀

若你使用Visual Studio Code或Visual Studio 2022搭配GitHub Copilot，設定這些MCP伺服器非常簡單。

### VS Code設定

VS Code的基本流程如下：

1. <strong>啟用代理模式</strong>：在VS Code中切換至Copilot Chat視窗的代理模式
2. **配置MCP伺服器**：將伺服器設定新增至你的VS Code settings.json檔案
3. <strong>啟動伺服器</strong>：點擊你想使用的每個伺服器旁的「啟動」按鈕
4. <strong>選擇工具</strong>：選擇本次工作階段要啟用的MCP伺服器

詳細設定說明請參考[VS Code MCP文件](https://code.visualstudio.com/docs/copilot/copilot-mcp)。

> **💡 專家提示：像專業人士一樣管理MCP伺服器！**
> 
> VS Code 擴充套件視圖現在新增了[方便的UI來管理已安裝的MCP伺服器](https://code.visualstudio.com/docs/copilot/chat/mcp-servers#_use-mcp-tools-in-agent-mode)！你能快速啟動、停止和管理任何已裝的MCP伺服器，介面簡單明瞭。快試試吧！

### Visual Studio 2022設定

對於Visual Studio 2022（17.14版或更高）：

1. <strong>啟用代理模式</strong>：點擊GitHub Copilot Chat視窗的「問」下拉選單並選擇「代理」
2. <strong>建立設定檔</strong>：在你的解決方案目錄下建立 `.mcp.json` 檔案（推薦位置：`<SOLUTIONDIR>\.mcp.json`）
3. <strong>配置伺服器</strong>：使用標準MCP格式新增你的MCP伺服器設定
4. <strong>工具授權</strong>：當系統提示時，批准帶有適當範圍權限的工具使用

詳細的Visual Studio設定說明請參考[Visual Studio MCP文件](https://learn.microsoft.com/visualstudio/ide/mcp-servers)。

每個MCP伺服器皆有其配置需求（連線字串、身份驗證等），但兩種IDE的設定模式大致相同。

### 1. 📚 Microsoft Learn Docs MCP伺服器

[![在VS Code安裝](https://img.shields.io/badge/VS_Code-Install_Microsoft_Docs_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D) [![在VS Code Insiders安裝](https://img.shields.io/badge/VS_Code_Insiders-Install_Microsoft_Docs_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/microsoft/mcp)

<strong>它的功能</strong>：Microsoft Learn Docs MCP伺服器是雲端服務，透過Model Context Protocol提供AI助手實時存取官方Microsoft文件的能力。它連接至`https://learn.microsoft.com/api/mcp`，並支援對Microsoft Learn、Azure說明文件、Microsoft 365文件及其他官方Microsoft資源的語義搜尋。

<strong>它的用途</strong>：雖然看似「只是文件」，此伺服器對使用Microsoft技術的每個開發者而言極為重要。許多.NET開發者針對AI程式碼助手最大的抱怨是它們未能跟上最新的.NET和C#版本。Microsoft Learn Docs MCP伺服器透過提供最新的文件、API參考與最佳實踐，解決了這個問題。不論是使用最新的Azure SDK、探索新的C# 13特性，或是實作前沿的Aspire模式，這個伺服器確保你的AI助手能引用權威而最新的資訊，生成準確且現代化的程式碼。

<strong>實務應用</strong>：「根據官方Microsoft Learn文件，建立Azure容器應用的az cli命令是什麼？」或者「如何在ASP.NET Core中使用依賴注入配置Entity Framework？」甚至「請檢查此程式碼是否符合Microsoft Learn文件中性能推薦。」此伺服器利用先進的語義搜尋，全面涵蓋Microsoft Learn、Azure文件與Microsoft 365說明，找到最具語境相關性的資訊。它返回最多10個高質量內容片段，附帶文章標題及URL，永遠引用最新發布的Microsoft文件。

<strong>特色範例</strong>：該伺服器公開`microsoft_docs_search`工具，對Microsoft官方技術文件執行語義搜尋。一旦設定完成，你可以問「如何在ASP.NET Core實作JWT認證？」這類問題，獲得詳細且官方的回覆並附帶來源連結。搜尋質量極佳，能理解語境 ── 在Azure語境下詢問「containers」會返回Azure Container Instances文件，而同一詞在.NET語境中則返回相關的C#集合資訊。

此功能尤其適用於快速變動或最近更新的函式庫和使用案例。例如，在近期的程式碼專案中，我想利用Aspire和Microsoft.Extensions.AI最新版本的功能。借助Microsoft Learn Docs MCP伺服器，我不只利用API文件，還能獲取剛發布的步驟說明與指導。

> **💡 專家提示**
> 
> 即便是工具友善的模型，也需要激勵去使用MCP工具！你可以考慮加入系統提示或[copilot-instructions.md](https://docs.github.com/copilot/how-tos/custom-instructions/adding-repository-custom-instructions-for-github-copilot)，例如：「你可以存取`microsoft.docs.mcp`——使用此工具搜尋Microsoft最新官方文件，以處理關於Microsoft技術（如C#、Azure、ASP.NET Core或Entity Framework）的問題。」
>
> 欲知這樣做的優秀實例，請查看Awesome GitHub Copilot倉庫中的[C# .NET Janitor聊天模式](https://github.com/awesome-copilot/chatmodes/blob/main/csharp-dotnet-janitor.chatmode.md)。此模式專用Microsoft Learn Docs MCP伺服器，協助清理和現代化C#程式碼，採用最新模式和最佳實踐。
### 2. ☁️ Azure MCP伺服器


[![在 VS Code 中安裝](https://img.shields.io/badge/VS_Code-Install_Azure_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D) [![在 VS Code Insiders 中安裝](https://img.shields.io/badge/VS_Code_Insiders-Install_Azure_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Azure/azure-mcp)

<strong>它的功能</strong>：Azure MCP Server 是一套包含 15 個以上專門 Azure 服務連接器的完整套件，將整個 Azure 生態系統帶入您的 AI 工作流程。這不僅是一台單一伺服器——它是一個強大的合集，包含資源管理、資料庫連接（PostgreSQL、SQL Server）、使用 KQL 的 Azure Monitor 日誌分析、Cosmos DB 整合等等。

<strong>為什麼有用</strong>：除了管理 Azure 資源外，此伺服器能顯著提升使用 Azure SDK 時的程式碼品質。當您以 Agent 模式使用 Azure MCP 時，它不只是幫助您編寫程式碼——它幫助您編寫符合當前認證模式、錯誤處理最佳實踐並利用最新 SDK 功能的 <em>更佳</em> Azure 程式碼。您不會得到僅能勉強運行的通用程式碼，而是遵循 Azure 推薦的生產工作負載模式的程式碼。

<strong>主要模組包括</strong>：
- **🗄️ 資料庫連接器**：直接以自然語言訪問 Azure Database for PostgreSQL 和 SQL Server
- **📊 Azure Monitor**：以 KQL 驅動的日誌分析與運營洞察
- **🌐 資源管理**：完整的 Azure 資源生命週期管理
- **🔐 認證**：DefaultAzureCredential 與託管身分識別模式
- **📦 儲存服務**：Blob 儲存、佇列儲存與表格儲存操作
- **🚀 容器服務**：Azure Container Apps、Container Instances 和 AKS 管理
- <strong>以及更多專門連接器</strong>

<strong>實際應用示例</strong>：「列出我的 Azure 儲存帳戶」、「查詢我 Log Analytics 工作區中最近一小時的錯誤」，或「協助我用 Node.js 建立一個正確認證的 Azure 應用程式」

<strong>完整演示情境</strong>：這裡有一個完整示範，展示將 Azure MCP 與 VS Code 中的 GitHub Copilot for Azure 擴充結合使用的強大能力。當您兩者皆安裝後，提示：

>「建立一個使用 DefaultAzureCredential 認證的 Python 腳本，上傳檔案到 Azure Blob Storage。該腳本應連接名為 'mycompanystorage' 的 Azure 儲存帳戶，上傳到名為 'documents' 的容器，建立一個帶有當前時間戳的測試檔案用於上傳，妥善處理錯誤並給出詳細輸出，遵循 Azure 認證與錯誤處理最佳實踐，包含說明 DefaultAzureCredential 如何運作的註解，且腳本結構良好，包含適當的函式與文件說明。」

Azure MCP Server 將產生一個完整且可用於生產的 Python 腳本，該腳本：
- 使用最新的 Azure Blob Storage SDK 並應用適當的非同步模式
- 實作 DefaultAzureCredential 並詳細說明 fallback 鏈
- 包含健全的錯誤處理，涵蓋特定 Azure 例外類型
- 遵循 Azure SDK 在資源管理與連線處理上的最佳實踐
- 提供詳盡日誌與資訊性控制台輸出
- 建立結構良好的腳本，包含函式、文件與型別提示

令人驚艷的是，若沒有 Azure MCP，您可能只會得到一串通用的 blob 儲存程式碼，雖能運作但不符合當前 Azure 模式。有了 Azure MCP，您將獲得利用最新認證方法、處理 Azure 特有錯誤場景，並遵循微軟推薦的生產應用程式最佳實踐的程式碼。

<strong>特色示例</strong>：我過去經常忘記使用 `az` 和 `azd` CLI 的特定指令，通常得先查語法再執行。我經常直接跳到入口網站點擊操作，因為不想承認自己不記得 CLI 語法。能直接描述想要的功能非常棒，更棒的是不用離開 IDE 就能完成！

在 [Azure MCP repository](https://github.com/Azure/azure-mcp?tab=readme-ov-file#-what-can-you-do-with-the-azure-mcp-server) 裡有一個很好的使用案例列表幫助您入門。想要完整設定指南與進階配置選項，請參考 [官方 Azure MCP 文件](https://learn.microsoft.com/azure/developer/azure-mcp-server/)。

### 3. 🐙 GitHub MCP Server

[![在 VS Code 中安裝](https://img.shields.io/badge/VS_Code-Install_Server-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D) [![在 VS Code Insiders 中安裝](https://img.shields.io/badge/VS_Code_Insiders-Install_Server-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/github/github-mcp-server)

<strong>它的功能</strong>：官方 GitHub MCP Server 提供與 GitHub 整個生態系統無縫整合，支持托管的遠程存取及本地 Docker 部署選項。這不只是基本的存儲庫操作——它是一套完整工具包，涵蓋 GitHub Actions 管理、拉取請求工作流程、問題追蹤、安全掃描、通知及進階自動化。

<strong>為什麼有用</strong>：此伺服器改變您與 GitHub 的互動方式，將完整平台體驗帶入您的開發環境。您不必總是在 VS Code 與 GitHub.com 之間切換進行專案管理、程式碼審查與 CI/CD 監控，而是可以透過自然語言指令處理解決所有事務，保持專注於程式碼。

> **ℹ️ 注意：不同類型的「代理人」**
> 
> 不要將此 GitHub MCP Server 與 GitHub 的 Coding Agent（可分配問題來進行自動化編碼任務的 AI 代理）混淆。GitHub MCP Server 在 VS Code 的 Agent 模式中工作，提供 GitHub API 整合，而 GitHub 的 Coding Agent 則是另一項功能，會在被分配給 GitHub 問題時創建拉取請求。

<strong>主要功能包括</strong>：
- **⚙️ GitHub Actions**：完整 CI/CD 管線管理、工作流程監控與工件處理
- **🔀 拉取請求**：建立、審查、合併與管理 PR，具有全面狀態追蹤

<strong>有用之處</strong>：現代文件工作流程不可或缺！MarkItDown 支援大量的檔案格式，並且保留關鍵的文件結構，如標題、清單、表格和連結。不同於簡單的文字擷取工具，它著重於維持對 AI 處理和人類可讀性都很重要的語意意義與格式。

- <strong>網頁內容</strong>：HTML、RSS 訂閱源、YouTube 連結、維基百科頁面
- <strong>資料格式</strong>：CSV、JSON、XML、ZIP 檔案（遞迴處理內容）
- <strong>出版格式</strong>：EPub、Jupyter 筆記本 (.ipynb)

> Markdown 非常接近純文字，只有極簡的標記或格式，但仍提供表示重要文件結構的方式。主流大型語言模型，如 OpenAI 的 GPT-4o，原生「使用」Markdown，並且常在未經提示下將 Markdown 融入其回應中。這顯示它們經過大量 Markdown 格式文本的訓練並且能很好地理解。附帶好處是，Markdown 約定也具有高度的標記效率。

MarkItDown 擅長保存文件結構，這對 AI 工作流程相當重要。例如，轉換 PowerPoint 簡報時，它會保持投影片結構及正確標題，將表格提取為 Markdown 表格，包含圖片替代文字，甚至處理講者備註。圖表會轉成可讀的資料表，產出的 Markdown 維持原始簡報的邏輯流。這使得它非常適合將簡報內容餵入 AI 系統或從現有投影片建立文件。

- 根據您的需求查詢模型目錄，推薦最佳推理模型
- 提供部署指令與您偏好 Azure 地區的配額資訊
- 為您的文件設置帶有正確架構的 Azure AI 搜尋索引
- 配置評估管線，包含品質指標與安全檢查
- 生成帶有 GitHub 認證的原型碼，立即進行測試
- 提供針對您的技術堆疊量身定制的全面設置指南

<strong>特色範例</strong>：作為開發者，我一直難以跟上眾多可用的 LLM 模型。我知道幾個主要模型，但總感覺錯過了一些生產力和效率的提升。而且，令牌和配額管理讓人壓力山大、很難掌握——我不知道自己是否為特定任務選擇了正確模型，還是無效率地燒掉預算。剛好從 James Montemagno 那裏聽說了這個 MCP Server，當時我正和團隊討論 MCP Server 推薦，我很期待實際使用它！模型探索功能對於像我這樣想跳出常規、尋找針對特定任務優化模型的人特別吸引。而評估框架能幫助我驗證，確保我真的獲得更好的結果，而不只是為了嘗試新東西而嘗試。

> **ℹ️ 實驗性狀態**

## 📋 結語

模型上下文協定（MCP）正在改變開發者與 AI 助理及外部工具互動的方式。這十個 Microsoft MCP 伺服器展示了標準化 AI 整合的威力，使開發者能在保持專注狀態下，無縫接取強大外部資源，創造連貫的工作流程。

從全面整合 Azure 生態系，到專門工具如 Playwright 用於瀏覽器自動化及 MarkItDown 進行文件處理，這些伺服器展現了 MCP 如何跨多元開發場景提升生產力。標準化協定確保這些工具能順利協作，締造流暢的開發體驗。

隨著 MCP 生態系持續演進，積極參與社區、探索新伺服器並打造自訂方案，將是提升開發效率的關鍵。MCP 的開放標準特性意味著您可以自由組合不同廠商的工具，打造最符合您需求的完美工作流程。
