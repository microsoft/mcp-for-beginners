## How to Get Started with MCP for VS Code and Visual Studio 🚀

To set up these MCP servers no hard if you dey use Visual Studio Code or Visual Studio 2022 with GitHub Copilot.

### VS Code Setup

Here be the basic way for VS Code:

1. **Enable Agent Mode**: For VS Code, switch to Agent mode for Copilot Chat window
2. **Configure MCP Servers**: Add server setting for your VS Code settings.json file
3. **Start Servers**: Click "Start" button for each server wey you want use
4. **Select Tools**: Pick which MCP servers you go want enable for your current session

To see detailed how to set am, check the [VS Code MCP documentation](https://code.visualstudio.com/docs/copilot/copilot-mcp).

> **💡 Pro Tip: Manage MCP Servers like pro!**
> 
> VS Code Extensions view get new UI to manage the MCP Servers wey you install. You fit start, stop, and control MCP Servers sharply with simple interface. Make you try am!

### Visual Studio 2022 Setup

For Visual Studio 2022 (version 17.14 or above):

1. **Enable Agent Mode**: Click "Ask" dropdown for GitHub Copilot Chat window and select "Agent"
2. **Create Configuration File**: Make `.mcp.json` file for your solution folder (recommended place: `<SOLUTIONDIR>\.mcp.json`)
3. **Configure Servers**: Add your MCP server settings with standard MCP format
4. **Tool Approval**: When e ask you, approve tools wey you wan use with correct permissions

For full Visual Studio setup, check [Visual Studio MCP documentation](https://learn.microsoft.com/visualstudio/ide/mcp-servers).

Each MCP server get their own config (connection strings, authentication, etc.) but setup process dey similar for both IDEs.

**Real-world use**: "Create pull request from my feature branch", "Show me all failed CI runs this week", "List open security alerts for my repositories", or "Find all issues assigned to me across my organizations"

GitHub MCP Server go:
- Query your recent pull requests with detailed status information
- Analyze workflow runs and highlight any failures or performance issues
- Compile security scanning results and prioritize critical alerts
- Generate comprehensive release notes by extracting information from merged PRs
- Provide actionable next steps for sprint planning and release preparation

**Featured example**: I like to dey use this for code review workflow dem. Instead of waka between VS Code, GitHub notifications and pull request pages, I fit talk "Show me all PRs wey dey wait for my review" then "Add comment to PR #123 wey ask about the error handling for the authentication method." The server dey handle GitHub API calls, maintain context about the discussion, and even help me craft better review comments.

**Authentication options**: The server support both OAuth (smoothly inside VS Code) and Personal Access Tokens, with configurate toolsets to only enable GitHub functionality wey you need. You fit run am as remote hosted service for quick setup or locally by Docker for full control.

> **💡 Pro Tip**

**Wetin e dey do**: MarkItDown na one kain complete document conversion server wey dey change different file formats go high-quality Markdown, wey dem optimize for LLM consumption and text analysis workflows.

**Why e useful**: E important for modern documentation workflows! MarkItDown fit handle plenty file formats while e still keep important document structure like headings, lists, tables, and links. E no be like simple text extraction tools, e dey focus to keep semantic meaning and formatting wey dey important for both AI processing and human reading.

**File formats wey e support**:
- **Office Documents**: PDF, PowerPoint (PPTX), Word (DOCX), Excel (XLSX/XLS)
- **Media Files**: Images (with EXIF metadata and OCR), Audio (with EXIF metadata and speech transcription)
- **Web Content**: HTML, RSS feeds, YouTube URLs, Wikipedia pages
- **Data Formats**: CSV, JSON, XML, ZIP files (dem fit process contents recursively)
- **Publishing Formats**: EPub, Jupyter notebooks (.ipynb)
- **Email**: Outlook messages (.msg)
- **Advanced**: Azure Document Intelligence integration for better PDF processing

**Advanced capabilities**: MarkItDown fit do LLM-powered image descriptions (if you get OpenAI client), Azure Document Intelligence for better PDF processing, audio transcription to speech content, and e get plugin system wey fit add more file formats.

**How people dey use am for real life**: "Convert this PowerPoint presentation to Markdown for our documentation site", "Extract text from this PDF with proper heading structure", or "Change this Excel spreadsheet go readable table format"

**Example wey stand out**: To quote [MarkItDown docs](https://github.com/microsoft/markitdown#why-markdown):

> Markdown dey very close to plain text, e get small markup or formatting, but e still fit show important document structure. Mainstream LLMs, like OpenAI GPT-4o, dey "speak" Markdown naturally, and dem fit put Markdown join for their responses without prompt. This one show say dem don train dem for plenty Markdown-formatted text, and dem sabi am well well. As bonus, Markdown convention dey token-efficient.

MarkItDown dey well well for keeping document structure, wey dey important for AI workflows. For example, if dem dey convert PowerPoint presentation, e dey keep slide organization with correct headings, dey carry tables as Markdown tables, dey put alt text for images, and still fit process speaker notes. Charts dey convert go readable data tables, and the Markdown wey e produce fit keep the real logical flow of the original presentation. This one make am perfect to feed presentation content go AI systems or to create documentation from slides wey already exist.
