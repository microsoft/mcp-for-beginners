# Увод у интеграцију MCP базе података

> [!NOTE]
> Дијаграми или код у овом учењу који користе HTTP/SSE или опције инициализације

## 🎯 Шта овај лабораторијски рад покрива

Овај уводни лабораторијски рад пружа обухватан преглед изградње Model Context Protocol (MCP) сервера са интеграцијом базе података. Разумете пословни случај, техничку архитектуру и примену у стварном свету кроз Zava Retail аналитички случај на https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail.

## Преглед

**Model Context Protocol (MCP)** омогућава AI асистентима безбедан приступ и интеракцију са екстерним изворима података у реалном времену. У комбинацији са интеграцијом базе података, MCP откључава моћне могућности за примене AI засноване на подацима.

Овај курс вас учи како да изградите MCP сервере спремне за производњу који повезују AI асистенте са подацима о продаји преко PostgreSQL-а, примењујући корпоративне обрасце као што су Row Level Security, семантичка претрага и приступ подацима више закупаца.

## Циљеви учења

По завршетку овог лабораторијског рада бићете у стању да:

- **Дефинишете** Model Context Protocol и његове основне предности за интеграцију базе података
- **Идентификујете** кључне компоненте MCP серверске архитектуре са базама података
- **Разумете** Zava Retail случај употребе и његове пословне захтеве
- **Препознате** корпоративне обрасце за безбедан и скалабилан приступ бази података
- **Наведете** алате и технологије коришћене у овом курсу

## 🧭 Изазов: AI и подаци из стварног света

### Ограничења традиционалног AI

Модерни AI асистенти су изузетно моћни али се суочавају са значајним ограничењима при раду са пословним подацима из стварног света:

| **Изазов** | **Опис** | **Пословни утицај** |
|---------------|-----------------|-------------------|
| **Статично знање** | AI модели обучени на фиксним скупљевима података не могу да приступе актуелним пословним подацима | Застареле увиде, пропуштене прилике |
| **Силоси података** | Информације закључане у базама података, API-јима и системима којима AI не може приступити | Непотпуна анализа, фрагментирани токови рада |
| **Безбедносна ограничења** | Директан приступ бази података подиже безбедносне и регулаторне забринутости | Ограничена примена, ручна припрема података |
| **Комплексни упити** | Пословни корисници морају имати техничко знање за издвајање података | Смањена употреба, неефикасни процеси |

### MCP решење

Model Context Protocol решава ове изазове пружајући:

- **Приступ подацима у реалном времену**: AI асистенти упитују живе базе података и API-је
- **Безбедну интеграцију**: Контролисани приступ са аутентификацијом и дозволама
- **Природан језички интерфејс**: Пословни корисници постављају питања на једноставном енглеском
- **Стандаризовани протокол**: Ради на различитим AI платформама и алатима

## 🏪 Упознајте Zava Retail: Наш студијски случај https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

Током овог курса градићемо MCP сервер за **Zava Retail**, фиктивни DIY малопродајни ланац са више продајних места. Овај реалистични сценарио демонстрира имплементацију корпоративног нивоа MCP.

### Пословни контекст

**Zava Retail** послује:
- **8 физичких продавница** широм државе Вашингтон (Сијетл, Белвју, Такома, Спокан, Еверет, Редмонд, Киркланд)
- **1 онлајн продавница** за е-комерцијалну продају
- **Разноврстан каталог производа** укључујући алате, хардвер, вртовски материјал и грађевински материјал
- **Мулти-ниво управљања** са менаџерима продајних места, регионалним менаџерима и руководиоцима

### Пословни захтеви

Менаџери продавница и руководиоци захтевају AI-ом покретану аналитика да:

1. **Анализирају перформансе продаје** по продавницама и временским периодима
2. **Прате нивое залиха** и идентификују потребе за допуну
3. **Разумеју понашање купаца** и обрасце куповине
4. **Открију увиде о производу** кроз семантичку претрагу
5. **Генеришу извештаје** уз питања на природном језику
6. **Одржавају безбедност података** са контролом приступа заснованом на улогама

### Технички захтеви

MCP сервер мора да пружи:

- **Приступ подацима више закупаца** где менаџери виде само податке своје продавнице
- **Флексибилно упитивање** које подржава сложене SQL операције
- **Семантичку претрагу** за откривање производа и препоруке
- **Подаци у реалном времену** који одражавају актуелно пословно стање
- **Безбедна аутентификација** са Row Level Security
- **Скалабилна архитектура** која подржава више истовремених корисника

### Кључне компоненте

#### **1. MCP слој сервера**
- **FastMCP Framework**: Модерна имплементација MCP сервера у Python-у
- **Регистрација алата**: Декларативне дефиниције алата са типском сигурношћу
- **Контекст захтева**: Идентификација корисника и управљање сесијом
- **Руковање грешкама**: Робусно управљање грешкама и евидентирање

#### **2. Слој интеграције базе података**
- **Управљање везама (Connection pooling)**: Ефикасно асинхроно управљање везама помоћу asyncpg
- **Провајдер шеме**: Динамичко откривање шема табела
- **Извођач упита**: Безбедно извршење SQL упита у RLS контексту
- **Управљање трансакцијама**: ACID усаглашеност и руковање враћањем трансакција

#### **3. Слој безбедности**
- **Row Level Security**: PostgreSQL RLS за изолацију података више закупаца
- **Идентификација корисника**: Аутентикација и авторизација менаџера продавница
- **Контрола приступа**: Фино подешене дозволе и аудиторски трагови
- **Валидација улаза**: Превенција SQL инјекција и валидација упита

#### **4. Слој AI побољшања**
- **Семантичка претрага**: Векторска уграђивања за откривање производа
- **Интеграција Azure OpenAI**: Генерисање текстуалних уграђивања
- **Алгоритми сличности**: Претрага по косинусној сличности помоћу pgvector
- **Оптимизација претраге**: Индексирање и подешавање перформанси

## 🎬 Сценарији употребе у стварном свету

Хајде да испитамо како различити корисници комуницирају са нашим MCP сервером:

### Сценарио 1: Преглед перформанси менаџера продавнице

**Корисник**: Сара, менаџерка продавнице у Сијетлу  
**Циљ**: Анализирати перформансе продаје у последњем кварталу

**Питање на природном језику**:
> "Прикажи ми 10 најпродаванијих производа по приходу за моју продавницу у Q4 2024"

**Шта се дешава**:
1. VS Code AI Chat шаље упит MCP серверу
2. MCP сервер идентификује контекст продавнице Саре (Сијетл)
3. RLS политике филтрирају податке само из Сијетл продавнице
4. Генерише и извршава SQL упит
5. Резултати се форматирају и враћају AI Чету
6. AI пружа анализу и увиде

### Сценарио 2: Откривање производа уз семантичку претрагу

**Корисник**: Мајк, менаџер залиха  
**Циљ**: Пронаћи производе сличне захтеву купца

**Питање на природном језику**:
> "Које производе продајемо сличне 'водоотпорним електричним конекторима за спољашњу употребу'?"

**Шта се дешава**:
1. Упит обрађује алат за семантичку претрагу
2. Azure OpenAI генерише вектор уграђивања
3. pgvector изводи претрагу сличности
4. Понудјени производи рангирани по релевантности
5. Резултати укључују детаље о производу и доступност
6. AI предлаже алтернативе и могућности паковања

### Сценарио 3: Аналитика преко продавница

**Корисник**: Џенјфер, регионална менаџерка  
**Циљ**: Упоредити перформансе свих продавница

**Питање на природном језику**:
> "Упореди продају по категоријама за све продавнице у последњих 6 месеци"

**Шта се дешава**:
1. Pостављен RLS контекст за приступ регионалног менаџера
2. Генерише се сложен упит за више продавница
3. Податци збиру по локацијама продавница
4. Резултати укључују трендове и поређења
5. AI идентификује увиде и препоруке

## 🔒 Детаљан преглед безбедности и мулти-лизинга

Наша имплементација приоритетно решава корпоративни ниво безбедности:

### Row Level Security (RLS)

PostgreSQL RLS осигурава изолацију података:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### Управљање идентитетом корисника

Свака MCP веза укључује:
- **Идентификатор менаџера продавнице**: Јединствени идентификатор за RLS контекст
- **Додела улога**: Дозволе и нивои приступа
- **Управљање сесијом**: Безбедни аутентификациони токени
- **Аудит логовање**: Комплетна историја приступа

### Заштита података

Више слојева безбедности:
- **Енкрипција веза**: TLS за све везе са базом података
- **Превенција SQL инјекција**: Само параметризовани упити
- **Валидација улаза**: Комплетна валидација захтева
- **Руковање грешкама**: Без осетљивих података у порукама о грешци
