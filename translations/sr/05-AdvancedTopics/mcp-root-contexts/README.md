# MCP Корени (Застарела функција)

> [!WARNING]
> Корени су застарели од MCP `2026-07-28`. Остају у овој ревизији ради
> компатибилности и могу бити уклоњени у првој ревизији спецификације
> објављеној 28. јула 2027. или после тог датума. Нова имплементација треба да преноси
> директоријуме или фајлове кроз параметре алата, URI ресурса или конфигурацију сервера.


## Преглед

Корени омогућавају MCP клијенту да серверу каже који локације у фајл систему су релевантне
за тренутни захтев. Корен садржи обавезан `file://` URI и опционални
човекозразумљиви назив.

Корени су информативни наговештаји. Нису контејнери историје разговора,
протоколарне сесије или механизам контроле приступа. Протокол не
приморава сервер да остане у оквиру наведених корена.

## Циљеви учења

До краја овог часа ћете моћи да:

- Објасните шта MCP корени представљају, а шта не представљају.
- Препознате тренутни `roots/list` вишекратно-командни ток.
- Примените безбедносне контроле независно од корена.
- Мигрирате нове имплементације на подржане алтернативе.

## Подаци о корену

Клијент враћа сваки корен као `file://` URI са опционалним приказним именом:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

Клијенти би требало да излажу само локације које је корисник одобрио. Сервери треба да третирају
резултат као смерницу о релевантним фајловима, а не као доказ овлашћења.

## MCP 2026-07-28 ток

Клијент који подржава корене декларише ту могућност у сваком захтеву:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

Док обрађује захтев клијента, сервер може вратити
`InputRequiredResult` који садржи улазни захтев `roots/list`:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

Клијент сакупља одобрена корена и покушава поново оригинални захтев са
одговарајућим `inputResponses` и непромењеним `requestState`. Овај вишекратно-командни
образац задржава протокол бездржним; нема руковање „initialize“ или
сесије на нивоу протокола.

## Застарело понашање 2025-11-25

У MCP `2025-11-25` клијенти су оглашавали корене током иницијализације. Сервер
је могао директно да пошаље захтев `roots/list`, а клијент је могао слати
`notifications/roots/list_changed` када би му се корени променили.

Тaј животни циклус је застарело понашање. Не комбинујте примере иницијализације или
обавештења са имплементацијом из `2026-07-28`.

## Препоручени замениоци

### Параметри алата

Направите обавезан директоријум или фајл експлицитним у шеми алата:

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### URI ресурса

Користите MCP ресурсе када сервер може изложити релевантне фајлове путем стабилних
URI. Ово одржава откривање и преузимање експлицитним.

### Конфигурација сервера

За фиксне имплементације, конфигуришите дозвољене директоријуме приликом покретања сервера.
Ово је често јасније него њихово откривање током позива алата.

## Безбедносни захтеви

Који год заменилац да изаберете:

- Обезбедите сагласност корисника пре откривања локација фајл система.
- Канонизујте и проверите путање да бисте спречили превалачење.
- Спроводите овлашћење и изолацију независно од вредности корена.
- Поново проверавајте дозволе када се фајл приступи, а не само када се наведе.
- Избегавајте враћање осетљивих путања у логовима или порукама о грешци.

## Кључни закључци

- Корени описују релевантне локације фајл система; они не чувају стање разговора.

- Корени су смернице, а не граница контроле приступа.
- MCP `2026-07-28` носи могућност по захтеву и користи
  `InputRequiredResult` за `roots/list`.
- Нове имплементације треба да користе параметре алата, URI ресурса или
  конфигурацију сервера уместо тога.
