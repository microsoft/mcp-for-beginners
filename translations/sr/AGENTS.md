# AGENTS.md

## Преглед Пројекта

**MCP за почетнике** је образовни курикулум отвореног кода за учење Model Context Protocol (MCP) - стандардизованог оквира за интеракције између AI модела и клијентских апликација. Ово складиште пружа свеобухватне материјале за учење са практичним примерима кода на више програмских језика.

### Кључне Технолгије

- **Програмски језици**: C#, Java, JavaScript, TypeScript, Python, Rust
- **Фрејмворци и SDK-ови**: 
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **Базе података**: PostgreSQL са pgvector екстензијом
- **Облачне платформе**: Azure (Container Apps, OpenAI, Content Safety, Application Insights)
- **Алатке за грађење**: npm, Maven, pip, Cargo
- **Документација**: Markdown са аутоматизованим преводом на више језика (48+ језика)

### Архитектура

- **11 основних модула (00-11)**: Секвенцијални пут учења од основних до напредних тема
- **Практичне лабораторије**: Практични задаци са комплетним кодом решења на више језика
- **Пример пројеката**: Ради сервер и клијент имплементације MCP-а
- **Систем превођења**: Аутоматизовани GitHub Actions радни ток за подршку више језика
- **Сликовни ресурси**: Централизован директоријум са преведеним верзијама слика

#### Предлог радног тока MCP алата: `validate_curriculum_change`

##### Циљ

Верификује промене у документацији курикулума и здравље репрезентативног пример кода пре спајања.


##### Улази

- `changed_paths: string[]` (обавезно) - релативне путање промене у PR-у.
- `run_docs_lint: boolean` (подразумевано `true`)
- `run_links_audit: boolean` (подразумевано `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (сви `false` као подразумевано)

##### Излази

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### Дозволе

- Читање фајлова радног простора и писање артефаката које генерише алат (нпр. линт
  извештаје, логове тестова) само; без писања у `translations/` или
  `translated_images/`.
- Извођење локалних шел команди.
- Опционо приступ мрежи само за обнову пакета (`npm ci`,
  `python -m pip install`, резолуција зависности `mvn`).
- Без дозвољеног пушовања, спајања или измене `translations/` или
  `translated_images/`.

##### Начини неуспеха

- `E_NO_INPUT_PATHS`: `changed_paths` је празан.
- `E_INVALID_PATH`: улазна путања излази ван корена складишта.
- `E_LINT_FAILED`: markdown лент не изађе са нултом вредношћу.
- `E_LINK_AUDIT_FAILED`: команда за проверу линкова не изађе са нултом вредношћу.
- `E_SAMPLE_TEST_FAILED`: тест/грађење примера не изађе са нултом вредношћу.
- `E_TIMEOUT`: команда прелази дозвољено време извршења.

##### Препоручени CI уговор

За аутоматизацију валидације, конфигуришите CI посао који:

- Триггерује при pull request-овима који дирају `*.md`, пример код или ову датотеку.
- Извршава тачно наведене команде горе.
- Чува логове као артефакте.
- Неуспех посла на било који не-нулти код излаза.

### Структура документације

- **Модули 00-11**: Основни садржај наставног програма по редоследу
- **translations/**: Верзије на специфичним језицима (ауто-генерисане, не уређуј директно)
- **translated_images/**: Локализоване верзије слика (ауто-генерисано)
- **images/**: Изворне слике и дијаграми

### Како правити измене у документацији

1. Уређуј само енглеске markdown датотеке у главним директоријумима модула (00-11)
2. Ако је потребно, ажурирај слике у директоријуму `images/`
3. GitHub Action co-op-translator ће аутоматски генерисати преводе
4. Преводи се регенеришу при пушу на главну грану

### Рад са преводима

- **Аутоматизован превод**: GitHub Actions workflow управља свим преводима
- **НЕ уређуј** датотеке у директоријуму `translations/` ручно
- Мета-подаци о преводу уграђени су у сваку преведену датотеку
- Подржани језици: 48+ језика укључујући арапски, кинески, француски, немачки, хинди, јапански, корејски, португалски, руски, шпански и многе друге

- Укључи примере кода на више језика када је применљиво

  - Користи ATX стил заглавља (`#` синтакса)
  - Користи ограђене блокове кода са идентификаторима језика
  - Укључи описни alt текст за слике
  - Држи дужину линија разумном (нема тврдог ограничења, али буди разуман)

#### TypeScript/JavaScript
- Користи ES модуле (`import`/`export`)
- Прати TypeScript строге мод конвенције
- Укључи типске анотације
- Циљна верзија ES2022

#### Python
- Прати PEP 8 стилске смернице
- Користи типске наговештаје где је прикладно
- Укључи docstrings за функције и класе
- Користи модерне Python функције (3.8+)

#### Java
- Прати Spring Boot конвенције
- Користи Java 21 функције
- Прати стандардну Maven структуру пројекта
- Укључи Javadoc коментаре

## Упутства за допринос

### Процес Pull Request-а

1. **Форк и клонирај**: Форкуј репозиторijум и клонирај свој форк локално
2. **Креирај грану**: Користи описне називе грана (нпр. `fix/typo-module-3`, `add/python-example`)
3. **Прави измене**: Уређуј само енглеске markdown датотеке (не преводе)
4. **Тестирај локално**: Проверии да ли markdown исправно приказује садржај
5. **Пошаљи PR**: Користи јасне наслове и описе PR-а
6. **CLA**: Потпиши Microsoft Contributor License Agreement када се затражи

### Формат наслова PR-а

Користи јасне, описне наслове:
- `[Module XX] Кратак опис` за измене специфичне по модулу
- `[Samples] Опис` за измене пример кода
- `[Docs] Опис` за опште ажурирање документације

### Шта допринети

- Исправке грешака у документацији или примерима кода
- Нови примери кода на додатним језицима
- Објашњења и побољшања постојећег садржаја
- Нове студије случаја или практични примери
- Пријаве проблема за нејасан или нетачан садржај

### Шта НЕ радити

- Не уређуј директно фајлове у `translations/` директоријуму
- Не уређуј `translated_images/` директоријум
- Не додавај велике бинарне фајлове без претходне дискусије
- Не мењај workflow фајлове за превод без координације

### Честа решавања проблема

**П: Мој PR не пролази проверу превода**
О: Увери се да си уређивао само енглеске markdown датотеке у коренским директоријумима модула, а не преведене верзије.

**П: Како да додам нови језик?**
О: Подршка за језике се управља кроз co-op-translator workflow. Отвори issue за дискусију о додавању нових језика.

**П: Примери кода не раде**
О: Увери се да си следио упутства за подешавање у README-у конкретног примера. Провери да имаш исправне верзије зависности.


**П: Слике се не приказују**

А: Потврдите да су путање до слика релативне и да користе косе црте унапред. Слике треба да буду у директоријуму `images/` или `translated_images/` за локализоване верзије.
