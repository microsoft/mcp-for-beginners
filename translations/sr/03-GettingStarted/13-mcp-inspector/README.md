# Дебаговање уз MCP Инспектор

> [!NOTE]
> Команде које користе `--sse` и URL-ови који се завршавају на `/sse` тестирају наслеђени HTTP+SSE
> транспорт. За нови MCP сервер `2026-07-28`, користите верзију Инспектора која
> подржава Streamable HTTP и изаберите тај транспорт уместо тога.

**MCP Инспектор** је основни алат за дебаговање који вам омогућава интерактивно тестирање и решавање проблема ваших MCP сервера без потребе за пуном апликацијом за AI хост. Замислите га као "Postman за MCP" - пружа визуелни интерфејс за слање захтева, преглед одговора и разумевање понашања вашег сервера.

## Зашто користити MCP Инспектор?

При изградњи MCP сервера често ћете се сусретати са следећим изазовима:

- **"Да ли мој сервер уопште ради?"** - Инспектор приказује статус везе
- **"Да ли су моји алати правилно регистровани?"** - Инспектор показује све расположиве алате
- **"Који је формат одговора?"** - Инспектор приказује целе JSON одговоре
- **"Зашто овај алат не ради?"** - Инспектор приказује детаљне поруке о грешкама

## Захтеви

- Node.js 18+ инсталиран
- npm (долази са Node.js)
- MCP сервер за тестирање (погледајте [Модул 3.1 - Први сервер](../01-first-server/README.md))

## Инсталација

### Опција 1: Покрените са npx (препоручено за брзо тестирање)

```bash
npx @modelcontextprotocol/inspector
```

### Опција 2: Инсталирајте глобално

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### Опција 3: Додајте у свој пројекат

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

Додајте у `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## Повезивање са вашим сервером

### stdio сервери (локални процес)

За сервере који комуницирају преко стандардног улаза/излаза:

```bash
# Питхон сервер
npx @modelcontextprotocol/inspector python -m your_server_module

# Node.js сервер
npx @modelcontextprotocol/inspector node ./build/index.js

# Са променљивим окружења
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP сервери (мрежа)

За сервере који раде као HTTP услуге:

1. Прво покрените свој сервер:
   ```bash
   python server.py  # Сервер ради на http://localhost:8080
   ```

2. Покрените Инспектор и повежите се:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## Тестирање алата

### Листање расположивих алата

1. Кликните на картицу **Tools**
2. Инспектор аутоматски позива `tools/list`
3. Видећете све регистроване алате са:
   - Назив алата
   - Опис
   - Шема уноса (параметри)

### Позивање алата

1. Изаберите алат са листе
2. Попуните потребне параметре у форми
3. Кликните на **Run Tool**
4. Погледајте одговор у панелу са резултатима

**Пример: Тестирање калкулатор алата**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### Дебаговање грешака алата

Када алат не успе, Инспектор приказује:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

Уобичајени кодови грешака:
| Код | Значење |
|------|---------|
| -32700 | Грешка парсирања (неважећи JSON) |
| -32600 | Неважећи захтев |
| -32601 | Метод није пронађен |
| -32602 | Неважећи параметри |
| -32603 | Унутрашња грешка |

## Тестирање ресурса

### Листање ресурса

1. Кликните на картицу **Resources**
2. Инспектор позива `resources/list`
3. Видећете:
   - URI ресурса
   - Називе и описе
   - MIME типа

### Читање ресурса

1. Изаберите ресурс
2. Кликните на **Read Resource**
3. Погледајте враћени садржај

**Пример излаза:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## Тестирање упита

### Листање упита

1. Кликните на картицу **Prompts**
2. Инспектор позива `prompts/list`
3. Погледајте расположиве шаблоне упита

### Претходно преузимање упита

1. Изаберите упит
2. Попуните све потребне аргументе
3. Кликните на **Get Prompt**
4. Видећете приказане поруке упита

## Анализа дневника порука

Дневник порука приказује све MCP протокол поруке. Транскрипт испод је са
наслеђеног `2025-11-25` сервера и укључује уклоњени `initialize` руковање. Сервер
`2026-07-28` користи само садржану метаподацима захтева и `server/discover`
уместо тога.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### На шта обратити пажњу

- **Парови захтев/одговор**: Свакој `→` треба да одговара `←`
- **Поруке о грешкама**: Тражите `"error"` у одговорима
- **Временска раздаљина**: Велики застој може указивати на проблеме са перформансама
- **Верзија протокола**: Уверите се да сервер и клијент користе исту верзију

      "preLaunchTask": "Start MCP Inspector"

## Уобичајени сценарији за дебаговање

### Сценарио 1: Сервер се не повезује

**Симптоми:** Инспектор приказује "Disconnected" или стоји на "Connecting..."

**Контролна листа:**
1. ✅ Да ли је команда за сервер исправна?
2. ✅ Да ли су све зависности инсталиране?
3. ✅ Да ли је пут до сервера апсолутан или релативан у односу на тренутни директоријум?
4. ✅ Да ли су потребне системске променљиве подешене?

**Кораци за дебаговање:**
```bash
# Прво ручно тестиратe сервер
python -c "import your_server_module; print('OK')"

# Проверите грешке при импорту
python -m your_server_module 2>&1 | head -20

# Потврдите да је MCP SDK инсталиран
pip show mcp
```

### Сценарио 2: Алатке се не приказују

**Симптоми:** Картица алата показује празну листу

**Могући узроци:**
1. Алатке нису регистроване током иницијализације сервера
2. Сервер је пао након покретања
3. `tools/list` руковалац враћа празан низ

**Кораци за дебаговање:**
1. Проверите дневник порука за `tools/list` одговор
2. Додајте логовање у свој код за регистрацију алата
3. Проверите да ли су `@mcp.tool()` декоратори присутни (Python)

### Сценарио 3: Алат враћа грешку

**Симптоми:** Позив алата враћа одговор са грешком

**Приступ дебаговању:**
1. Пажљиво прочитајте поруку о грешци
2. Проверите да ли типови параметара одговарају шеми
3. Додајте try/catch са детаљним порукама о грешци
4. Проверите дневнике сервера за стек трагове

**Пример побољшаног руковања грешкама:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # Логика алата овде
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### Сценарио 4: Садржај ресурса је празан

**Симптоми:** Ресурс враћа, али садржај је празан или нул

**Контролна листа:**
1. ✅ Пут или URI фајла је исправан
2. ✅ Сервер има дозволу за читање ресурса
3. ✅ Садржај ресурса се исправно враћа

## Напредне функције Инспектора

### Прилагођени заглавља (SSE)

```bash
npx @modelcontextprotocol/inspector \
  --sse http://localhost:8080/sse \
  --header "Authorization: Bearer your-token"
```

### Детаљно логовање

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### Снимање сесија

Инспектор може извести дневнике порука за каснију анализу:
1. Кликните на **Export Log** у панелу порука
2. Сачувајте JSON фајл
3. Делите са члановима тима за дебаговање

## Најбоље праксе

1. **Тестирај рано и често** - Користи Инспектор током развоја, не само када нешто поквариш
2. **Почни једноставно** - Тестирај основну повезаност пре позива сложених алата
3. **Проверите шему** - Многе грешке настају због неусклађености типова параметара
4. **Читај поруке о грешкама** - MCP грешке су обично описне
5. **Држи Инспектор отвореним** - Помоћи ће ти да уочиш проблеме током развоја
