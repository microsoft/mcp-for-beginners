# Дневник измена: MCP за почетнике наставни план

Овај документ служи као евиденција свих значајних измена урађених у Model Context Protocol (MCP) за почетнике наставном плану. Измене су документањем у обрнутом хронолошком реду (најновије измене прве).

## 29. јул 2026.

### Нови модул 08 пратилац: Поуздани Сидарс и Безбедни Поновни Покушаји

Додата је неутрална према добављачима пратилачка лекција за MCP алате који креирају реалне
ефекте, усклађена са коначном `2026-07-28` спецификацијом.

- **Ново**: [лекција пратилаш поузданости сидара][reliability-sidecar]
  користи једну причу са подршком, два Mermaid дијаграма, и ток одлука о поновном покушају
  да објасни кључеве стабилног рада, атомски пријем дупликата,
  помирења, доказе и границу проширења Задака.
- **Ново**: Вежба увођења грешака помоћу стандардне библиотеке Python и SQLite
  користи одвојене продавнице операција и карата да демонстрира изгубљен одговор
  након што се спољашњи ефекат заврши. Шест детерминистичких тестова покривају наивну
  дупликацију, заштићени опоравак од поновног покретања, конфликте података,
  кеширанe резултатe, активнe захтевe и конкурентни пријем дупликата.
- **Ажурирано**: Модул 08 сада повезује пратилачку лекцију, идентификује
  коначни `2026-07-28` модел беспокретног захтева, разликује OpenTelemetry
  опсервабилност од застареле MCP функције евидентирања и ограничава свој
  општи пример поновног покушаја само на операције за читање.
- **Опционо**: Лекција мапира своје преносиве концепте на једну означену заједничку
  имплементацију без укључивања домаћег сервиса или позива на мрежу као део
  вежбе.

### Појачавање безбедности и решавање рањивости зависности

Прошао комплетан безбедносни преглед сваког манифеста зависности и узорка изворног кода, потом отклонио све пријављене npm упозорења и једно кодско налазиште. Након ревизије, `npm audit` пријављује **0 рањивости** у свакој провераваној фасцикли.

#### npm рањивости зависности (транзитивне) — Исправљено

Проверавано је свих 15 обављених `package-lock.json` датотека. Ранивости су ограничене на транзитивне зависности које уносе MCP Inspector алат за развој, OpenAI клијент и MCP SDK; све су сада решене без прекида примера:
- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/inspector** и **lab3/code/weather_mcp/inspector**: Подигнут `@modelcontextprotocol/inspector` верзија (`0.16.6` / `0.14.1` → `0.22.0`), што је очистило упозорења бундлова `ajv`, `brace-expansion`, `diff`, `path-to-regexp` и `ws`. Додат npm `overrides` унос који приморава исправљени `shell-quote@1.8.4` да уклони преостало критично упозорење нанео од стране `concurrently`; регенерисане обе lockfajle (сада 0 рањивости)
- **03-GettingStarted/samples/typescript**: `npm audit fix` ажурирао транзитивни `qs` (умерено) у исправљену верзију
- **03-GettingStarted/samples/javascript**: `npm audit fix` ажурирао транзитивни `hono` (умерено) у исправљену верзију
- **03-GettingStarted/03-llm-client/solution/typescript**: `npm audit fix` ажурирао транзитивни `form-data` (високо) у исправљену верзију
- **03-GettingStarted/11-simple-auth/solution/typescript**: Генерисан недостајући `package-lock.json` да би пројекат био репродуктиван и ревизијски стабилан (0 рањивости)

#### Безбедносна исправка на нивоу кода (OWASP A03: Инјекција)

- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/src/server.py**: Уклонио `shell=True` из `open_in_vscode` алата. Претходна команда `subprocess.run(["start", "", vscode_path, folder_path], shell=True)` омогућавала је тумачење шелл метакарактера у путањи фасцикле од стране `cmd.exe` (вектор инјекције команда). Сада директно покреће разрешени `Code.exe` са фасциклом као аргументом — без шела — што је функционално еквивалентно и безбедно

#### Python провера зависности

- Проверавани сваки Python скуп зависности са `pip-audit`. `05-AdvancedTopics` и `03-GettingStarted/samples/python` пријавили су **нема познатих рањивости** (њихови распони `mcp` / `httpx` / `pydantic` / `python-dotenv` разрешавају се на тренутне исправљене верзије)
- **09-CaseStudy/docs-mcp/solution/python/requirements.txt**: `pip-audit` је означио транзитивну зависност **`werkzeug` 3.1.1** са три `safe_join` DoS упозорења за Windows имена уређаја — `CVE-2025-66221`, `CVE-2026-21860`, и `CVE-2026-27199` (све исправљено у 3.1.6). Додат је експлицитан безбедносни пин `werkzeug>=3.1.6` тако да се разреши исправљена верзија; потврђено да ограничење исправно разрешава комбинацију `chainlit` / `mcp` / `semantic-kernel`

- **Безбедносна исправка — инјекција команди**: Замена `execSync` интерполације шела са `execFile` + `promisify` у TypeScript `run_python` алату, елиминишући површину инјекције команди (код контролисан LLM-ом сада се прослеђује као дословни аргумент argv без учешћа шела)
- **Повезивање петље алата MCP**: Ажурирање Python оркестратора дебате за коришћење `AsyncAnthropic` клијента (уместо блокирајућег синхроног `Anthropic`), прослеђивање живе `ClientSession` директно сваком агентском потезу, преузимање дефиниција алата преко `session.list_tools()` сваки пут и слање `tool_use` блокова преко `session.call_tool()` у петљи док модел не емитује коначни текстуални одговор

  - Домаћини сада јасно дефинисани као AI апликације које координишу везе више MCP клијената
  - Клијенти описани као протокол конектори који одржавају директне везе са сервером
  - Сервери побољшани са сценаријима локације и удаљеног распоређивања
- **Примитиви реструктурирани**: Потпуно прерађени примитиви за сервер и клијента
  - Серверски примитиви: Ресурси (извори података), Промптови (шаблони), Алати (извршне функције) са детаљним објашњењима и примерима
  - Клијентски примитиви: Узорковање (LLM завршетци), Изазивање уноса (кориснички унос), Логовање (дебаговање/надзор)
  - Ажурирано са тренутним патернима метода за откривање (`*/list`), добијање (`*/get`) и извршење (`*/call`)
- **Архитектура протокола**: Уведен модел архитектуре са два слоја
  - Слој података: JSON-RPC 2.0 основа са управљањем животним циклусом и примитивима
  - Транспортни слој: STDIO (локално) и Streamable HTTP са SSE (удаљени) транспортни механизми
- **Безбедносни оквир**: Свеобухватни безбедносни принципи укључујући експлицитни кориснички пристанак, заштиту приватности података, безбедност извршења алата и безбедност транспортног слоја
