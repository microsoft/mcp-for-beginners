# MCP निरीक्षकसँग डिबगिङ

> [!NOTE]
> `--sse` र `/sse` मा अन्त्य हुने URL हरू समावेश गर्ने आदेशहरूले लेगेसी HTTP+SSE
> यातायात परीक्षण गर्छन्। नयाँ MCP `2026-07-28` सर्भरका लागि,
> स्ट्रिमेबल HTTP समर्थन गर्ने निरीक्षक संस्करण प्रयोग गर्नुहोस् र त्यो यातायात चयन गर्नुहोस्।

**MCP निरीक्षक** एउटा आवश्यक डिबगिङ उपकरण हो जसले तपाईंलाई पूर्ण AI होस्ट एप्लिकेशन बिना नै तपाईंका MCP सर्भरहरू अन्तरक्रियात्मक रूपमा परीक्षण र समस्या समाधान गर्न दिन्छ। यसलाई "MCP को लागि पोस्टम्यान" भनेर सोच्नुहोस् - यो अनुरोधहरू पठाउन, प्रतिक्रियाहरू हेर्न, र कसरी तपाईंको सर्भर व्यवहार गर्दैछ बुझ्न दृश्यात्मक इन्टरफेस प्रदान गर्दछ।

## किन MCP निरीक्षक प्रयोग गर्ने?

MCP सर्भर निर्माण गर्दा तपाईँ प्रायः यी चुनौतीहरू सामना गर्नुहुन्छ:

- **"के मेरो सर्भर चलिरहेको नै छ?"** - निरीक्षकले जडान स्थिति देखाउँछ
- **"के मेरा उपकरणहरू ठीकसँग दर्ता भएका छन्?"** - निरीक्षकले सबै उपलब्ध उपकरणहरू सूचीबद्ध गर्दछ
- **"प्रतिक्रिया ढाँचा कस्तो छ?"** - निरीक्षकले पूर्ण JSON प्रतिक्रिया देखाउँछ
- **"किन यो उपकरण काम गरिरहेको छैन?"** - निरीक्षकले विस्तृत त्रुटि सन्देशहरू देखाउँछ

## पूर्व आवश्यकताहरू

- Node.js 18+ इन्स्टल गरिएको
- npm (Node.js सँग आउँछ)
- परीक्षण गर्न MCP सर्भर (हेर्नुस् [मोड्युल 3.1 - पहिलो सर्भर](../01-first-server/README.md))

## इन्स्टलेशन

### विकल्प 1: npx संग चलाउनुहोस् (छिटो परीक्षणका लागि सिफारिस गरिएको)

```bash
npx @modelcontextprotocol/inspector
```

### विकल्प २: ग्लोबली इन्स्टल गर्नुहोस्

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### विकल्प ३: तपाईंको प्रोजेक्टमा थप्नुहोस्

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` मा थप्नुहोस्:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## तपाईंको सर्भरसँग जडान

### stdio सर्भरहरू (स्थानिय प्रक्रिया)

त्यो सर्भरहरूका लागि जसले मानक इनपुट/आउटपुटमार्फत संवाद गर्छन्:

```bash
# पाइथन सर्भर
npx @modelcontextprotocol/inspector python -m your_server_module

# नोड.जेएस सर्भर
npx @modelcontextprotocol/inspector node ./build/index.js

# वातावरण चरहरूसँग
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP सर्भरहरू (नेटवर्क)

HTTP सेवा रूपमा चल्ने सर्भरहरूका लागि:

1. पहिले आफ्नो सर्भर सुरू गर्नुहोस्:
   ```bash
   python server.py  # सर्भर http://localhost:8080 मा चलिरहेको छ
   ```

2. निरीक्षक सुरू गरेर जडान गर्नुहोस्:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## परीक्षण उपकरणहरू

### उपलब्ध उपकरणहरू सूचीबद्ध गर्ने

1. **Tools** ट्याब क्लिक गर्नुहोस्
2. निरीक्षकले स्वचालित रूपमा `tools/list` कल गर्छ
3. तपाईं सबै दर्ता गरिएका उपकरणहरू देख्नुहुनेछ:
   - उपकरण नाम
   - विवरण
   - इनपुट स्कीमा (प्यारामिटरहरू)

### उपकरण कल गर्ने

1. सूचीबाट उपकरण चयन गर्नुहोस्
2. फारममा आवश्यक प्यारामिटरहरू भर्नुहोस्
3. **Run Tool** क्लिक गर्नुहोस्
4. परिणाम प्यानलमा प्रतिक्रिया हेर्नुहोस्

**उदाहरण: क्याल्कुलेटर उपकरण परीक्षण गर्ने**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### उपकरण त्रुटिहरू डिबग गर्ने

जब उपकरण असफल हुन्छ, निरीक्षक देखाउँछ:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

सामान्य त्रुटि कोडहरू:
| कोड | अर्थ |
|------|---------|
| -32700 | पार्स त्रुटि (अवैध JSON) |
| -32600 | अवैध अनुरोध |
| -32601 | विधि फेला परेन |
| -32602 | अवैध प्यारामिटरहरू |
| -32603 | आन्तरिक त्रुटि |

## परीक्षण स्रोतहरू

### स्रोतहरू सूचीबद्ध गर्ने

1. **Resources** ट्याब क्लिक गर्नुहोस्
2. निरीक्षक `resources/list` कल गर्छ
3. तपाईं देख्नुहुनेछ:
   - स्रोत URI हरू
   - नाम र विवरणहरू
   - MIME प्रकारहरू

### स्रोत पढ्ने

1. स्रोत चयन गर्नुहोस्
2. **Read Resource** क्लिक गर्नुहोस्
3. फिर्ता गरिएको सामग्री हेर्नुहोस्

**उदाहरण आउटपुट:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## परीक्षण प्रॉम्प्टहरू

### प्रॉम्प्टहरू सूचीबद्ध गर्ने

1. **Prompts** ट्याब क्लिक गर्नुहोस्
2. निरीक्षकले `prompts/list` कल गर्छ
3. उपलब्ध प्रॉम्प्ट टेम्प्लेटहरू हेर्नुहोस्

### प्रॉम्प्ट प्राप्त गर्ने

1. प्रॉम्प्ट चयन गर्नुहोस्
2. कुनै आवश्यक तर्कहरू भर्नुहोस्
3. **Get Prompt** क्लिक गर्नुहोस्
4. रेंडर गरिएका प्रॉम्प्ट सन्देशहरू हेर्नुहोस्

## सन्देश लग विश्लेषण

सन्देश लगले सबै MCP प्रोटोकल सन्देशहरू देखाउँछ। तलको ट्रान्सक्रिप्ट एउटा
लेगेसी `2025-11-25` सर्भरबाट हो र हटाइएको `initialize` ह्याण्डशेक समावेश गर्दछ। एउटा
`2026-07-28` सर्भर स्व-समावेश अनुरोध मेटाडाटा र `server/discover`
प्रयोग गर्दछ।

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### के हेर्नुहोस

- **अनुरोध/प्रतिक्रिया जोडीहरू**: प्रत्येक `→` मा मिल्ने `←` हुनु पर्छ
- **त्रुटि सन्देशहरू**: प्रतिक्रियामा `"error"` को खोजी गर्नुहोस्
- **समय**: ठूला खालि समयले प्रदर्शन समस्याहरू संकेत गर्न सक्छ
- **प्रोटोकल संस्करण**: सुनिश्चित गर्नुहोस् सर्भर र क्लाइन्टले संस्करणमा सहमत छन्

## सामान्य डिबगिङ परिस्थितिहरू

### अवस्था १: सर्भर जडान हुँदैन

**लक्षणहरू:** निरीक्षकले "Disconnected" देखाउँछ वा "Connecting..." मा अड्किन्छ

**जाँच सूची:**
1. ✅ सर्भर कमाण्ड ठिक छ?
2. ✅ सबै निर्भरता इन्स्टल छन्?
3. ✅ सर्भर पथ पूर्ण वा चलिरहेको डिरेक्टरी सापेक्ष छ?
4. ✅ आवश्यक वातावरण भेरिएबलहरू सेट छन्?

**डिबग कदमहरू:**
```bash
# सर्भरलाई पहिले म्यानुअली टेस्ट गर्नुहोस्
python -c "import your_server_module; print('OK')"

# आयात त्रुटिहरू जाँच गर्नुहोस्
python -m your_server_module 2>&1 | head -20

# MCP SDK स्थापना गरिएको छ कि छैन पुष्टि गर्नुहोस्
pip show mcp
```

### अवस्था २: उपकरणहरू देखिँदैन

**लक्षणहरू:** उपकरण ट्याब खाली सूची देखाउँछ

**संभावित कारणहरू:**
1. सर्भर इनेशियलाइजेसनको समयमा उपकरणहरू दर्ता नभएका
2. सुरु भएपछि सर्भर क्र्यास भयो
3. `tools/list` ह्यान्डलरले रिक्त एरे फर्काइरहेको छ

**डिबग कदमहरू:**
1. सन्देश लगमा `tools/list` प्रतिक्रिया जाँच गर्ने
2. तपाईँको उपकरण दर्ता कोडमा लगिङ थप्ने
3. `@mcp.tool()` डेकोरेटरहरू हुनु जाँच्ने (Python)

### अवस्था ३: उपकरणले त्रुटि फर्काउँछ

**लक्षणहरू:** उपकरण कलले त्रुटि प्रतिक्रिया फर्काउँछ

**डिबग तरिका:**
1. त्रुटि सन्देश ध्यान दिएर पढ्नुहोस्
2. प्यारामिटर प्रकार स्कीमासँग मेल खान्छ कि जाँच्नुहोस्
3. विस्तृत त्रुटि सन्देशसहित try/catch थप्नुहोस्
4. सर्भर लगहरूमा स्ट्याक ट्रेसहरू जाँच्नुहोस्

**उदाहरण सुधारिएको त्रुटि ह्यान्डलिङ:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # उपकरण तर्क यहाँ
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### अवस्था ४: स्रोत सामग्री खाली छ

**लक्षणहरू:** स्रोत फिर्ता हुन्छ तर सामग्री खाली वा शून्य छ

**जाँच सूची:**
1. ✅ फाइल पथ वा URI ठिक छ
2. ✅ सर्भरलाई स्रोत पढ्ने अनुमति छ
3. ✅ स्रोत सामग्री ठीकसँग फिर्ता हुँदैछ

## राम्रो अभ्यासहरू

1. **छिटो र प्रायः परीक्षण गर्नुहोस्** - विकासको क्रममा निरीक्षक प्रयोग गर्नुहोस्, मात्र समस्या आउँदा हैन
2. **साधारण बाट सुरु गर्नुहोस्** - जटिल उपकरण कल अघि आधारभूत जडान परीक्षण गर्नुहोस्
3. **स्कीमा जाँच गर्नुहोस्** - धेरै त्रुटिहरू प्यारामिटर प्रकार मेल नखाने कारण आउँछन्
4. **त्रुटि सन्देश हेर्नुहोस्** - MCP त्रुटिहरू सामान्यतया व्याख्यात्मक हुन्छन्
5. **निरीक्षक खुला राख्नुहोस्** - विकास गर्दा समस्याहरू पत्ता लगाउन मद्दत गर्छ
