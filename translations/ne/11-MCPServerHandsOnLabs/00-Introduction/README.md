## 🎯 यस प्रयोगशालाले के समेट्छ

यस परिचयात्मक प्रयोगशालाले Model Context Protocol (MCP) सर्भरहरूको डेटाबेस एकीकरणसहित बनाउने विस्तृत अवलोकन प्रदान गर्दछ। तपाईंले व्यापार केस, प्राविधिक वास्तुकला, र वास्तविक-विश्व अनुप्रयोगहरू बुझ्नु हुनेछ Zava Retail विश्लेषण प्रयोग केस मार्फत https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail मा।

## अवलोकन

**Model Context Protocol (MCP)** ले AI सहायकहरूलाई बाह्य डाटा स्रोतहरूलाई वास्तविक-समयमा सुरक्षित रूपमा पहुँच र अन्तरक्रिया गर्न सक्षम बनाउँछ। डेटाबेस एकीकरणसँग संयोजन गर्दा, MCP ले डाटा-चालित AI अनुप्रयोगहरूको लागि शक्तिशाली क्षमता अनलक गर्दछ।

यस सिकाइ मार्गले तपाईंलाई उत्पादन-तयार MCP सर्भरहरू बनाउन सिकाउँछ जुन AI सहायकहरूलाई PostgreSQL मार्फत खुद्रा बिक्री डाटासँग जोड्छ, रो लेवल सेक्युरिटी, सेम्यान्टिक खोज, र बहु-टेनेंट डाटा पहुँच जस्ता उद्यम नमूनाहरू कार्यान्वयन गर्दै।

## सिकाइ लक्ष्यहरू

यस प्रयोगशाला अन्त्यसम्म, तपाईं सक्षम हुनुहुनेछ:

- **परिभाषित गर्नुहोस्** Model Context Protocol र यसको डेटाबेस एकीकरणका लागि मुख्य लाभहरू
- **पहिचान गर्नुहोस्** MCP सर्भर वास्तुकलाका प्रमुख कम्पोनेन्टहरू डेटाबेसहरूसँग
- **बुझ्नुहोस्** Zava Retail प्रयोग केस र यसको व्यापार आवश्यकताहरू
- **मान्यता दिनुहोस्** सुरक्षित, स्केलेबल डेटाबेस पहुँचका लागि उद्यम नमूनाहरू
- **सूचीबद्ध गर्नुहोस्** यस सिकाइ मार्गमा प्रयोग गरिएका उपकरण र प्रविधिहरू

## 🧭 चुनौती: AI र वास्तविक-विश्व डाटा

### परम्परागत AI सीमितताहरू

आधुनिक AI सहायकहरू अत्यन्त शक्तिशाली छन् तर वास्तविक-विश्व व्यापार डाटा सँग काम गर्दा महत्त्वपूर्ण सीमितताहरू भोग्छन्:

| **चुनौती** | **विवरण** | **व्यापार प्रभाव** |
|---------------|-----------------|-------------------|
| **स्थिर ज्ञान** | AI मोडेलहरू निश्चित डेटासेटहरूमा तालिम गरिएका छन्, वर्तमान व्यापार डाटा पहुँच गर्न सक्दैनन् | पुराना बुझाइहरू, अवसरहरू गुमाउनु |
| **डाटा सिलोहरू** | डाटाबेसहरू, API हरू, र प्रणालीहरूमा बन्द जानकारी AI ले पहुँच गर्न सक्दैन | अधूरा विश्लेषण, टुक्रिएको कार्यप्रवाहहरू |
| **सुरक्षा सीमाहरू** | प्रत्यक्ष डेटाबेस पहुँचले सुरक्षा र अनुपालन चिन्ताहरू बढाउँछ | सीमित वितरण, म्यानुअल डाटा तयारी |
| **जटिल प्रश्नहरू** | व्यापार प्रयोगकर्ताहरूलाई डाटा निष्कर्षणका लागि प्राविधिक ज्ञान आवश्यक पर्छ | कम अपनत्व, अप्रभावकारी प्रक्रियाहरू |

### MCP समाधान

Model Context Protocol यी चुनौतीहरूलाई यसरी सम्बोधन गर्छ:

- **वास्तविक-समय डाटा पहुँच**: AI सहायकहरूले प्रत्यक्ष डाटाबेस र API हरूलाई सोध्छन्
- **सुरक्षित एकीकरण**: प्रमाणीकरण र अनुमतिहरू सहित नियन्त्रण गरिएको पहुँच
- **प्राकृतिक भाषा इन्टरफेस**: व्यापार प्रयोगकर्ताहरू साधारण अंग्रेजीमा प्रश्न सोध्दछन्
- **मानकीकृत प्रोटोकल**: विभिन्न AI प्लेटफर्म र उपकरणहरूमा काम गर्छ

- **स्केलेबल वास्तुकला** जुन धेरै समवर्ती प्रयोगकर्ताहरूलाई समर्थन गर्छ

### प्रमुख कम्पोनेन्टहरू

#### **१. MCP सर्भर तह**
- **FastMCP फ्रेमवर्क**: आधुनिक Python MCP सर्भर कार्यान्वयन
- **टूल रजिस्ट्रेसन**: प्रकार सुरक्षा सहित घोषणात्मक उपकरण परिभाषाहरू
- **अनुरोध सन्दर्भ**: प्रयोगकर्ता पहिचान र सत्र प्रबन्धन
- **त्रुटि ह्यान्डलिंग**: दृढ त्रुटि व्यवस्थापन र लगिङ

#### **२. डेटाबेस एकीकरण तह**
- **कनेक्शन पूलिङ**: कुशल asyncpg कनेक्शन व्यवस्थापन
- **स्कीमा प्रदायक**: गतिशील तालिका स्कीमा खोज
- **प्रश्न कार्यान्वयनकर्ता**: RLS सन्दर्भ सहित सुरक्षित SQL कार्यान्वयन
- **लेनदेन व्यवस्थापन**: ACID अनुपालन र रोलब्याक ह्यान्डलिंग

#### **३. सुरक्षा तह**
- **रो लेवल सेक्युरिटी**: बहु-टेनेंट डाटा पृथक्करणका लागि PostgreSQL RLS
- **प्रयोगकर्ता पहिचान**: स्टोर प्रबन्धक प्रमाणीकरण र अधिकार
- **पहुँच नियन्त्रण**: सूक्ष्म अनुमतिहरू र लेखा निरीक्षण
- **इनपुट मान्यकरण**: SQL इन्जेक्शन रोकथाम र प्रश्न प्रमाणीकरण

#### **४. AI सुधार तह**
- **सेम्यान्टिक खोज**: उत्पादन पत्ता लगाउनका लागि भेक्टर एम्बेडिङहरू
- **Azure OpenAI एकीकरण**: टेक्स्ट एम्बेडिङ सिर्जना
- **समानता एल्गोरिदमहरू**: pgvector कोसाइन समानता खोज
- **खोज अनुकूलन**: अनुक्रमणिका र प्रदर्शन ट्यूनिङ

> "मेरो स्टोरको Q4 2024 का लागि राजस्वअनुसार शीर्ष १० उत्पादनहरू देखाउनुहोस्"

४. SQL प्रश्न सिर्जना र कार्यान्वयन गरिन्छ
५. परिणामहरू स्वरूपित गरिन्छ र AI च्याटमा फिर्ता पठाइन्छ
६. AI विश्लेषण र अन्तर्दृष्टिहरू प्रदान गर्छ

## 🔒 सुरक्षा र बहु-टेनेंसी गहिराइमा

हाम्रो कार्यान्वयनले उद्यम-स्तरीय सुरक्षालाई प्राथमिकता दिन्छ:

### रो लेवल सेक्युरिटी (RLS)

PostgreSQL RLS ले डाटा पृथक्करण सुनिश्चित गर्छ:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### प्रयोगकर्ता पहिचान व्यवस्थापन

प्रत्येक MCP कनेक्शनमा समावेश छ:
- **स्टोर प्रबन्धक ID**: RLS सन्दर्भको लागि अनूठो पहिचानकर्ता
- **भूमिका निर्धारण**: अनुमतिहरू र पहुँच स्तरहरू
- **सत्र व्यवस्थापन**: सुरक्षित प्रमाणीकरण टोकनहरू
- **अडिट लगिङ**: पूर्ण पहुँच इतिहास

### डाटा सुरक्षा

सुरक्षा स्तरहरू विभिन्न छन्:
- **कनेक्शन इन्क्रिप्सन**: सबै डेटाबेस कनेक्शनहरूका लागि TLS
- **SQL इन्जेक्शन रोकथाम**: केवल प्यारामिटराइज्ड प्रश्नहरू
- **इनपुट प्रमाणीकरण**: व्यापक अनुरोध प्रमाणीकरण
- **त्रुटि ह्यान्डलिंग**: त्रुटि सन्देशहरूमा संवेदनशील डाटा छैन
