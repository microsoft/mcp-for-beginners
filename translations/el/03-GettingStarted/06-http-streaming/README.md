Καλύπτει το κίνητρο για ροή, τους διαθέσιμους μηχανισμούς μεταφοράς, τον τρόπο υλοποίησης ροής HTTP στο MCP, τις βέλτιστες πρακτικές ασφαλείας, τη μετάβαση από SSE, και πρακτικές οδηγίες για την κατασκευή των δικών σας εφαρμογών MCP με ροή.

Η υποψηφία έκδοση για το `2026-07-28` αφαιρεί εντελώς το χειραψία και το αναγνωριστικό συνεδρίας, καθιστώντας κάθε αίτημα αυτόνομο και δρομολογήσιμο σε οποιαδήποτε παρουσία διακομιστή χωρίς συνεδρίες συνεχιστικότητας. ## Μηχανισμοί Μεταφοράς και Ροή στο MCP

Αυτή η ενότητα εξερευνά τους διαφορετικούς μηχανισμούς μεταφοράς που είναι διαθέσιμοι στο MCP και τον ρόλο τους στην ενεργοποίηση λειτουργιών ροής για επικοινωνία σε πραγματικό χρόνο μεταξύ πελατών και διακομιστών.

### Τι είναι ένας Μηχανισμός Μεταφοράς;

Ένας μηχανισμός μεταφοράς ορίζει πώς ανταλλάσσονται τα δεδομένα μεταξύ πελάτη και διακομιστή. Το MCP υποστηρίζει πολλούς τύπους μεταφοράς για να ταιριάζει σε διαφορετικά περιβάλλοντα και απαιτήσεις:

- **stdio**: Πρότυπη είσοδος/έξοδος, κατάλληλη για τοπικά εργαλεία και εργαλεία CLI. Απλή αλλά όχι κατάλληλη για web ή cloud.
- **SSE (Server-Sent Events)**: Επιτρέπει στους διακομιστές να στέλνουν ενημερώσεις σε πραγματικό χρόνο στους πελάτες μέσω HTTP. Κατάλληλο για διεπαφές ιστού, αλλά περιορισμένο στην κλιμακωσιμότητα και ευελιξία. Από το MCP Specification 2025-06-18, ο αυτόνομος μηχανισμός μεταφοράς SSE (Server-Sent Events) έχει απαλειφθεί και αντικατασταθεί από τον μηχανισμό "Streamable HTTP".
- **Streamable HTTP**: Σύγχρονη μεταφορά ροής βασισμένη σε HTTP, υποστηρίζοντας ειδοποιήσεις και καλύτερη κλιμακωσιμότητα. Συνιστάται για τις περισσότερες παραγωγικές και cloud περιπτώσεις.

### Πίνακας Σύγκρισης

Ρίξτε μια ματιά στον παρακάτω πίνακα σύγκρισης για να κατανοήσετε τις διαφορές μεταξύ αυτών των μηχανισμών μεταφοράς:

| Μεταφορά         | Ενημερώσεις σε πραγματικό χρόνο | Ροή      | Κλιμακωσιμότητα | Περίπτωση χρήσης          |
|-------------------|-------------------------------|-----------|-----------------|---------------------------|
| stdio             | Όχι                            | Όχι       | Χαμηλή          | Τοπικά εργαλεία CLI       |
| SSE               | Ναι                            | Ναι       | Μέτρια          | Ιστός, ενημερώσεις σε πραγματικό χρόνο |
| Streamable HTTP   | Ναι                            | Ναι       | Υψηλή           | Cloud, πολλαπλοί πελάτες  |

> **Συμβουλή:** Η επιλογή του σωστού μηχανισμού μεταφοράς επηρεάζει την απόδοση, την κλιμακωσιμότητα και την εμπειρία χρήστη. Το **Streamable HTTP** συνιστάται για σύγχρονες, κλιμακούμενες και έτοιμες για cloud εφαρμογές.

Σημειώστε τους μηχανισμούς stdio και SSE που παρουσιάστηκαν στα προηγούμενα κεφάλαια και πώς το Streamable HTTP είναι ο μηχανισμός που καλύπτεται σε αυτό το κεφάλαιο.

## Ροή: Έννοιες και Κίνητρα

Η κατανόηση των βασικών εννοιών και κινήτρων πίσω από τη ροή είναι ουσιώδης για την υλοποίηση αποτελεσματικών συστημάτων επικοινωνίας σε πραγματικό χρόνο.

**Η ροή** είναι μια τεχνική στον προγραμματισμό δικτύων που επιτρέπει την αποστολή και λήψη δεδομένων σε μικρά, διαχειρίσιμα κομμάτια ή ως ακολουθία συμβάντων, αντί να περιμένετε να είναι έτοιμη μια ολόκληρη ανταπόκριση. Αυτό είναι ιδιαίτερα χρήσιμο για:

- Μεγάλα αρχεία ή σύνολα δεδομένων.
- Ενημερώσεις σε πραγματικό χρόνο (π.χ., συνομιλίες, μπάρες προόδου).
- Μακροχρόνιες υπολογιστικές διεργασίες όπου θέλετε να κρατάτε τον χρήστη ενήμερο.

Να τι πρέπει να γνωρίζετε συνοπτικά για τη ροή:

- Τα δεδομένα παραδίδονται σταδιακά, όχι όλα μαζί.
- Ο πελάτης μπορεί να επεξεργάζεται τα δεδομένα καθώς φτάνουν.
- Μειώνει την αντιληπτή καθυστέρηση και βελτιώνει την εμπειρία χρήστη.

### Γιατί να χρησιμοποιήσετε ροή;

Οι λόγοι για τη χρήση της ροής είναι οι εξής:

- Οι χρήστες λαμβάνουν άμεση ανάδραση, όχι μόνο στο τέλος
- Επιτρέπει εφαρμογές σε πραγματικό χρόνο και ανταποκρινόμενες διεπαφές
- Αποτελεσματικότερη χρήση πόρων δικτύου και υπολογισμού

### Απλό Παράδειγμα: Διακομιστής & Πελάτης HTTP Ροής

Εδώ είναι ένα απλό παράδειγμα του πώς μπορεί να υλοποιηθεί η ροή:

#### Python

**Διακομιστής (Python, χρησιμοποιώντας FastAPI και StreamingResponse):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**Πελάτης (Python, χρησιμοποιώντας requests):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

Αυτό το παράδειγμα δείχνει έναν διακομιστή να στέλνει μια σειρά μηνυμάτων στον πελάτη καθώς καθίστανται διαθέσιμα, αντί να περιμένει να είναι έτοιμα όλα τα μηνύματα.

**Πώς λειτουργεί:**

- Ο διακομιστής παράγει κάθε μήνυμα καθώς είναι έτοιμο.
- Ο πελάτης λαμβάνει και εκτυπώνει κάθε κομμάτι καθώς φτάνει.

**Απαιτήσεις:**

- Ο διακομιστής πρέπει να χρησιμοποιεί απάντηση ροής (π.χ., `StreamingResponse` στο FastAPI).
- Ο πελάτης πρέπει να επεξεργάζεται την απάντηση ως ροή (`stream=True` στα requests).
- Το Content-Type συνήθως είναι `text/event-stream` ή `application/octet-stream`.

#### Java

**Διακομιστής (Java, χρησιμοποιώντας Spring Boot και Server-Sent Events):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**Πελάτης (Java, χρησιμοποιώντας Spring WebFlux WebClient):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**Σημειώσεις Εφαρμογής Java:**

- Χρησιμοποιεί το αντιδραστικό stack του Spring Boot με `Flux` για ροή
- Το `ServerSentEvent` παρέχει δομημένη ροή συμβάντων με τύπους συμβάντων
- Το `WebClient` με `bodyToFlux()` επιτρέπει την αντιδραστική κατανάλωση ροής
- Το `delayElements()` προσομοιώνει χρόνο επεξεργασίας μεταξύ συμβάντων
- Τα συμβάντα μπορούν να έχουν τύπους (`info`, `result`) για καλύτερη διαχείριση από τον πελάτη

### Σύγκριση: Κλασική Ροή vs Ροή MCP

Οι διαφορές μεταξύ του πώς λειτουργεί η ροή με "κλασικό" τρόπο σε σύγκριση με το πώς λειτουργεί στο MCP μπορούν να αποτυπωθούν ως εξής:

| Χαρακτηριστικό          | Κλασική HTTP Ροή             | Ροή MCP (Ειδοποιήσεις)           |
|------------------------|------------------------------|----------------------------------|
| Κύρια απάντηση         | Κατά τμήματα                 | Ενιαία, στο τέλος                |
| Ενημερώσεις προόδου     | Στέλνονται ως κομμάτια δεδομένων | Στέλνονται ως ειδοποιήσεις        |
| Απαιτήσεις πελάτη      | Πρέπει να επεξεργαστεί ροή   | Πρέπει να υλοποιήσει χειριστή μηνυμάτων |
| Περίπτωση χρήσης       | Μεγάλα αρχεία, ροές token AI | Πρόοδος, καταγραφές, ανάδραση σε πραγματικό χρόνο |

### Σημαντικές Διαφορές που Παρατηρούνται

Επιπλέον, εδώ είναι μερικές βασικές διαφορές:

- **Πρότυπο επικοινωνίας:**
  - Κλασική HTTP ροή: Χρησιμοποιεί απλή κωδικοποίηση μεταφοράς κατά τμήματα για αποστολή δεδομένων
  - MCP ροή: Χρησιμοποιεί δομημένο σύστημα ειδοποιήσεων με το πρωτόκολλο JSON-RPC

- **Μορφή μηνύματος:**
  - Κλασική HTTP: Απλά κείμενα με νέα γραμμή
  - MCP: Δομημένα αντικείμενα LoggingMessageNotification με μεταδεδομένα

- **Υλοποίηση πελάτη:**
  - Κλασική HTTP: Απλός πελάτης που επεξεργάζεται ροές απαντήσεων
  - MCP: Πιο εξελιγμένος πελάτης με χειριστή μηνυμάτων για επεξεργασία διαφορετικών τύπων μηνυμάτων

- **Ενημερώσεις προόδου:**
  - Κλασική HTTP: Η πρόοδος είναι μέρος της κύριας ροής απάντησης
  - MCP: Η πρόοδος αποστέλλεται μέσω ξεχωριστών μηνυμάτων ειδοποίησης ενώ η κύρια απάντηση έρχεται στο τέλος

### Συστάσεις

Υπάρχουν ορισμένα πράγματα που προτείνουμε όταν πρόκειται για την επιλογή μεταξύ υλοποίησης κλασικής ροής (ως endpoint που σας δείξαμε παραπάνω χρησιμοποιώντας `/stream`) έναντι ροής μέσω MCP.

- **Για απλές ανάγκες ροής:** Η κλασική HTTP ροή είναι πιο απλή στην υλοποίηση και επαρκής για βασικές ανάγκες ροής.

- **Για σύνθετες, διαδραστικές εφαρμογές:** Η ροή MCP παρέχει πιο δομημένη προσέγγιση με πλουσιότερα μεταδεδομένα και διαχωρισμό μεταξύ ειδοποιήσεων και τελικών αποτελεσμάτων.

- **Για εφαρμογές AI:** Το σύστημα ειδοποιήσεων του MCP είναι ιδιαίτερα χρήσιμο για μακροχρόνιες εργασίες AI όπου θέλετε να κρατάτε τους χρήστες ενήμερους για την πρόοδο.

## Ροή στο MCP

Εντάξει, έχετε δει κάποιες συστάσεις και συγκρίσεις μέχρι τώρα σχετικά με τη διαφορά μεταξύ κλασικής ροής και ροής στο MCP. Ας εμβαθύνουμε στο πώς ακριβώς μπορείτε να αξιοποιήσετε τη ροή στο MCP.

Η κατανόηση του πώς λειτουργεί η ροή εντός του πλαισίου MCP είναι ουσιώδης για την κατασκευή ανταποκρινόμενων εφαρμογών που παρέχουν ανάδραση σε πραγματικό χρόνο στους χρήστες κατά τη διάρκεια μακροχρόνιων λειτουργιών.

Στο MCP, η ροή δεν αφορά την αποστολή της κύριας απάντησης σε κομμάτια, αλλά την αποστολή **ειδοποιήσεων** στον πελάτη ενώ ένα εργαλείο επεξεργάζεται ένα αίτημα. Αυτές οι ειδοποιήσεις μπορεί να περιλαμβάνουν ενημερώσεις προόδου, καταγραφές ή άλλα συμβάντα.

### Πώς λειτουργεί

Το κύριο αποτέλεσμα εξακολουθεί να αποστέλλεται ως μία ενιαία απάντηση. Ωστόσο, ειδοποιήσεις μπορούν να αποστέλλονται ως ξεχωριστά μηνύματα κατά τη διάρκεια της επεξεργασίας και έτσι ενημερώνουν τον πελάτη σε πραγματικό χρόνο. Ο πελάτης πρέπει να μπορεί να διαχειρίζεται και να εμφανίζει αυτές τις ειδοποιήσεις.

## Τι είναι μια Ειδοποίηση;

Είπαμε "Ειδοποίηση", τι σημαίνει αυτό στο πλαίσιο του MCP;

Μια ειδοποίηση είναι ένα μήνυμα που αποστέλλεται από τον διακομιστή προς τον πελάτη για να ενημερώσει σχετικά με πρόοδο, κατάσταση ή άλλα συμβάντα κατά τη διάρκεια μιας μακροχρόνιας λειτουργίας. Οι ειδοποιήσεις βελτιώνουν τη διαφάνεια και την εμπειρία χρήστη.

Για παράδειγμα, ένας πελάτης υποτίθεται ότι αποστέλλει μια ειδοποίηση μόλις γίνει η αρχική χειραψία με τον διακομιστή.

Μια ειδοποίηση μοιάζει ως εξής ως μήνυμα JSON:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

Οι ειδοποιήσεις ανήκουν σε ένα θέμα στο MCP που αναφέρεται ως ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging).

> **Ειδοποίηση απόσυρσης:** η υποψηφία έκδοση για το MCP `2026-07-28` σηματοδοτεί την πρωτόγονη λειτουργία Logging ως αποσυρόμενη υπέρ του `stderr` για μεταφορές stdio και του OpenTelemetry για δομημένη παρατηρησιμότητα. Η λειτουργία καταγραφής συνεχίζει να λειτουργεί στο `2025-11-25` και για τουλάχιστον ένα χρόνο μετά από οποιαδήποτε επίσημη απόσυρση. Δείτε το [What's Changing in MCP: The 2026-07-28 Release Candidate](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md).

Για να λειτουργήσει η καταγραφή, ο διακομιστής χρειάζεται να την ενεργοποιήσει ως χαρακτηριστικό/δυνατότητα ως εξής:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> Ανάλογα με το SDK που χρησιμοποιείται, η καταγραφή μπορεί να είναι ενεργοποιημένη από προεπιλογή, ή μπορεί να χρειαστεί να την ενεργοποιήσετε ρητά στις ρυθμίσεις του διακομιστή σας.

Υπάρχουν διαφορετικοί τύποι ειδοποιήσεων:

| Επίπεδο    | Περιγραφή                      | Παράδειγμα περίπτωσης χρήσης   |
|-----------|-------------------------------|--------------------------------|
| debug     | Λεπτομερής πληροφορίες εντοπισμού σφαλμάτων | Σημεία εισόδου/εξόδου συναρτήσεων |
| info      | Γενικά ενημερωτικά μηνύματα   | Ενημερώσεις προόδου εργασιών    |
| notice    | Κανονικά αλλά σημαντικά συμβάντα | Αλλαγές ρυθμίσεων                |
| warning   | Συνθήκες προειδοποίησης       | Χρήση αποσυρόμενων λειτουργιών |
| error     | Συνθήκες σφάλματος            | Αποτυχίες λειτουργίας           |
| critical  | Κρίσιμες συνθήκες             | Αποτυχίες συστήματος            |
| alert     | Απαιτείται άμεση δράση         | Ανιχνεύθηκε διαφθορά δεδομένων  |
| emergency | Το σύστημα δεν είναι λειτουργικό | Ολική αποτυχία συστήματος     |

## Υλοποίηση Ειδοποιήσεων στο MCP

Για να υλοποιήσετε ειδοποιήσεις στο MCP, χρειάζεται να ρυθμίσετε τόσο την πλευρά του διακομιστή όσο και του πελάτη για να διαχειρίζονται ενημερώσεις σε πραγματικό χρόνο. Αυτό επιτρέπει στην εφαρμογή σας να παρέχει άμεση ανάδραση στους χρήστες κατά τη διάρκεια μακροχρόνιων λειτουργιών.

### Πλευρά Διακομιστή: Αποστολή Ειδοποιήσεων

Ας ξεκινήσουμε με την πλευρά του διακομιστή. Στο MCP, ορίζετε εργαλεία που μπορούν να στέλνουν ειδοποιήσεις κατά την επεξεργασία αιτήσεων. Ο διακομιστής χρησιμοποιεί το αντικείμενο συμφραζομένων (συνήθως `ctx`) για να στέλνει μηνύματα στον πελάτη.

#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

Στο προηγούμενο παράδειγμα, το εργαλείο `process_files` στέλνει τρεις ειδοποιήσεις στον πελάτη καθώς επεξεργάζεται κάθε αρχείο. Η μέθοδος `ctx.info()` χρησιμοποιείται για να στείλει ενημερωτικά μηνύματα.

Επιπλέον, για να ενεργοποιηθούν οι ειδοποιήσεις, βεβαιωθείτε ότι ο διακομιστής σας χρησιμοποιεί μηχανισμό ροής (όπως `streamable-http`) και ο πελάτης σας υλοποιεί χειριστή μηνυμάτων για να διαχειρίζεται τις ειδοποιήσεις. Δείτε πώς μπορείτε να ρυθμίσετε τον διακομιστή να χρησιμοποιεί τη μεταφορά `streamable-http`:

```python
mcp.run(transport="streamable-http")
```

#### .NET

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

Σε αυτό το παράδειγμα .NET, το εργαλείο `ProcessFiles` είναι διακοσμημένο με το χαρακτηριστικό `Tool` και στέλνει τρεις ειδοποιήσεις στον πελάτη καθώς επεξεργάζεται κάθε αρχείο. Η μέθοδος `ctx.Info()` χρησιμοποιείται για να στείλει ενημερωτικά μηνύματα.

Για να ενεργοποιήσετε τις ειδοποιήσεις στο .NET MCP διακομιστή σας, βεβαιωθείτε ότι χρησιμοποιείτε μηχανισμό ροής:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### Πλευρά Πελάτη: Λήψη Ειδοποιήσεων

Ο πελάτης πρέπει να υλοποιεί χειριστή μηνυμάτων για να επεξεργάζεται και να εμφανίζει τις ειδοποιήσεις καθώς φτάνουν.

#### Python

```python
async def message_handler(message):
```

## Ειδοποιήσεις Προόδου & Σενάρια

Αυτή η ενότητα εξηγεί την έννοια των ειδοποιήσεων προόδου στο MCP, γιατί είναι σημαντικές, και πώς να τις υλοποιήσετε χρησιμοποιώντας το Streamable HTTP. Θα βρείτε επίσης μια πρακτική άσκηση για να ενισχύσετε την κατανόησή σας.

Οι ειδοποιήσεις προόδου είναι μηνύματα σε πραγματικό χρόνο που αποστέλλονται από τον διακομιστή προς τον πελάτη κατά τη διάρκεια μακροχρόνιων λειτουργιών. Αντί να περιμένει να ολοκληρωθεί ολόκληρη η διαδικασία, ο διακομιστής κρατά τον πελάτη ενημερωμένο για την τρέχουσα κατάσταση. Αυτό βελτιώνει τη διαφάνεια, την εμπειρία χρήστη και διευκολύνει τον εντοπισμό σφαλμάτων.

**Παράδειγμα:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### Γιατί να Χρησιμοποιήσετε Ειδοποιήσεις Προόδου;

Οι ειδοποιήσεις προόδου είναι απαραίτητες για πολλούς λόγους:

- **Καλύτερη εμπειρία χρήστη:** Οι χρήστες βλέπουν ενημερώσεις καθώς εξελίσσεται η εργασία, όχι μόνο στο τέλος.
- **Ανάδραση σε πραγματικό χρόνο:** Οι πελάτες μπορούν να εμφανίζουν μπάρες προόδου ή καταγραφές, κάνοντας την εφαρμογή να φαίνεται πιο ανταποκρινόμενη.
- **Εύκολη παρακολούθηση και εντοπισμός σφαλμάτων:** Οι προγραμματιστές και οι χρήστες μπορούν να δουν πού μπορεί να υπάρχει καθυστέρηση ή κολλήμα στην διαδικασία.

### Πώς να Υλοποιήσετε Ειδοποιήσεις Προόδου

Να πώς μπορείτε να υλοποιήσετε τις ειδοποιήσεις προόδου στο MCP:

- **Στον διακομιστή:** Χρησιμοποιήστε `ctx.info()` ή `ctx.log()` για να στέλνετε ειδοποιήσεις καθώς κάθε στοιχείο επεξεργάζεται. Αυτό στέλνει μήνυμα στον πελάτη πριν το κύριο αποτέλεσμα είναι έτοιμο.
- **Στον πελάτη:** Υλοποιήστε έναν χειριστή μηνυμάτων που ακούει και εμφανίζει τις ειδοποιήσεις καθώς φτάνουν. Αυτός ο χειριστής διαχωρίζει τις ειδοποιήσεις από το τελικό αποτέλεσμα.

**Παράδειγμα διακομιστή:**


#### Python

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

## Θεωρήσεις Ασφαλείας

Η ασφάλεια πρέπει να είναι κορυφαία προτεραιότητα κατά την υλοποίηση οποιουδήποτε διακομιστή, ειδικά όταν χρησιμοποιούνται μεταφορές βασισμένες σε HTTP όπως το Streamable HTTP στο MCP.

Κατά την υλοποίηση διακομιστών MCP με μεταφορές βασισμένες σε HTTP, η ασφάλεια γίνεται ζωτικός παράγοντας που απαιτεί προσεκτική προσοχή σε πολλαπλές επιθέσεις και μηχανισμούς προστασίας.

### Επισκόπηση

Η ασφάλεια είναι κρίσιμη όταν γίνονται διαθέσιμοι διακομιστές MCP μέσω HTTP. Το Streamable HTTP εισάγει νέες επιφάνειες επιθέσεων και απαιτεί προσεκτική διαμόρφωση.

Εδώ είναι μερικές βασικές θεωρήσεις ασφαλείας:

- **Επικύρωση της Επικεφαλίδας Origin**: Πάντα επικυρώνετε την επικεφαλίδα `Origin` για να αποτρέψετε επιθέσεις DNS rebinding.
- **Δέσμευση στο Localhost**: Για τοπική ανάπτυξη, δεσμεύστε τους διακομιστές στο `localhost` για να αποφύγετε την έκθεσή τους στο δημόσιο διαδίκτυο.
- **Πιστοποίηση**: Εφαρμόστε πιστοποίηση (π.χ. API keys, OAuth) για παραγωγικές αναπτύξεις.
- **CORS**: Διαμορφώστε πολιτικές Cross-Origin Resource Sharing (CORS) για να περιορίσετε την πρόσβαση.
- **HTTPS**: Χρησιμοποιήστε HTTPS στην παραγωγή για να κρυπτογραφήσετε την κίνηση.

### Καλές Πρακτικές

Επιπλέον, εδώ είναι μερικές καλές πρακτικές που πρέπει να ακολουθήσετε κατά την υλοποίηση της ασφάλειας στον streaming server MCP σας:

- Μην εμπιστεύεστε ποτέ εισερχόμενα αιτήματα χωρίς επικύρωση.
- Καταγράφετε και παρακολουθείτε όλες τις προσβάσεις και τα λάθη.
- Ενημερώνετε τακτικά τις εξαρτήσεις για να διορθώνετε τρωτά σημεία ασφαλείας.

### Προκλήσεις

Θα αντιμετωπίσετε κάποιες προκλήσεις κατά την υλοποίηση της ασφάλειας σε streaming servers MCP:

- Εξισορρόπηση της ασφάλειας με την ευκολία ανάπτυξης
- Εξασφάλιση συμβατότητας με διάφορα περιβάλλοντα πελατών


## Αναβάθμιση από SSE σε Streamable HTTP

Για εφαρμογές που χρησιμοποιούν Server-Sent Events (SSE), η μετάβαση σε Streamable HTTP παρέχει βελτιωμένες δυνατότητες και καλύτερη μακροπρόθεσμη βιωσιμότητα για τις υλοποιήσεις MCP σας.

### Γιατί Αναβάθμιση;

Υπάρχουν δύο πειστικοί λόγοι για να αναβαθμίσετε από SSE σε Streamable HTTP:

- Το Streamable HTTP προσφέρει καλύτερη κλιμακωσιμότητα, συμβατότητα και πιο πλούσια υποστήριξη ειδοποιήσεων από το SSE.
- Είναι η προτεινόμενη μεταφορά για νέες εφαρμογές MCP.

### Βήματα Μεταφοράς

Δείτε πώς μπορείτε να μεταφέρετε από SSE σε Streamable HTTP στις εφαρμογές MCP σας:

- **Ενημερώστε τον κώδικα του διακομιστή** να χρησιμοποιεί `transport="streamable-http"` στο `mcp.run()`.
- **Ενημερώστε τον κώδικα του πελάτη** να χρησιμοποιεί `streamablehttp_client` αντί για τον SSE client.
- **Εφαρμόστε ένα χειριστή μηνυμάτων** στον πελάτη για να επεξεργάζεται τις ειδοποιήσεις.
- **Δοκιμάστε για συμβατότητα** με υπάρχοντα εργαλεία και ροές εργασίας.

### Διατήρηση Συμβατότητας

Συνιστάται να διατηρήσετε τη συμβατότητα με υπάρχοντες πελάτες SSE κατά τη διαδικασία μετανάστευσης. Εδώ είναι μερικές στρατηγικές:

- Μπορείτε να υποστηρίξετε και τα δύο, SSE και Streamable HTTP, τρέχοντας και τις δύο μεταφορές σε διαφορετικά σημεία πρόσβασης.
- Μεταφέρετε σταδιακά τους πελάτες στη νέα μεταφορά.

### Προκλήσεις

Βεβαιωθείτε ότι αντιμετωπίζετε τις ακόλουθες προκλήσεις κατά τη μετανάστευση:

- Εξασφάλιση ότι όλοι οι πελάτες ενημερώνονται
- Διαχείριση διαφορών στην παράδοση ειδοποιήσεων

### Άσκηση: Δημιουργήστε τη δική σας Εφαρμογή Streaming MCP

**Σενάριο:**
Δημιουργήστε έναν διακομιστή MCP και έναν πελάτη όπου ο διακομιστής επεξεργάζεται μια λίστα αντικειμένων (π.χ. αρχεία ή έγγραφα) και στέλνει μια ειδοποίηση για κάθε επεξεργασμένο αντικείμενο. Ο πελάτης πρέπει να εμφανίζει κάθε ειδοποίηση καθώς αυτή φτάνει.

**Βήματα:**

1. Υλοποιήστε ένα εργαλείο διακομιστή που επεξεργάζεται μια λίστα και στέλνει ειδοποιήσεις για κάθε αντικείμενο.
2. Υλοποιήστε έναν πελάτη με χειριστή μηνυμάτων για να εμφανίζει τις ειδοποιήσεις σε πραγματικό χρόνο.
3. Δοκιμάστε την υλοποίησή σας τρέχοντας τόσο τον διακομιστή όσο και τον πελάτη και παρατηρήστε τις ειδοποιήσεις.
