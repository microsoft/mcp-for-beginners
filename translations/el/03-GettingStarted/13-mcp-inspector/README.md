# Αποσφαλμάτωση με το MCP Inspector

> [!NOTE]
> Οι εντολές που χρησιμοποιούν `--sse` και οι διευθύνσεις URL που τελειώνουν σε `/sse` δοκιμάζουν το παλαιό πρωτόκολλο HTTP+SSE.
> Για έναν νέο MCP εξυπηρετητή `2026-07-28`, χρησιμοποιήστε μια έκδοση Inspector που
> υποστηρίζει Streamable HTTP και επιλέξτε αυτό το πρωτόκολλο αντί γι' αυτό.

Το **MCP Inspector** είναι ένα απαραίτητο εργαλείο αποσφαλμάτωσης που σας επιτρέπει να δοκιμάζετε και να επιλύετε διαδραστικά προβλήματα στους MCP εξυπηρετητές σας χωρίς να χρειάζεστε μια πλήρη εφαρμογή φιλοξενίας AI. Σκεφτείτε το ως "Postman για MCP" - παρέχει ένα οπτικό περιβάλλον για να στέλνετε αιτήματα, να βλέπετε απαντήσεις και να κατανοείτε πώς συμπεριφέρεται ο εξυπηρετητής σας.

## Γιατί να χρησιμοποιήσετε το MCP Inspector;

Κατά την κατασκευή MCP εξυπηρετητών, συχνά θα αντιμετωπίσετε αυτά τα προβλήματα:

- **"Λειτουργεί καν ο εξυπηρετητής μου;"** - Το Inspector δείχνει την κατάσταση σύνδεσης
- **"Είναι τα εργαλεία μου σωστά καταχωρημένα;"** - Το Inspector εμφανίζει όλα τα διαθέσιμα εργαλεία
- **"Ποια είναι η μορφή απάντησης;"** - Το Inspector παρουσιάζει πλήρεις απαντήσεις JSON
- **"Γιατί δε λειτουργεί αυτό το εργαλείο;"** - Το Inspector δείχνει λεπτομερή μηνύματα σφάλματος

## Προαπαιτούμενα

- Εγκατεστημένο Node.js 18+
- npm (έρχεται με το Node.js)
- Ένας MCP εξυπηρετητής για δοκιμή (βλέπε [Module 3.1 - First Server](../01-first-server/README.md))

## Εγκατάσταση

### Επιλογή 1: Εκτέλεση με npx (Συνιστάται για γρήγορη δοκιμή)

```bash
npx @modelcontextprotocol/inspector
```

### Επιλογή 2: Παγκόσμια εγκατάσταση

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### Επιλογή 3: Προσθήκη στο έργο σας

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

Προσθήκη στο `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## Σύνδεση με τον εξυπηρετητή σας

### stdio Εξυπηρετητές (Τοπική διαδικασία)

Για εξυπηρετητές που επικοινωνούν μέσω τυπικής εισόδου/εξόδου:

```bash
# Python διακομιστής
npx @modelcontextprotocol/inspector python -m your_server_module

# Node.js διακομιστής
npx @modelcontextprotocol/inspector node ./build/index.js

# Με μεταβλητές περιβάλλοντος
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP Εξυπηρετητές (Δίκτυο)

Για εξυπηρετητές που τρέχουν ως υπηρεσίες HTTP:

1. Ξεκινήστε πρώτα τον εξυπηρετητή σας:
   ```bash
   python server.py  # Ο διακομιστής λειτουργεί στο http://localhost:8080
   ```

2. Εκκινήστε το Inspector και συνδεθείτε:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## Δοκιμή Εργαλείων

### Λίστα Διαθέσιμων Εργαλείων

1. Κάντε κλικ στην καρτέλα **Tools**
2. Το Inspector καλεί αυτόματα το `tools/list`
3. Θα δείτε όλα τα καταχωρημένα εργαλεία με:
   - Όνομα εργαλείου
   - Περιγραφή
   - Σχήμα εισόδου (παραμέτρους)

### Κλήση Εργαλείου

1. Επιλέξτε ένα εργαλείο από τη λίστα
2. Συμπληρώστε τις απαιτούμενες παραμέτρους στη φόρμα
3. Κάντε κλικ στο **Run Tool**
4. Δείτε την απάντηση στον πίνακα αποτελεσμάτων

**Παράδειγμα: Δοκιμή εργαλείου υπολογιστή**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### Αποσφαλμάτωση σφαλμάτων εργαλείων

Όταν ένα εργαλείο αποτυγχάνει, το Inspector δείχνει:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

Συνηθισμένοι κωδικοί σφάλματος:
| Κωδικός | Σημασία |
|------|---------|
| -32700 | Σφάλμα ανάλυσης (μη έγκυρο JSON) |
| -32600 | Μη έγκυρο αίτημα |
| -32601 | Μέθοδος δεν βρέθηκε |
| -32602 | Μη έγκυρες παράμετροι |
| -32603 | Εσωτερικό σφάλμα |

## Δοκιμή Πόρων

### Λίστα Πόρων

1. Κάντε κλικ στην καρτέλα **Resources**
2. Το Inspector καλεί `resources/list`
3. Θα δείτε:
   - URI πόρων
   - Ονόματα και περιγραφές
   - Τύπους MIME

### Ανάγνωση Πόρου

1. Επιλέξτε έναν πόρο
2. Κάντε κλικ στο **Read Resource**
3. Δείτε το επιστρεφόμενο περιεχόμενο

**Παράδειγμα εξόδου:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## Δοκιμή Προτροπών (Prompts)

### Λίστα Προτροπών

1. Κάντε κλικ στην καρτέλα **Prompts**
2. Το Inspector καλεί `prompts/list`
3. Δείτε διαθέσιμα πρότυπα προτροπών

### Λήψη Προτροπής

1. Επιλέξτε μια προτροπή
2. Συμπληρώστε τυχόν απαιτούμενα επιχειρήματα
3. Κάντε κλικ στο **Get Prompt**
4. Δείτε τα αποδοθέντα μηνύματα προτροπής

## Ανάλυση Αρχείου Καταγραφής Μηνυμάτων

Το αρχείο καταγραφής μηνυμάτων δείχνει όλα τα μηνύματα πρωτοκόλλου MCP. Η παρακάτω απομαγνητοφώνηση προέρχεται από έναν
παλαιό εξυπηρετητή `2025-11-25` και περιλαμβάνει το αφαιρεθέν χειραψία `initialize`. Ένας
εξυπηρετητής `2026-07-28` χρησιμοποιεί αυτοδύναμα μεταδεδομένα αιτήματος και `server/discover`
αντί αυτού.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### Τι να προσέξετε

- **Ζεύγη Αιτήματος/Απάντησης**: Κάθε `→` πρέπει να έχει αντίστοιχο `←`
- **Μηνύματα σφάλματος**: Ψάξτε για `"error"` στις απαντήσεις
- **Χρονισμός**: Μεγάλα διαστήματα μπορεί να υποδεικνύουν θέματα απόδοσης
- **Έκδοση πρωτοκόλλου**: Εξασφαλίστε ότι ο εξυπηρετητής και ο πελάτης συμφωνούν στην έκδοση

## Ενσωμάτωση με VS Code

Μπορείτε να εκτελέσετε το Inspector απευθείας από το VS Code:

### Χρήση launch.json

Προσθέστε στο `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

### Χρήση Tasks

Προσθέστε στο `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Start MCP Inspector",
      "type": "shell",
      "command": "npx @modelcontextprotocol/inspector node ${workspaceFolder}/build/index.js",
      "isBackground": true,
      "problemMatcher": {
        "pattern": {
          "regexp": "^$"
        },
        "background": {
          "activeOnStart": true,
          "beginsPattern": "Inspector",
          "endsPattern": "listening"
        }
      }
    }
  ]
}
```

## Συνήθη Σενάρια Αποσφαλμάτωσης

### Σενάριο 1: Ο εξυπηρετητής δεν συνδέεται

**Συμπτώματα:** Το Inspector δείχνει "Disconnected" ή κολλάει στο "Connecting..."

**Λίστα ελέγχου:**
1. ✅ Η εντολή εξυπηρετητή είναι σωστή;
2. ✅ Όλες οι εξαρτήσεις είναι εγκατεστημένες;
3. ✅ Η διαδρομή του εξυπηρετητή είναι απόλυτη ή σχετική προς τον τρέχοντα κατάλογο;
4. ✅ Έχουν οριστεί οι απαιτούμενες περιβαλλοντικές μεταβλητές;

**Βήματα αποσφαλμάτωσης:**
```bash
# Δοκιμάστε τον διακομιστή χειροκίνητα πρώτα
python -c "import your_server_module; print('OK')"

# Ελέγξτε για σφάλματα εισαγωγής
python -m your_server_module 2>&1 | head -20

# Επαληθεύστε ότι το MCP SDK είναι εγκατεστημένο
pip show mcp
```

### Σενάριο 2: Τα εργαλεία δεν εμφανίζονται

**Συμπτώματα:** Η καρτέλα εργαλείων εμφανίζει κενή λίστα

**Πιθανές αιτίες:**
1. Τα εργαλεία δεν καταχωρήθηκαν κατά την εκκίνηση του εξυπηρετητή
2. Ο εξυπηρετητής κατέρρευσε μετά την εκκίνηση
3. Ο χειριστής `tools/list` επιστρέφει κενό πίνακα

**Βήματα αποσφαλμάτωσης:**
1. Ελέγξτε το αρχείο καταγραφής για απάντηση `tools/list`
2. Προσθέστε καταγραφή στον κώδικα καταχώρησης εργαλείων σας
3. Επιβεβαιώστε ότι υπάρχουν διακοσμητές `@mcp.tool()` (Python)

### Σενάριο 3: Το εργαλείο επιστρέφει σφάλμα

**Συμπτώματα:** Η κλήση εργαλείου επιστρέφει απάντηση με σφάλμα

**Προσέγγιση αποσφαλμάτωσης:**
1. Διαβάστε προσεκτικά το μήνυμα σφάλματος
2. Ελέγξτε αν οι τύποι παραμέτρων ταιριάζουν με το σχήμα
3. Προσθέστε try/catch με λεπτομερή μηνύματα σφάλματος
4. Ελέγξτε τα αρχεία καταγραφής εξυπηρετητή για στοίβες κλήσεων

**Παράδειγμα βελτιωμένης διαχείρισης σφαλμάτων:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # Η λογική του εργαλείου εδώ
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### Σενάριο 4: Το περιεχόμενο πόρου είναι κενό

**Συμπτώματα:** Ο πόρος επιστρέφει αλλά το περιεχόμενο είναι κενό ή null

**Λίστα ελέγχου:**
1. ✅ Η διαδρομή αρχείου ή URI είναι σωστή
2. ✅ Ο εξυπηρετητής έχει άδεια ανάγνωσης του πόρου
3. ✅ Το περιεχόμενο του πόρου επιστρέφεται σωστά

## Προχωρημένες δυνατότητες Inspector

### Προσαρμοσμένες κεφαλίδες (SSE)

```bash
npx @modelcontextprotocol/inspector \
  --sse http://localhost:8080/sse \
  --header "Authorization: Bearer your-token"
```

### Αναλυτική Καταγραφή

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### Εγγραφή Συνεδριών

Το Inspector μπορεί να εξάγει αρχεία καταγραφής μηνυμάτων για μετέπειτα ανάλυση:
1. Κάντε κλικ στο **Export Log** στον πίνακα μηνυμάτων
2. Αποθηκεύστε το αρχείο JSON
3. Μοιραστείτε το με μέλη της ομάδας για αποσφαλμάτωση

## Καλές πρακτικές

1. **Δοκιμάζετε νωρίς και συχνά** - Χρησιμοποιήστε το Inspector κατά την ανάπτυξη, όχι μόνο όταν προκύπτουν προβλήματα
2. **Ξεκινήστε απλά** - Δοκιμάστε βασική συνδεσιμότητα πριν από σύνθετες κλήσεις εργαλείων
3. **Ελέγξτε το σχήμα** - Πολλά σφάλματα προέρχονται από ασυμφωνίες τύπων παραμέτρων
4. **Διαβάστε τα μηνύματα σφάλματος** - Τα σφάλματα MCP συνήθως είναι περιγραφικά
5. **Κρατήστε ανοιχτό το Inspector** - Βοηθά στην έγκαιρη ανίχνευση προβλημάτων κατά την ανάπτυξη
