# Налагодження з MCP Inspector

> [!NOTE]
> Команди з використанням `--sse` і URL-адреси, що закінчуються на `/sse`, тестують спадкову HTTP+SSE 
> транспортну технологію. Для нового сервера MCP `2026-07-28` використовуйте версію Inspector, яка 
> підтримує Streamable HTTP, і виберіть цей транспорт замість цього.

**MCP Inspector** — це необхідний інструмент налагодження, який дозволяє вам інтерактивно тестувати та усувати несправності серверів MCP без потреби в повноцінному AI хості. Уявіть його як "Postman для MCP" — він надає візуальний інтерфейс для відправлення запитів, перегляду відповідей і розуміння поведінки вашого сервера.

## Чому варто використовувати MCP Inspector?

Під час створення серверів MCP ви часто стикатиметеся з такими викликами:

- **"Чи запущений мій сервер?"** — Inspector показує статус підключення
- **"Чи правильно зареєстровані мої інструменти?"** — Inspector відображає всі доступні інструменти
- **"Який формат відповіді?"** — Inspector відображає повні відповіді у форматі JSON
- **"Чому цей інструмент не працює?"** — Inspector показує детальні повідомлення про помилки

## Вимоги

- Встановлений Node.js версії 18 або новіший
- npm (входить до складу Node.js)
- MCP-сервер для тестування (див. [Модуль 3.1 - Перший сервер](../01-first-server/README.md))

## Встановлення

### Варіант 1: Запуск через npx (Рекомендовано для швидкого тестування)

```bash
npx @modelcontextprotocol/inspector
```

### Варіант 2: Глобальна установка

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### Варіант 3: Додати до вашого проекту

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

Додайте до `package.json`:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## Підключення до сервера

### Сервери stdio (локальний процес)

Для серверів, які спілкуються через стандартний ввід/вивід:

```bash
# Сервер на Python
npx @modelcontextprotocol/inspector python -m your_server_module

# Сервер на Node.js
npx @modelcontextprotocol/inspector node ./build/index.js

# З змінними оточення
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### Сервери SSE/HTTP (мережеві)

Для серверів, що працюють як HTTP-сервіси:

1. Спочатку запустіть сервер:
   ```bash
   python server.py  # Сервер запущено на http://localhost:8080
   ```

2. Запустіть Inspector і підключіться:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## Тестування інструментів

### Перелік доступних інструментів

1. Клацніть на вкладку **Tools**
2. Inspector автоматично викликає `tools/list`
3. Ви побачите всі зареєстровані інструменти з:
   - Назвою інструменту
   - Описом
   - Схемою введення (параметрами)

### Виклик інструменту

1. Виберіть інструмент зі списку
2. Заповніть потрібні параметри у формі
3. Натисніть **Run Tool**
4. Перегляньте відповідь у панелі результатів

**Приклад: Тестування калькуляторного інструменту**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### Налагодження помилок інструментів

Якщо інструмент не працює, Inspector виводить:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

Поширені коди помилок:
| Код | Значення |
|------|---------|
| -32700 | Помилка розбору (недійсний JSON) |
| -32600 | Недійсний запит |
| -32601 | Метод не знайдено |
| -32602 | Недійсні параметри |
| -32603 | Внутрішня помилка |

## Тестування ресурсів

### Перелік ресурсів

1. Клацніть на вкладку **Resources**
2. Inspector викликає `resources/list`
3. Ви побачите:
   - URI ресурсів
   - Назви та описи
   - MIME-типи

### Читання ресурсу

1. Виберіть ресурс
2. Натисніть **Read Resource**
3. Перегляньте повернений вміст

**Приклад виводу:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## Тестування підказок

### Перелік підказок

1. Клацніть на вкладку **Prompts**
2. Inspector викликає `prompts/list`
3. Перегляньте доступні шаблони підказок

### Отримання підказки

1. Виберіть підказку
2. Заповніть необхідні аргументи
3. Натисніть **Get Prompt**
4. Перегляньте відображені повідомлення підказки

## Аналіз журналу повідомлень

Журнал повідомлень відображає всі повідомлення протоколу MCP. Нижче наведено транскрипт зі
спадкового сервера `2025-11-25`, що містить видалене рукостискання `initialize`. Сервер
`2026-07-28` використовує самодостатні метадані запиту та `server/discover`
замість цього.

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### На що звернути увагу

- **Пари Запит/Відповідь**: Для кожного `→` має бути відповідний `←`
- **Повідомлення про помилки**: Шукайте `"error"` у відповідях
- **Час**: Великі паузи можуть свідчити про проблеми з продуктивністю
- **Версія протоколу**: Переконайтеся, що сервер і клієнт узгоджують версію

## Інтеграція з VS Code

Ви можете запускати Inspector прямо із VS Code:

### Використання launch.json

Додайте до `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug with MCP Inspector",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npx",
      "runtimeArgs": [
        "@modelcontextprotocol/inspector",
        "python",
        "${workspaceFolder}/server.py"
      ],
      "console": "integratedTerminal"
    },
    {
      "name": "Debug SSE Server with Inspector",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:5173",
      "preLaunchTask": "Start MCP Inspector"
    }
  ]
}
```

### Використання задач (Tasks)

Додайте до `.vscode/tasks.json`:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "Start MCP Inspector",
      "type": "shell",
      "command": "npx @modelcontextprotocol/inspector node ${workspaceFolder}/build/index.js",
      "isBackground": true,
      "problemMatcher": {
        "pattern": {
          "regexp": "^$"
        },
        "background": {
          "activeOnStart": true,
          "beginsPattern": "Inspector",
          "endsPattern": "listening"
        }
      }
    }
  ]
}
```

## Поширені сценарії налагодження

### Сценарій 1: Сервер не підключається

**Симптоми:** Inspector показує "Disconnected" або зависає на "Connecting..."

**Контрольний список:**
1. ✅ Чи правильна команда запуску сервера?
2. ✅ Чи встановлені всі залежності?
3. ✅ Чи є шлях до сервера абсолютним або відносним до поточної теки?
4. ✅ Чи встановлені потрібні змінні середовища?

**Кроки налагодження:**
```bash
# Спочатку вручну протестуйте сервер
python -c "import your_server_module; print('OK')"

# Перевірте на наявність помилок імпорту
python -m your_server_module 2>&1 | head -20

# Переконайтеся, що MCP SDK встановлено
pip show mcp
```

### Сценарій 2: Інструменти не з’являються

**Симптоми:** Вкладка інструментів показує порожній список

**Можливі причини:**
1. Інструменти не зареєстровані під час ініціалізації сервера
2. Сервер аварійно завершив роботу після запуску
3. Обробник `tools/list` повертає порожній масив

**Кроки налагодження:**
1. Перевірте журнал повідомлень для відповіді `tools/list`
2. Додайте логування у код реєстрації інструментів
3. Переконайтеся, що є декоратори `@mcp.tool()` (для Python)

### Сценарій 3: Інструмент повертає помилку

**Симптоми:** Виклик інструменту повертає повідомлення про помилку

**Підхід до налагодження:**
1. Уважно прочитайте повідомлення про помилку
2. Перевірте, чи типи параметрів відповідають схемі
3. Додайте блок try/catch з детальними повідомленнями про помилки
4. Перевірте логи серверу на наявність трасування стека

**Приклад покращеного оброблення помилок:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # Логіка інструменту тут
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### Сценарій 4: Вміст ресурсу порожній

**Симптоми:** Ресурс повертає, але вміст порожній або null

**Контрольний список:**
1. ✅ Шлях до файлу або URI правильний
2. ✅ Сервер має дозвіл на читання ресурсу
3. ✅ Вміст ресурсу коректно повертається

## Розширені можливості Inspector

### Користувацькі заголовки (SSE)

```bash
npx @modelcontextprotocol/inspector \
  --sse http://localhost:8080/sse \
  --header "Authorization: Bearer your-token"
```

### Розширене логування

```bash
DEBUG=mcp* npx @modelcontextprotocol/inspector python server.py
```

### Запис сесій

Inspector може експортувати журнали повідомлень для подальшого аналізу:
1. Клацніть **Export Log** у панелі повідомлень
2. Збережіть JSON-файл
3. Поділіться ним з членами команди для налагодження

## Кращі практики

1. **Тестуйте рано і часто** — Використовуйте Inspector під час розробки, а не лише коли щось ламається
2. **Починайте з простого** — Перевірте базове з'єднання перед викликами складних інструментів
3. **Перевірте схему** — Багато помилок виникають через невідповідність типів параметрів
4. **Читайте повідомлення про помилки** — Помилки MCP зазвичай описові
5. **Тримайте Inspector відкритим** — це допомагає виявляти проблеми під час розробки
