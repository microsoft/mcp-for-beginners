# Розгортання MCP серверів

> [!NOTE]
> Приклади конфігурацій, які використовують кінцеву точку `/sse`, орієнтовані на застарілий транспорт HTTP+SSE. MCP віддалені сервери `2026-07-28` використовують Streamable HTTP, зазвичай на серверно-визначеній кінцевій точці, такій як `/mcp`.
> 
> 

Розгортання вашого MCP сервера дозволяє іншим отримувати доступ до його інструментів і ресурсів поза межами вашого локального середовища. Існує кілька стратегій розгортання, які варто врахувати залежно від ваших вимог до масштабованості, надійності та зручності керування. Нижче ви знайдете рекомендації щодо розгортання MCP серверів локально, у контейнерах і в хмарі.

## Огляд

У цьому уроці розглядається, як розгорнути ваш MCP сервер.

## Цілі навчання

Наприкінці цього уроку ви зможете:

- Оцінювати різні підходи до розгортання.
- Розгортати ваш додаток.

## Локальна розробка та розгортання

Якщо ваш сервер призначений для використання на комп’ютері користувача, ви можете слідувати цим крокам:

1. **Завантажте сервер**. Якщо ви не писали сервер, спочатку завантажте його на свій комп’ютер.
1. **Запустіть процес сервера**: Запустіть ваш MCP сервер додаток

Для SSE (не потрібно для серверів типу stdio)

1. **Налаштуйте мережу**: Переконайтеся, що сервер доступний на потрібному порті
1. **Підключіть клієнтів**: Використовуйте локальні URL-адреси типу `http://localhost:3000`

## Розгортання в хмарі

MCP сервери можна розгортати на різних хмарних платформах:

- **Serverless-функції**: розгортайте легкі MCP сервери як serverless-функції
- **Контейнерні сервіси**: використовуйте сервіси на кшталт Azure Container Apps, AWS ECS або Google Cloud Run
- **Kubernetes**: розгортайте й керуйте MCP серверами в кластерах Kubernetes для високої доступності

### Приклад: Azure Container Apps

Azure Container Apps підтримують розгортання MCP серверів. Це ще в процесі розробки, і наразі підтримуються SSE сервери.

Ось як ви можете це зробити:

1. Клонуйте репозиторій:

  ```sh
  git clone https://github.com/anthonychu/azure-container-apps-mcp-sample.git
  ```

1. Запустіть локально для тестування:

  ```sh
  uv venv
  uv sync

  # linux/macOS
  export API_KEYS=<AN_API_KEY>
  # windows
  set API_KEYS=<AN_API_KEY>

  uv run fastapi dev main.py
  ```

1. Щоб спробувати локально, створіть файл *mcp.json* у директорії *.vscode* і додайте такий вміст:

  ```json
  {
      "inputs": [
          {
              "type": "promptString",
              "id": "weather-api-key",
              "description": "Weather API Key",
              "password": true
          }
      ],
      "servers": {
          "weather-sse": {
              "type": "sse",
              "url": "http://localhost:8000/sse",
              "headers": {
                  "x-api-key": "${input:weather-api-key}"
              }
          }
      }
  }
  ```

  Як тільки SSE сервер буде запущено, ви можете натиснути на іконку відтворення у JSON-файлі, тепер ви повинні бачити, що інструменти на сервері підхоплює GitHub Copilot, дивіться іконку інструментів.

1. Для розгортання виконайте наступну команду:

  ```sh
  az containerapp up -g <RESOURCE_GROUP_NAME> -n weather-mcp --environment mcp -l westus --env-vars API_KEYS=<AN_API_KEY> --source .
  ```

Ось і все, розгорніть локально або в Azure за допомогою цих кроків.
