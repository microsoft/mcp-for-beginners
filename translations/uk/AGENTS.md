# AGENTS.md

## Огляд Проєкту

**MCP для початківців** — це відкритий освітній курс для вивчення Model Context Protocol (MCP) — стандартизованої структури для взаємодії між AI-моделями та клієнтськими додатками. Цей репозиторій надає всебічні навчальні матеріали з практичними прикладами коду на кількох мовах програмування.

### Ключові технології

- **Мови програмування**: C#, Java, JavaScript, TypeScript, Python, Rust
- **Фреймворки та SDK**: 
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **Бази даних**: PostgreSQL з розширенням pgvector
- **Хмарні платформи**: Azure (Container Apps, OpenAI, Content Safety, Application Insights)
- **Інструменти збірки**: npm, Maven, pip, Cargo
- **Документація**: Markdown з автоматизованим багатомовним перекладом (понад 48 мов)

### Архітектура

- **11 основних модулів (00-11)**: Послідовний навчальний шлях від базових до просунутих тем
- **Практичні лабораторні роботи**: Практичні вправи з повним кодом рішень на кількох мовах
- **Зразкові проєкти**: Робочі реалізації MCP-сервера та клієнта
- **Система перекладу**: Автоматизований GitHub Actions workflow для підтримки багатьох мов
- **Графічні ресурси**: Централізований каталог зображень із перекладеними версіями

## Команди для налаштування

Це репозиторій, орієнтований на документацію. Основне налаштування відбувається в окремих зразкових проєктах та лабораторіях.

### Налаштування репозиторію

```bash
# Клонуйте репозиторій
git clone https://github.com/microsoft/mcp-for-beginners.git
cd mcp-for-beginners
```

### Робота із зразковими проєктами

Зразкові проєкти розміщені у:
- `03-GettingStarted/samples/` — приклади для конкретних мов
- `03-GettingStarted/01-first-server/solution/` — перші реалізації серверів
- `03-GettingStarted/02-client/solution/` — реалізації клієнтів
- `11-MCPServerHandsOnLabs/` — комплексні лабораторні роботи з інтеграції БД

Кожен зразковий проєкт містить власні інструкції з налаштування:

#### Проєкти на TypeScript/JavaScript
```bash
cd <project-directory>
npm install
npm start
```

#### Проєкти на Python
```bash
cd <project-directory>
pip install -r requirements.txt
# або
pip install -e .
python main.py
```

#### Проєкти на Java
```bash
cd <project-directory>
mvn clean install
mvn spring-boot:run
```

##### Мета

Перевірити стан змін у документації курсу та репрезентативному прикладному коді
перед злиттям.

##### Вхідні дані

- `changed_paths: string[]` (обов’язково) — відносні шляхи, змінені у PR.
- `run_docs_lint: boolean` (за замовчуванням `true`)
- `run_links_audit: boolean` (за замовчуванням `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (за замовчуванням усі `false`)

##### Вихідні дані

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### Права доступу

- Лише читання робочих файлів та запис артефактів, створених інструментом (наприклад, звіти лінтингу,
  логи тестів); без запису у `translations/` або
  `translated_images/`.
- Виконання локальних shell-команд.
- Опціональний мережевий доступ лише для відновлення пакетів (`npm ci`,
  `python -m pip install`, `mvn` dependency resolution).
- Без прав на пуш, злиття або модифікацію `translations/` або
  `translated_images/`.

##### Режими відмови

- `E_NO_INPUT_PATHS`: пустий `changed_paths`.
- `E_INVALID_PATH`: вхідний шлях виходить за межі кореня репозиторію.
- `E_LINT_FAILED`: лінтинг markdown завершився з кодом, відмінним від нуля.
- `E_LINK_AUDIT_FAILED`: команда аудиту посилань завершилась з кодом, відмінним від нуля.
- `E_SAMPLE_TEST_FAILED`: тест або збірка зразка завершилися з кодом, відмінним від нуля.
- `E_TIMEOUT`: команда перевищила налаштований таймаут.

- Використовуйте зрозумілу, дружню до початківців мову

  - Використовуйте заголовки ATX-стилю (синтаксис `#`)

  - Додавайте описовий alt-текст для зображень
  - Тримайте довжину рядків розумною (без жорстких обмежень, але раціонально)

### Стиль прикладів коду

#### TypeScript/JavaScript
- Використовуйте модулі ES (`import`/`export`)
- Дотримуйтеся строгого режиму TypeScript
- Включайте анотації типів
- Орієнтуйтеся на ES2022

#### Python
- Дотримуйтеся стандарту стилю PEP 8
- Використовуйте типові підказки, там де потрібно
- Додавайте docstrings для функцій і класів
- Використовуйте сучасні можливості Python (3.8+)

#### Java
- Дотримуйтеся конвенцій Spring Boot
- Використовуйте можливості Java 21
- Дотримуйтеся стандартної структури Maven-проєкту
- Додавайте коментарі Javadoc

## Правила внесення змін

### Процес Pull Request

1. **Форк та клонування**: зробіть форк репозиторію та клонувати свій форк локально
2. **Створення гілки**: використовуйте описові назви гілок (наприклад, `fix/typo-module-3`, `add/python-example`)
3. **Внесення змін**: редагуйте лише англомовні markdown-файли (не переклади)
4. **Локальне тестування**: перевірте правильність відображення markdown
5. **Відправка PR**: використовуйте чіткі назви та описи PR
6. **CLA**: підпишіть Microsoft Contributor License Agreement, коли буде запитано

### Формат заголовків PR

Використовуйте чіткі, описові заголовки:
- `[Module XX] Короткий опис` для змін у модулі
- `[Samples] Опис` для змін у зразковому коді
- `[Docs] Опис` для загальних оновлень документації

### Що можна додавати

- Виправлення помилок у документації або коді прикладів
- Нові приклади коду на додаткових мовах
- Уточнення та покращення існуючого контенту
- Нові кейс-стаді або практичні приклади
- Запити на усунення неясностей або помилок

### Чого НЕ слід робити

- Не редагуйте безпосередньо файли у каталозі `translations/`
- Не редагуйте каталог `translated_images/`
- Не додавайте великі бінарні файли без обговорення
- Не змінюйте файли workflow перекладу без координації

**Питання: Приклади коду не працюють**

В: Переконайтеся, що ви виконали інструкції з налаштування у README конкретного прикладу. Перевірте, чи встановлені у вас правильні версії залежностей.

**Питання: Зображення не відображаються**
В: Перевірте, що шляхи до зображень відносні й використовують прямі косі риски. Зображення повинні знаходитися в директорії `images/` або `translated_images/` для локалізованих версій.
