# Найкращі практики безпеки MCP - Оновлення вересня 2026

Цей комплексний посібник окреслює основні найкращі практики безпеки для
впровадження систем Протоколу Контексту Моделі (MCP), засновані на
**Специфікації MCP 2026-07-28** та поточних галузевих стандартах. Ці
практики охоплюють як традиційні проблеми безпеки, так і специфічні загрози ШІ,
характерні для впроваджень MCP.

## Критичні вимоги безпеки

### Обов’язкові заходи безпеки (вимоги MUST)

1. **Перевірка токенів**: MCP сервери **НЕ ПОВИННІ** приймати будь-які токени, які не були явно видані для самого MCP сервера
2. **Перевірка авторизації**: MCP сервери, які реалізують авторизацію, **ПОВИННІ** перевіряти ВСІ вхідні запити та **НЕ ПОВИННІ** використовувати сесії для аутентифікації  
3. **Згода користувача**: Проксі-сервери MCP, які використовують статичні ідентифікатори клієнтів третіх сторін, **ПОВИННІ** отримувати явну згоду для кожного MCP клієнта перед передачею потоку авторизації
4. **Безпека дескриптора стану**: MCP сервери **НЕ ПОВИННІ** розглядати володіння дескриптором стану програми як аутентифікацію і **ПОВИННІ** авторизувати кожен
	запит, що його використовує


## Основні практики безпеки

### 1. Валідація та санітизація введення
- **Комплексна валідація введення**: Валідуйте та санітизуйте всі введення, щоб запобігти ін’єкційним атакам, проблемам "заплутаного посередника" і вразливостям до ін’єкції підказок
- **Дотримання схеми параметрів**: Застосовуйте сувору валідацію схеми JSON для всіх параметрів інструментів та входів API
- **Фільтрація контенту**: Використовуйте Microsoft Prompt Shields та Azure Content Safety для фільтрації шкідливого вмісту у підказках і відповідях
- **Санітизація виводу**: Валідуйте та санітизуйте всі вихідні дані моделі перед їхнім поданням користувачам або системам нижчого рівня

### 2. Відмінна аутентифікація та авторизація  
- **Зовнішні провайдери ідентичності**: Делегуйте аутентифікацію встановленим провайдерам ідентичності (Microsoft Entra ID, провайдери OAuth 2.1) замість реалізації власної аутентифікації
- **Реєстрація клієнта**: Віддавайте перевагу метаданним документам Client ID або попередній реєстрації; використовуйте застарілу Динамічну реєстрацію клієнтів тільки для сумісності
- **Точкові права доступу**: Реалізуйте детальні, специфічні для інструментів права доступу за принципом найменших привілеїв
- **Керування життєвим циклом токенів**: Використовуйте короткоживучі токени доступу з безпечною ротацією та належною перевіркою аудиторії
- **Багатофакторна аутентифікація**: Вимагайте MFA для всього адміністративного доступу та чутливих операцій

### 3. Захищені протоколи зв’язку
- **Транспортний рівень безпеки**: Використовуйте HTTPS з належною перевіркою сертифікатів
	для віддалених HTTP-комунікацій MCP; використовуйте ізоляцію процесів та облікові дані середовища
	для локальних stdio-серверів
- **Енд-ту-енд шифрування**: Реалізуйте додаткові рівні шифрування для дуже конфіденційних даних під час передачі та зберігання
- **Керування сертифікатами**: Підтримуйте належний життєвий цикл сертифікатів із автоматизованим процесом поновлення
- **Дотримання версії протоколу**: Використовуйте MCP `2026-07-28`, включайте необхідні
	метадані версії у кожен запит і відхиляйте непідтримувані версії

### 4. Розширене обмеження частоти та захист ресурсів
- **Багаторівневе обмеження частоти**: Впроваджуйте обмеження частоти за користувачем, обліковими даними,
  операцією, інструментом і ресурсом для запобігання зловживанням
- **Адаптивне обмеження частоти**: Використовуйте обмеження частоти на основі машинного навчання, що адаптується до моделей використання та індикаторів загроз
- **Керування квотами ресурсів**: Встановлюйте відповідні ліміти на обчислювальні ресурси, використання пам'яті та час виконання
- **Захист від DDoS**: Розгортайте комплексний захист від DDoS та системи аналізу трафіку

### 5. Комплексне логування та моніторинг
- **Структуроване аудиторське логування**: Реалізуйте докладні, пошукові журнали для всіх операцій MCP, виконань інструментів і подій безпеки
- **Моніторинг безпеки в режимі реального часу**: Розгортайте SIEM-системи з AI-підсиленою детекцією аномалій для навантажень MCP
- **Логування з дотриманням конфіденційності**: Логувати події безпеки дотримуючись вимог щодо конфіденційності даних і нормативів
- **Інтеграція реагування на інциденти**: Підключіть системи логування до автоматизованих робочих процесів реагування на інциденти

### 6. Покращені практики безпечного зберігання
- **Апаратні модулі безпеки**: Використовуйте зберігання ключів на основі HSM (Azure Key Vault, AWS CloudHSM) для критичних криптографічних операцій
- **Керування ключами шифрування**: Реалізуйте належну ротацію ключів, сегрегацію та контроль доступу до ключів шифрування
- **Керування секретами**: Зберігайте всі API ключі, токени та облікові дані в спеціалізованих системах керування секретами
- **Класифікація даних**: Класифікуйте дані за рівнями чутливості та застосовуйте відповідні заходи захисту

### 7. Розширене керування токенами
- **Запобігання передачі токенів без контролю**: Явно забороняйте схеми передачі токенів, які обходять заходи безпеки
- **Перевірка аудиторії**: Завжди перевіряйте відповідність тверджень аудиторії токена ідентичності MCP сервера
- **Авторизація на основі тверджень**: Реалізуйте детальну авторизацію на основі тверджень токена та атрибутів користувача
- **Прив’язка токена**: Перевіряйте, що токени призначені цільовому ресурсу MCP та
	зв’язуйте дескриптори стану програми на боці сервера з автентифікованим суб’єктом

### 8. Безпечний стан програми

- **Криптографічні дескриптори стану**: Генеруйте непрозорі, недетерміновані дескриптори
	для стану, що охоплює запити
- **Прив’язка до користувача**: Зв’язуйте кожен дескриптор на боці сервера з автентифікованим
	суб’єктом; не довіряйте ID користувача, наданому клієнтом
- **Контроль життєвого циклу**: Встановлюйте терміни дії та відкликайте дескриптори, визначайте, як виклики
	відновлюються від застарілого стану
- **Авторизація для кожного запиту**: Повторно перевіряйте авторизацію щоразу, коли пред’являється дескриптор; дескриптор — це ім’я, а не облікові дані


### 9. Специфічні для ШІ заходи безпеки
- **Захист від ін’єкції підказок**: Використовуйте Microsoft Prompt Shields із висвітленням, роздільниками та техніками датамаркування
- **Запобігання отруєнню інструментів**: Перевіряйте метадані інструментів, стежте за динамічними змінами і перевіряйте цілісність інструментів
- **Перевірка виходу моделі**: Скани виходів моделі на потенційне витікання даних, шкідливий вміст або порушення політики безпеки
- **Захист контекстного вікна**: Впроваджуйте контролі для запобігання отруєнню та маніпулюванню контекстним вікном

### 10. Безпека виконання інструментів
- **Ізоляція виконання**: Запускайте виконання інструментів у контейнеризованих, ізольованих середовищах з лімітами ресурсів
- **Розділення привілеїв**: Виконуйте інструменти з мінімально необхідними правами та окремими сервісними обліковими записами
- **Ізоляція мережі**: Реалізуйте сегментацію мережі для середовищ виконання інструментів
- **Моніторинг виконання**: Моніторьте виконання інструментів на предмет аномальної поведінки, використання ресурсів та порушень безпеки

### 11. Безперервна перевірка безпеки
- **Автоматизоване тестування безпеки**: Інтегруйте тестування безпеки у CI/CD пайплайни з інструментами на кшталт GitHub Advanced Security
- **Керування вразливостями**: Регулярно скануйте всі залежності, включно з моделями ШІ та зовнішніми сервісами
- **Пенетраційне тестування**: Проводьте регулярні оцінки безпеки, спеціально спрямовані на впровадження MCP
- **Перегляд безпеки коду**: Реалізуйте обов’язкові перевірки безпеки для всіх змін коду, пов’язаних з MCP

### 12. Безпека ланцюга постачання для ШІ
- **Перевірка компонентів**: Перевіряйте походження, цілісність і безпеку всіх компонентів ШІ (моделей, вбудовувань, API)
- **Керування залежностями**: Підтримуйте актуальні реєстри всього програмного забезпечення та залежностей ШІ з відстеженням вразливостей
- **Довірені репозиторії**: Використовуйте перевірені, довірені джерела для всіх моделей ШІ, бібліотек і інструментів
- **Моніторинг ланцюга постачання**: Безперервно слідкуйте за компрометацією постачальників AI сервісів та репозиторіїв моделей

## Розширені шаблони безпеки

### Архітектура нульової довіри для MCP
- **Ніколи не довіряй, завжди перевіряй**: Реалізуйте безперервну перевірку для всіх учасників MCP
- **Мікросегментація**: Ізолюйте компоненти MCP із детальним контролем мережі та ідентичності
- **Умовний доступ**: Впроваджуйте контроль доступу на основі ризику, що адаптується до контексту та поведінки
- **Безперервна оцінка ризиків**: Динамічно оцінюйте стан безпеки на основі поточних індикаторів загроз

### Впровадження AI з дотриманням конфіденційності
- **Мінімізація даних**: Виставляйте лише мінімально необхідні дані для кожної операції MCP
- **Диференціальна приватність**: Реалізуйте методи збереження конфіденційності для обробки чутливих даних
- **Гомоморфне шифрування**: Використовуйте просунуті методи шифрування для безпечних обчислень над зашифрованими даними
- **Федеративне навчання**: Впроваджуйте розподілені підходи до навчання, що зберігають локальність і конфіденційність даних

### Реагування на інциденти для систем ШІ
- **Процедури інцидентів, специфічні для ШІ**: Розробляйте процедури реагування на інциденти, адаптовані до загроз ШІ і MCP
- **Автоматизоване реагування**: Впроваджуйте автоматичне обмеження та усунення типових інцидентів безпеки ШІ  
- **Форензика**: Підтримуйте готовність до судово-технічного аналізу при компрометації систем ШІ та витоках даних
- **Процедури відновлення**: Встановлюйте процедури відновлення після отруєння моделей ШІ, атак ін’єкції підказок і компрометацій сервісів

- **Розвідка про загрози**: Підписуйтеся на канали загроз безпеці ШІ та бази даних уразливостей  
- **Залучення спільноти**: Беріть участь у дискусіях та робочих групах спільноти безпеки MCP
- **Регулярна оцінка**: Проводьте квартальні оцінки стану безпеки та відповідно оновлюйте практики

### Внесок у безпеку MCP
- **Дослідження безпеки**: Вносьте свій вклад у дослідження безпеки MCP та програми розкриття вразливостей
- **Обмін кращими практиками**: Діліться реалізаціями безпеки та отриманими уроками зі спільнотою
- **Розробка стандартів**: Беріть участь у розробці специфікацій MCP та створенні стандартів безпеки
- **Розробка інструментів**: Розробляйте та діліться інструментами і бібліотеками безпеки для екосистеми MCP
