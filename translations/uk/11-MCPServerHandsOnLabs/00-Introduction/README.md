# Вступ до інтеграції MCP з базою даних

> [!NOTE]
> Діаграми або код у цьому навчальному шляху, які використовують HTTP/SSE або параметри ініціалізації,
> відображають залежності зразка MCP `2025-11-25`. Для нових реалізацій використовуйте безстані запити
> `2026-07-28` та Streamable HTTP.

## 🎯 Що охоплює ця лабораторна робота

Ця вступна лабораторна робота надає всебічний огляд створення серверів Model Context Protocol (MCP) з інтеграцією бази даних. Ви зрозумієте бізнес-контекст, технічну архітектуру та реальні застосування на прикладі аналітики Zava Retail за адресою https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail.

## Огляд

**Model Context Protocol (MCP)** дозволяє AI-асистентам безпечно отримувати доступ і взаємодіяти з зовнішніми джерелами даних у реальному часі. У поєднанні з інтеграцією баз даних MCP відкриває потужні можливості для керованих даними AI-застосунків.

Цей навчальний шлях навчає вас створювати готові до виробництва MCP-сервери, які підключають AI-асистентів до даних роздрібних продажів через PostgreSQL, впроваджуючи корпоративні шаблони, такі як безпека на рівні рядків, семантичний пошук і мультиорендна робота з даними.

- **Впізнати** корпоративні шаблони для безпечного та масштабованого доступу до баз даних
- **Перелічити** інструменти та технології, що використовуються у цьому навчальному шляху

## 🧭 Виклик: AI зустрічається з реальними даними

### Традиційні обмеження AI

Сучасні AI-асистенти надзвичайно потужні, але стикаються з суттєвими обмеженнями під час роботи з реальними бізнес-даними:

| **Виклик** | **Опис** | **Вплив на бізнес** |
|---------------|-----------------|-------------------|
| **Статичні знання** | AI-моделі, навчені на фіксованих наборах даних, не мають доступу до поточних бізнес-даних | Застаріла інформація, пропущені можливості |
| **Силоси даних** | Інформація, заблокована в базах даних, API та системах, до яких AI не має доступу | Неповний аналіз, фрагментовані робочі процеси |
| **Обмеження безпеки** | Прямий доступ до бази даних спричиняє проблеми з безпекою та відповідністю | Обмежене впровадження, ручна підготовка даних |
| **Складні запити** | Бізнес-користувачам потрібні технічні знання для вилучення даних | Знижене впровадження, неефективні процеси |

### Рішення MCP

Model Context Protocol вирішує ці виклики, надаючи:

- **Доступ до даних у реальному часі**: AI-асистенти запитують живі бази даних і API
- **Безпечна інтеграція**: Контрольований доступ з автентифікацією та дозволами
- **Інтерфейс природною мовою**: Бізнес-користувачі ставлять питання зрозумілою англійською
- **Стандартизований протокол**: Працює через різні AI-платформи та інструменти

## 🏪 Познайомтесь з Zava Retail: наш кейс навчання https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

Упродовж цього навчального шляху ми створимо MCP сервер для **Zava Retail**, вигаданої мережі магазинів DIY зі кількома торговими точками. Цей реалістичний сценарій демонструє впровадження MCP корпоративного рівня.

### Бізнес-контекст

**Zava Retail** працює:
- **8 фізичних магазинів** в штаті Вашингтон (Сіетл, Белв’ю, Такома, Спокан, Еврит, Редмонд, Кіркланд)
- **1 інтернет-магазин** для електронної комерції
- **Різноманітний каталог продуктів**, включно з інструментами, обладнанням, садовим приладдям та будівельними матеріалами
- **Багаторівневе управління** з менеджерами магазинів, регіональними менеджерами та керівництвом

### Бізнес-вимоги

Менеджери магазинів та керівники потребують аналітики на основі AI для:

1. **Аналізу показників продажів** за магазинами та періодами
2. **Відстеження рівня запасів** та визначення потреби в поповненні
3. **Розуміння поведінки клієнтів** та їхніх покупних патернів
4. **Виявлення інсайтів про продукти** через семантичний пошук
5. **Генерації звітів** за допомогою запитів природною мовою
6. **Підтримки безпеки даних** з контролем доступу за ролями

### Технічні вимоги

MCP сервер має забезпечувати:

- **Мультиорендний доступ до даних**, де менеджери магазинів бачать лише дані свого магазину
- **Гнучкі запити** з підтримкою складних SQL-операцій
- **Семантичний пошук** для виявлення продуктів і рекомендацій
- **Дані в реальному часі**, що відображають актуальний стан бізнесу
- **Безпечна автентифікація** з використанням безпеки на рівні рядків
- **Масштабована архітектура** з підтримкою кількох одночасних користувачів

## 🏗️ Огляд архітектури MCP-сервера

Наш MCP сервер реалізує багаторівневу архітектуру, оптимізовану для інтеграції з базою даних:

```
┌─────────────────────────────────────────────────────────────┐
│                    VS Code AI Client                       │
│                  (Natural Language Queries)                │
└─────────────────────┬───────────────────────────────────────┘
                      │ HTTP/SSE
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                     MCP Server                             │
│  ┌─────────────────┐ ┌─────────────────┐ ┌───────────────┐ │
│  │   Tool Layer    │ │  Security Layer │ │  Config Layer │ │
│  │                 │ │                 │ │               │ │
│  │ • Query Tools   │ │ • RLS Context   │ │ • Environment │ │
│  │ • Schema Tools  │ │ • User Identity │ │ • Connections │ │
│  │ • Search Tools  │ │ • Access Control│ │ • Validation  │ │
│  └─────────────────┘ └─────────────────┘ └───────────────┘ │
└─────────────────────┬───────────────────────────────────────┘
                      │ asyncpg
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                PostgreSQL Database                         │
│  ┌─────────────────┐ ┌─────────────────┐ ┌───────────────┐ │
│  │  Retail Schema  │ │   RLS Policies  │ │   pgvector    │ │
│  │                 │ │                 │ │               │ │
│  │ • Stores        │ │ • Store-based   │ │ • Embeddings  │ │

│  │ • Products      │ │ • Role Control  │ │   Search      │ │

│               (Text Embeddings)                            │
```

### Ключові компоненти

#### **1. Шар MCP-сервера**
- **FastMCP Framework**: Сучасна реалізація MCP-сервера на Python
- **Реєстрація інструментів**: Декларативні визначення інструментів з типобезпечністю
- **Контекст запитів**: Ідентифікація користувача та управління сесією
- **Обробка помилок**: Надійне управління помилками та ведення журналів

#### **2. Шар інтеграції з базою даних**
- **Пул підключень**: Ефективне асинхронне управління підключеннями asyncpg
- **Провайдер схеми**: Динамічне виявлення структури таблиць
- **Виконавець запитів**: Безпечне виконання SQL з контекстом RLS
- **Управління транзакціями**: Відповідність ACID та обробка відкатів

#### **3. Шар безпеки**
- **Безпека на рівні рядків (RLS)**: PostgreSQL RLS для ізоляції мультиорендних даних
- **Ідентифікація користувача**: Автентифікація та авторизація менеджера магазину
- **Контроль доступу**: Тонке дозвілля та журнали аудиту
- **Валідація введення**: Захист від SQL-ін’єкцій та перевірка запитів

#### **4. Шар AI-покращень**
- **Семантичний пошук**: Векторні ембеддинги для пошуку продуктів
- **Інтеграція Azure OpenAI**: Генерація текстових ембеддингів
- **Алгоритми подібності**: Пошук схожості косинусів через pgvector
- **Оптимізація пошуку**: Індексація та налаштування продуктивності

## 🎬 Сценарії використання у реальному світі

Розглянемо, як різні користувачі взаємодіють із нашим MCP сервером:

### Сценарій 1: Огляд ефективності менеджера магазину

**Користувач**: Сара, менеджер магазину в Сіетлі  
**Мета**: Проаналізувати показники продажів за останній квартал

**Запит природною мовою**:
> "Покажи мені топ 10 продуктів за доходом для мого магазину за Q4 2024"

**Що відбувається**:
1. AI чат VS Code надсилає запит до MCP сервера
2. MCP сервер ідентифікує контекст магазину Сари (Сіетл)
3. Політики RLS фільтрують дані лише до магазину в Сіетлі
4. Генерується та виконується SQL-запит
5. Результати форматуються та повертаються в AI чат
6. AI надає аналіз та інсайти

### Сценарій 2: Виявлення продуктів за допомогою семантичного пошуку

**Користувач**: Майк, менеджер інвентарю  
**Мета**: Знайти продукти, схожі на запит клієнта

**Запит природною мовою**:
> "Які продукти ми продаємо, що схожі на 'водонепроникні електричні з'єднувачі для зовнішнього використання'?"

**Що відбувається**:
1. Запит обробляється інструментом семантичного пошуку
2. Azure OpenAI генерує вектор ембеддингу
3. pgvector виконує пошук за схожістю
4. Пов’язані продукти ранжуються за релевантністю
5. Результати включають деталі продуктів та наявність
6. AI пропонує альтернативи та варіанти комплектування

### Сценарій 3: Аналітика між магазинами

**Користувач**: Дженніфер, регіональний менеджер  
**Мета**: Порівняти показники усіх магазинів

**Запит природною мовою**:
> "Порівняй продажі за категоріями для всіх магазинів за останні 6 місяців"

**Що відбувається**:
1. Встановлюється контекст RLS для доступу регіонального менеджера
2. Генерується складний запит для кількох магазинів
3. Дані агрегуються по всіх торгових точках
4. Результати включають тренди та порівняння
5. AI ідентифікує інсайти та дає рекомендації

## 🔒 Безпека та мультиорендність: детальний огляд

Наша реалізація орієнтована на корпоративний рівень безпеки:

### Безпека на рівні рядків (RLS)

PostgreSQL RLS забезпечує ізоляцію даних:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### Управління ідентифікацією користувачів

Кожне підключення MCP містить:
- **ID менеджера магазину**: Унікальний ідентифікатор для контексту RLS
- **Призначення ролі**: Дозволи та рівні доступу
- **Управління сесією**: Захищені токени автентифікації
- **Журнали аудиту**: Повна історія доступу

### Захист даних

Багатошаровий захист:
- **Шифрування з’єднань**: TLS для всіх підключень до бази даних
- **Запобігання SQL-ін’єкціям**: Лише параметризовані запити
- **Валідація введення**: Комплексна перевірка запитів
- **Обробка помилок**: Відсутність чутливих даних у повідомленнях про помилки
