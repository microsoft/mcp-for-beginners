# دراسة حالة: كشف واجهة برمجة التطبيقات REST في إدارة واجهات برمجة التطبيقات كخادم MCP

إدارة واجهات برمجة التطبيقات من Azure هي خدمة توفر بوابة فوق نقاط نهاية واجهة برمجة التطبيقات الخاصة بك. كيف تعمل هو أن إدارة واجهات برمجة التطبيقات من Azure تعمل كوكيل أمام واجهات برمجة التطبيقات الخاصة بك ويمكنها أن تقرر ما الذي يجب فعله مع الطلبات الواردة.

باستخدامها، تضيف مجموعة كاملة من الميزات مثل:

- **الأمان**، يمكنك استخدام كل شيء من مفاتيح API وJWT إلى الهوية المدارّة.
- **تقييد المعدل**، ميزة رائعة هي القدرة على تحديد عدد المكالمات التي تمر خلال وحدة زمنية معينة. هذا يساعد على ضمان تجربة رائعة لجميع المستخدمين وكذلك على عدم إرهاق خدمتك بالطلبات.
- **التوسع وتحميل الأحمال**. يمكنك إعداد عدد من النقاط الطرفية لتوزيع الحمل ويمكنك أيضًا تحديد كيفية "توزيع الأحمال".
- **ميزات الذكاء الاصطناعي مثل التخزين المؤقت الدلالي**، حد الرموز ومراقبة الرموز والمزيد. هذه ميزات رائعة تحسن الاستجابة وتساعدك في السيطرة على إنفاق الرموز. [اقرأ المزيد هنا](https://learn.microsoft.com/en-us/azure/api-management/genai-gateway-capabilities).

## لماذا MCP + إدارة واجهات برمجة التطبيقات من Azure؟

بروتوكول سياق النموذج يصبح بسرعة معيارًا لتطبيقات الذكاء الاصطناعي الوكيلية وكيفية كشف الأدوات والبيانات بطريقة متسقة. إدارة واجهات برمجة التطبيقات من Azure خيار طبيعي عندما تحتاج إلى "إدارة" واجهات برمجة التطبيقات. غالبًا ما تندمج خوادم MCP مع واجهات برمجة التطبيقات الأخرى لحل الطلبات لأداة على سبيل المثال. لذلك فإن الجمع بين إدارة واجهات برمجة التطبيقات من Azure وMCP منطقي جدًا.

## نظرة عامة

في هذه الحالة الخاصة سنتعلم كيفية كشف نقاط نهاية واجهة برمجة التطبيقات كخادم MCP. من خلال القيام بذلك، يمكننا بسهولة جعل هذه النقاط جزءًا من تطبيق وكيل مع الاستفادة أيضًا من ميزات إدارة واجهات برمجة التطبيقات من Azure.

## الميزات الرئيسية

- تختار أساليب النقاط الطرفية التي تريد كشفها كأدوات.
- الميزات الإضافية التي تحصل عليها تعتمد على ما تقوم بتكوينه في قسم السياسات لواجهة برمجة التطبيقات الخاصة بك. لكن هنا سنوضح لك كيف يمكنك إضافة تقييد المعدل.

## الخطوة السابقة: استيراد واجهة برمجة تطبيقات

إذا كان لديك واجهة برمجة تطبيقات في إدارة واجهات برمجة التطبيقات من Azure بالفعل فهذا رائع، إذن يمكنك تخطي هذه الخطوة. إن لم يكن، اطلع على هذا الرابط، [استيراد واجهة برمجة تطبيقات إلى إدارة واجهات برمجة التطبيقات من Azure](https://learn.microsoft.com/en-us/azure/api-management/import-and-publish#import-and-publish-a-backend-api).

## كشف واجهة برمجة التطبيقات كخادم MCP

لكشف نقاط نهاية واجهة برمجة التطبيقات، دعنا نتبع هذه الخطوات:

1. انتقل إلى بوابة Azure والعنوان التالي <https://portal.azure.com/?Microsoft_Azure_ApiManagement=mcp>
انتقل إلى مثيل إدارة واجهات برمجة التطبيقات الخاص بك.

1. في القائمة اليسرى، اختر APIs > MCP Servers > + إنشاء خادم MCP جديد.

1. في API، اختر واجهة برمجة تطبيقات REST لكشفها كخادم MCP.

1. اختر عملية أو أكثر لواجهة برمجة التطبيقات لكشفها كأدوات. يمكنك اختيار جميع العمليات أو عمليات معينة فقط.

    ![اختر الأساليب للكشف](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/create-mcp-server-small.png)


1. اختر **إنشاء**.

1. انتقل إلى خيار القائمة **APIs** و**MCP Servers**، يجب أن ترى ما يلي:

    ![رؤية خادم MCP في القسم الرئيسي](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-list.png)

    تم إنشاء خادم MCP وعمليات API مكشوفة كأدوات. يتم إدراج خادم MCP في لوحة خوادم MCP. يعرض عمود URL نقطة نهاية خادم MCP التي يمكنك الاتصال بها للاختبار أو ضمن تطبيق العميل.

## اختياري: تكوين السياسات

لدى إدارة واجهات برمجة التطبيقات من Azure مفهوم أساسي وهو السياسات حيث يمكنك إعداد قواعد مختلفة لنقاط النهاية الخاصة بك مثل تقييد المعدل أو التخزين المؤقت الدلالي. تُكتب هذه السياسات بتنسيق XML.

إليك كيف يمكنك إعداد سياسة لتقييد معدل خادم MCP الخاص بك:

1. في البوابة، تحت APIs، اختر **MCP Servers**.

1. اختر خادم MCP الذي أنشأته.

1. في القائمة اليسرى، تحت MCP، اختر **Policies**.

1. في محرر السياسات، أضف أو حرر السياسات التي تريد تطبيقها على أدوات خادم MCP. تُعرف السياسات بتنسيق XML. على سبيل المثال، يمكنك إضافة سياسة لتقييد المكالمات إلى أدوات خادم MCP (في هذا المثال، 5 مكالمات كل 30 ثانية لكل عنوان IP عميل). ها هو XML الذي سيقوم بتقييد المعدل:

    ```xml
     <rate-limit-by-key calls="5" 
       renewal-period="30" 
       counter-key="@(context.Request.IpAddress)" 
       remaining-calls-variable-name="remainingCallsPerIP" 
    />
    ```

    هذا صورة لمحرر السياسات:

    ![محرر السياسات](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-policies-small.png)
 
## جربها

دعنا نتحقق من أن خادم MCP يعمل كما هو مقصود.

> [!NOTE]
> تعرض إدارة واجهات برمجة التطبيقات من Azure هذا الخادم حاليًا من خلال 
> نقطة نهاية HTTP `/mcp` القابلة للتدفق. واجهة النقل الأقدم 
> HTTP+SSE `/sse` مهجورة ويجب استخدامها فقط مع العملاء القدامى.

لهذا، سنستخدم Visual Studio Code وGitHub Copilot ووضع العميل الخاص به. سنضيف خادم MCP إلى ملف *mcp.json*. من خلال القيام بذلك، سيعمل Visual Studio Code كعميل بقدرات وكيلة وسيتمكن المستخدمون النهائيون من كتابة موجه والتفاعل مع هذا الخادم.

لنرَ كيف، لإضافة خادم MCP في Visual Studio Code:

1. استخدم أمر MCP: **إضافة خادم من لوحة الأوامر**.

1. عند المطالبة، اختر نوع الخادم: **HTTP (HTTP أو Server Sent Events)**.

1. أدخل عنوان URL HTTP القابل للتدفق المعروض لخادم MCP في إدارة API.
    على سبيل المثال:
    `https://<apim-service-name>.azure-api.net/<api-name>-mcp/mcp`.

1. أدخل معرف الخادم الذي تختاره. هذه ليست قيمة مهمة لكنها ستساعدك على تذكر هذه الحالة من الخادم.

1. اختر ما إذا كنت تريد حفظ التكوين إلى إعدادات مساحة العمل أو إعدادات المستخدم.

  - **إعدادات مساحة العمل** - يتم حفظ تكوين الخادم إلى ملف .vscode/mcp.json متاح فقط في مساحة العمل الحالية.

    *mcp.json*

    ```json
    "servers": {
        "APIM petstore" : {
            "type": "http",
            "url": "url-to-mcp-server/mcp"
        }
    }
    ```

  - **إعدادات المستخدم** - يضاف تكوين الخادم إلى ملف *settings.json* العالمي الخاص بك ويتوفر في جميع مساحات العمل. يكون التكوين مشابهًا لما يلي:

    ![إعداد المستخدم](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-servers-visual-studio-code.png)

1. تحتاج أيضًا لإضافة تكوين، رأس للتأكد من أنه يتحقق من المصادقة بشكل صحيح تجاه إدارة واجهات برمجة التطبيقات من Azure. يستخدم رأسًا يسمى **Ocp-Apim-Subscription-Key**.


    - إليك كيفية إضافته إلى الإعدادات:

    ![إضافة رأس للمصادقة](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/mcp-server-with-header-visual-studio-code.png)، سيؤدي هذا إلى عرض مطالبة تطلب منك قيمة مفتاح API والتي يمكنك العثور عليها في بوابة Azure لحالة إدارة API الخاصة بك في Azure.

   - لإضافته بدلاً من ذلك إلى *mcp.json*، يمكنك إضافته كما يلي:

    ```json
    "inputs": [
      {
        "type": "promptString",
        "id": "apim_key",
        "description": "API Key for Azure API Management",
        "password": true
      }
    ]
    "servers": {
        "APIM petstore" : {
            "type": "http",
            "url": "url-to-mcp-server/mcp",
            "headers": {
                "Ocp-Apim-Subscription-Key": "Bearer ${input:apim_key}"
            }
        }
    }
    ```

### استخدام وضع الوكيل

الآن نحن جاهزون تماماً في الإعدادات أو في *.vscode/mcp.json*. دعنا نجربها.

يجب أن يكون هناك أيقونة أدوات مثل هذه، حيث يتم سرد الأدوات المكشوفة من خادمك:

![الأدوات من الخادم](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/tools-button-visual-studio-code.png)

1. انقر على أيقونة الأدوات ويجب أن ترى قائمة الأدوات مثل هذه:

    ![الأدوات](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/select-tools-visual-studio-code.png)

1. أدخل مطلبًا في الدردشة لاستدعاء الأداة. على سبيل المثال، إذا اخترت أداة للحصول على معلومات حول طلب، يمكنك سؤال الوكيل عن الطلب. إليك مثالاً على مطلب:

    ```text
    get information from order 2
    ```

    سيتم الآن عرض أيقونة أدوات تطلب منك المتابعة لاستدعاء أداة. اختر المتابعة لتشغيل الأداة، يجب أن ترى الآن ناتجًا مثل هذا:

    ![النتيجة من المطلب](https://learn.microsoft.com/en-us/azure/api-management/media/export-rest-mcp-server/chat-results-visual-studio-code.png)

    **ما تراه أعلاه يعتمد على الأدوات التي قمت بإعدادها، لكن الفكرة هي أنك تحصل على استجابة نصية كما هو موضح أعلاه**
