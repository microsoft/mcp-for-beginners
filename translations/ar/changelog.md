#### التحقق من العينة مقابل SDKs الحالية

- **TypeScript (03-GettingStarted/01-first-server/solution/typescript)**: حل `npm install` لـ `@modelcontextprotocol/sdk@1.29.0`; نجح `tsc --noEmit` بدون أخطاء نوعية — تبقى واجهات برمجة التطبيقات الحالية لـ `McpServer`/`StdioServerTransport` صالحة
- **Python (03-GettingStarted/01-first-server/solution/python)**: تم التحقق في `.venv` معزول مع `mcp[cli]` (1.27.2); نجح `py_compile` وعادت دالة `FastMCP.list_tools()` بشكل صحيح بالأدوات `add` و `subtract`
- تم تأكيد أن جميع نطاقات إصدار عينة `@modelcontextprotocol/sdk` (`>=1.26.0` / `^1.26.0` / `^1.27.0`) تحل بوضوح إلى الإصدار الحالي `1.29.0` بدون تغييرات على واجهة برمجة التطبيقات تكسر التوافق

### تعزيز الأمان ومعالجة ثغرات التبعيات

تم إجراء فحص أمني كامل لكل ملف تعريف تبعيات وكل رمز مصدر للعينة، ثم تم معالجة جميع تحذيرات npm المبلغ عنها واكتشاف أمني برمجي واحد. بعد المعالجة، تقارير `npm audit` توضح **0 ثغرات** في كل مجلد تم تدقيقه.

#### ثغرات npm في التبعيات (عبور) — تم الإصلاح

تم تدقيق كل ملفات `package-lock.json` الخمسة عشر المرتكزة. اقتصر وجود الثغرات على التبعيات العبور التي يجلبها أداة تطوير MCP Inspector، وعميل OpenAI، و MCP SDK؛ جميعها تم حلها الآن دون كسر العينات:
- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/inspector** و **lab3/code/weather_mcp/inspector**: تم رفع `@modelcontextprotocol/inspector` (`0.16.6` / `0.14.1` → `0.22.0`)، ما أزال التحذيرات في `ajv`، `brace-expansion`، `diff`، `path-to-regexp` و `ws` المجمعة. أضيف إدخال `overrides` في npm يجبر استخدام النسخة المرقعة لـ `shell-quote@1.8.4` لإزالة التحذير الحرج المتبقي الذي تحمله `concurrently`؛ أُعيد توليد كلا ملفي القفل (الآن 0 ثغرات)
- **03-GettingStarted/samples/typescript**: `npm audit fix` حدث التبعية العبور `qs` (متوسطة) إلى إصدار مرقع
- **03-GettingStarted/samples/javascript**: `npm audit fix` حدث التبعية العبور `hono` (متوسطة) إلى إصدار مرقع
- **03-GettingStarted/03-llm-client/solution/typescript**: `npm audit fix` حدث التبعية العبور `form-data` (عالية) إلى إصدار مرقع
- **03-GettingStarted/11-simple-auth/solution/typescript**: تم إنشاء `package-lock.json` المفقود بحيث يصبح المشروع قابلاً لإعادة الإنتاج والتدقيق (0 ثغرات)

#### إصلاح أمني على مستوى الكود (OWASP A03: Injection)

- **10-StreamliningAIWorkflows.../lab4/code/github_mcp_server/src/server.py**: أزيل `shell=True` من أداة `open_in_vscode`. السابق `subprocess.run(["start", "", vscode_path, folder_path], shell=True)` سمح لرموز خاصة في مسار المجلد بأن يُفسرها `cmd.exe` (متجه حقن الأوامر). وهو الآن يشغل ملف `Code.exe` المحلول مباشرةً مع المجلد كوسيط - بدون shell - وهو مكافئ وظيفياً وآمن

#### تدقيق تبعيات Python

- تم تدقيق كل مجموعة متطلبات Python باستخدام `pip-audit`. لم تُبلغ `05-AdvancedTopics` و `03-GettingStarted/samples/python` عن **أي ثغرات معروفة** (نطاقاتهم لـ `mcp` / `httpx` / `pydantic` / `python-dotenv` تحل إلى الإصدارات المرقعة الحالية)
- **09-CaseStudy/docs-mcp/solution/python/requirements.txt**: رصد `pip-audit` التبعية العابرة **`werkzeug` 3.1.1** مع ثلاث تحذيرات من DoS لأسماء أجهزة Windows في `safe_join` — `CVE-2025-66221`، `CVE-2026-21860`، و `CVE-2026-27199` (كلها ثابتة في 3.1.6). تمت إضافة تثبيت أمني صريح `werkzeug>=3.1.6` بحيث تحل النسخة المرقعة؛ تم التحقق أن القيد يحل بوضوح مع مكدس `chainlit` / `mcp` / `semantic-kernel`

  - سيناريوهات هجوم حقن الموجه المفصلة مع أمثلة واقعية  
  - آليات تسميم الأدوات وأنماط هجوم "سحب السجاد"  
  - تسميم نافذة السياق وهجمات الارتباك النموذجي  
- **حلول أمان Microsoft للذكاء الاصطناعي**: تغطية شاملة لمنظومة أمان Microsoft  
  - دروع موجهات الذكاء الاصطناعي مع تقنيات الكشف المتقدمة، التسليط، وتقنيات تحديد الحدود  
  - أنماط دمج Azure Content Safety  
  - أمان GitHub المتقدم لحماية سلسلة التوريد  
- **التخفيف المتقدم للتهديدات**: ضوابط أمان مفصلة لـ  
  - اختطاف الجلسات مع سيناريوهات هجوم خاصة بـ MCP ومتطلبات معرف الجلسة المشفرة  
  - مشاكل الوسيطة المحيرة في سيناريوهات بروكسي MCP مع متطلبات الموافقة الصريحة  
  - نقاط الضعف في تمرير التوكن مع ضوابط تحقق إلزامية  
- **أمان سلسلة التوريد**: توسيع تغطية سلسلة التوريد للذكاء الاصطناعي تشمل النماذج الأساسية، خدمات التضمين، موفري السياق، وواجهات برمجة التطبيقات الخارجية  
- **أمان الأساسيات**: دمج محسّن مع أنماط أمان المؤسسات بما في ذلك بنية الثقة الصفرية ومنظومة أمان Microsoft  
- **تنظيم الموارد**: تصنيف شامل للروابط حسب النوع (الوثائق الرسمية، المعايير، الأبحاث، حلول Microsoft، أدلة التنفيذ)  

### تحسينات جودة التوثيق  
- **أهداف تعلم منظمة**: تعزيز الأهداف التعليمية بنتائج محددة وقابلة للتنفيذ  
- **مراجع متقاطعة**: إضافة روابط بين مواضيع الأمان والمفاهيم الأساسية ذات الصلة  
- **معلومات حديثة**: تحديث جميع التواريخ وروابط المواصفات للمعايير الحالية  
- **إرشادات التنفيذ**: إضافة إرشادات تنفيذية محددة وقابلة للتنفيذ في كلا القسمين
