# جذور MCP (ميزة قديمة)

> [!WARNING]
> تم إهمال الجذور اعتبارًا من MCP `2026-07-28`. تبقى في هذا الإصدار لل
> توافق وهي مؤهلة للإزالة في مراجعة المواصفات الأولى التي تصدر في أو بعد 28 يوليو 2027.
> يجب على التطبيقات الجديدة تمرير الأدلة أو الملفات عبر معلمات الأداة أو 
> روابط الموارد أو إعدادات الخادم.


## نظرة عامة

تسمح الجذور لعميل MCP بإخبار الخادم بمواقع نظام الملفات ذات الصلة
بالطلب الحالي. يحتوي الجذر على رابط `file://` مطلوب واسم اختياري
يمكن قراءته بواسطة الإنسان.

الجذور هي إشارات معلوماتية. ليست حاويات محفوظات المحادثة،
أو جلسات البروتوكول، أو آلية تحكم في الوصول. لا يفرض البروتوكول
أن يبقى الخادم ضمن الجذور المدرجة.

## أهداف التعلم

في نهاية هذا الدرس، ستكون قادرًا على:

- شرح ما تمثله جذور MCP وما لا تمثله.
- التعرف على تدفق الجولة المتعددة الحالي `roots/list`.
- تطبيق ضوابط الأمان بشكل مستقل عن الجذور.
- ترحيل التطبيقات الجديدة إلى البدائل المدعومة.

## بيانات الجذر

يرجع العميل كل جذر كرابط `file://` مع اسم عرض اختياري:

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/weather-service",
      "name": "Weather Service"
    }
  ]
}
```

يجب على العملاء الكشف فقط عن المواقع التي وافق عليها المستخدم. يجب على الخوادم التعامل
مع النتيجة كدليل حول الملفات ذات الصلة، وليس كدليل على التفويض.

## تدفق MCP 2026-07-28

يعلن العميل الذي يدعم الجذور القدرة في كل طلب:

```json
{
  "_meta": {
    "io.modelcontextprotocol/clientCapabilities": {
      "roots": {}
    }
  }
}
```

أثناء معالجة طلب العميل، يمكن للخادم إرجاع
`InputRequiredResult` يحتوي على طلب إدخال `roots/list`:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "workspaceRoots": {
      "method": "roots/list"
    }
  },
  "requestState": "opaque-state-from-server"
}
```

يجمع العميل الجذور المعتمدة ويعاد محاولة الطلب الأصلي مع الـ
`inputResponses` المطابقة و`requestState` دون تغيير. يحافظ هذا النمط
متعدد الجولات على بروتوكول بدون حالة؛ لا يوجد مصافحة `initialize` أو
جلسة على مستوى البروتوكول.

## سلوك قديم 2025-11-25

في MCP `2025-11-25`، أعلن العملاء عن الجذور أثناء التهيئة. كان بإمكان الخادم
إصدار طلب مباشر `roots/list`، وكان بإمكان العميل إرسال
`notifications/roots/list_changed` عند تغير جذوره.

تلك دورة الحياة هي سلوك قديم. لا تدمج أمثلتها للتهيئة أو
الإشعار مع تنفيذ `2026-07-28`.

## البدائل الموصى بها

### معلمات الأداة

اجعل الدليل أو الملف المطلوب صريحًا في مخطط الأداة:

```json
{
  "name": "analyze_project",
  "inputSchema": {
    "type": "object",
    "properties": {
      "projectDirectory": {
        "type": "string",
        "description": "Approved project directory to analyze"
      }
    },
    "required": ["projectDirectory"]
  }
}
```

### روابط الموارد

استخدم موارد MCP عندما يمكن للخادم الكشف عن الملفات ذات الصلة عبر روابط
مستقرة. هذا يحافظ على الاكتشاف والاسترجاع بشكل صريح.

### إعدادات الخادم

للنشر الثابت، قم بإعداد دلائل مسموح بها عند بدء تشغيل الخادم.
يكون هذا غالبًا أوضح من اكتشافهم أثناء استدعاء الأداة.

## متطلبات الأمان

أيًا كان البديل الذي تختاره:

- الحصول على موافقة المستخدم قبل الكشف عن مواقع نظام الملفات.
- تحويل وتحقيق صحة المسارات لمنع التجاوز.
- فرض التفويض والعزل بشكل مستقل عن قيم الجذر.
- إعادة فحص الأذونات عند الوصول إلى ملف، وليس فقط عند إدراجه.
- تجنب إرجاع المسارات الحساسة في السجلات أو رسائل الخطأ.

## النقاط الرئيسية

- تصف الجذور مواقع نظام الملفات ذات الصلة؛ لكنها لا تخزن حالة المحادثة.

- الجذور إرشادية، وليست حدود تحكم في الوصول.
- يحمل MCP `2026-07-28` القدرة لكل طلب ويستخدم
  `InputRequiredResult` لـ `roots/list`.
- يجب أن تستخدم التطبيقات الجديدة معلمات الأداة، أو روابط الموارد، أو
  إعدادات الخادم بدلاً من ذلك.
