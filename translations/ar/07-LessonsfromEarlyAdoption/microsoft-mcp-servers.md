# 🚀 10 خوادم Microsoft MCP التي تُحوّل إنتاجية المطورين

## 🎯 ما ستتعلمه في هذا الدليل

يعرض هذا الدليل العملي عشرة خوادم Microsoft MCP التي تُحوّل بشكل فعلي كيفية عمل المطورين مع مساعدين الذكاء الاصطناعي. بدلًا من شرح ما *يمكن* للخوادم MCP القيام به فقط، سنُظهر لك خوادم تحدث فرقًا حقيقيًا في سير العمل اليومي للتطوير في مايكروسوفت وخارجها.

تم اختيار كل خادم في هذا الدليل بناءً على الاستخدام الواقعي وردود فعل المطورين. ستكتشف ليس فقط ما يقوم به كل خادم، بل لماذا هو مهم وكيف يمكنك الاستفادة القصوى منه في مشاريعك الخاصة. سواء كنت جديدًا تمامًا على MCP أو تسعى لتوسيع إعدادك الحالي، تمثل هذه الخوادم بعضًا من أكثر الأدوات عملية وتأثيرًا في نظام مايكروسوفت البيئي.

## 🔧 فهم خوادم MCP: دليل للمبتدئين

### ما هي خوادم MCP؟

كمبتدئ في بروتوكول نموذج السياق (MCP)، قد تتساءل: "ما هو بالضبط خادم MCP، ولماذا يجب أن أهتم؟" لنبدأ بتشبيه بسيط.

فكر في خوادم MCP كمساعدين متخصصين يساعدون رفيق الترميز الذكي الخاص بك (مثل GitHub Copilot) على الاتصال بالأدوات والخدمات الخارجية. تمامًا كما قد تستخدم تطبيقات مختلفة على هاتفك لمهام مختلفة—واحد للطقس، واحد للملاحة، واحد للبنك—تُمكّن خوادم MCP مساعد الذكاء الاصطناعي لديك من التفاعل مع أدوات وخدمات التطوير المختلفة.

### المشكلة التي تحلها خوادم MCP

قبل خوادم MCP، إذا أردت:
- التحقق من موارد Azure الخاصة بك
- إنشاء مشكلة في GitHub
- الاستعلام في قاعدة بياناتك
- البحث في الوثائق

كان عليك التوقف عن الترميز، وفتح متصفح، والذهاب إلى الموقع المناسب، وأداء هذه المهام يدويًا. هذا التبديل المستمر للسياق يكسر تدفق عملك ويقلل الإنتاجية.

### كيف تُغير خوادم MCP تجربة التطوير الخاصة بك

باستخدام خوادم MCP، يمكنك البقاء في بيئة التطوير الخاصة بك (VS Code، Visual Studio، إلخ) وطلب مساعد الذكاء الاصطناعي التعامل مع هذه المهام ببساطة. على سبيل المثال:

**بدلًا من سير العمل التقليدي هذا:**
1. توقف عن الترميز
2. افتح المتصفح
3. انتقل إلى بوابة Azure
4. ابحث عن تفاصيل حساب التخزين
5. عد إلى VS Code
6. استأنف الترميز

**يمكنك الآن فعل هذا:**
1. اسأل الذكاء الاصطناعي: "ما حالة حسابات تخزين Azure الخاصة بي؟"
2. تابع الترميز مع المعلومات المقدمة

### فوائد رئيسية للمبتدئين

#### 1. 🔄 **ابقَ في حالة تدفقك**
- لا مزيد من التبديل بين تطبيقات متعددة
- حافظ على تركيزك على الكود الذي تكتبه
- قلل العبء الذهني لإدارة أدوات مختلفة

#### 2. 🤖 **استخدم اللغة الطبيعية بدلًا من الأوامر المعقدة**
- بدلًا من حفظ صيغة SQL، صف البيانات التي تحتاجها
- بدلًا من تذكر أوامر Azure CLI، اشرح ما تريد إنجازه
- دع الذكاء الاصطناعي يتولى التفاصيل التقنية بينما تركز على المنطق

#### 3. 🔗 **قم بربط أدوات متعددة معًا**
- أنشئ سير عمل قوي بدمج خدمات مختلفة
- مثال: "احصل على كل المشاكل الحديثة في GitHub وأنشئ عناصر عمل مقابلة في Azure DevOps"
- بنِ أتمتة بدون كتابة نصوص معقدة

#### 4. 🌐 **الوصول إلى نظام بيئي متنامٍ**
- استفد من الخوادم التي تبنيها مايكروسوفت، GitHub، وشركات أخرى
- امزج وطابق الأدوات من بائعين مختلفين بسلاسة
- انضم إلى نظام بيئي موحد يعمل عبر مساعدين ذكاء اصطناعي مختلفين

#### 5. 🛠️ **تعلّم بالممارسة**
- ابدأ بخوادم مُجهزة مسبقًا لفهم المفاهيم
- أنشئ خوادمك الخاصة تدريجيًا كلما أصبحت أكثر ارتياحًا
- استخدم SDKs والوثائق المتاحة لتوجيه تعلمك

### مثال واقعي للمبتدئين

لنفترض أنك جديد في تطوير الويب وتعمل على مشروعك الأول. إليك كيف يمكن لخوادم MCP المساعدة:

**النهج التقليدي:**
```
1. Code a feature
2. Open browser → Navigate to GitHub
3. Create an issue for testing
4. Open another tab → Check Azure docs for deployment
5. Open third tab → Look up database connection examples
6. Return to VS Code
7. Try to remember what you were doing
```

**مع خوادم MCP:**
```
1. Code a feature
2. Ask AI: "Create a GitHub issue for testing this login feature"
3. Ask AI: "How do I deploy this to Azure according to the docs?"
4. Ask AI: "Show me the best way to connect to my database"
5. Continue coding with all the information you need
```

### ميزة المعيار المؤسسي

MCP أصبح معيارًا صناعيًا واسع الانتشار، مما يعني:
- **الاتساق**: تجربة مماثلة عبر أدوات وشركات مختلفة
- **التشغيل البيني**: خوادم مختلفة من بائعين متنوعين تتعاون معًا
- **ضمان المستقبل**: تنتقل المهارات والإعدادات بين مساعدين ذكاء اصطناعي مختلفين
- **المجتمع**: نظام بيئي واسع من المعرفة والموارد المشتركة

## البدء باستخدام MCP في VS Code وVisual Studio 🚀

إعداد خوادم MCP هذه بسيط إذا كنت تستخدم Visual Studio Code أو Visual Studio 2022 مع GitHub Copilot.

### إعداد VS Code

إليك العملية الأساسية لـ VS Code:

1. **تفعيل وضع الوكيل**: في VS Code، انتقل إلى وضع الوكيل في نافذة الدردشة الخاصة بـ Copilot
2. **تهيئة خوادم MCP**: أضف إعدادات الخادم إلى ملف settings.json الخاص بـ VS Code
3. **تشغيل الخوادم**: اضغط زر "تشغيل" لكل خادم ترغب في استخدامه
4. **اختيار الأدوات**: اختر خوادم MCP التي تود تمكينها للجلسة الحالية

للتعليمات التفصيلية للإعداد، راجع [وثائق MCP لـ VS Code](https://code.visualstudio.com/docs/copilot/copilot-mcp).

> **💡 نصيحة احترافية: إدارة خوادم MCP كمحترف!**
> 
> يعرض قسم الملحقات في VS Code الآن [واجهة جديدة لإدارة خوادم MCP المثبتة](https://code.visualstudio.com/docs/copilot/chat/mcp-servers#_use-mcp-tools-in-agent-mode)! أصبح لديك وصول سريع لتشغيل، إيقاف، وإدارة أي خادم MCP مثبت باستخدام واجهة واضحة وبسيطة. جربها!

### إعداد Visual Studio 2022

لبرنامج Visual Studio 2022 (الإصدار 17.14 أو أحدث):

1. **تفعيل وضع الوكيل**: انقر على القائمة المنسدلة "اسأل" في نافذة GitHub Copilot Chat واختر "وكيل"
2. **إنشاء ملف التهيئة**: أنشئ ملف `.mcp.json` في دليل الحل الخاص بك (المكان الموصى به: `<SOLUTIONDIR>\.mcp.json`)
3. **تهيئة الخوادم**: أضف إعدادات خوادم MCP باستخدام تنسيق MCP القياسي
4. **موافقة على الأدوات**: عند الطلب، وافق على الأدوات التي تود استخدامها مع الأذونات المناسبة

للتعليمات التفصيلية لإعداد Visual Studio، راجع [وثائق MCP لـ Visual Studio](https://learn.microsoft.com/visualstudio/ide/mcp-servers).

كل خادم MCP يأتي مع متطلبات تهيئة خاصة به (سلاسل الاتصال، المصادقة، إلخ)، لكن نمط الإعداد موحد عبر كل بيئة التطوير المتكاملة.

### 1. 📚 خادم Microsoft Learn Docs MCP

[![تثبيت في VS Code](https://img.shields.io/badge/VS_Code-Install_Microsoft_Docs_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D) [![تثبيت في VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Microsoft_Docs_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=microsoft.docs.mcp&config=%7B%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Flearn.microsoft.com%2Fapi%2Fmcp%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/microsoft/mcp)

**ما يفعله**: خادم Microsoft Learn Docs MCP هو خدمة مستضافة سحابيًا توفر للمساعدين الذكاء الاصطناعي وصولًا فوريًا إلى الوثائق الرسمية من مايكروسوفت عبر بروتوكول نموذج السياق. يتصل بـ `https://learn.microsoft.com/api/mcp` ويُمكن البحث الدلالي عبر Microsoft Learn، وثائق Azure، وثائق Microsoft 365، ومصادر مايكروسوفت الرسمية الأخرى.

**لماذا هو مفيد**: رغم أنه قد يبدو مجرد "وثائق"، إلا أن هذا الخادم ضروري لكل مطور يستخدم تقنيات مايكروسوفت. واحدة من أكبر شكاوى مطوري .NET حول مساعدين الترميز بالذكاء الاصطناعي هي أنهم ليسوا على اطلاع بآخر إصدارات .NET وC#. يحل خادم Microsoft Learn Docs MCP هذا بتوفير وصول فوري لآخر الوثائق، المراجع API، وأفضل الممارسات. سواء كنت تعمل مع أحدث SDKs لـ Azure، تستكشف ميزات C# 13 الجديدة، أو تطبق أنماط Aspire المتطورة، يضمن هذا الخادم أن مساعدك الذكي لديه الوصول للمعلومات الرسمية والمحدثة اللازمة لتوليد شفرة صحيحة وعصرية.

**استخدام حقيقي**: "ما هي أوامر az cli لإنشاء تطبيق حاوية Azure وفقًا لوثائق Microsoft Learn الرسمية؟" أو "كيف أُهيئ Entity Framework مع الحقن التبعّي في ASP.NET Core؟" أو "راجع هذا الكود للتأكد من مطابقته لتوصيات الأداء في وثائق Microsoft Learn." يوفر الخادم تغطية شاملة عبر Microsoft Learn، ووثائق Azure، ووثائق Microsoft 365 مستخدمًا بحثًا دلاليًا متقدمًا لإيجاد أكثر المعلومات ملاءمة للسياق. يعيد حتى 10 أجزاء محتوى عالية الجودة مع عناوين المقالات وروابط URL، مسترجعًا دائمًا أحدث الوثائق الرسمية من مايكروسوفت فور نشرها.

**مثال بارز**: يكشف الخادم عن أداة `microsoft_docs_search` التي تُجري بحثًا دلاليًا ضد الوثائق التقنية الرسمية لمايكروسوفت. بمجرد التهيئة، يمكنك طرح أسئلة مثل "كيف أنفذ مصادقة JWT في ASP.NET Core؟" وتحصل على ردود مفصلة ورسمية مع روابط المصادر. جودة البحث استثنائية لأنه يفهم السياق — السؤال عن "containers" في سياق Azure يرجع وثائق Azure Container Instances، بينما نفس المصطلح في سياق .NET يرجع معلومات مناسبة عن مجموعات C#.

هذا مفيد بشكل خاص للمكتبات واستخدامات تناولها التحديثات مؤخرًا أو تتغير بسرعة. على سبيل المثال، في بعض مشاريع الترميز الأخيرة أردت استغلال ميزات الإصدارات الأخيرة من Aspire وMicrosoft.Extensions.AI. عن طريق تضمين خادم Microsoft Learn Docs MCP، تمكنت من الاستفادة ليس فقط من وثائق API، بل من الشروحات والإرشادات التي نُشرت حديثًا.

> **💡 نصيحة احترافية**
> 
> حتى النماذج الملائمة للأدوات تحتاج تشجيعًا لاستخدام أدوات MCP! فكر في إضافة موجه نظام أو [copilot-instructions.md](https://docs.github.com/copilot/how-tos/custom-instructions/adding-repository-custom-instructions-for-github-copilot) مثل: "لديك وصول إلى `microsoft.docs.mcp` — استخدم هذه الأداة للبحث في أحدث الوثائق الرسمية لمايكروسوفت عند التعامل مع أسئلة حول تقنيات Microsoft مثل C#، Azure، ASP.NET Core، أو Entity Framework."
>
> لمثال رائع على هذا في التطبيق، راجع وضع الدردشة [عامل النظافة لـ C# .NET](https://github.com/awesome-copilot/chatmodes/blob/main/csharp-dotnet-janitor.chatmode.md) من مستودع Awesome GitHub Copilot. هذا الوضع يستخدم خادم Microsoft Learn Docs MCP بشكل خاص لمساعدة تنظيف وتحديث كود C# باستخدام أحدث الأنماط وأفضل الممارسات.
### 2. ☁️ خادم Azure MCP


[![التثبيت في VS Code](https://img.shields.io/badge/VS_Code-Install_Azure_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D) [![التثبيت في VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Azure_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=Azure%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40azure%2Fazure-mcp%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Azure/azure-mcp)

**ما الذي يفعله**: خادم Azure MCP هو مجموعة شاملة من أكثر من 15 موصلًا متخصصًا لخدمات Azure يجلب النظام البيئي الكامل لـ Azure إلى سير عمل الذكاء الاصطناعي الخاص بك. هذا ليس مجرد خادم واحد – إنه مجموعة قوية تتضمن إدارة الموارد، والاتصال بقواعد البيانات (PostgreSQL، SQL Server)، وتحليل سجلات Azure Monitor باستخدام KQL، وتكامل Cosmos DB، والمزيد.

**لماذا هو مفيد**: بخلاف إدارة موارد Azure فقط، يعمل هذا الخادم على تحسين جودة الكود بشكل كبير عند العمل مع Azure SDKs. عند استخدام Azure MCP في وضع الوكيل، لا يساعدك فقط في كتابة الكود – بل يساعدك على كتابة كود *أفضل* لـ Azure يتبع أنماط المصادقة الحالية، وأفضل ممارسات معالجة الأخطاء، ويستفيد من أحدث ميزات SDK. بدلاً من الحصول على كود عام قد يعمل، تحصل على كود يتبع أنماط Azure الموصى بها لأحمال العمل الإنتاجية.

**الوحدات الأساسية تشمل**:
- **🗄️ موصلات قواعد البيانات**: وصول مباشر عبر اللغة الطبيعية إلى Azure Database لـ PostgreSQL وSQL Server
- **📊 Azure Monitor**: تحليل السجلات powered by KQL والرؤى التشغيلية
- **🌐 إدارة الموارد**: إدارة كاملة لدورة حياة موارد Azure
- **🔐 المصادقة**: أنماط DefaultAzureCredential والهوية المُدارة
- **📦 خدمات التخزين**: عمليات Blob Storage وQueue Storage وTable Storage
- **🚀 خدمات الحاويات**: تطبيقات Azure Container، مثيلات الحاويات، وإدارة AKS
- **وكثير من الموصلات المتخصصة الأخرى**

**الاستخدام العملي**: "أظهر لي حسابات تخزين Azure الخاصة بي"، "اسأل workspace تحليلات السجلات عن الأخطاء في الساعة الماضية"، أو "ساعدني في بناء تطبيق Azure باستخدام Node.js مع مصادقة صحيحة"

**سيناريو العرض التوضيحي الكامل**: إليك جولة كاملة تُظهر قوة دمج Azure MCP مع امتداد GitHub Copilot for Azure في VS Code. عندما يكون كلاهما مثبتًا وتطلب:

> "أنشئ سكربت Python يرفع ملفًا إلى Azure Blob Storage باستخدام مصادقة DefaultAzureCredential. يجب أن يتصل السكربت بحساب تخزين Azure الخاص بي المسمى 'mycompanystorage'، يرفع إلى حاوية مسماة 'documents'، ينشئ ملف اختبار مع الطابع الزمني الحالي للرفع، يتعامل مع الأخطاء بسلاسة ويقدم مخرجات معلوماتية، يتبع أفضل ممارسات Azure للمصادقة ومعالجة الأخطاء، يتضمن تعليقات تشرح كيفية عمل مصادقة DefaultAzureCredential، ويجعل السكربت منظمًا بشكل جيد مع الدوال والتوثيق المناسب."

سيولد خادم Azure MCP سكربت Python كامل وجاهز للإنتاج يقوم بـ:
- استخدام أحدث Azure Blob Storage SDK مع أنماط async صحيحة
- تنفيذ DefaultAzureCredential مع شرح شامل لسلسلة التراجع fallback
- تضمين معالجة أخطاء قوية مع أنواع استثناءات Azure المحددة
- اتباع أفضل ممارسات Azure SDK لإدارة الموارد ومعالجة الاتصال
- توفير تسجيلات تفصيلية ومخرجات معلوماتية على وحدة التحكم
- إنشاء سكربت منظم بشكل صحيح مع دوال، توثيق، وتلميحات نوعية

ما يجعل ذلك ملحوظًا هو أنه بدون Azure MCP، قد تحصل على كود تخزين blob عام يعمل ولكنه لا يتبع أنماط Azure الحالية. مع Azure MCP، تحصل على كود يستخدم أحدث طرق المصادقة، يتعامل مع سيناريوهات أخطاء خاصة بـ Azure، ويتبع ممارسات Microsoft الموصى بها لتطبيقات الإنتاج.

**مثال مميز**: كنت أواجه صعوبة في تذكر الأوامر الخاصة بـ `az` و`azd` لاستخدامات عشوائية. دائمًا ما تكون عملية من خطوتين بالنسبة لي: أولاً أبحث عن الصياغة ثم أشغل الأمر. غالبًا ما أدخل إلى البوابة وأنقر بحرية لأنني لا أريد أن أعترف أنني لا أتذكر صياغة CLI. القدرة على وصف ما أريد فقط أمر رائع، والأفضل أن أستطيع فعل ذلك دون مغادرة بيئة التطوير الخاصة بي!

هناك قائمة رائعة من حالات الاستخدام في [مستودع Azure MCP](https://github.com/Azure/azure-mcp?tab=readme-ov-file#-what-can-you-do-with-the-azure-mcp-server) لتبدأ بها. لأدلة إعداد شاملة وخيارات تهيئة متقدمة، اطلع على [التوثيق الرسمي لـ Azure MCP](https://learn.microsoft.com/azure/developer/azure-mcp-server/).

### 3. 🐙 خادم GitHub MCP

[![التثبيت في VS Code](https://img.shields.io/badge/VS_Code-Install_Server-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D) [![التثبيت في VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_Server-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=github&config=%7B%22type%22%3A%20%22http%22%2C%22url%22%3A%20%22https%3A%2F%2Fapi.githubcopilot.com%2Fmcp%2F%22%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/github/github-mcp-server)

**ما الذي يفعله**: يوفر الخادم الرسمي لـ GitHub MCP تكاملًا سلسًا مع النظام البيئي الكامل لـ GitHub، مع خيارات وصول مستضافة عن بُعد وخيارات نشر محلي عبر Docker. هذا ليس مجرد عمليات مستودع أساسية – بل هو مجموعة أدوات شاملة تشمل إدارة GitHub Actions، سير عمل طلبات السحب، تتبع القضايا، فحص الأمان، الإشعارات، وقدرات الأتمتة المتقدمة.

**لماذا هو مفيد**: هذا الخادم يغير كيفية تفاعلك مع GitHub من خلال جلب تجربة المنصة الكاملة مباشرة إلى بيئة تطويرك. بدلاً من التنقل المستمر بين VS Code وGitHub.com لإدارة المشاريع، مراجعة الكود، ومراقبة CI/CD، يمكنك التعامل مع كل شيء من خلال أوامر اللغة الطبيعية مع البقاء مركزًا على الكود.

> **ℹ️ ملاحظة: أنواع مختلفة من "الوكلاء"**
> 
> لا تخلط بين خادم GitHub MCP هذا ووكيل الترميز الخاص بـ GitHub (الوكيلي الذكي الذي يمكنك تعيين القضايا له لتنفيذ مهام الترميز الآلية). يعمل خادم GitHub MCP ضمن وضع الوكيل في VS Code لتوفير تكامل API لـ GitHub، بينما وكيل الترميز في GitHub هو ميزة منفصلة تنشئ طلبات سحب عند تعيينها لقضايا GitHub.

**القدرات الرئيسية تشمل**:
- **⚙️ GitHub Actions**: إدارة كاملة لأنابيب CI/CD، مراقبة سير العمل، والتعامل مع الآثار
- **🔀 طلبات السحب**: إنشاء ومراجعة ودمج وإدارة طلبات السحب مع تتبع شامل للحالة
- **🐛 القضايا**: إدارة كاملة لدورة حياة القضية، التعليق، التصنيف، والتعيين
- **🔒 الأمان**: تنبيهات فحص الكود، كشف الأسرار، وتكامل Dependabot
- **🔔 الإشعارات**: إدارة ذكية للإشعارات والتحكم في الاشتراك في المستودعات
- **📁 إدارة المستودعات**: عمليات الملفات، إدارة الفروع، وإدارة المستودعات
- **👥 التعاون**: بحث المستخدم والمؤسسة، إدارة الفرق، والتحكم في الوصول

**الاستخدام العملي**: "أنشئ طلب سحب من فرعي الميزة"، "أرني كل جلسات CI الفاشلة هذا الأسبوع"، "سرد تنبيهات الأمان المفتوحة لمستودعاتي"، أو "اعثر على كل القضايا المعينة لي عبر مؤسساتي"

**سيناريو العرض التوضيحي الكامل**: إليك سير عمل قوي يظهر قدرات خادم GitHub MCP:

> "أحتاج للتحضير لمراجعة السبرينت. أرني كل طلبات السحب التي أنشأتها هذا الأسبوع، تحقق من حالة أنابيب CI/CD، أنشئ ملخصًا لأي تنبيهات أمان يجب معالجتها، وساعدني في صياغة ملاحظات الإصدار بناءً على طلبات السحب المدمجة والمصنفة كـ 'feature'."

سيقوم خادم GitHub MCP بـ:
- الاستعلام عن طلبات السحب الأخيرة الخاصة بك مع معلومات حالة تفصيلية
- تحليل تشغيلات سير العمل وتسليط الضوء على أي إخفاقات أو مشكلات في الأداء
- تجميع نتائج فحص الأمان وترتيب التنبيهات الحرجة
- إنشاء ملاحظات إصدار شاملة من خلال استخراج المعلومات من طلبات السحب المدمجة
- تقديم الخطوات التالية العملية لتخطيط السبرينت والتحضير للإصدار

**مثال مميز**: أحب استخدام هذا لسير عمل مراجعة الكود. بدلاً من التنقل بين VS Code وإشعارات GitHub وصفحات طلبات السحب، يمكنني القول "أرني كل طلبات السحب التي تنتظر مراجعتي" ثم "أضف تعليقًا على PR رقم 123 يسأل عن معالجة الأخطاء في طريقة المصادقة." يدير الخادم استدعاءات API لـ GitHub، يحتفظ بسياق النقاش، ويساعدني حتى في صياغة تعليقات مراجعة أكثر بناءة.

**خيارات المصادقة**: يدعم الخادم كل من OAuth (بسلاسة في VS Code) ورموز الوصول الشخصي، مع مجموعات أدوات قابلة للتكوين لتمكين وظائف GitHub التي تحتاجها فقط. يمكنك تشغيله كخدمة مستضافة عن بُعد للإعداد السريع أو محليًا عبر Docker للتحكم الكامل.

> **💡 نصيحة احترافية**
> 
> قوم بتمكين مجموعات الأدوات التي تحتاجها فقط عن طريق تكوين معلمة `--toolsets` في إعدادات خادم MCP لتقليل حجم السياق وتحسين اختيار أدوات الذكاء الاصطناعي. على سبيل المثال، أضف `"--toolsets", "repos,issues,pull_requests,actions"` إلى معلمات تكوين MCP الخاصة بك لسير عمل التطوير الأساسي، أو استخدم `"--toolsets", "notifications, security"` إذا كنت تركز أساسًا على قدرات مراقبة GitHub.

### 5. 📝 خادم MarkItDown MCP


[![التثبيت في VS Code](https://img.shields.io/badge/VS_Code-Install_MarkItDown_MCP-0098FF?style=flat-square&logo=visualstudiocode&logoColor=white)](https://vscode.dev/redirect/mcp/install?name=MarkItDown%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40microsoft%2Fmcp-markitdown%40latest%22%5D%7D) [![التثبيت في VS Code Insiders](https://img.shields.io/badge/VS_Code_Insiders-Install_MarkItDown_MCP-24bfa5?style=flat-square&logo=visualstudiocode&logoColor=white)](https://insiders.vscode.dev/redirect/mcp/install?name=MarkItDown%20MCP&config=%7B%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40microsoft%2Fmcp-markitdown%40latest%22%5D%7D&quality=insiders) [![GitHub](https://img.shields.io/badge/GitHub-View_Repository-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/microsoft/markitdown)

**ما الذي يفعله**: MarkItDown هو خادم تحويل مستندات شامل يحول تنسيقات ملفات متنوعة إلى Markdown عالي الجودة، مصمم خصيصًا لاستهلاك نماذج اللغة الكبيرة (LLM) وسير عمل تحليل النصوص.

**لماذا هو مفيد**: ضروري لسير عمل التوثيق الحديث! يتعامل MarkItDown مع مجموعة واسعة من تنسيقات الملفات مع الحفاظ على الهيكلية الأساسية للمستند مثل العناوين، القوائم، الجداول، والروابط. على عكس أدوات استخراج النصوص البسيطة، يركز على الحفاظ على المعنى الدلالي والتنسيق الذي يهم كل من المعالجة الآلية والقراءة البشرية.

**تنسيقات الملفات المدعومة**:
- **مستندات أوفيس**: PDF، باوربوينت (PPTX)، وورد (DOCX)، إكسل (XLSX/XLS)
- **ملفات وسائط**: الصور (مع بيانات EXIF المضمنة والتعرف الضوئي على الحروف OCR)، الصوت (مع بيانات EXIF وتفريغ الكلام)
- **محتوى الويب**: HTML، خلاصات RSS، عناوين يوتيوب، صفحات ويكيبيديا
- **تنسيقات بيانات**: CSV، JSON، XML، ملفات ZIP (مع معالجة المحتويات بشكل متكرر)
- **تنسيقات نشر**: EPub، دفاتر Jupyter (.ipynb)
- **البريد الإلكتروني**: رسائل Outlook (.msg)
- **متقدم**: تكامل Azure Document Intelligence لتحسين معالجة PDF

**القدرات المتقدمة**: يدعم MarkItDown توصيف الصور بواسطة نماذج اللغة الكبيرة (عند وجود عميل OpenAI)، وAzure Document Intelligence لتحسين معالجة ملفات PDF، وتفريغ الصوت لمحتوى الكلام، ونظام إضافات لتوسيع دعم مزيد من تنسيقات الملفات.

**الاستخدام العملي**: "حول هذا العرض التقديمي لباوربوينت إلى Markdown لموقع التوثيق الخاص بنا"، "استخرج نصًا من هذا PDF مع الحفاظ على هيكل العناوين الصحيح"، أو "حوّل جدول إكسل هذا إلى تنسيق جدول قابل للقراءة"

**مثال مميز**: للاقتباس من [وثائق MarkItDown](https://github.com/microsoft/markitdown#why-markdown):

> Markdown قريب جدًا من النص العادي، مع أقل قدر من العلامات أو التنسيق، لكنه لا يزال يوفر طريقة لتمثيل الهيكل الهام للمستند. نماذج اللغة الكبيرة الرئيسية، مثل GPT-4o من OpenAI، "تتحدث" Markdown بطبيعة الحال، وغالبًا ما تدرج Markdown ضمن ردودها بدون طلب. هذا يشير إلى أنها تم تدريبها على كميات هائلة من النصوص المنسقة بـ Markdown، وتفهمها جيدًا. كمزية إضافية، اتفاقيات Markdown فعالة جدًا من حيث عدد الرموز المميزة.

MarkItDown يجيد حقًا الحفاظ على هيكل المستند، وهو أمر مهم لسير عمل الذكاء الاصطناعي. على سبيل المثال، عند تحويل عرض باوربوينت، يحافظ على تنظيم الشرائح مع العناوين المناسبة، ويستخرج الجداول كجداول Markdown، ويضيف نصًا بديلًا للصور، وحتى يعالج ملاحظات المتحدث. يتم تحويل الرسوم البيانية إلى جداول بيانات قابلة للقراءة، وMarkdown الناتج يحافظ على التدفق المنطقي للعرض التقديمي الأصلي. هذا يجعله مثاليًا لإدخال محتوى العروض التقديمية إلى أنظمة الذكاء الاصطناعي أو لإنشاء التوثيق من الشرائح الحالية.

**لماذا هو مفيد**: يحول هذا الخادم طريقة عملك مع خدمات Azure AI من خلال جلب قدرات الذكاء الاصطناعي بمستوى مؤسسي مباشرة إلى سير عمل التطوير الخاص بك. بدلاً من التنقل بين بوابة Azure والوثائق وIDE الخاص بك، يمكنك اكتشاف النماذج، نشر الخدمات، إدارة قواعد المعرفة، وتقييم أداء الذكاء الاصطناعي عبر أوامر اللغة الطبيعية. وهو قوي بشكل خاص للمطورين الذين يبنون تطبيقات RAG (التوليد المعزز بالاستخلاص)، يديرون نشر نماذج متعددة، أو ينفذون مسارات تقييم شاملة للذكاء الاصطناعي.

**القدرات الرئيسية للمطورين**:

- **📚 إدارة المعرفة**: أنشئ وأدر فهارس Azure AI Search، أضف مستندات، قم بتكوين المفهرسين، وابن أنظمة RAG معقدة
- **⚡ دمج وكلاء الذكاء الاصطناعي**: اتصل بوكلاء Azure AI، استعلم عن الوكلاء الحاليين، وقيم أداء الوكلاء في سيناريوهات الإنتاج
- **📊 إطار التقييم**: شغّل تقييمات شاملة للنص والوكيل، أنشئ تقارير ماركداون، وطبق ضمان الجودة لتطبيقات الذكاء الاصطناعي
- **🚀 أدوات النمذجة الأولية**: احصل على تعليمات الإعداد للنمذجة الأولية القائمة على GitHub وادخل مختبرات Microsoft Foundry للحصول على نماذج بحث متطورة

**الاستخدام الواقعي للمطورين**: "انشر نموذج Phi-4 إلى خدمات Azure AI لتطبيقي"، "أنشئ مؤشر بحث جديد لنظام RAG الخاص بوثائقي"، "قيّم ردود وكيلي مقابل مقاييس الجودة"، أو "اعثر على أفضل نموذج استدلال لمهام تحليلي المعقدة"

سيقوم خادم Microsoft Foundry MCP بـ:

- إعداد فهارس Azure AI Search مع المخطط الصحيح لوثائقك

- إنشاء رمز النمذجة الأولية مع مصادقة GitHub للاختبار الفوري
- تقديم أدلة إعداد شاملة مخصصة لتكديس التكنولوجيا الخاص بك

**مثال مميز**: كمطور، كنت أعاني لمتابعة نماذج LLM المختلفة المتاحة. أعرف بعض النماذج الرئيسة، لكن شعرت أنني أفوت مكاسب في الإنتاجية والكفاءة. الرموز والحصص مرهقة وصعبة الإدارة – لا أعرف أبدًا إذا كنت أختار النموذج المناسب للمهمة أو أحرق الميزانية بكفاءة منخفضة. سمعت مؤخرًا عن هذا الخادم من James Montemagno أثناء البحث مع زملائي لتوصيات MCP Server لهذا المنشور، وأنا متحمس لاستخدامه! قدرات اكتشاف النماذج تبدو رائعة لشخص مثلي يريد استكشاف خارج المعتاد والعثور على نماذج محسنة لمهام محددة. يجب أن يساعدني إطار التقييم في التأكد من أنني أحصل فعلاً على نتائج أفضل، وليس فقط تجربة شيء جديد لمجرد ذلك.

## 📋 الخلاصة

بروتوكول سياق النموذج (MCP) يحول كيفية تفاعل المطورين مع مساعدين الذكاء الاصطناعي والأدوات الخارجية. تعرض هذه الخوادم العشرة لـ Microsoft MCP قوة التكامل الموحد للذكاء الاصطناعي، مما يمكّن سير عمل سلس يبقي المطورين في حالة تدفق بينما يصلون إلى قدرات خارجية قوية.

من التكامل الشامل لنظام Azure البيئي إلى الأدوات المتخصصة مثل Playwright لأتمتة المتصفح وMarkItDown لمعالجة المستندات، تعرض هذه الخوادم كيف يمكن لـ MCP تعزيز الإنتاجية عبر سيناريوهات تطوير متنوعة. يضمن البروتوكول الموحد أن تعمل هذه الأدوات معًا بسلاسة، مما يخلق تجربة تطوير متماسكة.

مع استمرار تطور نظام MCP البيئي، سيكون البقاء متفاعلًا مع المجتمع، استكشاف الخوادم الجديدة، وبناء الحلول المخصصة مفتاحًا لتعظيم إنتاجية التطوير الخاصة بك. تعني الطبيعة المفتوحة للبروتوكول MCP أنه يمكنك دمج الأدوات من بائعين مختلفين لإنشاء سير عمل مثالي لاحتياجاتك الخاصة.

4. **تحليل الأداء**: قارن كفاءة استخدام خوادم MCP مقابل الأساليب التقليدية للمهام التطويرية الشائعة.
5. **تقييم الأمان**: قم بتقييم تأثيرات الأمان لاستخدام خوادم MCP في بيئة التطوير الخاصة بك واقترح أفضل الممارسات.


التالي: [أفضل الممارسات](../08-BestPractices/README.md)
