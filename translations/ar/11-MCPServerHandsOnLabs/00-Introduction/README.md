# مقدمة في دمج قاعدة بيانات MCP

> [!NOTE]
> تعكس المخططات أو التعليمات البرمجية في مسار التعلم هذا التي تستخدم HTTP/SSE أو خيارات التهيئة
> تبعيات MCP النموذجية لـ `2025-11-25`. للعمليات الجديدة،
> استخدم طلبات بدون حالة وإمكانية البث عبر HTTP لإصدار `2026-07-28`.

## 🎯 ماذا يغطي هذا المختبر

يوفر هذا المختبر التمهيدي نظرة شاملة على بناء خوادم بروتوكول سياق النموذج (MCP) مع تكامل قاعدة البيانات. ستفهم حالة العمل، والهندسة التقنية، والتطبيقات الواقعية من خلال حالة استخدام تحليلات تجزئة Zava في https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail.

## نظرة عامة

**بروتوكول سياق النموذج (MCP)** يمكّن مساعدين الذكاء الاصطناعي من الوصول والتفاعل بأمان مع مصادر البيانات الخارجية في الوقت الحقيقي. عند دمجه مع تكامل قواعد البيانات، يفتح MCP إمكانيات قوية لتطبيقات الذكاء الاصطناعي المعتمدة على البيانات.

يعلمك هذا المسار التعليمي كيفية بناء خوادم MCP جاهزة للإنتاج تربط مساعدين الذكاء الاصطناعي ببيانات مبيعات التجزئة عبر PostgreSQL، وتنفيذ أنماط مؤسسية مثل أمان مستوى الصف، والبحث الدلالي، والوصول متعدد المستأجرين للبيانات.

## أهداف التعلم

بحلول نهاية هذا المختبر، ستكون قادرًا على:

- **تعريف** بروتوكول سياق النموذج وفوائده الأساسية لتكامل قاعدة البيانات
- **تحديد** المكونات الرئيسية لهندسة خادم MCP مع قواعد البيانات
- **فهم** حالة استخدام Zava Retail ومتطلبات العمل الخاصة بها
- **التعرف** على أنماط المؤسسات للوصول الآمن والقابل للتوسع إلى قاعدة البيانات
- **إدراج** الأدوات والتقنيات المستخدمة خلال مسار التعلم هذا

## 🧭 التحدي: عندما يلتقي الذكاء الاصطناعي بالبيانات الواقعية

### قيود الذكاء الاصطناعي التقليدي

مساعدين الذكاء الاصطناعي الحديثين أقوياء للغاية لكنهم يواجهون قيودًا كبيرة عند العمل مع بيانات الأعمال الواقعية:

| **التحدي** | **الوصف** | **تأثير العمل** |
|---------------|-----------------|-------------------|
| **المعرفة الثابتة** | النماذج المدربة على مجموعات بيانات ثابتة لا يمكنها الوصول إلى بيانات الأعمال الحالية | رؤى قديمة، فرص ضائعة |
| **جزر البيانات** | المعلومات محصورة في قواعد بيانات، واجهات برمجة التطبيقات، وأنظمة لا يمكن للذكاء الاصطناعي الوصول إليها | تحليل غير مكتمل، سير عمل مجزأ |
| **قيود الأمان** | الوصول المباشر إلى قاعدة البيانات يثير مخاوف أمنية وامتثال | نشر محدود، تحضير بيانات يدوي |
| **الاستعلامات المعقدة** | يحتاج المستخدمون التجاريون إلى معرفة تقنية لاستخراج رؤى البيانات | تبني أقل، عمليات غير فعالة |

### حل MCP

يعالج بروتوكول سياق النموذج هذه التحديات من خلال توفير:

- **الوصول إلى البيانات في الوقت الحقيقي**: يسأل المساعدون الذكيون قواعد البيانات والواجهات الحية
- **تكامل آمن**: وصول التحكم مع المصادقة والصلاحيات
- **واجهة اللغة الطبيعية**: يطرح المستخدمون التجاريون أسئلة باللغة الإنجليزية البسيطة
- **بروتوكول موحد**: يعمل عبر منصات وأدوات ذكاء اصطناعي مختلفة

## 🏪 التعرف على Zava Retail: دراسة حالة التعلم https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

خلال مسار التعلم هذا، سنبني خادم MCP لـ **Zava Retail**، سلسلة متاجر خيالية لبيع أدوات التجهيز الذاتي مع مواقع متعددة. يوضح هذا السيناريو الواقعي تنفيذ MCP بمستوى مؤسسي.

### سياق العمل

تدير **Zava Retail**:
- **8 متاجر فعلية** عبر ولاية واشنطن (سياتل، بلفيو، تاكوما، سبوكان، إيفريت، ريدموند، كيركلاند)
- **متجر إلكتروني واحد** للمبيعات عبر الإنترنت
- **كتالوج منتجات متنوع** يشمل الأدوات، الأجهزة، مستلزمات الحديقة، ومواد البناء
- **إدارة متعددة المستويات** مع مديري المتاجر، مديري المناطق، والتنفيذيين

### متطلبات العمل

يحتاج مدراء المتاجر والتنفيذيون إلى تحليلات مدعمة بالذكاء الاصطناعي لـ:

1. **تحليل أداء المبيعات** عبر المتاجر والفترات الزمنية
2. **تتبع مستويات المخزون** وتحديد احتياجات إعادة التوريد
3. **فهم سلوك العملاء** وأنماط الشراء
4. **اكتشاف رؤى المنتجات** من خلال البحث الدلالي
5. **توليد تقارير** من استعلامات اللغة الطبيعية
6. **الحفاظ على أمان البيانات** من خلال التحكم في الوصول بناءً على الدور

### المتطلبات التقنية

يجب أن يقدم خادم MCP:

- **وصول بيانات متعدد المستأجرين** حيث يرى مديرو المتجر بيانات متجرهم فقط
- **استعلام مرن** يدعم عمليات SQL المعقدة
- **بحث دلالي** لاكتشاف المنتجات والتوصيات
- **بيانات في الوقت الحقيقي** تعكس الحالة الحالية للعمل
- **مصادقة آمنة** باستخدام أمان مستوى الصف
- **هندسة قابلة للتوسع** تدعم عدة مستخدمين متزامنين

### المكونات الرئيسية

#### **1. طبقة خادم MCP**
- **إطار FastMCP**: تنفيذ خادم MCP حديث بلغة بايثون
- **تسجيل الأدوات**: تعريف أدوات تعبيرية مع أمان الأنواع
- **سياق الطلب**: هوية المستخدم وإدارة الجلسة
- **معالجة الأخطاء**: إدارة أخطاء قوية وتسجيلها

#### **2. طبقة تكامل قاعدة البيانات**
- **تجميع الاتصالات**: إدارة فعالة لاتصالات asyncpg
- **مزود المخطط**: اكتشاف مخطط الجداول ديناميكيًا
- **منفذ الاستعلامات**: تنفيذ SQL آمن مع سياق RLS
- **إدارة المعاملات**: التزام ACID والتراجع عن العمليات

#### **3. طبقة الأمان**
- **أمان مستوى الصف**: نظام RLS في PostgreSQL لعزل بيانات متعدد المستأجرين
- **هوية المستخدم**: مصادقة وتفويض مديري المتاجر
- **التحكم في الوصول**: صلاحيات دقيقة ومسارات تدقيق
- **التحقق من الإدخال**: منع هجمات حقن SQL والتحقق من الاستعلامات

#### **4. طبقة تعزيز الذكاء الاصطناعي**
- **البحث الدلالي**: تضمين المتجهات لاكتشاف المنتجات
- **تكامل Azure OpenAI**: توليد تضمين النصوص
- **خوارزميات التشابه**: بحث تشابه جيوميتري pgvector
- **تحسين البحث**: الفهرسة وضبط الأداء

## 🎬 سيناريوهات الاستخدام الواقعي

دعونا نستعرض كيف يتفاعل المستخدمون المختلفون مع خادم MCP الخاص بنا:

### السيناريو 1: مراجعة أداء مدير المتجر

**المستخدم**: سارة، مديرة متجر سياتل  
**الهدف**: تحليل أداء المبيعات للربع الأخير

**استعلام اللغة الطبيعية**:

**ما يحدث**:
1. ترسل دردشة AI في VS Code الاستعلام إلى خادم MCP
2. يحدد خادم MCP سياق متجر سارة (سياتل)
3. تقوم سياسات RLS بتصفية البيانات لتشمل متجر سياتل فقط
4. يتم إنشاء وتنفيذ استعلام SQL
5. يتم تنسيق النتائج وإرجاعها لدردشة AI
6. يقدم الذكاء الاصطناعي التحليل والرؤى

### السيناريو 2: اكتشاف المنتجات عبر البحث الدلالي

**المستخدم**: مايك، مدير المخزون  
**الهدف**: إيجاد منتجات مشابهة لطلب العميل

**استعلام اللغة الطبيعية**:
> "ما المنتجات التي نبيعها والتي تشبه 'وصلات كهربائية مقاومة للماء للاستخدام الخارجي'؟"

**ما يحدث**:
1. يقوم أداة البحث الدلالي بمعالجة الاستعلام
2. يولد Azure OpenAI متجه تضمين النص
3. يجري pgvector بحث تشابه
4. تصنف المنتجات ذات الصلة حسب الصلة
5. تشمل النتائج تفاصيل المنتج والتوفر
6. يقترح الذكاء الاصطناعي بدائل وفرص التجميع

### السيناريو 3: تحليلات عبر المتاجر

**المستخدم**: جينيفر، مديرة إقليمية  
**الهدف**: مقارنة الأداء عبر جميع المتاجر

**استعلام اللغة الطبيعية**:
> "قارن المبيعات حسب الفئة لجميع المتاجر خلال الأشهر الستة الماضية"

**ما يحدث**:
1. يتم تعيين سياق RLS للوصول مديرة الإقليم
2. يُنشأ استعلام متعدد المتاجر معقد
3. تُجمع البيانات عبر مواقع المتاجر
4. تشمل النتائج الاتجاهات والمقارنات
5. يحدد الذكاء الاصطناعي رؤى وتوصيات

## 🔒 الغوص العميق في الأمان وتعدد المستأجرين

يمنح تنفيذنا الأولوية لأمان بمستوى مؤسسي:

### أمان مستوى الصف (RLS)

يضمن RLS في PostgreSQL عزل البيانات:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

### إدارة هوية المستخدم

تتضمن كل اتصال MCP:
- **معرف مدير المتجر**: معرف فريد لسياق RLS
- **تعيين الدور**: الصلاحيات ومستويات الوصول
- **إدارة الجلسة**: رموز مصادقة آمنة
- **تسجيل التدقيق**: سجل كامل للوصول

### حماية البيانات

طبقات أمان متعددة:
- **تشفير الاتصال**: TLS لجميع اتصالات قاعدة البيانات
- **منع حقن SQL**: استعلامات ذات معلمات فقط
- **التحقق من الإدخال**: تحقق شامل من الطلبات
- **معالجة الأخطاء**: عدم وجود بيانات حساسة في رسائل الخطأ
