# AGENTS.md

## نظرة عامة على المشروع

**MCP للمبتدئين** هو منهج تعليمي مفتوح المصدر لتعلم بروتوكول سياق النموذج (MCP) - وهو إطار معياري للتفاعلات بين نماذج الذكاء الاصطناعي وتطبيقات العميل. يوفر هذا المستودع مواد تعليمية شاملة مع أمثلة تعليمية عملية عبر لغات برمجة متعددة.

### التقنيات الرئيسية

- **لغات البرمجة**: C#، Java، JavaScript، TypeScript، Python، Rust
- **الأُطُر ومجموعات تطوير البرمجيات (SDKs)**: 
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **قواعد البيانات**: PostgreSQL مع امتداد pgvector
- **منصات الحوسبة السحابية**: Azure (تطبيقات الحاويات، OpenAI، أمان المحتوى، Application Insights)
- **أدوات البناء**: npm، Maven، pip، Cargo
- **التوثيق**: Markdown مع ترجمة آلية متعددة اللغات (أكثر من 48 لغة)

### البنية المعمارية

- **11 وحدة أساسية (00-11)**: مسار تعلم متسلسل من الأساسيات إلى المواضيع المتقدمة
- **مختبرات تطبيقية**: تمارين عملية مع شفرة الحلول الكاملة بلغات متعددة
- **مشاريع نموذجية**: تطبيقات خادم MCP وعملاء تعمل بكفاءة
- **نظام الترجمة**: سير عمل آلي لـ GitHub Actions لدعم تعدد اللغات
- **موارد الصور**: دليل مركزي للصور مع نسخ مترجمة

## أوامر الإعداد

هذا مستودع مركز على التوثيق. يتم معظم الإعداد داخل مشاريع مختبرية وعينية منفصلة.

### إعداد المستودع

```bash
# استنساخ المستودع
git clone https://github.com/microsoft/mcp-for-beginners.git
cd mcp-for-beginners
```

### العمل مع المشاريع النموذجية

المشاريع النموذجية تقع في:
- `03-GettingStarted/samples/` - أمثلة خاصة بكل لغة
- `03-GettingStarted/01-first-server/solution/` - تطبيقات الخادم الأولى
- `03-GettingStarted/02-client/solution/` - تطبيقات العميل
- `11-MCPServerHandsOnLabs/` - مختبرات تكامل قواعد البيانات الشاملة

كل مشروع نموذجي يحتوي على تعليمات إعداد خاصة به:

#### مشاريع TypeScript/JavaScript
```bash
cd <project-directory>
npm install
npm start
```

#### مشاريع Python
```bash
cd <project-directory>
pip install -r requirements.txt
# أو
pip install -e .
python main.py
```

#### مشاريع Java
```bash
cd <project-directory>
mvn clean install
mvn spring-boot:run
```

##### الهدف

التحقق من صحة تغييرات وثائق المنهج الدراسي وعينة التعليمات البرمجية التمثيلية
قبل الدمج.

##### المُدخلات

- `changed_paths: string[]` (مطلوب) - المسارات النسبية التي تم تغييرها في PR.
- `run_docs_lint: boolean` (افتراضي `true`)
- `run_links_audit: boolean` (افتراضي `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (الافتراضي الكل `false`)

##### المخرجات

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### الأذونات

- قراءة ملفات مساحة العمل وكتابة القطع المُولدة من الأدوات (مثل تقارير الـ
  lint، سجلات الاختبار) فقط؛ لا توجد كتابات على `translations/` أو
  `translated_images/`.
- تنفيذ أوامر الـ shell المحلية.
- وصول اختياري إلى الشبكة فقط لاستعادة الحزم (`npm ci`,
  `python -m pip install`, حل تبعيات `mvn`).
- لا توجد إذن للدفع أو الدمج أو تعديل `translations/` أو
  `translated_images/`.

##### أنماط الفشل

- `E_NO_INPUT_PATHS`: `changed_paths` فارغ.
- `E_INVALID_PATH`: مسار الإدخال يخرج من جذر المستودع.
- `E_LINT_FAILED`: خروج غير صفر لأداة فحص اللغة.
- `E_LINK_AUDIT_FAILED`: خروج غير صفر لأمر تدقيق الروابط.
- `E_SAMPLE_TEST_FAILED`: خروج غير صفر لاختبار/بناء العينة.
- `E_TIMEOUT`: الأمر تجاوز المهلة المحددة.

##### عقد CI الموصى به

لأتمتة التحقق، قم بتكوين مهمة CI التي:

- تنطلق عند طلبات السحب التي تلمس `*.md`، الشفرة النموذجية، أو هذا الملف.
- تنفذ الأوامر المذكورة أعلاه بالضبط.
- تحافظ على السجلات كقطع.
- تفشل المهمة عند أي رمز خروج غير صفري.

### هيكلية الوثائق

- **الوحدات 00-11**: محتوى المنهج الأساسي بترتيب تسلسلي
- **translations/**: نسخ بلغات محددة (تُولَد تلقائيًا، لا تُحرر مباشرة)
- **translated_images/**: نسخ الصور المحلّاة (توليد تلقائي)
- **images/**: صور ومخططات المصدر

### إجراء تغييرات على الوثائق

1. حرر فقط ملفات الماركدون الإنجليزية في مجلدات الوحدة الجذرية (00-11)
2. حدث الصور في مجلد `images/` إذا لزم الأمر
3. إجراء الترجمة التلقائي في GitHub Action يقوم بتوليد الترجمات تلقائيًا
4. تتم إعادة توليد الترجمات عند الدفع إلى الفرع الأساسي (main)

### العمل مع الترجمات

- **الترجمة التلقائية**: سير العمل في GitHub Actions يتولى كل الترجمات
- **لا تقم بالتحرير اليدوي** لملفات مجلد `translations/`
- بيانات التعريف الخاصة بالترجمة مضمنة داخل كل ملف مترجم
- اللغات المدعومة: أكثر من 48 لغة تشمل العربية، الصينية، الفرنسية، الألمانية، الهندية، اليابانية، الكورية، البرتغالية، الروسية، الإسبانية، وغيرها الكثير

## تعليمات الاختبار

### التحقق من الوثائق

بما أن هذا مستودع وثائق بشكل أساسي، يركز الاختبار على:

1. **مراجعة نمط الروابط**: سرد روابط ماركدون للمراجعة

   ```bash
   # سرد روابط ماركداون (تدقيق النمط)
   find . -name "*.md" -not -path "*/node_modules/*" -not -path "./translations/*" -not -path "./translated_images/*" -print0 | xargs -0 grep -En "\[.*\]\(.*\)"
   ```

2. **التحقق من عينات الكود**: اختبار أن الأمثلة البرمجية تُجمع/تعمل

   ```bash
   # انتقل إلى عينة معينة وقم بتشغيل اختباراتها
   cd 03-GettingStarted/samples/typescript
   npm install && npm test
   ```

3. **مدقق ماركدون**: التحقق من اتساق التنسيق

   ```bash
   # استخدم markdownlint إذا لزم الأمر
   npx --yes markdownlint-cli2 "**/*.md" "#node_modules" "#translations" "#translated_images"
   ```

### اختبار المشروع النموذجي

## إرشادات نمط الكود

### أسلوب التوثيق

- استخدم لغة واضحة ومناسبة للمبتدئين
- أدرج أمثلة برمجية بلغات متعددة عند الاقتضاء
- اتبع أفضل ممارسات الماركدون:
  - استخدم رؤوس ATX (`#` )
  - استخدم كتل كود مسيجة مع معرفات اللغة
  - أدرج نصًا بديلًا وصفيًا للصور
  - حافظ على طول الأسطر معقولًا (لا يوجد حد صارم، لكن كن معقولًا)

### أسلوب عينات الكود

#### تايب سكريبت/جافاسكريبت
- استخدم وحدات ES (`import`/`export`)
- اتبع قواعد الوضع الصارم في تايب سكريبت
- أدرج تعليقات النوع (type annotations)
- استهدف ES2022

#### بايثون
- اتبع إرشادات نمط PEP 8
- استخدم تلميحات النوع عند الاقتضاء
- أدرج سلاسل وثائق (docstrings) للدوال والفصول
- استخدم ميزات بايثون الحديثة (3.8+)

#### جافا
- اتبع قواعد Spring Boot
- استخدم ميزات جافا 21
- اتبع الهيكل القياسي لمشاريع Maven
- أدرج تعليقات Javadoc

## إرشادات المساهمة

### عملية طلب السحب (Pull Request)

1. **التفرع والاستنساخ**: افصل المستودع ونسخ الفرع محليًا
2. **إنشاء فرع**: استخدم أسماء فرع وصفية (مثلاً، `fix/typo-module-3`، `add/python-example`)
3. **إجراء التغييرات**: حرر ملفات الماركدون الإنجليزية فقط (ليس الترجمات)
4. **الاختبار محليًا**: تحقق من أن عرض الماركدون صحيح
5. **إرسال طلب السحب**: استخدم عناوين واستعراضات طلب سحب واضحة
6. **اتفاقية مساهم مايكروسوفت**: وقع الاتفاقية عندما يُطلب منك ذلك

### تنسيق عنوان طلب السحب

استخدم عناوين واضحة ووصفية:
- `[Module XX] وصف مختصر` لتغييرات محددة بالوحدة
- `[Samples] وصف` لتغييرات أمثلة الكود
- `[Docs] وصف` لتحديثات الوثائق العامة

### ما يجب المساهمة به

- إصلاحات أخطاء في الوثائق أو نماذج الكود
- أمثلة كود جديدة بلغات إضافية
- توضيحات وتحسينات للمحتوى الحالي
- دراسات حالة جديدة أو أمثلة تطبيقية
- تقارير مشاكل خاصة بالمحتوى غير الواضح أو الخاطئ

### ما لا يجب فعله

- لا تقم بتحرير الملفات في مجلد `translations/` مباشرة
- لا تعدل مجلد `translated_images/`
- لا تضف ملفات ثنائية كبيرة بدون مناقشة
- لا تغير ملفات سير عمل الترجمة بدون تنسيق مسبق
