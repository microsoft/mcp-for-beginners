# ਮਾਡਲ ਸੰਦਰਭ ਪ੍ਰੋਟੋਕੋਲ (MCP) ਨਾਲ HTTPS ਸਟ੍ਰੀਮਿੰਗ

ਇਹ ਅਧਿਆਇ HTTPS ਦੀ ਵਰਤੋਂ ਨਾਲ ਮਾਡਲ ਸੰਦਰਭ ਪ੍ਰੋਟੋਕੋਲ (MCP) ਨਾਲ ਸੁਰੱਖਿਅਤ, ਵਧੇਰੇ ਸਕੇਲ ਕਰਨ ਯੋਗ, ਅਤੇ ਤੁਰੰਤ ਸਟ੍ਰੀਮਿੰਗ ਲਾਗੂ ਕਰਨ ਲਈ ਇਕ ਵਿਸਥਾਰਪੂਰਕ ਮਾਰ్గਦਰਸ਼ਨ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ। ਇਹ ਸਟ੍ਰੀਮਿੰਗ ਲਈ ਪ੍ਰੇਰਣਾ, ਉਪਲਬਧ ਟ੍ਰਾਂਸਪੋਰਟ ਕਿਸਮਾਂ, MCP ਵਿੱਚ ਸਟ੍ਰੀਮਿੰਗ HTTP ਕਿਵੇਂ ਲਾਗੂ ਕਰੀਏ, ਸੁਰੱਖਿਅਤਾ ਲਈ ਸਭ ਤੋਂ ਵਧੀਆ ਅਭਿਆਸ, SSE ਤੋਂ ਮਾਈਗ੍ਰੇਸ਼ਨ ਅਤੇ ਆਪਣੇ ਆਪ ਦੇ ਸਟ੍ਰੀਮਿੰਗ MCP ਐਪਲੀਕੇਸ਼ਨਾਂ ਦੇ ਬਣਾਉਣ ਲਈ ਵਿਹਾਰਿਕ ਮਾਰਗਦਰਸ਼ਨ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ।

> **ਅਗਲੇ ਭਵਿੱਖ ਵੱਲ ਵੇਖਦੇ ਹੋਏ:** ਇਹ ਪਾਠ MCP ਵਿਵਰਣ 2025-11-25 ਅਧੀਨ ਸਟ੍ਰੀਮਿੰਗ ਯੋਗ HTTP ਦੀ ਵਿਆਖਿਆ ਕਰਦਾ ਹੈ, ਜਿੱਥੇ ਸੈਸ਼ਨ `initialize` ਦੌਰਾਨ ਸਥਾਪਿਤ ਹੁੰਦਾ ਹੈ ਅਤੇ `Mcp-Session-Id` ਹੈਡਰ ਨਾਲ ਪਿੰਨ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। `2026-07-28` ਰਿਲੀਜ਼ ਉਮੀਦਵਾਰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਹੈਂਡਸ਼ੇਕ ਅਤੇ ਸੈਸ਼ਨ ਆਈਡੀ ਨੂੰ ਹਟਾ ਦਿੰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਹਰ ਬੇਨਤੀ ਸਵੈ-ਸੰਯੁਕਤ ਅਤੇ ਕਿਸੇ ਵੀ ਸਰਵਰ ਇੰਸਟੈਂਸ ਨੂੰ ਰੂਟ ਕਰਨ ਯੋਗ ਬਣ ਜਾਂਦੀ ਹੈ ਬਿਨਾਂ ਚਟਕੀ ਸੈਸ਼ਨਾਂ ਦੇ। ਵੇਰਵੇ ਲਈ [MCP ਵਿੱਚ ਕੀ ਬਦਲ ਰਿਹਾ ਹੈ: 2026-07-28 ਰਿਲੀਜ਼ ਉਮੀਦਵਾਰ](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ਵੇਖੋ।

## MCP ਵਿੱਚ ਟ੍ਰਾਂਸਪੋਰਟ ਮੈਕੈਨਿਜ਼ਮ ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ

ਇਹ ਭਾਗ MCP ਵਿੱਚ ਵਿਭਿੰਨ ਉਪਲਬਧ ਟ੍ਰਾਂਸਪੋਰਟ ਮੈਕੈਨਿਜ਼ਮਾਂ ਅਤੇ ਉਹਨਾਂ ਦੀ ਭੂਮਿਕਾ ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ ਜੋ ਕਲਾਇੰਟ ਅਤੇ ਸਰਵਰ ਦੇ ਵਿਚਕਾਰ ਤੁਰੰਤ ਸੰਚਾਰ ਲਈ ਸਟ੍ਰੀਮਿੰਗ ਸਮਰੱਥਾਵਾਂ ਨੂੰ ਯੋਗ ਬਣਾਉਂਦੇ ਹਨ।

### ਟ੍ਰਾਂਸਪੋਰਟ ਮੈਕੈਨਿਜ਼ਮ ਕੀ ਹੈ?

ਟ੍ਰਾਂਸਪੋਰਟ ਮੈਕੈਨਿਜ਼ਮ ਇਹ ਪਰਿਭਾਸ਼ਤ ਕਰਦਾ ਹੈ ਕਿ ਕਲਾਇੰਟ ਅਤੇ ਸਰਵਰ ਦਰਮਿਆਨ ਡਾਟਾ ਨੂੰ ਕਿਵੇਂ ਅਦਾਨ-ਪ੍ਰਦਾਨ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। MCP ਵੱਖ-ਵੱਖ ਵਾਤਾਵਰਨਾਂ ਅਤੇ ਲੋੜਾਂ ਦੇ ਨਾਲ ਮੇਲ ਖਾਂਦੇ ਕਈ ਟ੍ਰਾਂਸਪੋਰਟ ਕਿਸਮਾਂ ਨੂੰ ਸਮਰਥਨ ਦਿੰਦਾ ਹੈ:

- **stdio**: ਸਧਾਰਣ ਇਨਪੁਟ/ਆਉਟਪੁਟ, ਜੋ ਸਥਾਨਕ ਅਤੇ CLI-ਅਧਾਰਿਤ ਟੂਲਾਂ ਲਈ ਉਚਿਤ ਹੈ। ਸਧਾਰਣ ਪਰ ਵੈੱਬ ਜਾਂ ਕਲਾਉਡ ਲਈ ਉਚਿਤ ਨਹੀਂ।
- **SSE (ਸਰਵਰ-ਸੈਂਟ ਇਵੈਂਟਸ)**: ਸਰਵਰਾਂ ਨੂੰ HTTP ਉਪਰ ਤੁਰੰਤ ਅਪਡੇਟਸ ਕਲਾਇੰਟਾਂ ਨੂੰ ਭੇਜਣ ਦੀ umožਲ ਦਿੰਦਾ ਹੈ। ਵੈੱਬ UI ਲਈ ਵਧੀਆ, ਪਰ ਸਕੇਲੇਬਿਲਟੀ ਅਤੇ ਲਚਕ ਵਿੱਚ ਸੀਮਿਤ। MCP ਵਿਵਰਣ 2025-06-18 ਅਨੁਸਾਰ, ਸਵਤੰਤਰ SSE ਟ੍ਰਾਂਸਪੋਰਟ ਨੂੰ ਡੀਪ੍ਰੀਕੇਟ ਕਰਕੇ "ਸਟ੍ਰੀਮਿੰਗ HTTP" ਨਾਲ ਬਦਲ ਦਿੱਤਾ ਗਿਆ ਹੈ।
- **ਸਟ੍ਰੀਮਿੰਗ HTTP**: ਆਧੁਨਿਕ HTTP ਅਧਾਰਿਤ ਸਟ੍ਰੀਮਿੰਗ ਟ੍ਰਾਂਸਪੋਰਟ, ਸੂਚਨਾਵਾਂ ਅਤੇ ਵਧੀਆ ਸਕੇਲਬਿਲਟੀ ਨੂੰ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। ਜ਼ਿਆਦਾਤਰ ਉਤਪਾਦਨ ਅਤੇ ਕਲਾਉਡ ਸਥਿਤੀਆਂ ਲਈ ਸਿਫਾਰਸ਼ੀ ਹੈ।

### ਤੁਲਨਾਤਮਕ ਸਾਰਣੀ

ਹੇਠਾਂ ਦਿੱਤੀ ਸਾਰਣੀ ਵਿੱਚ ਇਨ੍ਹਾਂ ਟ੍ਰਾਂਸਪੋਰਟ ਮੈਕੈਨਿਜ਼ਮਾਂ ਵਿੱਚ ਵੱਖ-ਵੱਖੀ ਨੂੰ ਸਮਝਣ ਲਈ ਦੇਖੋ:

| ਟ੍ਰਾਂਸਪੋਰਟ          | ਤੁਰੰਤ ਅਪਡੇਟ   | ਸਟ੍ਰੀਮਿੰਗ  | ਸਕੇਲਾ ਬਿਲਟੀ   | ਵਰਤੋਂ ਦਾ ਕੇਸ            |
|---------------------|----------------|------------|--------------|-------------------------|
| stdio               | ਨਹੀਂ           | ਨਹੀਂ       | ਘੱਟ          | ਸਥਾਨਕ CLI ਟੂਲ           |
| SSE                 | ਹਾਂ            | ਹਾਂ        | ਦਰਮਿਆਨਾ    | ਵੈੱਬ, ਤੁਰੰਤ ਅਪਡੇਟਸ       |
| ਸਟ੍ਰੀਮਿੰਗ HTTP       | ਹਾਂ            | ਹਾਂ        | ਵਧੀਆ        | ਕਲਾਉਡ, ਬਹੁ-ਕਲਾਇੰਟ       |

> **ਸੁਝਾਅ:** ਸਹੀ ਟ੍ਰਾਂਸਪੋਰਟ ਚੁਣਨਾ ਕੰਮਗੁਜ਼ਾਰੀ, ਸਕੇਲਾ ਬਿਲਟੀ ਅਤੇ ਉਪਭੋਗਤਾ ਅਨੁਭਵ ’ਤੇ ਅਸਰ ਪਾਉਂਦਾ ਹੈ। ਆਧੁਨਿਕ, ਸਕੇਲਹੋਣਯੋਗ, ਅਤੇ ਕਲਾਉਡ-ਤਿਆਰ ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ **ਸਟ੍ਰੀਮਿੰਗ HTTP** ਸਿਫਾਰਸ਼ੀ ਹੈ।

ਦਿਆਨ ਦਿਓ ਕਿ stdio ਅਤੇ SSE ਟ੍ਰਾਂਸਪੋਰਟ ਜਿਸਨੂੰ ਤੁਸੀਂ ਪਿਛਲੇ ਅਧਿਆਇਆਂ ਵਿੱਚ ਵੇਖਿਆ ਸੀ ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ HTTP ਇਸ ਅਧਿਆਇ ਵਿੱਚ ਕਵਰ ਕੀਤਾ ਗਿਆ ਟ੍ਰਾਂਸਪੋਰਟ ਹੈ।

## ਸਟ੍ਰੀਮਿੰਗ: ਧਾਰਾਏਂ ਅਤੇ ਪ੍ਰੇਰਣਾ

ਸਟ੍ਰੀਮਿੰਗ ਦੇ ਮੁੱਖ ਧਾਰਣਾਂ ਅਤੇ ਪ੍ਰੇਰਣਾਵਾਂ ਨੂੰ ਸਮਝਣਾ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਤੁਰੰਤ ਸੰਚਾਰ ਪ੍ਰਣਾਲੀਆਂ ਲਾਗੂ ਕਰਨ ਲਈ ਜ਼ਰੂਰੀ ਹੈ।

**ਸਟ੍ਰੀਮਿੰਗ** ਇੱਕ ਨੈੱਟਵਰਕ ਪ੍ਰੋਗ੍ਰਾਮਿੰਗ ਤਕਨੀਕ ਹੈ ਜੋ ਡਾਟਾ ਨੂੰ ਛੋਟੇ, ਸੰਭਾਲਣਯੋਗ ਹਿੱਸਿਆਂ ਜਾਂ ਘਟਨਾਵਾਂ ਦੇ ਸਤਰ ਵੱਜੋਂ ਭੇਜਣ ਅਤੇ ਪ੍ਰਾਪਤ ਕਰਨ ਦੀ ਆਗਿਆ ਦਿੰਦੀ ਹੈ, ਬਿਨਾਂ ਪੂਰੇ ਜਵਾਬ ਦੇ ਤਿਆਰ ਹੋਣ ਦੀ ਉਡੀਕ ਕੀਤੇ। ਇਹ ਖਾਸ ਕਰਕੇ ਲਈ ਉਪਯੋਗੀ ਹੈ:

- ਵੱਡੀਆਂ ਫਾਈਲਾਂ ਜਾਂ ਡਾਟਾ ਸੈੱਟ्स ਲਈ।
- ਤੁਰੰਤ ਅਪਡੇਟਸ (ਉਦਾਹਰਨ ਵਜੋਂ ਚੈਟ, ਪ੍ਰਗਟੀ ਬਾਰ) ਲਈ।
- ਲੰਬੇ ਸਮੇਂ ਚੱਲਣ ਵਾਲੇ ਗਣਨਾਵਾਂ ਜਿੱਥੇ ਤੁਸੀਂ ਯੂਜ਼ਰ ਨੂੰ ਸੂਚਿਤ ਰੱਖਣਾ ਚਾਹੁੰਦੇ ਹੋ।

ਹੇਠਾਂ ਸਟ੍ਰੀਮਿੰਗ ਬਾਰੇ ਕੁਝ ਉੱਚ ਦਰਜੇ ਦੀਆਂ ਜ਼ਰੂਰੀ ਗੱਲਾਂ ਦਿੱਤੀਆਂ ਗਈਆਂ ਹਨ:

- ਡਾਟਾ ਹੌਲੀ-ਹੌਲੀ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ, ਸਾਰਾ ਇਕੱਠਾ ਨਹੀਂ।
- ਕਲਾਇੰਟ ਆਉਣ ਵਾਲੇ ਡਾਟੇ ਨੂੰ ਤੁਰੰਤ ਪ੍ਰਕਿਰਿਆ ਕਰ ਸਕਦਾ ਹੈ।
- ਇਸ ਨਾਲ ਲੱਗਣ ਵਾਲਾ ਸਮਾਂ ਘਟਦਾ ਹੈ ਅਤੇ ਉਪਭੋਗਤਾ ਅਨੁਭਵ ਸੁਧਰਦਾ ਹੈ।

### ਸਟ੍ਰੀਮਿੰਗ ਕਿਉਂ ਵਰਤਣਾ?

ਸਟ੍ਰੀਮਿੰਗ ਵਰਤਣ ਦੇ ਕਾਰਣ ਹੇਠਾਂ ਦਿੱਤੇ ਗਏ ਹਨ:

- ਯੂਜ਼ਰ ਤੁਰੰਤ ਪ੍ਰਤਿਕਿਰਿਆ ਮਿਲਦੀ ਹੈ, ਸਿਰਫ ਅੰਤ ਵਿੱਚ ਨਹੀਂ
- ਤੁਰੰਤ ਐਪਲੀਕੇਸ਼ਨਾਂ ਅਤੇ ਜਵਾਬਦੇਹ UI ਯੋਗ ਬਣਾਉਂਦਾ ਹੈ
- ਨੈੱਟਵਰਕ ਅਤੇ ਕਮਪਿਊਟ ਸਰੋਤਾਂ ਦੀ ਕਾਰਗਰ ਵਰਤੋਂ

### ਸਧਾਰਣ ਉਦਾਹਰਨ: HTTP ਸਟ੍ਰੀਮਿੰਗ ਸਰਵਰ ਅਤੇ ਕਲਾਇੰਟ

ਹੇਠਾਂ ਇੱਕ ਸਧਾਰਣ ਉਦਾਹਰਨ ਦਿੱਤੀ ਗਈ ਹੈ ਕਿ ਕਿਵੇਂ ਸਟ੍ਰੀਮਿੰਗ ਲਾਗੂ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ:

#### ਪਾਈਥਨ

**ਸਰਵਰ (ਪਾਈਥਨ, FastAPI ਅਤੇ StreamingResponse ਦੀ ਵਰਤੋਂ):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**ਕਲਾਇੰਟ (ਪਾਈਥਨ, requests ਦੀ ਵਰਤੋਂ):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

ਇਹ ਉਦਾਹਰਨ ਦਿਖਾਉਂਦੀ ਹੈ ਕਿ ਸਰਵਰ ਕਿਵੇਂ ਕਲਾਇੰਟ ਨੂੰ ਲਗਾਤਾਰ ਸੁਨੇਹੇ ਭੇਜਦਾ ਹੈ ਜਿਵੇਂ ਉਹ ਉਪਲਬਧ ਹੁੰਦੇ ਹਨ, ਸਾਰੇ ਸੁਨੇਹਿਆਂ ਦੇ ਤੈਅ ਹੋਣ ਦੀ ਉਡੀਕ ਕਰਨ ਦੀ ਥਾਂ।

**ਇਸ ਦਾ ਕੰਮ ਕਰਨ ਦਾ ਤਰੀਕਾ:**

- ਸਰਵਰ ਹਰ ਸੁਨੇਹਾ ਜਿਵੇਂ ਜਿਵੇਂ ਉਹ ਤਿਆਰ ਹੁੰਦਾ ਹੈ, ਭੇਜਦਾ ਹੈ।
- ਕਲਾਇੰਟ ਹਰ ਹਿੱਸਾ ਮੁੜ ਮੁੜ ਪ੍ਰਾਪਤ ਕਰਦਾ ਅਤੇ ਛਾਪਦਾ ਹੈ।

**ਲੋੜੀਂਦੇ ਤੱਤ:**

- ਸਰਵਰ ਨੂੰ ਸਟ੍ਰੀਮਿੰਗ ਜਵਾਬ ਦੀ ਵਰਤੋਂ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ (ਜਿਵੇਂ FastAPI ਵਿੱਚ `StreamingResponse`)।
- ਕਲਾਇੰਟ ਨੂੰ ਜਵਾਬ ਨੂੰ ਸਟ੍ਰੀਮ ਵੱਜੋਂ ਪ੍ਰਕਿਰਿਆ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ (`stream=True` requests ਵਿੱਚ)।
- ਸਮੱਗਰੀ-ਕਸਰਤ ਅਕਸਰ `text/event-stream` ਜਾਂ `application/octet-stream` ਹੁੰਦੀ ਹੈ।

#### ਜਾਵਾ

**ਸਰਵਰ (ਜਾਵਾ, Spring Boot ਅਤੇ Server-Sent Events ਦੀ ਵਰਤੋਂ):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**ਕਲਾਇੰਟ (ਜਾਵਾ, Spring WebFlux WebClient ਦੀ ਵਰਤੋਂ):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**ਜਾਵਾ ਲਾਗੂ ਕਰਨ ਦੇ ਨੋਟ:**

- ਸਟ੍ਰੀਮਿੰਗ ਲਈ Spring Boot ਦੇ reactive stack ਵਿੱਚ `Flux` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ
- `ServerSentEvent` ਘਟਨਾ ਤਰ੍ਹਾਂ ਸਟ੍ਰੀਮਿੰਗ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ
- `WebClient` `bodyToFlux()` ਨਾਲ reactive ਸਟ੍ਰੀਮ ਖਪਤ ਯੋਗ ਬਣਾਉਂਦਾ ਹੈ
- `delayElements()` ਘਟਨਾਵਾਂ ਵਿਚਕਾਰ ਪ੍ਰਕਿਰਿਆ ਸਮਾਂ ਦਾ ਅਨੁਕਰਨ ਕਰਦਾ ਹੈ
- ਘਟਨਾਵਾਂ ਦੇ ਕਿਸਮਾਂ (`info`, `result`) ਹੋ ਸਕਦੀਆਂ ਹਨ ਜਿਨ੍ਹਾਂ ਦਾ ਵਧੀਆ ਕਲਾਇੰਟ ਸੰਭਾਲਣ ਲਈ ਵਰਤੋਂ ਹੁੰਦੀ ਹੈ

### ਤੁਲਨਾ: ਪਰੰਪਰਾਗਤ ਸਟ੍ਰੀਮਿੰਗ ਬਨਾਮ MCP ਸਟ੍ਰੀਮਿੰਗ

ਸਪੱਸ਼ਟ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ ਕਿ ਸਟ੍ਰੀਮਿੰਗ ਕਿਵੇਂ "ਪਰੰਪਰਾਗਤ" ਤਰੀਕੇ ਨਾਲ ਕੰਮ ਕਰਦੀ ਹੈ ਅਤੇ MCP ਵਿੱਚ ਕਿਵੇਂ:

| ਵਿਸ਼ੇਸ਼ਤਾ            | ਪਰੰਪਰਾਗਤ HTTP ਸਟ੍ਰੀਮਿੰਗ    | MCP ਸਟ੍ਰੀਮਿੰਗ (ਸੂਚਨਾਵਾਂ)         |
|----------------------|------------------------------|----------------------------------|
| ਮੂਲ ਜਵਾਬ           | ਟੁਕੜਿਆਂ ਵਿੱਚ                | ਇਕੱਲਾ, ਅੰਤ ਵਿੱਚ                  |
| ਪ੍ਰਗਟ ਪੇਸ਼ਕਸ਼          | ਡਾਟਾ ਟੁਕੜਿਆਂ ਵਜੋਂ ਭੇਜਿਆ      | ਸੂਚਨਾਵਾਂ ਵਜੋਂ ਭੇਜਿਆ            |
| ਕਲਾਇੰਟ ਲੋੜਾਂ         | ਸਟ੍ਰੀਮ ਨੂੰ ਪ੍ਰਕਿਰਿਆ ਕਰਨਾ ਜ਼ਰੂਰੀ| ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰਨਾ ਜ਼ਰੂਰੀ |
| ਵਰਤੋਂ ਦਾ ਕੇਸ         | ਵੱਡੀਆਂ ਫਾਈਲਾਂ, AI ਟੋਕਨ ਸਟ੍ਰੀਮ | ਪ੍ਰਗਟ, ਲੌਗ, ਤੁਰੰਤ ਪ੍ਰਤਿਕਿਰਿਆ     |

### ਮਹੱਤਵਪੂਰਨ ਫਰਕ

ਨਾਲ ਹੀ ਕੁਝ ਮੁੱਖ ਫਰਕ ਹਨ:

- **ਕਮਿਊਨੀਕੇਸ਼ਨ ਪੈਟਰਨ:**
  - ਪਰੰਪਰਾਗਤ HTTP ਸਟ੍ਰੀਮਿੰਗ: ਸਧਾਰਣ ਟੁਕੜਿਆਂ ਵਾਲਾ ਟਰਾਂਸਫਰ ਏਨਕੋਡਿੰਗ ਵਰਤਦਾ ਹੈ
  - MCP ਸਟ੍ਰੀਮਿੰਗ: JSON-RPC ਪ੍ਰੋਟੋਕੋਲ ਨਾਲ ਸੰਰਚਿਤ ਸੂਚਨਾ ਪ੍ਰਣਾਲੀ ਵਰਤੀ ਜਾਂਦੀ ਹੈ

- **ਸੁਨੇਹਾ ਫਾਰਮੈਟ:**
  - ਪਰੰਪਰਾਗਤ HTTP: ਨਵੀਂ ਲਾਈਨਾਂ ਵਾਲੇ ਸਧਾਰਣ ਟੈਕਸਟ ਟੁਕੜੇ
  - MCP: ਮੈਟਾਡੇਟਾ ਸਮੇਤ ਸੰਰਚਿਤ LoggingMessageNotification ਓਬਜੈਕਟ

- **ਕਲਾਇੰਟ ਲਾਗੂ ਕਰਨ:**
  - ਪਰੰਪਰਾਗਤ HTTP: ਸਧਾਰਣ ਕਲਾਇੰਟ ਜੋ ਸਟ੍ਰੀਮਿੰਗ ਜਵਾਬ ਨੂੰ ਪ੍ਰਕਿਰਿਆ ਕਰਦਾ ਹੈ
  - MCP: ਹੋਰ ਵਧੀਆ ਕਲਾਇੰਟ ਜਿਸ ਵਿੱਚ ਮਿਲਦੇ-ਜੁਲਦੇ ਕਿਸਮਾਂ ਦੇ ਸੁਨੇਹਿਆਂ ਲਈ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਹੈ

- **ਪ੍ਰਗਟ ਅਪਡੇਟਸ:**
  - ਪਰੰਪਰਾਗਤ HTTP: ਪ੍ਰਗਟ ਮੂਲ ਜਵਾਬ ਸਟ੍ਰੀਮ ਦਾ ਹਿੱਸਾ ਹੁੰਦਾ ਹੈ
  - MCP: ਪ੍ਰਗਟ ਕੱਟ-ਕੱਟ ਸੂਚਨਾ ਸੁਨੇਹਿਆਂ ਰਾਹੀਂ ਭੇਜੇ ਜਾਂਦੇ ਹਨ ਜਦਕਿ ਮੂਲ ਜਵਾਬ ਅੰਤ ਵਿੱਚ ਆਉਂਦਾ ਹੈ

### ਸਿਫਾਰਿਸ਼ਾਂ

ਪਰੰਪਰਾਗਤ ਸਟ੍ਰੀਮਿੰਗ (ਜਿਵੇਂ ਕਿ ਅਸੀਂ `/stream` ਬਿੰਦੂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਦਿਖਾਇਆ) ਅਤੇ MCP ਸਟ੍ਰੀਮਿੰਗ ਬੀਚ ਚੋਣ ਕਰਨ ਲਈ ਕੁਝ ਸਲਾਹਾਂ ਦਿੱਤੀਆਂ ਜਾ ਰਹੀਆਂ ਹਨ।

- **ਸਧਾਰਣ ਸਟ੍ਰੀਮਿੰਗ ਲੋੜਾਂ ਲਈ:** ਪਰੰਪਰਾਗਤ HTTP ਸਟ੍ਰੀਮਿੰਗ ਸਪੱਸ਼ਟ ਅਤੇ ਬੁਨਿਆਦੀ ਲੋੜਾਂ ਲਈ ਕਾਫ਼ੀ ਹੈ।

- **ਕੰਪਲੇਕਸ, ਇੰਟਰੇਕਟਿਵ ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ:** MCP ਸਟ੍ਰੀਮਿੰਗ ਵਿਸ਼ਤ੍ਰਿਤ ਮੈਟਾਡੇਟਾ ਅਤੇ ਸੂਚਨਾਵਾਂ ਅਤੇ ਅੰਤਿਮ ਨਤੀਜਿਆਂ ਵਿੱਚ ਵੱਖਰਾ ਅਪਰੋਕਸ਼ੇਤਾ ਦਿੰਦਾ ਹੈ।

- **AI ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ:** MCP ਦੀ ਸੂਚਨਾ ਪ੍ਰਣਾਲੀ ਲੰਬੇ ਸਮੇਂ ਚੱਲਣ ਵਾਲੀਆਂ AI ਕਾਰਵਾਈਆਂ ਵਿੱਚ ਜੋ ਪ੍ਰਗਟ ਨੂੰ ਅੱਪਡੇਟ ਕਰਦੀ ਹੈ ਖਾਸ ਕਰਕੇ ਲਾਭਦਾਇਕ ਹੈ।

## MCP ਵਿੱਚ ਸਟ੍ਰੀਮਿੰਗ

ਤਦ ਤੱਕ ਤੁਸੀਂ ਪਰੰਪਰਾਗਤ ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ MCP ਸਟ੍ਰੀਮਿੰਗ ਬੀਚ ਕੁਝ ਸਿਫਾਰਸ਼ਾਂ ਅਤੇ ਤੁਲਨਾਵਾਂ ਵੇਖ ਚੁੱਕੇ ਹੋ। ਹੁਣ ਅਸੀਂ ਵੇਖਾਂਗੇ ਕਿ ਤੁਸੀਂ MCP ਵਿੱਚ ਸਟ੍ਰੀਮਿੰਗ ਨੂੰ ਕਿਵੇਂ ਲਾਗੂ ਕਰ ਸਕਦੇ ਹੋ।

MCP ਫ੍ਰੇਮਵਰਕ ਅੰਦਰ ਸਟ੍ਰੀਮਿੰਗ ਕਿਵੇਂ ਕੰਮ ਕਰਦੀ ਹੈ ਇਹ ਜਾਣਨਾ ਜ਼ਰੂਰੀ ਹੈ ਤਾਂ ਜੋ ਤੁਸੀਂ ਲੰਬੇ ਸਮੇਂ ਚੱਲਣ ਵਾਲੇ ਕਾਰਜ ਦੌਰਾਨ ਯੂਜ਼ਰ ਨੂੰ ਤੁਰੰਤ ਪ੍ਰਤਿਕਿਰਿਆ ਦੇਣ ਵਾਲੀਆਂ ਐਪਲੀਕੇਸ਼ਨਾਂ ਤਿਆਰ ਕਰ ਸਕੋ।

MCP ਵਿੱਚ, ਸਟ੍ਰੀਮਿੰਗ ਮੂਲ ਜਵਾਬ ਨੂੰ ਟੁਕੜਿਆਂ ਵਿੱਚ ਭੇਜਣ ਬਾਰੇ ਨਹੀਂ ਹੈ, ਬਲਕਿ ਕਲਾਇੰਟ ਨੂੰ ਸੂਚਨਾਵਾਂ ਭੇਜਣ ਬਾਰੇ ਹੈ ਜਦੋਂ ਟੂਲ ਬੇਨਤੀ ਨੂੰ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਲੈਂਦਾ ਹੈ। ਇਹ ਸੂਚਨਾਵਾਂ ਪ੍ਰਗਟੀ ਅਪਡੇਟਸ, ਲੌਗ ਜਾਂ ਹੋਰ ਘਟਨਾਵਾਂ ਹੋ ਸਕਦੀਆਂ ਹਨ।

### ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

ਮੁੱਖ ਨਤੀਜਾ ਹੁਣ ਵੀ ਇੱਕ ਜਵਾਬ ਵੱਜੋਂ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ। ਪਰ ਸੂਚਨਾਵਾਂ ਪ੍ਰਕਿਰਿਆ ਦੌਰਾਨ ਵੱਖ-ਵੱਖ ਸੁਨੇਹਿਆਂ ਵਜੋਂ ਭੇਜੀਆਂ ਜਾ ਸਕਦੀਆਂ ਹਨ ਅਤੇ ਇਸ ਤਰ੍ਹਾਂ ਕਲਾਇੰਟ ਨੂੰ ਤੁਰੰਤ ਅਪਡੇਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਕਲਾਇੰਟ ਨੂੰ ਇਹ ਸੂਚਨਾਵਾਂ ਸੰਭਾਲਣ ਅਤੇ ਦਿਖਾਉਣ ਵਿੱਚ ਸਮਰੱਥ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ।

## ਸੂਚਨਾ ਕੀ ਹੈ?

ਅਸੀਂ "ਸੂਚਨਾ" ਬਾਰੇ ਗੱਲ ਕੀਤੀ, MCP ਦੇ ਸੰਦਰਭ ਵਿੱਚ ਇਸਦਾ ਕੀ ਮਤਲਬ ਹੈ?

ਇੱਕ ਸੂਚਨਾ ਸਰਵਰ ਵਲੋਂ ਕਲਾਇੰਟ ਨੂੰ ਭੇਜਿਆ ਗਿਆ ਸੁਨੇਹਾ ਹੁੰਦਾ ਹੈ, ਜੋ ਲੰਬੇ ਸਮੇਂ ਚੱਲ ਰਹੀ ਕਾਰਵਾਈ ਦੌਰਾਨ ਪ੍ਰਗਟ, ਸਥਿਤੀ ਜਾਂ ਹੋਰ ਘਟਨਾਵਾਂ ਬਾਰੇ ਜਾਣੂ ਕਰਾਉਂਦਾ ਹੈ। ਸੂਚਨਾਵਾਂ ਪਾਰਦਰਸ਼ਤਾ ਅਤੇ ਉਪਭੋਗਤਾ ਅਨੁਭਵ ਵਿੱਚ ਸੁਧਾਰ ਲਿਆਉਂਦੀਆਂ ਹਨ।

ਉਦਾਹਰਨ ਵਜੋਂ, ਇੱਕ ਕਲਾਇੰਟ ਨੂੰ ਸਰਵਰ ਨਾਲ ਮੁਲਾਕਾਤ ਸੰਬੰਧੀ ਸੂਚਨਾ ਭੇਜਣੀ ਚਾਹੀਦੀ ਹੈ ਜਦੋਂ ਪਹਿਲਾ ਹੈਂਡਸ਼ੇਕ ਹੋ ਜਾਵੇ।

ਇੱਕ ਸੂਚਨਾ ਇਹ ਤਰ੍ਹਾਂ JSON ਸੁਨੇਹੇ ਵਜੋਂ ਦਿਖਾਈ ਦੇ ਸਕਦੀ ਹੈ:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

ਸੂਚਨਾਵਾਂ MCP ਵਿੱਚ ["ਲੌਗਿੰਗ"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) ਨਾਮਕ ਵਿਸ਼ੇ ਨਾਲ ਸੰਬੰਧਿਤ ਹੁੰਦੀਆਂ ਹਨ।

> **ਡੀਪ੍ਰੀਕੇਸ਼ਨ ਨੋਟਿਸ:** MCP ਵਿਵਰਣ 2026-07-28 ਰਿਲੀਜ਼ ਉਮੀਦਵਾਰ ਵਿੱਚ ਲੌਗਿੰਗ primitive ਨੂੰ `stderr` ਲਈ stdio ਟ੍ਰਾਂਸਪੋਰਟ ਅਤੇ ਢਾਂਚਾਵੰਦ ਅਬਜ਼ਰਵੇਬਿਲਿਟੀ ਲਈ OpenTelemetry ਵਿੱਚ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਬਦਲਾਅ ਦਿੱਤਾ ਗਿਆ ਹੈ। ਲੌਗਿੰਗ 2025-11-25 ਵਿੱਚ ਅਤੇ ਕਿਸੇ ਵੀ ਅਧਿਕਾਰਿਤ ਡੀਪ੍ਰੀਕੇਸ਼ਨ ਦੇ ਬਾਅਦ ਘੱਟੋ ਘੱਟ ਇੱਕ ਸਾਲ ਤਕ ਕੰਮ ਕਰਦੀ ਰਹੇਗੀ। ਵੇਰਵੇ ਲਈ [MCP ਵਿੱਚ ਕੀ ਬਦਲ ਰਿਹਾ ਹੈ: 2026-07-28 ਰਿਲੀਜ਼ ਉਮੀਦਵਾਰ](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md) ਵੇਖੋ।

ਲੌਗਿੰਗ ਚਲਾਉਣ ਲਈ ਸਰਵਰ ਨੂੰ ਇਸਨੂੰ ਇਕ ਫੀਚਰ/ਸਮਰੱਥਾ ਵਜੋਂ ਯੋਗ ਕਰਨਾ ਪੈਂਦਾ ਹੈ, ਇਸ ਤਰ੍ਹਾਂ:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> ਜਿਹੜਾ SDK ਤੁਸੀਂ ਵਰਤਦੇ ਹੋ, ਉਸ ਦੇ ਅਨੁਸਾਰ ਲੌਗਿੰਗ ਸਦਾਚਾਰਤ ਤੌਰ ਤੇ ਯੋਗ ਹੋ ਸਕਦੀ ਹੈ, ਜਾਂ ਤੁਹਾਨੂੰ ਆਪਣੇ ਸਰਵਰ ਸੰਰਚਨਾ ਵਿੱਚ ਇਸਨੂੰ ਅੱਪਣਾਉਣਾ ਪੈ ਸਕਦਾ ਹੈ।

ਸੂਚਨਾਵਾਂ ਦੇ ਵੱਖ-ਵੱਖ ਕਿਸਮਾਂ ਹਨ:

| ਪੱਧਰ      | ਵਿਆਖਿਆ                       | ਉਦਾਹਰਨ ਵਰਤੋਂ ਦਾ ਕੇਸ           |
|-----------|-------------------------------|---------------------------------|
| ਡੀਬੱਗ     | ਵਿਸਥਾਰਪੂਰਕ ਡੀਬੱਗ ਜਾਣਕਾਰੀ    | ਫੰਕਸ਼ਨ ਦੇ ਜਾਂਚ ਅਤੇ ਬਾਹਰ ਜਾਣੇ ਦੇ ਬਿੰਦੂ |
| ਜਾਣਕਾਰੀ   | ਆਮ ਜਾਣਕਾਰੀ ਵਾਲੇ ਸੁਨੇਹੇ        | ਕਾਰਵਾਈ ਦੀ ਪ੍ਰਗਟ ਅਪਡੇਟਸ          |
| ਸੂਚਨਾ    | ਆਮ ਪਰ ਮਹੱਤਵਪੂਰਨ ਘਟਨਾਵਾਂ     | ਸੰਰਚਨਾ ਵਿੱਚ ਤਬਦੀਲੀਆਂ          |
| ਚੇਤਾਵਨੀ    | ਚੇਤਾਵਨੀ ਸਥਿਤੀਆਂ             | ਮਿੱਟੀ ਹੋ ਚੁਕੀ ਫੀਚਰ ਵਰਤੋਂ        |
| ਗਲਤੀ      | ਗਲਤੀ ਸਥਿਤੀਆਂ                | ਕਾਰਵਾਈ ਦੇ ਅਸਫਲ ਹੋਣ             |
| ਗੰਭੀਰ     | ਗੰਭੀਰ ਸਥਿਤੀਆਂ              | ਸਿਸਟਮ ਭਾਗਾਂ ਦੀ ਨਾਕਾਮੀ          |
| ਚਿਤਾਵਨੀ    | ਜਲਦੀ ਕਾਰਵਾਈ ਲੋੜੀਂਦੀ          | ਡਾਟਾ ਖਰਾਬੀ ਦਾ ਪਤਾ ਲੱਗਣਾ        |
| ਸੰਗੀਨ     | ਸਿਸਟਮ ਅਣਪਹਿਲੂਦੀ                    | ਪੂਰਾ ਸਿਸਟਮ ਫੇਲ                |

## MCP ਵਿੱਚ ਸੂਚਨਾਵਾਂ ਲਾਗੂ ਕਰਨਾ

MCP ਵਿੱਚ ਸੂਚਨਾਵਾਂ ਲਾਗੂ ਕਰਨ ਲਈ ਤੁਹਾਨੂੰ ਸਰਵਰ ਅਤੇ ਕਲਾਇੰਟ ਦੋਹਾਂ ਪਾਸਿਆਂ ਨੂੰ ਤੁਰੰਤ ਅਪਡੇਟਸ ਨੂੰ ਸੰਭਾਲਣ ਲਈ ਤਿਆਰ ਕਰਨਾ ਪੈਂਦਾ ਹੈ। ਇਹ ਤੁਹਾਡੀ ਐਪਲੀਕੇਸ਼ਨ ਨੂੰ ਲੰਬੇ ਸਮੇਂ ਚੱਲ ਰਹੇ ਕਾਰਜ ਦੌਰਾਨ ਯੂਜ਼ਰਾਂ ਨੂੰ ਤੁਰੰਤ ਪ੍ਰਤਿਕਿਰਿਆ ਦੇਣ ਦੀ ਆਗਿਆ ਦਿੰਦਾ ਹੈ।

### ਸਰਵਰ-ਪਾਸਾ: ਸੂਚਨਾਵਾਂ ਭੇਜਣਾ

ਚਲੋ ਸਰਵਰ ਪਾਸੇ ਤੋਂ ਸ਼ੁਰੂ ਕਰੀਏ। MCP ਵਿੱਚ ਤੁਸੀਂ ਉਹ ਟੂਲ ਪਰਿਭਾਸ਼ਿਤ ਕਰਦੇ ਹੋ ਜੋ ਬੇਨਤੀਆਂ ਦੀ ਪ੍ਰਕਿਰਿਆ ਦੌਰਾਨ ਸੂਚਨਾਵਾਂ ਭੇਜ ਸਕਦੇ ਹਨ। ਸਰਵਰ ਸੰਦੇਸ਼ ਭੇਜਣ ਲਈ ਸੰਦਰਭ ਵਸਤੂ (ਆਮ ਤੌਰ ਤੇ `ctx`) ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

#### ਪਾਈਥਨ

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

ਪੂਰਵ ਦਿੱਤੀ ਉਦਾਹਰਨ ਵਿੱਚ, `process_files` ਟੂਲ ਹਰ ਫਾਈਲ ਦੀ ਪ੍ਰਕਿਰਿਆ ਦੌਰਾਨ ਕਲਾਇੰਟ ਨੂੰ ਤਿੰਨ ਸੂਚਨਾਵਾਂ ਭੇਜਦਾ ਹੈ। ਜਾਣਕਾਰੀ ਸੁਨੇਹੇ ਭੇਜਣ ਲਈ `ctx.info()` ਤਰੀਕਾ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ।

ਇਲਾਵਾ, ਸੂਚਨਾਵਾਂ ਚਾਲੂ ਕਰਨ ਲਈ ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਤੁਹਾਡਾ ਸਰਵਰ ਸਟ੍ਰੀਮਿੰਗ ਟ੍ਰਾਂਸਪੋਰਟ (ਜਿਵੇਂ ਕਿ `streamable-http`) ਵਰਤ ਰਿਹਾ ਹੈ ਅਤੇ ਤੁਹਾਡਾ ਕਲਾਇੰਟ ਸੂਚਨਾ ਪ੍ਰਕਿਰਿਆ ਲਈ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰਦਾ ਹੈ। ਸਰਵਰ ਵਿੱਚ `streamable-http` ਟ੍ਰਾਂਸਪੋਰਟ ਵਰਤਣ ਲਈ ਇਹ ਤਰੀਕਾ ਹੈ:

```python
mcp.run(transport="streamable-http")
```

#### .NET

.NET MCP ਸਰਵਰ ਵਿੱਚ ਸੂਚਨਾਵਾਂ ਯੋਗ ਕਰਨ ਲਈ, ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਤੁਸੀਂ ਸਟ੍ਰੀਮਿੰਗ ਟ੍ਰਾਂਸਪੋਰਟ ਵਰਤ ਰਹੇ ਹੋ:

```csharp

await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### ਕਲਾਇੰਟ-ਪਾਸਾ: ਸੂਚਨਾਵਾਂ ਪ੍ਰਾਪਤ ਕਰਨਾ

ਕਲਾਇੰਟ ਨੂੰ ਸੂਚਨਾਵਾਂ ਨੂੰ ਪ੍ਰਕਿਰਿਆ ਕਰਨ ਅਤੇ ਦਰਸਾਉਣ ਲਈ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰਨਾ ਜ਼ਰੂਰੀ ਹੈ।

#### ਪਾਈਥਨ

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

ਉਪਰ ਦਿੱਤੇ ਕੋਡ ਵਿੱਚ, `message_handler` ਫੰਕਸ਼ਨ ਜਾਂਚਦਾ ਹੈ ਕਿ ਆਉਂਦਾ ਸੁਨੇਹਾ ਸੂਚਨਾ ਹੈ ਜਾਂ ਨਹੀਂ। ਜੇ ਹੈ, ਤਾਂ ਇਹ ਸੂਚਨਾ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ; ਨਹੀਂ ਤਾਂ ਇਹ ਇੱਕ ਆਮ ਸਰਵਰ ਸੁਨੇਹੇ ਵਾਂਗ ਪ੍ਰਕਿਰਿਆ ਕਰਦਾ ਹੈ। ਇਸ ਦੇ ਨਾਲ `ClientSession` ਨੂੰ `message_handler` ਨਾਲ ਇਨਿਸ਼ੀਅਲਾਈਜ਼ ਕੀਤਾ ਗਿਆ ਹੈ ਤਾਂ ਜੋ ਆ ਰਹੀਆਂ ਸੂਚਨਾਵਾਂ ਨੂੰ ਸੰਭਾਲਿਆ ਜਾ ਸਕੇ।

#### .NET

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

ਇਸ .NET ਉਦਾਹਰਨ ਵਿੱਚ, `MessageHandler` ਫੰਕਸ਼ਨ ਜਾਂਚਦਾ ਹੈ ਕਿ ਆਉਂਦਾ ਸੁਨੇਹਾ ਸੂਚਨਾ ਹੈ ਜਾਂ ਨਹੀਂ। ਜੇ ਹੈ, ਤਾਂ ਇਹ ਸੂਚਨਾ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ; ਨਹੀਂ ਤਾਂ ਇਹ ਇੱਕ ਆਮ ਸਰਵਰ ਸੁਨੇਹੇ ਵਾਂਗ ਪ੍ਰਕਿਰਿਆ ਕਰਦਾ ਹੈ। `ClientSession` ਨੂੰ message handler ਦੇ ਨਾਲ `ClientSessionOptions` ਰਾਹੀਂ ਇਨਿਸ਼ੀਅਲਾਈਜ਼ ਕੀਤਾ ਗਿਆ ਹੈ।

ਸੂਚਨਾਵਾਂ ਯੋਗ ਕਰਨ ਲਈ ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਇਹੋ ਸਰਵਰ ਸਟ੍ਰੀਮਿੰਗ ਟ੍ਰਾਂਸਪੋਰਟ (ਜਿਵੇਂ `streamable-http`) ਵਰਤ ਰਿਹਾ ਹੈ ਅਤੇ ਕਲਾਇੰਟ ਸੂਚਨਾ ਪ੍ਰਕਿਰਿਆ ਲਈ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰਦਾ ਹੈ।

## ਪ੍ਰਗਟੀ ਸੂਚਨਾਵਾਂ ਅਤੇ ਪਰੀਖਣ

ਇਹ ਭਾਗ MCP ਵਿੱਚ ਪ੍ਰਗਟ ਸੂਚਨਾਵਾਂ ਦੀ ਪਰਿਭਾਸ਼ਾ, ਉਸਦਾ ਮਹੱਤਵ ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ HTTP ਦੀ ਵਰਤੋਂ ਨਾਲ ਲਾਗੂ ਕਰਨ ਦਾ ਤਰੀਕਾ ਸਮਝਾਉਂਦਾ ਹੈ। ਨਾਲ ਹੀ ਇੱਕ ਵਿਹਾਰਿਕ ਅਸਾਈਨਮੈਂਟ ਵੀ ਦਿੱਤੀ ਗਈ ਹੈ ਤਾਂ ਜੋ ਤੁਸੀਂ ਆਪਣੇ ਗਿਆਨ ਨੂੰ ਮਜ਼ਬੂਤ ਕਰ ਸਕੋ।

ਪ੍ਰਗਟ ਸੂਚਨਾਵਾਂ ਸਰਵਰ ਵਲੋਂ ਕਲਾਇੰਟ ਨੂੰ ਜਲਦ-ਜਲਦ ਭੇਜੇ ਜਾਣ ਵਾਲੇ ਸੁਨੇਹੇ ਹਨ ਜੋ ਲੰਬੇ ਚੱਲ ਰਹੇ ਕਾਰਜ ਦੌਰਾਨ ਭੇਜੇ ਜਾਂਦੇ ਹਨ। ਪੂਰੇ ਕਾਰਜ ਦੇ ਮੁਕੰਮਲ ਹੋਣ ਦੀ ਉਡੀਕ ਕਰਨ ਦੀ ਥਾਂ, ਸਰਵਰ ਕਲਾਇੰਟ ਨੂੰ ਵਰਤਮਾਨ ਸਥਿਤੀ ਦੀ ਜਾਣਕਾਰੀ ਦਿੰਦਾ ਰਹਿੰਦਾ ਹੈ। ਇਹ ਪਾਰਦਰਸ਼ਤਾ, ਉਪਭੋਗਤਾ ਅਨੁਭਵ ਵਿੱਚ ਸੁਧਾਰ ਅਤੇ ਡੀਬਗਿੰਗ ਸੌਖੀ ਬਣਾਉਂਦਾ ਹੈ।

**ਉਦਾਹਰਨ:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### ਪ੍ਰਗਟੀ ਸੂਚਨਾਵਾਂ ਕਿਉਂ ਵਰਤਣ?

ਪ੍ਰਗਟੀ ਸੂਚਨਾਵਾਂ ਕਈ ਕਾਰਨਾਂ ਲਈ ਜ਼ਰੂਰੀ ਹਨ:

- **ਵਧੀਆ ਉਪਭੋਗਤਾ ਅਨੁਭਵ:** ਯੂਜ਼ਰ ਕਾਰਜ ਦੇ ਚੱਲਦੇ ਸਮੇਂ ਅਪਡੇਟਸ ਵੇਖਦੇ ਹਨ, ਸਿਰਫ ਅੰਤ ਵਿੱਚ ਨਹੀਂ।
- **ਤੁਰੰਤ ਪ੍ਰਤਿਕਿਰਿਆ:** ਕਲਾਇੰਟ ਪ੍ਰਗਟ ਬਾਰ ਜਾਂ ਲੌਗ ਦਿਖਾ ਸਕਦੇ ਹਨ, ਜਿਸ ਨਾਲ ਐਪ ਸੱਮੱਥ ਬਣਦੀ ਹੈ।
- **ਸੌਖੀ ਡੀਬਗਿੰਗ ਅਤੇ ਨਿਗਰਾਨੀ:** ਵਿਕਾਸਕਾਰ ਅਤੇ ਯੂਜ਼ਰ ਵੇਖ ਸਕਦੇ ਹਨ ਕਿ ਕਾਰਜ ਕਿੱਥੇ ਹੌਲੀ ਜਾਂ ਰੁਕਿਆ ਹੋਇਆ ਹੈ।

### ਪ੍ਰਗਟੀ ਸੂਚਨਾਵਾਂ ਕਿਵੇਂ ਲਾਗੂ ਕਰੀਏ

ਹੇਠਾਂ MCP ਵਿੱਚ ਪ੍ਰਗਟੀ ਸੂਚਨਾਵਾਂ ਲਾਗੂ ਕਰਨ ਦੇ ਤਰੀਕੇ ਹਨ:

- **ਸਰਵਰ ਪਾਸਾ:** ਹਰ ਚੀਜ਼ ਪ੍ਰਕਿਰਿਆ ਕੰਮ ਹੁੰਦਾ, `ctx.info()` ਜਾਂ `ctx.log()` ਨਾਲ ਸੂਚਨਾਵਾਂ ਭੇਜੋ। ਇਹ ਸੁਨੇਹਾ ਮੁੱਖ ਨਤੀਜੇ ਤੋਂ ਪਹਿਲਾਂ ਕਲਾਇੰਟ ਨੂੰ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ।
- **ਕਲਾਇੰਟ ਪਾਸਾ:** ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰੋ ਜੋ ਆਉਂਦੀਆਂ ਸੂਚਨਾਵਾਂ ਨੂੰ ਸੁਣਦਾ ਅਤੇ ਪ੍ਰਦਰਸ਼ਿਤ ਕਰਦਾ ਹੈ। ਇਹ ਹੈਂਡਲਰ ਸੂਚਨਾਵਾਂ ਅਤੇ ਆਖਰੀ ਨਤੀਜੇ ਵਿਚਕਾਰ ਫ਼ਰਕ ਕਰਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ ਬਾਰੇ ਵਿਚਾਰ

ਸੁਰੱਖਿਆ ਕਿਸੇ ਵੀ ਸਰਵਰ ਨੂੰ ਲਾਗੂ ਕਰਦੇ ਸਮੇਂ ਸਬ ਤੋਂ ਉੱਪਰ ਦੌਰ 'ਤੇ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ, ਖਾਸ ਕਰਕੇ ਜਦੋਂ HTTP-ਆਧਾਰਿਤ ਟ੍ਰਾਂਸਪੋਰਟਾਂ ਜਿਵੇਂ ਕਿ MCP ਵਿੱਚ Streamable HTTP ਵਰਤੀ ਜਾਵੇ।

ਜਦੋਂ MCP ਸਰਵਰ HTTP-ਆਧਾਰਿਤ ਟ੍ਰਾਂਸਪੋਰਟਾਂ ਨਾਲ ਲਾਗੂ ਕੀਤੇ ਜਾਂਦੇ ਹਨ, ਤਾਂ ਸੁਰੱਖਿਆ ਇੱਕ ਅਹੰਕਾਰਪੂਰਨ ਵਿਸ਼ਾ ਹੋ ਜਾਂਦਾ ਹੈ ਜੋ ਅਨੇਕ ਹਮਲੇਵਾਰ ਵੈਕਟਰਾਂ ਅਤੇ ਸੁਰੱਖਿਆ ਪ੍ਰਣਾਲੀਆਂ 'ਤੇ ਧਿਆਨ ਦੇਣ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

### ਜਾਇਜ਼ਾ

MCP ਸਰਵਰਾਂ ਨੂੰ HTTP ਰਾਹੀਂ ਐਕਸਪੋਜ਼ ਕਰਦਿਆਂ ਸੁਰੱਖਿਆ ਬਹੁਤ ਜਰੂਰੀ ਹੁੰਦੀ ਹੈ। Streamable HTTP ਨਵੇਂ ਹਮਲਾਵਾਰ ਖਿੱਤਿਆਂ ਨੂੰ ਪੈਦਾ ਕਰਦਾ ਹੈ ਅਤੇ ਇਸ ਦੀ ਸੰਰਚਨਾ ਸੰਭਾਲਣੀ ਪੈਂਦੀ ਹੈ।

ਇੱਥੇ ਕੁਝ ਮੁੱਖ ਸੁਰੱਖਿਆ ਬਿੰਦੂ ਹਨ:

- **Origin ਹੈਡਰ ਵੈਰੀਫਿਕੇਸ਼ਨ**: DNS ਰੀਬਾਈਂਡਿੰਗ ਹਮਲਿਆਂ ਤੋਂ ਬਚਣ ਲਈ ਹਮੇਸ਼ਾ `Origin` ਹੈਡਰ ਦੀ ਜਾਂਚ ਕਰੋ।
- **Localhost ਬਾਈਂਡਿੰਗ**: ਸਥਾਨਕ ਵਿਕਾਸ ਲਈ ਸਰਵਰਾਂ ਨੂੰ `localhost` ਨਾਲ ਬਾਈਂਡ ਕਰੋ ਤਾਂ ਜੋ ਉਹ ਪਬਲਿਕ ਇੰਟਰਨੈੱਟ ਤੋਂ ਪ੍ਰਗਟ ਨਾ ਹੋਣ।
- **ਪ੍ਰਮਾਣਿਕਤਾ**: ਉਤਪਾਦਨ ਤैनਾਤੀ ਲਈ ਪ੍ਰਮਾਣਿਕਤਾ ਲਾਗੂ ਕਰੋ (ਜਿਵੇਂ API ਕੁੰਜੀਆਂ, OAuth)।
- **CORS**: ਕ੍ਰਾਸ-ਓਰਿਜਨ ਸਰਵਿਸ ਸਾਂਝ (CORS) ਨੀਤੀਆਂ ਨੂੰ ਸੀਮਿਤ ਕਰਨ ਲਈ ਸੰਰਚਿਤ ਕਰੋ।
- **HTTPS**: ਟ੍ਰੈਫਿਕ ਐਨਕ੍ਰਿਪਸ਼ਨ ਲਈ ਉਤਪਾਦਨ ਵਿੱਚ HTTPS ਵਰਤੋਂ।

### ਸਰਵੋਤਮ ਅਭਿਆਸ

ਨਾਲ ਹੀ, MCP ਸਟ੍ਰੀਮਿੰਗ ਸਰਵਰ ਵਿੱਚ ਸੁਰੱਖਿਆ ਲਾਗੂ ਕਰਦਿਆਂ ਇਹ ਕੁਝ ਸਰਵੋਤਮ ਅਭਿਆਸ ਹਨ:

- ਆਉਣ ਵਾਲੇ ਬਿਨਾਂ ਸਥਿਰ ਖ਼ਾਤਮਿਆਂ 'ਤੇ ਕਦੇ ਭਰੋਸਾ ਨਾ ਕਰੋ।
- ਸਾਰੀਆਂ ਪਹੁੰਚਾਂ ਅਤੇ ਗਲਤੀਆਂ ਦੀ ਲਾਗਿੰਗ ਅਤੇ ਨਿਗਰਾਨੀ ਕਰੋ।
- ਸੁਰੱਖਿਆ ਖਾਮੀਆਂ ਨੂੰ ਠੀਕ ਕਰਨ ਲਈ dependencies ਨੂੰ ਨਿਯਮਿਤ ਤੌਰ 'ਤੇ ਅਪਡੇਟ ਕਰੋ।

### ਚੁਣੌਤੀਆਂ

MCP ਸਟ੍ਰੀਮਿੰਗ ਸਰਵਰਾਂ ਵਿੱਚ ਸੁਰੱਖਿਆ ਲਾਗੂ ਕਰਦਿਆਂ ਤੁਹਾਨੂੰ ਕੁਝ ਚੁਣੌਤੀਆਂ ਦਾ ਸਾਹਮਣਾ ਕਰਨਾ ਪਵੇਗਾ:

- ਵਿਕਾਸ ਦੀ ਸੁਗਮਤਾ ਨਾਲ ਸੁਰੱਖਿਆ ਨੂੰ ਸੰਤੁਲਿਤ ਕਰਨ ਦੀ ਲੋੜ
- ਵੱਖ-ਵੱਖ ਕਲਾਇੰਟ ਵਾਤਾਵਰਣਾਂ ਦੇ ਨਾਲ ਮੈਚ ਕਰਨ ਨੂੰ ਯਕੀਨੀ ਬਨਾਉਣਾ


## SSE ਤੋਂ Streamable HTTP ਵਿੱਚ ਅੱਪਗਰੇਡਿੰਗ

ਜਿਹੜੇ ਐਪਲੀਕੇਸ਼ਨਾਂ ਵਿੱਚ ਵਰਤਮਾਨ ਵਿੱਚ ਸਰਵਰ-ਸੈਂਟ ਇਵੈਂਟਸ (SSE) ਵਰਤੇ ਜਾ ਰਹੇ ਹਨ, ਉਨ੍ਹਾਂ ਲਈ Streamable HTTP ਵਿੱਚ ਮਾਈਗ੍ਰੇਟ ਕਰਨਾ ਤੁਹਾਡੇ MCP ਲਾਗੂ ਕਰਨ ਵਾਲੇ ਹੱਲਾਂ ਲਈ ਵਧੇਰੇ ਸਮਰੱਥਾ ਅਤੇ ਲੰਮੀ ਮਿਆਦ ਦੀ ਸਥਿਰਤਾ ਦਿੰਦਾ ਹੈ।

### ਕਿਉਂ ਅੱਪਗਰੇਡ ਕਰਨਾ?

SSE ਤੋਂ Streamable HTTP ਨੂੰ ਅੱਪਗਰੇਡ ਕਰਨ ਦੇ ਦੋ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਕਾਰਨ ਹਨ:

- Streamable HTTP—SSE ਨਾਲੋਂ ਵਧੀਆ ਸਕੇਲਬਿਲਟੀ, ਅਨੁਕੂਲਤਾ ਅਤੇ ਰਿਚ ਨੋਟੀਫਿਕੇਸ਼ਨ ਸਮਰਥਨ ਦਿੰਦਾ ਹੈ।
- ਇਹ ਨਵੇਂ MCP ਐਪਲੀਕੇਸ਼ਨਾਂ ਲਈ ਸਿਫਾਰਸ਼ੀ ਟ੍ਰਾਂਸਪੋਰਟ ਹੈ।

### ਮਾਈਗ੍ਰੇਸ਼ਨ ਦੇ ਕਦਮ

ਆਪਣੇ MCP ਐਪਲੀਕੇਸ਼ਨਾਂ ਵਿੱਚ SSE ਤੋਂ Streamable HTTP ਜਾਣ ਦਾ ਤਰੀਕਾ ਇਹ ਹੈ:

- **ਸਰਵਰ ਕੋਡ ਅਪਡੇਟ ਕਰੋ** تاکہ `mcp.run()` ਵਿਚ `transport="streamable-http"` ਵਰਤੋਂ।
- **ਕਲਾਇੰਟ ਕੋਡ ਅਪਡੇਟ ਕਰੋ** SSE ਕਲਾਇੰਟ ਦੀ ਥਾਂ `streamablehttp_client` ਵਰਤੋਂ।
- **ਕਲਾਇੰਟ ਵਿੱਚ ਇੱਕ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਲਾਗੂ ਕਰੋ** ਜੋ ਨੋਟੀਫਿਕੇਸ਼ਨਾਂ ਨੂੰ ਪ੍ਰੋਸੈਸ ਕਰੇ।
- **ਮੌਜੂਦਾ ਟੂਲਾਂ ਅਤੇ ਵਰਕਫਲੋਜ਼ ਨਾਲ ਅਨੁਕੂਲਤਾ ਦੀ ਜਾਂਚ ਕਰੋ**।

### ਅਨੁਕੂਲਤਾ ਕਾਇਮ ਰੱਖਣਾ

ਮਾਈਗ੍ਰੇਸ਼ਨ ਪ੍ਰਕਿਰਿਆ ਦੌਰਾਨ ਮੌਜੂਦਾ SSE ਕਲਾਇੰਟਾਂ ਨਾਲ ਅਨੁਕੂਲਤਾ ਕਾਇਮ ਰੱਖਣ ਦੀ ਸਿਫਾਰਸ਼ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਇੱਥੇ ਕੁਝ ਰਣਨੀਤੀਆਂ ਹਨ:

- ਤੁਸੀਂ ਦੋਹਾਂ SSE ਤੇ Streamable HTTP ਨੂੰ ਵੱਖ-ਵੱਖ ਐਂਡਪੋਇਂਟਾਂ 'ਤੇ ਚੁਲਾਕੇ ਸਹਿਯੋਗ ਦੇ ਸਕਦੇ ਹੋ।
- ਕਰਕਿਰਾ ਕਰਕੇ ਕਲਾਇੰਟਾਂ ਨੂੰ ਨਵੀਂ ਟ੍ਰਾਂਸਪੋਰਟ ਵੱਲ ਮਾਈਗ੍ਰੇਟ ਕਰੋ।

### ਚੁਣੌਤੀਆਂ

ਮਾਈਗ੍ਰੇਸ਼ਨ ਦੌਰਾਨ ਨਿਮ্ন ਚੁਣੌਤੀਆਂ ਦਾ ਸਮਨਾ ਕਰੋ:

- ਸਾਰੇ ਕਲਾਇੰਟਾਂ को ਅਪਡੇਟ ਕੀਤਾ ਜਾਵੇ ਇਹ ਯਕੀਨੀ ਬਣਾਉਣਾ
- ਨੋਟੀਫਿਕੇਸ਼ਨ ਦੇ ਹੁੰਦੇ ਫਰਕਾਂ ਨੂੰ ਸੰਭਾਲਣਾ

### ਅਸਾਈਨਮੈਂਟ: ਆਪਣਾ ਸਟ੍ਰੀਮਿੰਗ MCP ਐਪ ਬਣਾਓ

**ਪ੍ਰਸੰਗ:**
ਇੱਕ MCP ਸਰਵਰ ਅਤੇ ਕਲਾਇੰਟ ਬਣਾਓ ਜਿੱਥੇ ਸਰਵਰ ਆਈਟਮਾਂ ਦੀ ਸੂਚੀ (ਜਿਵੇਂ ਫਾਇਲਾਂ ਜਾਂ ਦਸਤਾਵੇਜ਼) ਨੂੰ ਪ੍ਰੋਸੈਸ ਕਰਦਾ ਹੈ ਅਤੇ ਹਰ ਪ੍ਰੋਸੈਸ ਕੀਤੇ ਆਈਟਮ ਲਈ ਨੋਟੀਫਿਕੇਸ਼ਨ ਭੇਜਦਾ ਹੈ। ਕਲਾਇੰਟ ਨੂੰ ਹਰ ਨੋਟੀਫਿਕੇਸ਼ਨ ਨੂੰ ਜਿਵੇਂ ਉਹ ਪਹਿਲਾਂ ਆਉਂਦੀ ਹੈ, ਦਿਖਾਉਣਾ ਚਾਹੀਦਾ ਹੈ।

**ਕਦਮ:**

1. ਇੱਕ ਸਰਵਰ ਟੂਲ ਲਾਗੂ ਕਰੋ ਜੋ ਸੂਚੀ ਪ੍ਰੋਸੈਸ ਕਰੇ ਅਤੇ ਹਰ ਆਈਟਮ ਲਈ ਨੋਟੀਫਿਕੇਸ਼ਨ ਭੇਜੇ।
2. ਇੱਕ ਕਲਾਇੰਟ ਲਾਗੂ ਕਰੋ ਜਿਸ ਵਿੱਚ ਇੱਕ ਸੁਨੇਹਾ ਹੈਂਡਲਰ ਹੋਵੇ ਜੋ ਨੋਟੀਫਿਕੇਸ਼ਨਾਂ ਨੂੰ ਰੀਅਲ ਟਾਈਮ ਵਿੱਚ ਦਿਖਾਏ।
3. ਆਪਣੀ ਲਾਗੂ ਕਰਨ ਦੇ ਪਰੀਖਣ ਲਈ ਸਰਵਰ ਅਤੇ ਕਲਾਇੰਟ ਦੋਹਾਂ ਨੂੰ ਚਲਾਉ ਅਤੇ ਨੋਟੀਫਿਕੇਸ਼ਨਾਂ ਨੂੰ ਵੇਖੋ।
