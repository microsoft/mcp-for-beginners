# MCP ਇੰਸਪੈਕਟਰ ਨਾਲ ਡੀਬੱਗਿੰਗ

> [!NOTE]
> `--sse` ਵਰਤਦੇ ਕੰਮਾਂਡਾਂ ਅਤੇ URL ਜੋ `/sse` 'ਤੇ ਖਤਮ ਹੁੰਦੇ ਹਨ ਉਨ੍ਹਾਂ ਨੂੰ ਲੈਗੇਸੀ HTTP+SSE ਟਰਾਂਸਪੋਰਟ ਦੀ ਜਾਂਚ ਕਰਦੇ ਹਨ। ਨਵੇਂ MCP `2026-07-28` ਸਰਵਰ ਲਈ, ਉਸ ਇੰਸਪੈਕਟਰ ਵਰਜ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੋ ਜੋ Streamable HTTP ਨੂੰ ਸਮਰਥਨ ਦੇਵੇ ਅਤੇ ਉਸ ਟਰਾਂਸਪੋਰਟ ਨੂੰ ਚੁਣੋ।
>  
>  

**MCP ਇੰਸਪੈਕਟਰ** ਇੱਕ ਜ਼ਰੂਰੀ ਡੀਬੱਗਿੰਗ ਟੂਲ ਹੈ ਜੋ ਤੁਹਾਨੂੰ ਪੂਰੇ AI ਹੋਸਟ ਐਪਲੀਕੇਸ਼ਨ ਦੀ ਲੋੜ ਬਿਨਾਂ MCP ਸਰਵਰਾਂ ਨੂੰ ਇੰਟਰਐਕਟਿਵ ਤੌਰ 'ਤੇ ਟੈਸਟ ਅਤੇ ਸਮੱਸਿਆ ਮਿਟਾਊਣ ਦੀ ਆਗਿਆ ਦਿੰਦਾ ਹੈ। ਇਸ ਨੂੰ "MCP ਲਈ ਪੋਸਟਮੈਨ" ਸਮਝੋ - ਇਹ ਬੇਨਤੀ ਭੇਜਣ, ਜਵਾਬ ਵੇਖਣ ਅਤੇ ਸਮਝਣ ਲਈ ਇੱਕ ਵਿਜ਼ੂਅਲ ਇੰਟਰਫੇਸ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ ਕਿ ਤੁਹਾਡਾ ਸਰਵਰ ਕਿਵੇਂ ਪ੍ਰਵ੍ਹਾਵ ਕਰਦਾ ਹੈ।

## MCP ਇੰਸਪੈਕਟਰ ਕਿਉਂ ਵਰਤਣਾ ਚਾਹੀਦਾ ਹੈ?

MCP ਸਰਵਰ ਬਣਾਉਂਦੇ ਸਮੇਂ, ਤੁਸੀਂ ਅਕਸਰ ਇਹ ਚੁਣੌਤੀਆਂ ਸਾਹਮਣਾ ਕਰਦੇ ਹੋ:

- **"ਕੀ ਮੇਰਾ ਸਰਵਰ ਚੱਲ ਹੀ ਰਿਹਾ ਹੈ?"** - ਇੰਸਪੈਕਟਰ ਕਨੈਕਸ਼ਨ ਦੀ ਸਥਿਤੀ ਦਿਖਾਉਂਦਾ ਹੈ
- **"ਕੀ ਮੇਰੇ ਟੂਲ ਸਹੀ ਤਰ੍ਹਾਂ ਰਜਿਸਟਰ ਹੋਏ ਹਨ?"** - ਇੰਸਪੈਕਟਰ ਸਾਰੇ ਉਪਲਬਧ ਟੂਲ ਦੀ ਸੂਚੀ ਦਿਖਾਉਂਦਾ ਹੈ
- **"ਜਵਾਬ ਫਾਰਮੈਟ ਕੀ ਹੈ?"** - ਇੰਸਪੈਕਟਰ ਪੂਰੇ JSON ਜਵਾਬ ਦਿਖਾਉਂਦਾ ਹੈ
- **"ਇਹ ਟੂਲ ਕਿਉਂ ਕੰਮ ਨਹੀਂ ਕਰ ਰਿਹਾ?"** - ਇੰਸਪੈਕਟਰ ਵਿਸਥਾਰ ਵਿੱਚ ਗਲਤੀ ਸੁਨੇਹੇ ਦਿਖਾਉਂਦਾ ਹੈ

## ਲੋੜੀਂਦੇ ਚੀਜ਼ਾਂ

- Node.js 18+ ਇੰਸਟਾਲ ਹੋਇਆ ਹੋਵੇ
- npm (Node.js ਨਾਲ ਆਉਂਦਾ ਹੈ)
- ਕਿਸੇ MCP ਸਰਵਰ ਨੂੰ ਟੈਸਟ ਕਰਨ ਲਈ (ਦੇਖੋ [Module 3.1 - First Server](../01-first-server/README.md))

## ਇੰਸਟਾਲੇਸ਼ਨ

### ਵਿਕਲਪ 1: npx ਨਾਲ ਚਲਾਉਣਾ (ਤੇਜ਼ ਟੈਸਟਿੰਗ ਲਈ ਸੁਝਾਇਆ ਗਿਆ)

```bash
npx @modelcontextprotocol/inspector
```

### ਵਿਕਲਪ 2: ਗਲੋਬਲੀ ਇੰਸਟਾਲ ਕਰੋ

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### ਵਿਕਲਪ 3: ਆਪਣੇ ਪ੍ਰੋਜੇਕਟ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## ਆਪਣੇ ਸਰਵਰ ਨਾਲ ਜੁੜਨਾ

### stdio ਸਰਵਰ (ਲੋਕਲ ਪ੍ਰੋਸੈਸ)

ਉਹਨਾਂ ਸਰਵਰਾਂ ਲਈ ਜੋ ਮਿਆਰੀ ਇਨਪੁੱਟ/ਆਉਟਪੁੱਟ ਰਾਹੀਂ ਸੰਚਾਰ ਕਰਦੇ ਹਨ:

```bash
# ਪਾਇਥਨ ਸਰਵਰ
npx @modelcontextprotocol/inspector python -m your_server_module

# ਨੋਡ.ਜੇਐਸ ਸਰਵਰ
npx @modelcontextprotocol/inspector node ./build/index.js

# ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲਾਂ ਨਾਲ
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP ਸਰਵਰ (ਨੈੱਟਵਰਕ)

HTTP ਸੇਵਾਵਾਂ ਵਜੋਂ ਚੱਲ ਰਹੇ ਸਰਵਰਾਂ ਲਈ:

1. ਪਹਿਲਾਂ ਆਪਣਾ ਸਰਵਰ ਚਾਲੂ ਕਰੋ:
   ```bash
   python server.py  # ਸਰਵਰ http://localhost:8080 'ਤੇ ਚੱਲ ਰਿਹਾ ਹੈ
   ```

2. ਇੰਸਪੈਕਟਰ ਨੂੰ ਲਾਂਚ ਕਰੋ ਅਤੇ ਕਨੈਕਟ ਕਰੋ:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## ਟੂਲ ਟੈਸਟ ਕਰਨਾ

### ਉਪਲਬਧ ਟੂਲਾਂ ਦੀ ਸੂਚੀ

1. **Tools** ਟੈਬ 'ਤੇ ਕਲਿੱਕ ਕਰੋ
2. ਇੰਸਪੈਕਟਰ ਆਪਣੇ-ਆਪ `tools/list` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ
3. ਤੁਸੀਂ ਸਾਰੇ ਰਜਿਸਟਰਡ ਟੂਲ ਵੇਖੋਗੇ:
   - ਟੂਲ ਦਾ ਨਾਮ
   - ਵਰਣਨ
   - ਇਨਪੁੱਟ ਸਕੀਮਾ (ਪੈਰੇਮੀਟਰ)

### ਟੂਲ ਕਾਲ ਕਰਨਾ

1. ਸੂਚੀ ਵਿੱਚੋਂ ਇੱਕ ਟੂਲ ਚੁਣੋ
2. ਫਾਰਮ ਵਿੱਚ ਲੋੜੀਦੇ ਪੈਰੇਮੀਟਰ ਭਰੋ
3. **Run Tool** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
4. ਨਤੀਜੇ ਪੈਨਲ ' ਵਿੱਚ ਜਵਾਬ ਵੇਖੋ

**ਉਦਾਹਰਨ: ਕੈਲਕੂਲੇਟਰ ਟੂਲ ਦੀ ਜਾਂਚ**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### ਟੂਲ ਦੀਆਂ ਗਲਤੀਆਂ ਡੀਬੱਗ ਕਰਨਾ

ਜਦ ਟੂਲ ਫੇਲ ਹੁੰਦਾ ਹੈ, ਇੰਸਪੈਕਟਰ ਦਿਖਾਉਂਦਾ ਹੈ:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

ਆਮ ਗਲਤੀ ਕੋਡ:
| ਕੋਡ | ਅਰਥ |
|------|---------|
| -32700 | ਪਾਰਸ ਗਲਤੀ (ਅਵੈਧ JSON) |
| -32600 | ਅਵੈਧ ਬੇਨਤੀ |
| -32601 | ਤਰੀਕਾ ਨਹੀਂ ਲੱਭਿਆ ਗਿਆ |
| -32602 | ਪੈਰੇਮੀਟਰ ਅਵੈਧ |
| -32603 | ਅੰਦਰੂਨੀ ਗਲਤੀ |

## ਸਰੋਤ ਟੈਸਟ ਕਰਨਾ

### ਸਰੋਤਾਂ ਦੀ ਸੂਚੀ

1. **Resources** ਟੈਬ 'ਤੇ ਕਲਿੱਕ ਕਰੋ
2. ਇੰਸਪੈਕਟਰ `resources/list` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ
3. ਤੁਸੀਂ ਦੇਖੋਗੇ:
   - ਸਰੋਤ URI
   - ਨਾਮ ਤੇ ਵਰਣਨ
   - MIME ਕਿਸਮਾਂ

### ਸਰੋਤ ਪੜ੍ਹਨਾ

1. ਇੱਕ ਸਰੋਤ ਚੁਣੋ
2. **Read Resource** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
3. ਵਾਪਸ ਆਏ ਸਮੱਗਰੀ ਵੇਖੋ

**ਉਦਾਹਰਨ ਨਤੀਜਾ:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

2. ਲੋੜੀਂਦੇ ਦਲੀਲਾਂ ਭਰੋ
3. **Get Prompt** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
4. ਪ੍ਰਦਰਸ਼ਿਤ ਪ੍ਰੋੰਪਟ ਸੁਨੇਹੇ ਵੇਖੋ

## ਸੁਨੇਹਾ ਲਾਗ ਵਿਸ਼ਲੇਸ਼ਣ

ਸੁਨੇਹਾ ਲਾਗ ਸਾਰੇ MCP ਪ੍ਰੋਟੋਕੋਲ ਸੁਨੇਹੇ ਦਿਖਾਉਂਦਾ ਹੈ। ਹੇਠਾਂ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਇੱਕ
ਲੈਗੇਸੀ `2025-11-25` ਸਰਵਰ ਤੋਂ ਹੈ ਜਿਸ ਵਿੱਚ ਹਟਾਇਆ ਗਿਆ `initialize` ਹੈਂਡਸ਼ੇਕ ਸ਼ਾਮਲ ਹੈ। ਇੱਕ
`2026-07-28` ਸਰਵਰ ਖੁਦ-ਸ਼ਾਮਲ ਬੇਨਤੀ ਮੈਟਾਡੇਟਾ ਅਤੇ `server/discover`
ਵਰਤਦਾ ਹੈ।

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### ਕੀ ਦੇਖਣਾ ਹੈ

- **ਬੇਨਤੀ/ਜਵਾਬ ਜੋੜੇ**: ਹਰ `→` ਨੂੰ ਇੱਕ ਮੈਚਿੰਗ `←` ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ
- **ਗਲਤੀ ਸੁਨੇਹੇ**: ਜਵਾਬਾਂ ਵਿੱਚ `"error"` ਵੇਖੋ
- **ਟਾਈਮਿੰਗ**: ਵੱਡੀਆਂ ਖਾਲੀਆਂ ਪ੍ਰਦਰਸ਼ਨ ਸਮੱਸਿਆਵਾਂ ਦਾ ਸੰਕੇਤ ਹੋ ਸਕਦੀਆਂ ਹਨ
- **ਪ੍ਰੋਟੋਕੋਲ ਵਰਜ਼ਨ**: ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਸਰਵਰ ਅਤੇ ਕਲਾਇੰਟ ਵਰਜ਼ਨ 'ਤੇ ਸਹਿਮਤ ਹਨ

## ਆਮ ਡੀਬੱਗਿੰਗ ਹਾਲਾਤ

### ਹਾਲਾਤ 1: ਸਰਵਰ ਕਨੈਕਟ ਨਹੀਂ ਹੁੰਦਾ

**ਲੱਛਣ:** ਇੰਸਪੈਕਟਰ "Disconnected" ਦਿਖਾਉਂਦਾ ਹੈ ਜਾਂ "Connecting..." ਤੇ ਫਸ ਜਾਂਦਾ ਹੈ

**ਚੈੱਕਲਿਸਟ:**
1. ✅ ਕੀ ਸਰਵਰ ਕਮਾਂਡ ਸਹੀ ਹੈ?
2. ✅ ਕੀ ਸਾਰੇ ਇੰਨਾਮਦਾਂ ਇੰਸਟਾਲ ਹਨ?
3. ✅ ਕੀ ਸਰਵਰ ਪਾਥ ਮੌਜੂਦਾ ਡਾਇਰੈਕਟਰੀ ਦੇ ਸਾਥ ਅਪੇਖਿਤ ਜਾਂ ਅਬਸੋਲਿਊਟ ਹੈ?
4. ✅ ਕੀ ਲੋੜੀਦੇ ਵਾਤਾਵਰਣ ਵੈਰੀਏਬਲ ਸੈਟ ਹਨ?

**ਡੀਬੱਗ ਕਦਮ:**
```bash
# ਪਹਿਲਾਂ ਸਰਵਰ ਨੂੰ ਹੱਥੋਂ ਟੈਸਟ ਕਰੋ
python -c "import your_server_module; print('OK')"

# ਇੰਪੋਰਟ ਤਰੁਟੀਆਂ ਦੀ ਜਾਂਚ ਕਰੋ
python -m your_server_module 2>&1 | head -20

# ਯਕੀਨੀ ਬਣਾਓ ਕਿ MCP SDK ਇੰਸਟਾਲ ਕੀਤਾ ਗਿਆ ਹੈ
pip show mcp
```

### ਹਾਲਾਤ 2: ਟੂਲ ਨਹੀਂ ਦਿਖ ਰਹੇ

**ਲੱਛਣ:** ਟੂਲ ਟੈਬ ਖਾਲੀ ਸੂਚੀ ਦਿਖਾਉਂਦਾ ਹੈ

**ਸੰਭਾਵਿਤ ਕਾਰਨ:**
1. ਸਰਵਰ ਸ਼ੁਰੂਆਤ ਦੌਰਾਨ ਟੂਲ ਰਜਿਸਟਰ ਨਹੀਂ ਹੋਏ
2. ਸਰਵਰ ਸ਼ੁਰੂ ਹੋਣ ਮਗਰੋਂ ਕ੍ਰੈਸ਼ ਹੋ ਗਿਆ
3. `tools/list` ਹੈਂਡਲਰ ਖਾਲੀ array ਵਾਪਸ ਕਰ ਰਿਹਾ ਹੈ

**ਡੀਬੱਗ ਕਦਮ:**
1. ਮੇਸੇਜ ਲਾਗ ਵਿੱਚ `tools/list` ਜਵਾਬ ਨੂੰ ਜਾਂਚੋ
2. ਆਪਣੇ ਟੂਲ ਰਜਿਸਟਰੇਸ਼ਨ ਕੋਡ ਵਿੱਚ ਲਾਗਿੰਗ ਸ਼ਾਮਲ ਕਰੋ
3. ਯਕੀਨੀ ਬਣਾਓ ਕਿ `@mcp.tool()` ਡੈਕੋਰੇਟਰ ਮੌਜੂਦ ਹਨ (Python)

### ਹਾਲਾਤ 3: ਟੂਲ ਗਲਤੀ ਵਾਪਸ ਕਰਦਾ ਹੈ

**ਲੱਛਣ:** ਟੂਲ ਕਾਲ ਗਲਤੀ ਜਵਾਬ ਵਾਪਸ ਕਰਦਾ ਹੈ

**ਡੀਬੱਗ ਤਰੀਕਾ:**
1. ਗਲਤੀ ਸੁਨੇਹਾ ਧਿਆਨ ਨਾਲ ਪੜ੍ਹੋ
2. ਪੈਰੇਮੀਟਰ ਦੀ ਕਿਸਮਾਂ ਨੂੰ ਸਕੀਮਾ ਨਾਲ ਮੇਲ ਕਰੋ
3. ਵਿਸਥਾਰਵਾਨ ਗਲਤੀ ਸੁਨੇਹੇ ਨਾਲ try/catch ਸ਼ਾਮਲ ਕਰੋ
4. ਸਰਵਰ ਲਾਗਸ ਵਿੱਚ ਸਟੈਕ ਟ੍ਰੇਸ ਦੀ ਜਾਂਚ ਕਰੋ

**ਉਦਾਹਰਨ ਸੁਧਾਰੀ ਗਲਤੀ ਸੰਭਾਲ:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # ਇੱਥੇ ਸੰਦ ਲਾਜ਼ਮਿਤੀ
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### ਹਾਲਾਤ 4: ਸਰੋਤ ਸਮੱਗਰੀ ਖਾਲੀ

**ਲੱਛਣ:** ਸਰੋਤ ਵਾਪਸ ਆਉਂਦਾ ਹੈ ਪਰ ਸਮੱਗਰੀ ਖਾਲੀ ਜਾਂ ਨਲ ਹੈ

**ਚੈੱਕਲਿਸਟ:**
1. ✅ ਫਾਈਲ ਪਾਥ ਜਾਂ URI ਸਹੀ ਹੈ
2. ✅ ਸਰਵਰ ਨੂੰ ਸਰੋਤ ਪੜ੍ਹਨ ਦੀ ਇਜਾਜ਼ਤ ਹੈ
3. ✅ ਸਰੋਤ ਸਮੱਗਰੀ ਠੀਕ ਤਰ੍ਹਾਂ ਵਾਪਸੀ ਕੀਤੀ ਜਾ ਰਹੀ ਹੈ

## ਸਭ ਤੋਂ ਵਧੀਆ ਅਭਿਆਸ

1. **ਸ਼ੁਰੂਆਤੀ ਅਤੇ ਆਮ ਤੌਰ 'ਤੇ ਟੈਸਟ ਕਰੋ** - ਵਿਕਾਸ ਦੌਰਾਨ ਇੰਸਪੈਕਟਰ ਇਸਤੇਮਾਲ ਕਰੋ, ਸਿਰਫ ਸਮੱਸਿਆਵਾਂ ਆਉਣ ਤੇ ਨਹੀਂ
2. **ਆਸਾਨ ਸ਼ੁਰੂ ਕਰੋ** - ਪਹਿਲਾਂ ਮੁੱਢਲੀ ਕਨੈਕਟੀਵਟੀ ਟੈਸਟ ਕਰੋ ਗੁੰਝਲਦਾਰ ਟੂਲ ਕਾਲਾਂ ਤੋਂ ਪਹਿਲਾਂ
3. **ਸਕੀਮਾ ਦੀ ਜਾਂਚ ਕਰੋ** - ਬਹੁਤ ਸਾਰੀਆਂ ਗਲਤੀਆਂ ਪੈਰੇਮੀਟਰ ਕਿਸਮਾਂ ਦੇ ਮਿਲਣ-ਨਾਹੀ ਮਿਲਣ ਤੋਂ ਆਉਂਦੀਆਂ ਹਨ
4. **ਗਲਤੀ ਸੁਨੇਹੇ ਪੜ੍ਹੋ** - MCP ਦੀਆਂ ਗਲਤੀਆਂ ਆਮ ਤੌਰ ਤੇ ਵੇਰਵਾ ਦਿੰਦੀਆਂ ਹਨ
5. **ਇੰਸਪੈਕਟਰ ਖੁਲਾ ਰੱਖੋ** - ਇਹ ਵਿਕਾਸ ਦੌਰਾਨ ਸਮੱਸਿਆਵਾਂ ਫੜਨ ਵਿੱਚ ਮਦਦ ਕਰਦਾ ਹੈ
