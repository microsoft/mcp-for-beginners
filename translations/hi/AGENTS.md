# AGENTS.md

## परियोजना अवलोकन

**शुरुआत करने वालों के लिए MCP** एक खुले स्रोत शैक्षिक पाठ्यक्रम है जो मॉडल कॉन्टेक्स्ट प्रोटोकॉल (MCP) सीखने के लिए है - जो AI मॉडल और क्लाइंट एप्लिकेशन के बीच इंटरैक्शन के लिए एक मानकीकृत फ्रेमवर्क है। यह रिपॉजिटरी विभिन्न प्रोग्रामिंग भाषाओं में हैंड्स-ऑन कोड उदाहरणों के साथ समग्र शिक्षण सामग्री प्रदान करती है।

### मुख्य तकनीकें

- **प्रोग्रामिंग भाषाएँ**: C#, Java, JavaScript, TypeScript, Python, Rust
- **फ्रेमवर्क और SDKs**:
  - MCP SDK (`@modelcontextprotocol/sdk`)
  - Spring Boot (Java)
  - FastMCP (Python)
  - LangChain4j (Java)
- **डेटाबेस**: PostgreSQL pgvector एक्सटेंशन के साथ
- **क्लाउड प्लेटफ़ॉर्म**: Azure (Container Apps, OpenAI, Content Safety, Application Insights)
- **बिल्ड टूल्स**: npm, Maven, pip, Cargo
- **डॉक्यूमेंटेशन**: स्वचालित बहुभाषी अनुवाद के साथ Markdown (48+ भाषाएँ)

### वास्तुकला

- **11 मुख्य मॉड्यूल (00-11)**: मूल बातों से लेकर उन्नत विषयों तक अनुक्रमिक सीखने का पथ
- **प्रायोगिक प्रयोगशालाएं**: कई भाषाओं में पूर्ण समाधान कोड के साथ व्यावहारिक अभ्यास
- **नमूना परियोजनाएं**: कार्यशील MCP सर्वर और क्लाइंट कार्यान्वयन
- **अनुवाद प्रणाली**: बहुभाषी समर्थन के लिए स्वचालित GitHub Actions वर्कफ़्लो
- **छवि संपत्ति**: केंद्रीकृत छवियां डायरेक्टरी अनूदित संस्करणों के साथ

## सेटअप कमांड

यह एक प्रलेखन-केंद्रित रिपॉजिटरी है। अधिकांश सेटअप व्यक्तिगत नमूना परियोजनाओं और प्रयोगशालाओं में होता है।

### रिपॉजिटरी सेटअप

```bash
# रिपॉजिटरी क्लोन करें
git clone https://github.com/microsoft/mcp-for-beginners.git

```

### नमूना परियोजनाओं के साथ काम करना

नमूना परियोजनाएं स्थित हैं:
- `03-GettingStarted/samples/` - भाषा-विशिष्ट उदाहरण
- `03-GettingStarted/01-first-server/solution/` - पहला सर्वर कार्यान्वयन
- `03-GettingStarted/02-client/solution/` - क्लाइंट कार्यान्वयन
- `11-MCPServerHandsOnLabs/` - व्यापक डेटाबेस इंटीग्रेशन प्रयोगशालाएं

प्रत्येक नमूना परियोजना में अपनी सेटअप निर्देश होते हैं:

#### TypeScript/JavaScript परियोजनाएं
```bash
cd <project-directory>
npm install
npm start
```

#### Python परियोजनाएं
```bash
cd <project-directory>
pip install -r requirements.txt
# या
pip install -e .
python main.py
```

#### Java परियोजनाएं
```bash
cd <project-directory>
mvn clean install
mvn spring-boot:run
```

##### लक्ष्य

पाठ्यक्रम दस्तावेज़ परिवर्तनों और प्रतिनिधि नमूना कोड
के स्वास्थ्य को मर्ज से पहले सत्यापित करें।

##### इनपुट

- `changed_paths: string[]` (आवश्यक) - PR में बदले हुए सापेक्ष पथ।
- `run_docs_lint: boolean` (डिफ़ॉल्ट `true`)
- `run_links_audit: boolean` (डिफ़ॉल्ट `true`)
- `run_samples: { typescript?: boolean, python?: boolean, java?: boolean }`
  (डिफ़ॉल्ट सभी `false`)

##### आउटपुट

- `status: "ok" | "failed"`
- `checks: Array<{ name: string, command: string, exit_code: number,
  summary: string }>`
- `artifacts: Array<{ type: "log" | "report", path: string }>`
- `failed_checks: string[]`

##### अनुमतियाँ

- केवल कार्यक्षेत्र फ़ाइलें पढ़ें और टूल-जनित कलाकृतियाँ लिखें (जैसे, लिंट
  रिपोर्ट, परीक्षण लॉग); `translations/` या
  `translated_images/` में कोई लिखावट नहीं।
- स्थानीय शेल कमांड निष्पादित करें।
- पैकेज पुनर्स्थापन के लिए वैकल्पिक नेटवर्क एक्सेस केवल (`npm ci`,
  `python -m pip install`, `mvn` निर्भरता समाधान)।
- `translations/` या
  `translated_images/` को पुश, मर्ज, या संशोधित करने की अनुमति नहीं।

##### विफलता मोड

- `E_NO_INPUT_PATHS`: `changed_paths` खाली है।
- `E_INVALID_PATH`: इनपुट पथ रिपॉजिटरी रूट से बाहर है।
- `E_LINT_FAILED`: मार्कडाउन लिंट गैर-शून्य के साथ समाप्त हुआ।
- `E_LINK_AUDIT_FAILED`: लिंक ऑडिट कमांड गैर-शून्य के साथ समाप्त हुआ।
- `E_SAMPLE_TEST_FAILED`: नमूना परीक्षण/बिल्ड गैर-शून्य के साथ समाप्त हुआ।
- `E_TIMEOUT`: कमांड विन्यस्त टाइमआउट से अधिक चला गया।

### दस्तावेज़ संरचना

- **मॉड्यूल 00-11**: अनुक्रमिक क्रम में मुख्य पाठ्यक्रम सामग्री
- **translations/**: भाषा-विशिष्ट संस्करण (स्वचालित उत्पन्न, सीधे संपादित न करें)
- **translated_images/**: स्थानीयकृत छवि संस्करण (स्वचालित उत्पन्न)
- **images/**: स्रोत छवियां और आरेख

### दस्तावेज़ परिवर्तनों को करना

1. केवल मूल मॉड्यूल डायरेक्टरीज़ (00-11) में अंग्रेज़ी मार्कडाउन फ़ाइलें संपादित करें
2. आवश्यकता पड़ने पर `images/` डायरेक्टरी में छवियां अपडेट करें
3. सह-ऑप-ट्रांसलेटर GitHub Action स्वतः अनुवाद उत्पन्न करेगा
4. अनुवाद मुख्य शाखा पर पुश करने पर पुनः उत्पन्न होते हैं

### अनुवाद के साथ काम करना

- **स्वचालित अनुवाद**: GitHub Actions वर्कफ़्लो सभी अनुवादों को संभालता है
- `translations/` डायरेक्टरी में फ़ाइलों को मैन्युअल रूप से संपादित न करें
- अनुवाद मेटाडेटा प्रत्येक अनूदित फ़ाइल में एम्बेड किया गया है
- समर्थित भाषाएँ: 48+ भाषाएँ जिनमें अरबी, चीनी, फ्रेंच, जर्मन, हिंदी, जापानी, कोरियाई, पुर्तगाली, रूसी, स्पेनिश, और कई और शामिल हैं

3. **परिवर्तन करें**: केवल अंग्रेज़ी मार्कडाउन फ़ाइलें संपादित करें (अनुवाद नहीं)
4. **लोकली टेस्ट करें**: सत्यापित करें कि मार्कडाउन सही रूप से रेंडर हो रहा है
5. **PR सबमिट करें**: स्पष्ट PR शीर्षक और विवरण का उपयोग करें
6. **CLA**: जब संकेत दिया जाए Microsoft योगदानकर्ता लाइसेंस एग्रीमेंट पर हस्ताक्षर करें

### PR शीर्षक प्रारूप

स्पष्ट, वर्णनात्मक शीर्षक का उपयोग करें:
- मॉड्यूल-विशिष्ट परिवर्तनों के लिए `[Module XX] संक्षिप्त विवरण`
- नमूना कोड परिवर्तनों के लिए `[Samples] विवरण`
- सामान्य प्रलेखन अपडेट के लिए `[Docs] विवरण`

### क्या योगदान करें

- प्रलेखन या कोड नमूनों में बग फिक्स
- अतिरिक्त भाषाओं में नए कोड उदाहरण
- मौजूदा सामग्री की स्पष्टता और सुधार
- नए केस अध्ययनों या व्यावहारिक उदाहरण
- अस्पष्ट या गलत सामग्री के लिए मुद्दा रिपोर्ट

### क्या न करें

- `translations/` डायरेक्टरी की फ़ाइलें सीधे संपादित न करें
- `translated_images/` डायरेक्टरी को संपादित न करें
- बिना चर्चा के बड़े बाइनरी फ़ाइलें न जोड़ें
- समन्वय के बिना अनुवाद वर्कफ़्लो फ़ाइलों को न बदलें
