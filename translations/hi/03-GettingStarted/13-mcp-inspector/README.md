# MCP इंस्पेक्टर के साथ डिबगिंग

> [!NOTE]
> `--sse` का उपयोग करने वाले कमांड और `/sse` पर समाप्त होने वाले URL पुराने HTTP+SSE
> ट्रांसपोर्ट का परीक्षण करते हैं। नए MCP `2026-07-28` सर्वर के लिए, किसी ऐसे इंस्पेक्टर संस्करण का उपयोग करें जो
> Streamable HTTP का समर्थन करता हो और उस ट्रांसपोर्ट को चुनें।

**MCP इंस्पेक्टर** एक आवश्यक डिबगिंग टूल है जो आपको बिना पूर्ण AI होस्ट एप्लिकेशन के अपने MCP सर्वरों को इंटरैक्टिव रूप से टेस्ट और troubleshoot करने देता है। इसे "MCP के लिए Postman" के रूप में सोचें - यह एक विजुअल इंटरफेस प्रदान करता है जो अनुरोध भेजने, प्रतिक्रियाएँ देखने और समझने के लिए कि आपका सर्वर कैसे व्यवहार करता है।

## MCP इंस्पेक्टर क्यों उपयोग करें?

MCP सर्वर बनाते समय, आप अक्सर इन चुनौतियों का सामना करेंगे:

- **"क्या मेरा सर्वर चल भी रहा है?"** - इंस्पेक्टर कनेक्शन स्थिति दिखाता है
- **"क्या मेरे टूल सही तरीके से पंजीकृत हैं?"** - इंस्पेक्टर सभी उपलब्ध टूल सूचीबद्ध करता है
- **"प्रतिक्रिया प्रारूप क्या है?"** - इंस्पेक्टर पूर्ण JSON प्रतिक्रियाएँ दिखाता है
- **"यह टूल क्यों काम नहीं कर रहा?"** - इंस्पेक्टर विस्तार से त्रुटि संदेश दिखाता है

## आवश्यकताएं

- Node.js 18+ स्थापित होना चाहिए
- npm (Node.js के साथ आता है)
- एक MCP सर्वर जिसे टेस्ट किया जा सके (देखें [Module 3.1 - First Server](../01-first-server/README.md))

## स्थापना

### विकल्प 1: npx के साथ चलाएँ (त्वरित परीक्षण के लिए अनुशंसित)

```bash
npx @modelcontextprotocol/inspector
```

### विकल्प 2: ग्लोबली इंस्टॉल करें

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### विकल्प 3: अपने प्रोजेक्ट में जोड़ें

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` में जोड़ें:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## अपने सर्वर से कनेक्ट करना

### stdio सर्वर (स्थानीय प्रक्रिया)

उन सर्वरों के लिए जो स्टैंडर्ड इनपुट/आउटपुट के माध्यम से संवाद करते हैं:

```bash
# पायथन सर्वर
npx @modelcontextprotocol/inspector python -m your_server_module

# नोड.जेएस सर्वर
npx @modelcontextprotocol/inspector node ./build/index.js

# पर्यावरण चर के साथ
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP सर्वर (नेटवर्क)

HTTP सेवाओं के रूप में चलने वाले सर्वरों के लिए:

1. पहले अपने सर्वर को चालू करें:
   ```bash
   python server.py  # सर्वर http://localhost:8080 पर चल रहा है
   ```

2. इंस्पेक्टर लॉन्च करें और कनेक्ट करें:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## टूल्स का परीक्षण

### उपलब्ध टूल्स सूचीबद्ध करना

1. **Tools** टैब पर क्लिक करें
2. इंस्पेक्टर स्वचालित रूप से `tools/list` कॉल करता है
3. आपको सभी पंजीकृत टूल दिखाई देंगे जिनमें शामिल हैं:
   - टूल का नाम
   - विवरण
   - इनपुट स्कीमा (पैरामीटर)

### टूल को कॉल करना

1. सूची से एक टूल चुनें
2. फॉर्म में आवश्यक पैरामीटर भरें
3. **Run Tool** पर क्लिक करें
4. परिणाम पैनल में प्रतिक्रिया देखें

**उदाहरण: एक कैलकुलेटर टूल का परीक्षण**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### टूल त्रुटियों का डिबगिंग

जब कोई टूल विफल होता है, इंस्पेक्टर दिखाता है:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

सामान्य त्रुटि कोड:
| कोड | अर्थ |
|------|---------|
| -32700 | पार्स त्रुटि (अमान्य JSON) |
| -32600 | अमान्य अनुरोध |
| -32601 | मेथड नहीं मिला |
| -32602 | अमान्य पैरामीटर |
| -32603 | आंतरिक त्रुटि |

## संसाधनों का परीक्षण

### संसाधनों की सूची बनाना

1. **Resources** टैब पर क्लिक करें
2. इंस्पेक्टर `resources/list` कॉल करता है
3. आपको दिखाई देगा:
   - संसाधन URI
   - नाम और विवरण
   - MIME प्रकार

### किसी संसाधन को पढ़ना

1. एक संसाधन चुनें
2. **Read Resource** पर क्लिक करें
3. लौटाई गई सामग्री देखें

**उदाहरण आउटपुट:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## प्रॉम्प्ट्स का परीक्षण

### प्रॉम्प्ट्स सूचीबद्ध करना

1. **Prompts** टैब पर क्लिक करें
2. इंस्पेक्टर `prompts/list` कॉल करता है
3. उपलब्ध प्रॉम्प्ट टेम्प्लेट देखें

### प्रॉम्प्ट प्राप्त करना

1. एक प्रॉम्प्ट चुनें
2. आवश्यक तर्क भरें
3. **Get Prompt** पर क्लिक करें
4. प्रस्तुत प्रॉम्प्ट संदेश देखें

## संदेश लॉग विश्लेषण

संदेश लॉग सभी MCP प्रोटोकॉल संदेश दिखाता है। नीचे दिया गया ट्रांसक्रिप्ट एक
पुराने `2025-11-25` सर्वर से है और इसमें हटाए गए `initialize` हैंडशेक शामिल हैं। एक
`2026-07-28` सर्वर सेल्फ-कंटेंड अनुरोध मेटाडेटा और `server/discover`
का उपयोग करता है।

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### क्या देखें

- **अनुरोध/प्रतिक्रिया जोड़े**: प्रत्येक `→` के लिए एक मेल खाने वाला `←` होना चाहिए
- **त्रुटि संदेश**: प्रतिक्रियाओं में `"error"` देखें
- **समय**: बड़े अंतर प्रदर्शन समस्याओं का संकेत हो सकते हैं
- **प्रोटोकॉल संस्करण**: सुनिश्चित करें कि सर्वर और क्लाइंट संस्करण पर सहमत हैं

## सामान्य डिबगिंग परिदृश्य

### परिदृश्य 1: सर्वर कनेक्ट नहीं हो रहा

**लक्षण:** इंस्पेक्टर "Disconnected" दिखाता है या "Connecting..." पर अटक जाता है

**चेकलिस्ट:**
1. ✅ क्या सर्वर कमांड सही है?
2. ✅ क्या सभी निर्भरता स्थापित हैं?
3. ✅ क्या सर्वर पथ पूर्ण है या वर्तमान निर्देशिका के सापेक्ष है?
4. ✅ क्या आवश्यक पर्यावरण वेरिएबल सेट हैं?

**डिबग चरण:**
```bash
# पहले मैन्युअली सर्वर का परीक्षण करें
python -c "import your_server_module; print('OK')"

# आयात त्रुटियों की जांच करें
python -m your_server_module 2>&1 | head -20

# सुनिश्चित करें कि MCP SDK इंस्टॉल किया गया है
pip show mcp
```

### परिदृश्य 2: टूल्स नहीं दिख रहे

**लक्षण:** टूल्स टैब खाली सूची दिखाता है

**संभावित कारण:**
1. सर्वर आरंभीकरण के दौरान टूल्स पंजीकृत नहीं हुए
2. स्टार्टअप के बाद सर्वर क्रैश हो गया
3. `tools/list` हैंडलर खाली ऐरे लौटा रहा है

**डिबग चरण:**
1. संदेश लॉग में `tools/list` प्रतिक्रिया जांचें
2. अपने टूल पंजीकरण कोड में लॉगिंग जोड़ें
3. सत्यापित करें कि `@mcp.tool()` डेकोरेटर्स मौजूद हैं (Python)

### परिदृश्य 3: टूल त्रुटि लौटाता है

**लक्षण:** टूल कॉल त्रुटि प्रतिक्रिया लौटाता है

**डिबग दृष्टिकोण:**
1. त्रुटि संदेश ध्यान से पढ़ें
2. देखें कि पैरामीटर प्रकार स्कीमा से मेल खाते हैं या नहीं
3. विस्तृत त्रुटि संदेशों के साथ try/catch जोड़ें
4. सर्वर लॉग में स्टैक ट्रेस जांचें

**उदाहरण बेहतर त्रुटि हैंडलिंग:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # उपकरण तर्क यहाँ
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### परिदृश्य 4: संसाधन सामग्री खाली है

**लक्षण:** संसाधन लौटा लेकिन सामग्री खाली या null है

**चेकलिस्ट:**
1. ✅ फ़ाइल पथ या URI सही है
2. ✅ सर्वर के पास संसाधन पढ़ने की अनुमति है
3. ✅ संसाधन सामग्री सही लौट रही है

## सर्वोत्तम प्रथाएं

1. **जल्दी और नियमित रूप से परीक्षण करें** - विकास के दौरान इंस्पेक्टर का उपयोग करें, केवल जब चीजें टूटें तब नहीं
2. **सरल शुरुआत करें** - जटिल टूल कॉल से पहले बुनियादी कनेक्टिविटी टेस्ट करें
3. **स्कीमा जांचें** - कई त्रुटियां पैरामीटर प्रकार मेल न खाने से आती हैं
4. **त्रुटि संदेश पढ़ें** - MCP त्रुटियां आमतौर पर वर्णनात्मक होती हैं
5. **इंस्पेक्टर खुला रखें** - विकास के दौरान यह समस्याओं को पकड़ने में मदद करता है
