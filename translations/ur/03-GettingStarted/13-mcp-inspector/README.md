# ایم سی پی انسپکٹر کے ساتھ ڈیبگنگ

> [!NOTE]
> `--sse` استعمال کرنے والے کمانڈز اور URLs جو `/sse` پر ختم ہوتے ہیں وہ لیگیسی HTTP+SSE
> ٹرانسپورٹ کو ٹیسٹ کرتے ہیں۔ نئے MCP `2026-07-28` سرور کے لیے، ایک ایسا انسپکٹر ورژن استعمال کریں جو
> Streamable HTTP کو سپورٹ کرتا ہو اور اس ٹرانسپورٹ کو منتخب کریں۔

**MCP انسپکٹر** ایک اہم ڈیبگنگ ٹول ہے جو آپ کو آپ کے MCP سرورز کو انٹرایکٹو طور پر ٹیسٹ اور مسئلہ حل کرنے دیتا ہے، بغیر یہ کہ آپ کو مکمل AI ہوسٹ ایپلیکیشن کی ضرورت ہو۔ اسے "MCP کے لیے پوسٹ مین" سمجھیں - یہ درخواستیں بھیجنے، جوابات دیکھنے، اور سرور کے رویے کو سمجھنے کے لیے ایک بصری انٹرفیس فراہم کرتا ہے۔

## MCP انسپکٹر کیوں استعمال کریں؟

MCP سرورز بناتے وقت، آپ اکثر درج ذیل چیلنجز کا سامنا کریں گے:

- **"کیا میرا سرور چل رہا ہے؟"** - انسپکٹر کنکشن کی حالت دکھاتا ہے
- **"کیا میرے ٹولز صحیح طریقے سے رجسٹر ہوئے ہیں؟"** - انسپکٹر تمام دستیاب ٹولز کی فہرست دیتا ہے
- **"جواب کا فارمیٹ کیا ہے؟"** - انسپکٹر مکمل JSON جوابات دکھاتا ہے
- **"یہ ٹول کیوں کام نہیں کر رہا؟"** - انسپکٹر تفصیلی ایرر میسجز دکھاتا ہے

## ضروریات

- نوڈ.js 18+ انسٹال شدہ
- npm (جو Node.js کے ساتھ آتا ہے)
- ایک MCP سرور ٹیسٹ کے لیے (دیکھیں [Module 3.1 - First Server](../01-first-server/README.md))

## انسٹالیشن

### آپشن 1: npx کے ساتھ چلائیں (تیز ٹیسٹنگ کے لیے تجویز کردہ)

```bash
npx @modelcontextprotocol/inspector
```

### آپشن 2: گلوبلی انسٹال کریں

```bash
npm install -g @modelcontextprotocol/inspector
mcp-inspector
```

### آپشن 3: اپنے پروجیکٹ میں شامل کریں

```bash
cd your-mcp-server-project
npm install --save-dev @modelcontextprotocol/inspector
```

`package.json` میں شامل کریں:
```json
{
  "scripts": {
    "inspector": "mcp-inspector"
  }
}
```

## اپنے سرور سے کنیکٹ کرنا

### stdio سرورز (مقامی پراسیس)

اُن سرورز کے لیے جو معیاری ان پٹ/آؤٹ پٹ سے بات چیت کرتے ہیں:

```bash
# پائتھن سرور
npx @modelcontextprotocol/inspector python -m your_server_module

# نوڈ.جے ایس سرور
npx @modelcontextprotocol/inspector node ./build/index.js

# ماحول کے متغیرات کے ساتھ
OPENAI_API_KEY=xxx npx @modelcontextprotocol/inspector python server.py
```

### SSE/HTTP سرورز (نیٹ ورک)

HTTP سروسز کے طور پر چلنے والے سرورز کے لیے:

1. پہلے اپنا سرور شروع کریں:
   ```bash
   python server.py  # سرور http://localhost:8080 پر چل رہا ہے
   ```

2. انسپکٹر لانچ کریں اور کنیکٹ کریں:
   ```bash
   npx @modelcontextprotocol/inspector --sse http://localhost:8080/sse
   ```

## ٹولز کی جانچ

### دستیاب ٹولز کی فہرست بنانا

1. **Tools** ٹیب پر کلک کریں
2. انسپکٹر خود بخود `tools/list` کال کرتا ہے
3. آپ کو تمام رجسٹر شدہ ٹولز دکھائی دیں گے جن میں:
   - ٹول کا نام
   - وضاحت
   - ان پٹ اسکیمہ (پیرا میٹرز)

### ٹول کال کرنا

1. فہرست سے ایک ٹول منتخب کریں
2. فارم میں ضرورت کے مطابق پیرا میٹرز بھریں
3. **Run Tool** پر کلک کریں
4. نتائج پینل میں جواب دیکھیں

**مثال: کیلکیولیٹر ٹول کی جانچ**

```
Tool: add
Parameters:
  a: 25
  b: 17

Response:
{
  "content": [
    {
      "type": "text",
      "text": "42"
    }
  ]
}
```

### ٹول کی غلطیوں کی ڈیبگنگ

جب کوئی ٹول ناکام ہوتا ہے، انسپکٹر دکھاتا ہے:

```
Error Response:
{
  "error": {
    "code": -32602,
    "message": "Invalid params: 'b' is required"
  }
}
```

عام غلطی کوڈز:
| کوڈ | معنی |
|------|---------|
| -32700 | پارس ایرر (غلط JSON) |
| -32600 | غلط درخواست |
| -32601 | طریقہ نہیں ملا |
| -32602 | غلط پیرا میٹرز |
| -32603 | اندرونی خرابی |

## وسائل کی جانچ

### وسائل کی فہرست بنانا

1. **Resources** ٹیب پر کلک کریں
2. انسپکٹر `resources/list` کال کرتا ہے
3. آپ دیکھیں گے:
   - ریسورس URIs
   - نام اور وضاحتیں
   - MIME اقسام

### ریسورس پڑھنا

1. ایک ریسورس منتخب کریں
2. **Read Resource** پر کلک کریں
3. واپس آنے والا مواد دیکھیں

**مثال کے طور پر آؤٹ پٹ:**

```
Resource: file:///config/settings.json
Content-Type: application/json

{
  "config": {
    "debug": true,
    "maxConnections": 10
  }
}
```

## پرامپٹس کی جانچ

### پرامپٹس کی فہرست

1. **Prompts** ٹیب پر کلک کریں
2. انسپکٹر `prompts/list` کال کرتا ہے
3. دستیاب پرامپٹ ٹیمپلیٹس دیکھیں

### پرامپٹ حاصل کرنا

1. ایک پرامپٹ منتخب کریں
2. کوئی بھی ضروری دلائل بھریں
3. **Get Prompt** پر کلک کریں
4. رینڈر شدہ پرامپٹ پیغامات دیکھیں

## میسج لاگ تجزیہ

میسج لاگ تمام MCP پروٹوکول میسجز دکھاتا ہے۔ نیچے کا ٹرانسکرپٹ ایک
لیگیسی `2025-11-25` سرور سے ہے اور اس میں ہٹائی گئی `initialize` ہینڈشیک شامل ہے۔ ایک
`2026-07-28` سرور خود مختار درخواست میٹا ڈیٹا اور `server/discover`
استعمال کرتا ہے۔

```
14:32:01 → {"jsonrpc":"2.0","id":1,"method":"initialize",...}
14:32:01 ← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-11-25",...}}
14:32:02 → {"jsonrpc":"2.0","id":2,"method":"tools/list"}
14:32:02 ← {"jsonrpc":"2.0","id":2,"result":{"tools":[...]}}
14:32:05 → {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"add",...}}
14:32:05 ← {"jsonrpc":"2.0","id":3,"result":{"content":[...]}}
```

### کیا دیکھنا ہے

- **درخواست/جواب جوڑے**: ہر `→` کے ساتھ ایک مماثل `←` ہونا چاہیے
- **غلطی کے پیغامات**: جوابات میں `"error"` تلاش کریں
- **ٹائمنگ**: بڑے وقفے کارکردگی کے مسائل کی نشاندہی کر سکتے ہیں
- **پروٹوکول ورژن**: یقینی بنائیں کہ سرور اور کلائنٹ ورژن پر متفق ہوں

## عام ڈیبگنگ کے مناظر

### منظر 1: سرور کنیکٹ نہیں ہوتا

**علامات:** انسپکٹر "Disconnected" دکھاتا ہے یا "Connecting..." پر پھنس جاتا ہے۔

**چیک لسٹ:**
1. ✅ کیا سرور کمانڈ صحیح ہے؟
2. ✅ کیا تمام dependencies انسٹال ہیں؟
3. ✅ کیا سرور کا راستہ موجودہ ڈائریکٹری کے لحاظ سے ایبسولیٹ یا ریلیٹو ہے؟
4. ✅ کیا ضروری ماحول کے متغیرات سیٹ ہیں؟

**ڈیبگ کے مراحل:**
```bash
# پہلے سرور کو دستی طور پر ٹیسٹ کریں
python -c "import your_server_module; print('OK')"

# درآمدی غلطیوں کے لئے چیک کریں
python -m your_server_module 2>&1 | head -20

# تصدیق کریں کہ MCP SDK نصب ہے
pip show mcp
```

### منظر 2: ٹولز نظر نہیں آ رہے

**علامات:** Tools ٹیب میں فہرست خالی دکھائی دیتی ہے

**ممکنہ وجوہات:**
1. سرور کی شروعات میں ٹولز رجسٹر نہیں ہوئے
2. سرور شروع ہونے کے بعد کریش ہو گیا
3. `tools/list` ہینڈلر خالی ارے لوٹا رہا ہے

**ڈیبگ کے مراحل:**
1. `tools/list` جواب کے لیے میسج لاگ چیک کریں
2. اپنے ٹول رجسٹریشن کوڈ میں لاگنگ شامل کریں
3. یقینی بنائیں کہ `@mcp.tool()` ڈیکوریٹرز موجود ہیں (Python)

### منظر 3: ٹول ایرر واپس کرتا ہے

**علامات:** ٹول کال ایرر کا جواب دیتا ہے

**ڈیبگ کے طریقے:**
1. ایرر میسج غور سے پڑھیں
2. پیرا میٹر کی اقسام اسکیمہ سے میل کھاتی ہیں یا نہیں چیک کریں
3. تفصیلی ایرر میسجز کے ساتھ try/catch شامل کریں
4. سرور لاگز میں سٹیک ٹریس چیک کریں

**بہتر ایرر ہینڈلنگ کی مثال:**

```python
@mcp.tool()
async def my_tool(param1: str, param2: int) -> str:
    try:
        # یہاں ٹول لوجک
        result = process(param1, param2)
        return str(result)
    except ValueError as e:
        raise McpError(f"Invalid parameter: {e}")
    except Exception as e:
        raise McpError(f"Tool failed: {type(e).__name__}: {e}")
```

### منظر 4: ریسورس مواد خالی ہے

**علامات:** ریسورس واپس آتا ہے مگر مواد خالی یا null ہوتا ہے

**چیک لسٹ:**
1. ✅ فائل کا راستہ یا URI صحیح ہے
2. ✅ سرور کو ریسورس پڑھنے کی اجازت ہے
3. ✅ ریسورس مواد صحیح طریقے سے واپس آیا ہے

1. میسج پینل میں **Export Log** پر کلک کریں
2. JSON فائل محفوظ کریں

## بہترین طریقے

1. **جلدی اور بار بار ٹیسٹ کریں** - ترقی کے دوران انسپکٹر استعمال کریں، صرف مسئلہ آنے پر نہیں
2. **سادہ سے شروع کریں** - پیچیدہ ٹول کالز سے پہلے بنیادی کنیکٹوٹی ٹیسٹ کریں
3. **اسکیمہ چیک کریں** - اکثر غلطیاں پیرا میٹر کی اقسام کے میل نہ کھانے سے ہوتی ہیں
4. **غلطی کے پیغامات پڑھیں** - MCP کی غلطیاں عموماً وضاحتی ہوتی ہیں
5. **انسپکٹر کو کھلا رکھیں** - یہ آپ کی ترقی میں مسائل کو پکڑنے میں مدد دیتا ہے
