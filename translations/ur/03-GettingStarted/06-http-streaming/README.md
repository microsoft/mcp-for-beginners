# HTTPS کے ساتھ ماڈل کانٹیکسٹ پروٹوکول (MCP) میں اسٹریمنگ

یہ باب HTTPS استعمال کرتے ہوئے ماڈل کانٹیکسٹ پروٹوکول (MCP) کے ساتھ محفوظ، قابل توسیع، اور حقیقی وقت کی اسٹریمنگ کو نافذ کرنے کے لیے ایک جامع رہنما فراہم کرتا ہے۔ یہ اسٹریمنگ کی ترغیب، دستیاب ٹرانسپورٹ میکانزم، MCP میں اسٹریمیبل HTTP کو کیسے نافذ کیا جائے، سیکیورٹی کی بہترین مشقیں، SSE سے مائیگریشن، اور اپنی اسٹریمنگ MCP ایپلیکیشنز کی تعمیر کے لیے عملی رہنمائی شامل کرتا ہے۔

> **آگے دیکھتے ہوئے:** یہ سبق **MCP Specification 2025-11-25** کے تحت اسٹریمیبل HTTP کو بیان کرتا ہے، جہاں ایک سیشن `initialize` کے دوران قائم کیا جاتا ہے اور `Mcp-Session-Id` ہیڈر کے ساتھ پن کیا جاتا ہے۔ `2026-07-28` کا ریلیز کینیڈیٹ ہینڈشیک اور سیشن آئی ڈی کو مکمل طور پر ختم کرتا ہے، جس سے ہر درخواست خود مختار ہوتی ہے اور کسی بھی سرور انسٹانس کے لیے روٹیبل ہوتی ہے بغیر اسٹکی سیشنز کے۔ تفصیلات کے لیے دیکھیں [What's Changing in MCP: The 2026-07-28 Release Candidate](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md)۔

## MCP میں ٹرانسپورٹ میکانزم اور اسٹریمنگ

اس سیکشن میں MCP میں دستیاب مختلف ٹرانسپورٹ میکانزم کو اور ان کے کردار کو دریافت کیا گیا ہے جو کلائنٹ اور سرور کے درمیان حقیقی وقت کی اسٹریمنگ صلاحیتوں کو فعال بناتے ہیں۔

### ٹرانسپورٹ میکانزم کیا ہے؟

ایک ٹرانسپورٹ میکانزم یہ تعین کرتا ہے کہ کلائنٹ اور سرور کے درمیان ڈیٹا کیسے تبادلہ کیا جاتا ہے۔ MCP مختلف ماحول اور ضروریات کے مطابق متعدد ٹرانسپورٹ اقسام کی حمایت کرتا ہے:

- **stdio**: معیاری ان پٹ/آؤٹ پٹ، مقامی اور CLI پر مبنی ٹولز کے لیے موزوں۔ سادہ لیکن ویب یا کلاؤڈ کے لیے مناسب نہیں۔
- **SSE (سرور-سینٹ ایونٹس)**: سرورز کو HTTP کے ذریعے کلائنٹس کو حقیقی وقت میں اپڈیٹس بھیجنے کی اجازت دیتا ہے۔ ویب یوزر انٹرفیس کے لیے اچھا، لیکن توسیع پذیری اور لچک میں محدود۔ MCP Specification 2025-06-18 کے مطابق، اسٹینڈ اَلون SSE (سرور-سینٹ ایونٹس) ٹرانسپورٹ کو ختم کر دیا گیا ہے اور اس کی جگہ "Streamable HTTP" ٹرانسپورٹ نے لے لی ہے۔
- **Streamable HTTP**: جدید HTTP پر مبنی اسٹریمنگ ٹرانسپورٹ، نوٹیفیکیشنز اور بہتر توسیع پذیری کی حمایت کرتا ہے۔ زیادہ تر پروڈکشن اور کلاؤڈ منظرناموں کے لیے سفارش کردہ۔

### تقابلی جدول

نیچے دی گئی جدول کو دیکھیں تاکہ ان ٹرانسپورٹ میکانزمز کے درمیان فرق کو سمجھ سکیں:

| ٹرانسپورٹ          | حقیقی وقت کے اپڈیٹس | اسٹریمنگ | توسیع پذیری | استعمال کا کیس        |
|-------------------|------------------|-----------|-------------|-------------------------|
| stdio             | نہیں             | نہیں      | کم          | مقامی CLI ٹولز         |
| SSE               | ہاں              | ہاں       | درمیانہ     | ویب، حقیقی وقت کی اپڈیٹس |
| Streamable HTTP   | ہاں              | ہاں       | زیادہ       | کلاؤڈ، کثیر صارف       |

> **مشورہ:** درست ٹرانسپورٹ کا انتخاب کارکردگی، توسیع پذیری، اور صارف کے تجربے پر اثر انداز ہوتا ہے۔ **Streamable HTTP** جدید، قابل توسیع، اور کلاؤڈ-ریڈی ایپلیکیشنز کے لیے سفارش کی جاتی ہے۔

سابقہ ابواب میں آپ کو دکھائے گئے stdio اور SSE ٹرانسپورٹس کو نوٹ کریں اور یہ دیکھیں کہ اس باب میں کس طرح اسٹریمیبل HTTP کو احاطہ کیا گیا ہے۔

## اسٹریمنگ: تصورات اور محرکات

اسٹریمنگ کے بنیادی تصورات اور محرکات کو سمجھنا مؤثر حقیقی وقت کے کمیونیکیشن سسٹمز کو نافذ کرنے کے لیے ضروری ہے۔

**اسٹریمنگ** نیٹ ورک پروگرامنگ میں ایک تکنیک ہے جو ڈیٹا کو چھوٹے، سنبھالنے کے قابل حصوں میں یا واقعات کی تسلسل کے طور پر بھیجنے اور وصول کرنے کی اجازت دیتی ہے، پورا جواب تیار ہونے تک انتظار کرنے کے بجائے۔ یہ خاص طور پر مفید ہے:

- بڑے فائلز یا ڈیٹاسیٹس کے لیے۔
- حقیقی وقت کی اپڈیٹس (مثلاً چیٹ، پروگریس بارز)۔
- طویل مدتی حساب کتاب جہاں آپ صارف کو آگاہ رکھنا چاہتے ہیں۔

یہاں آرہے ہیں اسٹریمنگ کے بارے میں آپ کو جو بنیادی باتیں جاننی چاہئیں:

- ڈیٹا کو تدریجی طور پر فراہم کیا جاتا ہے، ایک ساتھ نہیں۔
- کلائنٹ ڈیٹا کو جوں جوں آتا ہے، پراسیس کر سکتا ہے۔
- محسوس ہونے والی تاخیر کو کم کرتا ہے اور صارف کے تجربے کو بہتر بناتا ہے۔

### اسٹریمنگ کیوں استعمال کریں؟

اسٹریمنگ کے استعمال کی وجوہات درج ذیل ہیں:

- صارفین کو فوری فیڈبیک ملتا ہے، صرف آخر میں نہیں۔
- حقیقی وقت کی ایپس اور تیز ردعمل والے یوزر انٹرفیسز کو ممکن بناتا ہے۔
- نیٹ ورک اور کمپیوٹ وسائل کا زیادہ موثر استعمال۔

### آسان مثال: HTTP اسٹریمنگ سرور اور کلائنٹ

یہاں ایک سادہ مثال ہے کہ کس طرح اسٹریمنگ کو نافذ کیا جا سکتا ہے:

#### پائتھون

**سرور (پائتھون، FastAPI اور StreamingResponse استعمال کرتے ہوئے):**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import time

app = FastAPI()

async def event_stream():
    for i in range(1, 6):
        yield f"data: Message {i}\n\n"
        time.sleep(1)

@app.get("/stream")
def stream():
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

**کلائنٹ (پائتھون، requests استعمال کرتے ہوئے):**

```python
import requests

with requests.get("http://localhost:8000/stream", stream=True) as r:
    for line in r.iter_lines():
        if line:
            print(line.decode())
```

یہ مثال دکھاتی ہے کہ سرور کلائنٹ کو پیغامات کی ایک سیریز بھیج رہا ہے جیسے ہی وہ دستیاب ہوتے ہیں، بجائے اس کے کہ تمام پیغامات تیار ہونے کا انتظار کرے۔

**یہ کیسے کام کرتا ہے:**

- سرور ہر پیغام تیار ہونے پر جاری کرتا ہے۔
- کلائنٹ ہر حصہ موصول ہونے پر وصول اور پرنٹ کرتا ہے۔

**ضروریات:**

- سرور کو اسٹریمنگ ریسپانس استعمال کرنا چاہیے (مثلاً، FastAPI میں `StreamingResponse`)۔
- کلائنٹ کو ریسپانس کو اسٹریم کے طور پر پراسیس کرنا چاہیے (`stream=True` requests میں)۔
- مواد کی قسم عام طور پر `text/event-stream` یا `application/octet-stream` ہوتی ہے۔

#### جاوا

**سرور (جاوا، Spring Boot اور Server-Sent Events استعمال کرتے ہوئے):**

```java
@RestController
public class CalculatorController {

    @GetMapping(value = "/calculate", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> calculate(@RequestParam double a,
                                                   @RequestParam double b,
                                                   @RequestParam String op) {
        
        double result;
        switch (op) {
            case "add": result = a + b; break;
            case "sub": result = a - b; break;
            case "mul": result = a * b; break;
            case "div": result = b != 0 ? a / b : Double.NaN; break;
            default: result = Double.NaN;
        }

        return Flux.<ServerSentEvent<String>>just(
                    ServerSentEvent.<String>builder()
                        .event("info")
                        .data("Calculating: " + a + " " + op + " " + b)
                        .build(),
                    ServerSentEvent.<String>builder()
                        .event("result")
                        .data(String.valueOf(result))
                        .build()
                )
                .delayElements(Duration.ofSeconds(1));
    }
}
```

**کلائنٹ (جاوا، Spring WebFlux WebClient استعمال کرتے ہوئے):**

```java
@SpringBootApplication
public class CalculatorClientApplication implements CommandLineRunner {

    private final WebClient client = WebClient.builder()
            .baseUrl("http://localhost:8080")
            .build();

    @Override
    public void run(String... args) {
        client.get()
                .uri(uriBuilder -> uriBuilder
                        .path("/calculate")
                        .queryParam("a", 7)
                        .queryParam("b", 5)
                        .queryParam("op", "mul")
                        .build())
                .accept(MediaType.TEXT_EVENT_STREAM)
                .retrieve()
                .bodyToFlux(String.class)
                .doOnNext(System.out::println)
                .blockLast();
    }
}
```

**جاوا امپلیمنٹیشن نوٹس:**

- اسٹریمنگ کے لیے `Flux` کے ساتھ Spring Boot کے ریئیکٹو اسٹیک کا استعمال کرتا ہے
- `ServerSentEvent` واقعات کی اقسام کے ساتھ ساختہ ایونٹ اسٹریمنگ فراہم کرتا ہے
- `WebClient` `bodyToFlux()` کے ذریعے ریئیکٹو اسٹریمنگ کنزمپشن کو فعال بناتا ہے
- `delayElements()` ایونٹس کے درمیان پراسیسنگ وقت کی نقل کرتا ہے
- ایونٹس کی مختلف اقسام ہو سکتی ہیں (`info`, `result`) بہتر کلائنٹ ہینڈلنگ کے لیے

### موازنہ: کلاسیکی اسٹریمنگ بمقابلہ MCP اسٹریمنگ

کلاسیکی طریقے سے اسٹریمنگ کے کام کرنے اور MCP میں اسٹریمنگ کے کام کرنے کے طریقہ میں فرق کو یوں دکھایا جا سکتا ہے:

| خصوصیت              | کلاسیک HTTP اسٹریمنگ           | MCP اسٹریمنگ (نوٹیفیکیشنز)     |
|------------------------|-----------------------------|-------------------------------------|
| مرکزی جواب            | چنک شدہ                      | واحد، آخر میں                     |
| پیشرفت کی اپڈیٹس        | ڈیٹا چنکس کے طور پر بھیجی جاتی ہیں | نوٹیفیکیشنز کے طور پر بھیجی جاتی ہیں   |
| کلائنٹ کی ضروریات       | اسٹریم کا پراسیس کرنا ضروری    | پیغام ہینڈلر نافذ کرنا ضروری      |
| استعمال کا کیس          | بڑی فائلز، AI ٹوکن اسٹریمز    | پیشرفت، لاگز، حقیقی وقت کا فیڈبیک  |

### کلیدی فرق

اس کے علاوہ، یہاں کچھ کلیدی فرق نمایاں کیے گئے ہیں:

- **کمیونیکیشن پیٹرن:**
  - کلاسیک HTTP اسٹریمنگ: سادہ چنکڈ ٹرانسفر انکوڈنگ استعمال کرتا ہے ڈیٹا کو چنکس میں بھیجنے کے لیے
  - MCP اسٹریمنگ: JSON-RPC پروٹوکول کے ساتھ ساختہ نوٹیفیکیشن سسٹم استعمال کرتا ہے

- **پیغام کی شکل:**
  - کلاسیک HTTP: سادہ ٹیکسٹ چنکس نئی لائنز کے ساتھ
  - MCP: ساختہ LoggingMessageNotification اشیاء میٹا ڈیٹا کے ساتھ

- **کلائنٹ امپلیمنٹیشن:**
  - کلاسیک HTTP: ایک سادہ کلائنٹ جو اسٹریمنگ ریسپانسز کو پراسیس کرتا ہے
  - MCP: زیادہ پیچیدہ کلائنٹ جو مختلف اقسام کے پیغامات پراسیس کرنے کے لیے پیغام ہینڈلر رکھتا ہے

- **پیشرفت کی اپڈیٹس:**
  - کلاسیک HTTP: پیشرفت مرکزی ریسپانس اسٹریم کا حصہ ہوتی ہے
  - MCP: پیشرفت علاحدہ نوٹیفیکیشن پیغامات کے ذریعے بھیجی جاتی ہے جب کہ مرکزی ریسپانس آخر میں آتا ہے

### سفارشات

ذیل میں کچھ سفارشات ہیں جب کلاسیکی اسٹریمنگ (جیسا کہ اوپر `/stream` کے ذریعے دکھایا گیا) اور MCP کے ذریعے اسٹریمنگ کے انتخاب کا تعلق ہو:

- **سادہ اسٹریمنگ کی ضرورتوں کے لیے:** کلاسیکی HTTP اسٹریمنگ نافذ کرنا آسان اور بنیادی اسٹریمنگ کے لیے کافی ہے۔

- **پیچیدہ، انٹرایکٹو ایپلیکیشنز کے لیے:** MCP اسٹریمنگ ایک زیادہ ساختہ نقطہ نظر فراہم کرتا ہے جس میں امیر میٹاڈیٹا اور نوٹیفیکیشنز اور حتمی نتائج کے درمیان تفریق ہوتی ہے۔

- **AI ایپلیکیشنز کے لیے:** MCP کا نوٹیفیکیشن سسٹم طویل مدتی AI کاموں کے لیے خاص طور پر مفید ہے جہاں آپ صارفین کو پیشرفت کی اطلاع دینا چاہتے ہیں۔

## MCP میں اسٹریمنگ

تو، آپ نے اب تک کلاسیکی اسٹریمنگ اور MCP میں اسٹریمنگ کے مابین بعض سفارشات اور موازنہ دیکھا ہے۔ آئیے تفصیل سے دیکھتے ہیں کہ آپ MCP میں اسٹریمنگ کا فائدہ کیسے اٹھا سکتے ہیں۔

MCP کے فریم ورک کے اندر اسٹریمنگ کیسے کام کرتی ہے اسے سمجھنا ایسے ایپلیکیشنز بنانے کے لیے ضروری ہے جو طویل عرصے تک چلنے والے آپریشنز کے دوران صارفین کو حقیقی وقت میں فیڈبیک فراہم کرے۔

MCP میں، اسٹریمنگ کا مطلب مرکزی جواب کو چنکوں میں بھیجنا نہیں بلکہ درخواست پراسیس کرتے وقت کلائنٹ کو **نوٹیفیکیشنز** بھیجنا ہے۔ یہ نوٹیفیکیشنز پیشرفت کی اپڈیٹس، لاگز، یا دیگر واقعات شامل ہو سکتے ہیں۔

### یہ کیسے کام کرتا ہے

مرکزی نتیجہ اب بھی ایک واحد ریسپانس کے طور پر بھیجا جاتا ہے۔ تاہم، پراسیسنگ کے دوران نوٹیفیکیشنز کو علاحدہ پیغامات کے طور پر بھیجا جا سکتا ہے اور اس طرح کلائنٹ کو حقیقی وقت میں اپڈیٹ کیا جا سکتا ہے۔ کلائنٹ کو ان نوٹیفیکیشنز کو ہینڈل کرنے اور دکھانے کے قابل ہونا چاہیے۔

## نوٹیفیکیشن کیا ہے؟

ہم نے "نوٹیفیکیشن" کا ذکر کیا، MCP کے سیاق و سباق میں اس کا کیا مطلب ہے؟

ایک نوٹیفیکیشن سرور سے کلائنٹ کو بھیجا جانے والا پیغام ہے جو طویل عرصے تک چلنے والے آپریشن کے دوران پیشرفت، حیثیت، یا دیگر واقعات کی اطلاع دیتا ہے۔ نوٹیفیکیشنز شفافیت اور صارف کے تجربے کو بہتر بناتی ہیں۔

مثال کے طور پر، ایک کلائنٹ کو سرور کے ساتھ ابتدائی ہینڈشیک مکمل ہونے کے بعد نوٹیفیکیشن بھیجنی چاہیے۔

نوٹیفیکیشن ایک JSON پیغام کی طرح دکھتی ہے:

```json
{
  jsonrpc: "2.0";
  method: string;
  params?: {
    [key: string]: unknown;
  };
}
```

نوٹیفیکیشن MCP میں ["Logging"](https://modelcontextprotocol.io/specification/draft/server/utilities/logging) کے موضوع سے متعلق ہوتی ہیں۔

> **متروک ہونے کا نوٹس:** `2026-07-28` MCP وضاحت کا ریلیز کینیڈیٹ لاگنگ پرمیٹیو کو متروک قرار دیتا ہے، stdio ٹرانسپورٹس کے لیے `stderr` اور ساختہ اوزر ویبیلٹی کے لیے OpenTelemetry کو ترجیح دیتا ہے۔ لاگنگ `2025-11-25` میں اور کسی رسمی متروک ہونے کے بعد کم از کم ایک سال تک کام جاری رکھتی ہے۔ مزید معلومات کے لیے دیکھیں [What's Changing in MCP: The 2026-07-28 Release Candidate](../../01-CoreConcepts/mcp-2026-07-28-release-candidate.md)۔

لاگنگ کو فعال کرنے کے لیے سرور کو اسے فیچر/صلاحیت کے طور پر فعال کرنا پڑتا ہے جیسا کہ درج ذیل ہے:

```json
{
  "capabilities": {
    "logging": {}
  }
}
```

> [!NOTE]
> استعمال شدہ SDK کے لحاظ سے، لاگنگ شاید ڈیفالٹ فعال ہو، یا آپ کو اسے سرور کی تشکیل میں واضح طور پر فعال کرنا پڑے۔

مختلف قسم کی نوٹیفیکیشنز ہوتی ہیں:

| سطح         | وضاحت                         | مثال کا استعمال             |
|-------------|------------------------------|-----------------------------|
| debug       | تفصیلی ڈیبگنگ معلومات        | فنکشن انٹری/ایگزٹ پوائنٹس  |
| info        | عمومی معلوماتی پیغامات      | آپریشن کی پیشرفت کی اپڈیٹس  |
| notice      | عام لیکن اہم واقعات          | کنفیگریشن تبدیلیاں         |
| warning     | وارننگ کی حالتیں            | متروک فیچر کا استعمال       |
| error       | ایرر کی حالتیں               | آپریشن کی ناکامیاں         |
| critical    | سنگین حالتیں                | نظام کے اجزاء کی ناکامیاں    |
| alert       | فوری کارروائی ضروری ہے         | ڈیٹا کی کرپشن کا پتا       |
| emergency   | نظام ناقابل استعمال ہے       | مکمل نظام کی خرابی          |

## MCP میں نوٹیفیکیشنز کا نفاذ

MCP میں نوٹیفیکیشنز نافذ کرنے کے لیے، آپ کو دونوں سرور اور کلائنٹ سائیڈز کو حقیقی وقت کی اپڈیٹس سنبھالنے کے لیے تیار کرنا ہوگا۔ اس سے آپ کی ایپلیکیشن طویل آپریشنز کے دوران صارفین کو فوری فیڈبیک دے سکتی ہے۔

### سرور-سائیڈ: نوٹیفیکیشنز بھیجنا

چلیں سرور سائیڈ سے شروع کرتے ہیں۔ MCP میں، آپ ایسے ٹولز کی تعریف کرتے ہیں جو درخواستوں کی پراسیسنگ کے دوران نوٹیفیکیشن بھیج سکتے ہیں۔ سرور کلائنٹ کو پیغامات بھیجنے کے لیے کانٹیکسٹ آبجیکٹ (عام طور پر `ctx`) استعمال کرتا ہے۔

#### پائتھون

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    await ctx.info("Processing file 1/3...")
    await ctx.info("Processing file 2/3...")
    await ctx.info("Processing file 3/3...")
    return TextContent(type="text", text=f"Done: {message}")
```

پچھلے مثال میں، `process_files` ٹول کلائنٹ کو تین نوٹیفیکیشنز بھیجتا ہے جیسا کہ یہ ہر فائل کو پراسیس کرتا ہے۔ `ctx.info()` میتھڈ معلوماتی پیغامات بھیجنے کے لیے استعمال ہوتا ہے۔

اضافی طور پر، نوٹیفیکیشنز کو فعال کرنے کے لیے، یقینی بنائیں کہ آپ کا سرور ایک اسٹریمنگ ٹرانسپورٹ (جیسے `streamable-http`) استعمال کرتا ہے اور آپ کا کلائنٹ نوٹیفیکیشنز پراسیس کرنے کے لیے پیغام ہینڈلر نافذ کرتا ہے۔ یہاں یہ ہے کہ آپ سرور کو `streamable-http` ٹرانسپورٹ کے لیے کیسے سیٹ کریں:

```python
mcp.run(transport="streamable-http")
```

#### .NET

```csharp
[Tool("A tool that sends progress notifications")]
public async Task<TextContent> ProcessFiles(string message, ToolContext ctx)
{
    await ctx.Info("Processing file 1/3...");
    await ctx.Info("Processing file 2/3...");
    await ctx.Info("Processing file 3/3...");
    return new TextContent
    {
        Type = "text",
        Text = $"Done: {message}"
    };
}
```

اس .NET مثال میں، `ProcessFiles` ٹول `Tool` ایٹریبیوٹ کے ساتھ سجا ہوا ہے اور ہر فائل کو پراسیس کرتے ہوئے کلائنٹ کو تین نوٹیفیکیشنز بھیجتا ہے۔ `ctx.Info()` میتھڈ معلوماتی پیغامات بھیجنے کے لیے استعمال ہوتا ہے۔

اپنی .NET MCP سرور میں نوٹیفیکیشنز کو فعال کرنے کے لیے، یقینی بنائیں کہ آپ اسٹریمنگ ٹرانسپورٹ استعمال کر رہے ہیں:

```csharp
var builder = McpBuilder.Create();
await builder
    .UseStreamableHttp() // Enable streamable HTTP transport
    .Build()
    .RunAsync();
```

### کلائنٹ-سائیڈ: نوٹیفیکیشنز وصول کرنا

کلائنٹ کو ایک پیغام ہینڈلر نافذ کرنا ہوگا جو آنے والی نوٹیفیکیشنز کو پراسیس اور دکھا سکے۔

#### پائتھون

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)

async with ClientSession(
   read_stream, 
   write_stream,
   logging_callback=logging_collector,
   message_handler=message_handler,
) as session:
```

پچھلے کوڈ میں، `message_handler` فنکشن چیک کرتا ہے کہ آیا آنے والا پیغام نوٹیفیکیشن ہے۔ اگر ہے، تو یہ نوٹیفیکیشن کو پرنٹ کرتا ہے؛ ورنہ اسے ایک معمول کے سرور پیغام کے طور پر پراسیس کرتا ہے۔ نیز نوٹ کریں کہ `ClientSession` کو نوٹیفیکیشنز کو سنبھالنے کے لیے `message_handler` کے ساتھ انیشیئلائز کیا گیا ہے۔

#### .NET

```csharp
// Define a message handler
void MessageHandler(IJsonRpcMessage message)
{
    if (message is ServerNotification notification)
    {
        Console.WriteLine($"NOTIFICATION: {notification}");
    }
    else
    {
        Console.WriteLine($"SERVER MESSAGE: {message}");
    }
}

// Create and use a client session with the message handler
var clientOptions = new ClientSessionOptions
{
    MessageHandler = MessageHandler,
    LoggingCallback = (level, message) => Console.WriteLine($"[{level}] {message}")
};

using var client = new ClientSession(readStream, writeStream, clientOptions);
await client.InitializeAsync();

// Now the client will process notifications through the MessageHandler
```

اس .NET مثال میں، `MessageHandler` فنکشن چیک کرتا ہے کہ آیا آنے والا پیغام نوٹیفیکیشن ہے۔ اگر ہے، تو یہ نوٹیفیکیشن کو پرنٹ کرتا ہے؛ ورنہ اسے ایک معمول کے سرور پیغام کے طور پر پراسیس کرتا ہے۔ `ClientSession` کو پیغام ہینڈلر کے ساتھ `ClientSessionOptions` کے ذریعے انیشیئلائز کیا گیا ہے۔

نوٹیفیکیشنز کو فعال کرنے کے لیے، یقینی بنائیں کہ آپ کا سرور اسٹریمنگ ٹرانسپورٹ (جیسے `streamable-http`) استعمال کرتا ہے اور آپ کا کلائنٹ نوٹیفیکیشنز پراسیس کرنے کے لیے پیغام ہینڈلر نافذ کرتا ہے۔

## پیشرفت کی نوٹیفیکیشنز اور منظرنامے

یہ سیکشن MCP میں پیشرفت کی نوٹیفیکیشنز کے تصور، ان کی اہمیت، اور Streamable HTTP کے استعمال سے ان کے نفاذ کی وضاحت کرتا ہے۔ ساتھ ہی کوئی عملی مشق بھی شامل ہے تاکہ آپ کی سمجھ کو مضبوط کیا جا سکے۔

پیشرفت کی نوٹیفیکیشنز سرور سے کلائنٹ کو طویل آپریشنز کے دوران بھیجے جانے والے حقیقی وقت کے پیغامات ہیں۔ پورے عمل کے ختم ہونے کا انتظار کرنے کی بجائے، سرور کلائنٹ کو موجودہ صورتحال کے بارے میں اپ ڈیٹ رکھتا ہے۔ یہ شفافیت، صارف کے تجربے کو بہتر بناتا ہے، اور ڈیبگنگ کو آسان بناتا ہے۔

**مثال:**

```text

"Processing document 1/10"
"Processing document 2/10"
...
"Processing complete!"

```

### پیشرفت کی نوٹیفیکیشنز کیوں استعمال کریں؟

پیشرفت کی نوٹیفیکیشنز چند وجوہات کے لیے ضروری ہیں:

- **بہتر صارف تجربہ:** صارفین کام کی پیشرفت کو دیکھتے ہیں، صرف آخر میں نہیں۔
- **حقیقی وقت فیڈبیک:** کلائنٹس پروگریس بارز یا لاگز دکھا سکتے ہیں، ایپ کو تیز محسوس کرواتے ہیں۔
- **آسان ڈیبگنگ اور مانیٹرنگ:** ڈویلپرز اور صارفین دیکھ سکتے ہیں کہ عمل کہاں سست یا رکا ہوا ہے۔

### پیشرفت کی نوٹیفیکیشنز کو کیسے نافذ کریں

یہاں یہ ہے کہ آپ MCP میں پیشرفت کی نوٹیفیکیشنز کیسے نافذ کر سکتے ہیں:

- **سرور پر:** `ctx.info()` یا `ctx.log()` استعمال کریں تاکہ نوٹیفیکیشنز بھیجیں جیسے ہی ہر آئٹم پراسیس ہو۔ یہ کلائنٹ کو مرکزی نتیجہ تیار ہونے سے پہلے پیغام بھیجتا ہے۔
- **کلائنٹ پر:** ایک پیغام ہینڈلر نافذ کریں جو نوٹیفیکیشنز کو سنتا اور دکھاتا ہے جیسے ہی وہ آتی ہیں۔ یہ ہینڈلر نوٹیفیکیشنز اور حتمی نتیجہ میں فرق کرتا ہے۔

**سرور کی مثال:**


#### پائیتھن

```python
@mcp.tool(description="A tool that sends progress notifications")
async def process_files(message: str, ctx: Context) -> TextContent:
    for i in range(1, 11):
        await ctx.info(f"Processing document {i}/10")
    await ctx.info("Processing complete!")
    return TextContent(type="text", text=f"Done: {message}")
```

**کلائنٹ کی مثال:**

#### پائیتھن

```python
async def message_handler(message):
    if isinstance(message, types.ServerNotification):
        print("NOTIFICATION:", message)
    else:
        print("SERVER MESSAGE:", message)
```

## حفاظتی غور و فکر

کسی بھی سرور کو لاگو کرتے وقت سیکیورٹی کو اولین ترجیح دینی چاہیے، خاص طور پر جب HTTP پر مبنی ٹرانسپورٹ جیسے MCP میں Streamable HTTP استعمال کیا جا رہا ہو۔

جب MCP سرورز کو HTTP پر مبنی ٹرانسپورٹ کے ساتھ نافذ کیا جا رہا ہو، تو سیکیورٹی ایک اہم مسئلہ بن جاتی ہے جس کے لیے متعدد حملوں کے ذرائع اور حفاظتی طریقہ کار پر محتاط توجہ کی ضرورت ہوتی ہے۔

### جائزہ

MCP سرورز کو HTTP کے ذریعے ضبط کرتے وقت سیکیورٹی انتہائی اہم ہوتی ہے۔ Streamable HTTP نئے حملوں کے مواقع فراہم کرتا ہے اور محتاط ترتیب کی ضرورت ہوتی ہے۔

یہاں کچھ اہم حفاظتی غور و فکر درج ہیں:

- **اصل ہیڈر کی تصدیق**: DNS ریبائنڈنگ حملوں کو روکنے کے لیے ہمیشہ `Origin` ہیڈر کی تصدیق کریں۔
- **لوکل ہوسٹ بائنڈنگ**: مقامی ترقی کے لیے، سرورز کو `localhost` سے بائنڈ کریں تاکہ انہیں عوامی انٹرنیٹ پر ظاہر نہ کیا جائے۔
- **توثیق**: پیداواری تنصیبات کے لیے توثیق نافذ کریں (مثلاً API کیز، OAuth)۔
- **CORS**: رسائی کو محدود کرنے کے لیے کراس-اوریجن ریسورس شیئرنگ (CORS) پالیسیاں ترتیب دیں۔
- **HTTPS**: ٹریفک کو انکرپٹ کرنے کے لیے پیداوار میں HTTPS استعمال کریں۔

### بہترین طریقے

مزید برآں، اپنے MCP اسٹریمنگ سرور میں سیکیورٹی نافذ کرتے وقت یہ بہترین طریقے اپنانا ضروری ہے:

- آنے والی درخواستوں پر بغیر تصدیق کے کبھی بھروسہ نہ کریں۔
- تمام رسائی اور غلطیوں کا لاگ اور نگرانی کریں۔
- سیکیورٹی خامیوں کو ٹھیک کرنے کے لیے باقاعدگی سے انحصارات کو اپ ڈیٹ کریں۔

### چیلنجز

MCP اسٹریمنگ سرورز میں سیکیورٹی نافذ کرتے وقت آپ کو کچھ چیلنجز کا سامنا کرنا پڑے گا:

- ترقی کی آسانی کے ساتھ سیکیورٹی کا توازن قائم کرنا
- مختلف کلائنٹ ماحولیات کے ساتھ مطابقت کو یقینی بنانا


## SSE سے Streamable HTTP میں اپ گریڈ کرنا

جو ایپلیکیشنز فی الحال Server-Sent Events (SSE) استعمال کر رہی ہیں، ان کے لیے Streamable HTTP پر منتقلی بہتر صلاحیتیں اور MCP عمل درآمد کے لیے طویل مدتی پائیداری فراہم کرتی ہے۔

### کیوں اپ گریڈ کریں؟

SSE سے Streamable HTTP میں اپ گریڈ کرنے کے دو مضبوط وجوہات ہیں:

- Streamable HTTP SSE کے مقابلے میں بہتر اسکیل ایبلٹی، مطابقت، اور زیادہ متنوع نوٹیفکیشن سپورٹ فراہم کرتا ہے۔
- یہ نئے MCP ایپلیکیشنز کے لیے تجویز کردہ ٹرانسپورٹ ہے۔

### مائیگریشن کے مراحل

اپنے MCP ایپلیکیشنز میں SSE سے Streamable HTTP پر منتقلی کے طریقے درج ذیل ہیں:

- **سرور کوڈ اپ ڈیٹ کریں** تاکہ `mcp.run()` میں `transport="streamable-http"` استعمال ہو۔
- **کلائنٹ کوڈ کو اپ ڈیٹ کریں** تاکہ SSE کلائنٹ کی جگہ `streamablehttp_client` استعمال کیا جائے۔
- **کلائنٹ میں ایک میسج ہینڈلر نافذ کریں** جو نوٹیفکیشنز کو پروسیس کرے۔
- **موجودہ آلات اور ورک فلو کے ساتھ مطابقت کی جانچ کریں**۔

### مطابقت برقرار رکھنا

مائیگریشن کے دوران موجودہ SSE کلائنٹس کے ساتھ مطابقت برقرار رکھنا تجویز کیا جاتا ہے۔ یہاں کچھ حکمت عملی ہیں:

- آپ دونوں SSE اور Streamable HTTP کی حمایت کر سکتے ہیں اگر دونوں ٹرانسپورٹ مختلف اینڈپوائنٹس پر چلائیں۔
- کلائنٹس کو نئے ٹرانسپورٹ کی طرف بتدریج مائیگریٹ کریں۔

### چیلنجز

مائیگریشن کے دوران درج ذیل چیلنجز کو حل کرنا ضروری ہے:

- یقینی بنائیں کہ تمام کلائنٹس کو اپ ڈیٹ کیا گیا ہے
- نوٹیفکیشن ڈیلیوری میں فرق کو ہینڈل کرنا

### Assignment: اپنا اسٹریمنگ MCP ایپ بنائیں

**منظرنامہ:**
ایک MCP سرور اور کلائنٹ بنائیں جہاں سرور ایک اشیاء کی فہرست (جیسے فائلز یا دستاویزات) کو پروسیس کرے اور ہر پراسیس کی گئی آئٹم کے لیے ایک نوٹیفکیشن بھیجے۔ کلائنٹ کو ہر نوٹیفکیشن کو پہنچتے ہی ظاہر کرنا چاہیے۔

**مراحل:**

1. ایک سرور ٹول نافذ کریں جو فہرست کو پروسیس کرے اور ہر آئٹم کے نوٹیفکیشن بھیجے۔
2. ایک کلائنٹ نافذ کریں جس میں میسج ہینڈلر ہو جو نوٹیفکیشن کو حقیقی وقت میں دکھائے۔
3. اپنے عمل درآمد کی جانچ کریں، دونوں سرور اور کلائنٹ کو چلائیں، اور نوٹیفکیشنز کا مشاہدہ کریں۔
