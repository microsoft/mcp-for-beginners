## 🎯 נושאי המעבדה הזאת

מעבדת מבוא זו מספקת סקירה מקיפה לבניית שרתי Model Context Protocol (MCP) עם אינטגרציה למסד נתונים. תלמדו את המקרה העסקי, הארכיטקטורה הטכנית, ויישומים מעשיים דרך מקרה השימוש של ניתוחי Zava Retail בכתובת https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail.

## סקירה כללית

**Model Context Protocol (MCP)** מאפשר לעוזרי בינה מלאכותית לגשת בצורה מאובטחת ולפעול על מקורות נתונים חיצוניים בזמן אמת. בשילוב עם אינטגרציה למסד נתונים, MCP משחרר יכולות חזקות ליישומים מונעי נתונים בבינה מלאכותית.

מסלול הלמידה הזה ילמד אתכם לבנות שרתי MCP מוכנים לייצור שמחברים עוזרי בינה מלאכותית לנתוני מכירות קמעונאיים דרך PostgreSQL, תוך יישום דפוסי ארגונים כגון אבטחה ברמת שורה, חיפוש סמנטי, וגישה לנתונים מרובי דיירים.

## 🧭 האתגר: בינה מלאכותית ונתונים מעולם אמיתי

### מגבלות בינה מלאכותית מסורתית

עוזרי בינה מלאכותית מודרניים הם בעלי עוצמה רבה אך נתקלים במגבלות משמעותיות בעת עבודה עם נתוני עסקיים מעולם אמיתי:

| **אתגר** | **תיאור** | **השפעה עסקית** |
|---------------|-----------------|-------------------|
| **ידע סטטי** | דגמי בינה מלאכותית שעברו אימון על מערכי נתונים קבועים לא יכולים לגשת לנתוני עסקים עדכניים | תובנות מיושנות, הזדמנויות שנפספסו |
| **מחסומי נתונים** | מידע הכלוא במסדי נתונים, API ומערכות שאליהם בינה מלאכותית לא יכולה להגיע | ניתוח חלקי, תהליכי עבודה מפוזרים |
| **מגבלות אבטחה** | גישה ישירה למסד נתונים מעלה חששות אבטחה ועמידה בדרישות רגולטוריות | פריסה מוגבלת, הכנת נתונים ידנית |
| **שאילתות מורכבות** | משתמשים עסקיים זקוקים לידע טכני כדי לשלוף תובנות נתונים | אימוץ מופחת, תהליכים לא יעילים |

### הפתרון של MCP

Model Context Protocol מתמודד עם אתגרים אלה באמצעות:

- **גישה לנתונים בזמן אמת**: עוזרי בינה מלאכותית שואלים מסדי נתונים ו-API חיים
- **אינטגרציה מאובטחת**: גישה מבוקרת עם אימות והרשאות
- **ממשק שפה טבעית**: משתמשים עסקיים שואלים שאלות באנגלית פשוטה
- **פרוטוקול סטנדרטי**: פועל על פני פלטפורמות וכלים שונים של בינה מלאכותית

## 🏪 הכירו את Zava Retail: מקרה מבחן ללמידה https://github.com/microsoft/MCP-Server-and-PostgreSQL-Sample-Retail

לאורך מסלול הלמידה הזה, נבנה שרת MCP עבור **Zava Retail**, רשת קמעונאית דמיונית לעשה זאת בעצמך עם מספר מיקומי חנות. התרחיש הריאלי הזה מדגים יישום MCP ברמה ארגונית.

### הקשר עסקי

**Zava Retail** מפעילה:
- **8 חנויות פיזיות** ברחבי מדינת וושינגטון (סיאטל, בלוויו, טקומה, ספוקן, אברט, רדמונד, קירקלנד)
- **חנות אחת מקוונת** למכירות מסחר אלקטרוני
- **קטלוג מוצרים מגוון** הכולל כלים, חומרה, ציוד גינון וחומרי בניין
- **ניהול ברמות מרובות** עם מנהלי חנויות, מנהלי אזור, ומנהלים בכירים

### דרישות עסקיות

מנהלי חנויות ובכירים צריכים ניתוחים מבוססי בינה מלאכותית כדי:

1. **לנתח ביצועי מכירות** ברחבי החנויות ותקופות זמן שונות
2. **לעקוב אחר רמות מלאי** ולזהות צרכי מילוי
3. **להבין התנהגות לקוחות** ותבניות רכישה
4. **לגלות תובנות על מוצרים** באמצעות חיפוש סמנטי
5. **לייצר דוחות** באמצעות שאילתות בשפה טבעית
6. **לשמור על אבטחת נתונים** באמצעות בקרת גישה מבוססת תפקיד

### דרישות טכניות

שרת MCP חייב לספק:

- **גישה מרובה דיירים לנתונים** שבה מנהלי החנויות רואים רק את נתוני החנות שלהם
- **שאילתות גמישות** התומכות בפעולות SQL מורכבות
- **חיפוש סמנטי** לגילוי מוצרים והמלצות
- **נתוני זמן אמת** המשקפים את מצב העסק הנוכחי
- **אימות מאובטח** עם אבטחה ברמת שורה
- **ארכיטקטורה מדרגת** התומכת במספר משתמשים במקביל

### רכיבים מרכזיים

#### **1. שכבת שרת MCP**
- **FastMCP Framework**: יישום מודרני של שרת MCP בפייתון
- **רישום כלים**: הגדרות כלים דקלרטיביות עם בטיחות טיפוסים
- **הקשר בקשה**: ניהול זהות משתמשים ומפגשים
- **טיפול בשגיאות**: ניהול לוג שגיאות חסון

#### **2. שכבת אינטגרציית מסד נתונים**
- **קישורית בריכה**: ניהול קישורי asyncpg יעיל
- **מספק סכימות**: גילוי דינמי של סכימות טבלאות
- **מבצע שאילתות**: ביצוע בטוח של SQL עם הקשר RLS
- **ניהול עסקאות**: עמידה ב-ACID וטיפול בביטול

#### **3. שכבת אבטחה**
- **אבטחה ברמת שורה**: PostgreSQL RLS לבידוד נתונים מרובי דיירים
- **זהות משתמש**: אימות הרשאות ומנהל חנות
- **בקרת גישה**: הרשאות מדויקות ומעקב אחר גישה
- **ולידציה לקלט**: מניעת SQL Injection ואימות שאילתות

#### **4. שכבת שיפור בינה מלאכותית**
- **חיפוש סמנטי**: הטמעות וקטוריות לגילוי מוצרים
- **אינטגרציית Azure OpenAI**: יצירת הטמעות טקסטואליות
- **אלגוריתמים של דמיון**: חיפוש דמיון קוסינוס באמצעות pgvector
- **אופטימיזציית חיפוש**: אינדוקס וכוונון ביצועים

## 🔒 אבטחה וחשיפה לעומק רב-דיירים

היישום שלנו מדגיש אבטחה ברמת ארגון:

### אבטחה ברמת שורה (RLS)

PostgreSQL RLS מבטיחה בידוד נתונים:

```sql
-- Store managers see only their store's data
CREATE POLICY store_manager_policy ON retail.orders
  FOR ALL TO store_managers
  USING (store_id = get_current_user_store());

-- Regional managers see multiple stores
CREATE POLICY regional_manager_policy ON retail.orders
  FOR ALL TO regional_managers
  USING (store_id = ANY(get_user_store_list()));
```

כל חיבור MCP כולל:
- **מזהה מנהל חנות**: מזהה ייחודי להקשר RLS
