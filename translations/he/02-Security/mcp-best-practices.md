# שיטות אבטחה מיטביות עבור MCP - עדכון ספטמבר 2026

מדריך מקיף זה מפרט שיטות אבטחה חיוניות ליישום מערכות פרוטוקול הקשר לדגם (MCP) המבוססות על
**מפרט MCP 2026-07-28** ועל תקני התעשייה הנוכחיים. שיטות אלו
מתייחסות הן לחששות אבטחה מסורתיים והן לאיומי AI ספציפיים
הייחודיים לפריסות MCP.


## דרישות אבטחה קריטיות

### בקרות אבטחה מחייבות (דרישות MUST)

1. **אימות אסימונים**: שרתי MCP **אסור שיקבלו** אסימונים שלא הונפקו במפורש עבור שרת MCP עצמו
2. **אימות הרשאה**: שרתי MCP המיישמים הרשאה **חייבים** לאמת את כל הבקשות הנכנסות ו**אסור** להשתמש במפגשים לאימות  
3. **הסכמת משתמש**: שרתי פרוקסי MCP המשתמשים במזהי לקוח של צד שלישי סטטיים **חייבים** לקבל הסכמה מפורשת לכל לקוח MCP לפני העברת תהליך ההרשאה
4. **אבטחת מזהה מצב**: שרתי MCP **אסור שיטפלו** בהחזקה של
	מזהה מצב של אפליקציה כאימות ו**חייבים** להעניק הרשאה לכל
	בקשה שמשתמשת בו

## שיטות אבטחה מרכזיות

### 1. אימות וטיוב קלט
- **אימות קלט מקיף**: לאמת ולנקות את כל הקלטים כדי למנוע התקפות הזרקה, בעיות של נציג מבולבל ופגיעויות בהזרקת פרומפטים
- **אכיפת סכמת פרמטרים**: להטמיע אימות סכמת JSON מחמיר לכל פרמטרי הכלים וקלטי ה-API
- **סינון תוכן**: להשתמש ב-Microsoft Prompt Shields וב-Azure Content Safety לסינון תוכן זדוני בפרומפטים ובתגובות
- **טיוב פלט**: לאמת ולנקות את כל פלטי המודל לפני הצגתם למשתמשים או למערכות המשך

### 2. איכות אימות והרשאה  
- **ספקי זהות חיצוניים**: להסמיך אימות על ספקי זהות מבוססים (Microsoft Entra ID, ספקי OAuth 2.1) במקום ליישם אימות מותאם אישית
- **רישום לקוחות**: להעדיף מסמכי מטא-נתוני מזהה לקוח או רישום מוקדם; להשתמש ברישום דינמי מיושן רק לתאימות
- **הרשאות מדויקות**: ליישם הרשאות מדויקות, ספציפיות לכל כלי, על פי עקרון המינימום ההכרחי
- **ניהול מחזור חיים של אסימונים**: להשתמש באסימוני גישה קצרים עם סיבוב מאובטח ואימות קהל נכון
- **אימות דו-גורמי**: לדרוש אימות רב-גורמי לכל גישה ניהולית ולפעולות רגישות

### 3. פרוטוקולי תקשורת מאובטחים
- **אבטחת שכבת התחבורה**: להשתמש ב-HTTPS עם אימות תעודה נאות
	לתקשורת HTTP מרוחקת של MCP; להשתמש בבידוד תהליך ובקרדנציאלס סביבתיים לשרתי stdio מקומיים

- **הצפנה מקצה לקצה**: להטמיע שכבות הצפנה נוספות לנתונים רגישים מאוד במעבר ובמאוחסן
- **ניהול תעודות**: לנהל מחזור חיים תקין של תעודות עם תהליכי חידוש אוטומטיים
- **אכיפת גרסת פרוטוקול**: להשתמש בגרסת MCP `2026-07-28`, לכלול מטא-נתוני גרסה בכל בקשה, ולדחות גרסאות לא נתמכות


### 4. הגבלת קצב מתקדמת והגנת משאבים
- **הגבלת קצב רב-שכבתית**: להטמיע הגבלת קצב לפי משתמש, קרדנציאל,
  פעולה, כלי ומשאב כדי למנוע שימוש לרעה
- **הגבלת קצב אדפטיבית**: להשתמש בהגבלת קצב מבוססת למידת מכונה שמתאימה את עצמה לדפוסי שימוש ואינדיקטורים של איומים
- **ניהול מכסת משאבים**: להגדיר הגבלות מתאימות על משאבים חישוביים, שימוש בזיכרון וזמן ביצוע
- **הגנה מפני DDoS**: לפרוס מערכות הגנה מפני DDoS וניתוח תנועה מקיפות

### 5. רישום ומעקב מקיפים
- **רישום ביקורת מובנה**: להטמיע יומנים מפורטים, ניתנים לחיפוש לכל פעולות MCP, ביצועי כלים ואירועי אבטחה
- **מעקב אבטחה בזמן אמת**: לפרוס מערכות SIEM עם זיהוי חריגות מבוסס AI לעומסי העבודה של MCP
- **רישום תואם פרטיות**: לרשום אירועי אבטחה תוך כיבוד דרישות ותקנות הפרטיות
- **שילוב תגובה לאירועים**: לחבר מערכות רישום לזרימות עבודה אוטומטיות של תגובה לאירועים

### 6. שיטות אחסון מאובטחות משופרות
- **מודולי אבטחה חומרתיים**: להשתמש באחסון מפתחות מגובה HSM (Azure Key Vault, AWS CloudHSM) לפעולות קריפטוגרפיות קריטיות
- **ניהול מפתחות הצפנה**: ליישם סיבוב נכון של מפתחות, הפרדה ובקרות גישה למפתחות הצפנה
- **ניהול סודות**: לאחסן את כל מפתחות API, אסימונים וקרדנציאלס במערכות ניהול סודות ייעודיות
- **סיווג נתונים**: לסווג נתונים על בסיס רמות רגישות וליישם אמצעי הגנה מתאימים

### 7. ניהול אסימונים מתקדם
- **מניעת העברת אסימונים**: לאסור במפורש דפוסי העברת אסימונים שעוקפים בקרות אבטחה
- **אימות קהל**: תמיד לוודא שטענות האסימון מתאימות לזהות השרת MCP המיועד
- **הרשאה מבוססת טענות**: ליישם הרשאות מדויקות המבוססות על טענות באסימון ותכונות משתמש
- **קשירת אסימונים**: לאמת שהאסימונים מיועדים למשאב MCP המתאים ו-
	לחבר מזהי מצב אפליקציה בצד השרת לעיקרון המאומת

### 8. אבטחת מצב אפליקציה

- **מזהי מצב קריפטוגרפיים**: ליצור מזהים לא שקופים, לא דטרמיניסטיים
	למצב המתמשך על פני בקשות
- **קשירה ספציפית למשתמש**: לקשור כל מזהה בצד השרת לעיקרון המאומת;
	אסור לסמוך על מזהה משתמש שנמסר על ידי הלקוח
- **בקרות מחזור חיים**: לפוג ולהשעות מזהים, ולהגדיר כיצד מתקנים יכולים
	להתאושש ממצב מיושן
- **הרשאה לכל בקשה**: לבדוק מחדש הרשאה בכל פעם שמוצג מזהה; מזהה הוא שם, לא קרדנציאל


### 9. בקרות אבטחה ספציפיות ל-AI
- **הגנת הזרקת פרומפטים**: לפרוס את Microsoft Prompt Shields עם טכניקות של הדגשה, סימוני פסקאות וסימון נתונים
- **מניעת הרעלת כלים**: לאמת מטא-נתוני כלי, לנטר שינויים דינמיים, ולאמת תקינות הכלי
- **אימות פלט מודל**: לסרוק פלטי מודל לזיהוי דליפת נתונים, תוכן מזיק או הפרות מדיניות אבטחה
- **הגנת חלון הקשר**: ליישם בקרות למניעת הרעלת חלון הקשר והתקפות מניפולציה

### 10. אבטחת ביצוע כלים
- **הרצת כלים בסביבה מבודדת**: להריץ ביצועי כלים במיכלים מבודדים עם מגבלות משאבים
- **הפרדת הרשאות**: להריץ כלים עם ההרשאות המינימליות הנדרשות ולפרד חשבונות שירות
- **בידוד רשת**: ליישם סגמנטציה של רשת לסביבות ביצוע הכלים
- **מעקב ביצוע**: לנטר את ביצוע הכלים להתנהגות חריגה, שימוש במשאבים והפרות אבטחה

### 11. אימות אבטחה מתמשך
- **בדיקות אבטחה אוטומטיות**: לשלב בדיקות אבטחה בצינורות CI/CD עם כלים כמו GitHub Advanced Security
- **ניהול פגיעויות**: לסרוק באופן קבוע את כל התלויות, כולל מודלים חכמים ושירותים חיצוניים
- **בדיקות חדירה**: לבצע הערכות אבטחה תקופתיות הממוקדות במיוחד בפריסות MCP
- **סקירות קוד אבטחה**: להטמיע סקירות אבטחה מחייבות עבור כל שינויים בקוד הקשורים ל-MCP

### 12. אבטחת שרשרת אספקה ל-AI
- **אימות רכיבים**: לאמת מקור, שלמות ואבטחה של כל רכיבי ה-AI (מודלים, אמבדינגס, APIs)
- **ניהול תלות**: לשמור מלאי עדכני של כל התוכנה והתלות ב-AI עם מעקב אחרי פגיעויות
- **מאגרי אמון**: להשתמש במקורות מאומתים ומהימנים לכל המודלים, הספריות והכלים של AI
- **מעקב שרשרת אספקה**: לנטר באופן רציף פגיעויות אצל ספקי שירות AI ומאגרים למודלים

## דפוסי אבטחה מתקדמים

### ארכיטקטורת Zero Trust עבור MCP
- **לעולם אל תאמין, תמיד אמת**: להטמיע אימות מתמשך לכל המשתתפים ב-MCP
- **מיקרו-סגמנטציה**: לבודד רכיבי MCP עם בקרות רשת וזהות מדויקות
- **גישה מותנית**: להטמיע בקרות גישה מבוססות סיכון המסתגלות להקשר והתנהגות
- **הערכת סיכון רציפה**: להעריך באופן דינמי את מיקומו האבטחתי בהתבסס על אינדיקטורי איום עכשוויים

### יישום AI משמר פרטיות
- **מינימיזציה של נתונים**: לחשוף רק את המינימום הנדרש של נתונים לכל פעולה ב-MCP
- **פרטיות דיפרנציאלית**: ליישם טכניקות שמגנות על פרטיות בעיבוד נתונים רגישים
- **הצפנה הומומורפית**: להשתמש בטכניקות הצפנה מתקדמות לחישוב מאובטח על נתונים מוצפנים
- **למידה מפוזרת**: ליישם גישות למידה מבוזרת השומרות על מקומיות ופרטיות של נתונים

### תגובה לאירועים למערכות AI
- **נהלי אירועים ספציפיים ל-AI**: לפתח נהלי תגובה לאירועים המותאמים לאיומי AI ו-MCP
- **תגובה אוטומטית**: ליישם נשיאה ומיתון אוטומטיים לאירועי אבטחה נפוצים של AI  
- **יכולות פורנזיות**: לשמור על מוכנות פורנזית לפגיעות במערכות AI ולדליפות מידע
- **נהלי התאוששות**: לבסס נהלים להתאוששות מהרעלת מודלים, התקפות הזרקת פרומפטים ופריצות שירות
